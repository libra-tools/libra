# Libra DeepSeek Harness Bridge 实施计划（2026-08-18）

## 文档职责

本文规划 Libra Rust 侧对 DeepSeek Harness 的标准接入实现：增加
`libra agent bridge --stdio`，接收 TypeScript 插件通过 JSON-RPC NDJSON 发送的
session、event、workspace、checkpoint、evidence 和 provenance 数据，并将其接入 Libra
现有的 Agent ingress、AI 对象、VCS 操作、SQLite 和 workspace lease 服务。

本计划只覆盖 Libra 仓库的实现。TypeScript client、Harness bundle/profile、Harness
生命周期监听、插件本地 outbox 和 UI 适配由独立仓库
`/run/media/eli/sea/gitmono/deepseek-harness-libra-plugin` 的计划承接；两边通过版本化
bridge schema 和 contract fixture 协作。

### 适用范围

- `libra agent bridge --stdio` 的 CLI 入口、JSON-RPC 2.0 NDJSON framing、握手和错误契约。
- Libra 侧 bridge ingress、session/event batch、幂等键、ack、checkpoint、evidence、
  provenance 和审计记录。
- bridge 调用的 repository/worktree/workspace/lease/actor scope 校验。
- 高层只读查询和受审批保护的 VCS/Agent 操作方法。
- SQLite migration、对象/AI service 复用、单元/集成/兼容/安全测试及公开文档。

### 非目标

- 不在 Libra 中实现 DeepSeek Harness Agent loop、provider、session persistence、
  compaction 或 UI。
- 不直接暴露 `.libra/libra.db`、对象库、内部 SQL 或任意低层 AI object CRUD 给 TypeScript
  插件或模型。
- 不把 `libra code --control stdio` 改造成 Harness 写入入口；它继续只控制 Libra 自己
  运行中的 Code session。
- 不恢复 MCP 或其它旧工具服务器作为 Harness 的标准写入传输；本计划的唯一标准入站面
  是 `libra agent bridge --stdio`。
- 第一版不默认执行 `push`、`publish`、`reset`、`clean`、删除 worktree 或 raw transcript
  export；这些能力需要后续独立的权限和合规计划。
- 不替换 Harness 的原生 session persistence；Libra 只保存经过边界校验和脱敏的投影、
  provenance 与工程结果。

### 成功定义

- `libra agent bridge --stdio` 能在仓库内启动，stdout 只输出协议帧，诊断只写 stderr。
- TypeScript 插件能完成 `initialize`、`session.open`、事件 batch、ack、flush、close
  和结构化错误恢复。
- `(session_id,event_seq)` 和 `operation_id` 重试不会产生重复 session、event、checkpoint
  或 evidence；payload/hash 冲突会 fail-closed。
- 所有请求绑定 repository、worktree、workspace fence 和 bridge actor；调用方不能自报
  或覆盖 actor 身份。
- 只读方法和高层写方法均通过 typed allowlist，不能转化为任意 shell、SQL、路径或 ref
  操作；危险动作默认拒绝并留下审计记录。
- workspace claim/renew/release 复用现有 `WorkspaceStore` 的 owner+monotonic fence
  语义，过期或 stale lease 不会覆盖新 owner。
- 新增 CLI、schema、错误码、migration、测试 target 和 EN/zh 文档均完成兼容收口；
  `cargo +nightly fmt --all --check`、clippy、L1 全量测试和 bridge contract 测试通过。

## 已决议设计决策

### ADR-LB-01: `libra agent bridge --stdio` 是唯一标准入站入口

- **Status:** Accepted
- **Context:** `libra code --control stdio` 已是 Libra 自有 Code session 的 controller；
  Harness plugin 需要的是 repository-scoped Agent ingress，而不是控制一个已有 Code UI。
- **Decision:** 在 `libra agent` 下新增 `bridge --stdio`。协议为 JSON-RPC 2.0 风格的
  newline-delimited frames；stdout 只承载 response/notification，stderr 承载诊断。
- **Alternatives considered:** 直接写 `.libra/libra.db`、调用普通 CLI、复用 Code control、
  MCP/旧工具服务器；均拒绝，因为无法统一 actor、scope、ack、幂等和审计边界。
- **Consequences:** 需要独立的 protocol module、命令文档、错误码和 contract fixture；
  旧入口保持兼容，不产生隐式转发。
- **Revisit when:** 需要远程多租户 bridge 或 stdio 不再满足本地隔离时，另开 ADR/计划。

### ADR-LB-02: bridge 使用独立 source identity，不扩张 `AgentKind` roster

- **Status:** Accepted
- **Context:** `AgentKind` 是 provider/hook/transcript adapter 的闭集合，registry 和
  compatibility tests 明确 pin 当前外部 Agent roster；Harness bridge 由 TypeScript
  plugin 主动发送结构化事件，不依赖 provider hook 或 provider transcript 文件。
- **Decision:** 新增 `agent_bridge_session`/`agent_bridge_event`/`agent_bridge_operation`
  专用持久层，source 固定为 `deepseek-harness`；需要链接既有 checkpoint 时以明确的
  bridge session reference 关联，不把 `deepseek-harness` 伪装成 `AgentKind`。
- **Alternatives considered:** 添加 `AgentKind::DeepSeekHarness` 并扩展静态 registry；拒绝，
  会改变第一批 roster、adapter trait 和历史 provider 语义，且 bridge 不需要 hook install。
- **Consequences:** `libra agent session`/`checkpoint` 现有 provider 查询需要增加明确的
  bridge projection/read path；bridge checkpoint/link catalog 负责连接独立 bridge session
  与既有 AI/VCS object，不能假定所有 session 都来自 `AgentKind`。
- **Revisit when:** Harness 需要 provider-specific transcript import/rewind，并且有独立
  adapter、capability row 和 compat contract 时。

### ADR-LB-03: v1 以有界 redacted projection 为持久真源

- **Status:** Accepted
- **Context:** Harness 的原始 session persistence、compaction 和 UI replay 不应与 Libra
  object lifecycle 耦合；Libra 需要可查的 event/provenance，但不能默认保存 raw prompt、
  reasoning、环境变量和敏感文件内容。
- **Decision:** bridge server 在写入前再次验证 size/schema/scope，并只持久化结构化、脱敏、
  有界的 projection；event row 保存 `payload_sha256` 和归属字段，payload 超过 v1 上限或
  redaction 不确定时拒绝，不以原文回退。
- **Alternatives considered:** 直接镜像 Harness session persistence、只存日志文本、把
  全部 payload 写入 object store；均不作为 v1 默认路径。
- **Consequences:** TypeScript 仍保留自己的 outbox/replay；Libra ack 只代表 bridge
  projection durable，不代表 Harness 原始 transcript 已被 Libra 接管。
- **Revisit when:** 完成独立 raw export authorization、retention、encryption 和 audit
  设计后，另开 raw transcript 计划。

### 跨仓库 contract v1（由 Rust bridge 发布）

`LB-01` 发布的 schema/fixture 是两仓库唯一的 protocol authority；TypeScript 计划中的
`DEP-LB-01` 只能接收该 fixture、生成类型或执行 runtime validation，不得另定义 method、error
或 limit。`DEP-TS-01` 是 Rust release 提供给 TypeScript 的 handoff receipt，不是 Rust 实现的
前置依赖。v1 的固定值为：单 frame ≤ 256 KiB、单连接 in-flight request ≤ 64、event batch ≤ 64
events 且 ≤ 256 KiB、单 event ≤ 256 KiB、单 result ≤ 256 KiB、request deadline 默认 30 秒、
history/checkpoint page ≤ 100。

标准 method allowlist 为：`initialize`、`session.open`、`event.append`、`session.flush`、
`session.close`、`evidence.append`、`provenance.append`、`context.get`、`status.get`、
`diff.get`、`history.search`、`checkpoint.create`、`checkpoint.list`、`checkpoint.show`、
`checkpoint.restore`、`commit.create`、`review.run`、`workspace.claim`、`workspace.renew`、

outbox 仍负责 Harness 侧重放，`agent_bridge_*` 表和 Rust transaction 才是服务端 durable
projection 的归属。未知 major/method、scope/actor/lease 冲突、digest conflict、超限和
redaction 不确定均 fail-closed。

## 全局工程约束

- **GC-LB-01 事实刷新:** 每张卡开工前刷新当前 checkout、migration version、既有 service API、
  外部 Harness revision 和跨仓库 schema revision；不按过期行号实现。
- **GC-LB-02 单一协议源:** bridge schema、method allowlist、capability、error code、frame
  limits 和 retryability 只能由 bridge protocol module/schema 定义，不能在 CLI、测试或文档
  各写一份互相漂移的副本。
- **GC-LB-03 bridge-only:** TypeScript 插件只能通过 stdio bridge；Rust bridge 内部可调用
  service，但不得把 SQL、object path、任意 executable 或内部 CLI 转成外部参数。
- **GC-LB-04 stdout purity:** stdout 每行必须是一个合法 frame；日志、warning、trace 和
  child-process 诊断不得混入 stdout；broken pipe、EOF 和 stderr cap 必须有明确结果。
- **GC-LB-05 protocol evolution:** 未知 major、缺失必需字段、未知 method、重复 request id
  不得静默降级；minor/additive field 按 schema policy 处理，结果必须带 schema/protocol version。
- **GC-LB-06 scope fail-closed:** repository id、worktree id、workspace id、lease fence、
  actor/session lineage、path canonicalization 任一冲突即拒绝；不得从请求 body 猜测当前仓库。
- **GC-LB-07 actor authority:** `deepseek-harness:<session_id>` 和
  `deepseek-harness:<agent_id>` 由已认证 bridge session 派生；请求中的 actor_kind/actor_id
  只能用于一致性校验，不是认证凭据。
- **GC-LB-08 privacy:** raw prompt/reasoning、token、environment、secret、完整文件内容和
  未脱敏 stderr 默认不落库；redaction fail-closed；审计记录只保存必要的稳定 ID/hash。
- **GC-LB-09 durability:** event batch 的数据库提交与 ack 顺序必须可证明；ack 只能在事务和
  必要 payload durable 后返回；重复 digest 是成功重放，digest conflict 是错误。
- **GC-LB-10 lifecycle:** stdin/stdout reader、transaction、queue、timer、workspace lease、
  bridge child 和 tracing span 在 EOF/error/close/cancel 时释放；不得留下 orphan lease/process。
- **GC-LB-11 bounded resources:** 单 frame、batch、event payload、session count、cursor page、
  request timeout、ack retry 和 query result 均有硬上限；不允许每个 token/event 启动进程。
- **GC-LB-12 Rust quality:** 生产代码不得新增未解释的 `unwrap()`、`expect()` 或 `panic!()`；
  失败使用 `Result`、稳定错误码和可执行的用户诊断。
- **GC-LB-13 compatibility:** 新增 `agent` 子命令、schema、error code、migration、JSON field
  和 test target 必须同步 EN/zh command docs、development docs、COMPATIBILITY、error-codes、
  tests/INDEX、Cargo.toml 和必要的 compat guards。
- **GC-LB-14 no MCP:** 本计划和实现不得新增或恢复 Harness MCP server/client 作为 bridge
  写入路径；任何旧 MCP 代码只在既有兼容边界内保持，不与本计划共享新存储入口。

### 故障恢复矩阵

| 故障点 | 可接受残留 | 恢复动作 | 禁止结果 |
|---|---|---|---|
| initialize 后、session.open 前断开 | 无 session row 或已记录的 handshake diagnostic | 重启并重新 initialize；旧 connection 不可继续使用 | 使用未认证 scope 处理 request |
| event DB commit 后、ack 写出前进程崩溃 | 一次已 durable event batch、无 ack 给 client | client 重放同 batch；相同 digest 返回 duplicate/last ack | 重复创建 event/checkpoint 或返回假 ack |
| batch 中途 validation/transaction failure | 事务前状态；已确认的 earlier batch 保留 | 返回 per-item error/last ack，client 从 cursor 重试 | partial batch 被宣称全部成功 |
| digest conflict | 原 event row 和 conflict audit | 拒绝冲突，保留两边 digest/operation id 供诊断 | last-writer-wins 覆盖原 event |
| redaction uncertain/size overflow | 拒绝记录和必要的稳定 error/audit | TypeScript 按 policy 截断/重投；无 raw fallback | 把原文写入 DB/object/log |
| actor/repository/workspace/lease mismatch | 无 mutation；拒绝审计行 | 重新 initialize/claim；stale owner 走 renew/reclaim | 跨 repository 写入或静默切换 cwd |
| commit/checkpoint 后 response 丢失 | 已存在的 immutable result/provenance | 以 operation id 查询并返回原结果 | 再次执行非幂等 commit |
| lease owner 进程崩溃 | provisioning/active/orphaned record 按现有 store 语义保留 | bounded reclaim/doctor，再以新 fence claim | stale owner release 新 owner lease |
| migration 发布后发现 bug | 新表/已写数据，不删旧 agent capture | capability disable + forward-compatible migration/patch | down 删除 evidence 或 silent schema downgrade |
| release artifact/handoff 不一致 | 未更新 release ref 的构建产物 | REL-LB-01 abort，修正版本面后重发 | 发布 client/server 不匹配组合 |

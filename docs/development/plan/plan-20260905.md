## 文档职责

本文将 Claude Code 2.1.259 官方 Hook 参考所列的 **33 个当前事件**变成 Libra 的单一、版本 pin、可审计的监听集合。安装器必须为每个可配置事件写入一个 Libra-owned command handler；parser、CLI entry、doctor 和 conformance fixture 必须以同一张事件表为唯一事实源。它是纯观察采集：Libra 永不向 Claude Code 返回 allow/deny/continue、permission update、context 或其它会改变 Claude 行为的输出。

同时，本文让 Claude Code 本地 JSONL 中可读 `thinking` 经 typed redaction 进入 `SemanticRecord::Reasoning`，并将官方明示为 opaque/encrypted 的 `thinking.signature` 与 `redacted_thinking.data` 原字段字节保存为 reasoning artifact。它们必须遵守 9 月 4 日计划的 manifest、object index、镜像、erase、受控导出与 doctor 生命周期；不解密、不探测密钥、不把密文字节写回普通 transcript。

本文只规划任务，不宣称实现完成。落地时每张卡均先刷新源码、官方文档和 CLI 版本锚点，再按本卡验收。

### 适用范围

- Claude Code project-level `.claude/settings.json` 的 Libra-owned hook entry、安装/卸载、install-state 诊断与用户文档。
- `src/internal/ai/hooks/providers/claude/{events,parser,settings}.rs`、共享 `provider` / `lifecycle` / runtime、hidden hook CLI entry 与 `agent doctor`。
- Claude JSONL normalizer、reasoning classifier、live capture 与历史 import；只消费 RG artifact contract。
- `tests/fixtures/agent_transcripts/claude_code/**`、Claude hook / reasoning integration tests、compat 文档守卫、`tests/INDEX.md`。

### 非目标

- 不在 RG-01/RG-04/RG-02/RG-06/RG-03/RG-05 全部 `Acceptance=complete` 前实现、安装或启用任何本计划的 Claude reasoning 接线（GC-CC-04）。
- 不实现 Anthropic/Claude Code decryptor，不读取 keychain、环境变量、provider settings 或网络端点来寻找密钥；没有官方、显式授权 capability 时稳定报告 `encrypted_unavailable`。
- 不保存任意原始 hook envelope、用户绝对路径、prompt/tool/form 原文字节或 `MessageDisplay` 原文到 metadata、日志、coverage digest 或普通未脱敏 sink。
- 不把 FileChanged 伪装为“全文件系统 watcher”。上游将 matcher 当作工作目录中的**字面文件名**观察列表；本计划监听该 Hook 类型，但只能观察其显式注册的文件名，不能通过 `*` 或正则获得任意文件变化。
- 不改变 Claude Code 的权限、工具执行、停止、任务完成、模型切换、worktree 或 MCP elicitation 结果；这些事件的可控制输出一律不产生。
- 不重做 Codex、OpenCode 或其它 provider 的采集工作，也不将全量 raw Claude JSONL 作为未经脱敏的可恢复 archive（仍属 DEFER-CX-02 / DEFER-LB-02）。

### 成功定义

- `libra agent enable --agent claude-code` 在 Claude Code 2.1.259 项目配置中安装官方事件表的全部 33 个事件；`agent doctor --json` 对每一项给出 `installed`、`delivery_mode`、`matcher_policy` 与版本 pin，而不是单一布尔值掩盖缺口。
- 33 个合成、无真实内容的 envelope 各自经同一 registry 被 accept 并产生一个受限、去重、可归因的观察事件；未知上游 event 只记录无 payload 的 `unsupported_event` warning，不能被误标为完整采集。

- 对 `FileChanged`，doctor 精确报告当前字面观察名单及未覆盖的任意其它文件；不存在把 matcher `*` 写成有效全局 watcher 的虚假成功。

## 已决议设计决策

### ADR-CC-01: 固定 33 项 registry、一个 observe command、零控制输出

- **Status:** Accepted
- **Context:** 当前 installer、parser、CLI command 和文档分别维护不同 Claude Hook 名称集合；新增 event 若无统一表会产生安装成功而解析失败的静默缺口。
- **Decision:** 新建只属于 Claude provider 的 `ClaudeHookEventSpec` 表，精确枚举本计划的 33 名称、matcher policy、payload policy、lifecycle disposition、delivery class 和最低 Claude Code 版本。新 `libra ... hooks claude observe` command 仅接受 registry 中的 event；每个 settings entry 复用它，真正 event 名来自 stdin `hook_event_name` 并与 spec 二次校验。所有 handler command 只退出 0（成功/受控降级）或既有 ingest 错误码，stdout 恒为空；不写任何 control JSON，也不返回 exit 2。
- **Alternatives considered:** 为每个 event 增加 CLI verb——公开面膨胀且仍会有 33 份 mapping 漂移；安装 wildcard handler——Claude settings 以 event name 作顶层 key，无法订阅未列事件；使用 prompt/agent hooks——会消费模型/工具并可能改变 Claude 行为，不符合采集目的。
- **Consequences:** provider registry、settings installer、parser、doctor、fixture 与 docs 都必须对 33 项 exact set 做相等断言；未来上游新增/删除事件先更新 CC source evidence、spec、fixture、docs 与 version pin，不可被“unknown”静默吸收。
- **Revisit when:** Anthropic 发布的官方 Hook event table 变更，或 CLI 版本 pin 不再为 2.1.259。

### ADR-CC-02: 所有 Hook 都被监听，但 payload 按字段策略保存，FileChanged 不夸大覆盖

- **Status:** Accepted
- **Context:** “监听所有 Hook”不等于持久化每个原始 JSON 字节。许多 envelope 包含 prompt、tool input/output、MCP form、assistant message、路径或 permission suggestions；而 FileChanged 只能观察显式字面文件名。
- **Decision:** 每个 33 event 都写一个 Libra-owned handler。CC-02 将输入解析成有界 `ObservedAgentEvent`：identity / event / timestamp / disposition / allowlisted non-content attributes 保存；可读文本先 `RedactedBytes`；未列字段只产出无 payload 的 field warning；没有 raw `extra` backdoor。高频 MessageDisplay 以每 `(session, turn, event)` 计数和最后安全摘要合并，达到单 session 上限后记录 `partial`/dropped-count 而不无界写入。FileChanged 固定安装 `matcher: "CLAUDE.md"` 的真实字面观察项；doctor 将它显示为 `literal_watch_list=["CLAUDE.md"]`、`global_file_watch=false`。
- **Alternatives considered:** 继续保存 raw metadata——违反 typed redaction 与最小化原则；`matcher: "*"`——官方将它当作字面文件名，不会观察任意文件；忽略 FileChanged——违反用户要求和 event registry 完整性。
- **Consequences:** 监听完整性由“所有 provider event name 有 handler”衡量；文件变化覆盖率单独由 explicit watch list 衡量。无法从 Hook 获得的 payload 不得补读 provider home 或用 heuristic 伪造。
- **Revisit when:** Claude Code 支持真正的 recursive/global FileChanged subscription，或产品明确授权新的文件观察名单配置。

### ADR-CC-03: Claude reasoning 以 text / encrypted artifact 分路，永不解密

- **Status:** Accepted
- **Context:** Anthropic 官方将 `thinking` 表示为可读 reasoning，且说明 `thinking.signature` 与 `redacted_thinking.data` 是必须原样 round-trip 的 opaque/encrypted 值；当前 Libra normalizer 忽略它们。
- **Decision:** 对经 CC-04 fixture/version pin 验证的 Claude assistant content block：`thinking.thinking` 经 field-level typed redaction 转为 `SemanticRecord::Reasoning`；非空或空的 `thinking.signature`、`redacted_thinking.data` 均以原 JSON-string UTF-8 field bytes 创建 `OpaqueEncryptedBytes`，分别带 source-kind 和稳定 locator。signature/data 不 base64 decode、不 JSON reserialize、不进入 `RedactedBytes`。未知 thinking-like shape 使 turn `partial` 并只记录无 payload warning。
- **Alternatives considered:** 只保留 visible thinking——丢失 encrypted continuity evidence；把 signature/data 写进 transcript——破坏 RG 两种字节类型边界；尝试调用 Anthropic API 或扫描本机凭据解密——没有用户授权且违反 GC-RG-03。
- **Consequences:** live capture 与 historical import 共享 classifier；artifact 写失败时 checkpoint attempt fail/pending，不能将 encrypted bytes 降级塞回 transcript。existing artifact lifecycle 和 decrypt registry 仍完全由 RG cards 管理。
- **Revisit when:** Anthropic 发布官方、用户可授权的 decrypt/export capability；届时另立 provider-specific ADR 和卡。

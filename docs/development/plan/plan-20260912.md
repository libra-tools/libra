## 文檔職責

本文規劃唯一公開命令 `libra mega2 browser`：以終端 TUI 按需瀏覽 monoengine storage-only（及相容的 Review HTTP 寫入面）上的 Git 目錄樹，並在同一 TUI session 內建立目錄、（契約就緒後）刪除/移動/改名目錄，以及列出/建立/刪除 tag。`--json` / `--machine` 只輸出當前一層 listing，不提供寫入或 tag 的機器介面。它不克隆倉庫、不讀取 blob 內容，也不在本倉修改 monoengine。

### 適用範圍

- 新增且僅新增 `libra mega2 browser`；父命令 `mega2` 只穩定暴露 `browser`。
- 在 TUI 內追加操作鍵：`+` 建目錄；契約就緒後 `d` 刪目錄、`m` 移動、`R` 改名、`t` 打開 tag 面板。
- 消費已 pin 的 HTTP 契約：`GET /api/v1/tree`、`POST /api/v1/create-entry`；以及 Review 面已存在、storage-only 尚未掛載的 `/api/v1/tags*`（方法/欄位以程式與 60917 ADR-LB-05 為準）。
- 目錄刪除 / 移動 / 改名：**wire 已由** monoengine `plan-20260917.md` ADR-LB-03 **指定**（`POST /api/v1/delete-entry`、`POST /api/v1/move-entry` 與下表欄位），本倉不得發明第三套路徑或欄位名。實作卡在 `DEP-MB-04` 未帶**已掛載**路由的 `file:line` 前保持 `blocked`，TUI 不顯示這些鍵。
- 完成 CLI 註冊、browser 的輸出/錯誤契約、EN/zh-CN/網站命令文件、測試、版本發布與遠端 release 證據。

### 非目標

- **不新增** `mega2 mkdir` / `rmdir` / `mv` / `tag` 或任何第二個穩定子命令；這些操作不得有獨立 clap surface 或 JSON 寫入 envelope。
- 不在本計劃修改 monoengine 的 API、認證模型、資料庫或 Git 協定。發現契約不相容或表面缺失時 fail-closed，依對應 `DEP-MB-*` 阻斷，另立跨倉契約卡。
- 不做檔案內容預覽、檔案建立/編輯（`is_directory=false` / `POST /edit/save`）、下載、clone/fetch/push、遞迴全樹匯出、搜尋索引或本機目錄瀏覽。
- 不從 Git remote URL 猜測 HTTP endpoint；不把 token 放入 URL、設定檔或日誌。
- 不以 Git receive-pack、parent-path commit 或 agent-capture `file-ops` 冒充目錄刪除/移動/改名。
- 不接入 Review OAuth / CL / user router；tag 若只存在於 Review 面，不得在 TUI 顯示 tag 面板。

### 成功定義

- 有權連到目標 HTTP 服務的開發者可在 TTY 中逐層進入/返回目錄，且每一次導航只取得目前一層。
- `--json` 可在非 TTY 以穩定 envelope 取得同一層 listing；互動模式遇到非 TTY、無效 URL/path、非成功 HTTP、壞 JSON 或不可信目錄項目時拒絕而不寫本地狀態。
- TTY 中 `+` 可經已 pin 的 `create-entry` 建立空目錄；寫入只發生在 TUI，不經新子命令。
- 刪/移/改名與 tag 要麼已作為 TUI 鍵發布，要麼其卡仍為 `blocked` 且 TUI/help/docs 不顯示那些鍵。
- 穩定 help 永遠只有 `mega2 browser`。所有非延後卡皆 `done`/`complete`（MB-07/08/10/11 須在 DEP 轉 incoming 後做完，不得帶著 `blocked` 過完成門；若 60917 放棄則先改 `DEFER-*` 並登記修訂歷史）。各卡 C/D 發布證據與最終 Codex **以及** Claude Code 字面 `VERDICT: PASS` 已取得。

## 已決議設計決策

### ADR-MB-01: 一層、按需、fail-closed 的匿名 storage-only tree client

- **Status:** Accepted（2026-09-16 僅前推 pin，決策不變）
- **Context:** monoengine 已在 storage-only 形態暴露匿名 `/api/v1/tree`，但 `file_tree` 會額外提供祖先資料，遠端 response、path 和文字皆不該被 TUI 當成可信輸入。
- **Decision:** `libra mega2 browser` 只以 `data.tree_items` 作目前層資料；每次 enter/back/reload 以目前 rooted canonical path 建一次 GET。base URL 必為 HTTPS，或是無 userinfo 的 loopback HTTP；client 禁用 proxy 與 redirects、設定 connect/request/body/entry/session-cache 上限。它只接受 `req_result=true` + `data` + `content_type in {directory,file}`；拒絕絕對/相對轉義、`..`、NUL、separator 或 terminal control item name，並忽略 server-provided `path` 作為導航依據。HTTP 401/403、4xx/5xx、超時、schema mismatch、non-TTY interactive 呼叫均回穩定、secret-free CLI error。browse **不**送 Authorization。
- **Alternatives considered:** 一次遞迴列舉（拒絕：大型倉庫無界 I/O/memory）；從 Git remote 推導 URL（拒絕：SSH/HTTPS Git remote 不含 API service endpoint）；接受任意 HTTP/URL bearer token（拒絕：中間人與 secret 進 history/log 的風險）；修改 monoengine 增設樹 API（拒絕：現有 contract 足夠）。
- **Consequences:** browse 要求明示 `--server`。server `file_tree`、blob read 與 `edit/save` 都不會被 browse client 呼叫。
- **Revisit when:** monoengine 正式 versioned API/credential transport 和 pagination contract 已發布並有相容矩陣。

### ADR-MB-02: 唯一公開命令是 `mega2 browser`；寫入與 tag 只在 TUI；JSON 只列一層

- **Status:** Accepted（2026-09-16 更名 `mega`→`mega2`、`browse`→`browser`；同日改為「不新增子命令」）
- **Context:** TUI 的 alternate screen、raw mode 和鍵盤事件不適合管線、agent 或 snapshot testing；現有 `OutputConfig` 已提供 JSON envelope。使用者要求建目錄、刪/移/改名與 tag 都在 browser TUI 內完成，不新增 clap 命令。
- **Decision:** 穩定公開 surface 只有 `libra mega2 browser`。human mode 要求 stdin/stdout 都是 TTY，進 alternate screen。MB-02 只實作瀏覽鍵：`Up/Down` 選擇、`Enter` 進 directory、`Backspace`/`h` 返回、`r` reload、`q`/`Esc` 離開；file 只顯示不開 blob。`--json`/`--machine` 禁止啟動 TUI，僅 fetch 初始目錄並用 stable `mega2 browser` JSON envelope 輸出 server/ref/path/items；**永不**輸出寫入回執或 tag 列表。寫入/tag 只以同一 TUI 的後續鍵進入，不得註冊 `mkdir`/`rmdir`/`mv`/`tag` 子命令。TUI drop/guard 必定嘗試 restore terminal，錯誤保留原始操作脈絡但不回顯 URL userinfo/token。
- **Alternatives considered:** 為 mkdir/rmdir/tag 各開子命令（拒絕：2026-09-16 使用者糾正）；`--json` 同時跑互動介面或兼寫入（拒絕：破壞 machine output）；TUI 內預覽 blob（拒絕：內容、redaction 和容量另是行為軸）。
- **Consequences:** 非 TTY 使用者只能 script 一層 listing，不能從 CLI 建目錄或改 tag。TUI 只使用既有 `libc` / `windows-sys` + ANSI，且必須保持 `compat_agent_architecture_guard` 綠色。
- **Revisit when:** 若未來需要 agent 可呼叫的遠端 mkdir/tag，另開日期計劃，不得夾帶進本瀏覽器卡。

### ADR-MB-03: 遠端寫入憑證只走 header / env / token-file

- **Status:** Accepted
- **Context:** 2026-09-11 MVP 禁止任何 Authorization。2026-09-16 起 trunk `create-entry`（以及未來的 tag 寫）在 `git.push_auth=token` 時必須帶與 LFS/Git smart HTTP 相同的 Bearer 或 Basic 密碼欄（`api_write_auth.rs:27-72`）。URL userinfo 仍不可接受。
- **Decision:** 同一條 `mega2 browser` 從下列來源取 **一個** token，優先序：`--token-file <path>` → 環境變數 `LIBRA_MEGA2_TOKEN` → `--token`（help 必須警告 shell history）。GET `/tree` 與 tag list **不**送 header。只有 TUI 確認後的寫入請求帶 `Authorization`。client 把 token 放進 header 後立即從 argv 複本與錯誤字串中 redaction。禁止寫入 repo/global config、禁止日誌/JSON/trace 回顯、禁止 query/fragment。`push_auth=none` 的 loopback 測試必須證明未配置 token 時請求不含 Authorization 且 TUI 仍可 mkdir。MB-03 不宣告這些 flag；MB-05 把它們加到既有 browser 命令。
- **Alternatives considered:** 繼續無 header（拒絕：token 部署下 mkdir 恒 401）；把 token 放進 `--server` URL（拒絕：history/log/proxy）；讀 OS keyring 作為本計劃 MVP（延後：`DEFER-MB-03`）。
- **Consequences:** DEFER-MB-01 的「browse 匿名」仍然成立；「一切請求無 header」被本 ADR 取代。
- **Revisit when:** monoengine 發布獨立於 push token 的 versioned API credential。

### ADR-MB-04: 建目錄只走 `POST /api/v1/create-entry`

- **Status:** Accepted
- **Context:** storage-only 已掛 create-entry；`is_directory=true` 時忽略 file content，由 server 建含 `.gitkeep` 的 tree（`mono_api_service.rs:1774-1796`）。
- **Decision:** 只有 TUI `+` 觸發建目錄。它 POST `{is_directory:true,name,path,content:null,skip_build:true}`，**省略** `mode` 與 `author_username`（server 對 `mode` 的 serde 預設是 `EditCLMode::TryReuse(None)`；**禁止**送字串 `"try_reuse"`，該字面量不能反序列化 tuple variant）。parent `path` 與 `name` 在本地先通過與 browse 相同的 rooted/name 驗證。成功只信 HTTP 2xx + `req_result=true` 與非空 `data.commit_id` 與 `data.new_oid`；`data.path` / `data.cl_link` 只作回執，不作後續導航權威，導航仍由本地 parent+name 組成。不呼叫 `edit/save`、不建檔案、不新增 clap 子命令。
- **Alternatives considered:** 用 Git push 建空目錄（拒絕：本計劃不 clone/push）；client 自製 `.gitkeep` 再當檔案上傳（拒絕：重複 server 語意且會走 file 分支）。
- **Consequences:** 重複名、缺父路徑、401/403 都 fail-closed。trunk 成功時 `cl_link` 應為 null，client 不把它當必填。
- **Revisit when:** server 另提供純目錄 API 或 pagination/conflict token。

### ADR-MB-05: 目錄刪除/移動/改名已指定、未掛載前不得公開

- **Status:** Accepted（2026-09-16：指定-但-未掛載，不再把路徑當未知）
- **Context:** 2026-09-16 核對：preview write 只有 create-entry 與 edit/save。CL `apply_changes` 認識 Deleted/Renamed/Moved，但那不是 storage-only 產品面。trunk Git push 拒絕 delete command（`monorepo.rs:1266-1273`）。monoengine `plan-20260917.md` ADR-LB-03 已給出字面量。
- **Decision:** 本計劃 **消費** ADR-LB-03 的路徑與欄位，**不**發明第三套路徑或絕對路徑 DTO，也 **不**用 parent-path Git commit 或 agent-capture file-ops 冒充。MB-07/MB-08 在 `DEP-MB-04` 未帶**已掛載**路由的 `file:line`（契約頁或 `preview_router.rs`）前保持 `blocked`，TUI 不綁 `d`/`m`/`R`，docs/help 不描述這些鍵。

  指定（未掛載）契約，與 60917 相同：

  | 操作 | Method | Path | 請求（必填 / 可選） | 成功 `data` |
  |---|---|---|---|---|
  | 刪目錄 | `POST` | `/api/v1/delete-entry` | 必填 `path`（父）、`name`；可選 `author_username`（null/省略）、`skip_build`（serde 預設 `false`；**本計劃一律送 `true`**）。鑑權 path = 父 `path` | `{commit_id,path,cl_link}`；**無** `new_oid`；trunk `cl_link=null` |
  | 移/改名 | `POST` | `/api/v1/move-entry` | 必填 `from_path`,`from_name`,`to_path`,`to_name`；可選同上；改名 = 同 parent | `{commit_id,from_path,to_path,cl_link}`；**無** `new_oid` |

  HTTP 狀態與 create-entry 相同：**200** + `CommonResult`（不用 204）。成功判據：2xx + `req_result=true` + 非空 `commit_id`。回傳的 `path` / `from_path` / `to_path` **只作回執**，導航與 reload 路徑一律由本地已驗證的 parent+name 組成。move 必須對 `from_path` **與** `to_path` 各做一次與 create-entry 相同的 `authorize_trunk_api_write`（單一 token；任一未覆蓋 → 403，不寫）。
- **Alternatives considered:** 在 Libra 另猜 REST 形狀（拒絕：第三套欄位）；用 `git push` 刪目錄（拒絕：trunk 拒 delete）；另開 `mega2 rmdir`/`mv`（拒絕：2026-09-16 使用者糾正）。
- **Consequences:** 使用者在 source pin 完成前不能從 browser TUI 刪/移/改名遠端目錄。這是正確的產品誠實。
- **Revisit when:** 60917 LB-02/LB-03 掛上路由並完成本計劃 incoming pin 重核。

### ADR-MB-06: tag 消費 Review `tag_router` 契約，但只在 storage-only 真實掛載後公開

- **Status:** Accepted
- **Context:** `docs/monorepo.md` 規定 monorepo tag **只能**走 Web/HTTP，Git 客戶端 create/update/delete 被拒。`tag_router` 已實作 list/create/get/delete，但只 merge 進 Review `routers()`，`storage_only_routers_with` 不含它。list 的 OpenAPI/文件寫 `GET`，實作是 `POST /tags/list` + `PageParams<String>`。
- **Decision:** 本計劃 pin **程式**契約（欄位與 60917 ADR-LB-05 相同，不得發明 `tagger` 等第三套鍵）：

  | Method | Path | 鑑權 | 請求 | 成功 |
  |---|---|---|---|---|
  | `POST` | `/api/v1/tags` | trunk 寫走 push_auth；Review 不新增 401。create 鑑權 path = `path_context.unwrap_or("/")`；省略或 `"/"` 時，`paths=["/project"]` 這類不含 `/` 的 token → **403**（與 delete 相同） | `CreateTagRequest`：必填 `name`；可選 `target`（alias `target_commit`）、`path_context`、`tagger_name`、`tagger_email`、`message`。**無** `tagger` 鍵。root MVP 送 `path_context="/"` 或省略（省略時 server 用 `/`） | OpenAPI 現寫 201、handler 現回 **200** + `CommonResult<TagResponse>`；client 接受 **任一 2xx** + `req_result=true`，不硬編碼 201 |
  | `POST` | `/api/v1/tags/list` | 匿名，不送 header | `PageParams<String>`：`pagination{page,per_page}` 與 `additional` **皆為必填 JSON key**（server **無** serde default）。root 必須送 `additional:"/"`；server 把 `additional.trim().is_empty()` 視同 `/`（含空白） | `CommonResult<CommonPage<TagResponse>>` |
  | `GET` | `/api/v1/tags/{name}` | 匿名 | path `{name}`；server 硬編碼 `repo_path="/"` | `CommonResult<TagResponse>` |
  | `DELETE` | `/api/v1/tags/{name}` | trunk 寫走 push_auth，**授權 path 固定 `/`**（無 body/`path_context`）。`push_tokens.paths=["/project"]` 這類不含 `/` 的 token → **403**；tag 寫需要能覆蓋 `/` 的 token，或 `paths` 省略/空（whole repo） | path `{name}` | `CommonResult<DeleteTagResponse>`（`deleted_tag`,`message`） |

  `TagResponse` 欄位：`name`,`tag_id`,`object_id`,`object_type`,`tagger`,`message`,`created_at`（`tagger` 是**回應**字串，不是請求鍵）。MVP 只操作 monorepo root tags。client 不因產品文檔寫 GET 就改用 GET。`DEP-MB-05` 要求 storage-only 掛上同一 router。MB-10/MB-11 在該掛載未核對前 `blocked`，TUI 不顯示 `t` 面板，不註冊 `mega2 tag`。
- **Alternatives considered:** 對 Review server 走 OAuth 調 tag（拒絕：OAuth/CL 非本計劃目標）；用 `libra tag` + Git push（拒絕：server 明確拒絕客戶端 tag）；在 storage-only 404 時仍畫 tag 面板或發布 `mega2 tag`（拒絕：對主目標說謊）。
- **Consequences:** tag 面板在 outgoing 完成前不存在於 TUI 或 help。
- **Revisit when:** storage-only OpenAPI 含 `/tags` 且 list 方法與文件一致。

## 全局工程約束

本計劃繼承 `plan-template.md` v2.6 的 GC-01..GC-13 與 ER-01..ER-13。以下補充要求同時生效。

- **GC-MB-01 本地只讀、單一命令：** 唯一 handler 是 `mega2 browser`。它不開 repository/object storage、不改 refs/index/worktree/object store，也不把 server/ref/cache/token 持久化到 Libra 設定。可在非 Libra repository 啟動。MB-03 時 scope 與 mutation class 皆為 ReadOnly。MB-05 起同一命令保持 `CommandScope::ReadOnly`，但因為 TUI 可改遠端 tip，`MutationClass` 改為 `ExternalOrUnknown`；`--json` 路徑仍只做一次 GET。`src/cli.rs:1952-1954` 會把**所有** `CommandScope::ReadOnly` 短路成 `MutationClass::ReadOnly`；MB-05 **必須**在該短路之前為 `Commands::Mega2(browser)` 增加與 Config/Commit 同級的 early-return arm，回 `ExternalOrUnknown`。不得只改 census。不得把 process-wide `enforce_global_config_schema_policy` 誤述為本 command 的設定讀寫，亦不得為此改動該全域 gate。
- **GC-MB-02 網路/秘密邊界：** `--server` 解析後拒絕 userinfo、fragment、query 及非 HTTPS/non-loopback HTTP。listing GET 不帶 token。TUI 寫入只按 ADR-MB-03 取 token；`reqwest` 禁 redirect/no_proxy；錯誤、JSON、trace 不得回寫 URL credentials、token 或 response body。
- **GC-MB-03 有界資源：** 一次請求固定 timeout、最大 response bytes、最大 items/name bytes；session cache 為 LRU/clear-on-exit 且有固定 entry/byte 上限。禁止 recursive prefetch、background refresh、N+1 parent fetch 或 `file_tree` walk。寫入失敗不自動重試超過 ER-10 預設。
- **GC-MB-04 文檔與跨倉邊界：** 變更 TUI 可見鍵或 browser flag 的卡依 ER-06a 先確認 `../libra-backend` 單一 VCS 型態並切到/核實 `cf`，再寫網站文檔；無法確認時該卡 blocked，不改寫其它 repo。
- **GC-MB-05 缺失表面不得假裝存在：** 禁止註冊任何第二個 `mega2` 子命令。對未 pin 或未掛載的 HTTP 路徑，TUI 不得綁對應鍵，help/docs 不得宣稱「已支援」。blocked 卡可以先寫內部 DTO 草稿於卡內正文，不得落地 production 鍵或子命令。
- **ER-MB-01 雙評審閉環：** 每次規範性修訂後以 source-grounded high-recall Codex **與** Claude Code 唯讀審查（2026-09-16 使用者覆蓋 2026-09-11 的 Claude N/A）。兩邊最終輸出都必須含字面 `VERDICT: PASS`；P0/P1 全數關閉並重審。最新一輪 Codex 與 Claude 未維持 `PASS` 前禁止把任何卡標 `in-progress`。
- **ER-MB-02 API pin gate：** 所有 implementation 卡開工前重核其 `DEP-MB-*` 的 monoengine revision、route、method、request/response 欄位與 auth form；任一不一致先停卡並建立跨倉契約修訂，不以猜測解析。
- **ER-MB-03 發布次序：** 實作與發布嚴格按「發布窗口順序」串行；每張獨立卡依 ER-08 patch bump + `gh` release，後卡基線須含前卡發布。blocked 卡不得 bump、不得綁 TUI 鍵。

### 發布分組與並發窗口

本計劃沒有家族/批次發布。有效卡凡進入實作都是 `independent` 切片，按 ER-MB-03 串行發布；R 寫集由唯一發布者鎖定。blocked 與已取消卡不進入發布窗口。

**並發聲明:** 實作階段 **不可**並行 MB-01 與 MB-04：兩者 I 寫集都含 `src/internal/protocol/mod.rs`。其餘卡因 `mega2_browser/`、`cli.rs` 或 `docs/commands/mega2.md` I–I 相交必須串行。R 寫集由唯一發布者鎖定。

**發布者:** `/root` 主代理；負責每張卡 C 組 bump、build、install、精確暫存、簽章提交、main/tag push、`gh release create` 與 D 組證據。未經計劃與修訂歷史改寫，不移交發布者。

**發布窗口順序:** `MB-01 -> MB-02 -> MB-03 -> MB-04 -> MB-05`；其後僅在對應 DEP 轉為 incoming-available 後接 `MB-07 -> MB-08` 與 `MB-10 -> MB-11`。同一時刻至多一張卡處於已 bump 未完成 push/release 的狀態。

**D-MB-STD（每張 independent 卡）:** `libra push origin main` 後確認 `.github/workflows/codeql.yml` job `analyze`（event=`push`, ref=`main`）success；`gh release create v<version>` 的 tag push 後確認 `.github/workflows/release.yml` jobs `build-and-upload`、`upload-install-scripts`、`update-homebrew-tap`、`verify-homebrew-formula`、`request-stable-manifest`（event=`push`, ref=`v<version>`）success，並確認 sanitized download URL 可取得。任一失敗只能前滾。

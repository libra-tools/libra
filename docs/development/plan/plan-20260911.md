# Mega 遠端目錄 TUI 瀏覽計劃（2026-09-11）

## 文檔職責

本文規劃 `libra mega browse`：以終端互動式介面按需瀏覽 monoengine storage-only 伺服器的 Git 目錄樹。交付物是可獨立發布的 Libra 唯讀命令；它不克隆倉庫、不讀取 blob 內容，也不新增 monoengine 寫入端點。

### 適用範圍

- 新增 `libra mega browse --server <base-url> [path] [--ref <commit-or-tag>]` 的 HTTP client、TUI 與 machine-readable 單層列舉模式。
- 消費 monoengine storage-only 的 `GET /api/v1/tree?path=<rooted-path>&refs=<optional>` 契約。
- 完成 CLI 註冊、輸出/錯誤契約、EN/zh-CN/網站命令文件、測試、版本發布與遠端 release 證據。

### 非目標

- 不在本計劃修改 monoengine 的 API、認證模型、資料庫或 Git 協定；發現契約不相容時 fail-closed 並依 `DEP-MB-01` 阻斷。
- 不做檔案內容預覽、編輯、下載、clone/fetch/push、遞迴全樹匯出、搜尋索引或本機目錄瀏覽。
- 不從 Git remote URL 猜測 HTTP endpoint，不把 token 放入 URL、設定檔、命令列或日誌；MVP 不帶 Authorization header。

### 成功定義

- 有權連到 storage-only 服務的開發者可在 TTY 中逐層進入/返回目錄，且每一次導航只取得目前一層。
- `--json` 可在非 TTY 以穩定 envelope 取得同一層資料；互動模式遇到非 TTY、無效 URL/path、非成功 HTTP、壞 JSON 或不可信目錄項目時拒絕而不寫本地狀態。
- 所有非延後卡皆完成、各卡 C/D 發布證據與最終 Codex review `PASS` 已取得；Claude Code review 依使用者指示為 N/A。

## 已決議設計決策

### ADR-MB-01: 一層、按需、fail-closed 的匿名 storage-only tree client

- **Status:** Accepted
- **Context:** monoengine 已在 storage-only 形態暴露匿名 `/api/v1/tree`，但 `file_tree` 會額外提供祖先資料，遠端 response、path 和文字皆不該被 TUI 當成可信輸入。
- **Decision:** `libra mega browse` 只以 `data.tree_items` 作目前層資料；每次 enter/back/reload 以目前 rooted canonical path 建一次 GET。base URL 必為 HTTPS，或是無 userinfo 的 loopback HTTP；client 禁用 proxy 與 redirects、設定 connect/request/body/entry/session-cache 上限。它只接受 `req_result=true` + `data` + `content_type in {directory,file}`；拒絕絕對/相對轉義、`..`、NUL、separator 或 terminal control item name，並忽略 server-provided `path` 作為導航依據。HTTP 401/403、4xx/5xx、超時、schema mismatch、non-TTY interactive 呼叫均回穩定、secret-free CLI error。
- **Alternatives considered:** 一次遞迴列舉（拒絕：大型倉庫無界 I/O/memory）；從 Git remote 推導 URL（拒絕：SSH/HTTPS Git remote 不含 API service endpoint）；接受任意 HTTP/URL bearer token（拒絕：中間人與 secret 進 history/log 的風險）；修改 monoengine 增設樹 API（拒絕：現有 contract 足夠，跨倉擴張非本卡目標）。
- **Consequences:** MVP 要求明示 `--server`，不支援帶憑證的私有 reverse proxy；此為 `DEFER-MB-01`。server `file_tree`、blob read 與一切 write endpoint 都不會被 client 呼叫。
- **Revisit when:** monoengine 正式 versioned API/credential transport 和 pagination contract 已發布並有相容矩陣。

### ADR-MB-02: TUI 僅屬於人讀模式；JSON 是單層純資料模式

- **Status:** Accepted
- **Context:** TUI 的 alternate screen、raw mode 和鍵盤事件不適合管線、agent 或 snapshot testing；現有 `OutputConfig` 已提供 JSON envelope。
- **Decision:** human mode 要求 stdin/stdout 都是 TTY，進 alternate screen，`Up/Down` 選擇、`Enter` 進 directory、`Backspace`/`h` 返回、`r` reload、`q`/`Esc` 離開；file 只顯示不開 blob。`--json`/`--machine` 禁止啟動 TUI，僅 fetch 初始目錄並用 stable `mega browse` JSON envelope 輸出 server/ref/path/items。TUI drop/guard 必定嘗試 restore terminal，錯誤保留原始操作脈絡但不回顯 URL userinfo/token。
- **Alternatives considered:** `--json` 同時跑互動介面（拒絕：破壞 machine output）；TUI 內預覽 blob（拒絕：內容、redaction 和容量另是行為軸）；在 terminal 上 raw print 不 restore（拒絕：shell session 可用性故障）。
- **Consequences:** 非 TTY 使用者可以 script JSON，不可得到 ANSI UI；為不恢復已退役的 Code UI crates/tokens，MB-02 只使用既有 direct `libc`（Unix termios/poll）與 `windows-sys`（Windows console mode/input）加 ANSI alternate-screen renderer。這個新 browser 與 Code runtime 無共享模組、crate 或 symbol，且必須保持 `compat_agent_architecture_guard` 綠色。
- **Revisit when:** a remote file-preview contract 的安全模型、內容大小上限與 redaction 要求已另行設計。

### Task MB-01: 實作有界 monoengine tree transport 與 wire validation

**Task type:** `implementation`

**Lifecycle / Acceptance:** `pending` / ``

**Description:** 在 `src/internal/protocol/mega_tree.rs` 建立唯一的 monoengine `/api/v1/tree` DTO、URL/path/item validation 與 bounded GET client。唯一行為軸是「將不可信的一層 server response 轉為可安全消費的 immutable listing」，不含 terminal 或 public CLI wiring。

**Out of scope:**

- 不註冊 clap `mega` command 或改 `src/cli.rs`（MB-03）。
- 不進 raw terminal/alternate screen 或處理鍵盤（MB-02）。
- 不讀 blob、遞迴、token/header、配置持久化或修改 monoengine（永久非目標）。

**Current evidence:**

| 事實 | 證據 |
|---|---|
| `reqwest`/URL construction pattern is already in-tree | `Cargo.toml:57`; `src/command/code_control.rs:130-145,503-593` |
| existing tree API returns ancestors plus requested listing; only `tree_items` is relevant | monoengine@`2ba236c`: `src/api/router/preview_router.rs:166-208` |
| successful envelope uses `req_result`, `data`, and strings `directory`/`file` | monoengine@`2ba236c`: `src/contract/api/common.rs:4-34`; `src/ceres/model/git.rs:149-171` |

**Acceptance criteria:**

- [ ] The one client accepts explicit base URL, rooted path and optional ref; it appends exactly `/api/v1/tree`, encodes query pairs, and sends no auth header.
- [ ] URL parser rejects credentials, fragment/query, unsupported scheme and non-loopback HTTP; client disables redirects/proxy and enforces finite connect/request/body limits.
- [ ] Path normalizer accepts only rooted, separator-normalized components and refuses empty traversal, `.`, `..`, NUL or platform separator ambiguity.
- [ ] Parser requires HTTP success, `req_result=true`, non-null `data`, supported `content_type`, unique safe names and bounded item/name counts; it ignores `file_tree` and remote item `path` for authority.
- [ ] Transport/protocol errors map to existing suitable stable network/usage errors without emitting response body or sensitive URL material; no production unwrap/expect is introduced.
- [ ] Listing preserves server item data only after validation and exposes deterministic directory-first/name ordering to its consumer.
- [ ] Session request/cache accounting has fixed request/item/byte bounds and has no recursion, prefetch or background task.
- [ ] Focused mocked HTTP tests cover correct query encoding, valid result, 401/500/timeout, malformed envelope, hostile entries/path and limit rejection.

- [ ] `source .env.test && LIBRA_SKIP_WEB_BUILD=1 cargo test --lib internal::protocol::mega_tree` (new)
- [ ] `source .env.test && LIBRA_SKIP_WEB_BUILD=1 cargo test --test command_test mega_tree_transport` (new)
- [ ] Sanitized mock-server trace proves exactly one `/api/v1/tree` request per listing and zero local repository writes.

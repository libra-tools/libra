## 范围、非目标与成功定义

### 范围

- 在仓库数据库中加入 AgentKind::Pi 与 agent_session.agent_kind=pi，并用 role-aware migration registry 将 migration 限于 Repository。
- 读取 Pi 固定上游版本的 v3 session JSONL，安全发现、归一化、显式导入与 coverage/checkpoint 回填。
- 交付 Pi extension 到 libra agent hooks pi 的受控实时事件摄取，随后在独立卡提升为 libra agent enable/disable/list 的 supported Agent。
- 对 libra cloud sync 加 Pi capture 兼容围栏：本地 Repository DB 含 agent_kind=pi 时，在任何 D1/R2 请求、ensure、远端 catalog 读取、对象上传或本地 synced flag 改写前失败；既有远端备份保持不变。

### 非目标

- 不修改 src/utils/d1_client.rs、D1 表、D1 migration、R2 object layout、远端 restore catalog 或云端 Pi 数据恢复。
- 不把 Pi extension 改成 mode json / RPC 子进程，也不把任意文本拼进 shell 或 argv。
- 不支持 Pi v1、v2 或未知 session format；不猜测时间戳、文件名或任意数组末尾作为活动叶（固定 pin 的 `_buildIndex` 磁盘恢复规则例外，见 ADR-PI-03）。
- 不修改 plan-long.md；不修复 plan-20260910.md 的 role registry 或 config writer 工作。

### 成功定义

- pi 可以以 v3 transcript 被显式导入，重复导入不重复写 checkpoint；畸形、旧版和未知新版均带可操作错误且不落部分 checkpoint。
- Pi hooks 只经固定子命令和 stdin JSON 进入，持久化前经过已有 redaction/ownership/dedup 边界；乱序 tool result 有有界、可重放状态，不能静默丢失。
- cloud sync 的入口 preflight 发现任意 Pi capture 时退出 128 与既有 LBR-CONFLICT-002，说明 Pi capture 目前仅本地可用；该次调用零远端副作用，旧云备份不被修改。cloud restore 不承诺恢复 Pi capture，因为本计划从不上传它。
- 每卡完成 A/B/C/D 门、独立版本发布和 Codex review；全卡后 cargo test --all 绿色；Codex 与 Claude Code 的最后字面 verdict 均为 PASS。

## 决策记录

### ADR-PI-01：本地 schema 与云端兼容边界分离

- 决定：2026091101 只重建 Repository DB 的 agent_session CHECK，为原七值加 pi；保持列、FK、索引、trigger、已有行和版本顺序。没有 Pi D1 DDL、widen ledger 或先上传再回滚逻辑。
- 理由：cloud snapshot 还有 generation、tombstone、claim、revision 与 link；当前调用顺序无法把它们与旧客户端/restore 读路径置入可证明的原子迁移。局部 widen 会造成 silent loss、旧表读取或不可恢复删除。
- 后果：Pi capture 是本地事实；不能 backup/restore Pi capture 在 PI-05 同卡命令文档明确说明。未来 D1 支持另开设计并复核全 graph。

### ADR-PI-02：云端保护是总入口本地 preflight、任何远端副作用前的 typed fence

- 决定：run_cloud_sync 在取得本地 DB connection 后、validate_cloud_backup_env、ensure_repo_id、D1Client::from_env、所有 D1 ensure/repository upsert、R2 storage 和 object/metadata sync 前调用 reject_pi_cloud_sync_before_remote(db_conn)。helper 先检查 agent_session 表是否存在；存在时以只读 EXISTS 查询任一 agent_kind=pi。命中即返回 typed CloudError::PiCaptureLocalOnly，并在 sync 的 into_cli_error 映射既有 ConflictOperationBlocked / LBR-CONFLICT-002。
- 不变量：helper 不调用 load_agent_capture_snapshot，因为后者属于 agent mirror 后置路径；它对当前 Repository DB 的所有 agent_session 行作保守判定。fence 前不得发出 D1/R2 请求、创建 repo row、上传对象/metadata、更新 is_synced 或 remote generation。错误说明 Pi capture is local-only; no cloud data was changed，且不带 transcript 或私有路径。
- 验证：Pi fixture 在 D1/R2 env 缺失时也必须优先得到 Pi conflict，证明未进入 env/client path；recording seam 证明 Pi case 的 remote-call、R2 upload、repo-upsert、sync-flag mutation 均为零；另测无 Pi DB 保持原远端调用顺序。只测 pure predicate 不算通过。

### ADR-PI-03：Pi v3 以上游树叶为唯一活动分支依据

- 决定：实时 hook 一律取 `ctx.sessionManager.getLeafId()`；磁盘 normalizer 则精确复现固定 revision 的 `SessionManager::_buildIndex` 恢复规则：从 null 开始，按 JSONL 文件序跳过 `session` header，对每个已验证的 non-session entry 依次覆盖 leaf，故最后一个 non-session entry 才是该 upstream 的恢复 leaf。它不是 Libra 的时间戳、文件名或任意数组末项猜测；parser 必须以 source-pinned fixture 锁定这一算法，不能在 revision 漂移时继续导入。随后由 parent 链从该 leaf 回溯，检验整个 active path。
- compaction 按 firstKeptEntryId 保留范围：范围前历史降级 incomplete，digest 只覆盖恢复出的 active leaf 分支。header-only 是合法 zero-turn；v1/v2/unknown/断枝只产生具名拒绝或 zero-turn，不产 checkpoint。
- 拒绝：最新 timestamp、无来源的 leaf fallback、header-only 假 session、未知 version 的 best effort。Pi source pin 或其 `_buildIndex` 行为不可复验时，PI-03 blocked。

### ADR-PI-04：hook 事件固定 stdin envelope、持久有界状态

- 决定：Pi extension 安装目标只限固定 upstream Pi 的 canonical project-local `.pi/extensions/libra-hooks.ts`；rebranded config root、global extension 与 settings.json 注入均不支持。安装先 canonicalize 项目根；不写/不改变 Pi trust state，依靠 Pi 对 project-local extension 的既有 trust gate，且 extension 在任何 project-local read 或 forwarding 前检查 `ctx.isProjectTrusted()`，不可信即零副作用返回。若未来 extension 需要构造除已安装 asset 外的 Pi project config 路径，必须 import `CONFIG_DIR_NAME`，不得硬编码 `.pi`。
- asset 第一行是版本化精确 Libra-owned marker；install 遇到无 marker 的同名文件返回可操作错误且零覆盖，update 只覆盖 marker-owned 文件，disable 只删除 marker-owned 文件并幂等。写入采用 parent-dir canonical/anti-symlink 检查、临时同目录文件 + rename 的原子提交和 restrictive permissions。extension 从 event 只白名单提取 provider/session/immutable-id/受限 content 字段，canonical JSON 单 envelope 最大 1 MiB；禁止 `{...event}` 或任何未界定 blob 进入 serializer。既有 Rust receiver 是 redaction 的唯一事实源，且在任何 durable write 前处理该受限 envelope。模板仅嵌入 `resolve_hook_binary_path` 产出的 JSON-encoded canonical absolute executable；以 `node:child_process` 的 `spawn(executable, ["agent", "hooks", "pi", verb], { shell: false, stdio: ["pipe", "ignore", "ignore"] })` 启动，verb 只可为 compile-time allowlist。JSON 写 stdin；prompt/tool bytes 不进 argv、shell source、环境或日志。
- identity：session-start/session-end 使用 `(provider_session_id, fixed_lifecycle_verb)`，prompt 使用 Pi message entry ID，tool 使用 toolCallId，turn/compaction 使用 live `getLeafId()` 或 upstream immutable compaction entry ID；某 event 缺少其要求的 immutable ID 时不 forward，记录脱敏最小 diagnostics。`turnIndex` 只可作为 diagnostic，绝不是跨进程主键。
- 映射：session_start 到 start；user message_end 到 prompt；turn_start 到 turn-start；tool_call/tool_result 到 tool-use（同一 tool_use_id 更新）；turn_end 到 stop；session_before_compact 到 compaction；session_compact 到 compaction-completed；session_shutdown 到 session-end。assistant message_end 不伪造 prompt；无关 event 只记最小 diagnostics 后跳过。
- 乱序与重放：runtime 在 SessionState metadata 和 session lock 内存 pending tool result，按 pi session/tool_call_id/phase 去重；最多 64 项、canonical JSON 总量不超过 1 MiB、300 秒惰性过期。超限或无法配对返回 LBR-CONFLICT-002 供 extension 重试，绝不静默删数据。

### ADR-PI-05：public roster 只在 hook path 完整验证后提升

- PI-02 将 Pi 注册为 preview/unsupported，不令裸 agent enable 安装；PI-04 先验证 receiver/extension；PI-06 同卡更新 registry、capability pin、list、enable/disable、roster docs 与 live smoke 为 supported。
- 这样避免可安装但不能安全采集的半实现公开 surface。PI-06 失败时可回退 registry/install exposure，不影响 PI-03 已导入本地数据或 PI-05 cloud fence。

## 文档职责

本文为 Libra 的外部 Agent 捕获补上 Entire CLI 那种决策中层里缺的一块：在 `HookTarget::AgentTraces` 的 ingest 路径上，用纯函数 `session_capture::decide` 决定 SQLite `agent_session.state` 字符串和 checkpoint 写入类别。OpenCode、Codex、Claude Code、Pi 的既有采集计划继续做 parser、extract、coverage、安装与 migration。它们若要改这条 ingest 上的决策，必须改 `decide`。它们的实现写集若包含 `src/internal/ai/hooks/runtime.rs`，必须等 SCAP-01 完成后再开工，避免与本卡并发改同一文件。

本文不实现那些计划里的采集缺口。范围只有 OpenCode、Codex、Claude Code 和 Pi。

### Entire 中层与 Libra 的对应

Entire 的 Session Capture 中层分三块：事件平面（`ParseHookEvent`）、决策平面（`session.Transition` 只返回动作）、执行平面（dispatcher 做校验和 I/O）。

Libra 的 AgentTraces 路径已有事件平面和写入函数。缺的是决策平面：state 字符串和 checkpoint 类别还写在 ingest 的两处 `matches!` 里。`transition_phase` 已经是纯函数，但它服务另一条 `AiIntent` 路径，不能当成 SQLite 列的事实源。

本计划只把 AgentTraces ingest 的那张表收成 `decide`。表的内容与核对日代码相同。

## 已决议设计决策

### ADR-SCAP-01: `decide` 只负责 AgentTraces ingest 的一张表

- **Status:** Accepted
- **Context:** `runtime.rs:750-756` 与 `:928-935`、`:1008-1011` 是同一组 kind 的两个结果。这是 `ingest_agent_traces_payload_with_scope` 里的决策，不是全进程唯一的 state 写入点。
- **Decision:** 在 `src/internal/ai/hooks/session_capture.rs` 定义：

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub(crate) enum CheckpointWrite {
    None,
    Committed,
    SubagentBoundary,
}

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub(crate) struct CaptureDecision {
    pub session_state: &'static str,
    pub checkpoint: CheckpointWrite,
}

pub(crate) fn decide(kind: LifecycleEventKind) -> CaptureDecision
```

`decide` 在本 crate 内穷尽匹配，没有 `_` 臂。`hooks/mod.rs` 增加 `mod session_capture;`。`runtime.rs` 通过 `super::session_capture::decide` 调用。

| `LifecycleEventKind` | `session_state` | `checkpoint` |
|---|---|---|
| `SessionStart` | `active` | `None` |
| `TurnStart` | `active` | `None` |
| `ToolUse` | `active` | `None` |
| `ModelUpdate` | `active` | `None` |
| `Compaction` | `condensed` | `None` |
| `CompactionCompleted` | `active` | `None` |
| `PermissionRequest` | `active` | `None` |
| `SourceEnabled` | `active` | `None` |
| `SourceDisabled` | `active` | `None` |
| `TurnEnd` | `active` | `Committed` |
| `SessionEnd` | `stopped` | `Committed` |
| `SubagentStart` | `active` | `SubagentBoundary` |
| `SubagentEnd` | `active` | `SubagentBoundary` |

upsert 使用 `session_state`。checkpoint 块在 `checkpoint != None` 且 `repo_path` 为 `Some` 时进入。`SubagentBoundary` 调用现有 `write_subagent_checkpoint`。`Committed` 保留现有 else 分支。不搬迁函数体。`process_hook_event_with_target` 的文档改为：checkpoint 类别来自 `decide`，覆盖 TurnEnd、SessionEnd、SubagentStart、SubagentEnd。

- **Alternatives considered:** 把 `transition_phase` 并进来会改变 badge 或 SQLite 列。把函数放到 `src/internal/ai/mod.rs` 会和 plan-20260819 的写集相交。
- **Consequences:** 以后在这条 ingest 上改表，只改 `decide`。新增 `LifecycleEventKind` 的卡必须同时改 `decide`，否则编译失败。那张卡还要等 SCAP-01 完成。
- **Revisit when:** 上表任一行要改，或 kind 增加。

### ADR-SCAP-02: 相邻门保持原处

- **Status:** Accepted
- **Context:** owner 豁免、`stopped_at`、AiIntent 相位、session 命令和 import 已经各有写入点。
- **Decision:** 不改 `runtime.rs:709-712` 的豁免，不改 `:730-747` 的跳过，不改 `:863-864` 与 `:839-840` 的 `stopped_at`。不改 `transition_phase`。不改 `session.rs`、`agent_import.rs`、`coverage_gate.rs`、`status.rs`、`clean.rs`。`decide` 不接收路径、prompt 或 transcript。
- **Alternatives considered:** 让 `stopped_at` 从 `decide` 推导。UPDATE 语句已经用 `state = 'stopped'` 决定是否刷新，INSERT 仍用 `:863-864`。两处一起搬会变成第二个行为轴。
- **Consequences:** 内部文档必须列出这些非归属点。
- **Revisit when:** 单独的计划要改 owner 过滤或 `stopped_at`。

### ADR-SCAP-03: 语义阻塞和文件阻塞分开

- **Status:** Accepted
- **Context:** 多数采集卡不改这张表。另一些卡的写集含 `runtime.rs`，即使不改表也不能和 SCAP-01 并发。
- **Decision:** `DEP-SCAP-01` 只阻塞「修改 AgentTraces ingest 的 state 字符串或 checkpoint 类别」的卡。`DEP-SCAP-03` 阻塞写集含 `src/internal/ai/hooks/runtime.rs`、且尚未开工的具名卡，直到 SCAP-01 `Lifecycle=done` 且 `Acceptance=complete`。名单：OG-11、OG-05、CX-06、CX-28、CX-02、CX-07、CX-19、CX-09、CX-26、CC-02、CC-05、PI-04。`DEP-SCAP-04` 是与已可开工的 `plan-20260907` B3-00 的互斥：双方都写 `runtime.rs`，不得同时 `in-progress`。先完成的一方之后，另一方再改该文件。PI-01 的 migration 不在这两份名单里。
- **Alternatives considered:** 阻塞四份计划的每一张卡。PI-01 与 OpenCode parser 不写 `runtime.rs`。
- **Consequences:** SCAP-02 核对已写入的关系表一行，缺行才补。不改那些卡的 AC。
- **Revisit when:** 某张未列入的卡把 `runtime.rs` 加进写集。先改本 ADR 与关系表，再让它开工。

**D 组:**

| 项 | workflow / job | 触发 | 判据 |
|---|---|---|---|
| D1 | `release.yml` 的五个 job，名字以当时 `jobs:` 节点为准。核对日为事实基线里的五个 | C 组 tag push。event=`push`，head SHA 等于 merge SHA | `gh run view` 的每个 job `conclusion` 为 `success` |

```bash
set -euo pipefail
VERSION="$(sed -n 's/^version = "\(.*\)"/\1/p' Cargo.toml | head -n1)"
test -n "$VERSION"
REPO="$(gh repo view --json nameWithOwner --jq .nameWithOwner)"
MERGE_SHA="$(gh api "repos/${REPO}/commits/v${VERSION}" --jq .sha)"
test -n "$MERGE_SHA"
RUN_ID=""
i=0
while [ "$i" -lt 60 ]; do
  RUN_ID="$(gh run list --workflow=release.yml --commit "$MERGE_SHA" --json databaseId,event,headSha,conclusion --jq "[.[] | select(.event==\"push\" and .headSha==\"$MERGE_SHA\" and .conclusion==\"success\")][0].databaseId")"
  if [ -n "${RUN_ID}" ] && [ "${RUN_ID}" != "null" ]; then
    break
  fi
  i=$((i + 1))
  sleep 30
done
test -n "${RUN_ID}"
test "${RUN_ID}" != "null"
gh run view "$RUN_ID" --json jobs | jq -e '[.jobs[].conclusion] | all(. == "success")'
gh run view "$RUN_ID" --json jobs | jq -e 'def has($p): any(.[]; startswith($p)); [.jobs[].name] | has("build-and-upload") and has("upload-install-scripts") and has("update-homebrew-tap") and has("verify-homebrew-formula") and has("request-stable-manifest")'
CODEQL_OK="0"
j=0
while [ "$j" -lt 60 ]; do
  CODEQL_OK="$(gh run list --workflow=codeql.yml --commit "$MERGE_SHA" --json conclusion,headSha --jq "[.[] | select(.headSha==\"$MERGE_SHA\" and .conclusion==\"success\")] | length")"
  if [ "${CODEQL_OK}" -ge 1 ]; then
    break
  fi
  j=$((j + 1))
  sleep 30
done
test "${CODEQL_OK}" -ge 1
```

上面的脚本自身轮询最多 60 次、间隔 30 秒。任一断言失败都会因为 `set -euo pipefail` 退出。超时则 `remote-pending`。五个 job 的名字以执行当日的 `release.yml` 为准。

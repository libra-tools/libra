## 文档职责

先证明现成平台能够可信地执行 Libra 仓库记忆评测，再研究同一 agent 的修复收益。首个里程碑只接通一个真实样例的无模型链路，复用平台的配置、批次、结果与轨迹界面；不自建通用实验管理系统。

### 适用范围

- 冻结任务、公开代码/历史视图、agent 提交补丁、私有 evaluator 判分、结果导出的完整协议。
- Harbor 本地 Docker/jobs/viewer 的有界验证；openEuler Agent Insight 是候选，不同时部署两套平台。
- 来源隔离、失败留存、四臂配置身份、资源上限和 go/no-go 交接。全部运行在独立远端工作区，本机不编译。

### 非目标

- 本 PR 不运行评测平台、agent 模型或评测容器，不下载评测镜像，不修改 Rust、schema、公开 CLI、版本面或工作流。
- 本阶段 spike 不改生产代码，不承诺将临时 adapter 当成正式 benchmark 产品；需长期维护的代码另立 implementation 小 PR。
- 不重复开发已合入的基础存储，不在 adapter 中自造 Episode/path 召回，不恢复比赛 API，不合并或发布产品 PR。
- B2 修复、生产 consumer、真实 agent pilot、正式留出及 SWE-CI 维护执行分别有外部依赖/后续开工门；本计划不会把平台接通当成它们已经完成。

### 成功定义

交付可重取的冻结配置、真实样例接入记录及失败用例，回答平台是否符合下述协议、还缺什么，并形成明确 go/no-go。go 只表示可以继续准备生产 consumer 与真实四臂；不表示 Memory 有质量收益。调查完成与能力通过是两件事：有可复核失败的 no-go 也是有效调查结论，不把失败改记 pass。不能靠换题、移动 cutoff、删除失败或改用 LLM judge 获得 go。

**有界 no-go 路径：** 每个 spike 的验收是如实回答本卡问题，记录每项 capability=pass/fail/not-run 及理由、实际退出码和诊断；测试命令非零是被记录的失败，不能包装为“检查器成功所以能力通过”。必需能力失败或时间箱耗尽时停止本轮、精确清理，在本页登记 STOP 与 DEFER-BM-04 中的具体未执行卡及原因。BM-05 读取已有失败和正式延后记录作 no-go 交接，不要求继续花资源执行依赖已失败的探针。无结果/缺回执不能冒充有效调查完成；必需项含 fail/not-run 就不能给 go。

## 已决议设计决策

### ADR-BM-01：先验证 Harbor，保留 Agent Insight 候选

- Status：Accepted for spike；未作生产平台最终选择。
- Decision：先用 Harbor 本地 New run/jobs/viewer、custom BaseAgent、显式 separate verifier；不注册 Hub 或启第三方 tracking。
- Evidence：[固定 New run](https://github.com/harbor-framework/harbor/blob/f6cf2e2e86a102a9d2980ce8888f4bda251aa998/apps/viewer/app/routes/run.tsx)、[separate verifier](https://docs.harborframework.com/tasks/separate-verifier)。未配置 mode/environment 的兼容默认仍是 shared。
- Alternative：openEuler Agent Insight 已有真正 Benchmark Manifest/Adapter/Evaluator；但 [Benchmark UI 仅单组](https://github.com/openeuler-mirror/agent-insight/blob/eabde5b02f69797fe7e09b446b3f178374325d82/src/components/eval/ExperimentWizard.tsx#L2202)，[原生 xGovernor](https://github.com/openeuler-mirror/agent-insight/blob/eabde5b02f69797fe7e09b446b3f178374325d82/services/executor/src/xgovernor/backend.cjs#L74) 不接受通用 agentOptions，需核对 Runtime/Profile 与预算穿透。Harbor 关键门失败或已有团队部署优势时，先修订本 ADR，再用同一协议验证它。
- Consequences：适配边界保持平台中立；不同时维护两套 runner。Inspect AI/Braintrust/Langfuse 等仅在已选平台不能满足实际需求时重新比较，不默认增加 SaaS 或数据出口。

### ADR-BM-02：公开执行与私有评分分离

agent 只接收公开题面、准入代码/历史视图和所选 arm 工具；提交 candidate.patch。Gold、hidden test、目标 fix 映射、原始 oracle 日志和资格 reference patch 均在 evaluator。参考补丁仅用于 evaluator 资格检查，不能作为 stub 提交物或平台 dataset expected。每次评分从冻结 base 的新环境开始，不继承 agent 可写目录。候选 artifact 一律不可信：先校验格式/大小/路径，再拒绝修改受保护的 evaluator-owned tests、harness、pytest 配置/插件加载面、根/测试目录 conftest.py、sitecustomize.py/usercustomize.py 和结果/reward 路径。冻结具体路径/配置节 allowlist；需要改受保护面的任务必须在采样前判为本协议不支持，不能事后忽略改动或放宽策略。

应用顺序：验证 base 与保护面 hash → 只应用允许的 candidate source diff → 独立恢复/只读挂载 evaluator 的冻结测试与 runner 配置 → 低权限、断网子进程运行必要 pytest → 可信外层 verifier 校验完整预期 node 集和状态后生成 reward。候选测试进程无权写父级接受的 reward/报告目录，agent artifact 自带的 reward/JUnit 不被采信。参考补丁与原始映射不放进候选执行进程；不把评分日志反馈给仍活跃的 agent。BM-07 用“修改断言”和“新增 pytest_pyfunc_call hook 跳过测试体但保留 node 名”的有效仓库路径补丁做负控，必须拒绝或判未修复。此门验证明确的防篡改控制，不宣称任意恶意 Python 代码的通用安全证明。

最终成功要求所有必要 F2P 通过且 P2P 无回归；完整 node 覆盖缺失、超时或解析失败都不能成功。

### ADR-BM-03：证据独立于 UI 生命周期

权威记录是版本化 manifest 与 append-only ledger，key 为 task_alias×arm×seed×attempt，另记录 phase/qualification_kind。run ID 只定位物理运行；重试使用新 attempt，重评分另有 evaluation ID，均引用原 patch/config digest，不能覆盖旧失败。平台只读它的允许字段副本，重新上传不得重新跑 agent。

## 全局工程约束

继承模板 GC-01..13。追加约束：

- GC-BM-01：复用已有 SWE-rebench、Pro V2、SWE-CI 固定元数据和首轮 manifest；不全库重下。原 cutoff 不移动；strict_time、base_snapshot、guided/unguided 分开计数。
- GC-BM-02：clone/index 不替代 commit→change→Episode 导入；只走正式 writer/公共 CLI，不向事实表灌记录，不伪造历史 agent 成功。
- GC-BM-03：sealed agent 视图必须排除额外 Git 对象、refs/reflog/alternates/promisor/hooks、原始评测资产与共享 DB；checkout/reset 不是完整隔离。M0 工具与磁盘均不提供历史。
- GC-BM-04：工具环境从启动即断网，模型在可信 host 控制面调用；不暴露 host shell、Docker socket、provider web/MCP。核对实际 merged compose/inspect 和出站探针，不只读 policy 字段。
- GC-BM-05：同 agent binary/model/prompt/tool 协议与总预算；Memory 索引/检索/往返计入预算，冷/热启动分别记录。缺 usage 记 unknown，不能当 0；seed 不支持则记录，不宣称确定性。
- GC-BM-06：无模型阶段并发 1；每个执行/评分阶段 30 分钟硬超时，容器上限 2 CPU/4 GiB，单 run 新增空间 10 GiB、整阶段 20 GiB（含镜像），先测余量再拉取，超限停止并保留失败回执。stage wall-clock 也受各卡时间箱约束。
- GC-BM-07：使用独占、拒绝覆盖的远端 BENCH_RUN_DIR；先有基线配置再启动，不复用旧 run 目录。模型请求数必须为 0，关闭 Harbor 默认 telemetry；viewer 只监听 loopback，经可信 SSH 使用。
- GC-BM-08：导出字段采用白名单；不上传私有测试、reference answer、原始 evaluator 日志。Braintrust Harbor 插件默认会导出 reference answer/附件，故不直接启用。UI 缺分/均值不能改写完整分母。
- GC-BM-09：只清理本轮 manifest 列出且已冻结证据、无活动引用的中间产物；不做全局 prune，不删除其它工作区、原始数据或旧证据。

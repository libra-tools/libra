## 文档职责

本文收口 2026-09-17 DEFER-NP-02 执行期在本机 `cargo test --all` 上暴露、且**已证明与 nextest 分组无关**的两笔测试卫生债：

1. **`src/` 串行锁对不上**（`serial_test` 无 key 只锁空串，与 `#[serial(env)]` 互不排斥）。
2. **`command_test` 高并行 CLI spawn 压垮**（空 stderr 非零退出 + 整进程 SIGKILL）。

目标是：`cargo test --lib` 不再因 HOME / `LIBRA_TEST` / `LIBRA_CONFIG_GLOBAL_DB` 互踩而剥落；`cargo test --test command_test` 在本机默认线程数下不再因空 stderr / SIGKILL 假红。权威全量门仍是 nextest（已绿，本计划不得把它变红）。

### 适用范围

- `src/**` 的 `#[cfg(test)]` 串行属性与进程环境读写（`HOME`、`LIBRA_*`、cwd、hash kind）。
- `tests/SERIAL_CLASSIFY.sh` 增加可选 `src/` 扫描面；新增 `tests/SRC_SERIAL_REGISTRY.tsv`（**不**喂给 `NEXTEST_GROUPS.sh`）。
- `tests/compat/serial_registry.rs` 增加 src 侧守卫。
- `tests/command/mod.rs` 的 CLI spawn / `assert_cli_success`（进程内并发上限 + 失败诊断）。
- 承接并关闭 `plan-20260825.md` `DEFER-PS-05`（重启理由改为正确性剥落，不是耗时）。
- 开发文档 / 测试索引 / `plan-long.md` 日期索引一行。

### 非目标

- **不改** nextest 分组、`tests/SERIAL_REGISTRY.tsv` 既有 tests 行、`.config/nextest.toml` 成员或 `ADR-NP-01` 补集规则。
- **不把** `src/` 行并入 nextest `external` 组。
- **不把** `CLAUDE.md` 权威三门从 `cargo test --all` 迁到 nextest（`DEFER-NP-04`，仍归 `plan-20260827.md`）。
- **不要求** `src/` 清零全部无 key `#[serial]`（那是 TA-03 在 `tests/**` 的目标；在 `src/` 上会把 `--lib` 收成一条 cwd+env+hash_kind 车队）。
- **不新增** `#[serial(cli_spawn)]` 这类闭集外键（会被 ADR-NP-01 送进 `external`）。
- **不改** merge / add / commit 生产算法，不改 `libra add` TTY 摘要契约（#499 已在 `9a24b06` 修测试）。
- **不做** fixture 磁盘模板缓存（`DEFER-NP-01` / `DEFER-PS-07`）。
- **不改** SQLite schema、公开命令、错误码、COMPATIBILITY 用户面。

## 已决议设计决策

实现时若需偏离本节，必须先改本计划，不得在代码里默改语义。

### ADR-SH-01: `src/` 注册表不进入 nextest 组

- **Status:** Accepted
- **Context:** ADR-NP-01 规定 `.config/nextest.toml` 只由 `tests/SERIAL_REGISTRY.tsv` 生成。`src/` 单测编进 `--lib`；一测一进程下 cwd/env/hash_kind 锁无跨进程意义。把 `src/` 行喂进生成器，要么无操作，要么因全宇宙五键把 lib 测推进 `external`。
- **Decision:** 新增 `tests/SRC_SERIAL_REGISTRY.tsv`（或 SH-00 普查表经 SH-02 转正），**只**服务 `--lib` 锁卫生与 drift 守卫。`NEXTEST_GROUPS.sh` 继续只读 `SERIAL_REGISTRY.tsv`。守卫必须断言：src 注册表变更前后 `NEXTEST_GROUPS.sh --stdout` 与工作树 `.config/nextest.toml` 对 `external` 成员字节一致。
- **Alternatives considered:** 合并进 `SERIAL_REGISTRY.tsv`（拒绝：一组两语义，补集规则会把 lib 测送进 `external`）；不建表只靠守卫（拒绝：转换无理由列、无法 review）。
- **Consequences:** 两份注册表。文档必须写明「tests 行 → nextest；src 行 → 只锁」。
- **Revisit when:** 若 `--lib` 也改为一测一进程且不再跑 `cargo test --lib` 多线程。

### ADR-SH-02: 只转换「碰进程全局」的 `src/` 用例，fail-closed 扩到闭集而不是全宇宙

- **Status:** Accepted
- **Context:** TA-03 在 `tests/**` 把无 key 清零，是为拆空串车队。`src/` 的问题是**锁对不上**：无 key 车队与 `env` 车队并行。若把 363 条无 key 全写成 `#[serial(cwd, env, hash_kind)]`，`--lib` 会收成一条更大的车队，且分类器对生产 helper 几乎全判 `global`。
- **Decision:** 转换集合 = 下列并集，且 **只改属性行**（继承 GC-NP-01）。`touches` 必须含**传递助手**，不得只做当前函数体的字面 `set_var` 扫描：
  - `env`：直接 `set_var`/`remove_var`/`ScopedEnvVar`/`EnvVarGuard`/`EnvGuard`/`ConfigDbFixture`，或调用 `setup_with_new_libra_in` / `setup_clean_testing_env_in` / `command::init::init`（`init` 读进程 `LIBRA_CONFIG_GLOBAL_DB`；层测剥落就炸在 `src/utils/test.rs:412`），或子进程未 `env_clear` 却读 `HOME`/`LIBRA_*`（`opencode_export_offline_sandbox_profile`）；
  - `cwd`：`ChangeDirGuard` / `set_current_dir` / `current_dir`；
  - `hash_kind`：`set_hash_kind`。
  1. 无 key `#[serial]`，且普查 `touches!=none`；
  2. **没有任何** serial、但 `touches!=none` 的用例；
  3. `src/` 内全宇宙五键 → 收窄为分类器能证明的闭集 `{cwd, env, hash_kind}`（已有手写外部键如 `cloud_live` **单独**保留，不得再和闭集绑成五键）；
  4. 相邻双属性（keyed + 无 key）删掉无 key 那一行。
- 注册表 / 普查主键是 `file` + `fn`，**不是**裸 `fn`。`src/` 里已有重复短名（`scopes_are_isolated`、`from_resolved_env_errors_when_no_layer_supplies_api_key`）。
- 已具名且正确的键（`env`、`sandbox_env`、`rpc_path_env`、`export_sandbox_env`、`cwd`、`hash_kind`）不动，必要时**并入**闭集中缺失的 lane（例如只 `export_sandbox_env` 但读了 `HOME` → 加 `env`）。
- **不**把「无 key 且不碰进程全局」清零。那批仍只锁空串，彼此串行、与 `env` 车队并行——这是可接受残留，登记 `DEFER-SH-01`。
- fail-closed `global`（body 划界失败）若该用例已在转换集合内 → `#[serial(cwd, env, hash_kind)]`，**禁止**再展开 `cloud_live` / `workspace_failpoints`。
- **Alternatives considered:** 全量清零无 key（拒绝：`--lib` 车队）；只修三条实测失败（拒绝：24 fail 证明是类，不是例）；改 `serial_test` 让无 key 隐含 env（拒绝：改第三方语义）。
- **Consequences:** `src/` 仍允许无 key serial；常驻守卫是「碰全局必须具名」+「禁止五键」，不是 `no_unkeyed`。
- **Revisit when:** 需要把 `--lib` 墙钟压下去，或 `DEFER-SH-01` 被升格。

### ADR-SH-03: 分类器扩面不得改变 `tests/**` 裁决

- **Status:** Accepted
- **Decision:** `SERIAL_CLASSIFY.sh` 增加 `SERIAL_CLASSIFY_TREE=tests|src`（默认 `tests`）。`TREE=tests` 的 stdout 必须与 SH-01 开工前冻结基线字节一致。`TREE=src` 的行进入 src 注册表，不进 `SERIAL_REGISTRY.tsv`。
- **Alternatives considered:** 复制一份 `SRC_SERIAL_CLASSIFY.sh`（拒绝：双份 allowlist 必漂）；默认扫描 both（拒绝：破坏现有守卫假设）。
- **Revisit when:** allowlist 需要为 `src/` 生产 helper 单独增补（只许加、不许改 tests 裁决）。

### ADR-SP-01: spawn 压力用进程内信号量，不用新 serial 键

- **Status:** Accepted
- **Context:** 空 stderr + 整进程 SIGKILL + 隔离绿 + nextest 绿，指向「一个 `command_test` 进程里同时活着太多 CLI 子进程」。新键 `cli_spawn` 在 ADR-NP-01 下是外部键，会把大量 merge 推进 `external`，抵消 DEFER-NP-02。
- **Decision:** 在 `tests/command/mod.rs` 的 `base_libra_command` / spawn 路径上加**进程内**并发上限（`std::sync` 信号量或等价 RAII）。默认上限写入常量，可用 `LIBRA_TEST_CLI_SPAWN_LIMIT` 覆盖（正整数；缺省或非法 → 默认）。`assert_cli_success` 必须报告 `status`（含 signal）、stdout 前缀、stderr。
- 默认上限由 SP-00 决定，且 **必须 ≥ 单测内同时存活的 CLI 子进程峰值**（现网至少：`service run` 占 1 个槽再 spawn 其它 CLI；`worktree add` 三子进程锁屏障）。上限小于该峰值会在 **nextest 一测一进程** 下死锁，违反「不得把 nextest 变红」。未完成 SP-00 不得写 `1`。
- 限流计的是**仍在运行的 child**，`output()`/`wait` 结束后必须释放许可。
- **Alternatives considered:** `#[serial(cli_spawn)]`（拒绝：污染 nextest）；`.cargo/config.toml` 全局 `test-threads=1`（拒绝：惩罚全部 target）；忽略因为权威门是 nextest（拒绝：用户要求收口；`cargo test --lib` 边角 CI 仍在）。
- **Consequences:** 只减 cargo-test 单进程的瞬时子进程峰值；nextest 墙钟不变。
- **Revisit when:** SP-00 证明根因不是资源压垮而是隔离泄漏（那时本 ADR 作废，改隔离卡）。

### ADR-SP-02: spawn 轴先取证再改默认上限

- **Status:** Accepted
- **Decision:** SP-00 必须先钉死失败进程的 `ExitStatus`（signal 9 / 退出码 / wait 错误）、当时的**进程级**并发 spawn 数，以及 **单测内**同时存活 child 的峰值（含 `service` / 三路 `worktree add`）。只有「资源压垮」才执行 ADR-SP-01 的限流。若是隔离泄漏（子进程读到宿主 `.libra`、错误二进制、schema lockout），SP-00 的 go/no-go 改为「隔离修复」并按 ER-10 拆 `FIX-SP-*`，不得假装限流能修。
- **Revisit when:** 复现失败。

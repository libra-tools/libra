## 文档职责

本文先解决一个跨 provider 的前置缺口：**reasoning 只要以明文出现在获授权的源中，就必须按现有脱敏契约采集；若源以 provider 加密 payload 给出，则必须逐字节保留该密文，且不把「不可解密」误写成「未采集」。** RG-01/04/02/06/03/05 在任何 Codex、Claude Code、OpenCode 或未来 agent 的采集改进之前完成。其后本文解决 Libra 对 Codex CLI 会话在「转写智能、SessionEnd 收尾、可观测性」上的差距。目标是在保持现有 hook、coverage gate、fail-closed 打开、typed redaction、cloud mirror 与擦除 tombstone 的前提下，让真实 Codex 会话产出非零且正确的 prompt / model / token / 文件变更 / 轮次投影；明文 reasoning 可读、provider 密文在独立 opaque artifact 中可验证地保存，SessionEnd 在 Codex 3 s 硬上限内可靠收尾，hook 失败可见，并用 Codex 自有索引对账完整性。

本文只规划任务，不宣称实现完成。落地时每个任务都必须先刷新源码锚点，再按任务卡验收。

### 非目标

- 不实现凭空猜测、暴力破解、私钥抓取或绕过 provider 授权的解密。本计划核对范围内（Codex 0.152 rollout、`$CODEX_HOME/config.toml`、本机 SQLite 索引）未发现任何客户端解密材料；RG-03 只记录 `encrypted_unavailable` 并保留原密文，将来仅能由 provider 官方、显式授权的 decrypt/export capability 消费（DEFER-RG-01）。
- 不改变 `libra code --provider codex` 的 app-server 运行时面（`src/internal/ai/codex/**`、`src/command/code.rs`）——那是运行 Codex，不是采集用户自己的 Codex 会话。
- 不复制 Entire CLI 源码；只对齐行为契约与测试判据（GC-CX-01）。
- 不引入项目级 `.codex/hooks.json` 与 linked-worktree 发现（Entire 模式）；用户级安装已覆盖全部仓库（DEFER-CX-05）。
- 不做图片外置资产、compact transcript 投影角色与 redaction 规则广度（DEFER-CX-03/04/06）。provider 密文的完整保留不再是延后项；它由 RG-02/03/05 覆盖。
- 不做 `libra review` / `libra investigate` 的 Codex 评审面（属 agent 调用而非采集）。

### 成功定义

- 对每个获支持 provider，conformance fixture 证明其当前已知 reasoning 状态：明文 reasoning 经 typed redaction 后可读地进入 checkpoint；已知 provider 密文字节仅进入 manifest 声明的 opaque artifact，SHA-256 与源相同且未在普通 transcript、metadata、日志、coverage digest 或 LLM 上下文重复出现。任何 provider 新出现已加密字段时，必须先增加该字段的版本 pin fixture，才可分类为 `encrypted_unavailable`。
- 在 codex-cli 0.152.0 真实会话上，`libra agent checkpoint show --json` 的 `extraction` 给出非零且与 rollout 一致的 `prompt_count` / `token_usage`（含 `reasoning_tokens`）/ `modified_files` / `model`；一个 Codex 轮次恰产生一个 coverage claim。
- 正常 `transcript/codex.jsonl` 不含 `encrypted_content` 键，但 checkpoint manifest 指向完整的 provider-ciphertext artifact；metadata 记录 reasoning/compaction 的状态、体量、artifact ref；`docs/commands/agent.md` 的口径与实现一致；历史（本计划之前写入的）含密文 checkpoint 有盘点、读端剥离与幂等迁移路径。
- `~/.codex/hooks.json` 中 SessionEnd handler 为 3 s，trust hash 与 Codex 生效超时一致，`agent doctor` / `agent list` 对已安装且已受信的 Codex 报告 `installed=true`；SessionEnd 在 2 s 预算内标记会话结束，超预算的检查点写入以 `finalize_pending` 补做。
- `agent doctor --json` 能以 Codex 自有索引（`$CODEX_HOME/state_*.sqlite`）对账本仓库最近 7 天的线程数与已采集会话数，并给出未采集会话的导入入口；hook 调用失败有本地日志与计数。
- 每张代码卡 patch+1 发布并按 D-STD 取得远端证据，收口跑全量三门；Claude + Codex 双审 PASS 后本计划可标记完成。

### ADR-CX-01: 形状精确合成语料是唯一解析真值；pin codex-cli 0.152.0

- **Status:** Accepted
- **Context:** 现有 Codex fixture 是按 extractor 冻结形状手写的 generic 记录，与真实 rollout 无关，测试全绿而真实数据全零（GAP-CX-01/07）。真实 rollout 含 prompt、路径、工具输出，不能入库。
- **Decision:** CX-00 从本机 ≥150 个 0.150/0.152 rollout 归纳记录类型普查；CX-12 生成 **形状精确、内容合成** 的语料（结构/字段/顺序/`ordinal`/`turn_id` 与真实一致，文本替换为占位符），作为 RG-04/CX-04/05/06/15/09/10 的唯一解析真值；契约 pin 由 0.142.4 升至 0.152.0，`docs/development/tracing/agent.md` 与 `src/internal/ai/hooks/providers/codex/mod.rs` 注释同步；解析器对**未知**顶层/payload 类型宽容（跳过 + 计数进 `warnings`），对**已知**类型严格。
- **Alternatives considered:** 直接引用真实 rollout（隐私不可接受）；继续 generic 启发式（已证明无效）。
- **Consequences:** MANIFEST 计数成为 load-bearing；上游新增类型需重跑普查并扩语料。
- **Revisit when:** Codex 大版本改变 rollout 顶层信封。

### ADR-RG-01: reasoning 的可读采集、provider 密文 opaque 保留与受控解密

- **Status:** Accepted（用户决策，2026-09-03）
- **Context:** 当前三条 observed-agent 路径没有统一语义。Codex rollout 含 `reasoning.encrypted_content` 与 compaction 内嵌密文；Claude Code 的获授权本地 JSONL 是可读输入，但当前 coverage 模型没有 reasoning 记录；OpenCode 仅通过受信任 `opencode export` 获取内容，normalizer 只消费 `text`/`tool` part。现有 `RedactedBytes` 正确地阻止任意原始字节落到 traces/R2/D1，却也意味着不能把 provider 密文当作普通 redacted transcript 正确保真。密文不是「没有数据」：将来 provider 若给出可移植解密入口，或同一会话需要原 payload，它仍是有价值的原始证据。本计划核对范围内未发现客户端解密材料。
- **Decision（所有后续 provider 改进的前置，顺序不可颠倒）:**
  1. **显式分类，不用熵或字段名猜测。** 新增 provider 通用 `ReasoningAvailability` 五态：`provider_visible`（受支持且可读）、`encrypted_unavailable`（源明确声明的密文、当前无获授权 decryptor）、`opaque_archived`（该密文已提交为 artifact）、`not_present`、`unsupported_shape`。每个 adapter 只针对其被 fixture/版本 pin 证明的字段声明分类；未知 reasoning-like block 必须使该 turn `partial` 并写无 payload warning。
  2. **可读内容尽量采集。** `provider_visible` reasoning 进入新增 `SemanticRecord::Reasoning { provider, source_kind, text }`（不冒充 assistant answer），先走逐字段 typed redaction，再进入 coverage projection、checkpoint transcript 和可读 extraction；其文本不得落入未脱敏的 metadata、日志或 digest 输入以外的路径。
  3. **密文逐字节保存，但与普通 transcript 严格隔离。** artifact payload 是 provider wire schema 定义的密文字段原字节序列（JSON string 则为未解码、未重序列化的 UTF-8 字符序列；base64 不解码），由只能在 reasoning 模块内构造的 `OpaqueEncryptedBytes` 承载；它不转换为 `RedactedBytes`、不运行 redaction、不写入普通 `transcript/<agent>.jsonl`、metadata JSON、coverage digest、搜索索引或日志。每个 checkpoint 以 `reasoning/encrypted/<sha256>` manifest role 提交，manifest 只保存 `{provider, source_kind, locator, byte_len, sha256, availability, decrypt_capability}`。artifact 作为**同一 trace tree 内的 blob** 写入，manifest 条目携带其 Git `oid`，对象、manifest、`object_index` 登记与 ref CAS 在**同一 checkpoint attempt** 内完成（RG-06），使 GC 以 ref 可达性判定时 artifact 与 checkpoint 同生同灭。**扇出预算（RG-02 强制）**：单 checkpoint 的 `reasoning_artifacts[]` 条目数 ≤ `MAX_REASONING_ARTIFACTS = 512`、manifest/sidecar 的 reasoning 相关字节 ≤ 256 KiB、artifact 总字节 ≤ 32 MiB（= transcript 读取硬上限 16 MiB 的 2×）；任一超限即 **fail-closed**（live 路径转 `finalize_pending`，import 路径记 `partial`），不得静默截断或丢弃密文。同一 `(checkpoint, locator)` 唯一；相同 sha256 的对象只写一份（内容寻址）。`content_hash.txt` 仍只覆盖既有四角色，artifact 完整性由 manifest 条目 sha256 + doctor 校验保证，旧读端忽略未知 role。source locator 格式固定为 `<provider>:ordinal=<n>[/replacement_history[<i>]]`（Codex），其它 provider 在各自接线卡定义。
  4. **系统保存、镜像、擦除和导出必须同生命周期。** artifact 与 checkpoint 同一 traces commit、object index、cloud mirror、retention、tombstone/erase 和 doctor 完整性检查；不得出现「只在本机留密文」或「抹除 transcript 后留下密文」。默认 `show/list/graph` 只显示 availability/大小/摘要，读取实际字节必须走现有 raw-export 授权路径（`--allow-raw`、`--justification`、`agent_audit_log`、受限文件权限），不得把字节回显到终端或日志。
  5. **不自行解密；只支持 provider 官方、显式授权的 capability。** 定义可选 `ReasoningDecryptor`：输入为受作用域绑定的 `OpaqueEncryptedBytes`，输出为 `provider_visible` reasoning；调用要求 provider 公开的客户端导出/解密 API、用户明确授权、session/scope 校验、短生命周期内存处理和审计事件。没有 capability、密钥或授权时稳定返回 `encrypted_unavailable`，原 artifact 保持可取。当前 Codex、Claude Code、OpenCode 均不实现 decryptor；绝不扫描本机密钥链、config、环境变量或网络端点来猜测密钥（DEFER-RG-01）。
  6. **不以 Libra 自行「再加密」为前提。** provider 密文按原字节作为 opaque application payload 保存；受控存储若提供静态加密可透明实现，但不可改变字节、取代 scope 授权、保留、审计或 erase 契约。
  7. **普通 transcript 的去密文口径。** 从 rollout 复制件中删除已归档项的 `encrypted_content` **键**（而非仅置空），保留顶层行、`ordinal`、非密文结构与可读 summary；不新增 Libra 私有字段、不删除整行或嵌套项；随后再对复制件运行 redaction。
- **Alternatives considered:** 剥离并只留计数（Entire 策略；违背「能采尽采且保留密文」）；把密文塞回普通 JSONL（会被 future redactor/compact 投影改写、重复落库并误入搜索）；把所有高熵字段当密文（会把二进制附件/secret 误分类）；通用解密命令（没有安全的跨 provider 密钥来源）。
- **Consequences:** checkpoint manifest、history writer、cloud mirror 与 erase 路径新增一种受类型约束的 blob role；普通 transcript 不再含 Codex 密文，但系统仍保存完整原密文。provider-specific parsing 只能在 RG-* 完成后接线；未来 provider 支持 decryptor 时新增独立卡和 provider-specific live gate。历史含密文 checkpoint 按 ADR-CX-08 收敛。
- **Revisit when:** 任一 provider 发布有版本化、可审计、客户端可用的 reasoning decrypt/export 契约，或 Libra 引入独立的受控存储加密服务。

### ADR-CX-03: SessionEnd 有界收尾（3 s 上限、2 s 预算、finalize_pending 补做）

- **Status:** Accepted
- **Context:** Codex 把 SessionEnd 钳制到 3 s 并在超时杀进程树；Libra 在该 hook 内做完整 checkpoint 写入且无预算（GAP-CX-03）。
- **Decision:** handler 顺序固定：① 单条廉价 DB 写把会话置 `stopped`（不受预算约束）；② 仅当 coverage claim 表明存在未完成轮次时，在**自进程启动起 2.0 s** 的 deadline 内尝试 checkpoint 写入；③ 超预算/失败 → `metadata_json.finalize_pending = {reason, at}`，由下一次任一 codex hook、`agent doctor`、`agent import --session` 幂等补做（coverage gate 防重复）；④ doctor 把 `last_event_at` 超过 24 h 仍 `active` 的会话置 `stopped`（`stop_reason="owner_timeout"`）。安装面 SessionEnd `timeout=3`（CX-01）。
- **Alternatives considered:** 在 SessionEnd 什么都不写（丢最后一轮）；请求更长超时（Codex 钳制且 warning）。
- **Consequences:** 引入进程启动时钟与 `LIBRA_TEST_SESSION_END_BUDGET_MS` 注入点（debug only）；被杀窗口留下的半成品由 traces in-flight marker + doctor 既有修复覆盖。
- **Revisit when:** Codex 放宽 SessionEnd 上限。

### ADR-CX-04: 保留自算 trust hash，但 identity 按 Codex 生效超时；升级时以 live 向量核对

- **Status:** Accepted
- **Context:** Libra 自算写入 `trusted_hash` 让 `codex exec` 非交互场景开箱可用，但 identity 算法耦合上游；SessionEnd 钳制已造成 hash 不一致（GAP-CX-02）。Entire 选择不写 hash 只报缺口。
- **Decision:** 保留自算写入（产品差异化）；canonical identity 的 `timeout` 取 **生效值** `min(configured, per-event cap)`（当前仅 SessionEnd cap=3）；forward map 按事件带独立 timeout；freshness 判定同时比较 command 与 timeout，重装刷新陈旧 30 s 条目及其 state key；每次升级 pin 必须用隔离 `CODEX_HOME` 实测一组向量（≥2 事件，含 session_end）钉入单元测试；doctor 报告 gap 时区分「缺失」与「hash 漂移」。
- **Alternatives considered:** 改为 Entire 模式（用户手批）——破坏 `codex exec` 自动化；同时保留两种模式（复杂度）。
- **Consequences:** 上游 identity 变更会让 gap 计数变红而非静默跳过（可观测）。
- **Revisit when:** Codex 提供 durable hook id 或官方 trust API。

### ADR-CX-05: 轮次主键 = Codex `turn_id`；注入消息不开轮；coverage schema v2；fence 用常量

- **Status:** Accepted
- **Context:** GAP-CX-04：注入 user 消息开出伪轮；`turn_context.payload.turn_id`/`task_started.turn_id` 是 Codex 自身的轮标识；live fence 把 schema 版本写死为 1（`src/internal/ai/history.rs:5455-5468`），升版后 live reservation 会被拒绝。
- **Decision:** `normalize_codex_rollout` 以 `turn_id` 为 `logical_turn_key`（`turn_context` 与 `task_started` 任一先到即采用），仅在缺失时退化为 `ordinal:N`；注入前缀表（单一事实源，CX-04 新模块导出，初始集合 = 对标表 #9 的 12 条 + CX-00 补充）命中的 user 消息与 `developer` 角色**不开轮、不入 `User.text`**，只计入 provenance；`COVERAGE_SCHEMA_VERSION` 升为 2，fence 校验改用该常量；v1 claim 只读并存、不重写；`SemanticRecord::Reasoning` 变体（RG-04）随 v2 一并冻结；graph JSON v1 形状不变。
- **Alternatives considered:** 只过滤不换键（`ordinal` 仍不稳定）；重写 v1 claim（破坏 append-only 承诺）。
- **Consequences:** 同一会话在升级前后各有一套 claim（按 schema 版本隔离，读端取当前版本）；digest 变化不触发 conflict（不同 schema 键）。
- **Revisit when:** Codex 在 rollout 提供 per-item uuid。

### ADR-CX-06: 只读消费 Codex 自有索引做对账、导入与子代理关联（fail-soft）

- **Status:** Accepted
- **Context:** Codex 0.15x 已把线程/轮次/项目投影进 `$CODEX_HOME/state_<n>.sqlite` 与 `thread_history_<n>.sqlite`，含 cwd、rollout_path、git_branch/sha、model、tokens_used、spawn edges；两工具均未利用（GAP-CX-08）。
- **Decision（描述符验证 + 私有快照副本，消除 open 期 TOCTOU）:** 新增 `src/internal/ai/observed_agents/codex_index.rs`。因为本仓库的 SQLite 走 `sea-orm`/`sqlx`（无自定义 VFS 通道），"先验证路径再让 SQLite 按路径打开" 无法阻止 open 期间的替换，故不采用该形态。实际流程：① 从 `$CODEX_HOME` 目录描述符起，对最高编号的 `state_<n>.sqlite` 及其 `-wal`/`-shm` 兄弟文件逐层 `openat(O_NOFOLLOW)` 并 `fstat` 确认常规文件；② **只通过这些已验证描述符**把字节复制进本进程私有的 0700 临时目录（`mkdtemp`，用后即删）；③ SQLite 只打开该私有副本（副本可写，用于 WAL 恢复，从而使尚未 checkpoint 的行可见），**Codex 自有文件全程零写入**（GC-CX-02 保持）；④ **一致性证明义务（只有取得经验证的一致快照才查询）**：复制前后对 main、`-wal`、`-shm` 分别取 `(dev, ino, size, mtime_ns)`，四元组任一变化即判定复制期有并发写入/checkpoint → `available=false`（reason `codex_index_busy`，最多重试 2 次）；复制完成后在私有副本上执行 `PRAGMA integrity_check` 与一次 WAL 恢复（`PRAGMA wal_checkpoint(TRUNCATE)`），任一失败 → `available=false`（reason `codex_index_inconsistent`）。**FD 只固定 inode、不固定内容**，因此上述「变化检测 + 副本自校验」是本设计的一致性判据；无法通过时一律 fail-closed，绝不查询可能漏行的副本。⑤ 复制受预算约束：总字节 ≤ 512 MiB、墙钟 ≤ 5 s，超限或任一 `fstat`/复制失败 → `available=false` + reason（不做部分读取）；⑥ **私有快照的生命周期**：目录为 `.libra/tmp/codex-index-<pid>-<rand>`（0700、同 UID），正常路径用后即删；进程被杀留下的同前缀目录由下一次调用在开始前清扫（只清同 UID、同前缀、mtime 早于 1 h 的目录）。副本可能包含 `title`/`first_user_message`/`preview` 等列的字节，因此口径是「**不查询、也不写入 Libra 持久状态**」，而不是「字节从未落盘」；⑦ 查询语句只 SELECT `threads.{id,rollout_path,cwd,source,thread_source,created_at_ms,updated_at_ms,archived}` 与 `thread_spawn_edges`，**不查询、不写入 Libra 持久状态**中的 `title`/`first_user_message`/`preview`；⑧ 索引给出的 `rollout_path` 必须落在 `$CODEX_HOME/{sessions,archived_sessions}` 之内，越界一律丢弃并计数；⑨ 该读取只在 `agent doctor` 与 `agent import --uncaptured` 这两条诊断/导入路径上发生，不进入 `status` 等热路径。
- **Alternatives considered:** 解析 `session_index.jsonl`/`history.jsonl`（无 cwd/无 spawn 关系）；写入 Codex 索引（永不）。
- **Consequences:** schema 漂移、并发写入、副本自校验失败或预算超限时降级为 unavailable（对账缺失但不阻塞其它诊断，且 Codex 活跃写入期间对账可能持续不可用——这是刻意的 fail-closed 取舍）；每次诊断付一次快照复制成本（本机 `state_5.sqlite` ≈ 111 MiB，实测预算内）；测试用内置 fixture SQLite，含「复制期间替换目标再换回」「复制期并发 writer 提交」「复制期 checkpointer 运行」「副本被截断」四类注入用例，以及异常退出后的遗留快照清扫用例。
- **Revisit when:** Codex 发布官方索引 API。

### ADR-CX-07: `libra commit` 记录活跃 agent 会话（对象创建前注入 trailer + ref 成功后幂等关联）

- **Status:** Accepted
- **Context:** Entire 的核心价值是「commit ↔ session」可互查；Libra 作为 VCS 本身可在 `libra commit` 时原生完成关联（GAP-CX-11）。commit message 在创建对象前经 `resolve_final_message`/`append_trailers` 定稿（`src/command/commit.rs:1153-1166`、`:1671-1675`、`:1964`），提交后无法在不改写历史的前提下追加 trailer。
- **Decision:** ① 在 `resolve_final_message` 之前快照本仓库/worktree 内 eligible 会话（`state in ('active','condensed')` 或 `last_event_at ≥ now−30min`），经既有 `append_trailers` 路径注入 `Libra-Agent-Session: <session_id>` 行（每会话一行；`--no-agent-trailer` 或 `agent.commit_trailer=false` 关闭）；② commit 对象与 ref 更新成功后，在 `BEGIN IMMEDIATE` 事务中幂等 upsert `agent_session_commit(session_id, commit_oid, created_at)`，`PRIMARY KEY(session_id, commit_oid)`；ref 更新失败则零行且不留 journal 行；③ **顺序不变式（按 trailer 是否启用分支）**：trailer 启用时，commit 消息本身就是可恢复来源，故 DB 写失败只 warn（退出码 0）并把 `{session_id, commit_oid, ts}` 追加到仓库级 durable journal `.libra/agent-session-commit.pending`（NDJSON）；**trailer 被关闭时（`--no-agent-trailer` 或 `agent.commit_trailer=false`），journal 是唯一恢复来源**，因此必须在 **ref 更新之前**（commit 对象已建、oid 已知）**持久化**（不只是写入）journal 行：以 0600 打开/创建 → `write_all` → `File::sync_data`；**首次创建**时另对父目录 `sync_all`，确保断电后目录项与内容都在盘上。**上述任一步骤（write/sync_data/父目录 sync）失败即不更新 ref 并以明确错误终止提交**（此时只留下一个未被引用的 commit 对象，无副作用），杜绝「trailer 关、DB 与 journal 双失败 → 关联不可恢复地丢失」，也杜绝「ref 已落盘而 journal 仍在页缓存」的断电窗口；④ `agent doctor` 从可达 commit 的 trailer **与** journal 两个来源幂等重建关联行，且只消费指向**可达 commit** 的 journal 行（CX-20）；新表由 `src/internal/db/migration.rs::builtin_migrations` 显式注册（`include_str!` up/down）；⑤ 签名提交的 trailer 位于被签名内容内（注入先于签名）；⑥ 跨 agent 通用。
- **Alternatives considered:** post-commit hook 脚本；只写 DB 不写 trailer（跨机器不可见）；提交后追加 trailer（需 amend，破坏对象模型）。
- **Consequences:** 新表 + 迁移（forward-only）；trailer 会进入远端历史（用户可关）。
- **Revisit when:** 需要按 turn 粒度关联。

### ADR-CX-08: 历史含密文 checkpoint 的收敛（immutable 保留 + 读端剥离 + 幂等迁移）

- **Status:** Accepted
- **Context:** 本计划之前的 live 路径已把 Codex 密文混入普通 transcript blob（本机 7 条）；traces 对象不可重写（append-only），且可能已镜像到云端（GAP-CX-13）。
- **Decision:** ① 历史对象**保留不改**；② doctor 盘点含密文的 legacy Codex checkpoint（只输出 id 与计数）；③ 普通读端（`show`、非 raw `export`、graph 预览）对 legacy Codex blob 在读取时按 ADR-RG-01 第 7 层规则删除 `encrypted_content` 键（幂等、不落盘）；④ `agent doctor --repair-reasoning`（或等价子命令）为 legacy checkpoint 追加**新 revision**：密文提交为 RG-02 artifact、普通 transcript 为去密文复制件、`parent_checkpoint_id` 指向 legacy，幂等键 `(legacy_checkpoint_id, sha256)`；⑤ 已镜像的 legacy 对象不变，新 revision 按 RG-05 镜像；⑥ 历史 raw 字节仍只经 `--allow-raw` 审计导出。
- **Alternatives considered:** 重写历史对象（破坏 immutability 与云端 digest）；批量 prune（丢证据）。
- **Consequences:** legacy checkpoint 在迁移前后各有一份对象；doctor 有新 finding 类型。
- **Revisit when:** 云端支持对象级替换与 digest 重签。

## 全局工程约束

继承模板 GC-01..GC-12，并追加：

- **GC-CX-01 行为对标不抄代码:** Entire CLI 只作为行为契约与测试判据参照（pin 见 DEP-CX-02），不得复制其源码或测试数据；实现按 Libra 既有抽象（`HookProvider`、`SemanticRecord`、`RedactedBytes`、coverage gate）落地。
- **GC-CX-02 Codex 自有数据只读:** rollout、`sessions/`、`archived_sessions/`、`state_*.sqlite`、`thread_history_*.sqlite`、`history.jsonl` 永不写入；`hooks.json`/`config.toml` 只改 Libra 自有条目（既有契约）。
- **GC-CX-03 零真实内容:** 语料、测试 fixture、证据、日志一律合成或哈希/计数（ER-11）；capture 日志不含 prompt/tool payload 字节。
- **GC-CX-04 hook 进程时间预算:** 任何 `libra hooks codex <verb>` 入口的自设预算 ≤ 2 s（SessionEnd 强制，其它事件以 warning 记录超预算）；预算只约束可延后的工作，标记类 DB 写不受限。
- **GC-CX-05 解析宽容分级:** 未知记录类型跳过 + 计数进 `warnings`；已知类型解析失败标 `partial`；路径越界、非 UTF-8/JSON envelope、redaction 失败、size cap 超限、checkpoint 写入失败仍 fail-closed（沿 `docs/development/tracing/agent.md` §5）。
- **GC-RG-01 reasoning 不可降级为静默丢失:** 每个 supported agent 的 reasoning source 必须显式判定为五态之一；未知 reasoning-like 形状不得被宽容跳过后保留 `complete`，必须 partial + 无 payload warning。
- **GC-RG-02 两种字节类型、两条落盘路径:** 可读 reasoning 只能经 `RedactedBytes` 持久化；已知 provider 密文只能经不可伪造的 `OpaqueEncryptedBytes` 写入 manifest-declared artifact。二者都不得回显日志；密文不得变为普通 transcript、metadata、coverage digest、搜索索引或模型输入；分类/归档失败时原始 rollout 字节不得进入 Redactor 或任何持久化、导出、日志 sink。
- **GC-RG-03 provider 密钥零接触:** 不读取 keychain、环境变量、provider config 或网络端点来推测/收集解密密钥；decryptor 只能是 provider-specific、官方记录、显式授权、scope-bound、内存短生命周期的 capability。未实现 decryptor 的正常状态是 `encrypted_unavailable`，不是 capture failure。
- **GC-RG-04 前置顺序:** RG-01/04/02/06/03/05 全部 `Acceptance=complete` 之前，不得开始任何 provider（含 Codex CX-*）的 reasoning 解析/存储接线；串行链 DAG 边即为该约束的机器可核对形式。

#### D 组远端后置门标准登记（D-STD）

每张 `Release boundary = independent` 的卡在其字段 **D 组** 写 `D-STD（release.yml @ tag v<version>）`。`release.yml` 只由 `push` `v*` tag 触发，而 `gh release create --verify-tag` 在远端 tag 不存在时中止，因此发布与取证命令固定如下（**含管道的命令一律放在本代码块内，不进表格，避免转义破坏**）：

```bash
set -euo pipefail

# §0 发布触发（顺序不可换）
VERSION="$(sed -n 's/^version = "\(.*\)"/\1/p' Cargo.toml | head -n1)"
libra tag "v${VERSION}"                     # 指向已验证并推送的 main 提交
libra push origin "v${VERSION}"             # 触发 release.yml（on.push.tags: v*）
gh release create "v${VERSION}" --title "v${VERSION}" --generate-notes --verify-tag

# §1 解析唯一 run id 并等待结束（空值/多值/非成功一律失败）
RUN_IDS="$(gh run list --workflow=release.yml --branch "v${VERSION}" --event push --json databaseId --jq '.[].databaseId')"
[ "$(printf '%s\n' "${RUN_IDS}" | grep -c .)" -eq 1 ] || { echo "FAIL: expected exactly one release run, got: ${RUN_IDS}"; exit 1; }
RUN_ID="$(printf '%s\n' "${RUN_IDS}")"
gh run watch "${RUN_ID}" --exit-status
gh run view "${RUN_ID}" --json conclusion --jq '.conclusion' | grep -qx success || { echo "FAIL: run ${RUN_ID} not successful"; exit 1; }

# §2 CDN 安装冒烟（未转义管道；装到一次性目录，不改 PATH）
SMOKE_DIR="$(mktemp -d)"
curl -fsSL https://download.libra.tools/install.sh | sh -s -- -v "v${VERSION}" -d "${SMOKE_DIR}" --no-modify-path
"${SMOKE_DIR}/libra" --version | grep -q "${VERSION}" || { echo "FAIL: smoke binary version mismatch"; exit 1; }

# §3 安装脚本版本核对（先落盘再 rg，避免管道歧义）
SCRIPT_OUT="${LIBRA_TEST_SCRATCH_DIR:-/Volumes/Data/tmp}/install-${VERSION}.sh"
curl -fsSL https://download.libra.tools/install.sh -o "${SCRIPT_OUT}"
rg -n "DEFAULT_VERSION=\"v${VERSION}\"" "${SCRIPT_OUT}"

# §4 Homebrew 正面断言（job success 不足以判定，必须读 job 日志）
JOB_IDS="$(gh run view "${RUN_ID}" --json jobs --jq '.jobs[] | select(.name | test("verify-homebrew-formula")) | .databaseId')"
[ "$(printf '%s\n' "${JOB_IDS}" | grep -c .)" -eq 1 ] || { echo "FAIL: expected exactly one verify-homebrew-formula job, got: ${JOB_IDS}"; exit 1; }
BREW_LOG="${LIBRA_TEST_SCRATCH_DIR:-/Volumes/Data/tmp}/brew-${VERSION}.log"
gh run view "${RUN_ID}" --log --job "$(printf '%s\n' "${JOB_IDS}")" > "${BREW_LOG}"
rg -n "v${VERSION}" "${BREW_LOG}"
```

### 任务卡粒度规则（强制）

沿用模板 `G-01..G-11` 全文；本节不重复条款。

**本计划的 AC 计数口径（R3 后收紧）**：

- 每条 AC 恰含 **一个可独立失败的断言**。
- 同一**行为维度**内由**单次 `assert_eq!`/单次 diff/单个退出码**判定的多字段比较计为一条（例如「token 差分表与 MANIFEST 期望表 diff 为空」）。
- **跨行为维度必须分条**：文件「存在」与内容「相等」是两条；「注入失败」与「退出码」是两条；「导出字节相等」与「文件权限」是两条；「产生 finding」与「标记状态」是两条。
- 「文档已同步」统一由 `compat_agent_docs_contract` 一条守卫承担（该守卫已包含 `docs/development/commands/agent.md`，见 `tests/compat/agent_docs_contract.rs:15`）。
- 零命中守卫、结构门、命令类判据属 **Verification**，不计入 AC。
- **门族型验收（`EX-CX-01`）**：少数卡的验收本质是**同一恢复轴上的机械门族矩阵**（失败源 × sink、路径类别 × 拒绝语义、不可用状态 × 预算），逐门原子计数必然超过 8，而按门拆卡会把同一恢复轴切碎（违反 G-01/G-02 与「碎片卡」反模式）。这类卡按模板白名单登记 `EX-CX-01`，分子写作 `n/8@EX-CX-01`，并在卡内「判据规范（非计数正文）」块**逐门枚举**、每门给出具名测试；门族增减时同批更新 waiver 行与粒度审计表。除该 waiver 覆盖的卡外，其余卡一律 ≤ 8，超限即拆卡。

Verification 按独立验证门计；每条 `source .env.test && …` 命令计一门。每卡 `Granularity` 行为机器可核对摘要，ER-03 开工前逐字段核对。

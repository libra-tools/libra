## 文档职责

本文解决 **Libra 网络协议 pkt-line 解析路径可被远端畸形输入触发 panic / 巨量分配，且协议错误在多个 CLI 边界被错误归类为 `LBR-NET-001`、错误文本回显远端字节** 的问题。目标是：pkt-line 帧解析全面 fail-closed（同步解析器 + fetch/git/ssh 异步读取循环与头部解析），引入树内类型化错误 `PktLineError` 与 `PushError::Protocol`，在全部受影响的 CLI 映射点（fetch / clone / ls-remote / pull / push）以固定 marker 适配归入 `LBR-NET-002`，**本计划新写或改写的错误文本**零远端字节回显（协议解析、传输错误与 SSH 诊断路径），帧长校验单一事实源（GC-02）。

本文只规划任务，不宣称实现完成。落地时每个任务都必须先刷新源码锚点，再按任务卡验收。

### 成功定义

- 用户/系统行为变化：远端返回畸形 pkt-line（非 hex 头、不足 4 字节、`len∈1..3`、声明 payload 超过实际到达/剩余字节）时，fetch/clone/ls-remote/pull/push（git/ssh/https 三传输、discovery/upload-pack/receive-pack 三阶段）以稳定错误 `LBR-NET-002` 干净失败，不再 panic、不发生 ~4 GiB 级回绕分配；**本计划新写或改写的错误文本**零远端字节回显（协议解析、传输错误与 SSH 诊断路径——pkt-line 三点 + process-output 全部用户可见面）；既有未触碰面（https `Content-Type` 回显）不在口径内（DEFER-06）；合法帧（flush `0000`、`len==4` 空 payload、`0xffff` 上限帧）语义不变；非协议网络错误仍归类 `LBR-NET-001`；receive-pack 状态行语法违规归类 `PushError::Protocol`（`LBR-NET-002`，与同函数 `unpack`/`ng` 分支一致）；远端 `ng` 拒绝原因按 Git 惯例透传（ADR-PKT-02）。
- 机器接口变化：无新增错误码 / flag / schema；协议错误显式映射 `StableErrorCode::NetworkProtocol`（`src/utils/error.rs:375`）。
- 文档/测试/发布证据：`docs/error-codes.md` 无需新增（核对登记）；具名单测覆盖畸形矩阵、全部边界映射、零回显与合法帧回归（全部标 `(new)`，经失败闭合存在性脚本验证）；每个发布切片独立 bump + `gh` release + 全部 8 个 release job 记录的 D 组证据。
- 完成标记：十四张任务卡全部 `done/complete` + 全量收口门全绿 + Codex/Claude 双评审 PASS。

### ADR-PKT-01: 类型化 `PktLineError` + 外部类型边界 marker 适配 + 显式映射 `LBR-NET-002`

- **Status:** Accepted
- **Context:** 稳定码映射两层：① CLI 边界显式映射（`fetch.rs:943-957`、`fetch.rs:882-887`、`push.rs:878-900`、`push.rs:374-376/:404-406`、`ls_remote.rs:210-221`、`clone.rs:1012-1046,1059-1063`、`pull.rs:267,928-936,937-944,989-1001`）优先于 ② 字符串分类器（`error.rs:1680-1701`）。pkt-line 错误目前被包装为 `GitError::NetworkError` / `PushError::Network` / `IoError`，在上述边界落 `LBR-NET-001`。`GitError` 为外部 crate 类型不可加变体；`PushError` 为树内枚举可加变体。
- **Decision:** 三层机制：① **树内类型**：`PktLineError`（固定短语 + 固定原因枚举，零回显）承载解析与读取循环错误（含异步头部解析）；push 侧新增 `PushError::Protocol { detail }`（`detail` 以 marker 前缀开头、由 `PktLineError` 转换而来）仅承载协议错误。② **外部类型边界 marker 适配**：树内常量 `PKT_LINE_PROTOCOL_ERROR_PREFIX = "pkt-line protocol error: "`（GC-02 单点）随错误文本进入 `GitError::NetworkError`/`IoError`；在 **8 个 CLI 映射点**（fetch discovery、fetch FetchObjects、push discovery、ls-remote、clone discovery、clone fetch 阶段、pull discovery、pull FetchObjects）的显式分支内识别前缀 → `NetworkProtocol`（`LBR-NET-002`），其余维持原归类——每个适配点以具名测试做 marker/非 marker 双向锚定（8 为逻辑映射点口径；`PacketRead` 子臂的归类细化由 PKT-10 门 3/4/21-24 承载，R34 Codex P2-1）。**检测语义为 `starts_with`（串首锚定，R6 Claude P1-1）**：`contains` 会被远端可控字段（如 HTTPS `Content-Type` 头值）伪造子串命中而误判 `LBR-NET-002`，故拒绝；为使 `starts_with` 在传输包装后仍成立，SSH 三处包装点（`ssh_client.rs:273-284/:319-329/:449-459`）对 marker 错误**原样透传**（不套 `"SSH read failed: "` 等前置字面量，经共享辅助函数实现），非 marker 错误按现状包装——保证 marker 在最终用户可见文本中仍位于串首。③ **分类器兜底**：错误文本含 `pkt-line` 使 `is_network_protocol_error` 对未经适配路径成立。收到畸形帧一律中止当前操作。
- **Alternatives considered:** ① 仅靠分类器——拒绝（R2 证伪）；② 为 `GitError` 新增变体——拒绝（外部 crate）；③ 全面 `RemoteDiscoveryError` 迁移——DEFER-04；④ 静默跳过坏帧——拒绝（GC-07）；⑤ 错误文本附远端字节摘要——拒绝（反射面）；⑥ `contains` 检测语义——拒绝（远端可控字段可伪造子串命中，R6 Claude P1-1 证伪），改用 `starts_with` + SSH 透传保持串首锚定。
- **Consequences:** 协议错误归类由 `LBR-NET-001` 修正为 `LBR-NET-002`（既有码语义收敛）；marker 前缀成为跨层契约（常量单点 + 三层测试锚定）；对宽松远端兼容性下降。
- **Revisit when:** DEFER-04 落地或 `git_internal` 提供协议错误变体时移除 marker 层。

### ADR-PKT-02: 远端 `ng` 拒绝原因透传不属于「零回显」口径

- **Status:** Accepted
- **Context:** `push.rs:2140-2147` 把 receive-pack `ng` 状态行的远端 `reason`（如 "protected branch hook declined"）存入 `PushError::RemoteRefUpdateFailed` 并透传，测试 `:3404-3416` 锁定。
- **Decision:** 「零远端字节回显」限定于**协议解析与传输错误路径**（pkt-line 帧、advertisement、process-output 诊断）；远端对自身 ref 更新的拒绝原因是远端的权威用户消息，按 Git 上游惯例**透传但经安全化处理**：①`ng` 行的 `refname` 先校验属于本地 `expected_refs`——未知 refname 不透传，改归 `PushError::Protocol` 固定短语（R10 Codex P1-1）；②`reason` 与（校验通过的）`refname` 共用控制字符转义（`C0`/`DEL`/CSI）+ 200 字符限长（超出截断加省略号），防终端转义注入与日志洪水（R9 Codex P1-5）；③恶意 sentinel 覆盖人读与 `--json` 输出（refname 与 reason 两条路径）。
- **Alternatives considered:** ① 固定短语替换——拒绝：破坏 Git 兼容 UX；② allowlist——拒绝：开放集维护成本高。
- **Consequences:** `ng` reason 经控制字符转义（C0/DEL/CSI）与 200 字符限长后保留可读性（与 Git 上游一致）；残余风险为远端可注入**可读**误导文本（不可注入控制序列），由本 ADR 显式接受；`unpack ok`/状态行解析本身不回显（`unexpected receive-pack status line` 由 PKT-09 改归类 `Protocol` 并固定短语）。
- **Revisit when:** 上游 Git 改变 `ng` reason 惯例，或 Libra 引入结构化错误展示（DEFER-05）。

### ADR-PKT-03: SSH 捕获路径强制 BatchMode，host-key 交互 fail-closed

- **Status:** Accepted
- **Context:** `ssh_client.rs` 的 `interactive` 判定依据是 **libra 自身进程 stdin 是否为 TTY**（`:171` `is_terminal()`；`:180-182` 条件分支），非交互路径现状已强制 BatchMode（`CLAUDE.md` 既有设计）；`Stdio::inherit()` 分支（`:198-203`）命中的是**真实终端用户**（如终端里 `libra clone ssh://…`），远端 stderr 可直写用户终端（R9 Codex P1-4）。改为捕获后，OpenSSH 的 host-key 确认提示无法经事后渲染完成交互（R10 Codex P1-4 / Claude P1-2）。承载该逻辑的 `ssh_client.rs:164-204` 已纳入适用范围与 PKT-11 写集（R11 Claude P1-1）。
- **Decision:** 所有捕获路径的 SSH 子进程强制追加 `-o BatchMode=yes`：host key 未确认时 SSH 以 fail-closed 失败，Libra 返回稳定指引错误（含带外指纹核对说明、一次性 `ssh -T git@github.com` 交互 TOFU 步骤（以 GitHub 为例，实际仓库主机据实替换域名）与 `ssh.strictHostKeyChecking` 配置说明；**明确排除 `ssh-keyscan` 管道写入 known_hosts**，R16 Claude P1-2），不渲染任何远端提示原文；TOFU 工作流由用户手动完成一次后恢复自动化。与 `d57a908` 的 `ssh.strictHostKeyChecking`（默认 `ask`）并存：Libra 发起的捕获路径覆盖为 `BatchMode=yes`，交互确认由用户手动 `ssh` 完成。**host-key 失败的判定在脱敏前完成，唯一树内 carrier 为固定前缀常量（R28/R29/R30 Codex P1-4/P1-1）**：树内新增 `pub(crate) const SSH_HOST_KEY_UNCONFIRMED_SIGNAL: &str = "ssh host-key unconfirmed: ";`（GC-02 单点，与 `PKT_LINE_PROTOCOL_ERROR_PREFIX` 同型契约）；`ssh_client.rs` 捕获侧在脱敏前依据**退出码 255 + stderr 固定模式**（OpenSSH 固定文案前缀 `Host key verification failed.`、`REMOTE HOST IDENTIFICATION HAS CHANGED`）构造携带该前缀的 `GitError::NetworkError` 字符串载荷（外部 crate 类型边界的既有通道，与 ADR-PKT-01 marker 适配同构）；提取点 `clone.rs:1012-1029` 消费**内层 `GitError` 载荷**（即 `FetchError::Discovery.source.to_string()`——外层 `FetchError` Display 会前置 `failed to discover references from '{remote}': ` 包装破坏串首锚定，故判定必须作用于内层 source，R33 Codex P1-3）以 `starts_with(SSH_HOST_KEY_UNCONFIRMED_SIGNAL)` 识别；命中后**直接生成固定错误与指引短语，不嵌入内层 detail**；剥离点 `describe_status_with_stderr` 渲染前剥离全部 stderr 原文与信号前缀，用户可见文本不含任何远端字节。PKT-11 落地脱敏后，`clone.rs` 既有的 `"host key verification failed"` 原文匹配不可达，改为消费该信号。三段测试契约绑定 `…_host_key_fail_closed_guidance`：①信号产出（255+模式→前缀载荷）、②脱敏剥离（原文与前缀均不出现在用户可见文本）、③clone 指引（**内层 `source.to_string()`** starts_with 消费→固定短语，且固定错误不嵌入内层 detail——含 SSH→`FetchError::Discovery` 包装→clone 臂的层级契约子断言，R33 Codex P1-3）。
- **Alternatives considered:** ①白名单匹配 host-key 提示并保真渲染——拒绝：OpenSSH 提示文案随版本/locale 变化，匹配脆弱；指纹渲染引入截断/转义风险（Claude R10 P1-2）；②受限终端中介（pty 代理 + 逐行过滤）——拒绝：复杂度高，属独立设计（登记 DEFER-07）。
- **Consequences:** **附加影响（R17 Claude P1-3）**：`BatchMode=yes` 同时禁用私钥 passphrase 交互——口令保护私钥且无 ssh-agent 的用户在已确认主机上也会认证失败；错误提示须明确指向 ssh-agent（PKT-11 AC）。
- **Consequences:** **真实终端用户**首次连接未知主机时，从「像 `git clone` 一样看到 OpenSSH 指纹确认提示」变为「fail-closed + 手动 TOFU 指引」——这是一次有意的交互 UX 回退，换取远端 stderr 不再直通终端（R11 Claude P1-1 更正：受影响的是交互用户而非自动化调用，后者现状已 fail-closed）；`known_hosts` 已确认的主机不受影响；行为变化同步至用户文档（PKT-11）。
- **Revisit when:** DEFER-07（受限终端中介）立项或上游提供结构化 host-key 确认接口。

# Git 兼容性与 Agent tracing 收敛计划（2026-07-08）

## 文档职责

本文将 Git 兼容性探针、Issue #434/#437 与 Agent tracing 的 A0 工作流整理为可复核的收敛计划。目标是消除会造成静默错误、历史或对象损坏、机器输出漂移、冲突漏报和配置无声降级的差距。

本文是计划与复核契约，不把历史发布记录当作当前实现证据。执行任一任务前必须以当前 checkout 重新确认代码、测试、文档和兼容矩阵；已实现项目转为回归测试、文档或承诺校正，不得重复实现。

### 适用范围

- Git-compatible CLI：conflict、diff、clone/fetch、checkout/switch、commit、config、object plumbing、pathspec、ignore/attributes、porcelain、history、hooks、import/export 与邮件系列。
- Libra-only 表面：Agent tracing A0、安装器 `lba` 别名，以及稳定错误、JSON/machine 输出、SQLite/object/ref 写入语义。
- `COMPATIBILITY.md`、命令中英文文档、开发兼容文档、测试 target/index、错误码与发布证据。

### 非目标

- 不以 Git 全量命令或探针的全部记录清零为成功标准；长期或低价值能力仅明确标记为 unsupported/deferred。
- 不把 Git 2.55.0 之后的浮动行为、历史发布笔记或本地探针文件当作规范。
- 不包含 external-agent transcript import/graph 的实现；该能力由 [plan-20260713.md](plan-20260713.md) 承接。

### 成功定义

- 每个承诺的兼容子面有可执行的精确输出、退出码、错误和真实 Git（可用时）互操作断言。
- 高风险写路径 fail-closed、原子或可恢复，且不引入生产 `unwrap()`、`expect()` 或 `panic!()`。
- 公开行为、机器接口、测试索引和双语文档一致；未支持行为明确说明替代工作流。
- 所有未延后任务通过指定验证、review 与发布/回滚证据后方可关闭。

| 维度 | 结论 | 修订动作 |

## 已决议设计决策

### ADR-GC-01: 兼容承诺按风险和可验证行为管理

- **Status:** Accepted
- **Context:** Git 表面广泛，逐条模仿会稀释高风险修复且无法稳定验收。
- **Decision:** 固定 Git 2.55.0 为比较基线；仅对每个已承诺子面定义精确输出/退出码/错误断言。不能安全实现的行为显式 `unsupported` 或 `intentionally-different`。
- **Alternatives considered:** 全量模仿 Git；因成本和测试面不可控而拒绝。
- **Consequences:** 兼容等级、用户文档和 compat 测试必须同步；浮动外部版本不构成规范。
- **Revisit when:** 产品决定提升某一命令等级或更新 Git 基线时。

### ADR-GC-02: 共享引擎渐进替换且写路径 fail-closed

- **Status:** Accepted
- **Context:** pathspec、attributes、pretty-format 和对象校验跨多个命令，直接替换会放大回归。
- **Decision:** 新共享实现逐消费者接入，保留/迁移原有断言；对象闭包、schema 兼容、授权命令和原子写入前置失败即停止并给出稳定错误。
- **Alternatives considered:** 按命令复制逻辑或一次性切换；分别会持续漂移或难以回滚。
- **Consequences:** 每个消费者须独立验收；失败可留下可 GC 的不可达对象，但不得移动可见 refs/HEAD。
- **Revisit when:** 所有消费者已通过同一回归矩阵。

## 全局工程约束

- **GC-01 现状核实前置:** 每个任务先刷新源码、测试、用户文档和矩阵；已实现则改为补测/补文档/关闭。
- **GC-02 单一事实源:** pathspec、ignore/attributes、pretty、输出、配置与状态机不得在 CLI、测试和文档中复制实现。
- **GC-03 Git 互操作边界:** 已支持子面说明同点与有意差异；Libra-only 命令说明替代流程和机器接口。
- **GC-04 输出与错误契约:** 人读、`--json`、`--machine`、退出码和稳定 `LBR-*` 同时验收并更新 `docs/error-codes.md`。
- **GC-05 文档同步:** 公开行为同步 `docs/commands/` 双语页、开发命令页、`COMPATIBILITY.md` 与测试索引。
- **GC-06 测试索引:** 新/改 test target 同步 `Cargo.toml`、`tests/INDEX.md`，compat target 再同步 `tests/compat/README.md`。
- **GC-07 安全默认值:** 对象闭包、配置 schema、路径归属、sandbox 许可或 secret redaction 不满足时 fail-closed。
- **GC-08 原子性与恢复:** 对 HEAD、refs、index、SQLite、对象库的写入定义事务、CAS、崩溃窗口及前滚/回滚；不报告半成功。
- **GC-09 并发与资源生命周期:** 锁、子进程、临时文件、连接和队列必须释放；测试隔离全局状态。
- **GC-10 性能预算:** 热路径不得全树扫描、无界内存或 N+1；新增匹配/校验对 10k entries 规模有预算断言。
- **GC-11 生产 panic 禁止:** 不新增裸 `unwrap()`、`expect()`、`panic!()`；使用带上下文的 `Result`。
- **GC-12 精确暂存:** 仅 `libra add <相关路径>`；不使用 `commit -a`，无关脏状态不清理也不提交。

## 执行检查必备需求（强制）

1. 开工前运行 `libra status --short`，发现目标文件有未确认改动即停止覆盖并报告。
2. 每张任务卡先刷新源码/文档/测试/外部版本锚点；真机 Git 不可用时明确 skip 原因，不伪造通过。
3. 代码任务至少运行 `cargo +nightly fmt --all --check`、`cargo clippy --all-targets --all-features -- -D warnings` 和任务指定测试；纯文档任务运行 Markdown/链接或结构检查与 `libra diff --check`。
4. 完成后执行生产风险 review；修复 finding 后重跑受影响验证。
5. 公开行为同步文档、兼容矩阵、错误码、help/examples 和测试索引。
6. 使用 Libra 工作流；版本/发布只在用户可见代码切片时进行。本文档重写本身为文档-only，版本发布 N/A。
7. push 非 fast-forward 时先整合、重新验证再推；认证/网络失败记录原因，禁止盲目重试。
8. 证据不得保存 secret、token、PII、未脱敏 transcript 或私人绝对路径。

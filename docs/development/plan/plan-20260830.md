> 模板版本: v2.2（按 [`plan-template.md`](plan-template.md) 成稿；整份符合 v2.2，含 ER-13 分层测试执行与每卡 `Full-suite trigger` 登记）

## 文档职责

解决 **OpenCode 导出桥（`opencode export <sessionID>` 沙箱化子进程）在 macOS 上被 `#[cfg(not(target_os = "linux"))]` 直接 fail-closed，导致内容捕获在 macOS（主要开发平台）永远降级为 metadata-only** 的问题。目标是：让 OpenCode 内容捕获在 macOS 上经 **复用代码库既有的 Seatbelt 沙箱机制** 安全落地（方案 C 的共享执行器统一为机制、方案 B 的 macOS Seatbelt 启用为其产出），同时**保持 Linux bwrap 行为等价不变**、任何平台都不引入 unsandboxed 降级（GC-DR-14 延续）、且不改变 export 既有的**文件备份无损耗输出 + RLIMIT + 进程组 + 墙钟**执行模型。

本文只规划任务，不宣称实现完成。落地时每个任务都必须先刷新源码锚点，再按任务卡验收。

### 适用范围

- `src/internal/ai/observed_agents/opencode_export.rs`（`run_export_subprocess_sandboxed`、`pin_opencode_store`、`run_bounded_exporter`、`trusted_opencode_binary`）。
- `src/internal/ai/sandbox/` 共享执行器（`runtime.rs` 的 `SandboxManager::transform` / `create_bwrap_command_args_with_seccomp` / `create_seatbelt_command_args`、`policy.rs` 的 `SandboxPolicy`、`seatbelt_*.sbpl`）。
- `src/internal/ai/hooks/runtime.rs` 的 DR-04b 接线（`export_job::observe_idle` / `authorized_sandboxed_export`）。
- 测试：`tests/agent_opencode_bridge_test.rs`、`tests/agent_local_capture_smoke_test.rs` + driver `tests/harness/agent_local_capture.rs`、`tests/harness_self_test.rs`、`tests/compat/agent_docs_contract.rs`。
- 文档：`docs/development/tracing/agent.md`「OpenCode 安装流程契约」§5、`docs/commands/agent.md` EN + zh、`docs/development/commands/agent.md`、`COMPATIBILITY.md` `agent` 行。

### 非目标

- **不做 Option D（非 Linux 加固式非沙箱 + opt-in）**：明确拒绝——GC-DR-14「never an unsandboxed export」是本计划安全基线，任何平台都不引入 unsandboxed 路径。重启条件 = macOS Seatbelt 路径被 Apple 移除且无替代沙箱（届时另立 ADR）。
- **不做 Option E（Linux 侧车 / Lima 等 VM 转发）**：运行权重与失败面过大，不适合作为 hook 期子进程的默认形态。永久非目标（可作为高级用户旁路另行评估）。
- **不做 Option F（改用 plugin 事件内容、消除 export 子进程）**：破坏「受信二进制 + hash-pin」的 DR-04b 信任模型，plugin 信封是不受信输入。永久非目标。
- **不做「先做 B 的独立 seatbelt 分支、再由 C 删除」的两步**：产生 build-then-delete 浪费。本计划以 C（共享执行器）为机制、B（macOS Seatbelt 启用）为产出，见 ADR-SBX-01。
- **不改变 export 执行模型**：文件备份无损耗 stdout、`RLIMIT_FSIZE` 三重上限、进程组 kill、3s 墙钟、16 MiB 上限全部保留（ADR-SBX-02）；共享执行器只承担**沙箱装配**（`SandboxManager::transform`），不替换 `run_bounded_exporter` 的执行路径。
- 不改 `tests/harness/**` 的既有结构语义（只扩展 macOS seatbelt 验证面，继承 plan-20260827 的 GC-PS-05 精神）；不动 A6.5 的 Linux 验收口径。

### 成功定义

- **机制统一（装配层）**：`run_export_subprocess_sandboxed` 不再手写平台专属 argv，改经 `SandboxManager::transform`（`SandboxEnforcement::Required`）按 OS 自动生成沙箱化命令向量（Linux=bwrap+seccomp、macOS=seatbelt）；`opencode_export.rs` 内无平台分支的手写 sandbox arg 构造残留。
- **执行模型不变**：沙箱化命令仍由 `run_bounded_exporter` 执行（文件备份 stdout、RLIMIT、进程组、墙钟、字节上限逐项保留）；无损耗输出与「截断即失败」语义不回退。
- **Linux 保真**：Linux 上 bwrap 参数/语义与现状逐项**且按序**等价，由参数等价门 + `agent_opencode_bridge_test` 钉住；`SandboxEnforcement::Required` + 受信 bwrap 完整性门保证「沙箱不可用即 fail-closed 降级 metadata-only」，绝无 BestEffort 无沙箱执行（GC-SBX-02）。
- **macOS 启用**：macOS 上经 seatbelt（`/usr/bin/sandbox-exec`，实测在位）完成 export：store 目录可写（WAL SQLite 例外）、其余主机路径写被拒、网络被拒；`agent_opencode_bridge_test` 增加 seatbelt-gated 路径；A6.5 真机 smoke 在 macOS 具备 opencode 时通过。**读隔离不对称（seatbelt 全局读允许 vs bwrap 默认拒绝）作为有意差异显式披露**（ADR-SBX-03）。
- **文档收口**：`tracing/agent.md` §5 披露「macOS 支持 + seatbelt 弃用风险 + 读隔离不对称 + 平台沙箱可用性门控」；`docs/commands/agent.md` EN+zh 与 `docs/development/commands/agent.md` 同步 macOS 内容捕获行为；`COMPATIBILITY.md` `agent` 行同步。
- 所有非延后任务 `Lifecycle=done` 且 `Acceptance` 达到收口态；完成判据全绿（含模板三门全量收口）。

## 已决议设计决策

### ADR-SBX-01: 顺序与方案归属（C 为机制、B 为产出）

- **Status:** Accepted
- **Context:** 决策分析给出 B（`opencode_export.rs` 内直接加 macOS seatbelt 分支）与 C（复用共享执行器、按 OS 自动选沙箱）。若 B 先做、C 后做，C 必然删除 B 的专属 profile，产生 build-then-delete 浪费与双份装配中间态。
- **Decision:** 本计划以 **C（共享装配统一）为机制、B（macOS Seatbelt 启用）为产出**：先扩展共享装配 seam（SBX-02）→ export 桥改经 `SandboxManager::transform` 装配、执行仍走 `run_bounded_exporter`（SBX-03，Linux 保真）→ macOS 经共享 seatbelt 路径启用（SBX-04，含 store pin 移植与文档）→ macOS 验证与策略调优（SBX-05）。
- **Alternatives considered:** 「B 先行、C 后删」：拒绝（重复实现 + 双份漂移窗口）；Option D 非沙箱 opt-in：拒绝（GC-DR-14 安全基线）；E/F：拒绝（见非目标）。
- **Consequences:** macOS 能力晚于「独立 B」一两个卡片交付；SBX-02 改共享装配属跨切面（ER-13 T-1），需全量门。收益是长期单一事实源。
- **Revisit when:** 若 SBX-02 暴露共享装配 seam 成本远超独立 B（spike 判据），回退为「独立 B + 后续 C」，修订本 ADR。

### ADR-SBX-02: 共享装配 seam 形态（transform 装配 + run_bounded_exporter 执行分离）

- **Status:** Accepted（**SBX-01 spike 定稿 2026-08-31**；SBX-02 按本节开工，不再回该 spike）
- **Context:** ① export 必须保留文件备份无损耗 stdout（opencode 大输出在背压管道下会截断但仍 exit 0，`opencode_export.rs:17-27`），而共享全执行路径 `run_command_spec` 走管道（`mod.rs:1293`）——**不能**直接用 `run_command_spec` 执行 export；② 共享 bwrap 装配不 ro-bind HOME/XDG（`bwrap_read_only_host_paths` 仅系统目录，`runtime.rs:1093-1108`）；③ mount 顺序敏感：RO HOME/XDG 必须**先于** RW store bind，否则 RO 遮蔽 RW、WAL 写例外失效（`opencode_export.rs:473-486`）；④ `SandboxTransformRequest`（`runtime.rs:422-439`）现不能表达这三类输入。
- **Decision:** 复用 **`SandboxManager::transform`（纯装配函数，`runtime.rs:519`）** 生成沙箱化命令向量，执行仍走 **`run_bounded_exporter`（执行模型逐项不变）**。SBX-01 核读后的**最终 seam 形态**如下。

#### Spike conclusions（SBX-01, 2026-08-31）

**① transform 承载性 + `Required` fail-closed（GO，需扩字段）**

| 项 | 核读结论 | 锚点 |
|---|---|---|
| 现字段集不能直接承载三类输入 | `SandboxTransformRequest` = spec / policy / sandbox_policy_cwd / linux_sandbox_exe / use_linux_sandbox_bwrap / enforcement / deny_read_paths / seccomp_policy_path。**无** extra_ro_bind、writable-bind 三元组、`trusted_bwrap_exe` | `runtime.rs:422-439` |
| `Required` 无后端 fail-closed | `SandboxType::None` + `enforcement.requires_effective_sandbox()` + `internal_sandbox_required` → `EnforcementFailed` | `runtime.rs:641-649` |
| Linux 无 helper 且无 bwrap | `Required` → `EnforcementFailed`（文案点 `LIBRA_LINUX_SANDBOX_EXE` / `bwrap`）；`BestEffort` 才 unsandboxed | `runtime.rs:738-747` |
| 不安全通道（禁用于 export） | `locate_bwrap_binary`：`LIBRA_BWRAP_BINARY` 绝对路径存在即用，**无**完整性校验；`linux_sandbox_exe` 走 `create_linux_sandbox_command_args` helper 协议（`--sandbox-policy` JSON），非 bwrap | `runtime.rs:1047-1054`、`867-885` |
| 生产调用方 | AgentRuntime shell 经 `mod.rs:1524-1533` 构造 request；新字段必须默认空，该路径字节不变（GC-SBX-03） | `mod.rs:1524-1533`；测试字面量 11 处 `runtime.rs` `SandboxTransformRequest {` |

SBX-02 必须给 `SandboxTransformRequest` 增加：

```text
extra_ro_bind_paths: &'a [PathBuf]           // 默认 &[]
writable_binds: &'a [WritableBind]           // 默认 &[]；仅 source+destination 路径
trusted_bwrap_exe: Option<&'a Path>          // 默认 None
```

`WritableBind { source: PathBuf, destination: PathBuf }`——transform **只消费路径字符串** 生成 `--bind <source> <destination>`。逻辑三元组的第三元 **retained-fd 由调用方持有**，**不得**进入 `ExecEnv`（Codex SBX-01 R2 P1）：

- `ExecEnv` 现 `#[derive(Clone)]`（`runtime.rs:260`）；测试回退 `mod.rs:1582` 会 clone 整份 ExecEnv。`OwnedFd` 非 Clone，把 fd 放进 ExecEnv 会无法编译或被迫丢弃 Clone。
- `ExecEnv::into_command(self)`（`runtime.rs:297`）在 spawn **之前**消费 ExecEnv。若 fd 只活在 ExecEnv 里、且 `into_command` 未把它们挂到 `Command`，spawn 时 fd 已 drop，`/proc/self/fd/N` 失效。export 不走 `into_command`（走 `run_bounded_exporter`），AgentRuntime shell 走 `into_command`——把 fd 塞进 ExecEnv 会把两条执行路径绑死。

因此所有权契约 = **调用方 pin 得到 `OwnedFd` → 把 `/proc/self/fd/N` 与 dest 填进 `writable_binds` → transform 只出 argv → 调用方把 `Vec<OwnedFd>` 交给 `run_bounded_exporter` 的既有 `keep_fds` 直到 spawn 返回**（`opencode_export.rs:211-215` 现状）。SBX-02 单测 `seam_write_bind_tuple_source_dest` 用路径字符串即可，不持真实 fd。

**非 CLOEXEC 不变式（Codex SBX-01 R1 P1）：** 仅「fd 在父进程仍 open」不够——若 `FD_CLOEXEC` 置位，bwrap `exec` 后子进程看不到 `/proc/self/fd/N`，store bind 静默失败。现状 `pin_store_under` 在返回前显式 `F_GETFD`/`F_SETFD` 清 CLOEXEC（`opencode_export.rs:749-757`）。seam 要求：① pin 路径必须继续清 CLOEXEC；② 调用方 `keep_fds` **不得**把 CLOEXEC 设回去；③ SBX-03 以执行层回归钉住（pin helper 或 `runner_controls_preserved` 断言保留的 store fd `fcntl(F_GETFD)` 不含 `FD_CLOEXEC`）。macOS seatbelt 按路径绑定，此不变式 Linux-only。

当 `trusted_bwrap_exe` 为 `Some`：Linux 分支**必须**直接消费该路径，**跳过** `linux_sandbox_exe` helper 与 `locate_bwrap_binary`（含 `LIBRA_BWRAP_BINARY` / `PATH`）。注入路径缺失或对当前用户可写 → `Required` 下 `EnforcementFailed`（`seam_trusted_bwrap_rejects_user_writable`）。当 `None`：既有 helper / `locate_bwrap_binary` 路径不变。

**② 可写绑定「恰为 {store}」：专用 writable-bind 字段，不用 WorkspaceWrite（GO）**

候选评估：

| 候选 | 能否源≠目标 `/proc/self/fd/N → store` | 默认 `/tmp` | 其它副作用 | 结论 |
|---|---|---|---|---|
| A. 专用 `writable_binds` 字段 | 能（`--bind <src> <dest>`） | 不引入 | 默认空 → 既有 builder 空循环无 argv 变化 | **采用** |
| B. `WorkspaceWrite { writable_roots:[store], exclude_slash_tmp:true, exclude_tmpdir_env_var:true }` | **不能**：builder `--bind <root> <root>`（`runtime.rs:955`） | 可剔除 | 空 `writable_roots` 仍会把 cwd 当写 root（`policy.rs:788-790`）；store 上会挂 `.git`/`.libra` 保护子路径（`policy.rs:743-768`） | **拒绝**（无法表达 FD-pin；副作用过大） |

Export 的 policy 保持 **`SandboxPolicy::ReadOnly` + `NetworkAccessMode::Denied`**（与现状 `opencode_export.rs:450-456` 一致）。store 写例外**只**经 `writable_binds` 表达，集合恰为 `{store}`（测试 `seam_write_bind_set_exact`）。seatbelt：`build_macos_file_write_policy` 今日只读 policy 写 root（`runtime.rs:1198`）——ReadOnly 产生空写段；SBX-02 必须把 **writable_bind 的 destination** 并入 seatbelt 写策略，生成 `(allow file-write* (subpath <store>))`（`seam_seatbelt_store_write_segment`），**不**把 extra_ro_bind 变成新读段（全局 `(allow file-read*)`，`runtime.rs:1130`）。

bwrap 断言形态：`--bind <source> <destination>` 源≠目标可表达（`seam_write_bind_tuple_source_dest`）。seatbelt 断言形态：策略文本含 store 的 `file-write*` subpath；网络 Denied → 网络段空。

**③ macOS store pin（GO，路径级；强度差接受为 ADR-SBX-03）**

Linux 形态不可移植：`openat(O_PATH|O_DIRECTORY|O_NOFOLLOW)` + `/proc/self/fd/N`（`opencode_export.rs:698-724`；`O_PATH`/`/proc/self/fd` 为 Linux-only）。macOS 可行形态：

- `open(O_RDONLY|O_DIRECTORY|O_NOFOLLOW)` 钉住目录 inode（拒 symlink）
- `fcntl(F_GETPATH)` 取 canonical 绝对路径，作为 seatbelt 写 root / writable-bind destination
- pin 后立刻再校验路径存在且为目录
- `F_GETPATH` 失败 → fail-closed（SBX-04 `macos_pin_fgetpath_failure` 可注入解析 helper）
- Darwin 有 `/dev/fd/N` 但 seatbelt 按路径 subpath 匹配、不是 bwrap 的 fd bind，故 **F_GETPATH 是正确目标**，不假装 inode-pin

强度差 = 路径级匹配 vs Linux inode-fd（ADR-SBX-03 已接受）。SBX-04 落地，不在 SBX-02 做 pin。

**④ RLIMIT / 文件备份输出：留在 `run_bounded_exporter`（GO，DEFER-SBX-03）**

| 方案 | 成本 | 风险 |
|---|---|---|
| 留执行层（现状） | 零共享面 | 无 |
| 下沉 `CommandSpec` / `run_command_spec` | `CommandSpec`（`runtime.rs:47-62`）无 max_output_bytes / rlimit / 文件备份 stdout；`run_command_spec_inner` 固定 `Stdio::piped()`（`mod.rs:1293`）；要改 AgentRuntime shell 路径 | 管道截断陷阱重现；GC-SBX-03/04 违反 |

结论：不下沉。`run_bounded_exporter`（`opencode_export.rs:204-403`）保留文件备份 stdout、`RLIMIT_FSIZE`、进程组、3s 墙钟、16 MiB。DEFER-SBX-03 维持。

回退：若 SBX-02 实现中发现 builder 插入 extra_ro_bind 无法保持 HOME/XDG < store 而不破坏空集字节一致，才允许修订本 ADR（须新一轮双审）。当前核读：空切片循环是 no-op，空集字节一致可达成。

- **mount 顺序不变式（规范 argv / 同效 mount 表）**：当前 export 契约的**完整**实际顺序为「系统路径 ro-bind → `sandbox_cwd`（= binary parent，因 `ReadOnly` 无 writable roots 触发 `--ro-bind sandbox_cwd` 兜底，`runtime.rs:949-951`）→ HOME/XDG ro-bind → store writable-bind → 防御性 binary-parent 再 ro-bind → `--`」（`opencode_export.rs:450-456`、`463-500`；本调用 `deny_read_paths=&[]`，deny 掩蔽步当前为空操作——若未来非空，builder 会把它放在 `--` 拼接点之前、即 HOME/XDG 之前，与上述顺序不同，SBX-02 实现时按 builder 实际机制处理）。**binary parent 在现状中绑定两次**（`sandbox_cwd` 一次 + 防御性一次）。

  SBX-02 builder 落点：在 policy writable_roots / cwd 兜底 **之后**、`deny_read_paths` 与 `--` **之前**，按序插入 extra_ro_bind 循环、再 writable_binds 循环。因此 HOME/XDG（放进 extra_ro_bind）先于 store（writable_binds）。防御性 binary-parent 第二次 ro-bind 允许由 `sandbox_cwd` 去重省略（**同效 mount 表**，不要求逐字节 argv）。不得写成「全部 ro-bind 先于 store bind」。

  `bwrap_argv_equivalent`（SBX-03）按同效 mount 表判定，并在单测中固定最终期望序列。
- **Alternatives considered:** 直接用 `run_command_spec`：拒绝（管道截断破坏无损耗输出，`mod.rs:1293`）；把 RLIMIT/文件备份下沉为共享执行器通用参数：拒绝（SBX-01 成本对比，DEFER-SBX-03）；用 `WorkspaceWrite` 表达 store：拒绝（源=目标 bind + `/tmp`/cwd 默认写 root + metadata 保护子路径）。
- **Consequences:** 共享装配新增 extra_ro_bind + writable-bind 路径对 + `trusted_bwrap_exe`；retained-fd 留在 export 调用方（`keep_fds`），`ExecEnv` 保持 `Clone`。内部 AgentRuntime shell 路径策略语义不变（新字段默认空集，`mod.rs:1524-1533` 与全部既有 request 字面量补空）。Export 继续 `ReadOnly` + Denied 网络 + 专用 writable-bind，不启用 WorkspaceWrite。
- **Revisit when:** 出现第二个需要「只读绑定额外路径」或「文件备份无损耗输出」的调用方时；或 SBX-02 无法同时满足空集字节一致与 HOME/XDG < store。

### ADR-SBX-03: macOS 与 Linux 沙箱的两项有意差异（pin 竞态 + 读隔离不对称）

- **Status:** Accepted
- **Context:** ① Linux pin 用 `openat(O_PATH|O_DIRECTORY|O_NOFOLLOW)` + `/proc/self/fd/N` 原子解析并绑定被 pin 的 inode，防并发 rename/exchange；macOS 无 `O_PATH`/`/proc/self/fd`，seatbelt 按路径绑定。② 读隔离严重不对称：Linux bwrap 是默认拒绝（mount 命名空间只含显式 ro-bind 路径，`runtime.rs:918-970`）；macOS seatbelt 是默认允许读（全局 `(allow file-read*)` 减 curated deny 列表，`runtime.rs:1130/1161-1184`）——被沙箱的 exporter 可读调用用户可读的主机任意文件，Linux 侧看不到绑定外任何东西。
- **Decision:** 两项都作为**有意差异**接受并显式披露：
  1. **pin 竞态**：macOS pin 用 `open(O_RDONLY|O_DIRECTORY|O_NOFOLLOW)` + `fcntl(F_GETPATH)`/`/dev/fd/N` 解析 canonical 绝对路径，作为 seatbelt 写 root。强度差 = 路径级匹配而非 inode fd 匹配的窄竞态窗口；缓解 = pin 后立即重校验路径存在性与目录类型，且 exporter 已 hash-pin、输出按不可信输入处理（normalize/redact/claim）。
  2. **读隔离不对称**：macOS exporter 可读主机大范围文件（写入与网络仍被拒）。缓解 = exporter 二进制 sha256+路径 pin（受信且不可被攻击者替换）；导出内容经 normalize → redact → claim 管道（DR-04b 既有），读到的敏感数据在持久化前被脱敏。**文档义务**：`tracing/agent.md` §5 与 `docs/commands/agent.md` EN+zh 必须披露「macOS export 沙箱不限制读、只限制写与网络；与 Linux bwrap 的默认拒绝读不同」，避免操作者误判 posture 相当。
- **Alternatives considered:** 为 macOS 加白名单读策略（deny 全部读、只 allow store/config）：评估——需要枚举 exporter 的全部动态链接/系统读取面，维持成本高且易碎；spike 可复核「read-only store 快照到 tmpfs」路径以消除 store 写例外的同时收紧读面。默认不采用，作为 DEFER-SBX-05。
- **Consequences:** macOS 读面宽于 Linux（有意差异 + 文档披露）；写与网络仍受 seatbelt 拒绝。
- **Revisit when:** Apple 移除 `sandbox-exec` 或引入新沙箱 API；出现实际竞态/读越权利用证据；spike 复核确认快照方案可行。

## 全局工程约束

- **GC-SBX-01（Linux 保真）**：export 桥的任何装配切换不得静默改变 Linux 捕获行为。SBX-03 必须交付「新路径 bwrap argv 与当前契约逐项**且按序**一致」的参数等价门；`agent_opencode_bridge_test` 在 Linux 面保持全绿。
- **GC-SBX-02（永不 unsandboxed + 强制沙箱）**：任何平台、任何配置都不引入 unsandboxed export（GC-DR-14 延续）。装配必须显式 `SandboxEnforcement::Required`（共享执行器默认 `BestEffort` 不得沿用）；沙箱后端缺失/不受信 → 装配失败 → fail-closed 降级 metadata-only 并告警；不新增任何 opt-in 非沙箱 flag。
- **GC-SBX-03（共享装配最小 seam）**：SBX-02 对共享装配的改动以 export 所需 seam 为界（只读绑定额外路径 + 写 root 精确性 + mount 顺序不变式），不得改变内部 AgentRuntime shell 路径的既有策略语义；既有 sandbox 测试 + ER-13 全量门兜底。
- **GC-SBX-04（执行模型不变）**：`run_bounded_exporter` 的文件备份 stdout、RLIMIT、进程组、墙钟、字节上限逐项保留；任何改动不得把 export 输出改走管道或把截断标记为成功。
- **GC-SBX-05（继承默认）**：模板 GC-01..GC-12 全部生效；`libra` 工作流（GC-12 精确暂存、ER-07 签名预检）与 ER-13 分层测试按模板执行。
- **GC-SBX-06（门测试不标 `#[ignore]`）**：本计划全部具名**非 live** 门测试——SBX-02 的 seam 门（`seam_*`）、SBX-03 的 export 门（`bwrap_argv_equivalent`/`trusted_bwrap_*`/`backend_missing_degrades_metadata_only`/`runner_controls_preserved`/`trusted_bwrap_preflight`/`macos_kept_fail_closed`）、SBX-04 的 pin/seatbelt/库门（`macos_pin_*`/`macos_transform_selects_seatbelt`/`macos_sandbox_exec_missing_degrades`/`seam_seatbelt_store_write_segment`/`opencode_export_seatbelt_fake_exporter`/`macos_read_isolation_disclosure_pinned`）、SBX-05 的 `linux_a65_criteria_unchanged`——**不得标 `#[ignore]`**；仅 A6.5 真机段 `local_capture_smoke_opencode_macos` 为 ignore-gated。各卡 VER 的 `--include-ignored` 是机械兜底（即使误标也实际执行），源级不标 `#[ignore]` 是硬约束（逐卡以 `no_ignore` **精确属性块解析**守卫——Python 收集 fn 上方连续属性块（含多行 `#[...]` 续行，按 [] 平衡，遇非属性/非注释/非空行即停，不跨进前一个 fn），`#[ignore` 命中或 fn 缺失均 FAIL，解析错误 ERROR，存在且未 ignore=OK）。

**Description:** 按 ADR-SBX-02（SBX-01 定稿）在共享装配（`src/internal/ai/sandbox/`）增加 export 所需最小 seam：**(1) 只读绑定额外路径集合**——装配输入新增字段，bwrap builder 生成 `--ro-bind`（HOME/XDG 须先于 store writable-bind，顺序不变式）；binary parent 由 `sandbox_cwd`（现状已 ro-bind）与/或该字段承载，等价判据按同效 mount 表（允许去重）；seatbelt 侧无新读段（全局 `(allow file-read*)` 已是现状，仅作意图登记）；**(2) 可写绑定（writable-bind）**——transform 输入为 `(source, destination)` 路径对，以表达 Linux 的 `/proc/self/fd/N → store` FD-pinned bind（源≠目标）；逻辑第三元 retained-fd **由调用方持有**（不进 `ExecEnv`：该类型 `Clone` 且 `into_command(self)` 在 spawn 前消费，`runtime.rs:260/297`），可写绑定集合恰为 {store}（剔除默认 `/tmp` 写 root）；retained-fd 必须非 CLOEXEC；**(3) 受信 bwrap 显式传输字段 `trusted_bwrap_exe`**——`SandboxTransformRequest` 新字段，`transform` 直接消费、不再做环境/PATH 再发现（杜绝 `LIBRA_BWRAP_BINARY` 无完整性校验与 `linux_sandbox_exe` 非 bwrap 协议两条不安全通道），用户可写/缺失 bwrap 经该字段注入 → `Required` fail-closed。内部 AgentRuntime shell 路径策略语义不变（新字段默认空集，GC-SBX-03）。唯一行为轴 = 共享装配的 export 可表达性（含受信 bwrap 传输）。

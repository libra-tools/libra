# External-agent 数据读取能力改进计划（2026-07-13）

## 文档职责

本文规划 Claude Code、Codex 与 OpenCode 外部 agent 的 transcript 获取、导入、幂等写入、擦除防复活、子 agent 内容归属及只读图形化查看。目标是在不持久化未脱敏原文、不跨仓库混入会话、不破坏已冻结机器接口的前提下，安全补齐内容来源与历史回填。

本计划只定义可执行工作和验收，不以历史版本号、旧 release note 或外部项目的浮动分支证明实现状态。当前 checkout 已含大量相关组件；执行每张卡前必须重新核对事实，已落地的内容转为回归、文档或兼容收口，不得重做。

### 适用范围

- Claude/Codex 的安全发现与有界 transcript 读取，OpenCode 的受信 sandbox export，以及统一 `TranscriptSource` seam。
- live/import 的 typed normalize、redaction、coverage claim/revision、CAS、fence、import identity、tombstone 与子 agent 内容关联。
- `libra agent import`、`agent list` 显式 schema 协商、`libra agent graph <session>` 的 TUI/JSON 只读投影。
- SQLite migrations、命令双语文档、错误码、compat/integration/live-gated tests 与隐私/回滚说明。

### 非目标

- 不注册更多 hook 事件来替代内容读取；hook 是生命周期/归属/checkpoint 边界源，transcript 是内容源。
- 不提供默认主目录全扫、根外 `--path`、静默 non-TTY 读取、未经同意的跨仓库导入，或 SMTP/云端擦除承诺。
- 不重做 live whole-transcript checkpoint 的存储模型；全量 blob 的 O(n²) 历史成本单独立项。
- 不把 `agent graph` 接入 Code thread/`ai_index_*` 投影，也不为 capture 合成 `thread_id`。

### 成功定义

- 所有 provider 的来源在授权、大小和时间预算内被安全读取，并经同一 normalize → redact → digest → claim → persist 流程。
- 同一逻辑 turn 的重放、截断补全、并发和重试最多形成一个 current revision；ref/catalog/claim/identity 不出现可见半状态。
- import 只能显式选择、确认且匹配当前仓库；erase 在 discovery 与在途 writer 的最终事务中均为防复活屏障。
- v1 machine 输出保持冻结，新增能力通过显式协商；graph 只读取列白名单且不泄露内容、路径或自由文本。

## 已决议设计决策

### ADR-DR-01: 单一授权 TranscriptSource 入口

- **Status:** Accepted
- **Context:** hook path、import path 与 OpenCode export 若各自读文件/bytes，会绕过授权与 redaction。
- **Decision:** 所有 writer 只消费 `TranscriptSource::File`（provider-root 内安全打开的 handle）或 `TranscriptSource::Bytes`（受信 exporter 发出的绑定授权）；preparer 仅是 seam 的可选 flush 副作用，不能成为第二写入口。
- **Alternatives considered:** 各路径直接 `fs::read` 或让任意 bytes 进入 writer；会产生 TOCTOU 与授权绕过，拒绝。
- **Consequences:** writer 不得按 path 重开文件；OpenCode bytes 不落默认磁盘缓存。
- **Revisit when:** 新 provider 需要不同内容源时，先扩展授权类型与测试。

### ADR-DR-02: 固定安全流水线和逻辑 turn 身份

- **Status:** Accepted
- **Context:** 先持久化或按原始 digest 去重会泄露原文，且截断→完整会错误形成第二个 turn。
- **Decision:** 固定为“有界 raw read/export → 不可信结构解析 → typed normalize → 逐字段 redact → canonical digest → claim → persist”。claim 的唯一键为 session/logical turn/schema；revision 保存内容版本，`source_channel` 只作 provenance。
- **Alternatives considered:** raw payload 透传、先整段落盘再 split、digest 作身份；均拒绝。
- **Consequences:** unknown/raw provider fields 不得进入 digest 或 import/export 投影；live generic-redacted whole blob 是已记录兼容残差，未来 allowlist 化另立 RFC。
- **Revisit when:** coverage schema 或 live blob 格式升级时。

### ADR-DR-03: 原子写、fence 和 tombstone 必须在最终事务生效

- **Status:** Accepted
- **Context:** claim、ref/catalog、identity 分事务会 TOCTOU；仅在 discovery 查 tombstone 会让 in-flight writer 复活已擦除数据。
- **Decision:** 最终事务验证 owner/fence/expected state/tombstone，原子提交 ref CAS、catalog、revision、claim 与 identity。CAS head 改变时在事务外用新 head 重建对象后重试。erase 写 tombstone 并使旧 holder 失效；所有 writer 在同一事务查询它。
- **Alternatives considered:** metadata 后去重、DB 故障仍 append、读前一次 tombstone 检查；全部拒绝。
- **Consequences:** DB 门不可用时 fail-closed；可留下不可达对象但不得有可达重复或删除后复活。
- **Revisit when:** 事务 helper 或 cloud erase 语义改变时。

### ADR-DR-04: Import 明示同意与当前仓库边界

- **Status:** Accepted
- **Context:** 发现主目录会话、读取 `--path` 与非 TTY 批量导入都是敏感行为。
- **Decision:** 命令必须有 `--session`、`--path`、`--since` 或 `--all`；非 TTY/JSON 需要 `--yes`。仅导入已验证属于当前仓库的会话；`--yes` 不扩大 provider-root 或路径授权。批处理有 session/bytes/time 上限与可续 cursor。
- **Alternatives considered:** 默认全量扫描或 `--yes` 放宽路径；拒绝。
- **Consequences:** 跨仓库、歧义、tombstoned 数据显式 skip/quarantine/错误；非策略性失败以 partial 非零退出。
- **Revisit when:** 要支持经过审计的跨仓库导入时。

### ADR-DR-05: v1 冻结，graph 是 capture 的零写投影

- **Status:** Accepted
- **Context:** 既有 list JSON 与 capture 数据模型已经被使用；thread 投影和 metadata 有隐私/语义风险。
- **Decision:** `agent list` 默认 v1 字节形状与 schema version 不变，能力仅由明确 v2 请求返回。`agent graph` 只 SELECT session/checkpoint/claim/revision/tombstone/subagent 的列白名单；不读 blob、working_dir、description、metadata、digest，不触发 discovery/import/export 或任何写。
- **Alternatives considered:** 默认向 v1 加字段，或复用 `ProjectionResolver`/`ai_index_*`；拒绝。
- **Consequences:** legacy capture 显式 `unindexed`，erased 与不存在分开呈现；非 TTY 没有 JSON/machine 时稳定拒绝。
- **Revisit when:** 发布 versioned graph schema v2 时。

## 全局工程约束

- **GC-01 现状核实前置:** 每卡复核代码、迁移、文档、target 和外部 revision；已实现只补证据或回归。
- **GC-02 单一事实源:** source authorization、normalization、redaction、claim、identity/tombstone 和输出 schema 不得在 provider/CLI/test 各自复制。
- **GC-03 扩展边界:** `agent import`/`graph` 明确为 Libra-only，文档说明同意、隐私、替代流程和机器接口。
- **GC-04 输出与错误契约:** 人读、JSON/machine、退出码和 `LBR-*` 分别测试；v1 不隐式演进。
- **GC-05 文档同步:** 命令变更同步 EN/zh-CN、开发文档、`COMPATIBILITY.md`（适用时）、错误码和索引。
- **GC-06 测试索引:** 改 test target 同步 `Cargo.toml`、`tests/INDEX.md` 和适用的 compat README。
- **GC-07 安全默认值:** 未获 provider-root/bytes/sandbox/repo-identity/consent 授权时 fail-closed；不持久化未脱敏 raw。
- **GC-08 原子性与恢复:** 任何 session/checkpoint/claim/ref/catalog/identity/tombstone 写入定义事务、fence、CAS、崩溃窗口及恢复。
- **GC-09 并发与资源生命周期:** lease、子进程、FD、临时文件和队列设上限、超时、取消与清理；不得让 stale holder 影响新 owner。
- **GC-10 性能预算:** provider 扫描、export、raw read、JSON parse 有 entries/bytes/deadline cap；不增加无界全目录扫描。
- **GC-11 生产 panic 禁止:** 不新增裸 `unwrap()`、`expect()`、`panic!()`；用户错误需上下文与可操作修复方式。
- **GC-12 精确暂存:** 只 `libra add <相关路径>`，不使用 `commit -a`，不处理无关脏状态。

5. 完成后做 production-risk review；修复 findings 后重跑受影响验证。
6. 用 Libra 工作流精确暂存、签署提交。本文档改写是文档-only，不触发版本发布；代码切片才依开工实际版本发布。
7. 非 fast-forward 先整合并重验；网络/权限失败记录原因，不盲目重试。
8. 所有证据脱敏，不保存 transcript 原文、token、私有绝对路径或 exporter payload。

### 故障恢复矩阵

| 故障点 | 可接受残留 | 恢复动作 | 禁止结果 |
|---|---|---|---|
| raw read/export 超 cap 或格式错误 | 内存中的受限数据 | sanitized error/partial，下一次显式重试 | raw 落盘、静默成功 |
| claim 后、最终事务前崩溃 | lease 与不可达对象 | lease 过期后重放或 GC | 双 checkpoint/current revision |
| ref CAS 竞争 | 不可达旧 commit | 重读 head、重建对象、受限重试 | 把旧父 commit 接到新 head |
| erase 与 writer 并发 | tombstone/fence | old holder no-op/erased，显式 audited restore | 删除后重建 session/ref |
| graph schema/legacy 缺失 | 无写入 | 显式 unindexed/unavailable | 读取 blob 或伪造 turn |

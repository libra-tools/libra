## 文档职责

本文只规划 `libra add --pathspec-from-file` 错误条件的 Git 对齐，不实现代码、不提交、不发布。执行者开工时必须刷新源码锚点、上游 pin 与工作区状态。

### 适用范围

- `src/cli.rs` 的全局 parse-error 分类器：在 declined `--interactive` 拒绝之前识别 `--pathspec-from-file` 与 `-i/--interactive`、`--edit` 的组合冲突，同时保持两 flag 单独使用时在命令执行前 fail-closed。
- `src/command/add.rs` 的命令级校验：`-p/--patch`、位置 pathspec、`--pathspec-file-nul` 与空 pathspec 文件。

- 不实现 `add -i/--interactive` 交互选择（`DEFER-I669-01`）。
- 不实现 `add -e/--edit` 编辑流程；本卡不得在 `AddArgs` 增加 `interactive`/`edit` 布尔字段。

- 不新增或修改测试用例仓 case；现有 TC-0065 只作为外部判据。

### 成功定义

- `--pathspec-from-file` 与 `--interactive/--patch`、`--edit` 的组合先报 Git 命名的冲突，而不是 declined/unknown 诊断。
- `--pathspec-file-nul` 单独使用时报固定 requires 文案；空 pathspec 文件成功 no-op、stderr 固定、stdout 为空。
- 位置 pathspec 冲突的既有文案和退出码保持稳定。
- `--interactive` 与 `--edit` 单独使用时都在 `execute_safe` 之前失败，逐命令索引字节不变；不得因组合识别而变成可执行 flag。
- 原始 argv 扫描在 `--` 处停止；边界后的 `--interactive` / `--edit` 只作为 pathspec 数据，不得触发组合冲突分类。
- 文档、兼容矩阵、网站、测试、review、发布与远端证据同卡闭合。

## 已决议设计决策

### ADR-PSF-01：parse-error 组合冲突先于 declined/unknown，但单独 flag 仍 fail-closed

- **Status:** Accepted
- **Context:** `--interactive` 不是 `AddArgs` 字段，而是 clap 失败后由 `src/cli.rs` 的 declined 表分类；`--edit` 当前是普通 unknown argument。若只在 `add.rs` 增加 clap 字段，组合虽可到达命令校验，单独 flag 也可能进入 `execute_safe` 并暂存。
- **Decision:** 不给 `AddArgs` 增加 `interactive`/`edit` 字段。在 `classify_parse_error` 的 declined lookup 前增加 add 专用组合识别：仅扫描 `--` 之前的 option token，识别 `--pathspec-from-file FILE` / `--pathspec-from-file=FILE` 与 `-i/--interactive` 或 `--edit`；组合命中返回 129 + Git 冲突文案。未组合时，`-i/--interactive` 继续走既有 `LBR-UNSUPPORTED-001` declined 路径，`--edit` 继续走普通 clap usage；二者均在 `execute_safe` 前失败并保持 index 字节不变。`-p/--patch` 已被 clap 接受，仍在 `add.rs` 命令级 gate 处理。
- **Alternatives considered:** 在 `AddArgs` 增加两个 bool（会扩大可执行 surface，拒绝）；在 `main.rs` 特判（绕开单一 parse-error 分类点，拒绝）。
- **Consequences:** `src/cli.rs` 与其单测是必改生产/测试面；客观命中 ER-13 T-1。预扫描必须覆盖 `=`/分离值、短 flag，并忽略 `--` 后 token。
- **Revisit when:** Libra 真正实现 `add -i` 或 `add -e`。

### ADR-PSF-02：空 from-file 是有诊断的成功 no-op

- **Status:** Accepted
- **Context:** 当前解析空文件后丢失“来自 from-file”的来源信息，落入普通空 pathspec 用法错误；Git 对显式空列表返回 0 并在 stderr 给出首字母大写句子。
- **Decision:** 在读取前保留 `from_file_requested` 状态；解析结果为空且没有其它 whole-tree mode 时，在 index load/write 前返回成功输出：exit 0、stderr 恰为 `Nothing specified, nothing added.`（允许平台换行）、stdout 空。普通无参数 `libra add` 保持既有 129 错误。
- **Alternatives considered:** 把所有空 pathspec 改成成功（扩大行为，拒绝）；静默成功（偏离上游诊断，拒绝）。
- **Consequences:** 必须同时固定普通无参数回归与空文件 no-op，确保两条路径不混淆。
- **Revisit when:** Git 改变空 pathspec 文件合同。

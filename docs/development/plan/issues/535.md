# Issue #535：`grep` 位置参数、模式表达式、列号、函数行、二进制、颜色与选项分类对齐 Git 修复计划（2026-11-04）

> 模板版本：v2.16（不在 `code-only` 具名范围内，按默认版本化发布合同执行）。来源：[libra-tools/libra#535](https://github.com/libra-tools/libra/issues/535)（OPEN）。正文列出 6 类失败场景（行为/输出不一致、拒绝 `--column`、拒绝 `--recurse-submodules`、拒绝 `-p`、拒绝 `--and`、拒绝 `--show-function`）与「另有 5 个未列举的单例选项拒绝」；2026-09-23 的 6 条评论逐类给出触发场景，第 7 条评论关联 #478、#488。2026-11-02 起同一测试扫描又拆出 #918–#941 共 20 个细粒度 `grep` issue（见 ADR-GP-01）。状态：计划成稿，全部任务卡 `pending` / 空；Codex 计划评审见「Codex review log」。本文只规划，不宣称任何实现已完成。

## 文档职责

本文处理 Issue #535 在当前 `main` 上仍成立的 `libra grep` 与 Git 契约差异。目标：#535 正文与评论列出、且仍能复现的每一类场景，要么对齐 Git，要么显式归类为不支持并写进文档；并给出 #535 引用的上游用例如何复核。

新建或推进本计划时，必须在同一变更中更新 [`plan-status.md`](../plan-status.md)（状态、版本/提交、`YYYY-MM-DD HH:MM:SS UTC`）。

### 适用范围

- `libra grep` 的以下表面：
  - 位置参数语法：给出 `-e`/`-f` 时位置参数不再是模式；`--` 分隔；未知参数、找不到的路径、修订与文件同名的诊断；表达式选项必须在位置参数之前；
  - 位置修订：`<rev>`（提交、tag、树、`<rev>:<path>`、blob）搜索与 `<rev>:` 输出前缀；与 `--cached`、`--no-index`、`--untracked`、`--tree` 的冲突；
  - 模式表达式：`--and`、`--or`、`--not`、`(`、`)` 的优先级与分组，`--all-match`，以及 Git 的表达式语法错误；
  - `--column` 的列号；
  - `-p`/`--show-function` 的函数行，及 `diff=<driver>` 的 `funcname`/`xfuncname` 配置；
  - 二进制文件：`Binary file <path> matches`、`-l`/`-c`/`-q`/`-I`/`-L` 对二进制文件的处理、`-diff`/`binary`/`diff` 属性；
  - 颜色：`--color`/`--no-color` 与 `color.grep`、`color.ui`、`color.grep.<slot>`；
  - `--max-count` 的负值（不限）与达到上限后的后文上下文；
  - `--recursive`/`--no-recursive`，以及通配 pathspec 下 `--max-depth` 的忽略规则；
  - `-O`/`--open-files-in-pager` 的分类（非工作树诊断 + 工作树显式不支持）；
  - gitlink 条目与 `--recurse-submodules` 的分类。
- 对应文档：`docs/commands/grep.md`、`docs/commands/zh-CN/grep.md`、同步脚本生成的网站页 `../libra-backend/apps/tanstack-app/content/docs/commands/grep.en.md`、开发文档 `docs/development/commands/grep.md`，以及 `COMPATIBILITY.md` 第 233 行 `grep` 行（原地改写，不增删行）。
- 测试：`tests/command/grep_test.rs`（`command_test` 目标）；只读的既有 compat 目标 `compat_machine_porcelain_contract`、`compat_pathspec_magic`、`compat_help_flag_descriptions` 作为回归门。

### 非目标

- 下列同期细粒度 issue 与本计划不同轴，不在范围内，只登记顺序约束（DEP-GP-03）：#918（`-L --cached` 与 intent-to-add）、#921（仅存于索引的条目告警）、#923（`--no-index` 的目录树包含诊断）、#930（`-G`/`-F`/`-E` 优先级与 BRE）、#931（`-P`）、#932（引号路径的修订搜索）、#933（`-h`/`--no-filename`）。
- 不实现 `-W`/`--function-context`、`-<n>`（由 [`issues/478.md`](478.md) LG-16 保留，DEFER-GP-01）；不实现 `-P` 与 `--fixed-strings` 长名（478 LG-14）。
- 不实现子模块检索（#552）、`sparse-checkout`（#551）、`update-index --assume-unchanged`（#540）、`log --all-match`（#940）；这些缺口挡住部分上游用例，只登记依赖（DEP-GP-04）。
- 不改 Libra 全局错误输出合同（`Error-Code:` 行、紧凑 JSON 行），也不改 grep 既有的「命令错误退出 2」合同（ADR-GP-09）。
- 不改 Libra 分页器策略（固定 `less -R -F`，不读 `PAGER`/`GIT_PAGER`），因此 `-O` 在工作树上归类为不支持（ADR-GP-10）。
- 计划完成不以关闭 #535 或任何同期 issue 为条件；回复与关闭见 DEP-GP-06。

### 成功定义

- #535 的 6 类场景与 5 个单例拒绝在当前代码上逐项处理（GAP 表）：
  - `--column`、`--and`、`--recurse-submodules` 已被接受但语义错误或为空操作：分别按 Git 修正列号（GP-03）、改为表达式树（GP-02）、对 gitlink 显式分类（GP-10）；
  - `-p`/`--show-function` 实现 Git 的函数行（GP-04）；
  - 场景 1 的「行为/输出不一致」按根因修复：位置参数被当作模式（GP-01）、修订搜索缺前缀（GP-01）、二进制文件被跳过（GP-05）、颜色未输出（GP-06）、`-O --cached` 无诊断（GP-09）；
  - 单例拒绝 `-O`（GP-09）、`--recursive`/`--no-recursive`（GP-08）、`--max-count -1`（GP-07）按 Git 处理；`--full-name` 与 `--color` 已被接受（事实基线）。
- 每项行为都有 `command_test` 中的具名测试门；期望字节取自本计划「行为探针」表（ADR-GP-12）。
- EN、zh-CN、网站页、开发文档与 `COMPATIBILITY.md` 第 233 行与实现一致，`--help` 同步。
- 十张实现卡各自完成独立发布切片（ER-08），全部卡 `done` / `complete`，计划收口点 CLOSE-535 全绿。
- GP-11 已把 libra-testcases 维护者公开发布的复跑结果逐行写入本计划，并把仍失败的用例归到具体阻塞方。

### ADR-GP-02：位置参数语法与 argv 预扫描

- **Status:** Accepted
- **Context:** Git 的规则（探针 #2–#13、#68–#69；`t7810-grep.sh:1384-1404`）：先找第一个不作为选项值的 `--`；只要「有效表达式记号」非空（`-e` 的值、`-f` 文件中的非空行，以及 GP-02 起的 `--and`/`--not`/`(`/`)`；空的 `-f` 文件与单独的 `--or` 不计入，探针 #71），位置参数就全部是修订或路径，否则第一个位置参数是模式；`--` 之前的参数，给了 `--` 时全部按修订解析，否则从左到右「能解析为修订就是修订」，遇到第一个非修订即停止；其后的参数必须是存在的路径或看起来像 pathspec（含未被 `\` 转义的 `*`、`?`、`[`，或以长魔法 `:(` 开头；短魔法 `:/`、`:!`、`:^` 之后的部分仍须存在，探针 #85）。clap 不保留不同参数之间的相对顺序，也无法区分 `-e --` 中作为值的 `--` 与分隔符。
- **Decision:**
  1. **预扫描：** 新增 `src/command/grep/argv.rs`，提供 `pub(crate) fn normalize_grep_argv(raw_argv, root: &clap::Command) -> GrepArgvResolution`，照 `normalize_status_argv`（`src/command/status/input.rs:313`）的做法：用根命令的全局参数元数据定位 `grep` 子命令；在 `grep` 参数段内使用「根命令全局参数表 ∪ `grep` 子命令参数表」（与 `status/input.rs:345-365` 合并全局短选项的理由相同：全局选项如 `--max-connections <N>`、`--progress <MODE>` 可出现在子命令之后并消耗独立值）逐个跳过选项值，短选项簇中附着的值（如 `-efoo`）同样识别；不是 `grep` 的命令行原样返回；需要值的选项后紧跟的下一个参数一律视为该选项的值（即使它是 `--`、以 `-` 开头、或与 `--not` 等运算符同名），预扫描把每个 `-e`/`--regexp`/`-f`/`--file` 的分离值统一改写为附着形式（`-e --` → `--regexp=--`，`-e -.` → `--regexp=-.`）交给 clap，同时给 `regexp` 参数加 `allow_hyphen_values`，使附着与分离两种写法都不被 clap 当作新选项（探针 #89）；第一个未被当作值的 `--` 记为分隔符。结果记录：`seen_dashdash`、按出现顺序的表达式记号（每个 `-e` 值、每个 `-f` 文件、GP-02 的运算符）、位置参数（分隔符前、后两组）及每个表达式记号是否出现在第一个位置参数之后。`src/cli.rs` 的 `parse_async_scoped` 调用它（与 `normalize_status_argv` 并列），分发处改为 `command::grep::execute_safe_with_resolution(cmd_args, &output, Some(&grep_resolution))`；不经 CLI 的调用者仍用 `execute_safe`（resolution 为 `None`，按旧字段推导，不支持 `--` 语义）。
  2. **模式来源：** 「有效表达式记号」= 每个 `-e` 值、`-f` 文件中的每个非空行（空行按 Git 忽略，与现有 `grep.rs:607-612` 一致）、以及 GP-02 起的 `--and`/`--not`/`(`/`)`；`--or` 不计入（Git 中单独的 `--or` 不构成模式，探针 #71）。有效表达式记号非空时，位置参数全是修订/路径；否则第一个位置参数是模式。此时若位置参数段以一个 `--` 开头，该 `--` 只结束选项解析并被消耗，其后的参数作为模式（可以以 `-` 开头），分隔符的查找从模式之后开始（探针 #72：`grep -- mmap HEAD -- file`、`grep -- mmap HEAD`、`grep -- -- dd`）。
  3. **分类：** 模式之后、分隔符之前的其余参数：
     - 仓库已跟踪模式（未给 `--no-index`、`--untracked`）：解析结果分两类——「不是修订」（`CommitBaseError::InvalidReference`、`HeadUnborn`、`Ambiguous`，`src/utils/util.rs:1940-1956`）与「仓库读取失败」（`ReadFailure`、`CorruptReference`）。后者一律为 F 型拒绝（`failed to resolve revision '<arg>': <细节>`，`LBR-REPO-002`），既不回退为路径、也不输出任何结果。有分隔符时逐个按修订解析，「不是修订」为 T 型拒绝 `unable to resolve revision: <arg>`；无分隔符时从左到右尝试解析，解析成功且同时是工作树中存在的路径，为 UH 型拒绝 `ambiguous argument '<arg>': both revision and filename`；遇到第一个解析失败的参数即转为路径段。
     - `--no-index` 或 `--untracked`：不解析修订；有分隔符且分隔符前有参数，为 U 型拒绝 `--no-index or --untracked cannot be used with revs`。
  4. **路径校验（仅无分隔符时）：** 路径段的每个参数按 Git `verify_filename` 判定：含未转义的 `*`、`?`、`[`（`\` 转义其后一个字符，转义后的字符不算通配）或以 `:(` 开头，即通过；以 `:/` 开头时其余部分相对工作树根须存在（单独的 `:/` 通过），以 `:!`、`:^` 开头时其余部分相对当前目录须存在（单独的前缀通过）；其它参数相对当前目录须存在。不通过时：仓库模式下路径段的**第一个**参数为 UH 型 `ambiguous argument '<arg>': unknown revision or path not in the working tree.`（它也可能是拼错的修订），其后的参数与 `--no-index`/`--untracked` 下的全部参数为 UH 型 `<arg>: no such path in the working tree.`（探针 #85）。分隔符之后的参数不校验存在性（探针 #13）。
  5. **`--no-index` 的 pathspec 与缺失根：** `--no-index` 的路径参数也是 pathspec：先用共享的 `PathspecSet` 解析全部参数（含 `:(literal)`、`:(top)`、`:(exclude)` 等魔法），再从**正向**项推导遍历根：每个正向项取其魔法处理后、首个未转义通配符之前的目录前缀（`:(literal)` 项整体为字面路径；`:(top)` 相对工作树根，在仓库外相对当前目录；带 `:(icase)` 的项只取「上行前缀」作为根：先经公开的 `PathspecSet::positive_spec_match_path`（`src/utils/pathspec/mod.rs:219-224`）取得该项归一化后的工作树根相对路径，再换算为当前目录相对路径，取其开头的 `..` 段（`:(top)` 项即工作树根）；在仓库外则对去掉魔法前缀后的路径正文做词法归一化（保留开头的 `..`）后取开头的 `..` 段，`:(top)` 在仓库外即当前目录，其后的名称段一律不作为固定前缀，以免在大小写敏感的文件系统上从不存在的目录起步而漏掉文件；例如在 `t` 下 `:(icase)../V` 的根是 `..`（探针 #91）），无正向项（只有排除项）时以当前目录为根；遍历结果再按完整的 `PathspecSet` 统一过滤（探针 #77、#89）。多个参数的遍历根可能重叠（如 `file` 与 `fi*`），候选文件在搜索前按路径去重，每个文件至多搜索一次（现有收集函数只排序不去重，`grep.rs:918-927`）。分隔符之后、在文件系统中不存在的字面路径不作为错误，按「无文件」处理（退出 1、无输出、无 stderr，探针 #13）；改写现有 `get_no_index_files`（`grep.rs:841-928`）把缺失根转为错误的分支，存在但不可读的根仍按现有致命错误处理。
  6. **顺序：** 表达式记号出现在第一个位置参数之后，为 U 型拒绝 `option '<记号原文>' must come before non-option arguments`（GP-01 覆盖 `-e`/`--regexp`/`-f`/`--file`，GP-02 扩到运算符）。其它选项出现在位置参数之后仍按 Libra 现状接受（DEFER-GP-06）。
  7. **提示文本：** `ambiguous argument …` 两条的 hint 为 `Use '--' to separate paths from revisions, like this: 'libra grep [<revision>...] -- [<file>...]'`；`no such path …` 的 hint 为 `Use 'libra grep -- <path>...' to specify paths that do not exist locally.`。
- **Alternatives considered:** 只用 clap 的 `last = true` 收集 `--` 之后的路径：无法区分「有 `--` 但其后为空」与「没有 `--`」，也无法处理 `-e --`。直接改用 Git 的整体顺序约束（所有选项都必须在位置参数之前）：破坏大量现有 Libra 用法（如 `libra grep foo -n`）。
- **Consequences:** 对外行为变化：给了 `-e`/`-f` 时，位置参数不再是额外模式；`libra grep -e x foo` 中不存在的 `foo` 由静默改为报错。文档写明迁移方式（把额外模式改为 `-e`）。`src/cli.rs` 改动命中 T-1。
- **Revisit when:** Libra 决定对全部 grep 选项实施 Git 的选项先于位置参数规则。

### ADR-GP-03：修订搜索与输出前缀

- **Status:** Accepted
- **Context:** 探针 #14–#19、#47、#68。Git 对每个修订按命令行顺序搜索；行首为 `<修订原文>:` 加路径；`<rev>:<path>` 树以 `<原文>:` 加树内相对路径；blob 以 `<原文>` 本身代替路径；`-l`/`-L`/`-c`/`--heading`/`-z`/二进制提示同样带前缀；从子目录执行时按当前目录限定并显示相对路径（与 ADR-GR-02 一致）。
- **Decision:**
  - 每个位置修订用 `util::resolve_object_spec_typed` 解析，再用 `util::peel_to_non_tag_typed`（`util.rs:3125`）剥除任意层附注 tag：提交取其树，树直接使用，blob 作为单个搜索对象，其它类型为 T 型拒绝 `unable to resolve revision: <arg>`。
  - 显示名：提交/tag/树的条目为 `<原文>:<路径>`；blob 为 `<原文>`。整行格式不变，只把「路径」字段替换为显示名，`-n`、`--column`、`-z`、`--heading`、`-l`、`-L`、`-c` 均据此输出。
  - 由提交、tag 或纯树解析出的修订沿用 GR-02 的当前目录作用域与相对显示、`--full-name` 与 `--max-depth`；`<rev>:<path>` 树与 blob 不施加当前目录作用域，路径相对其自身根显示（与 Git 在子目录下的特殊输出不同，DEFER-GP-10）。
  - 多个修订按命令行顺序依次搜索，各自完整输出。
  - `--cached` 与位置修订同用为 U 型拒绝 `both --cached and trees are given`；`--tree` 与位置修订同用为 U 型拒绝 `--tree cannot be used with revision arguments`（Libra 扩展）。`--tree <rev>` 本身保持现状：只接受提交、不加前缀、JSON `context` 为 `tree:<rev>`。
  - **JSON：** 位置修订搜索时 `context` 为 `revisions`；`matches[]` 与 `counts[]` 的每个元素新增 `revision`（修订原文），`path` 保持树内路径（blob 为空串）；`files_with_matches`/`files_without_matches` 的元素为与人读输出相同的显示名。非修订搜索不出现 `revision` 字段。
- **Alternatives considered:** 让 `--tree` 也加前缀：改变既有 Libra 扩展的输出，脚本受影响，收益只是统一。拒绝 blob 修订：Git 支持且实现成本低。
- **Consequences:** `docs/commands/grep.md` 中「为什么用 `--tree`」一节改写为「两种写法并存」。
- **Revisit when:** 决定废弃 `--tree`。

### ADR-GP-04：模式表达式

- **Status:** Accepted
- **Context:** 探针 #31–#34；`t7810-grep.sh:216`、`:727`。Git 语法：`or := and { [--or] and }`（相邻项隐式 OR，`--or` 可省略，出现在开头或结尾时被忽略）；`and := not [ --and and ]`；`not := --not not | atom`；`atom := <模式> | ( or )`。`-f` 文件的每一行是一个模式原子，按出现位置插入。`--all-match`：括号只决定结构、不产生额外节点；OR 为右结合，沿 OR 树的右脊收集要求——右脊上每个 OR 节点的左子树算一项，右脊末端的非 OR 节点算一项；因此位于左侧的括号组算一项，而唯一的或最右侧的括号组会被展开到右脊中（探针 #86）。每一项都必须在文件中至少有一行命中，文件才输出由整个表达式选中的行。`-v` 对整个表达式取反。
- **Decision:**
  - 原子展开：位置模式与每个 `-e` 值在构建表达式之前按 LF 拆成多个有序原子（相邻片段之间等同隐式 OR，保留空片段——空模式匹配每一行，与 Git `grep.c` 的处理一致，探针 #88）；`-f` 文件按行展开且忽略空行（现状，探针 #71）。ADR-GP-02 的「有效表达式记号」按展开后的原子计。
  - 新增 `src/command/grep/expr.rs`：从 ADR-GP-02 的有序记号构建表达式树，求值返回是否命中；原子沿用现有的 `-F`/`-w`/`-i` 编译（`build_matcher`，`grep.rs:627-641`）。
  - `--and`、`--or`、`--not` 改为可重复的计数型旗标（只用于让 clap 接受），语义完全由有序记号决定；`(`、`)` 由预扫描在第一个位置参数之前识别为运算符（改写为隐藏旗标），之后出现的 `(`、`)` 仍是普通位置参数。
  - 语法错误为 U 型拒绝，消息与 Git 相同：`--and not preceded by pattern expression`、`--and not followed by pattern expression`、`--not not followed by pattern expression`、`--not followed by non pattern expression`、`unmatched ( for expression group`、`incomplete pattern expression group: )`；运算符出现在第一个位置参数之后为 `option '<记号>' must come before non-option arguments`。
  - 只给运算符而没有任何模式时，位置参数不作为模式（Git 行为，探针 #34 第 3 条）。
- **Alternatives considered:** 保留旗标模型、只修 `-e` 不命中：无法表达分组与重复 `--not`。
- **Consequences:** 对外行为变化：`--not` 不再对整个集合取反；`--and` 不再是「最后一个 and/or 生效」。文档与 `COMPATIBILITY.md` 同卡改写。取代 [`issues/478.md`](478.md) LG-15（DEP-GP-02）。
- **Revisit when:** 无。

### ADR-GP-05：`--column` 的列号

- **Status:** Accepted
- **Context:** 探针 #20–#30。Git 维护两个列值：处于偶数层 `--not` 之下的原子命中给出「正列」，奇数层之下的给出「反列」；带 `--column` 时 AND/OR 不短路，所有原子都参与；行因表达式为真而被选中时输出正列中最左的起点，因 `-v` 被选中时输出反列中最左的起点，没有则输出 1。`-o` 时每个命中各自输出其起点。
- **Decision:** 在 `expr.rs` 的求值中按上述规则返回 `(matched, col, icol)`；列号为 1 起的字节列。`-o` 时每个命中输出其实际起点 + 1；本机 Git 2.54 对同一行第二个及以后的命中少算 1（探针 #21），钉住的上游测试树（`t7810-grep.sh:315-332（期望列 14 位于第 326、328、330 行）`，TC-1648）期望实际列，本计划以上游测试树为兼容目标，并在文档中注明旧版 Git 的差异；同一规则也用于 `-o -p --column` 时函数行的命中片段（ADR-GP-06）。前文上下文（`-B`）与函数行不带列号；后文上下文（`-A`/`-C` 的后半）行若有偶数层原子命中，则输出其最左起点 + 1 作为列号，否则不带列号（钉住的上游源码 `grep.c` 对后文上下文传入 `col + 1`；探针 #82）。`-c`/`-l`/`-L` 不受影响。JSON 的匹配元素在 `--column` 时新增 `column`（1 起），恰在人读输出带列号的元素上出现。Libra 扩展 `-b` 保持现有合同不变：0 起偏移取该行上各原子命中起点的最小值（不区分 `--not`/`-v`，无命中为 0），与 `--column` 的规则相互独立（`gp03_byte_offset_unchanged` 守住）。
- **命中片段的选择（`-o`、着色与函数行片段共用）：** 在一行内从游标处起，取所有原子中起点最左的命中，起点相同取最长者，输出/着色后把游标移到其结束处继续；若某一步胜出的是零宽命中（含空模式），该行的片段扫描立即结束：不再输出或着色其后的任何命中（与钉住的上游源码 `grep.c` 一致）；该行仍被选中，退出 0（`-o -e ''` 无输出；`-o -e '' -e only` 也无输出；`-o -e '' -e foo` 在行首以更长的 `foo` 胜出后，下一步零宽胜出即结束，探针 #90）。现有 `-o` 按模式顺序展开（`grep.rs:536-556`）与着色时同起点取短（`grep.rs:1487-1507`）均改为此规则（探针 #89）。
- **Alternatives considered:** 各模式首个命中的最小值：在 `--not`、`-v` 下与 Git 不同（探针 #23、#27）。
- **Consequences:** 无。
- **Revisit when:** 无。

### ADR-GP-06：`-p`/`--show-function` 函数行

- **Status:** Accepted
- **Context:** 探针 #35–#44；`t7810-grep.sh:1040-1069`、`:662-680`。函数行规则：路径的 `diff` 属性为 `diff=<driver>` 且配置了 `diff.<driver>.xfuncname`（扩展正则）或 `diff.<driver>.funcname` 时用该规则（多行、以 `!` 开头的行为排除），否则用默认规则（行首为字母、`_` 或 `$`）。
- **Decision:**
  - 新增共享模块 `src/utils/funcname.rs`：`pub(crate) struct FuncnameRule`，提供按路径与属性来源构造、判断某行是否函数行的方法；供 grep 使用，并预留给 [`issues/478.md`](478.md) LG-16 的 diff hunk 头接入（DEP-GP-02）。`funcname`（Git 为 BRE）与 `xfuncname` 都按 Rust `regex` 编译，BRE 差异登记 DEFER-GP-08；Git 内置驱动（`diff=cpp` 等）的规则不实现，按默认规则处理（DEFER-GP-02）。
  - 输出：对每个被选中的行，向前查找最近的函数行；若该函数行既未作为命中行输出、也未作为函数行输出过，则在该命中所在块之前输出它，分隔符为 `=`（含 `-n` 时行号后也为 `=`）；落在 `-B`/`-C` 上下文中的函数行以 `=` 代替 `-` 输出；函数行本身命中时只按命中行输出一次。
  - `-c`、`-l`、`-L`、`-q` 下不输出函数行。`-o` 下函数行若含原子命中，则把每个命中片段作为一行、以 `=` 为分隔符输出（含 `-n` 时行号后也为 `=`）；不含命中的函数行不输出（探针 #83）。`-o -p --column` 时 Git 2.54 对函数行片段的列号输出不一致（首个片段无列号、后续片段给出错误的值，探针 #83），Libra 对函数行片段按 ADR-GP-05 的 `-o` 规则输出实际列号（有意差异，无上游用例依赖，文档注明）；`--max-count` 不把函数行计为命中。`diff` 属性经 GP-05 的 `GrepAttributeReader` 读取，来源规则同 ADR-GP-07（工作树/`--cached` 回退索引，修订只读工作树；探针 #75）。
  - JSON：函数行作为 `matches[]` 元素输出，新增字段 `is_function: true`，不计入 `total_matches`。
  - 给出 `-p` 时，在搜索前编译配置中全部 `diff.<driver>.xfuncname`/`funcname`；多行规则的最后一行以 `!` 开头为 U 型拒绝 `Last expression must not be negated: <该行>`（探针 #80）；任一编译失败为 U 型拒绝 `Invalid regexp to look for hunk header: <模式>`（Git 只在某文件实际用到该驱动时才失败，Libra 提前到搜索前，以保证拒绝不晚于任何输出；有意差异，见文档错误表）。
  - `-W`/`--function-context` 不在本计划（DEFER-GP-01），仍为 clap 未知参数。
- **Alternatives considered:** 等待 478 LG-16 一起实现：LG-16 依赖未评审的 LG-15、LG-03 与 LG-01，#535 场景 4、6 将长期挂起。
- **Consequences:** 新增共享模块，命中 T-1。
- **Revisit when:** 478 LG-16 开工时，diff 接入同一模块。

### ADR-GP-07：二进制文件

- **Status:** Accepted
- **Context:** 探针 #45–#49。Git 以属性优先：`diff` 未设置（`-diff`，或 `binary` 宏）为二进制；`diff` 已设置为文本；`diff=<driver>` 或未指定时看内容（前 8000 字节含 NUL）。二进制文件中有被选中的行时输出 `Binary file <显示名> matches`，`-l` 列出、`-c` 计数、`-q` 退出 0、`-L` 不列出；`-I` 下二进制文件不匹配且无告警；`-a` 当作文本；`-a` 与 `-I` 写入同一状态，按出现顺序最后者生效（探针 #88）。属性来源：工作树与 `--cached` 搜索读工作树的 `.gitattributes`，某目录在工作树中没有该文件时回退到索引中的版本；修订搜索只读工作树（不回退索引）。
- **Decision:**
  - 在 `src/utils/attributes.rs` 新增一个调用级读取器 `pub(crate) struct GrepAttributeReader`：构造时至多加载一次索引（调用级快照，不在每次查询时重新 `Index::load`，对比现有 `read_attribute_source_contents` 每次查询都重新加载索引，`attributes.rs:391-416`），按目录缓存「工作树文件 / 索引回退内容 / 不存在」的正、负查找结果；提供 `diff_state(path, mode)`（供 GP-04 的函数行驱动使用）与 `binary_decision(path, mode) -> BinaryDecision { Binary, Text, Auto }`。`mode` 为工作树/`--cached`（工作树优先、目录缺文件时回退索引）、提交类修订（提交或剥到提交的 tag，以及 `<rev>:<path>` 解析出的 blob——以冒号后的路径查询；只读工作树），或「无路径属性」（裸树对象，如 `HEAD^{tree}`、`HEAD:` 与 `<rev>:<dir>` 树：一律按未指定属性处理，二进制只看内容、函数行用默认规则）。这与 Git 按对象类型决定是否传入属性路径一致（探针 #87）。修订搜索需保留解析后的对象类型与属性路径。不改既有 `AttributeSourceKind` 枚举与其调用者。
  - 宏：读取器在合并赋值时按出现位置把内置宏 `binary` 展开为 `-diff -merge -text`，后出现的 `diff`/`!diff`/`-diff` 覆盖之（探针 #74）；其它宏不展开（属性宏的一般支持不在本计划）。
  - 共享快照：工作树与 `--cached` 搜索的候选枚举已经加载索引（`grep.rs:1028-1048`）；读取器直接复用这一份已加载的 `Index`，不另行加载。修订搜索不加载索引。
  - 调试计数：debug 构建且 `LIBRA_TEST=1`、`LIBRA_TEST_GREP_ATTR_STATS=1` 时，统计本次 grep 调用中全部 `Index::load`（候选枚举与读取器合计），grep 结束前向 stderr 输出一行 `grep-attr-stats: index-loads=<n>`（沿用 `tag.rs:889-902` 的仅调试测试钩子写法），用于验证索引只加载一次。`diff=<driver>` 的 `diff.<driver>.binary` 配置不实现（DEFER-GP-03）。
  - 输出：人读输出如 Git；不再产生 `skipped binary file` 告警。JSON 新增 `binary_matches`（显示名数组），这些文件的选中行计入 `total_matches`、文件计入 `total_files`，但不进入 `matches[]`。
  - 超过 512 KiB 的文件仍按现状跳过（`grep.rs:399-400`，不在本计划）。
- **Alternatives considered:** 只看内容不看属性：`t7815` 的属性用例继续失败。
- **Consequences:** 对外行为变化：二进制文件命中从「跳过 + 告警 + 退出 1」变为「报告命中 + 退出 0」。
- **Revisit when:** Libra 的通用属性解析实现宏展开时，读取器改用它。

### ADR-GP-08：颜色

- **Status:** Accepted
- **Context:** 探针 #62–#64。Git 的启用顺序：命令行 `--color[=<when>]`/`--no-color` > `color.grep` > `color.ui` > 终端检测；`color.grep`/`color.ui` 接受 `always`、`never`、`auto` 与 Git 布尔值（`true`/`yes`/`on`/非零整数等同 `auto`，`false`/`no`/`off`/`0`/空值等同 `never`；探针 #79），其它值为致命错误。槽位与默认值：`filename` 洋红、`lineNumber` 与 `column` 绿、`separator` 青、`matchSelected` 与 `matchContext` 粗体红（`match` 同时设置两者）、`context`/`selected`/`function` 为空。颜色值语法为 Git 的属性词加前景/背景色（名称、0–255、`#rrggbb`），非法值为致命错误。转义序列以 `\e[m` 结束。
- **Decision:**
  - 新增共享模块 `src/utils/git_color.rs`：`pub(crate) fn parse_git_color(value) -> Result<String, GitColorError>`，返回 SGR 序列（`normal`/空返回空串），字节与 Git 相同（如 `bold red` → `\e[1;31m`，`black yellow` → `\e[30;43m`，`#ff0000` → `\e[38;2;255;0;0m`）。不回改 `status` 的现有颜色逻辑。
  - 启用：`OutputConfig.color` 为 `Always`/`Never`（含 `--no-color`、`NO_COLOR`、`--machine`）时直接决定；为 `Auto` 时依次看 `color.grep`、`color.ui`，最后看 stdout 是否终端；JSON 输出永不着色。全局 `--color` 的默认值即为 `auto`，因此显式 `--color=auto` 无法压过 `color.grep=always`（DEFER-GP-07）。
  - `color.grep`/`color.ui` 按上述 Git 规则解析；不属于其中任何形式的值为 U 型拒绝 `bad boolean config value '<值>' for '<键>'`；非法槽位值为 U 型拒绝 `invalid color value '<值>' for 'color.grep.<slot>'`；二者在读取配置时检查，与是否着色无关。
  - 函数行（`-p` 输出的 `=` 行）：正文各非命中片段分别用 `function` 槽位包裹（含开头的空片段），其中的原子命中用 `matchContext`（探针 #81）。
  - 渲染逐字节按 Git：命中高亮覆盖表达式中所有原子（含 `--not` 之下的原子）在该行的命中，选中行用 `matchSelected`、上下文行用 `matchContext`（探针 #76）；文件名（含修订前缀）一个单元；`:`、`-`、`=` 与 `--` 用 `separator`；`-z` 的 NUL 不着色；选中行的非命中片段用 `selected`（每段各自包裹，含空的尾段）；上下文行用 `context`，其中的命中用 `matchContext`；`-v` 选中的行同样标出全部原子命中（用 `matchSelected`，探针 #82）。
- **Alternatives considered:** 继续用 `colored` crate：转义序列与 Git 不同（`\e[0m`），上游的 `test_decode_color` 比较失败。
- **Consequences:** 新增共享模块，命中 T-1。
- **Revisit when:** 其它命令需要 Git 颜色槽位时复用本模块。

### ADR-GP-09：错误合同

- **Status:** Accepted
- **Context:** Git 对本计划涉及的全部用法与前置条件错误都以 `die()` 输出 `fatal: …` 并退出 128；Libra grep 的既有合同是命令错误退出 2（`grep.rs:362-365`，文档 `docs/commands/grep.md:28`），`--[no-]exclude-standard` 的同类差异已在文档登记。
- **Decision:** 新增拒绝全部在 `run_grep` 内、读取任何搜索对象与输出任何内容之前产生，因此退出 2。Git 以 `fatal:` 报告的，构造为 `CliError::fatal(<Git 原文去掉 "fatal: ">)` 加稳定码：用法类 `CliInvalidArguments`（U/UH 型），修订无法解析 `CliInvalidTarget`（T 型，沿用 `--tree` 无效修订的码）；修订解析时的仓库读取失败 `RepoCorrupt`（F 型，与 `grep.rs` 现有读取失败的码一致）；Libra 显式不支持的，构造为 `CliError::failure(msg).with_stable_code(StableErrorCode::Unsupported).with_hint(hint)`（X 型）。Git 的 128 与 Libra 的 2 之差写入文档错误表。
- **Alternatives considered:** 用 128 对齐 Git：打破 grep 已文档化的 0/1/2 合同（`compat_machine_porcelain_contract`）。
- **Consequences:** 上游 `test_must_fail` 成立；比较完整 stderr 的用例仍会因 `Error-Code:` 行与紧凑 JSON 行失败，这是全局合同。
- **Revisit when:** 全局错误输出合同或 grep 退出码合同变化。

### ADR-GP-10：`-O`/`--open-files-in-pager` 分类

- **Status:** Accepted
- **Context:** 探针 #56–#57；`t7811-grep-open.sh:43-80`。Git 用 `GIT_PAGER`/`core.pager`/`PAGER` 打开命中文件，`-O<cmd>` 的值必须紧贴；`--cached` 或给出修订时以 `--open-files-in-pager only works on the worktree` 失败。Libra 的分页器固定为 `less -R -F`，不读 `PAGER`（`CLAUDE.md`「Environment Variables」`LIBRA_PAGER` 条）。
- **Decision:** 接受 `-O[<cmd>]`、`--open-files-in-pager[=<cmd>]`（值只能紧贴；预扫描把 `-O<cmd>` 改写为 `--open-files-in-pager=<cmd>`）。`--cached`、位置修订或 `--tree` 时为 U 型拒绝 `--open-files-in-pager only works on the worktree`；其它情况（工作树、`--no-index`）为 X 型拒绝 `--open-files-in-pager is not supported`，hint 为 `use 'libra grep -l <pattern>' and open the listed files yourself`。Libra 不启动任何外部程序（GC-GP-02）。
- **Alternatives considered:** 实现分页器启动：与 Libra 分页器策略冲突，并让 grep 产生由参数决定的任意子进程。
- **Consequences:** `t7811` 的 `-O --cached` 用例可通过；`-O` 工作树与 `--no-index` 用例保持失败，归属本 ADR（DEFER-GP-05）。
- **Revisit when:** Libra 分页器策略改为读取 `PAGER`。

### ADR-GP-11：gitlink 条目与 `--recurse-submodules`

- **Status:** Accepted
- **Context:** 探针 #58–#61。Git 只进入「活动且已检出」的子模块，未检出的 gitlink 在任何模式下都被静默跳过；`--recurse-submodules` 与 `--untracked` 互斥；`--no-index` 忽略 `--recurse-submodules`。Libra 没有子模块支持（#552），gitlink 在工作树搜索中告警、在 `--cached` 搜索中致命失败。
- **Decision:**
  - 不论是否给出 `--recurse-submodules`，工作树、`--cached`、位置修订与 `--tree` 搜索都静默跳过 gitlink（mode `160000`）条目：不读取、不告警。
  - 给出 `--recurse-submodules`（且未被其后的 `--no-recurse-submodules` 覆盖；两者改为最后者生效）时：在工作树、`--cached`、位置修订与 `--tree` 搜索中，经 pathspec 与当前目录作用域筛选后仍在范围内的 gitlink（「在范围内」按前导路径判定：pathspec 匹配 gitlink 路径本身，或可能匹配其下的路径——如 `sm/inner`、`sm/*`——都算在范围内，与 Git 的子模块路径匹配一致；现有 `PathspecSet::matches_path` 只做全路径匹配，GP-10 在 `grep.rs` 内对 gitlink 条目另做前导路径判定，不改共享 pathspec API） 若在工作树中已检出（`<path>/.git` 或 `<path>/.libra` 存在），为 X 型拒绝 `--recurse-submodules cannot search populated submodule '<path>'`，hint 为 `Libra does not search submodules yet; run libra grep inside the submodule`；未检出的照常跳过。
  - `--recurse-submodules` 与 `--untracked` 同用为 U 型拒绝 `--untracked not supported with --recurse-submodules`；`--no-index` 下忽略该旗标。
- **Alternatives considered:** 保持无声空操作：对已检出子模块给出不完整的结果而不告知。对已检出但未激活的子模块也照 Git 静默跳过：Libra 无法判断激活状态，fail-closed（GC-07）。
- **Consequences:** 有意差异：Git 会搜索活动的已检出子模块，Libra 拒绝（DEFER-GP-04）。
- **Revisit when:** #552 落地。

- **Context:** CI 有 `git`，但版本不固定。
- **Decision:** 测试门把期望字节写成测试内字面量，来源是本计划「行为探针」表与各卡判据规范；运行时不调用 Git。
- **Alternatives considered:** 运行时现场调用 Git 生成期望值：随 Git 版本漂移。
- **Consequences:** Git 行为变化时需人工更新字面量。
- **Revisit when:** Git 改变上述任一输出。


# Issue #869：Windows 库测试未使用的 normalize_json_value import（2026-11-02）

> 模板版本：v2.16。来源：[libra-tools/libra#869](https://github.com/libra-tools/libra/issues/869)。状态：WIN-01 为 `in-progress` / 空。三处测试 import 已收到 `#[cfg(unix)]`；Windows job 证据尚未登记，不宣称完成。

## 文档职责

本文规划修复 Issue #869：Windows 的 `compat-scoped-input-windows` 在 `cargo test --locked --lib` 上被 `-D warnings` 拦住，因为三处 `#[cfg(test)]` 模块导入了 `normalize_json_value`，而所有调用点都在 `#[cfg(unix)]` 里。

新建或推进本计划时，必须在同一变更中更新 [`plan-status.md`](../plan-status.md)。

### 适用范围

- `src/internal/ai/capture/catalog.rs`、`pending.rs`、`recovery.rs` 里上述测试 import 的编译条件。
- 让这些 import 与现有 Unix 调用点使用同一 `#[cfg(unix)]` 边界。
- 证明 Windows 库测试能通过 `-D warnings` 编过这三处，且 Unix 上原调用仍然编译。

### 非目标

- 不改变 `normalize_json_value` 的规范化行为，也不改 Unix 测试断言。
- 不改 capture 生产路径、公开命令、错误码或用户文档。
- 不处理 PR #868 的 fetch 对象缺失失败。那是另一条路径。
- 不改 `src/utils/path.rs`、`src/utils/object_ext.rs`、`src/command/status.rs` 或 `src/internal/worktree_scope.rs`。这些文件属于另一条在途工作。

### 成功定义

- 非 Unix 的库测试构建不再把这三处 import 当成 unused import。
- Unix 上原有调用点仍然能解析 `normalize_json_value`。
- `compat-scoped-input-windows` 不再停在 “Listing the scoped Windows fixtures failed”。夹具本身的通过与否另计，不由本卡冒充。

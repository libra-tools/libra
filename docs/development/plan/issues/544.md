### 成功定义

- `diff-files -p <path>` 与 `diff-files -p -- <path>` 都产生同一路径限定的 patch；多个裸路径按 Git 的输出次序呈现，未知选项仍按既有用法错误拒绝。
- `--no-patch --patch` 输出 patch，`--patch --no-patch` 不输出 diff 体；短选项具有同样的最后者生效语义。
- `--patch-with-raw` 的 raw 记录在前；存在 raw 时保留 Git 2.56.0 的分隔空行（即使 stat-dirty 导致 patch 为空），有 patch 则接其内容；raw 与 patch 均为空时整体无输出。其后出现 `--no-patch` 时抑制全部 diff 体。
- 行为复用同一 diff 引擎，porcelain `diff --raw` / `diff --stat` 不因 plumbing 的隐藏标记而改变。
- 每项行为在 `command_test` 有具名新用例，EN、zh-CN、网站、开发文档与 `COMPATIBILITY.md:230` 同卡同步。
- DFF-01、DFF-02、DFF-04 各自完成独立 `patch` 发布；DFF-04 同一发布边界包含组合实现与全部隔离验证。DFF-05 已废弃并入 DFF-04；DFF-03 取得钉住的上游复跑，以及四项未知选项的维护者清单或无法交接的明确确认；CLOSE-544 收口点全绿，缺必需证据时保持 blocked。

## 已决议设计决策

实现时若需偏离本节，必须先修订本计划并重新评审，不得在代码中静默改变语义。

### ADR-DFF-01：以当前 main 与后写评论界定范围

- **Status:** Accepted
- **Context:** 0.23.49 正文中的 `-p` / `--no-patch` 拒绝在当前 clap 中已不存在；0.30.91 后写评论给出仍可定位的裸路径失败。
- **Decision:** 实现 GAP-01..03，按 DEFER-DFF-05 对 GAP-05 逐项分类并同步全部文档；whitespace 与未列举选项保持证据边界。上游复跑缺证据一律 blocked，不能由分类或用户决定替代。
- **Alternatives considered:** 按旧标题重写已有选项会重复工作；忽略原场景或把所有 diff-files 选项一次补齐都不符合 issue 与单轴要求。
- **Consequences:** #544 可能因 DEFER-DFF-01/02/05、上游阻塞或其它命令缺口继续保持 OPEN。
- **Revisit when:** 维护者给出未列举选项或新结果表明 whitespace 仍由本命令触发。

### ADR-DFF-02：裸路径只在 wrapper 扩展，委托时仍补 `--`

- **Status:** Accepted
- **Context:** `paths(last=true)` 是唯一阻止裸路径的 clap 约束；共享 porcelain `diff` 会把 `--` 前的位置参数按 revision/path 规则消歧。
- **Decision:** `DiffFilesArgs.paths` 接受普通尾随位置参数，同时保留 `--` 形式；`execute_files_safe` 仍调用 `push_paths`，使全部路径在合成 argv 中位于 `--` 之后。`-` 开头的未知令牌仍由 clap 拒绝，不实现 revision 解析、stage selection 或 option/path 混排的额外扩展。
- **Alternatives considered:** 直接把裸路径塞进 porcelain `diff` 的 `pathspec` 会引入 revision 歧义；同时改 diff-index/tree 属于跨命令扩张。
- **Consequences:** 这是 `diff-files` 的定向兼容修正，`COMPATIBILITY.md:230` 不再写“paths require `--`”。
- **Revisit when:** 三个 plumbing 命令决定统一完整 Git 参数解析器时。

### ADR-DFF-03：最后者生效与显式 patch 组合使用内部标记

- **Status:** Accepted
- **Context:** 当前布尔字段丢失顺序，`no_patch` 固定优先；渲染器的 `raw` 分支会吞掉 patch。P-DFF-02/03/05/06 是可观察对照；`patch_body_is_shown` 还控制外部驱动，不能只改渲染分支。R2 审查确认：DFF-02 与 DFF-04 分别发布时，DFF-02 的状态机会产生「patch 与 raw 同时被选」的集合，而其发布窗口内组合渲染尚未交付，必须为该窗口写明自洽、可测试的过渡合同。
- **Decision:**
  - DFF-02 保留 argv 中每次 patch/no-patch/raw 的先后：`--no-patch` 清空已选输出，之后 `--patch` 与 `--raw` 分别重新加入；不能对所有字段简单 `overrides_with`。`--name-only` / `--name-status` 与这些选项混用时维持现有 `push_output_mode` 的名称模式优先级（两者并存时 name-only 优先），不纳入新状态机；DFF-02 对两种混合形式保留定向基线快照。保持 clap 对未知选项和路径的拒绝边界。**过渡合同（DFF-02 发布窗口）**：patch 与 raw 同选仍由既有渲染器输出 raw-only；`--patch-with-raw` 仍按未知选项退出 129。该合同写入 `COMPATIBILITY.md:230` 与开发文档，发布前评审复核；DFF-04 同批改写。
  - DFF-04 在同一发布边界增加 `--patch-with-raw`、隐藏 `--plumbing-patch`、组合渲染与驱动/结构化/porcelain 隔离的全部实现和测试。当有序选择结束时 patch 与 raw 同选，wrapper 注入隐藏标记及 `--no-ext-diff`；`patch_body_is_shown` 仅为该组合允许 patch，避免配置外部驱动（P-DFF-06）。**字节约定**：`format_diff_raw` 对非 `-z` raw 去掉末尾 LF（`render.rs:621-624`），`format_unified_diff` 去掉各 patch 末尾 LF（`:703-710`）；二者均非空时内部字符串为 `raw + LF LF + patch`，最终普通 pager 路径再补一个终止 LF（`:375-386`）。raw 非空且 patch 为空时，内部为 `raw + LF`，pager 补 LF 后 stdout 恰以两个 LF 结尾，见 P-DFF-09；两者均空时早退，stdout 空、退出 0（P-DFF-07/08），不得凭空产生分隔符。`-z`/binary/verbatim 等走不同终止路径，执行前须单独核对现有合同，不从非 `-z` 推断。DFF-04 同卡改写 DFF-02 过渡合同文档与过渡测试。
  - 既有 porcelain `diff --raw` 不注入隐藏标记或改变驱动决策；`--ext-diff` plumbing 开放不在范围。结构化输出不拼接人读文本且不新增字段；同卡测试验证 JSON、machine、porcelain 及配置外部驱动，任何一项失败均不得发布。`--quiet` 与 `--exit-code` 继续沿用 ADR-PL-09。若 #555 先交付同一隐藏标记，待双方核实语义后复用；当前交接未确认，写集仍须串行。
- **Alternatives considered:** 仅加 clap alias 会只输出 raw；wrapper 运行两次 diff 会重复 I/O 并产生分页/JSON 一致性问题；DFF-02 的顺序选择与 DFF-04 的组合渲染各有独立可恢复轴，分别保留自洽的版本合同。
- **Consequences:** 既有 `-p --raw` 在 DFF-04 交付前保持 raw-only（过渡合同），交付后修为组合输出；变更及驱动边界必须同卡说明。
- **Revisit when:** 共享渲染器正式建模多输出模式，而不是布尔优先级时。

## 全局工程约束

- **GC-DFF-01 单一引擎与输出事实源：** 必须继续经 `delegate_to_diff` / `command::diff::execute_safe`。raw+patch 只在共享渲染器中组合一次；不得复制 diff 计算、在 wrapper 运行两次引擎或直接用 `println!` 绕过 pager/JSON。
- **GC-DFF-02 公开与隐藏表面分离：** 隐藏 `plumbing_patch` 只供 plumbing 合成 argv，不得出现在公开 `diff --help`。新增 `diff-files` 选项必须同步 `DIFF_FILES_EXAMPLES`（需要时）及本计划列出的全部文档。
- **GC-DFF-03 只读与安全：** 不写 refs、HEAD、index、对象库或 SQLite；数据库角色全部 `N/A`。沿用既有 pathspec、存储读取与 `Result` 错误路径，不新增裸 `unwrap()` / `expect()` / `panic!()`。
- **GC-DFF-04 矩阵与账本：** `COMPATIBILITY.md:230` 只原地改写，文件总行数不变；其它行不属于写集。执行 `compat_ledger_schema` 与 `compat_matrix_alignment`。
- **GC-DFF-05 同卡文档与网站交付：** 每个实现卡逐文件交付 EN、zh-CN、开发文档、网站与矩阵。依模板 ER-06a 先核相邻后端 VCS、分支、远端和工作区；`.git`/`.libra` 同时存在或均不存在、非 `cf` 且无法安全切换、工作区有冲突时停止，不覆盖无关改动。
  - **原生 Libra `cf`：** 后端 `AGENTS.md:24-28` 明确要求先 `python3 scripts/sync-libra-command-docs.py --libra-root ../libra --check --only diff-files`（退出 1 是有漂移待审，2 是失败须停止），审核后在已验证的 `cf` 执行相同命令但用 `--write`，再以 `--check --only diff-files` 取得退出 0。随后按后端要求 `pnpm typecheck`、`pnpm build`、适用预览/E2E 和真实本机 Claude 评审；精确暂存网站路径、签名与 DCO 同提交验证、普通推送 `cf`。
  - **Git `cf`（干净且无无关超前提交）：** 现有后端 `AGENTS.md:27-28` 要求原生 Libra `--write`，而脚本 `require_cf` 明确拒绝 `.git`；因此当前没有已获授权的 Git 写入路径，受影响实现卡在**开工前 blocked**。后端维护者须先针对当前 Git 工作区授权以下等价方法或更新适用后端规则，并记录具名授权；没有该授权不得绕过 `require_cf` 或静默将草案当成交付。获授权后使用下列纯读取变换生成候选，逐字节更新唯一网站页，运行同一个脚本的 `--check --only diff-files`（必须退出 0），并执行本约束末尾的验证/推送/部署步骤。
  - **Git `cf`（干净但含无关超前提交）：** 同样先取得后端规则允许隔离克隆与等价写入的具名授权，否则开工前 blocked；按模板 ER-06a 刷新并核远端 SHA，以该 SHA 在新克隆 `cf` 生成候选，禁止触碰原工作区或推送其无关提交。相邻工作区有未提交修改时停止；不把隔离克隆推广为其它情况的绕行。

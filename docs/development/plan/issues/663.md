# Issue #663：`LIBRA_TRACE` 追踪设施与 `GIT_TRACE` 兼容别名（2026-11-11）

## 文档职责

### 适用范围

进程级追踪设施：`LIBRA_TRACE` 取值语义（`0/false`、`1/true`、`2`、绝对路径、fd）、追踪行格式（`trace: built-in: ...`）、输出目标（stderr / 追加文件 / fd）、启动接线（`src/main.rs` 的 `init_tracing` 与命令分派）；`GIT_TRACE` 兼容别名；以及 TC-0038～TC-0042 所依赖的上游 `t3701#73` 取证。

### 非目标

`GIT_TRACE_PERFORMANCE`/`_CURL`/`_PACKET`/`_SHALLOW` 族（`DEFER-I663-01`）。`LIBRA_LOG`/`LIBRA_LOG_FILE` 既有语义。跨进程 trace 继承（`DEFER-I663-05`，需独立设计后再议）。追踪写入 `--json` stdout（禁止）。`exec`/`run_command` 来源行（`DEFER-I663-02`：仓库无集中 spawn helper，且上游 `#73` 判据只要求文件存在且无 `not-changed` 行）。记录具体 argv 值（`DEFER-I663-03`：无可靠脱敏层）。Windows fd 语义（`DEFER-I663-04`）。

### 成功定义

- `LIBRA_TRACE` 支持五种取值形态；`1/2` 写 stderr，绝对路径创建并追加，`cfg(unix)` 下 fd 写入该 fd；未设置或 `0/false` 无输出无文件。
- 追踪行以 `trace: built-in: ` 开头（level 2 的时间戳紧随该前缀之后），可被上游 `^trace: (built-in|exec|run_command):` 匹配，且不产生 `not-changed` 片段。
- `GIT_TRACE` 在 `LIBRA_TRACE` 未设置时映射到同一设施，使上游 `#73` 的 trace 文件被创建，TC-0038～TC-0042 不再因该行中止。
- 文档、兼容矩阵与回归同卡。

## 已决议设计决策

### ADR-TR-01: `LIBRA_TRACE` 优先于 `GIT_TRACE`

- **Status:** Accepted
- **Decision:** 解析顺序 `LIBRA_TRACE` → `GIT_TRACE`；同时设置时以 `LIBRA_TRACE` 为准，并在启用时写一行 `trace: built-in: precedence: LIBRA_TRACE overrides GIT_TRACE`。
- **Alternatives considered:** 后者覆盖（不可预测）；双 sink（语义混乱）。
- **Consequences:** 上游脚本行为如 Git；Libra 用户可强制覆盖。
- **Revisit when:** 需要双目标记录。

### ADR-TR-02: 追踪行只记命令名与动作

- **Status:** Accepted
- **Context:** `redact.rs` 只处理 URL userinfo（`src/utils/redact.rs:26`），不能脱敏任意 argv。
- **Decision:** 行固定为 `trace: built-in: [<ISO8601> ]<command>[ <subcommand>] <action>`；level 2 的时间戳紧随 `trace: built-in: ` 之后，保证上游 `^trace:` 正则仍匹配；绝不输出参数值；URL 出现时经 `redact_url_credentials`。
- **Alternatives considered:** 记录完整 argv（泄露凭据，ER-11 违规）。
- **Consequences:** 依赖参数值的上游 grep 无法满足，登记 `DEFER-I663-03`。
- **Revisit when:** 引入可证明的 argv 脱敏层。

### ADR-TR-03: 未启用零开销，写失败不致命

- **Status:** Accepted
- **Decision:** 未设置时不初始化、不打开文件；打开失败 stderr 警告一次并禁用，退出码不变（与 `src/main.rs:765` best-effort 口径一致）。
- **Alternatives considered:** 打开失败即报错退出。
- **Consequences:** 不适用于 fail-closed 审计场景。
- **Revisit when:** 需要强制审计模式。

### ADR-TR-04: fd 目标仅 Unix，且不接管所有权

- **Status:** Accepted
- **Context:** 写任意 fd 涉及平台 API 与句柄所有权。
- **Decision:** `cfg(unix)` 下用 `std::os::fd::BorrowedFd` + `libc::write`（或 `UnsafeFile::from_raw_fd` 包在 `ManuallyDrop` 中）写入；不 close、不 dup 调用方 fd；非 Unix 平台 fd 形态解析成功但记一次「unsupported on this platform」并禁用；fd 只接受 `0..=1023` 范围，超出按配置错误拒绝。
- **Alternatives considered:** `File::from_raw_fd` 直接接管（会关闭调用方句柄，破坏调用者）。
- **Consequences:** Windows 上 fd 形态不可用，登记 `DEFER-I663-04`。
- **Revisit when:** 需要跨平台 fd 支持。

用户既有指令：只在 `main`、不建分支、不开 PR。ER-04 C 组的分支+PR 由下列等价保护替代：① 分支 `main` 且父提交等于推送前 `origin/main`；② 单父提交，`libra diff --name-only HEAD^ HEAD` 全落在本卡写集 + 本计划文件 + `plan-status.md`；③ `libra cat-file -p HEAD` 含 `gpgsig`，`Signed-off-by` 在该提交本身；④ 版本面差异仅版本行。推送后 D 组取同 SHA 的 `base.yml`、`codeql.yml`、`release.yml`；上游前进时 `libra pull --ff-only` 后重跑受影响门。

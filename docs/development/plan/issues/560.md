## 文档职责

本计划承接 #560 的剩余差额：在既有 HKT SSH 客户端上修复密钥、指纹与信任写入的绑定及确认资格，验证真正的终端 clone，修正安全回归的观察位置，并对历史交付记录作有限对账。本次文件权限与未来实施权限不同：本次用户只授权新建此计划。下述产品、文档、版本和发布写集是供将来评审的具体方案，须在取得相应授权并完成开工门后才可执行；Issue 的对外评论和关闭另需用户明确批准。不得据本计划声称 #560 已解决。

### 适用范围

覆盖既有 SSH 状态机的密钥验证与指纹授权、有效 strict 策略、配置读取错误与 human TTY 资格，clone/fetch/pull/push/ls-remote/Mega2 traces 的共享调用面，隔离测试、受影响文档与网站、兼容记录及各卡发布收口。HP-17 已把交互范围移交给 #582 的 HKT-00/01/02；本计划只安排其后续差额修复。开工前须由协调者与原所有者确认承接关系及唯一活动写者。

### 非目标

不另建 SSH transport、信任数据库或 prompt，不与 HKT/HP 平行实现；#577 的 publickey 认证失败仍由其原计划负责。#560 提出的可选服务商公布指纹自动比对不在本计划实现，具体边界见 `DEFER-SHK-01`；不得把此功能声称为已交付。

### 成功定义

合格的人类终端在未知主机路径可看到本地构造、与已验证密钥一一对应的算法和 SHA-256 指纹；Libra 自有确认路径仅将用户明确授权的展示密钥写入 OpenSSH 使用的 known-hosts 并重试原命令。`yes` 授权全部已展示的有效密钥，输入单个指纹只授权其唯一匹配密钥，二者的区别须在提示中明确。该路径在拒绝、EOF、changed key 和非交互场景保持关闭式失败；显式 OpenSSH `accept-new`/`no` 的自身行为以 GC-SHK-03 为准。各卡及最终收口须取得实际测试、文档、评审和适用 C/D 证据，并同步协调状态，方可形成有限范围的完成结论。

## 已决议设计决策

### ADR-SHK-01：复用既有状态机，分别修正策略与终端边界

- **Status:** Accepted（计划设计，尚未实施）。
- **Context:** 接受后写入并重试的控制流存在；`ssh -G` 未提供有效策略给确认分支，非 TTY 覆盖仍可启用确认。
- **Decision:** 在原 `SshClient` 上按真实 transport 的 SSH binary、user/host、port 和影响配置解析的选项解析 `ssh -G`，仅 Libra policy 与 OpenSSH effective policy 均为 `ask` 时允许 unknown-key 确认；读取失败、缺失、未知或其他值不触发 Libra keyscan、prompt 或 trust 写入，并保留原 untrusted 错误。本机 `ssh -G` 将配置输入 `yes/no` 输出为 `true/false`；对这些输出及字面 `yes/no` 均按非 `ask` 处理，不将未知字符串当 `ask`。同时解析 `proxycommand` 与 `proxyjump`：若任一有效（存在且非 `none`），因 `ssh-keyscan` 无法保证走同一代理路由，必须直接 fail-closed（不启动 keyscan、不提示、不写 trust、不重试，保留原 untrusted 错误）。同时区分“未配置 `userknownhostsfile`”与显式禁用目的地（`UserKnownHostsFile none`、`/dev/null`）：显式 `none` 或 `/dev/null` 必须写前直接 fail-closed（不启动 keyscan、不提示、不回退写入 `confirmation.known_hosts_path`、不重试，保留原 untrusted 错误）；普通目标文件的权限/I/O 写入失败不作写前探测，而是在同意后追加失败时保留错误且不重试、不声明成功。`run_ssh_g` 改用有界流式收集（超出 stdout/stderr 字节上限时终止子进程并按失败处理）。正常 transport 始终保留 `BatchMode=yes`。另移除生产非 TTY 强制覆盖，改用真实 PTY 测试。
- **Alternatives considered:** 重启 HP-17/另建 SSH transport（重复所有权）；只修测试或只把问题移出范围（不能修复行为）；无条件将所有失败降为 `ask`（不安全）。
- **Consequences:** 旧 SSH/test double 不支持有效 `ssh -G` 时，未知主机保持原失败而不提示；不更改已知主机的普通传输。明确 `accept-new`/`no` 的 OpenSSH 自身行为仍由用户配置控制；本卡只限制 Libra 自有确认阶段。执行时更新 fake `ssh -G` fixture，不能把 failure fallback 当作成功。
- **Revisit when:** 同一服务调用的有效选项无法一致重现，或所有权不能协调；先停止并修订计划。

### ADR-SHK-02：配置不确定时在网络前失败

- **Status:** Accepted（计划设计，尚未实施）。
- **Context:** 当前 strict cascade 的读取错误被吞掉，且非法策略值校验仍返回普通字符串；调用链将部分构造失败映射为远端 URL 错误。
- **Decision:** 将 strict 配置**读取失败**与**非法策略值**（env/local/global/system）统一纳入类型化配置错误，经共享构造链明确传播，给出配置键 `ssh.strictHostKeyChecking`、可识别的 scope/来源和可操作修复提示；不得启动 SSH/keyscan。保留已明确设置的非空环境变量优先级；没有配置值与读取失败/非法值必须区分。各调用入口（`clone`、`fetch`、`pull`、`push`、`ls-remote`、`mega2_traces`）保留配置错误分类，避免误报 URL 格式错误。
- **Consequences:** 原先在损坏配置下可能继续的命令会失败；同卡覆盖 clone/fetch 等共享入口及机器输出，不新建稳定错误码，除非按 ER-03 先重审并同步错误码契约。
- **Revisit when:** 无法确定安全的 scope 或现有错误码不适用；停止并更新写集与验收。

### ADR-SHK-04：验证后绑定候选，再按回答限定信任集合

- **Status:** Accepted（计划设计，尚未实施）。
- **Context:** keyscan 输出及其算法标签是不可信数据。现有按成功计算的指纹另建向量，再与未过滤的 entries 配对；任意指纹被接受后仍写入全部 entries。指纹 Base64 区分大小写。
- **Decision:** 仅允许 `ssh-ed25519`、`ssh-rsa`、`ecdsa-sha2-nistp256`、`ecdsa-sha2-nistp384`、`ecdsa-sha2-nistp521` 公钥类型；完整解码和解析 SSH wire blob，验证其中类型、曲线及字段结构与外部类型一致，拒绝截断、额外数据、非法编码、不支持的算法或伪造元数据。候选的解析公钥、规范算法、原始 blob 和计算出的 SHA-256 指纹构成不可拆分记录；去重后，提示与待写行均由同一经验证记录生成，不使用原始扫描算法/banner 填充提示。复用现有扫描的 idle timeout 与子进程清理，不额外增加网络往返；不可信目标/alias 不得引入终端控制序列或 known-hosts 行/模式注入，无法安全表示为 OpenSSH 同一身份时失败，不静默改写身份。没有可用候选时不提示、不写信任。
- **授权语义:** 提示明确列出每个候选，并说明 `yes` 接受全部已展示密钥，用户应通过可信渠道核对每个指纹；只有精确输入其中一个指纹才仅接受该唯一密钥。`SHA256:` 前缀可按现有习惯忽略大小写或省略，但 Base64 主体逐字节区分大小写；空输入/`no` 为拒绝，其它无效输入遵守现有有界重试。完全相同的密钥去重；若不同候选意外拥有相同指纹，则单指纹输入因歧义失败，不作选择。成功写入的行只能来自本次被授权的记录，既有 known-hosts 内容须保留。
- **安全切片:** SHK-05 先交付受验证记录、明确的 `yes` 全集语义，并暂时不再接受任何指纹输入，提示及文档同步说明此限制；这样一个指纹不会在中间提交误授权其它键。SHK-06 紧随其后恢复单指纹输入和精确选择。两张子卡各自含自身测试、文档与本地提交，均经 `REL-SHK-01` 统一对外发布；在 SHK-06 交付前不得声称完整 `yes/no/[fingerprint]` 已实现。
- **失败边界:** 拒绝、EOF、非法数据和匹配失败在开始写入前不得改 trust；I/O 写入失败不得重试连接或声称写入成功，也不得未经验证宣称文件毫无变化。现有追加实现可能发生部分写入，本计划不声称已验证写入事务原子性；出现该故障时提示检查目标文件且不删除或自动覆盖用户数据。
- **Alternatives:** 继续把一次 fingerprint 输入当成全部条目授权，或只过滤指纹而保留原 entries 写入（均不安全）；无条件信任 keyscan（不提供身份真实性证明）。本计划不自动比对服务商来源，仍须用户经可信渠道核对。

- **GC-SHK-05 对外写入：** 评论、关闭和重开 #560 均需用户明确批准；只读查询不构成批准。不得把批准前拟稿当成发送记录。
- **GC-SHK-06 状态与并发：** 本次只写本文件；执行阶段协调者在每次状态推进的同一变更同步 `plan-status.md`。除非另有授权，任何产品/网站/发布写入不得在本次起草中执行。
- **GC-SHK-07 时间与子进程：** 复用已有 idle timeout 和清理边界；`ssh -G` 与 `ssh-keyscan` 均须采用有界流式收集（替代无界 `cmd.output()`），单流（stdout / stderr 各自）上限固定为 `SSH_STDERR_LIMIT`（`64 KiB` / `65536` 字节），超限即终止并显式回收（`kill` + `wait` reap）子进程，按 fail-closed 保留原错误；不引入无限等待、无限输出收集或已知主机额外网络往返。失败路径不得重试原服务或扫描 key。
- **GC-SHK-08 Libra-native：** 本仓库只用 `libra` 版本控制，精确暂存；不混入协调者和其它计划的并发改动。
- **GC-SHK-09 nextest 与临时文件：** 默认 `.config/nextest.toml` 会生成 JUnit。每次 focused/全量 nextest 均使用下方 `shk_nextest`：先物理规范化并确认 scratch 在仓外，再由 `mktemp -d` 建立新的私有目录，独占创建 no-JUnit 配置；绝不覆盖用户提供的文件或清理既有目录。每轮私有配置独立，可重复运行；正常 Cargo 编译缓存可复用，不要求重建 target。若 nextest 配置结构变化、检查出新增/改写 JUnit 或扫描出错则本门失败。临时配置和构建缓存不是验收证据，不入库。
- **GC-SHK-10 测试树闭合：** 有测试会读取 `plan-status.md`，因此卡片/计划状态、协调者对应行及已产生的真实证据须先写入同一候选树，再执行该树的最终门。只在隔离、无无关改动的工作区测试；精确暂存后取 `libra write-tree`，测试前后均验证工作树与暂存一致，提交后验证 `HEAD^{tree}` 等于测试树。测试后若追加证据、改状态、rebase 或合并改变树，须重新固定树并重跑受影响门；不得把旧树结果算作新树验证。末端运行只能在完成后由终端输出/远端 run 向协调者报告，不得预填；末端 D 收据的例行状态补记依本节后文 v2.14 协议处理。
- **GC-SHK-11 文档通用事实：** 所有受影响 SSH 文档的同卡同步均须准确说明 transport 始终使用 `BatchMode=yes`，host-key 确认是独立的 Libra prompt；按各卡实际发布状态说明策略与 TTY 边界，不能提前宣称后续卡已交付。

### nextest 的安全调用

以下函数在仓库根目录的 Bash 中定义。`LIBRA_TEST_SCRATCH_DIR` 必须是执行者提供的已存在、绝对路径、可写且位于持久介质的仓外目录；若规范化后落在仓内则失败。函数每次只创建并清理本轮 `mktemp` 私有目录，编译缓存继续由 Cargo 原有配置决定。函数在运行前后比较实际 target 下已有 `junit.xml` 的相对路径、内容与修改时间；已有文件不删除、不覆盖，扫描失败或发生变化即停止。

```bash
shk_nextest() (
  set -euo pipefail
  : "${LIBRA_TEST_SCRATCH_DIR:?set an existing external scratch directory}"
  case "$LIBRA_TEST_SCRATCH_DIR" in /*) ;; *) printf '%s\n' 'scratch must be absolute' >&2; exit 1 ;; esac
  shk_repo_path="$(libra rev-parse --show-toplevel)" || exit 1
  shk_repo="$(cd -P -- "$shk_repo_path" && pwd -P)" || exit 1
  shk_scratch="$(cd -P -- "$LIBRA_TEST_SCRATCH_DIR" && pwd -P)" || exit 1
  case "$shk_scratch" in "$shk_repo"|"$shk_repo"/*) printf '%s\n' 'scratch resolves inside repository' >&2; exit 1 ;; esac
  umask 077
  shk_temp="$(mktemp -d "$shk_scratch/shk560.XXXXXXXXXX")" || exit 1
  shk_real="$(cd -P -- "$shk_temp" && pwd -P)" || exit 1
  case "$shk_real" in "$shk_repo"|"$shk_repo"/*) printf '%s\n' 'temporary directory resolves inside repository' >&2; exit 1 ;; esac
  case "$shk_real" in "$shk_scratch"/shk560.*) ;; *) printf '%s\n' 'unexpected temporary directory' >&2; exit 1 ;; esac
  readonly shk_temp
  trap 'rm -rf -- "$shk_temp"' EXIT
  python3 -I - "$shk_repo/.config/nextest.toml" "$shk_temp/nextest.toml" <<'PY' || exit 1
import copy, pathlib, sys, tomllib
source = pathlib.Path(sys.argv[1]).read_text(encoding="utf-8")
block = '[profile.default.junit]\npath = "junit.xml"\n'
if source.count(block) != 1:
    sys.exit("nextest JUnit configuration changed; revise the plan")
clean = source.replace(block, '', 1)
expected = copy.deepcopy(tomllib.loads(source))
expected['profile']['default'].pop('junit')
parsed = tomllib.loads(clean)
if parsed != expected or any('junit' in p for p in parsed.get('profile', {}).values()):
    sys.exit("unexpected nextest configuration change")
with open(sys.argv[2], 'x', encoding='utf-8') as output:
    output.write(clean)
PY
  shk_target="$(cargo metadata --no-deps --format-version 1 | python3 -I -c 'import json,sys; print(json.load(sys.stdin)["target_directory"])')" || exit 1
  shk_junit_snapshot() {
    python3 -I - "$1" <<'PY'
import hashlib, json, os, stat, sys
root = sys.argv[1]
items = []
def fail(error):
    raise error
try:
    root_info = os.stat(root)
except FileNotFoundError:
    root_info = None
if root_info is not None:
    if not stat.S_ISDIR(root_info.st_mode):
        raise RuntimeError('target directory is not a directory')
    for parent, dirs, names in os.walk(root, followlinks=False, onerror=fail):
        if parent == root and 'nextest' in dirs and os.path.islink(os.path.join(parent, 'nextest')):
            raise RuntimeError('symlinked nextest output directory cannot be checked safely')
        for name in names:
            if name.lower() != 'junit.xml':
                continue
            path = os.path.join(parent, name)
            info = os.lstat(path)
            if stat.S_ISLNK(info.st_mode):
                digest = 'link:' + os.readlink(path)
            elif stat.S_ISREG(info.st_mode):
                hasher = hashlib.sha256()
                with open(path, 'rb') as item:
                    for chunk in iter(lambda: item.read(1024 * 1024), b''):
                        hasher.update(chunk)
                digest = hasher.hexdigest()
            else:
                raise RuntimeError('unexpected JUnit file type')
            items.append((os.path.relpath(path, root), info.st_mtime_ns, digest))
print(json.dumps(sorted(items), ensure_ascii=True))
PY
  }
  shk_before="$(shk_junit_snapshot "$shk_target")" || exit 1
  shk_rc=0
  cargo nextest run --config-file "$shk_temp/nextest.toml" --user-config-file none --profile default --no-tests=fail "$@" || shk_rc=$?
  shk_after="$(shk_junit_snapshot "$shk_target")" || exit 1
  if [ "$shk_before" != "$shk_after" ]; then
    printf '%s\n' 'JUnit output changed; preserve it and investigate' >&2
    exit 1
  fi
  exit "$shk_rc"
)
```

将本计划的 `shk_nextest` 命令在同一 shell 中执行；每次运行重新生成私有配置。它只删除自身 `mktemp` 创建的目录；中断留下的目录应由执行者核实归属后处理，不能清理既有 target 或 scratch 根目录。禁止用目标目录非空作为失败判据。全量的实际执行形态为 `source .env.test && source .env.live-test && shk_nextest --all --no-fail-fast --retries 2`，函数内调用的仍是 `cargo nextest run --all --no-fail-fast --retries 2`，仅附 no-JUnit 和零测试守卫。

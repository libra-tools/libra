# Issue #489：`add --chmod` 拒绝非普通文件索引条目修复计划（2026-09-14）

> 来源：[libra-tools/libra#489](https://github.com/libra-tools/libra/issues/489)（libra-testcases TC-0008，对应 `t/t3700-add.sh:508-513`）。
> 状态：设计计划；任务卡 `pending`，尚未进行 Codex review（见「Codex review log」）。

## 文档职责

本文解决 issue #489：`libra add --chmod=+x --dry-run <symlink>` 以 exit 0 静默成功，而 Git 报 `error: cannot chmod +x '<path>'` 并以非零退出。

核对时发现这一问题不限于 `--dry-run`：Libra 的 `apply_chmod` 在**任何模式**下都会跳过索引中的符号链接（`120000`）与 gitlink（`160000`）条目，不报错也不改变退出码。真实暂存时（例如 `add --chmod=+x reg foo4`、对含符号链接的目录执行 `--chmod`、工作树里被替换成符号链接的已跟踪文件），Git 同样会报错并以非零退出，但仍更新其它合法路径（`t3700-add.sh:490-498`）。本计划用一张卡统一修复：chmod 作用到非普通文件索引条目时必须拒绝该路径、报告路径与 `+x`/`-x`、保持其索引条目不变，并以常规非零状态结束。

本文只规划任务，不宣称实现完成。落地时必须先刷新源码锚点，再按任务卡验收。

### 适用范围

- `libra add --chmod=(+|-)x` 在 `--dry-run` 与真实暂存两种模式下，对非普通文件索引条目（符号链接、gitlink）的拒绝语义、人读输出、JSON 输出与退出状态。
- 与 `--ignore-errors`、`--quiet`、`--exit-code-on-warning` 的组合。
- 同步：`docs/commands/add.md` EN + zh-CN、`docs/development/commands/add.md`、`COMPATIBILITY.md` 的 `add` 行、`../libra-backend` 网站文档。

### 非目标

- `update-index --chmod`（Libra 尚无该 flag；由 [`issues/479.md`](479.md) UI-03 承接，并复用本卡交付的拒绝语义）。
- 退出码与 Git 的 255 逐值对齐（ADR-CH-02）。
- 已跟踪 gitlink 在工作树缺失时 `add <gitlink>` 不暂存删除的差异（核对时观察到，与 chmod 无关，DEFER-01）。
- `add --chmod=+x --dry-run nonexistent` 的退出码（Libra 129 与 Git 128 均为非零，属既有文档化差异）。

### 成功定义

- 移植 TC-0008（`t3700-add.sh:508-513` 等价）：`add --chmod=+x --dry-run foo4`（`foo4` 为 `120000` 条目）以常规非零状态结束，stderr 同时指出 `foo4` 与 `+x`，索引模式与对象 id 不变。
- `t3700-add.sh:490-498`（非普通文件报错但更新其它路径）与 `:500-506`（`--dry-run` 不改变索引）的等价用例通过。
- 本计划判据矩阵每一行的退出状态（零/非零）、索引结果与 git 2.54 实跑一致。
- 本卡完成 C 组发布并取得 D 组证据，然后全量收口门全绿。满足这些之后，本计划才可标记完成。

## 已决议设计决策

实现时若需偏离本节，必须先修改计划并说明原因，不得在代码中静默改语义。

### ADR-CH-01: 拒绝判定

- **Status:** Accepted
- **Context:** GAP-01/02；git `builtin/add.c:44-72`、`:681-682`，`read-cache.c:920-942`。
- **Decision:**
  1. `apply_chmod` 对每个 pathspec 命中的索引条目（stage 0）判定：
     - 条目模式不是普通文件（`mode & 0o170000 != 0o100000`，含 `120000` 与 `160000`）→ 记为拒绝，条目保持不变，继续处理其余条目；
     - 普通文件 → 沿用现有逻辑（已是目标模式则无操作；dry-run 下工作树缺失或为符号链接时跳过且不报错）。
  2. 真实模式下，判定发生在本次暂存完成之后（沿用现有调用顺序 `add.rs:811-821`），因此新暂存的符号链接或工作树类型变化的条目以暂存后的模式判定。
  3. dry-run 下判定使用当前索引（沿用 `add.rs:695-702`），不把未入索引的新路径计入。
  4. 被拒绝路径的记录格式为 `(path, '+'|'-')`。
- **Alternatives considered:** 按工作树文件类型判定——与 Git 不一致（实测 `swap` 的 dry-run 在 Git 中为 exit 0），拒绝。遇到第一个非普通条目即中止——Git 会继续更新其它路径（`t3700:490-498`），拒绝。
- **Consequences:** `apply_chmod` 的签名增加拒绝列表输出，供 issues/479 UI-03 复用。
- **Revisit when:** Libra 支持 index v3 扩展条目类型。

### ADR-CH-02: 退出状态与人读输出

- **Status:** Accepted
- **Context:** issue 要求常规非零退出、指出路径与 `+x`，不要求数值或措辞与 Git 相同。issues/484 ADR-IA-02 已为 `add` 选定「完整渲染后 `silent_exit(1)`」模型。
- **Decision:**
  1. 存在任何拒绝时，`execute_safe` 在保存 index（真实模式）、完成常规渲染与既有警告之后，向 stderr 逐行输出 `error: cannot chmod +x '<path>'`（或 `-x`，路径按既有输出的路径表示），然后返回 `CliError::silent_exit(1)`。
  2. 退出码 1 优先于 `--exit-code-on-warning` 的 9。
  3. `--quiet` 不抑制 stderr 错误行；`--ignore-errors` 不抑制拒绝。
  4. 退出决策不放进 `run_add`，内部调用方行为不变。
  5. 与 issues/484 IA-01 共用同一个「渲染后非零」决策 helper：先落地者引入，后落地者复用（DEP-CH-04）。
- **Alternatives considered:** 返回带稳定错误码的 `CliError`（128/129）——会丢失已渲染的暂存结果与 JSON 数据，且与 issues/484 的模型不一致，拒绝。退出码 255——Libra 退出码表没有 255，拒绝。
- **Consequences:** 与 Git 的 255 差异在文档与 `COMPATIBILITY.md` 登记。
- **Revisit when:** Libra 统一「部分成功」退出码。

### ADR-CH-03: JSON 输出

- **Status:** Accepted
- **Context:** GAP-03。现有 `failed` 字段表示 `--ignore-errors` 下失败的路径，语义为警告级（exit 0）。
- **Decision:**
  - `AddOutput` 新增可选字段 `chmod_rejected: [{ "path": string, "flip": "+x" | "-x" }]`（为空时不序列化），不复用 `failed`。
  - `--json` / `--machine` 下 stdout 为既有 data envelope（包含该字段），退出码 1，stderr 不输出人读错误行。
- **Alternatives considered:** 复用 `failed`——混淆 `--ignore-errors` 的警告语义，拒绝。
- **Consequences:** 字段只增不改，既有 JSON 消费者不受影响。
- **Revisit when:** DEFER-01 或其它部分成功语义需要统一字段。

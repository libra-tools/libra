# Issue #817：`libra config <key> <value>` 必须接受以 `-` 开头的值（2026-11-12）

> 模板 v2.16。[Issue #817](https://github.com/libra-tools/libra/issues/817) OPEN，7 条评论（直接覆盖 TC-1106/1108/1110/1116/1201/1375/1377/1795/2885/2891–2899 共 18 个 TC；另有 TC-1805/1809 来自本仓 testcase 仓扩展，合计 20 个 TC）。仅规划，未授权执行；`I817-01` 为 `pending` / Acceptance 空。Git 对照 pin `6de20f6092dcf9bdb1c8efe03db4b70c82b423dd`。基线 `Cargo.toml` `0.30.197`（`Cargo.toml:3`）；实测 system `libra 0.30.171` 与 system `git`。测试用例仓 `/mnt/gitmono/libra-testcases` 本计划不修改。

## 文档职责

### 适用范围

`libra config <key> <value>`（包括 Git-compat 顶层位置参数入口与 `libra config set <key> <value>` 子命令入口）的**值位置**解析：当 key 已经作为第一个位置参数给出后，紧随其后的 argv 必须按字面值收下，即使它以 `-` 开头（如 `-trailing-space`、`-space-before-tab`、`-indent-with-non-tab`、`-tab-in-indent`、`-blank-at-eol`、`--no-tags`、`-n`、`--stat`、`-refname`、`-rc`、`--no-ff`、`--squash`、`---weird`、`--log=3` 等）。同步覆盖 `--add`、`--replace-all`、`--local/--global/--system` 等既有 flag 与值位置的共存顺序，以及 `--` 逃逸的既有行为保持可用。

### 非目标

不改变 `config --get/--get-all/--list/--get-regexp/--unset/--unset-all/--remove-section/--rename-section/--import` 等**选项**在 key 之前的识别规则（选项在 key 之前仍按 clap 正常识别）。不实现 `diff --check` 对 `core.whitespace` 的内部消费与空白规则检测（`DEFER-I817-06`）。不改变 vault 加密/明文存储策略与敏感键交互输入。不改变 `--type=bool|int|path` 的规范化语义。不实现 `issues/978.md` 的 `mergeOptions` 读取套用（`DEFER-I817-02`）。不实现 `issues/984.md` 的 `--no-squash` 参数面（`DEFER-I817-03`）。不实现 `issues/842.md` 的 `--color-moved-ws` diff 选项（`DEFER-I817-04`）。不实现 `issues/533.md` 的 `tag -l --no-sort` / `version:refname` 排序规则（`DEFER-I817-05`）。不改变 `--` 后参数的既有语义细节（见 `DEFER-I817-01`）。不修改测试用例仓。

### 成功定义

- `libra config branch.main.mergeOptions --no-ff` 退出 0，且 `libra config --get branch.main.mergeOptions` 返回 `--no-ff`。
- `core.whitespace` 支持写入 `-trailing-space`、`-space-before-tab`、`-indent-with-non-tab`、`-tab-in-indent`、`-blank-at-eol` 退出 0 且回读一致。
- `remote.<name>.tagopt` 支持写入 `--no-tags` 退出 0 且回读一致。
- `branch.<name>.mergeoptions` 支持写入 `-n` 与 `--stat` 退出 0 且回读一致。
- `tag.sort` 与 `versionsort.prereleaseSuffix` 支持写入 `-refname`、`-rc` 等负向排序键值。
- 值位置出现 `---weird` 与 `--log=3` 同样按字面存入。
- 子命令形式 `libra config set <key> <value>` 同步接纳连字符值。
- 既有选项面不受影响：`libra config --get <key>`、`libra config --unset <key>`、`libra config --list` 行为逐字不变。
- `libra config <key> -- <value>` 的既有逃逸行为保持可用。
- 未知**选项**在 key 之前仍按既有规则报错（不因本次放宽而在无 key 时静默吞掉拼写错误的 flag）。

## 已决议设计决策

### ADR-I817-01：`valuepattern` 与 `Set.value` 允许连字符值，沿用既有 `allow_hyphen_values` 范式

- **Status:** Accepted
- **Context:** `src/command/config.rs:619-620` 的 `ConfigArgs.valuepattern` 与 `:641-645` 的 `Set { value }` 未允许连字符，故 `libra config x.y --no-ff` 被 clap 判为未知选项（实测 `exit_code:129`）。仓库内已有同型范式：`src/cli.rs:933-934` 用 `allow_hyphen_values = true` 接纳连字符值。
- **Decision:** 顶层 `ConfigArgs` 以 `#[clap(trailing_var_arg = true, num_args = 0..)] operands: Vec<String>` 位置参数取代 `key`/`valuepattern` 两段式解析，同时显式处理分隔符：若 `operands` 中出现字面 `--`，只移除首个分隔符并把其后的 token 继续按值收集（因此 `config x.y -- --no-ff` 得到 2 个操作数并成功）。解析后立即校验 `operands.len() <= 2`（对所有模式，含 `--get-regexp` 的 name + value-pattern），超出则以 `LBR-CLI-002` 拒绝（与改动前 `config x.y a b` 与 `config --get-regexp n p extra` 的拒绝行为一致），并在 `ConfigCommand::Set.value` 上保留 `#[clap(allow_hyphen_values = true)]`。`trailing_var_arg` 使首个非选项 token（key）之后的全部 argv 按字面值收下，精确复现 Git `parse_options` 的 `PARSE_OPT_STOP_AT_NON_OPTION` 语义：key 之后的 `--get`、`--list`、`--unset`、`--no-ff` 等一律作为值，key 之前的同名 token 仍是选项。不在手写解析器中预切 argv（保持 GC-02）。
- **Alternatives considered:** 只加 `allow_hyphen_values`（clap 仍优先把 key 之后的已定义 flag 识别为选项，无法复现 Git 语义，R6 已否证）；依赖用户写 `--`（Git 不需要，上游 `test_config` 不写）；手写预解析（违背 GC-02）。
- **Consequences:** 连字符值与 Git 一致；选项识别仍由 clap 保障。
- **Revisit when:** clap 改变 `allow_hyphen_values` 与位置参数交互语义。

### ADR-I817-02：只放宽「已给出 key 之后」的值位置，不放宽无 key 情况

- **Status:** Accepted
- **Context:** 若对整条命令全局开启 `allow_hyphen_values`，`libra config --gett x.y`（拼写错误）会被当作键而非报错，掩盖真实错误。
- **Decision:** 只让 key 之后的位置放宽（`trailing_var_arg` 的 `operands` 与 `Set.value`）；`ConfigArgs` 层面的 Git-compat flag（`--get`/`--list`/…）在 key 之前保持严格识别，无 key 时的未知 `-` 前缀 token 仍以 `LBR-CLI-002` 拒绝。
- **Alternatives considered:** 全局放宽（会破坏拼写错误检测）。
- **Consequences:** 错误检测保留；值位置与 Git 对齐。
- **Revisit when:** N/A。

### ADR-I817-03：`--` 逃逸保持可用，但不再是被迫路径

- **Status:** Accepted
- **Context:** 现有实现通过 hint 引导用户写 `--`（实测 `libra config x.y -- --no-ff` 成功）。
- **Decision:** 保留 `--` 逃逸行为（不回归既有脚本），并在文档中说明 `--` 可省略：key 之后的全部 token（含与顶层选项同名的 `--get`/`--list`）均已按字面值收下。`--` 与 value 的精确交互边界登记为 `DEFER-I817-01`。
- **Alternatives considered:** 移除 `--` 支持（破坏既有脚本）。
- **Consequences:** 向后兼容。
- **Revisit when:** 明确 `--` 与 value 的 Git 精确语义后另案处理。

wait_run() {
  local wf="$1" i id st
  for i in $(seq 1 40); do
    id=$(gh run list --repo libra-tools/libra --workflow "$wf" --branch main --event push --limit 10 --json databaseId,headSha --jq '.[]|select(.headSha=="'"$HEAD_SHA"'")|.databaseId' | head -n1)
    test -n "$id" || { sleep 30; continue; }
    for _ in $(seq 1 480); do
      st=$(gh run view "$id" --repo libra-tools/libra --json status,conclusion --jq '.status+" "+.conclusion')
      case "$st" in "completed success") echo "$id"; return 0;; "completed "*) echo "$wf $id failed: $st" >&2; return 1;; esac
      sleep 30
    done
    return 1
  done
  return 1
}
BASE_ID="$(wait_run base.yml)"
for j in compat-rustfmt compat-clippy compat-owner-liveness-macos compat-scoped-input-windows compat-redundancy compat-offline-core compat-network-remotes opencode-export-sandbox-linux; do
  gh run view "$BASE_ID" --repo libra-tools/libra --json jobs --jq "[.jobs[]|select(.name|startswith(\"$j\"))|select(.conclusion==\"success\")]|length" | awk '{exit ($1>=1)?0:1}' || { echo "base job missing/failed: $j" >&2; exit 1; }
done
CQ_ID="$(wait_run codeql.yml)"
test "$(gh api "repos/libra-tools/libra/contents/.github/workflows/codeql.yml?ref=$HEAD_SHA" --jq .content | base64 -d | grep -c '^  analyze:')" = 1
test "$(gh run view "$CQ_ID" --repo libra-tools/libra --json jobs --jq '[.jobs[]|select(.name|startswith("security-codeql"))|select(.conclusion=="success")]|length')" -ge 2
gh release create "v$VERSION" --repo libra-tools/libra --target "$HEAD_SHA" --title "v$VERSION" --generate-notes
for i in $(seq 1 40); do
  REL_ID=$(gh run list --repo libra-tools/libra --workflow release.yml --limit 20 --json databaseId,headBranch --jq '.[]|select(.headBranch=="v'"$VERSION"'")|.databaseId' | head -n1)
  test -n "$REL_ID" && break
  sleep 30
done
test -n "$REL_ID"
REL_OK=
for _ in $(seq 1 480); do
  st=$(gh run view "$REL_ID" --repo libra-tools/libra --json status,conclusion --jq '.status+" "+.conclusion')
  case "$st" in "completed success") REL_OK=1; break;; "completed "*) echo "release failed: $st" >&2; exit 1;; esac
  sleep 30
done
test "${REL_OK:-}" = 1
test "$(gh run view "$REL_ID" --repo libra-tools/libra --json headSha --jq .headSha)" = "$HEAD_SHA"
code=$(curl --max-time 15 -s -o /dev/null -w '%{http_code}' -L "https://download.libra.tools/libra/releases/v$VERSION/libra-linux-amd64"); test "$code" = 200 || { echo "download.libra.tools artifact not reachable: $code" >&2; exit 1; }
test "$(gh run view "$REL_ID" --repo libra-tools/libra --json jobs --jq '[.jobs[]|select(.name|startswith("build-and-upload ("))|select(.conclusion=="success")]|length')" = 4
for j in upload-install-scripts update-homebrew-tap verify-homebrew-formula request-stable-manifest; do
  gh run view "$REL_ID" --repo libra-tools/libra --json jobs --jq "[.jobs[]|select(.name|startswith(\"$j\"))|select(.conclusion==\"success\")]|length" | awk '{exit ($1>=1)?0:1}' || { echo "release job missing/failed: $j" >&2; exit 1; }
done

## 已决议设计决策

### ADR-CG-01：legacy 参数边界

- **Context：** clap 在命令分发前拒绝未知 `-`；仅在 `resolve_command` 改写已太晚。
- **Decision：** 在 `src/cli.rs:3370` 前，只对可确认为 legacy `config`/`cfg` 的 argv 进行保守规范化。按真实 clap 元数据识别根和 config 选项、分离值及 `--x=y`，不得把选项参数当 key；已有 `--`、显式 `get`/`set` 子命令、`--get`/`--unset` 的 pattern、key 前未知旗标及其它命令保持既有合同。原始操作数以 `OsString` 保持到 clap，原本不支持的非 UTF-8 仍按现有解析错误处理，不承诺新支持。
- **共同解析优先级与二选一执行归属：** 第一个 key 后的 `-d` 或 `--default` 最高优先级地保留为 default 选项，直到其参数 consumed；它的 `=` 形式亦同。分隔标记只能插在已识别 key 及紧随的操作数之后，不能使该处 `-d`/`--default` 变成值。裸的 `key -d fallback`、`key --default fallback` 在最终合同中 exit 0 并输出 fallback；这项执行结果仅由 CG-02 拥有。CG-01 只有词法/argv 层归属：它验证规范化保留选项和参数、不误作 key 或值，是词法/argv 层合同。CG-01 的 bare-key 两门必须做纯词法断言，不跑端到端命令：对同一规范化输入只断言 `-d`/`--default` 与其参数仍为独立选项 token，不按该 token 推断 clap 或 default 守卫结果；不得断言命中 `src/command/config.rs:1764` 的旧默认守卫或任何退出码、输出。CG-02 发布后，在同一 CG-02 实现提交/仅承载版本与文档更新的变更中，替换 `cg01_bare_key_short_default`、`cg01_bare_key_long_default` 两个测试为对规范化 argv 的纯词法断言，或删除这两门并同步修订 CG-01 的 AC/VER 与 EX-CG-01；不得保留既已过时的旧守卫结果断言后声称最终树通过。为此，CG-01 的本轮通过不得被解释为最终合树结论。
- **升级原始意图预解析检查：** 唯一函数载体为 `pub(crate) fn check_upgrade_raw_argv(raw_argv: &[OsString]) -> CliResult<()>`，定义于 `src/command/config.rs` 中与现行 `upgrade_namespace_raw_preflight` 相邻的位置；唯一入口调用为 `src/cli.rs:3346` 的 `parse_async_scoped`。调用顺序严格为：`parse_async_scoped` 先在 `src/cli.rs:3346` 将原始 `argv: Vec<OsString>` clone 为 `raw_before_normalize`，随即调用 `check_upgrade_raw_argv(&raw_before_normalize)`；其后才开始 legacy config 规范化；最后把规范化结果交给现有 `Cli::try_parse_from`。该函数接收的是规范化前的完整原始 `&[OsString]`，且必须在 clone、检查和规范化之间不出现一次重新取值的路径。跨规范化例子：`["libra","cfg","upgrade.mode","--get","safe","-d","bad"]` 在规范化时可能把 key 后 `--get` 解释为值；`check_upgrade_raw_argv` 须先在规范化前以原始 `upgrade.mode` 为 key 并同时看到 `--get` 动作拼写，以升级命名空间冲突拒绝，故用户看到的拒绝来自原始拼写，而不是被改写后的 Set 结果。任何在 `Cli::try_parse_from` 之后“取得被推测原始意图”的实现必须停止并重设计；该载体只能由首次原始 `&[OsString]` 在规范化之前创建。`upgrade_raw_preflight_argv` 若在最终代码中仅指 `raw_before_normalize` 的内存占用而非函数名，应以该形状保存，不得另立未声明函数。
- **边界：** 保留 `--get key [pattern]`、`--unset key [pattern]` 的现有第二槽；裸写第三操作数今天不支持，仍按当前接口拒绝，不把已有 `handle_set` 中不可达的 value-pattern 分支称作已交付。完整第三参数支持由 DEFER-CG-03 跟踪。若无法在不改变现有保护键合同的前提下区分 argv，停止并修订计划，不放宽安全检查。
- **Alternatives：** 仅移动 resolver 或只接受未知负值，分别无法处理 clap 的前置拒绝或已知旗标作值。

### ADR-CG-02：裸读 default 的实际数据流

- **Context：** 裸 key 目前是 Set；是否为读取直到 `handle_set` 才知道；受保护键仍可触发安全输入。
- **Decision：** 仅当 legacy 为普通 key、无位置值、无赋值意图且有 default（按 ADR-CG-01 的保留优先级把 `config --get key -d fallback`、`config --get key --default fallback` 与裸 `config key -d fallback`、`config key --default fallback` 归为该状态）时，在 `resolve_command_typed` 明确构造 `ResolvedCommand::Get`，把 default、scope、cascade、输出格式与类型传入现有 `handle_get`。不得改变未带 default 的裸读及受保护键交互。敏感 key 的裸 default 在交互及写入前拒绝，使用既有安全分类；普通名称但存储为加密的 key 仍经既有读取脱敏。带 default 的裸赋值维持拒绝及零配置写入；既有显式 `--get`/`--get-all`/`--get-regexp` 合同和其它组合的现有行为保持现状，包括可能错误放行的组合；本卡不另改错误码或收紧全部动作。
- **Alternatives：** 只移动守卫而不传 default 不会修复缺失值；把所有裸 key 改 Get 会破坏受保护键的现有行为。
- **Consequences：** 后续 #557 CO-01 在同一 exact-get 路径接入覆盖后，负责交叉测试；CG-02 不能引用尚不存在的 `-c` 实现。

# Issue #673：`GIT_COMMITTER_DATE` 必须接受无时区的 `YYYY-MM-DD HH:MM`（2026-11-11）

> 模板 v2.16。[Issue #673](https://github.com/libra-tools/libra/issues/673) OPEN，含 4 条评论；正文与评论 TC 全集为 TC-0123/0125/0126/0140/3038/3039/3040。仅规划，未授权执行；卡 `pending` / 验收空。Git 对照 pin `6de20f6092dcf9bdb1c8efe03db4b70c82b423dd`；四个 archive TC（TC-0123/0125/0126/0140）均由本卡 Verification V3 必过验收（实测基线证明已有 commit 时四项均成功，日期修复即解除 blocker）；三个 blame 级联按 `DEFER-I673-02..04` 逐项追踪。实测基线 system `libra 0.30.171`。测试用例仓本计划不修改。

## 文档职责

### 适用范围

`GIT_AUTHOR_DATE` / `GIT_COMMITTER_DATE`（及 `commit --date`）对「日期 + 时间、无时区」形式 `YYYY-MM-DD HH:MM`（含可选的 `:SS`）的解析：是否接受、使用哪个时区、写入对象的 committer/author 时间戳与 `+HHMM` 偏移；既有 `YYYY-MM-DD`、RFC3339、`<unix> <tz>` 形式保持不变。

### 非目标

`parse_date`（`log --since/--until`）的既有相对日期语义变更（只新增必要分支并保持既有断言）。`am` 的 charset 支持（`issues/672.md` 承接）。`archive` 命令本身（TC-0123 的后续步骤依赖本卡提交成功，但 archive 行为不改）。时区数据库依赖（不使用 `TZ` 之外的隐式全局状态）。

### 成功定义

- `GIT_COMMITTER_DATE="2005-05-27 22:00" libra commit -m initial` 退出 0 并创建提交。
- 提交对象的 committer 时间戳等于该 wall time 在**本地时区**下的 epoch 秒，committer 偏移等于本地 `+HHMM`。
- `GIT_AUTHOR_DATE` 与 `commit --date` 同形式同样生效。
- DST gap（`LocalResult::None`）必须 fail-closed，返回 `invalid GIT_COMMITTER_DATE date '<value>': local time does not exist`，不得猜测 offset。
- 非法日期（如 `2005-13-45 99:99`）仍以既有 `LBR-CLI-002` fail-closed；文档与兼容矩阵同卡。

## 已决议设计决策

### ADR-DATE-01: 无时区形式按本地时区解释

- **Status:** Accepted
- **Context:** Git 把 `YYYY-MM-DD HH:MM` 解释为本地 wall time，并把对应偏移写入对象。
- **Decision:** 在 `parse_signature_date` 内新增 `%Y-%m-%d %H:%M` 与 `%Y-%m-%d %H:%M:%S` 两个 naive 分支，用 `chrono::Local.from_local_datetime(...)` 解析：`LocalResult::Single(value)` 直接采用；`LocalResult::Ambiguous(earliest, _)` 确定性采用最早瞬间；`LocalResult::None`（DST gap）立即返回 `CommitError::InvalidDate`，用户可见 detail 固定含 `local time does not exist（不得重复 Display 已带的 `invalid GIT_COMMITTER_DATE date '<value>'` 前缀）` 并映射 `LBR-CLI-002`。成功时返回 `SignatureDate { timestamp, Some(offset) }`；禁止为 gap 猜 offset、向前/向后平移或回退 UTC。
- **Alternatives considered:** 默认 UTC（与 Git 不一致，会写错时间）；要求用户显式时区（仍不能通过上游 setup）。
- **Consequences:** 结果依赖运行环境时区；测试只给子进程设置固定 `TZ`，同时断言正常 offset、ambiguous 最早瞬间与 gap 精确错误。
- **Revisit when:** 引入 `--date` 的显式时区策略。

### ADR-DATE-02: `log` 的 `parse_date` 只做最小扩展

- **Status:** Accepted
- **Context:** `parse_signature_date` 回退到 `log::date_parser::parse_date`；该函数服务于 `log --since/--until`。
- **Decision:** 只在 `parse_signature_date` 内新增 naive 分支，**不**改变 `log` 的既有相对日期与 `%Y-%m-%d`（date-only）语义；`log` 的新增接受面登记为 `DEFER-I673-01`。
- **Alternatives considered:** 直接在 `parse_date` 加分支（会同时改变 `log` 过滤语义，扩大写集）。
- **Consequences:** 两条调用路径的接受面不同，文档需各自说明。
- **Revisit when:** 需要统一日期解析语义。

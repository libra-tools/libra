## 文档职责

### 适用范围

让 `fast-import` 的 `from` 对象说明接受 Git 已接受的 `<commit-ish>^0`，使 TC-2997 的导入前置不再因哈希格式检查失败。包含回归、双语命令/网站文档和本卡独立发布。开工前重读源码、在跑写者和固定 Git 对照。

### 非目标

不实现 `from` 的裸引用名、短哈希、其它修订后缀、`cat-blob`/`ls`/`get-mark`、marks 文件，也不修改 `tag --contains` 的栈或深度行为。

### 成功定义

`from refs/heads/main^0` 解析到该分支尖端提交；同一 fast-import 流里后续没有 `from` 的 `commit refs/heads/main` 沿用流内尖端作为父提交并继承树；既有 mark 与完整十六进制 ID 不变；TC-2997 双轨 PASS。本文不授权执行。

## 已决议设计决策

### ADR-I1050-01: 只在三条 `from` 上接受窄语法

新增 `async fn resolve_from_objectish`，只替换这三处 `from`：`src/command/fast_import.rs:324` 的 commit `from`、`:641` 的 tag `from`、`:700` 的 reset `from`。`merge`（`:332`）、`M`（`:458`）和 `N`（`:547`）继续调用同步的 `resolve_commitish` / `resolve_dataref`。不把 `resolve_dataref` 改成 async，不使用 `block_on`。

允许的 `^0` 只有两类：完整十六进制，或 `refs/` 开头、不含 `^`、`~`、`:`、`@{` 且通过现有 `is_valid_refname` 的引用。这两类才 `await util::resolve_object_spec_typed`。`refs/heads/main~1^0`、`HEAD^0`、裸 `refs/heads/main` 以及其它形式仍走现有哈希格式致命错误，不进入共享解析器。失败不发布引用。

## 文档职责

### 适用范围

`libra add` 的 pathspec 未匹配判定在**空仓库**（无 HEAD 提交、索引为空）上的行为：`add -A .`、`add -A -- .`、`add --all .`、`add .`、`add :/` 的退出码与输出，以及无 pathspec 的 `add -A` 回归；非空仓库与含非根元素的混合输入保持既有失败语义。

### 非目标

通配符与 magic pathspec（`:(attr)`/`:(glob)`/`:(exclude)`、以及作为空 sentinel 的裸 `:`）语义。「未匹配」错误码与文案改版（`docs/error-codes.md` 不变）。`--ignore-missing` 警告路径（`src/command/add.rs:2608`）。`add -N/--intent-to-add` 的未匹配报错（`src/command/add.rs:1526-1535`）。`restore`/`checkout`/`rm` 的同名文案。

### 成功定义

- 空仓库上五种根 pathspec 形式退出 0、stdout/stderr 为空、索引无条目。
- 无 pathspec 的 `add -A` 保持退出 0（回归，不得因本卡回归）。
- 空仓库上 `add nonexistent` 与非空仓库未匹配 pathspec 仍以 `LBR-CLI-003` 家族错误失败。
- 回归、三处 add 文档与兼容矩阵同卡。

## 已决议设计决策

### ADR-EMPTY-01: 只对「根型 pathspec + unborn 仓库」放行

- **Status:** Accepted
- **Context:** add 以「匹配到 tracked 变更或工作树文件」为成功条件；空仓库无候选，故根 pathspec 被判未匹配。
- **Decision:** 当仓库无 HEAD 提交且索引为空时，`PathspecSet` 中**只含根型元素**（无 magic 前缀的 `.`、`:/`，以及 `-A/--all` 的隐式全树）不产生 `PathspecNotMatched`，命令成功且不写索引。裸 `:`（Git 的空 pathspec sentinel）不纳入放行集合，保持现状并登记 `DEFER-I662-01`。含非根元素的输入按元素逐个判定，非根未匹配照旧失败。
- **Alternatives considered:** 空仓库忽略全部 pathspec（会让 `add nonexistent` 静默成功）；把 `.` 恒视为匹配（非空仓库语义被放宽）。
- **Consequences:** 判定依赖 unborn 事实；`add -A .` 与 `add .` 的库内路径不同但结果一致。
- **Revisit when:** Git 改变 `t3700` 空仓库 expectations，或需要支持裸 `:`。

### ADR-EMPTY-02: 不新增错误码，只在既有判定点收窄

- **Status:** Accepted
- **Context:** 既有 `LBR-CLI-003` 家族文案保留。
- **Decision:** 仅在普通收集判定点（`src/command/add.rs:2766-2778`）与 resolved 分支同口径收窄；错误码/文案不变。
- **Alternatives considered:** 新增「空仓库」专门提示（Git 静默，会引入噪声）。
- **Consequences:** `docs/error-codes.md` 无需改动。
- **Revisit when:** 需要区分空仓库诊断。

# Issue #984：`merge` 缺少 `--no-squash` 取反形式（2026-11-12）

> 模板 v2.16。[Issue #984](https://github.com/libra-tools/libra/issues/984) OPEN。仅规划，未授权执行；`I984-01` 为 `pending` / Acceptance 空。Git 对照 pin `6de20f6092dcf9bdb1c8efe03db4b70c82b423dd`。基线 `Cargo.toml` `0.30.173`（`Cargo.toml:3`）；实测 system `libra 0.30.173`。测试用例仓 `/mnt/gitmono/libra-testcases` 本计划不修改。

## 文档职责

### 适用范围

`libra merge` 的 `--no-squash` 取反形式：clap 必须接受该 flag；`--no-squash` 单独使用时等价于默认合併（产生 merge commit 并移动 HEAD）；与 `--squash` 同时出现时按 Git 的**最后出现者生效**（last-wins）；`--no-squash` 覆盖 `mergeoptions`（`issues/978.md` 交付后）与 `branch.<name>.mergeOptions` 中的 `squash`。覆盖 `MergeArgs` 的 flag 定义、`squash` 的解析优先级与既有冲突集。

### 非目标

不实现 `mergeoptions`/`branch.<name>.mergeOptions` 的配置读取与套用（`issues/978.md`），本卡只保证当该配置将来存在时 `--no-squash` 能覆盖它（以既有 `args.squash` 布尔为唯一输入）。不实现以 `-` 开头的配置值解析（`issues/817.md`）。不改 `--squash` 的行为语义（staged 结果、不提交、不移动 HEAD）、不改 `--no-commit`/`--dry-run`/`--continue`/`--abort` 的既有冲突集、不改合併算法与消息渲染（`issues/974.md`/`issues/977.md`）、不修改测试用例仓。

### 成功定义

- `libra merge --no-squash <branch>` 被 parser 接受并以 0 退出（不再 `unexpected argument`）。
- `--no-squash` 单独使用时的可观察结果与不传 `--squash` 完全一致（产生 merge commit、HEAD 前移、无 `SQUASH_MSG` 残留）。
- `--squash --no-squash` 与 `--no-squash --squash` 分别呈现 last-wins：前者产生 merge commit，后者产生 staged-only 结果。
- `--no-squash` 与 `--no-commit`/`--continue`/`--abort`/`--dry-run` 的冲突判定与 `--squash` 一致（不因取反形式穿透既有守卫）。
- 帮助文本同时列出 `--squash` 与 `--no-squash`。

## 已决议设计决策

### ADR-I984-01：`--squash`/`--no-squash` 用 `overrides_with` 表达 last-wins

- **Status:** Accepted
- **Context:** `--stat`/`--no-stat` 已用 `overrides_with` 互相覆盖（`src/command/merge.rs:421,433`），而 `squash` 只有正向 flag 且带 `conflicts_with_all = ["continue_merge", "abort"]`（`:385-387`）。Git 对可否定布尔按「最后出现者生效」。
- **Decision:** 新增 `pub no_squash: bool` 并令 `squash` 与 `no_squash` 同时带 `overrides_with`（`squash.overrides_with = "no_squash"` 与 `no_squash.overrides_with = "squash"`），保留两者与 `continue_merge`/`abort` 的既有 `conflicts_with_all`。解析后以「`squash` 为真」为唯一输入写入运行时选项（`src/command/merge.rs:1307`），`no_squash` 不进入下游逻辑。
- **Alternatives considered:** 用 `conflicts_with`（会把 `--squash --no-squash` 变成 rc=2，与 Git 不符）。
- **Consequences:** 两个 flag 的语义都落到 `args.squash` 一个布尔；下游零改动。
- **Revisit when:** Git 把 `--squash` 改为非可否定。

### ADR-I984-02：`--no-squash` 不进下游分支，只影响 `args.squash` 的最终值

- **Status:** Accepted
- **Context:** `options.squash` 在 `src/command/merge.rs:1912,3250,3699,9036` 决定 staged-only 路径与消息处理。
- **Decision:** 下游只读 `options.squash`；`no_squash` 仅作为 clap 层面的清零器。禁止在 `run_merge*` 内再判 `no_squash`，避免两份真相。
- **Alternatives considered:** 把 `no_squash` 也透传到 `MergeOptions`（会引入互相矛盾的布尔对）。
- **Consequences:** 单一真相；`--no-squash`/`--squash` 的先后由 clap 保障。
- **Revisit when:** N/A。

### ADR-I984-03：冲突集合保持不变

- **Status:** Accepted
- **Context:** `--squash` 与 `--continue`/`--abort` 冲突（`src/command/merge.rs:386`），且 `--restart` 的集合包含 `squash`（`:282,308`）。
- **Decision:** `no_squash` 采用与 `squash` 完全相同的 `conflicts_with_all` 集合，使取反形式不能绕过既有守卫；`--no-squash --dry-run` 仍按既有 `dry_run` 冲突集行为。
- **Alternatives considered:** 只给 `squash` 加守卫（会让 `--no-squash --continue` 静默通过）。
- **Consequences:** 守卫对称。
- **Revisit when:** Git 改变这些组合的可接受性。

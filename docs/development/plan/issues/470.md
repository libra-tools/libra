## 文档职责

issue #470 报告两类问题：
1. 工作树物化（`clone`、`restore` 等）把 `100755` 条目写成 `0644`，丢失可执行位；
2. `status`/`diff` 不把工作树 mode 与索引的差异当作修改，损坏对 Libra 自身不可见。

本计划在 libra 0.22.28（与仓库源码同版本）与 git 2.54.0 上分三轮并排实跑，结论：

- **物化缺陷比 issue 描述更广：**
  - 丢失可执行位的路径：`clone`（Git 源与 Libra 源）、`restore`（索引源）、`checkout -- <path>`、`checkout <rev> -- <path>`、`restore --staged --worktree`、`merge`/`pull` 快进、`cherry-pick`（含冲突文件）、`revert` 恢复被删文件、`worktree add`、`checkout <commit>`、`restore --merge`。
  - 反方向（不清除可执行位）：切换到内容不同且条目为 `100644` 的分支时保留旧文件的 `755`。
  - 已正确的路径：`restore --source <rev> --worktree`、`reset --hard`、三路 `merge`、`rebase`、`stash pop` 新文件；但它们用固定 `0755` 覆盖，`umask 077` 下与 Git 的 `700` 不一致。
- **检测缺陷：** `diff` 能输出 `old mode/new mode`，但 `status`（短、长、porcelain v2、JSON）、`add`（`nothing to add`）、`commit -a`、`stash push`（`No local changes to save`）都忽略 mode-only 变化；`core.fileMode` 只被 `init` 写入、从未读取，非法值被静默忽略。

本计划交付 **3** 张卡（FM-03/FM-04 已迁至 [`plan-20260918.md`](../plan-20260918.md)）：
1. **Phase 1（物化）：** FM-01 共享写入原语与 `restore` 路径，FM-02 其余写入点。
2. **Phase 2（提示）：** FM-05 旧工作树修复提示；`core.fileMode` 与 mode-only 检测已迁至 plan-20260918 FM-03/FM-04。

本文只规划任务，不宣称实现完成。落地时每个任务都必须先刷新源码锚点，再按任务卡验收。

- `core.fileMode` 与 mode-only 检测/暂存：**已迁出**至 [`plan-20260918.md`](../plan-20260918.md) FM-03、FM-04。#470 关闭须等那些卡完成（DEP-FM-07）。

### 非目标

- 符号链接存在时 `stash pop` 报「local changes would be overwritten: link.sh」（实测新发现，与 mode 无关，DEFER-01）。
- `diff-files` 输出 patch 而非 raw 格式（归 #478/#479，DEFER-02）。
- `checkout -m`（Libra 未支持，DEFER-03）。
- Windows 上的可执行位语义（无 POSIX 权限；按 `core.fileMode=false` 处理，DEFER-04 登记验证）。
- `core.sharedRepository` 等其它权限配置（DEFER-05）。

- 判据矩阵 M-MAT、M-MAT2、M-CFG、M-DET、M-HINT 全部行由子进程集成测试证明，并附 git 2.54 并排对照。

### ADR-FM-02: 物化权限语义

- **Status:** Accepted
- **Context:** GAP-01..03；git `entry.c:86-90`、`:110-116`；实测 S5、S12、F5。
- **Decision:**
  1. 常规文件按条目 mode 创建：`100755` 用 `0777`，`100644` 用 `0666`，由内核在创建时应用进程 `umask`，与 Git 一致；不在用户态读取或修改 `umask`。
  2. 替换已有文件时，在同目录创建临时文件（上述权限），写入内容后 rename 到目标路径，从而同时设置或清除可执行位，且内容与权限原子生效。
  3. 符号链接条目按既有逻辑写入符号链接；gitlink 不物化文件。
  4. `core.fileMode` 不影响物化（Git 的 `create_file` 只看 `ce_mode`）。
  5. LFS 条目：对象内容先写入同目录临时文件，再按第 2 条 rename。
  6. 非 Unix 平台不设置权限位（DEFER-04 登记验证）。
- **Alternatives considered:** 写入后 `set_permissions(0o755)`——忽略 `umask`，与 F5 的 Git 结果不一致，且非原子，拒绝。在用户态读取 `umask`（`umask(0)` 再恢复）——多线程下有竞态，拒绝。
- **Consequences:** `reset`、`merge`、`rebase`、`stash` 的固定权限写法改为同一语义，`umask 077` 下行为变化（`755` → `700`），文档登记。
- **Revisit when:** 支持 `core.sharedRepository`（DEFER-05）。

### ADR-FM-03: 单一工作树 blob 写入原语

- **Status:** Accepted
- **Context:** 物化写入分散于 `restore.rs`、`cherry_pick.rs`、`revert.rs`、`reset.rs`、`merge.rs`、`rebase.rs`、`stash.rs`、`hydrate.rs`，各自处理符号链接与权限。
- **Decision:**
  1. 新增 `src/utils/worktree_blob.rs`，提供按 `TreeItemMode` 写入工作树的原语：常规文件按 ADR-FM-02 创建并原子替换，符号链接按既有规则写入，并返回写入后的元数据供索引刷新使用。
  2. 原语复用 `atomic_write` 的临时文件与 rename 实现；调用方既有的路径安全检查（拒绝经符号链接写出、清除目录占位）保留在调用方或以参数传入，不得削弱。
  3. FM-01 迁移 `restore.rs` 全部写入点；FM-02 迁移其余模块，并新增 compat 守卫 `compat_worktree_blob_writes`：在清单模块中检测对已跟踪 blob 的直接 `fs::write` / `util::write_file`，例外须登记理由。
  4. `util::write_file` 保留给非 blob 文件（配置、侧车等），不改语义。
- **Alternatives considered:** 在 `util::write_file` 内部加 mode 参数——该函数被大量非 blob 写入复用，改签名波及面过大，拒绝。
- **Consequences:** FM-01、FM-02 命中 T-1（共享原语）。
- **Revisit when:** `worktree_io` 执行器接管全部工作树写入。

### ADR-FM-04: `core.fileMode`

- **Status:** Accepted
- **Context:** GAP-04；git `environment.c:327-328`、`:762`、`read-cache.c:755-769`；实测 F1、F2、D4/S10。
- **Decision:**
  1. 新增仓库配置读取 `core.fileMode`（大小写不敏感），经 `parse_git_bool` 解析；未设置时 Unix 为 `true`、非 Unix 为 `false`。
  2. 非法值 fail-closed：消息 `bad boolean config value '<v>' for 'core.filemode'`，错误码与退出码沿用 `commit.verbose` 非法布尔的既有映射（`src/command/commit.rs:899`），在任何写入前报告。
  3. `false` 时：`add`、`update-index <path>`、`commit -a` 暂存已有条目沿用原条目 mode，新文件为 `100644`；`status`、`diff`、`stash push` 不比较可执行位。
  4. `add --chmod` 与 `update-index --chmod`/`--cacheinfo` 不受影响。
- **Alternatives considered:** 忽略非法值——与 Git 不一致且掩盖配置错误，拒绝。
- **Consequences:** 配置读取为共享 helper，FM-03 命中 T-1。
- **Revisit when:** 支持 `core.symlinks=false`。

### ADR-FM-05: mode-only 工作树变化检测

- **Status:** Accepted
- **Context:** GAP-05；git `read-cache.c:316-324`；实测 D1–D6、S2。
- **Decision:**
  1. 在 `changes_to_be_staged_split_with_index` 中，对常规文件条目在 `core.fileMode=true` 时比较索引 mode 与工作树属主 `x` 位；不同即为 modified，即使 blob hash 相同。
  2. porcelain v2 的 `.M` 行与模式列、JSON `modified` 由同一变化集合产生。
  3. `add`、`commit -a` 暂存 mode-only 变化时更新索引条目 mode 与 stat；`stash push` 把 mode-only 变化视为本地修改并在 pop 时恢复 mode。
  4. `diff` 在 `core.fileMode=false` 时不输出 mode-only 差异。
  5. 与 490 计划 SW-05 的 skip-worktree 跳过规则同时成立：带 skip-worktree 位的条目不做 mode 比较。
- **Alternatives considered:** 只在 `diff` 保留检测——issue 期望 `status` 可见，拒绝。
- **Consequences:** `status` 输出在旧工作树上出现新的 ` M` 行，由 FM-05 缓解。
- **Revisit when:** 引入 fsmonitor/untracked cache。

### ADR-FM-06: 旧工作树修复提示

- **Status:** Accepted
- **Context:** GAP-06。issue 指出旧版本物化的工作树在 Git 中出现伪 mode 变化，提交会去掉上游可执行位；FM-04 之后 Libra 同样会显示这些 ` M`。
- **Decision:**
  - `status` 长输出在存在「索引 `100755`、工作树不可执行、内容 hash 相同」的条目时，于修改列表后输出一次提示，给出数量与 `libra restore -- <path>...`（超过 5 个时给出前 5 个与 `libra restore -- .` 的替代写法）。
  - `--short`、`--porcelain`、`--json` 与 `core.fileMode=false` 时不输出（M-HINT H2、H5）。
  - 该提示是 Libra 有意差异，登记在 `COMPATIBILITY.md` status 行。
- **Alternatives considered:** 在 FM-04 发布时自动修复工作树权限——未经用户同意修改工作树，拒绝。在机器输出中增加字段——改变稳定输出契约，收益有限，拒绝。
- **Consequences:** 需要文档说明升级后执行 `libra restore -- .` 修复旧工作树。
- **Revisit when:** 旧版本 Libra（< FM-01 发布版本）不再被支持。

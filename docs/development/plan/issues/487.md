# Issue #487：本地 Git 转换挂死与中断后不可恢复修复计划（2026-09-14）

> 模板版本：v2.6；继承 [plan-template.md](../plan-template.md) 的 GC-01..13、ER-01..13、G-01..11。
> 来源：[libra-tools/libra#487](https://github.com/libra-tools/libra/issues/487)。
> 状态：设计计划；全部任务卡 `pending`，尚未进行 Codex review（见「Codex review log」）。

## 文档职责

本文解决 issue #487：`libra init --from-git-repository .` 在较大的 Git 仓库上中断后，留下一个「看似正常但没有任何历史」的 `.libra`，且重试被「already-initialized」拒绝，没有受支持的恢复路径。

核对时发现，中断很可能不是偶发外因，而是必然结果：本地传输的 pack 编码存在**确定性死锁**。源仓库对象数超过约 2 000 时，`init --from-git-repository` 与从本地路径 `clone` 都会永久挂起（0% CPU），用户最终只能杀进程。本计划因此分五个行为轴：

1. 修复死锁（P0）；
2. 普通错误与信号中断时回滚本次创建的目标状态；
3. 用崩溃安全标记让被强杀的转换可以安全重试；
4. 半成品仓库不再被当作正常空仓库使用；
5. 限制本地转换的峰值内存。

本文只规划任务，不宣称实现完成。落地时每个任务都必须先刷新源码锚点，再按任务卡验收。

### 适用范围

- 本地传输 `LocalClient::fetch_objects` 的 pack 编码与对象收集（GitRepo 与 LibraRepo 两种源），消费者为 `init --from-git-repository`、`clone <本地路径>`、`fetch <本地路径>`。
- `libra init --from-git-repository` 的失败原子性、信号处理、崩溃标记与重试语义。
- 带未完成转换标记的仓库上，其它命令的预检行为。
- 同步：`docs/commands/init.md` EN + zh-CN、`docs/development/commands/init.md`、`COMPATIBILITY.md` 的 `init` 行、`../libra-backend` 网站文档、`tests/INDEX.md`（如新增 target）。

### 非目标

- 普通 `libra init`（不带 `--from-git-repository`）的语义：不引入回滚或标记。
- 对本版本之前产生、没有标记的遗留半成品仓库做自动识别或自动移走：只提供文档化的手工恢复（DEFER-01）。
- fetch 接收端把整个 pack 读入 `Vec<u8>` 的内存模型（HTTP 与本地共用，DEFER-02）。
- 失败 operation 的 journal 停留在 `mutation` 阶段的清理（DEFER-03）。
- 远端（HTTP/SSH）传输的中断恢复（DEFER-04）。

### 成功定义

- ≥ 5 000 对象的本地 Git 源，其 `init --from-git-repository`、`clone` 与增量 `fetch`，以及 ≥ 5 000 对象的本地 Libra 源 `clone`，都能在测试时限内完成且历史完整。
- 转换返回错误、收到 SIGINT/SIGTERM 时，本次创建的目标状态被回滚，源 `.git` 与已有用户文件不受影响，可直接重试。
- 转换被强杀（无法执行回滚）后，目标带有崩溃安全标记；用相同源重试会把残留移到旁路目录并重新完成转换；其它命令在该仓库中明确拒绝并给出恢复命令。
- 本地 GitRepo 源转换的峰值内存不再随解码对象总量线性保留。
- 五张卡各自完成 C 组发布并取得 D 组证据，然后全量收口门全绿。满足这些之后，本计划才可标记完成。

## 已决议设计决策

实现时若需偏离本节，必须先修改计划并说明原因，不得在代码中静默改语义。

### ADR-IG-01: 本地传输复用 `pack_writer::encode_pack_bytes`

- **Status:** Accepted
- **Context:** GAP-01。两份同名编码函数，只有 `pack_writer` 的已修复。
- **Decision:** 删除 `local_client.rs::encode_pack_bytes`，`encode_entries_to_fetch_response` 改为调用 `crate::internal::pack_writer::encode_pack_bytes`（返回类型一致，均为 `io::Result<Vec<u8>>`）。在 `pack_writer` 增加超过两个通道容量之和的 entry 数回归单测，并以 `tokio::time::timeout` 防止测试本身挂起。
- **Alternatives considered:** 在 `local_client.rs` 内原地修补——保留两份实现，违反 GC-02，拒绝。
- **Consequences:** 本地传输与 `repack`/`pack-objects` 共用同一编码器；`pack_writer` 的后续修复自动覆盖本地传输。
- **Revisit when:** IG-05 需要流式编码接口时，在 `pack_writer` 内扩展，而非复制。

### ADR-IG-02: 转换事务标记

- **Status:** Accepted
- **Context:** GAP-02/03/04。转换逻辑经 cwd 发现 `.libra`，暂存到其它目录名再原子改名需要改造发现逻辑与全部下游命令，而 `--separate-libra-dir` 已被移除。
- **Decision:**
  1. 仅对 `--from-git-repository` 的**新建**路径，在 `fs::create_dir_all(&root_dir)` 之后、建库之前，于存储根写入 `CONVERSION_IN_PROGRESS`（JSON：`version`、`source`（规范化源 Git 目录）、`started_at`、`owner`（与 `operation_wrapper::claim_owner` 同格式）、`created`（本次创建的路径清单：目标目录是否由本次创建、存储根、根 `.libraignore`、转换生成的 `.libraignore` 列表））。写临时文件、fsync 后原子改名，并 fsync 存储根目录。
  2. `created` 清单在每个创建步骤**之前**追加，并以同样方式原子重写。
  3. 转换、vault 全部成功后，删除标记是 `run_init_internal` 返回前的最后一个写操作。
  4. 标记只由 init 转换路径读写；普通 init 与其它命令只读取其是否存在（IG-04）。
- **Alternatives considered:** 暂存目录 + 原子改名——见 Context，拒绝。把标记写进 SQLite——建库前的崩溃窗口无法覆盖，拒绝。
- **Consequences:** 旧二进制会忽略该文件，所以 IG-03/IG-04 之前产生的半成品仍按 DEFER-01 手工恢复。
- **Revisit when:** 恢复单独的存储目录支持。

### ADR-IG-03: 回滚与重试的安全边界

- **Status:** Accepted
- **Context:** `.libra` 可能包含用户数据；自动清理必须可证明只动本次转换创建的内容。
- **Decision:**
  1. **普通错误与信号（IG-02）：** 在转换期间安装 SIGINT/SIGTERM 处理，把信号转为取消，进入同一回滚路径。回滚按 `created` 清单逆序删除：目标目录由本次创建时整个删除；否则删除存储根与清单中的 `.libraignore` 文件，不触碰其它工作树文件与源 `.git`。回滚成功后返回原始错误（信号形态分别以 exit 130 / 143 结束）；回滚失败时保留标记，并在原始错误上附加 warning 与手工恢复命令。
  2. **强杀后重试（IG-03）：** `init --from-git-repository <src>` 发现目标存储根含标记时：
     - 标记不可解析或 `version` 未知 → `LBR-REPO-003` 拒绝，给出手工命令；
     - 存储根是 symlink → 拒绝；
     - `owner` 存活，或无法证明已退出（无出生令牌、跨机器）→ `LBR-CONFLICT-002` 拒绝；
     - `source` 与本次规范化源不同 → `LBR-REPO-003` 拒绝；
     - 否则把存储根原子改名为同级 `<存储根名>.incomplete-<UTC 时间戳>`（不删除），再从头执行新建转换，并在输出与 JSON `warnings` 中报告旁路目录路径。
  3. 转换生成、仍留在工作树中的 `.libraignore` 按 `created` 清单删除后重建；清单外的文件一律不动。
- **Alternatives considered:** 重试时原地续传——半写 refs/remote 配置与 `setup_repository` 的非幂等步骤难以证明正确，拒绝。直接删除残留——不可撤销且可能伤及用户数据，拒绝。
- **Consequences:** 重试需要额外磁盘空间保存旁路目录；文档必须说明确认后可删除。
- **Revisit when:** 转换步骤全部具备幂等续传能力。

### ADR-IG-04: 半成品仓库的命令守卫

- **Status:** Accepted
- **Context:** GAP-05。半成品仓库上 `status` 与写命令会误导用户，甚至在残缺仓库上产生用户数据。
- **Decision:** 在 `src/cli.rs` 的仓库预检中，若解析出的存储根含 `CONVERSION_IN_PROGRESS`：
  - owner 存活 → `LBR-CONFLICT-002`：「Git conversion in progress (pid …)」；
  - 否则 → `LBR-REPO-003`：「incomplete Git conversion」，提示 `libra init --from-git-repository <source>` 重试，或手工移走存储根。
  - 豁免：`init` 本身（交给 ADR-IG-03 处理），以及不需要仓库的命令（`--version`、`help`、`completions` 等由既有 `CommandPreflight::none()` 决定）。
  - 预检成本为一次 `stat`。
- **Alternatives considered:** 只在 `status` 输出 warning——写命令仍可在残缺仓库上执行，拒绝。
- **Consequences:** 即使只是读取型命令，在半成品仓库上也会失败（fail-closed，GC-07）。
- **Revisit when:** 需要在半成品仓库上做只读诊断。

### ADR-IG-05: 判据矩阵

- **Status:** Accepted
- **Context:** 规模、失败、崩溃与守卫各有大量形态，需要可复制执行的判据。
- **Decision:** 下列矩阵是各卡 AC 引用的判据规范，每行必须有对应测试。
  - 源仓库由测试用 `git fast-import` 生成（沿用 `init_from_git_test.rs:81` 调用 `git` 的约定）。

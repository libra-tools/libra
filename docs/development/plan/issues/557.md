## 文档职责

规划根参数、调用级配置覆盖、列明的配置读取器、安全边界和引用案例复核。根选项被接受只解除一层阻塞，不代表后续命令或上游测试通过。

### 适用范围

- `libra -c <section[.subsection].variable>=<value> <command>`，仅在子命令之前识别；支持重复与拼接短形式。只切第一个 `=`，值可为空或以 `-` 开头。
- 单次调用的有序内存快照；同名最后一次覆盖持久 scope，不写配置库。section/variable ASCII 大小写不敏感，subsection 大小写敏感。
- 普通 `config` cascade 的精确读取和 `--default`；显式 scope 与不支持组合按 ADR-CFG-03。四个共享 scalar 入口（其中非严格入口另按调用点核对 fileMode 消费者）、一个逐个计数 fileMode reader 的接线卡和两个内部 aggregate 入口按 ADR-CFG-04。
- 参数碰撞、预扫描、并发与取消、sync worker、缓存、安全拒绝、诊断、merge driver 和 mergetool 的具名回归；同步 EN/zh、开发文档、兼容矩阵及真实网站 config 页。
- 依据公开双轨结果复核 78 个引用 TC，区分直接拒绝、前置级联和其它命令缺口；证据不足不伪造结果。

### 非目标

- 除 CO-30 的 `switch` 直接 reader 外，不接入绕过共享 cascade 的直接 DB、专用环境变量和 best-effort 读取点；按下表和 DEFER-CFG-01 逐 key/消费者公开边界，不声称普通 `checkout` 支持 TC-0409。
- 不实现 include/includeIf、隐式布尔 `-c key`、`GIT_CONFIG_*` 环境协议、`--c` 或 `--config`；不改变仓库 hash 格式或升级状态来源。桌面 `ui` 绕过 CLI future 和作用域，根 `-c` 与 `ui` 的组合按 CO-31 在启动窗口前明确拒绝。
- 不实现带 `-c` 的 `config` 多值/regexp/list 或 value-pattern、`--file` 组合；显式拒绝与完整视图归 DEFER-CFG-02。
- 不替其它 issue 完成 pull/rebase、reset、status 的 untracked cache、trailer、repack、rev-parse hidden refs、format-patch、D-layout 或错误文本等业务。
- 不修改 [`529.md`](529.md)、[`532.md`](532.md)、[`534.md`](534.md)、[`536.md`](536.md)、[`537.md`](537.md)、[`538.md`](538.md)、[`539.md`](539.md)；它们的既有 incoming 依赖保留，它们的关闭不是本计划完成条件。

## 已决议设计决策

### ADR-CFG-01：根 `-c` 的语法和位置

- **Status:** Proposed，待独立复审；未批准开工。
- **Context:** 六个子命令已占用本地 `-c`；原 `global=true` 设计不能保证 clap 可构造或保留局部语义。
- **Decision:** 根 `-c` 是非 `global=true` 的重复根参数，只在子命令前可用，例如 `libra -c a.b=x commit -c <commit>`。子命令之后的 `-c` 按该子命令既有定义解析；没有本地定义时仍拒绝。支持 `-c key=value`、`-ckey=value`、重复形式；`--`、非 UTF-8 参数和已有全局选项维持既有规则。共享扫描器在 `OsString` 序列上识别位置：根分离形式消费整个下一 token（即使该 operand 以 `-` 开头或非法），缺失不消费不存在的 token；拼接形式只消费自身。只在根位置生效，尊重真实子命令和 `--`，不得先丢弃非 UTF-8 token 再重建位置。所有已有预解析使用者、status 独立规范化、UI/telemetry 入口和两条 `main.rs` 错误输出路径复用该边界；业务解析仍按既有非 UTF-8 错误合同失败。独立位于 operand 之外的 `--json`/`--machine` 仍决定错误模式。`log` 的首次 clap 解析与位置恢复所用的第二次 clap 解析都须接受同一前置 `-c` argv，并保留 `-s`/`--no-patch` 与 diff 输出的既有顺序及冲突合同。
- key 有非空 section/variable，可有非空 subsection；section/variable 以 ASCII 字母开头，后续只允许字母、数字、`-`；subsection 不含控制字符并保留原大小写。只在第一个 `=` 切分；无等号、非法 key 和长别名为 `LBR-CLI-002`、129。value 保留空串、后续 `=`、空白和前导 `-`。同名最后一次生效。
- **Alternative:** 给 clap 根字段加 `global=true`：与现有本地短名冲突，拒绝。每个重写器各自扫描：拒绝。
- **Consequence / Revisit:** 子命令后根 `-c` 不受支持；文档给出前置写法。未来若需扩展位置，先设计冲突语义并另立评审。

### ADR-CFG-02：请求作用域、生命周期和保留键

- **Status:** Proposed，待独立复审；未批准开工。
- **Decision:** 覆盖快照由 `internal::config` 作为不可变、有序的请求值管理，用 Tokio task-local 绑定实际 CLI future，**不设进程全局 fallback**。未绑定的直接库调用、锁前 worker、无关 task 和线程看不到其它调用的覆盖；CLI 锁只保留其原职责。参考 `worktree_scope/context.rs` 的显式捕获/重绑模式，但不得复用其生产全局 fallback。
- `main.rs:642-652` 的裸 `ui` 在 CLI worker 之前启动且不进入 task-local 作用域；根 `-c` 与 `ui` 组合由 CO-31 在窗口启动前以固定、不含 value 的使用错误拒绝，库 dispatcher 也同样拒绝。无 `-c` 的 `ui` 不变；本版不承诺 GUI 继承覆盖。
- 在 argv 重写/可能产生诊断之前建立仅属于该调用的解析保护；完整验证后在 conversion retry、hook、operation、upgrade recovery、hash preflight 与命令副作用之前绑定快照。返回、错误、help、panic 或 future 取消时撤销租约。确需传播的 `spawn`/`spawn_blocking`/同步线程捕获同一可撤销租约并显式绑定；未显式绑定为无覆盖。不得给脱离调用生命周期的后台任务传入覆盖。撤销后新的读取不能再取得值；已经交给任务的普通字符串无法靠撤销擦除，因此此类任务必须有受控退出及不得持久化/继续输出的约束，取消测试覆盖该边界。
- 在任何仓库/命令副作用前，忽略 section/variable 的 ASCII 大小写，拒绝 `core.objectformat`、`upgrade.*`、`include.*`、`includeIf.*`、`auth.token.*`，以及 `is_sensitive_key` 或 `is_vault_internal_key` 判定的键。后两类以现有谓词为权威，包括 vault 内部键和私钥；测试覆盖大小写与 subsection，不创建第二份手写 secret 清单。提示分别指向仓库格式、upgrade、auth/vault 管理及 DEFER-CFG-03，不回显值。
- `src/utils/util.rs` 路径缓存：只要请求绑定覆盖就绕过已有缓存读和写，sync worker 显式重绑；无覆盖调用继续原缓存合同。连续“预热持久值 → 覆盖 → 无覆盖”不得漏读或污染。
- **Alternative:** 进程级 store 加 CLI 锁：不能约束直接 reader 和前置 worker，拒绝。允许明文 auth/vault 覆盖：绕过 owner，拒绝。

### ADR-CFG-03：`config` 精确读取与 #549

- **Status:** Proposed，待独立复审；未批准开工。
- **Decision:** 在 #549 CG-02 完成后，普通 cascade 精确 get（显式 `get`、隐藏 `--get`、普通裸读）按 command → local → global → system 选择，最后一次 override 胜出；present-empty 也是命中。`--default` 仅当没有命中时使用。显式 `--local`/`--global`/`--system` 只读取指定持久 scope；命令级值不写入任何 scope。`--show-origin` 标 `command line`、`--show-scope` 标 `command`，human/JSON/machine 语义一致。
- 带任意根 `-c` 的 `config get --all`、regexp/list、exact value-pattern、`--file` 均在任何读取、提示、输出或写入前以 129/`LBR-CLI-002` 拒绝；即使显式 scope 也拒绝这些组合。无 `-c` 不改原合同；正常 mutation 可执行，但不得持久化 override。显式 scope、typed/default 与拒绝顺序各有测试。
- 敏感 override 在 ADR-CFG-02 已拒绝。对没有敏感 override 的受保护裸键，保留 CG-02 的安全输入/拒绝顺序；裸敏感键带 `--default` 保留 CG-02 的拒绝，不误认普通裸读。CG-01 的 hyphen-leading 操作数规则不回退。
- **Alternative:** 在聚合结果末尾追加覆盖或对 `--file` 静默忽略：不能表达遮蔽、多值和来源，拒绝。

### ADR-CFG-04：共享读取器合同

- **Status:** Proposed，待独立复审；未批准开工。
- strict scalar 保留 command present-empty；非严格、decrypted、fresh 将 command 值按该入口现有 trim/empty 规则处理，空时按原路径回退，非空命中不额外读 DB/vault；`core.fileMode` 的每个入口调用必须按逐命令 census 接入，实际接入的每一个调用点可单独恢复，不能只接共享 helper 就声称全部命中调用点。local/global/system 的原有错误、future-schema 和 fresh Unusable 隔离不变；环境变量与显式业务旗标维持原优先级。
- prefix 保留现有 `config_key_has_prefix` **对整个 prefix ASCII 大小写不敏感**与 `BTreeSet` 原始字符串去重；只把匹配的 override 原始键插入该集合，不声称 subsection 大小写敏感的逻辑去重。真正的精确 key 身份仍按 ADR-CFG-01。
- subsection 按 subsection 原样区分大小写，先计算最后 override；持久行若被同名 override 遮蔽，必须在解密之前过滤。其余 subsection 维持 local/global/system 及错误策略，present-empty 保留。真实 merge driver 与 mergetool 消费者必须验证，不以 helper 单测代替。
- 直接 DB/env reader 不被隐含迁移；CO-30 明确接入 `switch` 的 `checkout.defaultRemote`，其余按上方 key/消费者表在用户文档逐项列出可能静默忽略的边界。若同一命令另有自己的业务缺口，记 DEFER-CFG-01/04。

### ADR-CFG-05：普通值诊断、受保护键与引用证据

- **Status:** Proposed，待独立复审；未批准开工。
- **Decision:** 普通、非保留 key 的 override 与该 key 的持久值采用同一诊断合同；现有 history、status、`config --type` 和非严格 reader 可以沿用非法值错误中回显普通值的行为，warning/tracing 也不承诺对普通值做来源追踪或脱敏。`-c` 的 value 会进入 argv、shell history 和进程列表，用户不得把秘密交给普通 key；该限制写入 EN/zh/开发文档和网站。稳定错误码、退出码和 human/JSON/machine 的结构不因 `-c` 改变。
- ADR-CFG-02 拒绝的保留键不同：原始 argv 扫描在 clap、业务读取、vault/auth、持久写入和命令日志前识别其**规范 key 而不输出 value**，只用固定 key 类别提示。该早退的 human/JSON/machine 输出、warning 和 tracing 均不得包含 value。`config` 的既有受保护裸键输入流程不得被普通裸读分支取代。
- **Alternative:** 对所有普通 override 做全链路脱敏需要追踪派生值、直接 stderr、全局 tracing 和脱离生命周期的任务；Issue 未提出该要求，现有源码也没有可证明的边界，本计划不伪称提供。仅替换原始字符串会漏掉转换后的值，同样拒绝。
- 78 个 TC 是公开复跑与归因范围。只有实质失败落在本计划已承诺行为时创建 FIX 并前滚；其它失败逐项归属，不设“全 PASS”假门。

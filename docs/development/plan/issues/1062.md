# Issue #1062：`eol=crlf` 属性下 `status`/`diff` 误报与 `merge`/`pull` 拒绝（2026-11-10）

> 模板 v2.16；来源 [libra-tools/libra#1062](https://github.com/libra-tools/libra/issues/1062)（2026-11-10T11:59:45Z 由 genedna 创建，OPEN，0 评论；正文即全部上报范围）。本文**只规划**：五张卡全部 `pending`、验收为空、未评审、未授权执行。文中所有事实锚点均为 2026-11-10 本机实测，未执行任何生产代码修改、未创建提交（除本文与 `plan-status.md` 登记）。

## 文档职责

### 适用范围

- 已被 `libra status` / `libra diff` / `libra diff-files` / `libra diff-index` 判为「已修改」，但工作区内容在应用 `.gitattributes` 的 `text`/`eol` 转换后与索引条目 blob 完全相同的路径。
- 由上述误报直接导致的 `libra merge` / `libra pull` 干净度预检拒绝（`LBR-CONFLICT-002`，`phase: merge`）。
- 属性层（`.gitattributes`、`.libra_attributes`、`info/attributes`、`core.attributesFile`）已正确解析的情形；属性解析本身不是本计划范围（`check-attr` 已正确，见事实基线）。
- 本计划只覆盖工作区↔索引的一侧判定；历史对象、传输、打包不在此范围。

### 非目标

- 不修改仓库内的 `install.ps1`、`template/pre-commit.ps1`：用户 2026-11-10 明确要求这两份误报文件保持原状（不在本计划任何卡的写集内）。
- 不引入新的属性解析器：`text`/`eol` 语义只以 `check-attr` 同一实现为权威（ADR-1062-02）。
- 不做 `core.safecrlf`、`core.autocrlf=input|true` 的完整 Git 兼容矩阵；后者如确需，按 DEFER-1062-02 另立计划。
- 不修复 `git-internal` 依赖内部的其它 `Index` 缺陷（`is_modified` 的 `unwrap()` 崩溃、`contains_dir_file` 的 `TODO` 等），仅登记（DEFER-1062-01）。
- 不涉及 `*.bat`/`*.cmd` 的独立行为：与 `*.ps1` 同属 `eol=crlf` 面，由同一修复覆盖，不单独立卡。

### 成功定义

在不改动上述两份模板文件的前提下：`libra status`、`libra diff`、`libra diff-files` 对「blob 归一化后相同」的 `eol=crlf` 路径报告干净；`libra merge`/`libra pull` 在该仓库状态下的干净度预检不再以 `LBR-CONFLICT-002` 拒绝；`libra add` 不会把纯 CRLF 差异写成一次内容提交。四类命令的证据均落在本计划文件内（v2.12：不新建证据目录）。

# Issue #1062：显式 text/eol 转换与工作区一致性修复计划（2026-11-10）

> 模板 v2.16；本次规范性改写：2026-11-10 14:33:27 UTC。来源 [#1062](https://github.com/libra-tools/libra/issues/1062)。用户已授权按本文顺序实施，5 张活动卡：I1062-01/02/03 in-progress / locally-accepted，其余 pending / 验收空；旧 I1062-04、I1062-05 保留为退役编号，不计完成数。交付方式见下文 EX-EOL-USER-01。

## 文档职责

消除显式 text/eol 规则下 CRLF 表示造成的伪差异，使 clean 写入、内容比较、状态输出和同步预检共用相同口径。先完成本计划的整体发布，再由 [#861 计划](861.md) 扩展 text=auto；两份计划分别关闭自己的验收集合。

### 适用范围

- 普通文件明确 text（可搭配 eol=lf/crlf），及仅设置 eol 且 text 未设置时的 Git 转换语义；显式 -text 优先。代表样本是 *.ps1 text eol=crlf，也覆盖同规则的 .bat/.cmd。
- add 正常暂存与 --renormalize 的显式转换输入；status 默认/scan/check-dirty 与 JSON/porcelain；diff 工作区侧及 diff-files/diff-index 的实际内容比较模式。
- merge/pull 使用同一干净度结论；真实改动与失败路径仍拒绝。无需改动 merge/pull 算法时只补调用链回归，不人为添加空实现卡。
- 共享状态判定的既有消费者 switch/checkout/rebase/am/commit/describe/stash 只随同一判定轴回归及同步文档，不扩展它们自己的算法。
- 每行为卡的测试、命令文档及网站同步，家族唯一版本发布与最后全量收口。

### 非目标

- text=auto 的文本探测、已有 CRLF 索引保护、TC-1324：由 issues/861.md 的 I861-01 承接，不能把本计划的显式 text PASS 当作它完成。
- core.autocrlf=true/input、core.safecrlf、working-tree-encoding、ident、自定义 clean/smudge 的完整兼容：DEFER-1062-02，未排期。本次 fixture 显式隔离配置；不能因改了 text 就声称完整 Git filter 支持。
- checkout/smudge 写回 CRLF、历史 blob 批量重写、git-internal 本体升版：不在默认修复范围。必要性由 I1062-01 判定，超界先修计划。
- 不通过改写两份真实 PowerShell 模板、reset --hard 或 stash 伪改动来“修复”。

### 成功定义

显式转换场景下，规范化工作区 bytes 与索引 blob 相等时，内容比较与 status 不再误报；正常 add 不制造额外内容变化，真实变化仍可见；merge/pull 干净度检查可用。plumbing 的默认 raw/stat-only 行为以固定 Git 对照为准，不承诺 stat 失配时所有模式都无输出。五张活动卡具备适用 A/B/C/D，最终全量通过，文档及网站交付后本计划可收口；无需等待 #861。

## 全局工程约束

继承模板 GC-01～GC-13、G-01～G-11、ER-01～ER-14。数据库/schema 为 N/A：不改迁移、全局或系统配置库。另有共同约束：

1. 唯一转换实现位于拟新增 src/utils/worktree_conversion.rs；使用现有属性解析语法及优先级，不新增另一套 parser。转换策略必须带仓库根、相对路径、文件类型及必要的索引上下文，禁止依赖 worker 的偶然 cwd。
2. 工作区原始字节、clean 后字节、索引 blob 三者分开。仅转换工作区输入，禁止把索引/HEAD 历史对象也归一化后掩盖真实差异；禁止以空白忽略选项替代 clean。
3. 现有原始读字节 API 不得被无差别改成 clean API，避免改变 checkout、外部驱动、快照及其它未知调用方。调用方显式选择转换模式；LFS pointer 与 symlink target 仍走原有专用分支。
4. 模式位、类型变化、冲突 stage、intent-to-add、skip-worktree、删除等独立状态不得被“内容相等”覆盖。新生产路径不得加入无说明的 unwrap/expect/panic；失败须提供路径与可操作上下文。
5. 保持 status 的 no-follow/beneath 根能力、每次 I/O deadline、子进程回收、io_blocked 分类和 hash-kind 传递。不得把原受限读取挪回主进程同步 I/O，或把属性/索引读取失败当作未设置属性/干净。
6. 所有测试在隔离 fixture 中运行，真实 install.ps1、template/pre-commit.ps1 不作为可写 fixture。Implementation write set 排除两文件；install.ps1 仅在 ER-08 发布写集内允许版本字段同步，保持换行及其它内容。旧稿“任何写集都禁止该文件”与版本面强制门相冲突，本次明确区分修复写集与发布写集；若实施时另有仍有效的逐字节冻结指令，先登记发布阻塞，不偷偷豁免版本 parity。

## 文档职责

本文把 Issue #667 收敛为一张可执行实现卡：未显式 `--sparse` 时，`add --chmod` 对 stage-0 skip-worktree 条目的拒绝不得改写索引；显式 `--sparse` 与普通非 sparse chmod 行为保持不变。

### 适用范围

- `src/command/add.rs` 中 sparse pathspec 判定、真实 `apply_chmod(..., false, ...)` 调用及索引保存前的原子性。
- `tests/command/add_test.rs` 的 TC-0052 回归，以及现有 sparse/`--chmod` 两侧回归。
- `docs/commands/add.md`、`docs/commands/zh-CN/add.md`、`docs/development/commands/add.md`、`COMPATIBILITY.md` 与网站 add 页的同卡同步。
- 独立 patch 发布、main 直推 ref 保护、三个 workflow 的 D 组收据与网站 `cf` 部署验证。

### 非目标

- `--chmod` 对 symlink/gitlink 的拒绝语义：已由 `plan-20260918.md#CH-01` 交付，本卡不重做。
- `add --sparse` 的其它交互、`sparse-view` 命令、`sparse-checkout` 子命令：不同命令轴，不在本卡扩张。

- `add --chmod=+x sparse_entry` 仍以退出码 1 和现有 sparse 诊断拒绝。

- `add --sparse --chmod=+x sparse_entry` 的既有显式 opt-out 合同保持通过。

## 已决议设计决策

### ADR-CHM-01: 拒绝合同不变，索引 mutation eligibility 前置收紧

- **Status:** Accepted
- **Context:** `validate_pathspecs` 已在任何真实 chmod 前识别只命中 stage-0 skip-worktree 条目的 pathspec，但 `run_add` 仍把原始 `PathspecSet` 交给真实 `apply_chmod`；后者从全部 tracked 文件重新匹配，先改 mode，外层之后才按 `sparse_paths` 返回 1。
- **Decision:** 未显式 `--sparse` 时，真实 chmod 候选必须排除 stage-0 skip-worktree 条目；输出层仍使用既有 `AddOutput::sparse_paths`、header/path/two hints 与退出码 1。显式 `--sparse` 时不作该排除。dense 候选与非普通文件拒绝继续按现有规则处理。
- **Alternatives considered:** 在 `render_add_output` 后恢复旧 mode：拒绝，因为保存/崩溃窗口仍可能留下半写且会复制索引事务逻辑；遇到任一 sparse pathspec 就提前返回：拒绝，因为同一次命令的 dense 候选可能有既有部分成功语义。
- **Consequences:** 真实 mutation 候选与 validation 的 sparse 定义必须共享；测试必须同时固定拒绝不变量与 `--sparse` opt-out。
- **Revisit when:** add 引入统一的事务式 candidate plan，或 sparse 判定不再由 stage-0 skip-worktree 位定义。

### ADR-CHM-02: 以 stage-0 sparse 判定作为单一事实源

- **Status:** Accepted
- **Context:** `AddOutput::sparse_paths` 的字段声明（`389-397`）没有判定能力；真正的 skip-worktree 集合与 sparse-only 判定在 `validate_pathspecs:2664-2675,2697-2723`，真正的非 dry-run 写入入口在 `run_add:2221-2227` / `apply_chmod:2314-2320`。若实现只在输出字段或 dry-run 调用附近加条件，TC-0052 仍会失败。
- **Decision:** 实现必须让 `2221-2227` 的真实 chmod 路径消费 `validate_pathspecs` 已建立的 stage-0 skip-worktree 事实（可传排除集合、允许候选集或等价的单一共享产物）；不得在 `apply_chmod` 内重新用未经 sparse 过滤的 `index.tracked_files() + PathspecSet` 决定全部真实候选。`--sparse` 的显式 opt-out 由同一产物携带，不能另写字符串/path 猜测。
- **Alternatives considered:** 从 `AddOutput::sparse_paths` 的原始 pathspec 字符串反推文件：拒绝，目录/glob/magic pathspec 会失真；在保存后比较并回滚：拒绝，恢复不是原子事务。
- **Consequences:** stage 必须固定为 0，blob OID、mode、skip-worktree 位和工作树 mode都成为验收不变量；候选过滤不得引入额外索引全量扫描。
- **Revisit when:** `ValidatedPathspecs` 被替换为包含逐路径动作的统一 add plan。

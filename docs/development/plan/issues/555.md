## 文档职责

本文处理 Issue #555 在当前 `main` 上仍成立的 `diff-tree` 与 Git 契约差异。目标是：支持单提交对父提交的默认比较及 commit id 头；支持 `--no-commit-id`；让 `--stat` 与 `-p` 按 Git 同时输出；转发 `--full-index` 到既有引擎；再用公开上游复跑结果区分本计划修复与 format-patch/am/reset/layout 的剩余阻塞。

### 适用范围

- `libra diff-tree <commit>`：恰有一个父提交时比较 `<parent>` 与 `<commit>`；root/merge 在未给 `--root`、`-m` 等父选择时保持 Git 默认空输出。
- 单提交形式的 commit id 头，以及 `-s` / `--quiet` 下头部与退出码的组合。
- `--no-commit-id` 在单提交与双 tree-ish 形式中的行为。

### 成功定义

- 非 root、非 merge 的单提交有匹配差异时默认先输出完整 commit id，再输出与 `diff-tree <parent> <commit>` 相同的 diff；无匹配差异、root 或 merge 的默认形式为空输出且退出 0；读取失败必须报错退出，不能退化为空成功。
- 单提交 `-s` 保留 commit id；`--quiet` 有差异时保留 commit id 并退出 1；结构化输出不混入人读头部。
- `--no-commit-id` 只去掉该头部，不改变 diff 体或退出码；双 tree-ish 形式接受该选项且输出不变。
- `--stat` 单独输出 diffstat；`--stat -p` 先输出 diffstat、一个空行，再输出 patch；issue 点名的 `--no-commit-id --stat -p <commit>` 可生成 patch fixture。
- `--full-index` 让 patch `index` 行使用完整前后对象 id，raw 与 JSON schema 不变。
- 每项行为有具名新用例；EN、zh-CN、网站、开发文档与 `COMPATIBILITY.md:228` 同卡同步。
- 四张实现卡各自完成独立 `patch` 发布（DTR-01 连同原 DTR-06 的边界同卡发布）；DTR-05 取得钉版上游复跑并按实际结果记录 DEP-DTR-04/05 的剩余阻塞，缺证据时保持 blocked；CLOSE-555 全绿。

## 已决议设计决策

实现时若需偏离本节，必须先修订本计划并重新评审，不得在代码中静默改变语义。

### ADR-DTR-01：以后写评论和当前 main 定范围，不承诺级联用例自动通过

- **Status:** Accepted
- **Context:** 当前源码已接受 `-s` / `-c`；后续评论证明 `--no-commit-id`、单提交、`--stat`、`--full-index` 是剩余直接缺口，同时也列出 format-patch/am/reset/layout 依赖。
- **Decision:** 实现 GAP-01..04；combined 渲染与未要求选项延后。DTR-05 只按新公开结果判断用例，不能用“diff-tree 卡完成”替代 t4150/t4103 结论。
- **Alternatives considered:** 重复实现 `-s` / `-c` 无意义；把 format-patch/am/reset 一并纳入会形成多命令巨型计划。
- **Consequences:** #555 可因 DEFER-DTR-01 或其它 issue 的引用用例继续保持 OPEN。
- **Revisit when:** 新评论改变根因归属，或 529/536/547 与布局决策交付后。

### ADR-DTR-02：单提交解析与 commit id 头接入共享渲染

- **Status:** Accepted
- **Context:** `tree_b` 必填；P-DTR-01/04/05 证明单提交不仅有 parent diff，还有头部、quiet 和 root/merge 规则。wrapper 直接打印会绕过 pager，并遇到 `plumbing_quiet` / 空 body 的提前返回。
- **Decision:**
  - `tree_b` 改为可选；缺省时把 `tree_a` 解析为 commit。恰有一个 parent 时合成 `--old <parent> --new <commit>`；root 或无父选择的 merge 直接按 Git 默认返回空成功，不隐式实现 `--root` / `-m`。
  - 在 `DiffArgs` 增加隐藏 `plumbing_commit_id: Option<String>`，由 wrapper 注入。共享渲染器仅在过滤后存在匹配差异时为人读输出前置 `<oid>\n`；此时即使 `no_patch` 的 body 为空仍输出头部。无差异（含路径过滤掉全部差异）则无头部（P-DTR-07）。
  - `plumbing_quiet` 的人读单提交形式输出头部后按差异返回 0/1；`--json` / `--machine` 不增加字段、不输出人读头部，并保持既有 plumbing quiet 的结构化静默约定。
  - 无效 revision、commit/tree 读取失败沿用 `DiffError::InvalidRevision` / `ObjectLoad`，不得把 root/merge 默认空输出用于读取失败。
- **Alternatives considered:** wrapper `println!` 会绕过 pager/JSON 且在 quiet 下错误；只支持两树并要求用户手写 parent 不能关闭 issue 的点名命令。
- **Consequences:** 单提交成为公开形式，但 `--root`、merge 父选择与 combined 渲染仍明确延后。
- **Revisit when:** 实现 `--root`、`-m` 或完整 combined diff 时。

### ADR-DTR-03：`--no-commit-id` 只抑制头部

- **Status:** Accepted
- **Context:** P-DTR-02 证明该选项不改变 diff 体；双树没有头部但接受选项。
- **Decision:** wrapper 接受 `no_commit_id`；单提交时不注入隐藏头部，双树不注入且不改变输出。`-s` / `--quiet` 的退出码、stat+patch 和 full-index 与该选项正交。
- **Alternatives considered:** 在最终字符串中删除第一行会误删用户 patch 内容且污染 JSON；让该选项暗示 no-patch 与 Git 不符。
- **Consequences:** issue 的 `--no-commit-id --stat -p <commit>` 由 DTR-02 与本卡共同使能，完整组合由 DTR-03 验收。
- **Revisit when:** 未来机器输出 schema 显式加入 commit 元数据时；本计划不做。

### ADR-DTR-04：stat 与显式 patch 一次计算、按序组合

- **Status:** Accepted
- **Context:** 共享引擎已有 diffstat，但 `stat` 当前抑制 patch；P-DTR-03 要求 diffstat、空行、patch。
- **Decision:**
  - `DiffTreeArgs` 增加 `stat` 并转发；stat 单独存在时不再由 wrapper 默认追加 raw。
  - 复用/引入隐藏 `plumbing_patch`，表示“显式 patch 与 raw/stat 并存”。`stat && plumbing_patch` 在一次 `run_diff` 后渲染 `diffstat + "\n\n" + patch`；`patch_body_is_shown` 对该隐藏组合返回 true。
  - 隐藏标记只由 plumbing wrapper 注入，porcelain `diff --stat` 保持现状。#544 拟议由 DFF-04 统一交付该标记及其驱动、结构化隔离，尚未确认；两稿稳定后协调者核对实际契约。若对方先交付且满足本卡语义则复用并验证，不新建第二份组合 helper。
  - JSON 不拼接文本；`--no-commit-id` 只控制 ADR-DTR-03 的头部。
- **Alternatives considered:** 只转发 `--stat` 会丢失 patch；运行两次引擎会重复对象和工作树 I/O，并造成 pager/JSON 不一致。
- **Consequences:** `diff-tree --stat -p` 与 issue 点名命令具备 Git 顺序；`--stat --raw` 等未要求组合不扩展。
- **Revisit when:** 共享渲染器正式建模多输出模式时。

### ADR-DTR-05：`--full-index` 只做定向转发

- **Status:** Accepted
- **Context:** 共享引擎已实现 `--full-index` 的 patch index 行改写，且有既有行为测试；第 21 条评论把 diff-tree 的该选项列为 t4103 setup 的直接缺口，但 setup 中其它选项的具体失败尚未在钉版复跑前确认。
- **Decision:** 在 `DiffTreeArgs` 增加 `full_index` 并在合成 argv 追加 `--full-index`；不改变 raw、rename、exit-code 或 JSON 规则，不顺带开放 `--binary` 等其它选项。
- **Alternatives considered:** 在 plumbing 内重写 index 行会复制引擎逻辑；开放整个 porcelain flag surface 超出 issue。
- **Consequences:** 只能声称本卡使 `diff-tree --full-index` 可用并闭合该单一选项缺口；t4103 的 TC-3096/3097 与 `apply` 后续行为必须由 DTR-05 钉版复跑重新判定，本卡不预先宣布 setup 全绿。
- **Revisit when:** 有新 issue 要求更多 diff 选项时。

## 全局工程约束

- **GC-DTR-01 单一引擎与输出事实源：** 必须继续经 `delegate_to_diff` / `command::diff::execute_safe`。commit id 与 stat+patch 在共享渲染器组合，不得复制 diff 计算、运行两次引擎或在 wrapper 直接 `println!`。
- - **GC-DTR-02 公开与隐藏表面分离：** `plumbing_commit_id` / `plumbing_patch` 只供合成 argv，不出现在公开 `diff --help`。新增 diff-tree 选项同步 `DIFF_TREE_EXAMPLES`（本卡必需示例必须包括）和本计划列出的全部文档。DTR-02 的 `DIFF_TREE_EXAMPLES` 必须增加 `libra diff-tree <commit> --no-commit-id` 或等效示例；其余新增选项同步同表。
- **GC-DTR-03 只读与安全：** 不写 refs、HEAD、index、对象库或 SQLite；数据库角色全部 `N/A`。对象读取失败 fail-closed，不新增裸 `unwrap()` / `expect()` / `panic!()`。
- **GC-DTR-04 矩阵与账本：** `COMPATIBILITY.md:228` 只原地改写，文件总行数不变；其它行不属于写集。执行 `compat_ledger_schema` 与 `compat_matrix_alignment`。
- **GC-DTR-05 同卡文档：** 每个实现卡逐文件交付 EN、zh-CN、开发文档、网站页与矩阵。2026-11-08 本次只读核对：`../libra-backend` 是原生 `.libra`、无 `.git`，`libra status --short --branch` 为干净的 `cf...origin/cf`；`--check --only diff-tree` 退出 0、无漂移。这只是当前快照，不代替执行时重新核查，亦不表示未来卡的文档已交付。网站写入前按 ER-06a 重新识别 VCS，确认唯一元数据及干净、正确的 `cf`，以单一写者持有互斥窗口；检查 origin/cf 和本地待推提交，不能夹带无关提交。
  - **原生 Libra `cf`：** 在后端根目录先 `python3 scripts/sync-libra-command-docs.py --libra-root /mnt/data/gitmono/libra --check --only diff-tree`（1 为待同步漂移，2 为错误，须分别处理），核对 drift；然后同参数改为 `--write`，再 `--check --only diff-tree` 必须退出 0。执行时将绝对路径替换为实际 Libra 源码树，须绑定本卡最终源码与文档树。脚本要求 `cf` 且拒绝 `.git`；提交前核其他漂移与写集，不扩大同步范围。
  - **Git `cf` 干净但存在无关超前提交：** 严格执行模板 ER-06a 的 origin、fetch、远端 SHA、无关提交与全新 `cf` 隔离克隆核验；**不得使用脚本 `--write`**（`scripts/sync-libra-command-docs.py:273-279` 明确拒绝 `.git`）。下方方法以隔离克隆中的脚本为只读生成器，只替换 `diff-tree.en.md` 并以同脚本的 `--check` 证明字节等价；若后端实际规则不允许该路径、脚本版本/页面布局不匹配或任一校验失败，停止且此卡网站交付 blocked，不修改脚本或原相邻工作区。

  ```bash
  # 执行前按 ER-06a 验证隔离克隆在 cf，HEAD 等于记录的 origin/cf SHA。
  # 两个变量必须是已核验的绝对路径，LIBRA_DOC_ROOT 指本卡最终源码树。
  python3 -I - "$LIBRA_DOC_ROOT" "$BACKEND_CF_CLONE" <<'PY'
  import hashlib
  import importlib.util
  import os
  from pathlib import Path
  import sys
  import tempfile

  source, backend = map(Path, sys.argv[1:])
  if not source.is_absolute() or not backend.is_absolute():
      raise SystemExit('absolute source and backend paths required')
  script = backend / 'scripts/sync-libra-command-docs.py'
  spec = importlib.util.spec_from_file_location('command_doc_sync', script)
  if spec is None or spec.loader is None:
      raise SystemExit('cannot load reviewed sync script')
  sync = importlib.util.module_from_spec(spec)
  spec.loader.exec_module(sync)
  report = sync.synchronize(source, backend, False, 'libra', {'diff-tree'})
  directory = backend / 'apps/tanstack-app/content/docs/commands'
  target = directory / 'diff-tree.en.md'
  original = sync.regular(target)
  source_path = source / 'docs/commands/diff-tree.md'
  body = sync.regular(source_path)
  cli = sync.regular(source / 'src/cli.rs')
  names = {c['name'] for c in sync.parse_root_commands(cli.decode())}
  existing = {p.name.rsplit('.en.', 1)[0] for p in directory.iterdir()
              if p.name.endswith(('.en.md', '.en.mdx'))}
  guides = {n for n in ('repository-hooks', 'send-email')
            if (source / f'docs/commands/{n}.md').exists()}
  available = (existing - ({'gc', 'prune', 'stats'} - names)) | names | guides | {'index'}
  new = (sync.frontmatter('diff-tree', original.decode()) +
         sync.rewrite_body('docs/commands/diff-tree.md', body.decode(), available, source)).encode()
  drift = report['drift']
  if new != original:
      if len(drift) != 1 or drift[0]['path'] != str(target.relative_to(backend)) or \
         drift[0]['after_sha256'] != hashlib.sha256(new).hexdigest():
          raise SystemExit('unexpected drift or generated hash')
      if sync.regular(target) != original or sync.regular(source_path) != body or \
         sync.regular(source / 'src/cli.rs') != cli:
          raise SystemExit('input changed; repeat verification')
      fd, name = tempfile.mkstemp(prefix='.libra-doc-sync-', dir=directory)
      try:
          with os.fdopen(fd, 'wb') as out:
              os.fchmod(out.fileno(), target.stat().st_mode & 0o777)
              out.write(new)
          os.replace(name, target)
      finally:
          if os.path.exists(name):
              os.unlink(name)
  elif drift:
      raise SystemExit('unexpected drift')
  if sync.synchronize(source, backend, False, 'libra', {'diff-tree'})['drift']:
      raise SystemExit('post-write drift')
  print('diff-tree synchronized, sha256=' + hashlib.sha256(new).hexdigest())
  PY
  ```

#### Verification 判定口径

- 以下每个具名测试均为 `command_test::command::diff_plumbing_test::<test_fn> (new)`，加入现有 target，不新建 target；`tests/INDEX.md`、`Cargo.toml [[test]]`、`tests/compat/README.md` 为 `N/A`。每项 VER 是一次可复制的精确执行，不以集合列举证明实际运行。
- 在同一 `bash` 会话按 GC-DTR-06 准备 no-JUnit 配置后定义以下函数。本计划不接受单条精确 OR 表达式。`exact_new` 必须用带 `=:<完整测试路径>` 的精确匹配执行；Verification 表把每条 AC 绑定到一个或多个测试门，并为每个独立执行命令另记一门。独立 AC 门与独立执行命令门的分子允许不同，VER 只数后者。

```bash
exact_new() {
  test "$#" = 1
  ( source .env.test && cargo nextest run --config-file "$NEXTEST_NOJUNIT_CFG" --profile default --test command_test --no-tests=fail -E "test(=$1)" )
}
```

每执行一条命令，必须在本计划「实施证据汇总」逐项记录 UTC、完整命令、发现集合、实际执行 1 个、ignored 0、passed 1 和失败 0；任一项不符即整卡失败。测试函数内部可以包含多个断言，但 Verification 只能按真实执行命令计数，不能按 AC 数或测试内部断言数膨胀。

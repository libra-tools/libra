## 文档职责

本计划修复“本地 SSH 因公钥认证被拒绝、未收到 Git advertisement，却先报 pkt-line 协议损坏”的诊断；交付固定且可操作的认证错误、离线回归测试和从零配置 SSH 的网站说明。本文只规划，不宣称实现或发布完成。每次推进任务卡都必须在同一变更中更新 [`plan-status.md`](../plan-status.md) 的卡片状态、版本/commit 和日期。

### 适用范围

- SSH 引用发现路径及其 `clone`、`fetch`、`pull`、`push`、`ls-remote`、在线 `remote show/update/prune/set-head --auto/add -f` 用户错误边界；适用命令的 human、`--json`、`--machine` 输出。
- 英文/中文命令文档、网站对应英文命令页、开发文档、兼容矩阵和错误码说明。
- 本地假 SSH 子进程、现有 `command_test` 与库测试；一次 patch 发布切片和收口全量门。

### 非目标

- 不自动生成/上传密钥，不代用户改 `~/.ssh/config`、`known_hosts` 或代理状态；`BatchMode=yes` 保持。
- 不解决 #560 的首次 host-key 交互确认，不修改 HTTPS/`git://` pkt-line 分类。
- 不把任意 stderr 原文写入终端、JSON、machine 或 debug 日志；#577 的“原文 debug”建议不采用，原因是 SSH/远端诊断并非恒定无敏感内容。
- 不承诺单凭 SSH 退出 255 就能判断“机器没有密钥”；只能报告可观测到的公钥认证拒绝，并给出检查密钥、agent、账号和仓库权限的步骤。
- `maintenance prefetch` 是聚合多远端结果的维护任务，不在本卡的逐命令稳定错误码契约内；其底层 fetch 会获得固定诊断，但聚合报告是否需要认证专用稳定码另立问题处理。

### 成功定义

- `Permission denied (publickey)` 且符合本地失败前置条件时，六个命令表面的错误以 SSH 公钥认证失败为首要原因，不再显示“incomplete four-byte header”或协议代理 hint；稳定错误码选用既有 `LBR-AUTH-002`，退出 128，clone 给出结构化修复 hint。
- 真正的畸形/截断 pkt-line、host-key 未确认/变化、无诊断的 SSH 255、退出码非 255 等继续按原契约失败；无原始 stderr 泄露。
- 从零配置的用户能在网站 Getting Started 的独立 SSH 指南完成生成/登记密钥、加载 agent、验证连接，并理解 Libra 自带 vault SSH key 与 `BatchMode=yes`；六个命令页同步新的错误语义，SSH hint 指向指南。
- SA-02 与 SA-01 均达到 `done/complete`、C/D 门及最终全量收口门均有证据，才能将计划标完成。

## 已决议设计决策

### ADR-SA-01: 认证信号与错误契约

在 **必需 advertisement 的首个 pkt-line header 发生零字节 EOF**、SSH 直接子进程 **退出 255**、**未观察到 stdout**、有界 stderr 中存在完整的 `Permission denied (<method-list>)` 诊断且括号内有独立 `publickey` 方法 token 时，先于通用 pkt-line 包装产出带类型的认证失败。允许合法 `user@host:` 前缀、方法顺序变化（如 `gssapi-keyex,gssapi-with-mic,publickey`）以及诊断句末的其它文字；不能把这些其它文字复制到输出。拒绝“Permission denied”泛匹配、`publickey` 相似词、stdout 已发广告和非 255 状态。host-key 改变/未确认的专门分类优先。固定消息如 `SSH public-key authentication failed: Permission denied (publickey)`；消息不得推断“无密钥”。**这是诊断启发式，不是可信的认证证明**：本地 ssh stderr 可能混入远端 pre-auth banner 或远端命令 stderr，远端也可能退出 255 并伪造同一行；测试只能证明前置条件、近似词排除和输出保密，不能声称识别文本来源。分类仅在 discovery 入口生效；`fetch_objects`/`send_pack` 的后续 SSH spawn 即使出现相似 stderr，也保持原错误映射，必要时给共享 read wrapper 传明确 phase 以免扩大范围。分类结果使用专门的 `SshPublicKeyAuthenticationFailed` IO error 类型作为本地 carrier，`ssh_discovery_read_error` 将其保留在 `GitError::IOError` 中；各命令必须在 `is_pkt_line_io_error` 和通用 `IOError` 分支**之前**按类型 downcast，认证错误的 Display 不得以 `PKT_LINE_PROTOCOL_ERROR_PREFIX` 开头。`push` 必须增加专门错误变体，不能复用映射 AUTH-001 的 `PushError::AuthenticationFailed`；在线 `remote show/set-head --auto` 必须在 `src/command/remote.rs` 保留类型至 `RemoteError`/CLI 映射，不能先 stringify 成普通 `Discovery`；`remote update/prune/add -f` 经过 fetch 的错误映射也须核到 AUTH-002。统一映射既有 `AuthPermissionDenied` (`LBR-AUTH-002`, exit 128)。禁止用 `NetworkError(String)` 前缀或一般文本猜测认证类别；`finish_ssh_read_result` 的 cleanup warning 也不得抹掉该类型。选择 AUTH-002 而非 AUTH-001 的原因是观测到了远端拒绝，但无法证明缺少凭据；同卡将 `src/utils/error.rs` 的 AUTH-002 描述改为“远端拒绝认证或授权，具体原因未证实”，同步错误码表。SSH 专用 hint 要同时检查 Libra vault 远端密钥与普通 agent/密钥/仓库授权；HTTP 401 的原 hint 不变。现有非认证场景 stable code 不变。

### ADR-SA-02: stderr 保密与网站引导

分类器只从已捕获的最多 64 KiB 中读特征，不直接输出原文；human、JSON、machine、debug 均仅包含固定文案或现有元数据。SSH 专用固定 hint 为 `Check the public key selected by Libra (libra config list --ssh-keys), your SSH agent, and repository access. Setup: https://libra.tools/en/docs/getting-started/ssh`；各输出模式只允许结构化呈现同一字面值。命令文档需说明该分类是可伪造的诊断启发式。SA-02 的网站 Getting Started 独立指南提供从零设置流程并链接托管方权威文档；macOS 的 `UseKeychain` / `ssh-add --apple-use-keychain` 仅作为平台条件步骤；说明 Libra `config generate-ssh-key --remote` 的 vault key 优先于普通 agent/默认 key，须把实际使用的公钥登记到托管方。先通过可信来源核对主机指纹，不推荐关闭 host-key 检查。SA-01 的六个网站命令页同步新的错误语义；命令运行时 SSH hint 指向独立指南。

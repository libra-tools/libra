## 设计决策

- **ADR-AR-01**：commit/branch/tag→commit 取 commit 树与 committer time；tree/tag→tree/`REV:path` 按实际来源取树，非 commit 默认只在单次命令的解析阶段取样一次，并贯穿全部 writer 与 remote 影子路径，`--mtime` 优先；不得在 writer/remote 子路径重复取样；blob、缺失对象/subtree 返回可操作错误。ZIP 不可表示时间沿现有 1980 下限。AR-01 同卡交付全部 tree 来源的解析及时间，不公开半成品。
- **ADR-AR-02**：空结果必须先区分已解析空树、匹配后 export-ignore 全排除、无匹配及 unborn；四类分别以显式来源标记（例如 `EmptySource::ResolvedEmptyTree`、`ExportIgnoredAll`）贯穿 `create_archive`，commit-sourced/plain tar 走 pax-only、裸树/其他已解析空树走 10240 零字节、ZIP 走空目录集，不得以 `entries.is_empty()` 单条件混判；prefix、压缩 tar 和 ZIP 均按对应 fixture，同卡覆盖 stdout/文件错误。只有整个 AR-02 齐全才能解除 guard。
- **ADR-AR-03**：唯一 `OsString` archive 原始 argv 投影贯穿 clap 与 handler，按出现顺序记录 prefix、extra-file、虚拟文件与压缩级别，不复制平行扫描器。archive argv 的逐项矩阵为：功能短选项只有 `-l/--list`、`-v/--verbose`，均不取分离值，不可把后面的 token 误读为其值；确定性判定为：`--list` 模式下，布尔后出现任何位置参数（包括 `-l blah`、`--list blah`、`-l -0`）都以参数错误拒绝；非 list 模式下，布尔后第一个非选项 token 必须能解析为 treeish，裸 `-v HEAD`、裸 `--verbose HEAD` 视为合法 treeish；若该 token 又同时是已识别的 archive 选项，则为用法错误，不得当 treeish 或值；-l/-v 本身永不消费后继分离值；值取向短选项只有 `-f/--format`、`-o/--output`，均接受 `--format=VALUE`/`--output=VALUE`、分离值、`-fVALUE`/`-oVALUE` 附值形式（例如真实 argv `-ffmt` 若要验证附值，必须先通过 `ArchiveFormat::parse_strict` 的严格格式校验（`fmt` 不是受支持格式，必须失败，不得写出归档）；合法附值示例为 `-ftar.gz`、`-oFILE` 必须进入投影并由公开 CLI 落盘/入归档验证），其中 `-ffmt` 仅用于失败路径核查；值取向长选项包括 `--prefix`、`--add-file`、`--add-virtual-file`、`--mtime`、`--compression-level`（`0..9`）、`--remote`，以及 AR-03 所需的有序 `--prefix` / `--add-file` 交错，均接受 `--name=value` 与分离值；`--add-file` 的重复形式及 virtual-file 不使用短附值推测。所有接收值的选项都必须先消费其值，再判断值中的 `-0`/`--` 是否为终止符或数字级别；普通 `--` 与 archive 局部 `--end-of-options` 之后才是位置参数。未知选项、缺失必需分离值、附值为可选未知或 `-0..-9` 的非法数字值，均沿 clap 原有错误路径 fail-closed，不得猜测吞掉后续参数；`-l`/`-v` 误取分离值、`-o`/`-f` 附值未接线、值中的 `-0` 误判为数字级别、值中的 `--` 误判为终止符均是独立可判定失败。保留非 UTF-8，其他命令不变。真实 CLI 和投影两层均验证。
- **ADR-AR-04**：虚拟文件不带引号按首个冒号分割；以双引号开头的路径按 Git C-style 解码，闭引号后须紧接冒号；空名、未闭引号、缺冒号及绝对/逃逸路径拒绝。虚拟内容不读工作树。
- **ADR-AR-05**：`-0..-9` 与 Libra 的 `--compression-level` 混用时按原 argv 最后值生效；ZIP 0 Stored、1..9 Deflated，plain tar 忽略，bzip2 0 映射 1。`--remote=.` 仅当前仓库，remote 与两种 extra-file 互斥；其它 remote 显式不支持。Git 本身无该 Libra 长选项，混用规则是本计划明确的 Libra 契约。
- **ADR-AR-06-date**：共享 `parse_date` 新增 `%Y-%m-%dT%H:%M:%S%z` 分支同时影响 `log --since/--until` 与 `archive --mtime`；仅允许新增 T-basic-offset 接受面，禁止改动既有空间分隔与冒号偏移结果；回归边界以 `internal::log::date_parser::tests` 与 log 命令相关测试为 A 组必跑。
- **ADR-AR-06**：无仓库 list 只列 `tar/tgz/tar.gz/zip` 且不建库；仓库内只读 repository config，保留大小写、去重且有 command 才列；remote 只列 `remote=true`。无值/无效配置及读取错误失败且无部分输出；绝不执行 command 或触发 global migration。global/system 投影在 DEFER-AR-14。

**测试运行证据与日志。** 每个 exact `test(=...)` 都必须证明实际跑过且只跑一次：`--no-tests=fail` + 清单计数不能替代输出。RUN 记录必须保存 JUnit XML 与可读日志，以 `cargo nextest run --junit <file.xml>` 生成；JUnit 的该 `testcase` 须且只出现一次、`failures=0`/`errors=0`/`skipped=0`，其 `testsuite` 须 `tests=1/passed=1/failed=0/skipped=0` 且 `NEXTEST_EXIT=0`；日志字段包括 executor、exact filter、1 passed、0 failed/skipped/ignored。env-gate skip（如 `.env.live-test` 缺失使 L2/L3 门不满足）导致 testcase 缺失或 `skipped>0` 时记 remote-pending/blocked，不得改写为 passed。`cargo test --all` 若只诊断，仍须触发 `FLAKY` 明示；不可断言 “skipped=0” 而实际上该 env gate 本来要求 skip 的测试已被过滤。`--retries 2` 下 `FLAKY` 必须记录 `FLAKY` 与最终通过/失败记录；FLAKY 本身可通过但执行人须准确记录。双环境运行须完整保留原始日志片段。

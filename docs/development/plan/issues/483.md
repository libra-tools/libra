## 文档职责

本文解决 issue #483：`libra count-objects` 完全缺失，导致 Git 黑盒用例（`t2200-add-update.sh` 的 TC-0011 等）无法表达「被测命令没有写入任何对象」这一断言。目标是交付与 Git 对齐的 `libra count-objects [-v] [-H]`，并让它真正断言得住——修复本计划核对时实测发现的缺陷：多个 `--dry-run` / `-n` 预览命令在 Libra 中**会写入对象**。

本文只规划任务，不宣称实现完成。落地时每个任务都必须先刷新源码锚点，再按任务卡验收。

### 适用范围

- 新命令 `libra count-objects`：无参数形式、`-H/--human-readable`、`-v/--verbose`，以及 `--json` / `--machine` 机器接口。
- 松散对象目录、pack 目录、`objects/info/alternates` 的只读清点；不改变任何存储格式。
- `src/cli.rs` 中央操作 census（`operation_class_for_command`）对预览调用的分类：`add -n`、`rm --dry-run`、`clean -n`、`mv -n`、`reflog expire --dry-run`、`alternates prune --dry-run`、`cache evict --dry-run`。
- 同步：`docs/commands/` EN + zh-CN、`docs/development/commands/`、三处命令索引 README、`COMPATIBILITY.md`、help EXAMPLES、`../libra-backend` 网站文档、测试索引与 compat 守卫。

### 非目标

- `libra gc` / `prune-packed` 命令（#385、#481）：`count-objects -v` 会报告 `prune-packable`，但本计划不提供清理命令（DEFER-01）。
- #481 的 P1「repack 后短 SHA 被判 ambiguous」（`LocalStorage::search` 未去重）：本计划不改 `search`，且 `count-objects` 禁止复用它（DEFER-02）。
- 真实变更命令（`add`、`add --refresh`、`commit` 等）写入 Operation Log v2 快照对象：这是 Libra 有意的操作日志设计，不在本计划改变；只在 `count-objects` 文档说明其对计数的影响（ADR-CO-03）。
- Git `report_linked_checkout_garbage` 在 Libra linked worktree 布局下的对应物（DEFER-04）。
- 统计 tiered 存储远端层（S3/R2）中的对象。
- 把 `gc` / `cache evict` 的松散对象枚举迁移到本计划的新扫描器（DEFER-06）；修改热路径 `LocalStorage::read_idx` 的查找算法（DEFER-05）。

### 成功定义

- `libra count-objects` 在非裸仓库、裸仓库、linked worktree 中 exit 0；`-v` 按 Git 字段名与顺序输出 `count/size/in-pack/packs/size-pack/prune-packable/garbage/size-garbage`，其后是 `alternate:` 行；`-H` 输出 Git humanise 格式。
- `count-objects` 本身零写入：不创建或重建 `.idx`，不记录 operation，不取维护锁，不做 schema 迁移。
- 移植 TC-0011：`add -n -u` 前后 `count-objects -v` 输出逐字节相等，`ls-files -s check top` 相等，且仍报告 `check` 的 add 与 `top` 的 remove 候选；同一不变式对本计划列出的全部预览形态成立，并有守卫防止新预览 flag 回归。
- 四张卡各自完成 C 组发布（`patch + 1` + `gh` 触发 `release.yml`）并取得 D 组证据，然后全量收口门全绿。满足这些之后，本计划才可标记完成。

### ADR-CO-01: Git 语义参照与判据矩阵

- **Status:** Accepted
- **Context:** issue 要求 Git 字段名与顺序精确一致；`size` 等数值依赖文件系统，不能用固定 golden 文件比对。
- **Decision:** 语义以 issue pin git@`1630431f32` 源码为准（事实基线逐行锚定）；凡声明「与 Git 一致」的行，开工时必须用 `/usr/bin/git`（或同等版本）在相同 fixture 上实跑对照，并把 sanitized 结果写入 `LIBRA_TEST_SCRATCH_DIR`。自动化测试不调用系统 git，期望值由测试按下列矩阵现算（`size` 取 `metadata.blocks() * 512`，非 Unix 取 `len()`）。矩阵是各卡 AC 引用的**判据规范**，每行都必须有对应测试用例：

  **M-FMT（文本格式）**

  | 行 | 调用 / 输入 | 期望 |
  |---|---|---|
  | F1 | 空库 `count-objects` | `0 objects, 0 kilobytes` |
  | F2 | L 个松散对象、共占 B 字节 | `L objects, ⌊B/1024⌋ kilobytes` |
  | F3 | `-H`，B ∈ {0, 1, 1024, 1025, 1048577, 1073741825} | `0 bytes` / `1 byte` / `1024 bytes` / `1.00 KiB` / `1.00 MiB` / `1.00 GiB`（逐字复刻 `strbuf.c:873-907`：KiB/MiB 先加进位常数，GiB 截断） |
  | F4 | `-v` | 8 行 `key: value`，顺序为 `count, size, in-pack, packs, size-pack, prune-packable, garbage, size-garbage`；其后 0..n 行 `alternate: ` |
  | F5 | `-vH` | `size`、`size-pack`、`size-garbage` 用 F3 格式，其余字段为整数 |

  **M-LOOSE（松散对象判定）**

  | 行 | 输入 | 期望 |

  | L1 | `objects/<2 位小写十六进制>/<hexsz-2 位十六进制>` 的普通文件 | 计入 `count`；`size` 按上文口径累加 |

### ADR-CO-02: 只读命令接线与禁止复用的路径

- **Status:** Accepted
- **Context:** GAP-07：既有 pack 读取会重建 idx，既有松散枚举不报告 garbage；新命令必须严格只读。
- **Decision:**
  1. 在 `command_scope` 中归为 `CommandScope::ReadOnly`（因此 class 为 `ReadOnly`，不进入 operation 边界，不持维护锁）。
  2. 预检沿用 `verify-pack` 的 `repo_hash_kind_without_schema_guard`（不迁移 schema）；仓库外由 `execute_safe` 返回 `CliError::repo_not_found()`。
  3. 在 `src/command/count_objects.rs` 实现 Git 语义的只读扫描器（按 M-LOOSE/M-GARBAGE 分类）。
  4. 在 `src/utils/storage/local.rs` 暴露建立在 `read_idx_fanout` 之上的只读 helper：`pack_index_object_count(idx)`，以及 fanout 桶内二分查找的 `pack_index_contains(idx, oid)`。不改变 `read_idx` 本身。
  5. **禁止**调用 `list_all_idx`、`search`、`list_loose_objects`、`ClientStorage` 的远端回退路径。
  6. hexsz 取 `get_hash_kind().size() * 2`。
- **Alternatives considered:** 复用 `list_all_idx`——会写 idx，违反零写入，拒绝。复用 `verify_pack_index::parse_index`——需解析整个 idx，prune-packable 的内存为 O(packed)，拒绝。直接改 `read_idx` 为二分查找——触及所有对象读取热路径，风险超出本 issue，记为 DEFER-05。
- **Consequences:** 仓库里暂时存在「Git 语义扫描器」与「gc/evict 枚举」两套松散遍历，契约不同（报告 vs 跳过），迁移记为 DEFER-06。
- **Revisit when:** `gc` 命令落地（DEFER-01），或 DEFER-05/06 被排期。

### ADR-CO-03: 有意差异

- **Status:** Accepted
- **Context:** Libra 的目录布局、Operation Log、tiered 存储与 Git 不同；少数 Git 行为会让前后比对假通过。
- **Decision:** 以下差异必须同时写入四处：EN 文档、zh-CN 文档、`COMPATIBILITY.md` 的 `count-objects` 行、`docs/development/commands/count-objects.md`：
  1. warning 与 `garbage_entries` 中的路径为 Libra 解析出的**绝对路径**（Git 打印相对 `.git/objects/...` 的路径，目录名本来就不同）。
  2. 分片目录或 pack 目录不可读时 fail-closed 报 `LBR-IO-001`（Git 打印错误、提前停止遍历，仍 exit 0，会少计数）。
  3. Libra 真实变更命令写入的 Operation Log 快照对象计入 `count`，因此变更命令之后 Libra 的计数通常大于 Git。
  4. tiered 存储只统计本地层。
- **Alternatives considered:** 模仿 Git 的相对路径——Libra 可从任意子目录运行且目录名不同，无法对齐，拒绝。
- **Consequences:** 移植用例只能比较「同一 Libra 仓库内的前后输出」，不能与 Git 输出逐字节比较。
- **Revisit when:** Operation Log 快照改为非对象存储，或外部用例提出路径形态需求。

### ADR-CO-04: 机器接口

- **Status:** Accepted
- **Context:** issue 评论接受「等价的机器可读对象库检查契约」；Agent 需要原始字节数。
- **Decision:** `--json` / `--machine` 通过 `emit_json_data("count-objects", …)` 输出，`-H` 不影响 JSON 数值：
  - 无参数形式：`{"verbose": false, "count": u64, "size_bytes": u64, "size_kib": u64}`。
  - `-v` 追加：`verbose: true`、`in_pack`、`packs`、`size_pack_bytes`、`size_pack_kib`、`prune_packable`、`garbage`、`size_garbage_bytes`、`size_garbage_kib`、`garbage_entries: [{path, reason}]`（最多 100 条）、`garbage_entries_truncated: bool`、`alternates: [string]`。`reason` 取值为 `garbage_found | no_corresponding_idx | no_corresponding_pack | no_corresponding_idx_or_pack`。
  - 结构化模式下 garbage 明细只进入 `data.garbage_entries`，不再额外输出人读 warning 行。
- **Alternatives considered:** JSON 固定输出全部字段——非 `-v` 时会引入 pack 与 garbage 扫描，偏离 Git 成本模型，拒绝。
- **Consequences:** 字段只增不改；CO-02 追加的字段对 CO-01 的消费者向后兼容。
- **Revisit when:** 出现分页或流式 garbage 明细需求。

### ADR-CO-05: 预览调用在中央 census 归为 ReadOnly

- **Status:** Accepted
- **Context:** GAP-03..05。快照写入来自中央 operation 流水线（`src/cli.rs:3202-3209` → `middleware.rs:195-223`），不是预览业务代码；`commit --dry-run` 已有同类豁免（`src/cli.rs:1943-1950`）。
- **Decision:** 在 `operation_class_for_command` 中，对 CO-03/CO-04 列出的预览形态按已解析参数（`args.dry_run` 或对应子命令字段）返回 `MutationClass::ReadOnly`。不改变 `command_scope`，因此维护锁（`src/cli.rs:1692-1694`）与 legacy-symlink worktree 拒绝（`command_mutates_worktree_state`）行为不变。改分类后若复测仍有对象写入，而修复落在该命令的预览路径内，就在本卡修复；否则按 ER-10 建 `FIX-*`。

- **Consequences:** 预览调用不再获得 operation 级别的前后快照（它们本来也不发布 operation）。
- **Revisit when:** Operation Log 引入预览专用的只读快照需求。

### Task CO-01: `count-objects` 无参数形式与命令契约

**Task type:** `implementation`

## 文档职责

本文解决 issue #483：`libra count-objects` 完全缺失，导致 Git 黑盒用例（`t2200-add-update.sh` 的 TC-0011 等）无法表达「被测命令没有写入任何对象」这一断言。目标是交付与 Git 对齐的 `libra count-objects [-v] [-H]`，并让它真正断言得住——修复本计划核对时实测发现的缺陷：多个 `--dry-run` / `-n` 预览命令在 Libra 中**会写入对象**。

本文只规划任务，不宣称实现完成。落地时每个任务都必须先刷新源码锚点，再按任务卡验收。

### 适用范围

- 新命令 `libra count-objects`：无参数形式、`-H/--human-readable`、`-v/--verbose`，以及 `--json` / `--machine` 机器接口。
- 松散对象目录、pack 目录、`objects/info/alternates` 的只读清点；不改变任何存储格式。
- `src/cli.rs` 中央操作 census（`operation_class_for_command`）对预览调用的分类：`add -n`、`rm --dry-run`、`clean -n`、`mv -n`、`reflog expire --dry-run`、`alternates prune --dry-run`、`cache evict --dry-run`。
- 同步：`docs/commands/` EN + zh-CN、`docs/development/commands/`、三处命令索引 README、`COMPATIBILITY.md`、help EXAMPLES、`../libra-backend` 网站文档、测试索引与 compat 守卫。

### 非目标

- `libra gc` / `prune-packed` 命令（#385、#481）：`count-objects -v` 会报告 `prune-packable`，但本计划不提供清理命令（DEFER-01）。
- #481 的 P1「repack 后短 SHA 被判 ambiguous」（`LocalStorage::search` 未去重）：本计划不改 `search`，且 `count-objects` 禁止复用它（DEFER-02）。
- 真实变更命令（`add`、`add --refresh`、`commit` 等）写入 Operation Log v2 快照对象：这是 Libra 有意的操作日志设计，不在本计划改变；只在 `count-objects` 文档说明其对计数的影响（ADR-CO-03）。
- Git `report_linked_checkout_garbage` 在 Libra linked worktree 布局下的对应物（DEFER-04）。
- 统计 tiered 存储远端层（S3/R2）中的对象。
- 把 `gc` / `cache evict` 的松散对象枚举迁移到本计划的新扫描器（DEFER-06）；修改热路径 `LocalStorage::read_idx` 的查找算法（DEFER-05）。

### 成功定义

- `libra count-objects` 在非裸仓库、裸仓库、linked worktree 中 exit 0；`-v` 按 Git 字段名与顺序输出 `count/size/in-pack/packs/size-pack/prune-packable/garbage/size-garbage`，其后是 `alternate:` 行；`-H` 输出 Git humanise 格式。
- `count-objects` 本身零写入：不创建或重建 `.idx`，不记录 operation，不取维护锁，不做 schema 迁移。
- 移植 TC-0011：`add -n -u` 前后 `count-objects -v` 输出逐字节相等，`ls-files -s check top` 相等，且仍报告 `check` 的 add 与 `top` 的 remove 候选；同一不变式对本计划列出的全部预览形态成立，并有守卫防止新预览 flag 回归。
- 四张卡各自完成 C 组发布（`patch + 1` + `gh` 触发 `release.yml`）并取得 D 组证据，然后全量收口门全绿。满足这些之后，本计划才可标记完成。

### ADR-CO-01: Git 语义参照与判据矩阵

- **Status:** Accepted
- **Context:** issue 要求 Git 字段名与顺序精确一致；`size` 等数值依赖文件系统，不能用固定 golden 文件比对。
- **Decision:** 语义以 issue pin git@`1630431f32` 源码为准（事实基线逐行锚定）；凡声明「与 Git 一致」的行，开工时必须用 `/usr/bin/git`（或同等版本）在相同 fixture 上实跑对照，并把脱敏摘要写入本计划「实施证据汇总」（禁止新建外部证据文件，见模板 v2.12）。自动化测试不调用系统 git，期望值由测试按下列矩阵现算（`size` 取 `metadata.blocks() * 512`，非 Unix 取 `len()`）。矩阵是各卡 AC 引用的**判据规范**，每行都必须有对应测试用例：

  **M-FMT（文本格式）**

  | 行 | 调用 / 输入 | 期望 |
  |---|---|---|
  | F1 | 空库 `count-objects` | `0 objects, 0 kilobytes` |
  | F2 | L 个松散对象、共占 B 字节 | `L objects, ⌊B/1024⌋ kilobytes` |
  | F3 | `-H`，B ∈ {0, 1, 1024, 1025, 1048577, 1073741825} | `0 bytes` / `1 byte` / `1024 bytes` / `1.00 KiB` / `1.00 MiB` / `1.00 GiB`（逐字复刻 `strbuf.c:873-907`：KiB/MiB 先加进位常数，GiB 截断） |
  | F4 | `-v` | 8 行 `key: value`，顺序为 `count, size, in-pack, packs, size-pack, prune-packable, garbage, size-garbage`；其后 0..n 行 `alternate: ` |
  | F5 | `-vH` | `size`、`size-pack`、`size-garbage` 用 F3 格式，其余字段为整数 |

  **M-LOOSE（松散对象判定）**

  | 行 | 输入 | 期望 |
  |---|---|---|
  | L1 | `objects/<2 位小写十六进制>/<hexsz-2 位十六进制>` 的普通文件 | 计入 `count`；`size` 按上文口径累加 |
  | L2 | 同 L1，但文件名含大写 A–F | 计入（`hex-ll.c:4`）；开工时用 git 实跑确认 |
  | L3 | 非两位十六进制的顶层目录（`zz/`、`pack/`、`info/`） | 整个目录忽略，不计 garbage |
  | L4 | 分片内名称长度不等于 hexsz-2，或含非十六进制字符 | 不计 `count`（`-v` 时按 M-GARBAGE G1 处理） |
  | L5 | 分片内名称合法，但 lstat 结果不是普通文件（目录、符号链接） | 不计 `count`（`-v` 时按 G1 处理） |
  | L6 | `objects/` 根下的文件（如崩溃遗留的临时文件） | 忽略 |
  | L7 | `init --object-format sha256` 仓库 | hexsz=64，名称长度 62 |
  | L8 | `repack`（未 `-d`）后保留的松散副本 | 仍计入 `count` |

  **M-PACK（pack 字段，仅 `-v`）**

  | 行 | 输入 | 期望 |
  |---|---|---|
  | P1 | 同基名的 `.pack` + `.idx` | `packs`+1；`in-pack` += idx 对象数；`size-pack` += `(pack 字节 + idx 字节)`，输出时 `/1024` |
  | P2 | 只有 `.pack`，没有 `.idx` | 不计入 `packs`/`in-pack`；**不得**创建 `.idx`（按 G5 报告） |
  | P3 | `.idx` 头或 fanout 损坏 | 该 pack 跳过，命令不失败 |
  | P4 | `repack`（未 `-d`） | `prune-packable` = 同时存在于松散目录与本地 pack 的对象数 |
  | P5 | alternate 仓库中的 pack | 不计入 `in-pack`/`packs`（对应 `pack_local`） |

  **M-GARBAGE（仅 `-v`）**

  | 行 | 输入 | 期望 |
  |---|---|---|
  | G1 | 分片内的 L4/L5 条目 | `garbage`+1；`size-garbage` += `stat` 的 `st_size`；`warning: garbage found: <path>` |
  | G2 | pack 目录中无点号的文件 | `garbage found` |
  | G3 | pack 目录中扩展名不在 `.idx/.rev/.pack/.bitmap/.keep/.promisor/.mtimes` 内的文件 | `garbage found` |
  | G4 | 同基名组只有 `.idx`（可带其它已知扩展名） | 组内每个文件报 `no corresponding .pack` |
  | G5 | 同基名组只有 `.pack` | 组内每个文件报 `no corresponding .idx` |
  | G6 | 同基名组只有 `.keep`/`.rev`/`.bitmap`/`.promisor`/`.mtimes` | `no corresponding .idx or .pack` |
  | G7 | `multi-pack-index`、`multi-pack-index.d`、`multi-pack-index*.bitmap/.rev` | 忽略 |
  | G8 | 不带 `-v` | 不扫描 pack 目录，不输出任何 warning |
  | G9 | garbage 条数 > 100 | 人读 warning 与 JSON `garbage_entries` 均最多输出/记录 100 条（`GARBAGE_ENTRY_LIMIT = 100`）；`garbage` 与 `size-garbage` 仍计全量 |

  **M-ALT（仅 `-v`）**

  | 行 | 输入 | 期望 |
  |---|---|---|
  | A1 | 单个 alternate | 一行 `alternate: <绝对路径>` |
  | A2 | 多直接入口 + 分支传递链（如 `alternates` 含 `[A, B]`，且 `A` 含 `[A1, A2]`） | 按 Git `../git/odb/source-files.c:363` 保持 alternates 文件顺序并递归展开后代（`A, A1, A2, B`）；修正 `alternates::resolve_chain`（`src/internal/alternates/mod.rs:163` 当前 `Vec::pop()` 会反转直接入口顺序），在人读与 JSON 输出中均断言精确顺序 |
  | A3 | 环或缺失（dangling）目录 | 由 `alternates::resolve_chain`（`src/internal/alternates/mod.rs:152-184`）处理：规范化 visited 集合 + `MAX_DEPTH` 终止环；不存在的目录跳过（仅 `tracing::warn!`，不输出 `alternate:` 行、不硬失败）；需有单测/集成测试覆盖 |
  | A4 | 路径含 `"`、`\`、控制字符、非 ASCII 或非 UTF-8（含 `objects/info/alternates` 含原始非 UTF-8 字节） | 在 `src/internal/alternates/mod.rs` 提供无损字节读取与可失败错误传播路径（替代 `read_to_string().unwrap_or_default()` 对非法字节的静默吞并），非 `NotFound` I/O 错误报 `LBR-IO-001`；人读 `alternate:` 行按 `quote_c_style` 加引号并转义（对非 UTF-8 无损）；JSON `alternates` 输出原始 UTF-8 字符串，遇到非 UTF-8 alternate 路径时显式拒绝并返回 `LBR-IO-001`；需用原始字节 fixture 测试同时覆盖人读转义与 JSON `LBR-IO-001` |
  | A5 | alternate 仓库 pack 目录中的 garbage | 计入 `garbage` 并报告（git 2.54 `--shared` clone 实测行为） |

  **M-REPO（仓库形态）**

  | 行 | 位置 | 期望 |
  |---|---|---|
  | R1 | 非裸仓库根目录 | exit 0 |
  | R2 | 非裸仓库子目录 | 输出与 R1 相同 |
  | R3 | `init --bare` 目录内 | exit 0，统计 `<bare>/objects` |
  | R4 | linked worktree 内 | 输出与主 worktree 相同（共享对象库） |
  | R5 | 设置了 `LIBRA_STORAGE_TYPE` 的 tiered 仓库（endpoint 不可达） | 只统计本地对象目录，不发网络请求，不挂起 |

  **M-ERR（错误路径）**

  | 行 | 输入 | 期望 |
  |---|---|---|
  | E1 | 仓库外 | `LBR-REPO-001`，exit 128 |
  | E2 | 位置参数（`count-objects foo`） | `LBR-CLI-002`，exit 129 |
  | E3 | 未知 flag | `LBR-CLI-002`，exit 129 |
  | E4 | 分片目录不可读（Unix `chmod 000`；Windows 或 root `geteuid() == 0` 下跳过并打印 skipped 原因） | `LBR-IO-001` fail-closed，stdout 不输出部分计数 |

- **Alternatives considered:** 录制 git 输出做逐字节 golden——`size` 随块大小与文件系统变化，不可移植，拒绝。在测试中调用系统 git 做 oracle——CI 环境不保证有 git，且仓库既有测试避免调用 git，拒绝。
- **Consequences:** 矩阵行变化时，必须同批修改 ADR 与测试，并登记修订历史。
- **Revisit when:** issue pin 之后 Git 修改了 `count-objects.c` 或 pack 目录扫描逻辑，且外部用例仓库升级了参照版本。

### ADR-CO-02: 只读命令接线与禁止复用的路径

- **Status:** Accepted
- **Context:** GAP-07：既有 pack 读取会重建 idx，既有松散枚举不报告 garbage；新命令必须严格只读。
- **Decision:**
  1. 在 `command_scope` 中归为 `CommandScope::ReadOnly`（因此 class 为 `ReadOnly`，不进入 operation 边界，不持维护锁）。
  2. 预检沿用 `verify-pack` 的 `repo_hash_kind_without_schema_guard`（不迁移 schema）；仓库外由 `execute_safe` 返回 `CliError::repo_not_found()`。
  3. 在 `src/command/count_objects.rs` 实现 Git 语义的只读扫描器（按 M-LOOSE/M-GARBAGE 分类）。
  4. 在 `src/utils/storage/local.rs` 暴露建立在 `read_idx_fanout` 之上的只读 helper：`pack_index_object_count(idx)`，以及 fanout 桶内二分查找的 `pack_index_contains(idx, oid)`。不改变 `read_idx` 本身。
  5. **禁止**调用 `list_all_idx`、`search`、`list_loose_objects`、`ClientStorage` 的远端回退路径。
  6. hexsz 取 `get_hash_kind().size() * 2`。
- **Alternatives considered:** 复用 `list_all_idx`——会写 idx，违反零写入，拒绝。复用 `verify_pack_index::parse_index`——需解析整个 idx，prune-packable 的内存为 O(packed)，拒绝。直接改 `read_idx` 为二分查找——触及所有对象读取热路径，风险超出本 issue，记为 DEFER-05。
- **Consequences:** 仓库里暂时存在「Git 语义扫描器」与「gc/evict 枚举」两套松散遍历，契约不同（报告 vs 跳过），迁移记为 DEFER-06。
- **Revisit when:** `gc` 命令落地（DEFER-01），或 DEFER-05/06 被排期。

### ADR-CO-03: 有意差异

- **Status:** Accepted
- **Context:** Libra 的目录布局、Operation Log、tiered 存储与 Git 不同；少数 Git 行为会让前后比对假通过。
- **Decision:** 以下差异必须同时写入四处：EN 文档、zh-CN 文档、`COMPATIBILITY.md` 的 `count-objects` 行、`docs/development/commands/count-objects.md`：
  1. warning 与 `garbage_entries` 中的路径为 Libra 解析出的**绝对路径**（Git 打印相对 `.git/objects/...` 的路径，目录名本来就不同）。
  2. 分片目录或 pack 目录不可读时 fail-closed 报 `LBR-IO-001`（Git 打印错误、提前停止遍历，仍 exit 0，会少计数）。
  3. Libra 真实变更命令写入的 Operation Log 快照对象计入 `count`，因此变更命令之后 Libra 的计数通常大于 Git。
  4. tiered 存储只统计本地层。
- **Alternatives considered:** 模仿 Git 的相对路径——Libra 可从任意子目录运行且目录名不同，无法对齐，拒绝。
- **Consequences:** 移植用例只能比较「同一 Libra 仓库内的前后输出」，不能与 Git 输出逐字节比较。
- **Revisit when:** Operation Log 快照改为非对象存储，或外部用例提出路径形态需求。

### ADR-CO-04: 机器接口

- **Status:** Accepted
- **Context:** issue 评论接受「等价的机器可读对象库检查契约」；Agent 需要原始字节数。
- **Decision:** `--json` / `--machine` 通过 `emit_json_data("count-objects", …)` 输出，`-H` 不影响 JSON 数值：
  - 无参数形式：`{"verbose": false, "count": u64, "size_bytes": u64, "size_kib": u64}`。
  - `-v` 追加：`verbose: true`、`in_pack`、`packs`、`size_pack_bytes`、`size_pack_kib`、`prune_packable`、`garbage`、`size_garbage_bytes`、`size_garbage_kib`、`garbage_entries: [{path, reason}]`（最多 100 条）、`garbage_entries_truncated: bool`、`alternates: [string]`（原始 UTF-8 路径；非 UTF-8 路径显式拒绝）。`reason` 取值为 `garbage_found | no_corresponding_idx | no_corresponding_pack | no_corresponding_idx_or_pack`。
  - 结构化模式下 garbage 明细只进入 `data.garbage_entries`，不再额外输出人读 warning 行；人读模式下 garbage warning 同样以 100 条为上限（`GARBAGE_ENTRY_LIMIT = 100`）。
- **Alternatives considered:** JSON 固定输出全部字段——非 `-v` 时会引入 pack 与 garbage 扫描，偏离 Git 成本模型，拒绝。
- **Consequences:** 字段只增不改；CO-02 追加的字段对 CO-01 的消费者向后兼容。
- **Revisit when:** 出现分页或流式 garbage 明细需求。

### ADR-CO-05: 预览调用在中央 census 归为 ReadOnly

- **Status:** Accepted
- **Context:** GAP-03..04。快照写入来自中央 operation 流水线（`src/cli.rs:3775` → `middleware.rs`），不是预览业务代码；`commit --dry-run` 已有同类豁免（`src/cli.rs:2241`）。
- **Decision:** 在 `operation_class_for_command`（`src/cli.rs:2218`）中，对 CO-03/CO-04 列出的预览形态按已解析参数（`args.dry_run` 或对应子命令字段）返回 `MutationClass::ReadOnly`。不改变 `command_scope`，因此维护锁（`src/cli.rs:3655`）与 legacy-symlink worktree 拒绝（`command_mutates_worktree_state` at `src/cli.rs:2210`、`3633`）行为不变。改分类后若复测仍有对象写入，而修复落在该命令的预览路径内，就在本卡修复；否则按 ER-10 建 `FIX-*`。
- **Alternatives considered:** 让快照流水线识别「无变化」并跳过写对象——会改变全部真实变更的快照语义与 OL 计划契约，超出本 issue，拒绝。在各命令内部绕开边界——违反 GC-02 单一 census，拒绝。
- **Consequences:** 预览调用不再获得 operation 级别的前后快照（它们本来也不发布 operation）。
- **Revisit when:** Operation Log 引入预览专用的只读快照需求。

# Issue #997：`fetch`/`pull` 以 tag 作為 refspec 來源（顯式 destination）（2026-11-12）

> 模板 v2.16。[Issue #997](https://github.com/libra-tools/libra/issues/997) OPEN，无评论。仅规划，未授权执行；卡 `pending` / 验收空。Git 对照 pin `6de20f6092dcf9bdb1c8efe03db4b70c82b423dd`。实测基线 system `libra 0.30.171`。测试用例仓本计划不修改（TC 已存在）。

## 文档职责

### 适用范围

`libra fetch <remote> <tag-refspec>` 与 `libra pull <remote> <tag-refspec>` 在**显式 destination**（`refs/tags/<name>:<local>` 或 `refs/tags/<name>:refs/tags/<name>`）时的行为：source 解析（含轻量/附注 tag）、对象闭包、peel 到的 commit、FETCH_HEAD 记录与 destination 写入，以及 `pull` 以该 commit 进入既有 fast-forward/merge 状态机。

### 非目标

无 destination 时的 `not-for-merge` 标记与 `merge FETCH_HEAD` 消费（`DEFER-I997-01`，与 `issues/976.md` 契约相关，需该计划先行裁定）。未广告 OID 的 fail-closed 语义（`DEFER-I997-02`）。10k refs 性能门（`DEFER-I997-03`）。`fetch --prune` 与 `remote.<name>.push`。

### 成功定义

- 显式 `refs/tags/<name>:<destination>` 的 fetch 成功：tag 对象（附注）与 peeled commit 均被下载，destination 按 Git 语义写入（tag → tag ref；`<name>:<branch>` 写入 branch ref）。
- `pull` 使用同一 refspec 时以 peeled commit 进入既有 ff/merge 判定；冲突时走既有错误与退出码。
- 未知 tag、非法 refspec、无 destination 的用法分别以既有稳定错误码 fail-closed。
- 仓库命令文档、兼容矩阵与回归同卡。

## 已决议设计决策

### ADR-I997-01: source 解析以 Issue 正文为规范

- **Status:** Accepted
- **Context:** Issue 正文写明 Git DWIM 顺序以 `refs/heads/<name>` 在前；Git 2.56 的 ref 评分与其不一致。
- **Decision:** 本计划按 Issue 正文实现：短名依次 `refs/heads/<name>`、`refs/tags/<name>`、`refs/<name>`、advertisement 中的完整 OID；`refs/` 前缀精确匹配。与 Git 评分的差异只在 `COMPATIBILITY.md` 记录，不改变实现顺序。
- **Alternatives considered:** 按 Git 评分（与 Issue 正文冲突，会造成计划与来源不一致）。
- **Consequences:** 同名 branch/tag 时选 branch；与 Git 2.56 行为不同，需在兼容矩阵标注。
- **Revisit when:** Issue 正文或上游契约变更。

### ADR-I997-02: 附注 tag 的闭包与 destination 类型

- **Status:** Accepted
- **Decision:** 附注 tag 下载 tag object 与其 peeled commit；`<tag>:refs/tags/<x>` 写 tag ref，`<tag>:refs/heads/<b>` 写 branch ref 且指向 peeled commit；轻量 tag 直接写 commit。复用既有 refspec 解析器，不新增第二套。
- **Alternatives considered:** 只下载 commit（丢失 tag 对象，`verify-pack`/`show` 会失败）。
- **Consequences:** destination 写入由一个 ref writer 负责；FETCH_HEAD 记录按既有格式写入。
- **Revisit when:** 引入 tag 自动跟随（`--tags`）。

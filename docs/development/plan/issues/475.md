## 文档职责

issue #475 写于 libra 0.22.5。本计划在本机安装的 libra 0.22.28（等于仓库 `Cargo.toml` 版本）与 git 2.54.0 上分三轮并排实跑，逐条复核 issue 的 8 个行为条目与「Test gaps」一节，目标是**完全解决** issue 描述的所有问题。

复核结论分三类：
- **确认：** 条目 1–6 全部复现；条目 7 的退出码漂移复现且范围更大。
- **归因需修正：** 条目 7 关于 `--system` 的描述与实测部分相反：级联读取时 Libra 跳过不可读的 system 存储而 Git 报错；显式 `--system` 读取时 Libra 报 128 而 Git 返回 1。
- **issue 未列出、风险更高的新发现：**
  - `--unset-all <key> <value-pattern>` 忽略模式，**删除该 key 的全部值**（数据丢失）；`--unset <key> <pattern>` 对加密值同样忽略模式。
  - `--get-all no.such`、`--unset no.such`、`--unset-all no.such`、`config unset <key>` 在 key 不存在时 exit 0（Git 为 1 或 5）。
  - `--list` 默认只列 local 作用域且按 key 字母序；`--get-regexp` 输出 `key = value` 且按字母序；Git 列出全部作用域、按文件内出现顺序、`--get-regexp` 为 `key value`。
  - `--show-origin --list` 忽略 `--global`/`--local`/`--system`，总是列出全部作用域。
  - 无效正则在 `--get-regexp` 下被当作「缺少 section」、在 `--get-all key (` 下被静默忽略（Git exit 6）。
  - 保留的 `upgrade.*` 规则让 `--system --get-regexp .` 这类与 `upgrade.mode` 无关的作用域也报用法错误。

本计划按风险排序交付 15 张卡：
1. **Phase 1（数据安全与退出码）：** CF-02、CF-01。
2. **Phase 2（读取语义）：** CF-03..CF-07。
3. **Phase 3（写入语义）：** CF-08。
4. **Phase 4（类型）：** CF-09..CF-11。
5. **Phase 5（文件与编辑）：** CF-12..CF-14。
6. **Phase 6（子命令对齐）：** CF-15。

本文只规划任务，不宣称实现完成。落地时每个任务都必须先刷新源码锚点，再按任务卡验收。

### ADR-CF-02: 退出码与稳定错误码

- **Status:** Accepted
- **Context:**
  - Git config 用数据错误码区分失败原因（`config.h:27-34`）。Libra `config` 已按命令对齐其中一部分：缺失返回 1、缺少 section 返回 1、多值冲突返回 5，均通过 `with_exit_code`（`src/command/config.rs:1459`、`:1573`、`:1785`；`src/utils/error.rs:35` 注释以 `git config --get` 为例）。
  - [`issues/477.md`](477.md) ADR-HF-02 与 [`issues/479.md`](479.md) ADR-PL-02 保留 128/129 模型，但承认按命令匹配 Git 退出码的先例；`docs/error-codes.md:161-164` 已有按命令例外说明段。
  - 当前用户输入错误回落到 `LBR-INTERNAL-001`，与稳定码表语义不符。
- **Decision:**
  1. **退出码（legacy 参数与子命令一致）：**
     - `1`：get 类模式中 key 缺少 section，或 key/模式无匹配；
     - `2`：set/unset 类模式中 key 缺少 section 或变量名；
     - `5`：unset 类模式无匹配值，或单值写入/删除遇到多个匹配值；
     - `6`：key 模式或 value-pattern 无效；
     - `128`：`--type` 无法识别（Git `die`），以及存储读取、写入、锁与解密失败；
     - `129`：参数数目错误、互斥参数、未知参数。
     - Git 的 `3`（无效文件）、`4`（不可写）与锁失败时的 `255` 不采用，统一为 128，登记为有意差异。
  2. **稳定错误码：** key 格式、模式无效与 `--type` 无法识别 → `LBR-CLI-002`；key 缺失与无匹配 → `LBR-CLI-003`；多值冲突 → `LBR-CONFLICT-002`；读写失败 → `LBR-IO-001` / `LBR-IO-002`。用户输入错误不再使用 `LBR-INTERNAL-001`。
  3. **stderr：** `--get` / `config get` 单 key 缺失时保留 Libra 既有的 `not found` 与 `did you mean` 提示（登记为有意差异）；`--get-all`、`--get-regexp` 与 value-pattern 无匹配时不输出 stderr，与 Git 一致。
  4. **细粒度开关：** 上述覆盖在 `LIBRA_FINE_EXIT_CODES=1` 下同样生效；JSON error envelope 的 `exit_code` 反映覆盖值。
  5. **文档：** config 命令文档的错误表列出退出码与稳定码；`docs/error-codes.md` 的按命令例外说明段追加 config，不修改码表行。
- **Alternatives considered:** 统一改为 128/129——破坏依赖 `git config` 退出码的脚本，且与 config 已有覆盖矛盾，拒绝。新增 config 专用稳定码——命中 T-1 且收益有限，拒绝。
- **Consequences:** N2 列出的 exit 0 改为 1/5、无点 key 的 unset/set 由 1 改为 2、无效模式改为 6、`--type` 未知值由 129 改为 128，均为公开行为变化，在 `COMPATIBILITY.md:246` 与文档写明。
- **Revisit when:** 稳定错误码表进行 major 调整。

### ADR-CF-03: value-pattern 语义

- **Status:** Accepted
- **Context:** 条目 2、N1、N5、N9；git `builtin/config.c:560-612`、`config.c:2616-2634`、`t1300:2736-2830`。
- **Decision:**
  1. **引擎与匹配：** value-pattern 使用与现有 `--get-regexp` 相同的 Rust `regex` 引擎，对完整值做非锚定匹配；前缀 `!` 表示取反；`--fixed-value` 改为逐字节相等；`--fixed-value` 缺少模式时为用法错误（129）。
  2. **key 模式：** `--get-regexp` 先按 Git 规则把 section 与变量名部分小写化（`builtin/config.c:563-569`），子节保持原样；编译失败为 `error: invalid key pattern: <p>`（exit 6）。
  3. **方言差异：** POSIX ERE 与 Rust `regex` 的差异（如 GNU `\<`/`\>` 词边界不支持）登记为有意差异；矩阵覆盖 `t1300` 中实际使用的语法。
  4. **加密值：**
     - 普通加密值以进程内解密后的明文参与匹配，输出仍按既有规则脱敏（`--reveal` 行为不变）；
     - 解密失败时报错（`LBR-REPO-003`，128）并零写入；
     - vault 内部凭据（`is_vault_internal_key`）不接受 value-pattern，报用法错误，避免成为逐字符探测的判定器。
  5. **作用域：** 级联读取时模式逐条作用于各作用域的条目；写入只作用于显式作用域（缺省 local）。
- **Alternatives considered:** 加密值一律不匹配——`--unset secret.token abc123` 无法按值删除，与 Git 语义不一致，拒绝。
- **Consequences:** 值模式的编译与匹配集中在一个 helper 中，由 CF-02 引入、CF-01/CF-03/CF-08/CF-12/CF-13 复用。
- **Revisit when:** 需要 PCRE 或 ERE 精确方言。

### ADR-CF-04: 输出格式、顺序与默认作用域

- **Status:** Accepted
- **Context:** N3、N7；git `builtin/config.c:406-440`、`:1015-1036`。
- **Decision:**
  1. **顺序：** 作用域内按存储行 `id`（插入顺序）；作用域之间按 system → global → local → worktree 覆盖层（Git 的读取顺序）。`--get` 的「最后一个值获胜」沿用该顺序，因此现有「local 优先」的级联语义不变。
  2. **默认作用域：** legacy `--list` 与 `config list` 在未指定作用域时列出全部作用域；指定作用域时只列该作用域。
  3. **格式：** `--get-regexp` 为 `key value`；`--list` 为 `key=value`；`-z` 格式不变；legacy 形式新增 `--name-only`。
  4. **保留条目：** 文件承载的 `upgrade.mode` 条目放在 global 作用域条目之后。
  5. **JSON：** 条目顺序与人读输出一致；每个条目新增 `scope`；顶层 `scope` 为显式作用域名或 `all`。
  6. **不变：** Libra 专有视图（`--vault`、`--ssh-keys`、`--gpg-keys`）的人读输出不变。
- **Alternatives considered:** 保留字母序并只加选项——与 Git 默认不同，脚本仍需适配，拒绝。
- **Consequences:** 依赖字母序或「默认只列 local」的脚本需要调整，文档与 `COMPATIBILITY.md:246` 写明。
- **Revisit when:** 无。

### ADR-CF-05: 来源与作用域的表示

- **Status:** Accepted
- **Context:** 条目 3、4；N4、N7；git `builtin/config.c:234-264`。
- **Decision:**
  1. **SQLite 作用域：** 来源为 `file:<path>`，`path` 是承载该作用域的数据库文件。local 为相对工作树根的 `.libra/libra.db`（对应 Git 的 `.git/config`），链接工作树覆盖层为其 gitdir 下的相对路径，global/system 为解析后的绝对路径（尊重 `LIBRA_CONFIG_GLOBAL_DB` / `LIBRA_CONFIG_SYSTEM_DB`）。
  2. **其它来源：** `--file` 为 `file:<给定路径>`；stdin 为 `standard input:`；`--blob` 为 `blob:<rev>`；`--default` 为 `command line:`；保留 `upgrade.mode` 为 `file:<settings.json 路径>`。
  3. **作用域名：** `system`、`global`、`local`、`worktree`、`command`（`--file`/`--blob`/stdin/`--default`）。
  4. **拼接：** 顺序为作用域、来源、key、值；非 `-z` 时分隔符为 TAB，路径按 C 风格加引号；`-z` 时分隔符为 NUL，路径不加引号。
  5. **作用域参数：** `--show-origin`/`--show-scope` 不再改变读取范围，按显式作用域或默认作用域读取。
- **Alternatives considered:** 新增 `libra-db:` 来源类型——Git 脚本只认识既有类型，拒绝。保留 `--show-origin` 输出作用域标签——即 issue 条目 3 所述差异，拒绝。
- **Consequences:** `config list --show-origin` 的人读输出从作用域标签改为 Git 格式，作用域标签改由 `--show-scope` 提供；属公开变化。
- **Revisit when:** 支持 include 或 `-c` 来源。

### ADR-CF-06: 显式与级联作用域的读取错误

- **Status:** Accepted
- **Context:** 条目 7；`Documentation/git-config.adoc:397-403`；`_compatibility.md:39`（P1-05a 级联跳过）。
- **Decision:**
  1. **显式作用域缺失：** `--system`/`--global` 的存储缺失时，`--get*` 为 exit 1 且无 stderr；`--list` 为 exit 128 `fatal: unable to read config file '<path>': No such file or directory`。
  2. **显式作用域不可读：** 输出 `warning: unable to access '<path>': <原因>`，随后按缺失处理 `--get*`（exit 1）；`--list` 按 M-SYS Y4 实测写回。
  3. **级联：** 保留 P1-05a：级联读取遇到不可读或不支持的 system 存储时跳过（Git 报错，登记为有意差异）；缺失的 global/system 存储与 Git 一样忽略。
  4. **损坏与未来 schema：** 沿用 plan-20260910 MIG-04/MIG-05 的分类。
- **Alternatives considered:** 级联也改为报错——破坏 P1-05a 已发布契约与多命令默认值读取，拒绝。
- **Consequences:** 只有显式作用域的读取行为变化。
- **Revisit when:** P1-05a 契约修订。

### ADR-CF-07: `--file` / `--blob` 的 Git 格式配置文件后端

- **Status:** Accepted
- **Context:** 条目 4；Libra 内没有 Git 配置文件解析器（`import` 调用系统 git，`src/command/config.rs:3172-3195`）；git `config.c:3028-3067`、`builtin/config.c:925-1000`。
- **Decision:**
  1. **模块：** 新增 `src/internal/config_file/`（解析器与写入器），实现 Git 配置文件语法：节与子节（带引号子节、旧式 `[section.sub]`）、有值与无值变量、引号与转义（`\"`、`\\`、`\n`、`\t`、`\b`）、续行、`;`/`#` 注释、section 与变量名大小写不敏感。不跟随 `include`/`includeIf`（DEFER-01）。
  2. **读取（CF-12）：** `--file <path>`、`--file -`（stdin）、`--blob <rev:path>`（经 Libra 对象库解析）；来源与作用域按 ADR-CF-05。
  3. **写入（CF-13）：**
     - 放置规则对齐 Git `repo_config_set_multivar_in_file_gently`：原位替换匹配行、新变量追加到该节最后一次出现处、必要时在文件末尾新建节；值的引号规则对齐 Git；
     - 原子写入使用 `<file>.lock` 与 rename；
     - 拒绝向 stdin 与 blob 写入；
     - 文件后端不支持 vault 与加密参数，`upgrade.*` 保留规则不适用。
  4. **互斥：** `--file`/`--blob` 与作用域参数同用时报 exit 129 `error: only one config file at a time`。
  5. **import 不变：** `config import` 继续使用系统 git，不在本计划切换。
- **Alternatives considered:** 调用系统 `git config --file`——引入运行时 git 依赖，拒绝。把文件导入临时 SQLite 再操作——丢失文件格式与位置语义，拒绝。
- **Consequences:** 新模块由 CF-12 引入读取、CF-13 扩展写入、CF-14 复用导出与解析。
- **Revisit when:** DEFER-01（include）排期。

- **Context:** 条目 6；`docs/commands/config.md:616` 的「为什么不支持 edit」理由（明文导出密文危险）；git `builtin/config.c:1291-1345`。
- **Decision:**
  1. **文件目标：** `--file <path> --edit` 直接在该文件上启动编辑器；stdin 与 blob 按 Git 文案拒绝。
  2. **SQLite 作用域（缺省 local、`--global`、`--system`）：**
     - 以 CF-13 写入器把该作用域条目按插入顺序导出到作用域目录下的临时文件（权限 0600）；
     - 加密条目与 vault 内部 key 导出为只读注释占位 `# [encrypted] <key>`，保留 `upgrade.*` 不导出；
     - 编辑器以 `editor::resolve_editor` 解析，退出码非 0 时中止零写入。
  3. **导入：**
     - 内容字节未变 → exit 0 零写入；
     - 否则解析并按 key 计算保序多值差异，经 plan-20260910 的 Config role 写入 helper 在单事务中应用；
     - 占位行被忽略；新增 `vault.*`、`upgrade.*` 或与加密条目同名的 key → 拒绝零写入；
     - 解析失败 → 拒绝零写入，并保留临时文件、打印其路径。
  4. **清理：** 成功或普通失败都删除临时文件（解析失败时按上一条保留）。
- **Alternatives considered:** 维持不支持——CI 中 `GIT_EDITOR=true ... --edit` 继续硬失败，拒绝。导出密文明文——泄露风险，拒绝。
- **Consequences:** `docs/commands/config.md` 的「Why no config edit」改写为安全设计说明。
- **Revisit when:** vault 提供受控的交互式编辑。

### ADR-CF-09: `--type` 扩展

- **Status:** Accepted
- **Context:** 条目 5；git `builtin/config.c:151-190`、`:303-379`；`color.c:368-373`；`date.c:957`、`:1413`。
- **Decision:**
  1. **`bool-or-str`：** 可解析为布尔时输出 `true`/`false`，否则原样。**`bool-or-int`：** 可解析为带后缀整数时输出整数，否则按布尔。二者都新增快捷参数。
  2. **`color`：** 新增 `src/utils/config_color.rs`，移植 `color_parse_mem` 语义（颜色名与 `bright` 前缀、0–255、`#rgb`/`#rrggbb`、属性及 `no` 前缀、`reset`、`normal`、最多前景与背景各一）。读取输出 ANSI 序列；写入校验后存储原值；`--list --type=color` 只列出可规范化的值。
  3. **`expiry-date`：** 新增 `src/utils/approxidate.rs`，移植 `parse_expiry_date` 与 `approxidate_careful` 中矩阵覆盖的形式（相对 `<n>.<unit>.ago`、特殊词、绝对日期），绝对日期复用既有提交日期解析。矩阵外的 approxidate 形式按 Git 实跑补充或登记 DEFER-08。
  4. **未知类型：** `fatal: unrecognized --type argument, <t>`，exit 128，`LBR-CLI-002`，修复重复前缀。
- **Alternatives considered:** 只报更清晰的不支持错误——issue 条目 5 仍不成立，拒绝。
- **Consequences:** 颜色与日期解析为新的共享工具，可被后续命令复用。
- **Revisit when:** `color.*` 或 `gc.*Expire` 等配置读取需要同一解析器。

### ADR-CF-10: 保留 `upgrade.*` 规则按作用域收窄

- **Status:** Accepted
- **Context:** N6；`src/command/config.rs:838-875`；plan-20260714 §A.3。
- **Decision:** 能匹配 `upgrade.mode` 的 `--get-regexp` 模式只在读取范围可能包含文件承载的保留条目时（未指定作用域，或 `--global`）fail closed；`--local`、`--system`、`--file`、`--blob` 正常执行，并继续抑制 SQLite 中残留的 `upgrade.*` 行。位置参数与子命令的保留 key 规则不变。
- **Alternatives considered:** 在级联结果中直接包含保留条目——改变 §A.3 已发布契约，超出本 issue，拒绝。
- **Consequences:** 只有不可能包含保留条目的作用域行为变化。
- **Revisit when:** §A.3 修订。

### ADR-CF-11: legacy 参数与子命令共用语义层

- **Status:** Accepted
- **Context:** N8；Libra 文档把子命令作为主接口（`docs/commands/config.md:624`）；git `builtin/config.c:1038-1290`。
- **Decision:**
  1. **单一模型：** legacy 参数与子命令都解析为同一组 `ResolvedCommand`，新增字段 `value_pattern`、`fixed_value`、`all`（`--replace-all`/`set --all`）、`append`、`show_origin`、`show_scope`、`name_only` 与来源 `Scope|File|Stdin|Blob`。
  2. **子命令拼写（Git 2.46+）：**
     - `get [--all] [--regexp] [--value=<p>] [--fixed-value] [--show-origin] [--show-scope] [--default] [--type]`
     - `set [--all] [--value=<p>] [--fixed-value] [--append] [--type]`，Libra 既有 `--add` 保留为 `--append` 的别名
     - `unset [--all] [--value=<p>] [--fixed-value]`
     - `list [--name-only] [--show-origin] [--show-scope] [--type]`
     - `rename-section`、`remove-section`、`edit`
     - Libra 专有参数（`--reveal`、`--encrypt`、`--plaintext`、`--stdin`、`--vault`、`--ssh-keys`、`--gpg-keys`）保留。
  3. **legacy 位置参数：** 第三个位置参数在 get、get-all、get-regexp、set、replace-all、unset、unset-all 下都是 value-pattern；多余位置参数报 exit 129 `wrong number of arguments`。
  4. **名称冲突：** `rename-section`、`remove-section` 作为子命令名优先；合法 key 必须含点，不会与之冲突。
  5. **帮助：** 新增 legacy 参数沿用 `hide = true`；子命令参数在 `--help` 中可见。
- **Alternatives considered:** 只补 legacy 参数——文档声明的主接口无法使用新语义，拒绝。
- **Consequences:** CF-01..CF-14 在 legacy 与子命令两条入口上共用实现；CF-15 负责子命令拼写与表驱动一致性测试。
- **Revisit when:** 废弃 legacy 参数。

### 故障恢复矩阵

| 故障点 | 可接受残留 | 恢复动作 | 禁止结果 |
|---|---|---|---|
| 按模式删除或替换的事务中途失败 | 事务回滚后的原值 | 报 `LBR-IO-002`，提示重试 | 部分值被删除或替换 |
| `--file` 写入时锁或 rename 失败 | 原文件；可能残留 `<file>.lock` 由本进程清理 | 报错并提示检查锁文件 | 半写的配置文件 |
| `edit` 导入解析失败或写入失败 | 原作用域数据；保留的临时文件 | 打印临时文件路径，提示修复后重新编辑 | 部分导入 |
| 解密失败导致值模式无法匹配 | 原数据 | 报 `LBR-REPO-003` | 跳过加密值继续删除或替换 |
| 发布步 `gh release create` 失败 | 已推送的 `main` 提交 | 按 ER-09 记录，下一窗口补 tag/release | blind retry；只推 `main` 就宣称已发布 |
| D 组 `release.yml` 失败 | 已存在的 tag | 前滚修复，发新 patch | 回退已推送提交或删除已发布 artifact |

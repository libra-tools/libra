## 文檔職責

修復 `libra archive --format=tar` 在歸檔路徑或符號連結目標超過固定 header 欄位時提前失敗的問題，使 plain tar 及共用同一 writer 的 `tar.gz`、`tar.bz2` 能由常見 tar reader 完整列出、解出這些條目。實作、回歸測試、雙語命令/開發文檔、相容矩陣、網站與獨立版本發佈均在同一卡完成。

### 適用範圍

- tracked 普通檔案路徑超過 100 bytes，包括 `--prefix` 套用後才超過限制的情況。
- symlink 的 archive path 或其 target 超過 100 bytes；至少覆蓋 Issue 的 116-byte path、111-byte prefix 與 123-byte target 級別，並增加超過 ustar prefix 可分割範圍的長路徑樣本。
- `tar`、`tar.gz`、`tar.bz2` 共用的 `write_tar_archive`；ZIP writer 不改。
- 以 Rust tar parser 驗證邏輯 entry，並以系統 `tar -tf` / `tar -x` 驗證實際互通及 symlink round-trip。

### 非目標

- 不追求與 `git archive` 的 header bytes 逐位相同，也不要求必須使用 pax；本計劃選用 `tar` crate 已驗證的 GNU LongName/LongLink 互通格式。
- 不改 ZIP、pathspec、`export-ignore`、`--add-file` 的來源語義、mtime、mode、壓縮級別或錯誤碼表。
- 不承諾突破宿主檔案系統的 component/path 上限，也不新增無上限記憶體配置；長度只承諾到現有 repository/object 與測試環境可表示、且輸入規模有界的範圍。
- 不承接 #545 的 tree-ish、空歸檔、argv、remote/filter 等廣泛相容工作；#1056 的 `write-tree --prefix` 與 #673/mktree 亦不在本卡。

### 成功定義

Issue 的三類輸入不再以「provided value is too long」失敗：長路徑可由 `tar -tf` 全名列出，長 prefix 保留在全名中，長 symlink target 解包後由 `readlink` 逐值相等；三種 tar 格式均成功。既有短名、Unicode、pathspec、壓縮與錯誤路徑不迴歸。I1059-01 取得適用 A/B/C/D、網站部署與最終全量證據後，本計劃才可收口；產品完成不自動關閉遠端 Issue。

## 已決議設計決策

### ADR-I1059-01：Builder 長 path 與 raw-byte GNU LongLink，不使用 Path 寫 symlink target

- **Status:** Accepted（已實作，發佈驗收中；R1 後修訂）。
- **Context:** 直接 `Header::set_path` / `set_link_name_literal` 只能處理固定欄位；`append_data` 可處理長 path。R1 證實 `append_link` 雖能處理長 target，但其 Path-based `set_link_name` 會移除 `.`、重複 separator 等，違反原 target 逐 byte round-trip；因此不能把 raw-byte `OsStr` 轉 Path 當作無損保證。Git 使用 pax 是格式選擇，不是本 Issue 的 byte-level 驗收條件。
- **Decision:** 普通 entry 與所有 entry path 使用 `Builder::append_data`。`append_tar_symlink` 對固定欄位可容納的 target 使用 `set_link_name_literal`；超過 100 bytes 時以 raw header name `././@LongLink` 寫一個 GNU LongLink (`K`)，size=target bytes + 1、內容為原 target 加 NUL，再以 `append_data` 寫實際 symlink。恰好 100 bytes 的 target 依 crate 行為填滿固定欄位且不帶欄內 NUL，本卡以 GNU/Rust parser 互通為準。NUL target 在寫任何 entry 前拒絕。symlink 保持 size=0/mode/mtime/type；不再使用 `append_link` 或 Path target。plain writer 顯式 flush，gzip/bzip2 顯式 finish 後 flush，避免 drop 吞掉延遲錯誤。
- **Alternatives considered:** `append_link` 互通但會正規化 target，R1 後否決；手寫 pax 可更接近 Git，但增加另一套長度/編碼合同且無必要；繼續直接固定 header API 無法修復；只修普通檔案會留下確定的 symlink 缺口。
- **Consequences:** 輸出可能含 GNU LongName/LongLink 而非 pax 擴展，常見 GNU/BSD tar 與 Rust parser 可讀；raw target（含 separator-heavy、非 UTF-8、長 path+長 target）保持逐 byte 相等。CLI、退出碼與穩定錯誤碼不變。未來 #545 改 writer 必須保留這些行為及錯誤守衛。
- **Revisit when:** 維護者新增「必須 pax / Git byte-identical」合同，或依賴 crate 提供同時支援長名與 literal raw target 的公開 API 且互通測試完全一致。

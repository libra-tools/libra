> 模板版本：v2.16。本计划不在 `code-only` 具名范围内，实现卡按默认版本化发布合同执行（`independent`、`patch + 1`、`gh release`）。来源：[libra-tools/libra#541](https://github.com/libra-tools/libra/issues/541)（OPEN）。事实基线为 `main` @ `07bffa6885604553babc45d2148c3fe53341e868`（`Cargo.toml:3`、`Cargo.lock:6480`、`install.sh:21` 和 `install.ps1:25` 均为 `0.30.160`），2026-11-08。本文只规划，不宣称实现完成；所有行号开工时按 ER-02 刷新。`plan-status.md` 由协调者在同一提交登记，本文件不代替该登记。本轮只修订本文，不改动源码、测试或其它计划。

## 文档职责

本文处理 #541 正文与全部 20 条评论在上述 baseline 上仍成立、且未被 [`issues/479.md`](479.md) 交付的 `update-ref` 缺口。交付范围是既有 SQLite 模型能够完整表达的 `HEAD`、`refs/tags/*`、`refs/remotes/*` 和 `--create-reflog`；伪引用、任意命名空间、符号引用协议及未承接的 HEAD 形式保持明确拒绝。本文不重做 #479 的 stdin 事务，也不把下游命令的独立缺口写成已通过。

### 适用范围

- 符号 `HEAD` 默认解引用到当前分支，detached `HEAD` 更新当前 worktree 的 commit；覆盖 TC-0760/0761/0762、TC-3174/3175/3176。
- `refs/tags/*` 的位置参数与 stdin 更新；目标可以是已存在 commit、tag、tree 或 blob，保存原对象 id，不隐式 peel；覆盖 TC-1044、TC-2908、TC-3062..3066。
- `refs/remotes/<remote>/<branch>` 和直接指向对象 id 的 `refs/remotes/<remote>/HEAD`；覆盖评论 3–11 与 TC-2094/2095 的 update-ref 前置步骤。
- remote HEAD 的 Result 型读取、同事务写入/删除和故障零写；这是 #556 统一解析器及 SY-03 的强制前置。
- `--create-reflog` 的兼容接受；Libra 既有实现本来就在成功更新时写 reflog，因此该 flag 是受文档化约束的 no-op（TC-3173）。
- 所有路径继续共用 CAS、reflog、分支策略与单 SQLite 写事务；HEAD 与当前完整分支名的 stdin 别名按同一底层 ref 去重。
- EN、zh-CN、开发文档、网站页、`COMPATIBILITY.md:243`、必要的 `docs/error-codes.md:97` 和上游复核记录。

### 非目标

- 不重做 #479 UR-01 已交付的 heads CRUD/CAS、`--stdin [-z]`、`start/prepare/commit/abort`、`verify` 和整批原子性。正文“拒绝 `--stdin`”已过时。
- 不实现 stdin `symref-update` / `symref-create` / `symref-delete` / `symref-verify`；当前 `src/command/update_ref.rs:418-421` 的 129 拒绝保留（DEFER-UR-05）。
- 不为 CHERRY_PICK_HEAD、ORIG_HEAD、MERGE_HEAD、REVERT_HEAD、REBASE_HEAD、FETCH_HEAD、AUTO_MERGE 建第二可写存储（DEFER-UR-01）。
- 不实现 `refs/notes/*`、prefetch、rebase-merge、bundle、odd 等任意命名空间；只写而不可被 notes/log/for-each-ref 读取不算交付（DEFER-UR-02）。
- 不实现位置参数 `--no-deref HEAD`、`-d HEAD`、stdin 对 HEAD 的 no-deref/delete、unborn HEAD 创建，也不实现经符号 remote HEAD 更新目标（DEFER-UR-03/04）。这些组合必须 fail-closed，不能变成静默 no-op。
- 不补齐 direct/detached remote HEAD 在 `branch -r/-a`、`show-ref`、`for-each-ref` 的列表渲染；本计划只保证 `rev-parse` 与更新事务可读直接值（DEFER-UR-06）。
- 不修 branch -M、颜色、upstream、checkout 编码、commit/describe/fsck/notes/pull/log 的下游独立缺口。
- 不新增稳定错误码，不改变全局 JSON/错误渲染，不承诺整条上游 TC 仅因 setup 解除就通过。
- 不默认关闭 #541；DEFER 仍存在，回复和关闭须另经用户确认。

### 成功定义

- URM-01 交付完整、fallible 的 remote HEAD 读写；任何被本计划承诺处理的 DB 错误都不得被当成 ref 不存在。读取/写入能否安全拆成独立卡须先解决 checkout 消费者及 G-03，未解决前不开放直接引用。
- remote 分支、tag argv、tag stdin、HEAD argv、HEAD stdin 和 create-reflog 分别形成可独立恢复、独立发布的切片。
- HEAD/当前分支别名混合批在任何写入前按底层 ref 身份拒绝，refs 与两类 reflog 均不变。
- 所有未承接组合有稳定拒绝和准确文档；既有 heads/stdin/策略/worktree 合同无回归。
- 十二张当前实现卡均 `done` / `complete`，各自 CLI 与适用网站 D 证据齐全；若 G-03 拆卡继续，数量及依赖须随之修订。URD-01、URA-01 和 CLOSE-541 如实收口，issue 默认保持 OPEN。

### 本机 Git 行为复核

| 行为 | Git 2.56.0 实测 | 计划决策 |
|---|---|---|
| `update-ref HEAD <B> <A>` | 当前分支 A→B；带 `-m` 时 HEAD 和分支各一条 reflog | URH-01 |
| detached HEAD 更新 | 移动 HEAD，不移动分支 | URH-01 |
| `--no-deref HEAD` | detach HEAD，分支不动 | DEFER-UR-03，Libra 继续拒绝 |
| `-d HEAD` | 可删除 HEAD，随后仓库不再被该探针识别 | DEFER-UR-03，不复用已破坏夹具 |
| tag object/blob | tag ref 可保存原 tag/blob id | URT-01，不强制 commit |
| direct remote HEAD | update-ref 创建直接 ref，不是 symbolic ref | URM-01；符号形式由 #556 SY-03 |
| HEAD+当前分支 update/create/delete/verify 混合批 | 均以 128 拒绝：`multiple updates for 'refs/heads/main' (including one via symref 'HEAD') are not allowed`；状态不变 | URH-02 按底层 ref 身份去重 |
| stdin `option no-deref` 或 argv `--no-deref --stdin` 后更新 HEAD | Git detach HEAD，分支不动 | Libra 本计划明确拒绝，零写 |
| stdin `delete HEAD` | Git 删除当前分支并留下 symbolic HEAD | 本计划不承接，明确拒绝并零写 |
| `--create-reflog` | 成功且可读到带原因的 reflog | URC-01 no-op 接受 |

## 已决议设计决策

### ADR-UR-01：按现有存储能力拆分，不建万能 ref 存储

- **Status:** Accepted
- **Decision:** 本地/remote Branch、Tag、Head 各用既有行语义；伪引用和任意 namespace 不建半接入存储。
- **Alternatives considered:** 通用 ref 大迁移需要完整读者矩阵，超出本 issue；tag 伪装成 Branch 会破坏读者。
- **Consequences:** #541 完成后仍有 DEFER，不能宣称完整 update-ref。
- **Revisit when:** 另立通用 ref backend ADR。

### ADR-UR-02：先修 remote HEAD 已有读写错误通道，再开放直接引用

- **Status:** Accepted
- **Context:** lossy 查询同时存在于读取和 writer 内部；只修第一跳 CAS 不足。另见 GAP-08：checkout 自身仍把 Result 变成 Option，且可能已创建分支。
- **Decision:** `query_remote_head_with_conn` 改为 `Result<Option<_>>`；`remote_current_result_with_conn`、写入和新增删除 helper 全部在同一连接/事务使用它。busy 有界重试后仍为 Err；非 busy、损坏和重复行均 Err。update-ref 遇到 Head::Branch 符号行时拒绝，不写为 Detached。
- **Alternatives considered:** 在 CLI 先做一次 fallible 查询但保留 writer 内部 lossy 查询：仍有第二个插入窗口；由 #556 后补：会让 #541 先发布错误 CAS。若以后拆出读者/写者卡，须先证明每个已发布中间态及所有消费者安全，不能把现有故障保护或其测试拖到直接写入口之后。
- **Consequences:** URM-01 写集包含 `src/internal/head.rs`；GAP-08 必须先完成归属、精确写集与不留部分写入的设计。本卡现仍超限且不得开工。#556 的接收须按交接协议确认，不能单方宣称复用已生效。
- **Revisit when:** remote HEAD 存储模型改变。

### ADR-UR-03：tag 保存原对象 id

- **Status:** Accepted
- **Decision:** tag ref 检查对象存在但不做 commit-only/peel；argv 与 stdin 分卡交付，共用同一事务路由。
- **Consequences:** `docs/error-codes.md:97` 必须限定 commit-only 示例为 local branch、HEAD 和本计划支持的 remote branch，不包括 tag。
- **Revisit when:** Tag 模型或 revision 解析合同改变。

### ADR-UR-04：HEAD 默认解引用，别名按底层身份去重

- **Status:** Accepted
- **Decision:** attached HEAD 更新当前分支并写双 reflog；detached HEAD 更新 scoped Head 行。stdin prepare 做统一快照预检，commit 写事务内先重新固定所有 HEAD 路由并完成 canonical 去重，再执行任何写入。`HEAD` 与当前 `refs/heads/<branch>` 的 update/create/delete/verify 都是重复；detached HEAD 的身份是 HEAD 自身。
- **Alternatives considered:** 继续按输入字符串去重会双写；在事务外固定 HEAD 有切换窗口；顺带实现 no-deref/delete/unborn 会扩大行为轴。
- **Consequences:** 所有 DEFER-UR-03 形式明确 128/既有分类拒绝，refs/reflog 不变；`option deref` 保持未知选项拒绝（Git 探针 exit 128；`src/command/update_ref.rs:1516`）。
- **Revisit when:** 用户明确要求未承接 HEAD 状态转换。

### ADR-UR-05：direct remote HEAD 与符号 remote HEAD 不互相覆盖

- **Status:** Accepted
- **Decision:** URM-01 只对 missing/Detached 行做直接更新；预置 Head::Branch 的 update/create/delete/verify 无论默认解引用、argv `--no-deref` 或 stdin `option no-deref` 均拒绝且不写目标。SY-03 对 Detached 行的 symbolic-ref set/read/delete 也拒绝，保留 DEFER-SY-03；两个方向均有真实测试。
- **Consequences:** 不需要双向依赖，也不存在“谁先交付谁覆盖”的窗口。
- **Revisit when:** 另立直接 ref 与符号 ref 相互覆盖的原子策略卡。

### ADR-UR-06：`--create-reflog` 为兼容 no-op

- **Status:** Accepted
- **Decision:** 注册 flag，但不新增按配置开关 reflog 的引擎；文档说明 Libra 成功更新本即写日志。
- **Revisit when:** 引入可关闭的 reflog 策略。

## 全局工程约束

- **GC-UR-01 单一路由：** argv/stdin 共用 ref 分类、CAS 和写入；tag helper 在 tag 存储层，remote 复用 Branch/Head，不在批量路径复制规则。
- **GC-UR-02 原子快照：** 当前值、CAS、策略、ref 写入和 reflog 在事务内；任何失败 refs/reflog 不变。SELECT/写入故障不得被转成 missing/no-op。
- **GC-UR-03 HEAD 固定：** HEAD 形态、WorktreeScope 和目标分支在事务内固定；另一 worktree 的 Head 行与 HEAD reflog 不变。
- **GC-UR-04 校验：** 完整 refname 与对象存在性检查 fail-closed；branch/HEAD 仍 commit-only，tag 不 peel；remote 不套本地 checkout 守卫。
- **GC-UR-05 既有合同：** heads 的 `-z`、重复更新、事务状态机、abort、stdout closed 和整批回滚测试不得削弱。范围外回归改用 `refs/notes/v1`，不能删除原子性断言。
- **GC-UR-06 文档：** `COMPATIBILITY.md:243` 原地更新且不增删物理行；逐卡同步 EN/zh/dev/网站，区分支持、no-op 和 DEFER。
- **GC-UR-07 精确写集：** 只暂存本卡文件；发现他人改动即停，不清理、不混入。
- **GC-UR-08 跨计划联合：** URM-01 用 seeded Head::Branch 做 update-ref 拒绝测试；#556 SY-03 必须运行 direct→symbolic-ref 与 symbolic→update-ref 两个真实 CLI 方向，不接受条件跳过。
- **GC-UR-09 证据卫生：** 计划内只写 sanitized 摘要；不记录 secret、PII、私有路径或未脱敏 transcript。
- **GC-UR-10 no-JUnit 与重跑安全：** 本计划每条 nextest 命令都使用下面的 `run_nextest` / `check_exact_set`（`run_exact`、`run_exact_names` 分别封装它们）执行。配置只能在规范化验证的仓外新建 0700 私有目录内由 `mkstemp` 独占创建；禁止用 `>` 写到调用者路径、复用已有配置、跟随 symlink 或经 `..` 指回仓库。每次运行生成不同配置，普通 Cargo 编译缓存可以复用；不设置“必须不存在”的共享测试输出目录，也不清理其它轮次内容。

```bash
TASK_NEXTEST_DIR="$(python3 -I -c 'import pathlib,tempfile; root=pathlib.Path.cwd().resolve(); base=pathlib.Path("/tmp").resolve(strict=True); assert base != root and root not in base.parents; print(tempfile.mkdtemp(prefix="libra-541-nextest-",dir=base))')" || exit
export TASK_NEXTEST_DIR
prepare_nextest_cfg() {
  NEXTEST_NOJUNIT_CFG="$(python3 -I -c 'import os,pathlib,stat,sys,tempfile; root=pathlib.Path.cwd().resolve(); d=pathlib.Path(sys.argv[1]); real=d.resolve(strict=True); st=d.lstat(); assert d.is_absolute() and not stat.S_ISLNK(st.st_mode) and real==d and root != real and root not in real.parents and st.st_uid==os.getuid() and stat.S_IMODE(st.st_mode)==0o700; s=pathlib.Path(".config/nextest.toml").read_text(); a="[profile.default.junit]\npath = \"junit.xml\"\n"; assert s.count(a)==1 and s.count(".junit]")==1; fd,p=tempfile.mkstemp(prefix="nextest-",suffix=".toml",dir=real); f=os.fdopen(fd,"w"); f.write(s.replace(a,"",1)); f.close(); print(p)' "$TASK_NEXTEST_DIR")" || return
  export NEXTEST_NOJUNIT_CFG
}
run_nextest() {
  prepare_nextest_cfg || return
  cargo nextest run --config-file "$NEXTEST_NOJUNIT_CFG" "$@"
}
run_exact() {
  local target="$1" name="$2"
  shift 2
  if [ "$target" = --lib ]; then
    run_nextest --lib --no-tests=fail -E "test(=$name)" "$@"
  else
    run_nextest --test "$target" --no-tests=fail -E "test(=$name)" "$@"
  fi
}
check_exact_set() {
  local target="$1" ignored="$2" expected="$3" expr="$4"
  shift 4
  local -a selector=()
  [ "$target" = --lib ] && selector=(--lib) || selector=(--test "$target")
  case "$ignored" in default|only) ;; *) return 2 ;; esac
  prepare_nextest_cfg || return
  (set -o pipefail
   cargo nextest list --config-file "$NEXTEST_NOJUNIT_CFG" --user-config-file none --show-progress none --ignore-default-filter "${selector[@]}" --run-ignored "$ignored" -E "$expr" -T oneline "$@" |
     python3 -I -c 'import sys; expected=sys.argv[1].splitlines(); found=sys.stdin.read().splitlines(); names=[line.split(None,1)[1] for line in found]; assert expected and len(set(expected))==len(expected) and sorted(names)==sorted(expected), {"expected":expected,"found":names}' "$expected") || return
  cargo nextest run --config-file "$NEXTEST_NOJUNIT_CFG" --user-config-file none --ignore-default-filter --no-tests=fail --no-fail-fast --status-level pass --final-status-level all "${selector[@]}" --run-ignored "$ignored" -E "$expr" "$@"
}
run_exact_names() {
  local target="$1" ignored="$2" expected expr="" name
  shift 2
  [ "$#" -gt 0 ] || return 2
  printf -v expected '%s\n' "$@"
  for name in "$@"; do
    [[ "$name" =~ ^[a-zA-Z0-9_]+(::[a-zA-Z0-9_]+)*$ ]] || return 2
    [ -z "$expr" ] || expr+=" or "
    expr+="test(=$name)"
  done
  check_exact_set "$target" "$ignored" "$expected" "$expr"
}
```

模板 G-05 只要求确切命令，不要求每个测试各跑一次。单一测试用 `run_exact target '完整函数名'`；多个同类必需测试用 `check_exact_set target ignored 期望的完整函数名清单 'test(=name1) or test(=name2)'`，`ignored` 为 `default` 或 `only`。该门先以 `nextest list` 验证实际选中且可运行的完整名称与预期集合**完全一致**，零命中、漏名、额外名、错误 ignored 分类及默认 filter 排除均失败；再以完全相同的 selector、filterset、ignored mode 和 `--ignore-default-filter` 执行，并显示并记录逐测试 terminal status。不能用宽泛前缀的非零命中替代此集合校验。每次 `check_exact_set` 的 list 判定和 run 判定按 G-03 分别计两门，里面测试覆盖的行为谓词仍分别计入 AC。

```bash
TASK_URM01_TESTS="$(printf '%s\n' 'command::update_ref_test::urm01_example_a' 'command::update_ref_test::urm01_example_b')"
check_exact_set command_test default "$TASK_URM01_TESTS" 'test(=command::update_ref_test::urm01_example_a) or test(=command::update_ref_test::urm01_example_b)'
```

`run_exact_names target ignored 完整测试名...` 依上述清单生成精确表达式，仍按 list 和 run 各计一门；不接受空清单、重复名或非法名称。该集合 helper 已在独立临时 Rust 测试夹具验证：完全匹配及 only-ignored 成功，漏项、多项和默认模式选 ignored 均失败；这不是本计划新增测试已实现的证据。

环境 gate 或平台 guard 不能造成静默跳过：这类测试在隔离前置条件满足后执行，加 `--no-capture` 并在结果中记录实际 terminal status 和实际 setup；缺前置保持 blocked，而不是把 skip 算作通过。`nextest list` 的 oneline 解析规则已对照本机 nextest-runner 0.122.1 `src/list/test_list.rs:2316-2327`，固定 cargo-nextest 0.9.143。

根配置的 JUnit 段若与断言不符即停止，不得静默删除其它配置。每轮配置路径均唯一且不会覆盖已有内容；只需清理本轮经上述检查的专属目录，不要求重建 Cargo target 缓存。

## 文档职责

issue #480 是一次写于 libra 0.22.5 的批量对照。本计划在 libra 0.22.28 与 git 2.54.0 上用本地路径仓库分两轮并排实跑，逐条复核正文的全部断言与「Test gaps」一节，目标是**完全解决**正文描述的全部问题。结论分三类：

- **已修复或断言不成立：**
  - `remote rename` 已迁移 tracking ref、`branch.*.remote` 与 refspec 目标；`remote set-head`、`set-branches`、`add --tags/--no-tags`、`fetch --all` 已存在。
  - 「显式 refspec 的 fetch 不写 `branch.<b>.remote/merge`」与 Git 一致（Git 只在 `--set-upstream` 时写）。
  - 「Git 的 `pull` 没有 `--allow-unrelated-histories`」不成立：Git `pull` 有该参数（`builtin/pull.c:938`）。
  - 「`pull --rebase` 遇到无关历史时 Git 也失败」不成立：git 2.54 成功把本地提交重放到上游之上。
  - 「`pull f1 main` 在 fetch 后无法合并」对存在的分支不复现；真实差异是远端分支不存在时的诊断文案。
  - `rerere enable/disable` 在 Git 中同样不存在；rerere 自动记录与重放已可用。
  - `push -d <tag>`（#465）已修复并有回归测试。
- **确认的缺口：**
  - `remote add` 不写默认 `remote.<name>.fetch`；`--mirror=fetch|push` 不可用，裸 `--mirror` 不写 `+refs/*:refs/*`。
  - `fetch` 缺 `--set-upstream`、`--atomic`、`--update-head-ok`、`--refmap`、`--prune-tags/-P`、`--negotiation-tip`、`--unshallow`。
  - `pull` 缺 `--allow-unrelated-histories` 与对应提示。
  - 本地路径 `push` 被拒绝（D2）。
  - `credential store` 必须在仓库内；`rerere remaining` 缺失。
- **issue 未列出的新发现：**
  - `fetch`/`pull`/`push` 不接受路径或 URL 作为仓库参数（只有 `ls-remote` 接受）。
  - `remote rename` 不改写仓库级 `remote.pushDefault`。
  - `pull --rebase` 与 `rebase <upstream>` 在无关历史上报 `no common ancestor found`。
  - Libra 不能作为 Git 的 `credential.helper`：Git 调用 `get`，Libra 只有 `fill`。

本计划按依赖交付 16 张卡，分五个 Phase：
1. **Phase 1（remote 配置）：** HP-01、HP-02。
2. **Phase 2（fetch/pull 参数）：** HP-03、HP-04、HP-05、HP-10。
3. **Phase 3（仓库参数、诊断与本地 push，部分重开 D2）：** HP-06、HP-11、HP-07、HP-08、HP-09。
4. **Phase 4（历史与凭据）：** HP-12、HP-13、HP-14、HP-15。
5. **Phase 5（承接 477 DEFER-08）：** HP-16。

本文只规划任务，不宣称实现完成。落地时每个任务都必须先刷新源码锚点，再按任务卡验收。

### 适用范围

- `remote add` 的默认 fetch refspec 与 `--mirror[=fetch|push]`；`remote rename` 对仓库级 `remote.pushDefault` 与 `branch.*.pushRemote` 的改写。
- `fetch` 的 `--set-upstream`、`--update-head-ok`、`--refmap`、`--atomic`、`--prune-tags/-P`、`--negotiation-tip`、`--unshallow`。
- `fetch`/`pull`/`push` 接受本地路径与 `file://` URL 作为仓库参数（匿名远端）。
- 本地路径 `push`：目标为本地 Libra 仓库与本地 Git 仓库，含 refspec 矩阵、`-u`、`--dry-run`、`--porcelain`、`--delete`、`--tags`、`--follow-tags`、`--atomic`、`--force-with-lease`、`--mirror`，以及非裸目标的检出分支保护。
- `pull --allow-unrelated-histories` 与无关历史提示；远端分支不存在时的诊断。
- `pull --rebase` 与 `rebase <upstream>` 在无关历史上的重放。
- `credential` 作为 Git 凭据助手的 `get/store/erase` 操作名；仓库外的 `store/fill/erase`。
- `rerere remaining`。
- `branch.<b>.remote=.`（当前仓库作为远端）的 `fetch`/`pull`/`push`（承接 issues/477 DEFER-08）。
- SSH 传输入口的 host-key 校验与交互式指纹确认，以及 `clone`/网络 transport 的启动与失败诊断（issue #560，HP-17）。
- 「Test gaps」一节列出的 `t5505`、`t5510`、`t5516`、`t5520/t5521`、`t0300/t0302`、`t4200` 场景移植。
- 同步：相关命令 `docs/commands/` EN + zh-CN、`docs/development/commands/`、`docs/development/commands/_compatibility.md`、`COMPATIBILITY.md` 相关行、`../libra-backend` 网站文档。

### 非目标

- `git://` 与 HTTPS 的完整传输行为（本计划只扩展本地路径、`file://` 与 SSH 传输入口，见 HP-17）；`protocol v2` 与 packfile 协商的深层行为。
- 本地 Libra 源的浅克隆协商（D20 维持 fail-closed）；push 侧 `refs/notes/deps` 旅行（D17 维持延后）。
- 目标仓库上的服务端 hook（`pre-receive`/`update`/`post-receive`，D3 维持拒绝）；`receive.denyCurrentBranch=updateInstead` 与 `push-to-checkout`（DEFER-01）。
- `fetch`/`push` 输出流与格式的逐字节对齐（Libra 写 stdout 且用 `[new ref]`，Git 写 stderr 且用 `[new branch]`，DEFER-02）。
- `branch -a` 的远端行格式（`remotes/<r>/<b>`、`HEAD ->` 行）：由 issues/477 HF-09 的 M-LIST V6 承接，本计划不重复规划。
- 未设置 `pull.rebase` 时 Git 对分叉历史的「divergent branches」提示（DEFER-03）。
- `credential-cache`、多用户名、`credential.helper` 链（COMPATIBILITY 已登记为不暴露）。
- 远端分支不存在时把退出码改为 Git 的 1（ADR-HP-02）。

### ADR-HP-02: 退出码模型

- **Status:** Accepted
- **Context:** Git 对「远端分支不存在」「非快进拒绝」「检出分支拒绝」多为 exit 1；Libra 的稳定错误码表把用法与无效目标映射为 129、运行期拒绝映射为 128。[`issues/479.md`](479.md) ADR-PL-02 与 [`issues/477.md`](477.md) ADR-HF-02 已决定保留文档化退出码。
- **Decision:**
  1. 本计划新增或修改的错误保留 128/129 与现有稳定错误码：远端分支不存在 129 + `LBR-CLI-003`；非快进与检出分支拒绝 128 + `LBR-CONFLICT-002`；目标锁定与对象格式不一致 128 + 现有仓库状态码。
  2. `push` 部分 ref 被拒绝时沿用网络 push 的既有退出与 `--porcelain` 行为，本地目标不另起一套。
  3. 脚本通过 `Error-Code:`、JSON `error_code` 或 `LIBRA_FINE_EXIT_CODES=1` 区分拒绝类型。
- **Alternatives considered:** 按 Git 改为 exit 1——与 479/477 的决策冲突，且 issue 未对这些退出码提出要求，拒绝。
- **Consequences:** 差异在 fetch、pull、push 行登记为有意差异。
- **Revisit when:** 稳定错误码表进行 major 调整。

### ADR-HP-03: remote 配置写入

- **Status:** Accepted
- **Context:** GAP-01、GAP-02；git `builtin/remote.c:126-160`、`:227-240`、`:820-840`、`:981`。
- **Decision:**
  1. **默认 refspec：** `remote add` 未给 `-t` 时写 `+refs/heads/*:refs/remotes/<name>/*`；给 `-t` 时逐分支写（现状）。
  2. **镜像：** `--mirror[=fetch|push]` 接受可选值。无值时输出 Git 同义弃用警告并视为 fetch+push；`fetch` 形态写 `+refs/*:refs/*` 与 `mirror=true`；`push` 形态只写 `mirror=true`。组合限制按 M-ADD A7。
  3. **既有远端不迁移：** 旧版本创建、无 fetch 配置的远端继续使用隐式默认映射，`fetch` 不改写配置。
  4. **rename：** 在既有事务内同时改写仓库级 `remote.pushDefault` 与所有 `branch.<b>.pushRemote`；全局/系统级 `remote.pushDefault` 不改，输出 Git 同义警告。
- **Alternatives considered:** 首次 fetch 时补写默认 refspec——静默修改用户配置，拒绝。
- **Consequences:** `remote add` 的配置输出变化写入文档；`remote show` 与 `fetch` 行为不变。
- **Revisit when:** 无。

### ADR-HP-04: fetch 参数语义

- **Status:** Accepted
- **Context:** GAP-03..05；git `builtin/fetch.c:1521`、`:2541-2613`；`t5510`、`t5553`、`t5537`。
- **Decision:**
  1. **`--set-upstream`：** 仅当命令行给出远端与单个分支来源时，为当前分支写 `branch.<cur>.remote/merge`；远端为 URL 时 `remote` 写 URL（`t5553:85`）。
  2. **`--update-head-ok`：** 仅放开「目标为当前检出分支」的既有拒绝；非快进规则不变；其它工作树检出的分支仍拒绝。
  3. **`--refmap=<spec>`：** 替换配置映射用于命令行 refspec 的目标推导；空值表示不更新 tracking ref；无命令行 refspec 时报错。
  4. **`--atomic`：** 所有 ref、reflog 与 `FETCH_HEAD` 在一次元数据事务内提交；任一更新被拒绝则整体不提交，对象保留为未引用对象。
  5. **`--prune-tags` / `-P`：** 语义与 `fetch.pruneTags`、`remote.<n>.pruneTags` 配置矩阵一致；显式 refspec 时忽略。
  6. **`--negotiation-tip`：** 限定协商时发送的 have；本地传输同样生效（本地传输以限定集计算可达对象差集）。
  7. **`--unshallow`：** 对 Git 源（网络或本地 Git 仓库）补全 shallow 边界；对本地 Libra 源按 D20 fail-closed。
- **Alternatives considered:** 对本地传输把 `--negotiation-tip` 视为 no-op——与上游 `t5510:1536-1600` 断言不符，拒绝。
- **Consequences:** fetch 文档与 `COMPATIBILITY.md:223` 中「`--refmap`、`--atomic`、shallow-expansion flags remain deferred」一句随 HP-04/HP-05 改写。
- **Revisit when:** 无。

### ADR-HP-05: 路径与 URL 作为仓库参数

- **Status:** Accepted
- **Context:** GAP-06；N1；git `transport.c:1223-1270`。
- **Decision:**
  1. **解析顺序：** `fetch`/`pull`/`push` 的仓库参数先按已配置远端名解析；否则若为 `file://` URL、绝对路径或相对路径（含 `.`、`..`）且指向 Libra 或 Git 仓库，则作为匿名远端；否则报远端不存在。
  2. **匿名 fetch：** 只写 `FETCH_HEAD`，不写 tracking ref、不写 `remote.*` 配置。
  3. **匿名 pull：** 合并或变基 `FETCH_HEAD`，其余规则与已配置远端相同；合并消息为 `Merge branch '<b>' of <url>`。
  4. **匿名 push：** 与已配置本地路径远端走同一本地目标路径（HP-07/HP-08）；`-u` 对匿名远端以 git 实跑为准。
  5. **`.`：** 当前仓库作为远端的语义由 HP-16 实现；HP-06 期间 `.` 按「路径指向当前仓库」解析，但 `push .` 与 `pull .` 的 ref 更新规则在 HP-16 完成前保持 fail-closed。
- **Alternatives considered:** 自动为路径创建临时远端配置——污染配置且与 Git 不一致，拒绝。
- **Consequences:** `ls-remote` 已有的路径解析逻辑被抽取为三命令共用的解析函数。
- **Revisit when:** 支持 `url.<base>.insteadOf` 改写。

### ADR-HP-06: 部分重开 D2，本地路径 push

- **Status:** Accepted
- **Context:**
  - GAP-07；issue 将本地路径 push 标为 P1。
  - D2 的重启条件是「明确本地多工作树协作场景，并完成 lock/恢复语义设计」（`_compatibility.md:112-115`）。本 ADR 给出场景（本地同步、CI 产物仓库、离线测试）与 lock/恢复设计。
  - 本地 fetch 通过进程级 cwd 切换读取源仓库（`local_client.rs:61-96`），不适合写入目标。
- **Decision:**
  1. **范围：** 目标为本地 Libra 仓库（裸与非裸）与本地 Git 仓库（裸与非裸）；来源为当前 Libra 仓库。服务端 hook 不运行（D3）；`receive.denyCurrentBranch=updateInstead` 与 `push-to-checkout` 延后（DEFER-01）。
  2. **目标访问：** 按路径打开目标存储，不切换进程 cwd。Libra 目标使用独立的数据库连接与对象库句柄；Git 目标直接读写 `.git`（或裸仓库根）下的对象与 ref 文件。
  3. **计划构建复用：** refspec 解析、`--force-with-lease`、`--atomic`、`--follow-tags`、`--mirror`、`--tags`、删除解析复用网络 push 的计划构建；目标「广告 ref」由本地读取目标 ref 得到。
  4. **写入顺序：** 先把缺失对象写入目标（Libra 目标写对象库；Git 目标写 pack 与 idx，复用 issues/487 修复后的 pack 编码），fsync 策略遵循 `--sync-data`；再在目标锁内逐 ref 比较旧值后更新并写 reflog。
  5. **锁与原子性：** Libra 目标在一次元数据写事务内完成全部 ref 更新；Git 目标对每个 ref 取 `<ref>.lock`，`--atomic` 时先取全部锁再依次提交，任一失败则释放全部锁且不提交。锁获取超时报错并零写入。
  6. **检出分支保护：** 非裸目标上当前检出的分支（Libra 目标包括其全部工作树）默认拒绝更新，文案与 Git 一致；目标配置 `receive.denyCurrentBranch=ignore|warn` 时按 Git 语义放行。
  7. **一致性检查：** 源与目标对象格式不一致时 fail-closed；目标为 shallow 仓库时按 Git 规则拒绝不完整历史（以 git 实跑为准）。
  8. **不带出的内容：** `refs/notes/deps` 不随 push 旅行（D17）。
- **Alternatives considered:**
  - 在目标目录下启动 `git receive-pack` 子进程——Libra 目标不适用，且违背仓库不依赖系统 git 的约定，拒绝。
  - 复用本地 fetch 的 cwd 切换——多线程下与其它操作共享进程 cwd，写入场景风险不可接受，拒绝。
- **Consequences:** D2 在 HP-09 完成后修订为「本地 push 已实现，`updateInstead`、服务端 hook 延后」；`docs/commands/push.md:431-433` 一节改写。
- **Revisit when:** 需要 `updateInstead` 或目标侧 hook。

### ADR-HP-07: pull 的无关历史与缺失分支诊断

- **Status:** Accepted
- **Context:** GAP-08、GAP-09；git `builtin/pull.c:566`、`:938-940`；`builtin/merge.c:1642-1644`；`remote.c:2157`。

### ADR-HP-08: 无关历史上的 rebase

### ADR-HP-09: credential 助手协议与仓库外存储

- **Status:** Accepted
- **Context:** GAP-11、GAP-12；git `builtin/credential-store.c:169-216`、`t/lib-credential.sh:67`；`src/command/credential.rs:188-220`；`src/internal/auth.rs:370`。
- **Decision:**
  1. **助手操作名：** 新增 `get` 作为 `fill` 的助手协议别名，`store`、`erase` 保持现名；三者在 Git 以 `credential.helper` 调用时读写助手协议帧。未知操作按 Git 助手约定静默忽略（以 git 实跑为准）。
  2. **仓库外存储：** 不在 Libra 仓库内（或仓库无 vault）时，`store/fill/erase` 使用用户级加密凭据存储，复用全局 auth 存储的密钥与加密原语，条目仍以 protocol/host/path 的 SHA-256 摘要为键。

- **Alternatives considered:** 仓库外继续拒绝并在文档说明——与 issue 要求的「作为全局助手可用」相反，拒绝。明文 `~/.git-credentials` 兼容格式——违背 Libra 不落明文秘密的约束，拒绝。
- **Consequences:** `COMPATIBILITY.md:247` 改写「vault 是仓库级」的表述。
- **Revisit when:** 需要 `credential-cache` 或助手链。

### ADR-HP-10: `rerere remaining`

### ADR-HP-12: SSH 传输入口与 host-key 校验（issue #560）

**决策:** 新增 HP-17，为经 SSH 的 `clone`/`fetch`/`pull`/`push` 提供 host-key 校验与「缺项时的可操作失败诊断」。不在 `~/.ssh/known_hosts` 时不再静默/硬失败，而是优先交互式指纹确认（与 Git 一致），无法交互时给出明确诊断与手动更新 `known_hosts` 的修复指引。

**理由:** #560 实测 `libra clone git@github.com:...` 在 `known_hosts` 缺 host key 时立即 `fatal: SSH host key could not be verified`；Git 会先进行主机指纹确认。Libra 将 network transport 的 host-key 处理作为一个可发布切片，属本计划「remote/credential」范围，但实现上与本地路径/`file://` 卡共享 transport/credential 写集（DEP-HP-10）。

**Alternatives considered:** 维持现状（硬失败）——用户需手工添加 host key，首次连接体验差。
**Consequences:** HP-17 依赖 DEP-HP-10 写集互斥；`clone`/SSH 路径首次可用，首次连接诊断可操作化。
**Revisit when:** 全量 HTTPS/git:// 传输接入时（其时 transport 层深层行为由后续计划处理）。

### 故障恢复矩阵

| 故障点 | 可接受残留 | 恢复动作 | 禁止结果 |
|---|---|---|---|
| 本地 push 对象写入完成、ref 更新前进程中断 | 目标中的未引用对象 | 下次 push 复用或由目标 gc 清理 | 目标 ref 或 reflog 半更新 |
| Git 目标 ref 锁获取失败或残留 `.lock` | 本次创建的 `.lock` 已清理；他人的 `.lock` 保留 | 报错并提示检查目标上的其它进程 | 删除他人的锁文件；强行覆盖 ref |
| `--atomic` 中途某个 ref 被拒绝 | 已取得的锁全部释放 | 报告被拒绝的 ref | 部分 ref 已提交 |
| `fetch --atomic` 事务提交失败 | 已下载对象 | 报错，ref 与 `FETCH_HEAD` 保持原状 | 部分 tracking ref 已更新 |
| 用户级凭据文件损坏或无法解密 | 原文件保留 | 视为未命中并在 stderr 提示用 `erase` 重建 | 输出部分解密的秘密；静默覆盖 |
| 源与目标对象格式不一致 | 无写入 | fail-closed 报错 | 以错误哈希写入目标 |
| 发布步 `gh release create` 失败 | 已推送的 `main` 提交 | 按 ER-09 记录，下一窗口补 tag/release | blind retry；只推 `main` 就宣称已发布 |
| D 组 `release.yml` 失败 | 已存在的 tag | 前滚修复，发新 patch | 回退已推送提交或删除已发布 artifact |

## 性能与容量摘要

| 操作 | 单次成本 | 累积成本 | 预算/上限 | 验证 |
|---|---|---|---|---|
| 本地 push（Libra 目标） | 缺失对象写入 + 一次元数据事务 | O(待推送对象数) | 与网络 push 同量级，内存按 issues/487 IG-05 上界 | M-PUSHL |
| 本地 push（Git 目标） | 一个 pack + 每 ref 一次 rename | O(待推送对象数 + ref 数) | 同上 | M-PUSHG |
| `fetch --atomic` | 一次事务提交 | O(ref 数) | 与现有事务化写入同量级 | M-FATOM |
| `fetch --negotiation-tip` | 缩小 have 集 | 不高于默认协商 | ≤ 默认 | M-FNEG |
| 仓库参数解析 | 一次路径探测 | O(1) | 可忽略 | M-URL |
| 凭据查找 | 至多两次存储读取 | O(1) | 可忽略 | M-CREDG |

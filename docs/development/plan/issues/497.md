## 文档职责

本计划解决 issue #497（commit 系列）：当删除仓库中**最后一个被跟踪文件**后执行 `libra commit` / `commit -a`，libra 误报 `nothing to commit, working tree clean`，而没有真正提交这次删除。Git 的行为是：删除最后一个被跟踪文件（清空 worktree 内容）后 `git commit -a` / `git add -A && git commit` 应产生一个提交（树为空，相对于 HEAD 为一次删除），而不是“nothing to commit”。

「文档职责」全文：目标是对齐 Git 的「删除最后一个被跟踪文件」语义——该删除是**应从工作树删除、并落入索引与提交**的有效变更，而非空工作树。

本文只规划任务，不宣称实现完成。落地时每个任务都必须先刷新源码锚点，再按任务卡验收。

### 适用范围

- `libra commit` / `commit -a` / `commit -am` 在“删除最后一个被跟踪文件”下的判定与输出。
- 索引 vs 工作树的“是否有变更”判定；删除（D）与 untracked 空目录的区分。
- 相关的 `status`/`ls-files` 输出一致性。
- 同步：commit 文档、`COMPATIBILITY.md`、`../libra-backend` 文档、compat 守卫。

### 非目标

- `add` 家族（#484/#489/#491–#494）的删除/未合并语义。
- 交互式 commit、`--amend` 空消息（#478）。
- 空树提交（`--allow-empty`）的独立行为。

### 成功定义

- 删除最后一个被跟踪文件后，`libra add -A && libra commit`（或 `libra commit -a`）**成功**产生一个删除型提交；`commit` 不再误报 `nothing to commit`。
- 若工作树确实干净（无任何变更），`commit` 仍按 Git 报 `nothing to commit, working tree clean`（exit 1）。
- 移植对应的 Git 上游场景（删除最后一个被跟踪文件 → commit 成功），并有回归守卫。
- 任务卡取得 C 组发布与 D 组证据，收口门全绿后才标记完成。

## 已决议设计决策

### ADR-CD-01: 空索引 + 相对 HEAD 存在暂存删除时允许提交

- **Status:** Accepted
- **Context:** 删除仓库中最后一个被跟踪文件后（`libra rm <path>` 或 `libra add -A`），索引变空。`commit -a` 时 `auto_stage_tracked_changes` 因索引已无被跟踪文件而找不到工作树变更，返回 `false`（`auto_stage_applied=false`）；随后 `src/command/commit.rs` 的 `tracked_entries.is_empty() && !allow_empty && !is_amend && !auto_stage_applied` 门被触发，误返回 `NothingToCommitNoTracked`（`nothing to commit (create/copy files and use 'libra add' to track)`，`LBR-REPO-003`）。Git 的 `git rm <last-file> && git commit` 会真正产生删除提交，而 `libra commit` 误报“无变更”。
- **Decision:** 先计算 `status::changes_to_be_committed_safe()`（相对 `HEAD` 的暂存变更），再把「空索引即无变更」的门收紧为 **`tracked_entries.is_empty() && staged_changes.is_empty()`**。这样：
  - 删除最后一个被跟踪文件（索引空，但相对 `HEAD` 存在 `deleted` 变更）→ 条件为假 → 正常走提交，产生删除提交。
  - 真正空仓库（无任何提交、未暂存任何文件）→ 相对 `HEAD` 无可提交变更 → 仍返回 `NothingToCommitNoTracked`，文案与 Git 一致。
  - 干净工作树（相对 `HEAD` 无变更）→ 仍由 `classify_nothing_to_commit` 分型（`nothing to commit, working tree clean` / `nothing added to commit but untracked files present` / `no changes added to commit`）。
- **Alternatives considered:** (1) 移除 `tracked_entries.is_empty()` 门，完全依赖 `staged_changes.is_empty()`——但这样空仓库无文件时会把“从未暂存”误报为 `nothing to commit, working tree clean`，丢失 Git 的 `create/copy files` 专属文案，故不采纳。(2) 让 `auto_stage_tracked_changes` 在索引为空时仍返回 `true`——不准确（该函数语义是“是否找到工作树可暂存变更”），且不解决 `add -A && commit`（无 `-a`）路径。(3) 在 `libra rm` / `add -A` 删除最后文件时保留一个空 tree 以规避“空索引”——不必要，索引本身变空是正确语义。
- **Consequences:** `commit` / `commit -a` 的判定顺序发生变化（先算相对 `HEAD` 暂存变更再分类）；对性能影响可忽略（`changes_to_be_committed_safe` 是纯内存读）。`status --porcelain` / `ls-files` 输出不受影响（保持与 Git 一致：`D  <path>` / 空）。
- **Revisit when:** 若 `changes_to_be_committed_safe` 的未来实现改变“相对 HEAD 变更”的定义，或 `add`/`rm` 的索引语义调整，应重审本判定的排序与 `NothingToCommitNoTracked` 文案。

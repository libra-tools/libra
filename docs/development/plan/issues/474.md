## 文档职责

issue #474 在 libra 0.22.5 上报告了 clone 的一组问题：
- P1：`--depth` 生成的仓库 `log` 崩溃而 `fsck` 静默通过；
- bundle 源被拒；
- 普通本地路径接受 `--depth`；
- `--mirror` 之后 `fetch` 不按 mirror 更新；
- `--bare` 仍写工作树；
- upstream 状态不一致；
- depth 测试不校验浅化结果。

本计划在 libra 0.22.28（与当前源码同版本）与 git 2.54 上分三轮并排实测，结论如下：

- **已修复：** `--bare` 不再写工作树与 index（条目 4 主体）；新克隆不再报 `upstream is gone`（条目 5 主体，修复提交 `7245929`）；本地 Libra 源的 `--depth` 已按 D20 fail-closed。
- **确认并扩大的缺陷：**
  - **P1 仍成立，形态有变：** 从 shallow 的 Git 源 `clone --depth 1 file://` 得到的仓库，`log`/`rev-list` 在浅边界处报 `storage broken, object not found`。`fsck`（含 `--strict`、`--connectivity-only`）即使删掉 `.libra/shallow`、父提交确实缺失，也以 0 退出。
  - **`--depth` 在本地 Git 源上无效：** 历史不截断；`--single-branch` 被忽略，所有分支都被取回；`.libra/shallow` 标出的边界与实际不符，`--depth 2` 时根本不写。
  - **本地路径语义：** 普通路径上的 `--depth` 被照常处理；Git 忽略并警告，只在 `file://` 或 `--no-local` 下浅化。
  - **bundle：** `clone <bundle>` 被拒；`libra bundle create` 生成的 bundle 缺 `HEAD`，Git 从中克隆得到空分支。
  - **`--mirror`：** 只映射 fetch 取回的命名空间；之后的 `fetch`/`fetch --prune` 只更新 `refs/remotes/*`。
- **新发现：**
  - 以 shallow Git 仓库为源（不带 `--depth`）直接失败，并被错误归类为网络错误 `LBR-NET-001`；
  - `--bare` 默认目录名缺 `.git` 后缀；
  - `branch -a` 的远程跟踪显示缺 `remotes/` 前缀与 `HEAD ->` 行。

目标是**完全解决** issue 描述的所有问题，包括「Test gaps」一节列出的覆盖缺口。本计划交付 15 张卡：
1. **Phase 1（完整性检测）：** CL-01..CL-03。
2. **Phase 2（浅克隆正确性）：** CL-04..CL-07。
3. **Phase 3（bundle 源）：** CL-08..CL-10。
4. **Phase 4（bare 与 mirror）：** CL-11..CL-13。
5. **Phase 5（测试缺口与显示）：** CL-14、CL-15。

本文只规划任务，不宣称实现完成。落地时每个任务都必须先刷新源码锚点，再按任务卡验收。

### 适用范围

- `fsck` 对缺失父提交、树与 blob 的断链检测，以及对 `.libra/shallow` 边界的豁免。
- 以 `.libra/shallow` 为「无父」边界的历史遍历：`log`、`rev-list`、`merge-base`、`status` ahead/behind、`blame`、`describe`、`shortlog`。
- 本地 Git 传输（`file://`、普通路径、`--no-local`）的浅边界计算、`--depth` 隐含 `--single-branch`、普通本地路径上 `--depth/--shallow-since/--shallow-exclude/--filter` 的忽略与警告。
- 以 shallow Git 仓库为源的 clone 与 `--reject-shallow`。
- bundle：`bundle create` 写入 `HEAD`；`clone <bundle>`（含 `.bundle` 后缀解析）；以 bundle 为 remote 的 `fetch`/`pull`。
- `--bare`/`--mirror` 默认目录名；`--mirror` 映射全部命名空间并记录 `+refs/*:refs/*`；mirror 感知的 `fetch`/`fetch --prune`。
- 用本地确定性测试替换无效的 depth 覆盖，并移植上游对应场景。
- `branch -a`/`-r` 的远程跟踪显示。
- 同步：`clone`、`fetch`、`pull`、`bundle`、`fsck`、`log`、`rev-list`、`branch` 的 `docs/commands/` EN + zh-CN、`docs/development/commands/`、`COMPATIBILITY.md` 相关行、`../libra-backend` 网站文档。

### 非目标

- `fetch --deepen/--unshallow/--update-shallow`、shallow 仓库中的 `pull` 加深（DEFER-01）。
- `--shallow-since`/`--shallow-exclude` 在 `file://` 或网络源上的真实实现（DEFER-02；现状为带警告的 no-op）。
- `--filter` 部分克隆（DEFER-03）；`--bundle-uri`（DEFER-04）。
- 本地 Libra 源的 shallow 协商（D20 维持，DEFER-05）。
- `--reference` 的对象借用（DEFER-06）。
- Libra 裸仓库的元数据布局（`libra.db`、`objects` 等位于顶层，不含 `config`/`HEAD`/`refs` 文件）：属于 SQLite 元数据的有意差异，不改（ADR-CL-06）。

### ADR-CL-02: shallow 边界语义

- **Status:** Accepted
- **Context:** N1、N2、N4；git `shallow.c:180-200`、`builtin/clone.c:1025-1028`。
- **Decision:**
  1. **边界定义：** 发送集合中「至少一个父提交因深度限制未发送」的提交是边界，根提交恰好位于深度截断处时同样记为边界（与 Git B2、B4 一致）。边界在全部 want 的遍历完成后统一计算：父提交已由其它 want 送出的提交不是边界。
  2. **深度计算：** 以每个 want 为起点的最短距离；同一提交从多个 want 可达时取最小距离。
  3. **源仓库自身为 shallow 时：** 源的 shallow 边界视为无父提交，不再读取其父提交；这些边界并入目标的 shallow 集合。
  4. **目标仓库：** `.libra/shallow` 中的提交在所有历史遍历中被当作无父提交；集合为空时删除文件。
  5. **损坏处理：** shallow 文件含非法行时，读取方 fail-closed（`LBR-REPO-002`），不当作完整仓库继续。
- **Alternatives considered:** 保留「每个 want 独立截断」——产生 N2 的错误边界，拒绝。
- **Consequences:** CL-04 修改传输侧，CL-02/CL-03 修改读取侧；二者都以 M-BOUND 夹具验证。
- **Revisit when:** 实现 DEFER-01 的 deepen/unshallow。

### ADR-CL-03: 本地路径上的浅化参数

- **Status:** Accepted
- **Context:** 条目 2；git `builtin/clone.c:1323-1340`。
- **Decision:**
  1. **普通本地路径（非 `file://`）的 Git 源：** 默认按「本地克隆」处理，`--depth`、`--shallow-since`、`--shallow-exclude`、`--filter` 被忽略，并分别输出 Git 原文警告（`warning: --depth is ignored in local clones; use file:// instead.` 等）。结果为完整克隆。
  2. **`file://` 或 `--no-local`：** 走传输语义，按 ADR-CL-02 浅化；`-l/--local` 恢复为本地克隆语义。`-l/--no-local` 因此不再是纯 no-op，文档与 `COMPATIBILITY.md:165` 同步。
  3. **源本身为 shallow 时：** 本地克隆自动改走传输语义（与 Git 相同），`--reject-shallow` 在此时报错。
  4. **本地 Libra 源：** D20 不变，`--depth` 在普通路径与 `file://` 下都 fail-closed。
  5. **bundle 源：** 按本地源处理，浅化参数被忽略并警告（以 M-BUNDLE U5 实跑为准）。
- **Alternatives considered:** 普通路径也浅化——与 Git 结果不同，脚本迁移后行为改变，拒绝。普通路径上报错——Git 不报错，拒绝。
- **Consequences:** 「普通本地路径 + `--depth`」从浅克隆变为完整克隆加警告，是公开行为变化，在 clone 文档与 `COMPATIBILITY.md` 登记。
- **Revisit when:** 无。

### ADR-CL-04: fsck 断链检测

- **Status:** Accepted
- **Context:** N5、P1；Git 对缺失父提交输出 `broken link` 与 `missing <type>`。
- **Decision:**
  1. `fsck` 连通性检查对提交的树与父提交、树条目指向的对象逐一确认存在。缺失时报告 `broken link from <type> <oid>` / `to <type> <oid>` 与 `missing <type> <oid>`，并以 fsck 既有的问题退出码非零退出（`docs/commands/fsck.md:134`）。
  2. `--connectivity-only` 与 `--strict` 同样执行该检查。
  3. `.libra/shallow` 中的提交不检查父提交；shallow 文件损坏时报告元数据错误。
  4. `--json` 输出新增 `broken_links` 与 `missing_objects` 条目，不改已有字段。
  5. `--heal` 在检测之前运行的现有顺序不变；可修复的缺失对象修复后不再报告（M-FSCK F7）。
  6. **有意抹除：** 缺失目标若带 obliteration tombstone（`is_intentionally_absent`），报告 `intentionally absent` 诊断、exit 0，不写入 `broken_links` / `missing_objects`（M-FSCK F6）。不得把 tombstone 当成损坏去 `--heal` 复活。
  7. **reflog：** `.libra/shallow` 边界提交的父 OID、以及 tombstoned OID，在 reflog 中缺对象时不报 `missing`；其它缺失 reflog OID 保持既有 `missing unknown` 行为。
- **Alternatives considered:** 只在 `--strict` 下检测——默认 `fsck` 仍会对坏仓库报告健康，拒绝。把 tombstone 当 broken link——与 lore.md 2.5 冲突，拒绝。
- **Consequences:** 现有依赖「缺失对象时 fsck 仍 exit 0」的测试若存在，须同批更新并说明。
- **Revisit when:** 无。

### ADR-CL-06: bundle、bare 与 mirror

- **Status:** Accepted
- **Context:** 条目 1、3、4；N6、N7；git `builtin/clone.c:97-142`、`:796-840`、`:1036-1044`、`:1071`。
- **Decision:**
  1. **源识别顺序：** 先判定本地仓库目录（Git 或 Libra），再依次尝试 `<path>.bundle` 与 `<path>` 作为 bundle 文件，都不是时维持现有错误。
  2. **bundle 读取：** 复用 `bundle.rs` 的头部、前置提交与 pack 校验，以及大小上限，安装 pack 后按 bundle 的 heads 建立 `refs/remotes/origin/*` 与 tag。`HEAD` 选择顺序：bundle 的 `HEAD` 行；否则是否含默认分支（`init.defaultBranch`，默认 `main`）；两者都没有则不创建本地分支。`remote.origin.url` 记录 bundle 的绝对路径。
  3. **bundle 作为 remote：** `fetch`/`pull` 在 remote url 指向 bundle 文件时，读取当前文件内容作为广告与 pack。
  4. **bundle create：** `--all` 与显式 `HEAD` 写入 `HEAD` 行，与 Git 一致。
  5. **bare/mirror 命名：** 未给目标时，默认目录名为源 basename（去掉 `.git`、`.bundle`、结尾 `/`）加 `.git`；非 bare 克隆的命名不变。
  6. **bare 布局：** Libra 裸仓库把 `libra.db`、`objects` 等放在目标目录顶层，不写 `config`/`HEAD`/`refs` 文件，登记为有意差异（SQLite 元数据）；不写 index 与工作树（回归守卫）。
  7. **mirror：** 映射源广告的全部 ref 命名空间（`refs/heads`、`refs/tags`、`refs/notes`、`refs/mr` 及其它合法 ref，不含 `HEAD`），记录 `remote.<name>.fetch=+refs/*:refs/*` 与 `remote.<name>.mirror=true`。`fetch` 读到该 refspec 时逐一原样更新、强制更新与 `--prune` 删除，不创建 `refs/remotes/*`。
- **Alternatives considered:**
  - 保留 mirror 收窄——条目 3 要求镜像保持完整，拒绝。
  - bundle 先 unbundle 再手工建 ref——`docs/development/commands/bundle.md:41` 的临时替代，不满足 clone 语义，拒绝。
- **Consequences:** fetch 的目标 ref 限制（`COMPATIBILITY.md:223` 只允许 `refs/heads/*` 与 `refs/remotes/<remote>/*`）在 mirror refspec 下放宽，须同批更新文档与守卫。
- **Revisit when:** 实现 `--bundle-uri`（DEFER-04）。

### 故障恢复矩阵

| 故障点 | 可接受残留 | 恢复动作 | 禁止结果 |
|---|---|---|---|
| clone 中途失败（shallow 源、bundle、reject-shallow） | 无目标目录 | 按 GC-CL-04 清理并报告仓库错误 | 留下半初始化仓库；归类为网络错误 |
| `.libra/shallow` 损坏 | 仓库原样 | 遍历与 fsck fail-closed，提示元数据损坏 | 当作完整仓库继续遍历 |
| 浅克隆写入 shallow 失败 | 无目标目录 | 视为 clone 失败并清理 | 有对象无边界的仓库 |
| mirror fetch 中途失败 | 原 ref 状态 | ref 写入事务回滚 | 部分 ref 更新 |
| 发布步 `gh release create` 失败 | 已推送的 `main` 提交 | 按 ER-09 记录，下一窗口补 tag/release | blind retry；只推 `main` 就宣称已发布 |
| D 组 `release.yml` 失败 | 已存在的 tag | 前滚修复，发新 patch | 回退已推送提交或删除已发布 artifact |

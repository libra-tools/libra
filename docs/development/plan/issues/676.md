## 已决议设计决策

### ADR-I676-01：只放行 unborn→target commit 的完全等价状态

- **Status:** Accepted
- **Context:** staged 集合相对不存在的 HEAD 看似全新增，但可与目标提交完全相同。`switch.rs:1215-1219` 不看目标。
- **Decision:** 不修改 `ensure_clean_status_for_commit`。`switch.rs:1215-1219` 在 staged 非空时仍无条件 `DirtyUncommitted`。`libra switch` 在 `:1136` 进入该 helper，`:296-298` 仍映射为退出码 128、`LBR-REPO-003`、文案 `uncommitted changes, can't switch branch`，并且不移动 HEAD。checkout 对 unborn 且目标是已存在本地分支、`args.detach` 为 false 的路径，先调用 `ensure_no_untracked_overwrite`。失败则返回 `CheckoutError::UntrackedOverwrite`：退出码 128、`LBR-CONFLICT-002`，不移动 HEAD，也不改该未跟踪文件。通过后才允许在 `:604` 之前跳过共享 helper，并且仅当 index 等于该分支提交的 tree、已跟踪 worktree 相对 index 无变化。index 与目标树不一致时不跳过。裸 OID 与 tag 能在 `:566-585` 解析成 commit，但 `:626` 的 `is_branch` 为 false，`:632` 会进入 `checkout_detached`。它们和 `checkout --detach <branch>` 都不满足附着分支谓词，所以仍先被未修改的 helper 拒绝：退出码 128、`LBR-REPO-003`、文案 `local changes would be overwritten by checkout`，HEAD 留在 orphan。
- **Alternatives:** 在共享 helper 里放行会同时改变 `libra switch`。只判断 `args.detach==false` 会放行裸 OID 与 tag。跳过全部 dirty 检查会丢数据。强制 `-f` 不符合 Git cleanup。
- **Consequences:** 不等价 staged/unstaged，包括 TC-0321 探针里多出来的 `world`，继续 128。`libra switch` 不获得本例外。unborn→unborn 没有目标 commit，不在本决策内。
- **Revisit:** 新 Issue 要求 Git 的非等价 carry-over 或 unborn→unborn 时。

### ADR-I676-02：branch 链只作下游证据

- **Status:** Accepted
- **Context:** 0.30.91 notes 已证明 `branch t` / `-v -d` 在正常 HEAD 可用；失败是 orphan cleanup 的 cascade。
- **Decision:** 不改 branch 生产代码。checkout 成功后用 Issue 正文第 3–5 条和 TC-0154 验收。
- **Alternatives:** 同卡重写 branch 会变成第二行为轴。
- **Consequences:** `commit-graph` 与评论里的下游命令继续延后。
- **Revisit:** checkout 已成功而 #44 仍在 branch 命令本身失败时。

## 远端交付与保护（squash PR 口径）

`main` 没有分支保护。允许临时 `review/I676-01` 与对应 PR，只为取得一条 `state=APPROVED` 且 reviewer 不是推送者的审查，以及同一已签名 SHA 的 `pull_request` `base.yml` 与 `codeql.yml` success。`required_status_checks` 与 PR 结论都不能代替那条审查。通过后，仅当 `origin/main` 仍等于提交父时，用 `gh pr merge --squash --match-head-commit "$HEAD_SHA"` 合并该 PR。不得再用 `libra push origin main` 绕过 PR，也不得用 `--merge` 或 rebase。squash 后的 `mergeCommit.oid` 必须等于远端 `main`，树必须等于已签名功能提交的树，并且只有一个父提交、等于合并前的 `main`。C 组在该 SHA 上 `gh release create`。D 组只观察 workflow 与 CDN。本地 diff 只含卡内 I/R 写集，其中包含 `plan-status.md` 里链接到 `issues/676.md` 的那一行。功能提交有 PGP 与 DCO。

  sleep 15
done
test "${ok:-}" = 1

test -n "${ISO:-}" && rm -rf "$ISO"

## 文檔職責

本文解決 #574 報告的中等規模倉庫只讀命令延遲：`branch -l` 等 Repository 域只讀查詢被分類為 `RepoMutation`，因而進入 Operation v2 持久事務並對整個工作區做前後兩次逐檔哈希快照；`log -1`／`rev-list --max-count` 則先全量遍歷可達提交再截斷。目標是讓只讀查詢不再支付寫邊界成本、讓有限額的歷史查詢提前終止，並讓仍須快照的寫命令跳過 stat 未變的已追蹤檔案。

本文只規劃任務，不宣稱實作完成。每張任務卡開工時都必須依 ER-01..ER-03 刷新源碼、測試與文件錨點；任一任務狀態推進時，同一變更必須更新 [`plan-status.md`](../plan-status.md)（本計劃新建時已在其「issues/ 下的計劃」表登記一行）。

### 適用範圍

- `libra branch` 的查詢形態（無動作參數的列表、`-l`／`-r`／`-a`／`--show-current`／`-v`／`--contains`／`--no-contains`／`--points-at`／`--merged`／`--no-merged`／`--sort`／`--format`／`--column`）在 `src/cli.rs` operation census 中的分類。
- `libra tag`、`remote`、`reflog`、`notes` 的只讀子命令／形態在同一 census 中的分類。
- `libra log` 的預設提交排序遍歷與 `-n`／`--max-count`／`--skip` 限額下推；`libra rev-list` 的 `--max-count`／`--skip` 限額下推。
- Operation v2 `WorkspaceSnapshotter` 對已追蹤檔案的 stat 短路（沿用 `status` 的 stat 比對語義與 racy 防護）。
- 上述行為在 `op log`、`branch`／`tag`／`remote`／`reflog`／`notes`／`log`／`rev-list` 的人讀、`--json`、`--machine` 輸出與錯誤路徑上的回歸測試，以及 EN／zh-CN／開發／網站文件與 `COMPATIBILITY.md` 同步。

### 非目標

- 不改變任何 mutating 命令的 Operation v2 記錄語義：建立／刪除／改名／複製分支、建立／刪除 tag、新增／刪除 remote、`reflog delete`／`expire`、`notes add` 等仍各自記錄一筆 operation。
- 不移除或弱化 `command_scope` 的 Repository lease 分類（ADR-BRL-01）；#574 已以 lease 豁免環境變數實測排除 lease 為成本來源。
- 不改變 `BackgroundIndexDrainGuard` 的 60 秒排空預算與 object-index repair 協議；不以 TTL 刪除 `object-index-repair-locks/` 下的 shard 鎖檔（DEFER-BRL-01）。
- 不改變 `get_reachable_commits` 等「可達集合」語義的共用函式（`branch --contains`、`merge-base`、`rev_list_spec` 的排除閉包等消費者不受影響）；只有 `log` 主路徑與 `rev-list` 的輸出遍歷改用新 walker。
- 不實作 Git `core.abbrev=auto` 的物件庫級縮寫長度（DEFER-BRL-02）。
- 不處理 #574 的 debug build 體積（1.1G）或 `target/` 目錄規模；這不是 Libra 行為。

### 成功定義

- 在同一倉庫（本 checkout：1930 個已追蹤檔案、4165 個提交）上，release build 的 `branch -l`、`tag -l`、`remote -v`、`reflog`、`notes list` 不再新增 `op log` 記錄，且耗時與 `config user.name` 同量級（sanitized 人工證據，目標 < 1 秒）。
- `log --oneline -1` 與 `rev-list --max-count=5 HEAD` 的載入提交數以限額為界（debug 測試計數器斷言），且在無時鐘偏斜的歷史上輸出與無限額輸出的前綴逐位元組一致。
- 仍需快照的寫命令對 stat 未變的已追蹤檔案不再提交 worker 哈希請求，且快照 manifest 在 ADR-BRL-04 的 stat-cache 信任等級內與關閉短路一致（stat 判定未變的檔案記錄同一 oid；其餘檔案兩種模式都走哈希、manifest 逐位元組一致）。
- 五張卡各自取得 C/D 發布證據；文件、兼容矩陣與測試同步；計劃收口門全綠後才可標記完成。

## 已決議設計決策

### ADR-BRL-01：只讀查詢只調整 operation 分類，不調整 `command_scope`

- **Status:** Accepted
- **Context:** `command_scope` 同時驅動 lease、worktree 狀態守衛與 `publishes_object_references`（object-index 前置修復）；`operation_class_for_command` 才決定是否進入 `run_with_operation`。#574 以 `LIBRA_INTERNAL_REPOSITORY_REF_LEASE_HELD=1 LIBRA_INTERNAL_OPERATION_SCOPE_LEASE_HELD=1` 實測 lease 豁免後耗時不變，成本來自快照。
- **Decision:** 在 `operation_class_for_command` 的特例 `match` 中，仿 `config_command_is_read_only`／`set_upstream_is_idempotent` 先例，為 `Branch`、`Tag`、`Remote`、`Reflog`、`Notes` 各加一條 `if <module>::<predicate>(args) => MutationClass::ReadOnly`。判定函式定義在各命令模組內，且必須與該命令自身的派發共用同一個模式判定（例如 `run_branch` 改為先計算 `BranchMode` 再派發，判定函式回傳 `BranchMode::is_read_only()`），不得在 `cli.rs` 重寫欄位組合。`command_scope` 保持 `Repository`。
- **Alternatives considered:** 把查詢形態移到 `command_scope` 的 `ReadOnly` 臂（會同時改變 lease 與 object-index 前置修復語義，擴大影響面）；在 `run_with_operation` 內偵測「無變更」後丟棄記錄（仍付出雙快照成本）；在 `cli.rs` 直接匹配欄位（與派發邏輯重複，違反 GC-02）。
- **Consequences:** 判定錯誤的方向必須是保守的：任何無法確定為只讀的形態維持 `RepoMutation`。每張分類卡以表格測試覆蓋每個動作欄位／子命令，並以 `op log` 斷言 mutating 形態仍記錄。
- **Revisit when:** census 改為由命令模組宣告自身 mutation class（屆時把判定遷入該宣告）。

### ADR-BRL-02：`log` 採用日期優先佇列遍歷並在限額內提前終止

- **Status:** Accepted
- **Context:** 現行 `log` 先 BFS 收集全部可達提交再以 committer 時間全域穩定排序，因此任何限額都無法提前終止。Git 的預設輸出順序是以 commit date 為鍵的優先佇列遍歷，可以在輸出 N 筆後停止；#574 建議的 `depth = skip + number` 不正確（深度不等於輸出筆數，合併歷史會漏或多）。
- **Decision:** 新增只供 `log` 主路徑（BRL-03）與 `rev-list` 預設排序輸出路徑（BRL-04）使用的 walker：以（排序鍵降序、發現序號升序）為鍵的優先佇列，排序鍵為 committer 時間（`--date-order` 是 Git parity no-op、選擇同一預設鍵，隨預設路徑走 walker）；父提交在**入佇列時**載入並解析排序鍵（與 Git 的 `process_parents` 相同——排序鍵在入佇列前不可知，「彈出時才載入」與排序鍵自相矛盾），同一提交只載入一次（in-queue／seen 集合去重）；`--first-parent` 與 shallow 邊界語義與現行 `history_parents` 一致。帶 `--author-date-order` 的調用**不走新 walker**，保留現行「全量收集＋全域 author 時間排序」路徑（限額不提前終止；其現行語義不變，開工日刷新錨點後如將其改掛 author 鍵 walker 須另行修訂本 ADR）。無限額與有限額的預設排序 `log` 都使用同一 walker，因此 `log -n N` 永遠是 `log` 的前綴。限額下推只在「合格」調用時啟用：存在 `-n`／`--max-count`，且未使用任何需要全量集合或逐提交過濾的選項（開工日以 `LogArgs` 欄位盤點為準，至少包含 `--reverse`、`--graph`、`--children`、`--author-date-order`、`--follow`、`-L`、pathspec、`--author`／`--committer`／`--grep`／`--since`／`--until`／pickaxe／`--merges`／`--no-merges`／`--min-parents`／`--max-parents`／trailer 過濾，以及帶排除端的範圍、`--all`／多個修訂起點——walker 為單起點設計，多 tip 一律不合格走全量）；**eligibility 以解析後有效值判定，不只匹配原始 CLI 欄位**（`--follow`／`--no-follow` 與 config `log.follow` 的解析後有效值入判定：`--follow` 生效、或 `configured_follow_path(..)` 解析為 `Some`（恰一個 pathspec 且為檔案，`src/command/log.rs:1070-1073`）時不合格；config `log.follow=true` 在無 pathspec 或路徑非單一檔案時不影響合格性）；合格時停止條件為已輸出 `skip + number` 筆。不合格（仍為預設排序）調用走同一 walker 但不提前終止。載入計數鉤子統計「walker 解析過的提交物件數」（含入佇列載入的父提交），測試對固定 fixture 斷言確切期望值，不使用「當下佇列前沿大小」這類測試端無法獨立計算的量。
- **Alternatives considered:** 保留全域排序、只在無偏斜時截斷（需要先知道無偏斜，仍要全量）；`depth` 截斷（語義錯誤）；只讓有限額路徑用新 walker（`log -n N` 與 `log | head -n N` 在偏斜歷史上不一致）。
- **Consequences:** 在無時鐘偏斜（父提交 committer 時間不晚於子提交）且無同時間戳跨分支並列的歷史上，預設排序輸出與現行逐位元組一致；在偏斜或並列歷史上，順序改為與 Git 相同的優先佇列順序——同秒提交的並列以發現序號（確定性的遍歷起點序）決定，新舊順序可能不同（例：M(10) 有兩個父 P1(5)、P2(9)，P1 的父為 A(5)、P2 的父為 B(5)：舊全域排序輸出 M,P2,P1,A,B，新 walker 輸出 M,P2,P1,B,A）——這是使用者可見變更，必須寫入 `log` 文件的 Git 差異段與 `COMPATIBILITY.md`；既有測試中同秒提交 fixture 的輸出順序可能改變，新 fixture 以 `GIT_COMMITTER_DATE` 設定互不相同的 committer 時間。錯誤路徑變化：`log -1` 在深層祖先缺失的歷史上會從「全量遍歷後失敗」變為「提前終止後成功（輸出可達前綴）」。`get_reachable_commits` 等集合語義函式不變。**與 rev-list 的不對稱（明確登記）：** `log` 的不合格（仍為預設排序）調用走同一 walker、只是不提前終止；`rev-list` 的全量選項／過濾路徑保留現行全域排序（`sort_rev_list_commits`）不走 walker——帶過濾的 `log` 與帶過濾的 `rev-list` 在偏斜歷史上順序可能不同。此差異寫入兩命令的開發文件，並登記於風險表；若日後要求對稱，另立卡讓 rev-list 過濾路徑也走 walker。
- **Revisit when:** Libra 實作 `--topo-order` 或 commit-graph generation number（屆時可改用 generation 加速並重審排序鍵）。

### ADR-BRL-03：有限額 `log` 的縮寫長度以本次已輸出的提交集合計算，下限 7

- **Status:** Accepted
- **Context:** 現行縮寫長度以全部可達提交的最短唯一前綴計算（`src/utils/util.rs:3079-3098`），這本身就不是 Git 的物件庫級唯一性；提前終止後無法取得全部可達提交而不失去性能收益。
- **Decision:** 合格的有限額 `log` 以「本次已輸出的提交集合」（非「已載入集合」——後者包含佇列前沿，結果依賴歷史形狀；已輸出集合是確定且可測的）計算最短唯一前綴，下限維持 7；無限額與不合格調用維持現行計算。
- **Alternatives considered:** 物件庫級唯一縮寫（需要新的 pack／loose 前綴索引，另立 DEFER-BRL-02）；有限額時一律輸出完整 hash（改變 `--oneline` 預設外觀）。
- **Consequences:** 在 7 位前綴已在可達歷史中衝突的極大倉庫，`log --oneline -n N` 的縮寫可能短於 `log --oneline`；BRL-03 在 `docs/commands/log.md` EN／zh-CN 的 Git 差異段記錄此點。BRL-03 的前綴一致性測試使用 7 位前綴唯一的 fixture。
- **Revisit when:** DEFER-BRL-02 的物件庫級縮寫落地。

### ADR-BRL-04：快照 stat 短路只在可證明等價時重用 index oid

- **Status:** Accepted
- **Context:** 快照 manifest 記錄的是工作區原始位元組的 blob oid（`IoRequest::FileBlobHash` 對原始檔案位元組哈希）；index entry 的 oid 在內容轉換（eol／filter／LFS pointer）下與原始位元組哈希不同。status 的 `index_stat_differs` 已定義可信 stat 比對與 racy 判定。
- **Decision:** 對已追蹤檔案，只有同時滿足下列條件才重用 index entry oid、跳過 worker 哈希：stage 0；entry 為一般檔案模式（非 symlink、非 gitlink）且與檔案類型一致；與 status 共用的 stat 比對判定為「未改動」（含 index 檔 mtime racy 判定、>4GiB 一律比對內容）；該路徑不適用任何 attribute／config 驅動的內容轉換——`core.autocrlf` 未啟用，且該路徑無 `text`／`eol`／`filter`／`working-tree-encoding`／`ident` 等任何轉換屬性，非 LFS 追蹤路徑（現行 `src/utils/attributes.rs` 的轉換判定能力以 LFS 為主：凡開工日無法由 attributes 模組**證明**「無轉換」的路徑一律走哈希路徑，fail-closed，與 GC-BRL-01 同構）；該 oid 的 blob 存在於本地物件庫。任一條件不成立即走原哈希路徑。不採信 assume-unchanged／skip-worktree 位元。stat 比對抽為 status 與快照共用的單一 helper，置於 `command` 與 `internal::operation` 都可依賴的中立模組（`src/utils/` 下新檔，開工日定名）；helper 介面以 index entry 的 stat 三元組＋index 檔 mtime 為輸入，status 的 `CapturedStat` 與快照的 `fs::Metadata` 適配在呼叫端完成，`internal::operation` 不反向依賴 `command`；status 既有 `entry_stat_matches_metadata` 鏡像（`src/command/mod.rs:384-440`）在同卡一併收斂。
- **等價性的信任等級（明確限定）：** stat 三元組＋racy 判定提供的是**與 status／index stat-cache 相同的信任等級**，不是 byte-identity 證明。在 Linux 本地檔案系統上，任何內容寫入都會更新 ctime（ctime 不可由使用者空間回撥），因此「同 size、stat 被復原／同秒粒度內替換」的內容變更會被 ctime 比對或 racy 判定捕獲；殘留盲區是 ctime 粒度粗或由外部掛載操縱時間戳的檔案系統（網路檔案系統）——該盲區與 status 的既有信任等級一致，登記於風險表，不做（也無法做）超出 stat-cache 語義的承諾。
- **Alternatives considered:** 對所有檔案信任 stat（racy 與轉換路徑會產生錯誤 manifest，破壞 `op restore`／undo）；只對 ReadOnly 邊界跳過快照（BRL-01／BRL-02 已使只讀查詢不進邊界，寫命令仍需快照）。
- **Consequences:** 快照 manifest 的等價承諾限定於 ADR-BRL-04 的 stat-cache 信任等級：stat 判定為「未改動」的檔案，啟用與關閉短路時記錄**同一 oid**（該 oid 即 index oid）；stat 判定為「已改動」、racy、轉換路徑的檔案，兩種模式都走哈希、manifest **逐位元組一致**；測試 seam 可強制關閉短路做對拍。ctime 粒度粗／外部掛載等盲區內（同 size、stat 完全相同的內容替換）兩種模式與 status 一樣不可偵測——這是已登記的殘留風險，不是測試可釘住的等價失敗。`touch -r` 式的 mtime 復原因 ctime 必然前移而被偵測（有專門測試）。未追蹤檔案仍逐檔哈希。短路同時覆蓋持久化階段：`persist_files` 對滿足上述條件（含 blob-exists 已驗證）的檔案跳過 `read_stable_file`／重算哈希／`put_blob`，直接以 index oid 進入 manifest——blob 的存在性在掃描階段已驗證，因此 manifest 引用的 blob 必然存在；未短路路徑保留 `oid == expected_oid` 比對安全網不變（該比對目前是「錯誤 oid 降級 Partial」的最後防線，不得移除）。
- **Revisit when:** 快照改為儲存 index 語義（轉換後）oid，或 Libra 引入 fsmonitor／untracked cache。

## 全局工程約束

本計劃完整繼承模板 GC-01..GC-13。另加下列本計劃約束：

- **GC-BRL-01 保守分類：** 任何無法由命令模組自身模式判定證明為只讀的形態，維持原 `MutationClass`；新判定不得讓 census 出現未分類 mutation。census 守衛以 `src/cli.rs` `#[cfg(test)]` 內、針對解析後 `Commands` 呼叫 `operation_class_for_command` 的 `--lib` 矩陣測試為權威（名稱型 `classify_command` 不解析 CLI 形態，只作 `tests/operation_command_coverage.rs` 的補充守衛）。
- **GC-BRL-02 判定同源：** 只讀判定與命令派發必須共用同一模式判定函式；`src/cli.rs` 只呼叫判定，不重寫欄位組合。
- **GC-BRL-03 輸出等價：** 分類與遍歷調整不得改變只讀查詢的人讀、`--json`、`--machine` 輸出與退出碼，ADR-BRL-02／ADR-BRL-03 明列的偏斜排序與縮寫例外除外。
- **GC-BRL-04 測試隔離：** 所有測試使用 tempdir 倉庫與 `LIBRA_CONFIG_GLOBAL_DB`／`LIBRA_CONFIG_SYSTEM_DB` 隔離；性能證據只以 debug 計數器斷言與 sanitized 人工量測呈現，不寫 wall-clock 斷言。

**Task type:** `implementation`

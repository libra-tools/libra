## 文档职责

本文逐项核对 #576 在 Libra 0.23.67 + OpenCode 2.0.18 上报告的五类破坏性变化，分开记录当前源码机制、固定 2.0.18 上游证据、冻结 2.0.26 fixture、历史 2.0.29 真机结果和本次尚未执行的验证。当前结论是：**第 1–4 点的当前兼容机制有源码和固定版本证据，不重复实现；第 5 点已有有界同步与 cleanup/exit flush，但 issue 所述正常 headless shutdown 竞态尚未证实闭合。** 未证实已修不等于已确认存在产品 bug，故当前建立五张 audit / no-release 卡，不预先建立实现卡。

### 适用范围

- 仓库内实际插件源 `src/internal/ai/hooks/providers/opencode/settings.rs` 中的 `OPENCODE_PLUGIN_TEMPLATE`，以及事件 registry、parser、真实 ingress、checkpoint reducer 和既有测试。
- 固定官方 OpenCode 2.0.18 commit 的模块、事件、headless 客户端、总线、插件 cleanup 与 standalone 生命周期源码。
- 当前 ordinary 2.0.29 pin、冻结 2.0.26 合同 fixture、历史 OG-02/OG-UPGRADE-029-01 证据的各自适用边界。
- 五张串行审计卡：模块/context、上游事件发布、固定版本用户 prompt 到当前插件的映射、当前 registry/真实 Libra ingress/checkpoint、正常 shutdown；任一卡确认真实未修项后，先重规划再实现。

### 非目标

- 不重复实现第 1–4 点已有机制，不添加 `.opencode/plugins/libra-hooks-compat.js` 或第二份仓库内 JS 插件。
- 不把第 5 点的 `spawnSync` 直接称为 shutdown 等价证明，也不预设必须使用 `detached:true` / `unref()`。
- 不恢复 Bun `$`，不转发 tool input/result/provider state，不把旧版 `tool_response` 观察当成当前 checkpoint 必要条件。
- 不认证所有 OpenCode 2.x；静态源码、Node/Bun synthetic、真实 Libra ingress 和真实 OpenCode session 是不同证据层。
- 不在审计卡中修改产品代码、测试、公开文档、CI、版本面或发布通道；确认未修项时按 ADR-OC2-04 新建实现卡。
- 不套用 v2.16 具名 `code-only`；未来未修实现卡须单轴、S/M、`independent + patch`，其 AC/VER 独立谓词按 G-03 如实计数；超过 8 须先依 G-03 拆卡，若拆分违反 G-01/G-02，仅能申请模板白名单内具名 waiver，实际批准前禁止开工。
- 不自动回复或关闭 #576；尤其不得在第 5 点仍为未验证时宣称原 issue 已完整解决。

### 成功定义

- 五点均有当前源码锚点、版本适用范围和「已修机制 / 未验证 / 已确认未修」的准确区分。
- 第 1–4 点不重复建设；第 5 点不以同步子进程或 fake exporter 代替宿主 shutdown 证明。
- 2.0.18 的 delivered 发布与 headless 等待链有固定 commit 证据；2.0.26 fixture 与 2.0.29 历史真机结果不互相冒名。
- 真实 ingress/checkpoint 的 ignored 手工门被显式执行并显示 `[executed]`，或明确保持 UNRUN 且对应 AC 不完成。
- 每卡按独立谓词计数，写集包含协调者 status；Codex 执行评审、no-JUnit 全量门和同 SHA main D 均可终止执行。

## 已决议设计决策

### ADR-OC2-01：以当前 managed 模板、registry 和固定上游源码为事实源

- **Status:** Accepted
- **Context:** issue 针对 0.23.67 的 1.x named-export 插件；当前模板已前滚，但不同 OpenCode 版本不能混用证据。
- **Decision:** 第 1–4 点不重复实现。OC2-A01/A02/A05 核对当前源码和固定 2.0.18 commit；未来若确认代码缺口，修改 `src/internal/ai/hooks/providers/opencode/settings.rs` 的 `OPENCODE_PLUGIN_TEMPLATE` 及必要的安装/status 逻辑，不加入用户 shim。
- **Alternatives considered:** 移植 workaround：形成第二插件事实源并扩大 tool result 数据。只看当前 2.0.29 pin：无法证明 2.0.18。
- **Consequences:** 当前无产品变更/版本发布；每个结论均带版本范围。
- **Revisit when:** 当前 pin/API 变化、focused 失败或受信真机复现失败。

### ADR-OC2-02：第 5 点保持未验证，不把同步投递等同于 shutdown 证明

- **Status:** Accepted
- **Context:** `spawnSync` 只阻塞处理事件的进程；2.0.18 总线不等待插件 handler，standalone 另有 SIGTERM/3 秒 force-kill。setup cleanup 虽被 await，也不能单独证明所有终态和 prompt 已在关闭前排空。
- **Decision:** 记录有界同步、dispose/exit flush 是现有机制，但不宣称 issue 的正常 shutdown 竞态已闭合。现有 synthetic 测试只覆盖自身场景；历史 2.0.29 结果只有在该次运行与当前模板/执行模式/终态路径同一性重新证明后才可复用。另一历史 observer 收据的整文件摘要与当前不同，既未绑定该真机运行，也不能证明模板段不同；不得直接复用历史真机结果。
- **Alternatives considered:** 直接判已修：证据越界。直接判未修并改 detached：尚无当前产品失败证据，且会引入孤儿进程与资源边界变化。
- **Consequences:** OC2-A03 可以完成“证据审计”，不能完成“2.0.18 真机兼容认证”；issue 关闭必须另有受信证据。受信复现失败才触发实现重规划。
- **Revisit when:** 获得固定 2.0.18/当前 pin 的真实正常 shutdown 记录，或上游关闭合同变化。

### ADR-OC2-03：不把旧 `tool_response` 观察列为第六个缺口

- **Status:** Accepted
- **Context:** issue 的 0.23.67 观察称 tool-use 必须带 tool_response 才有 checkpoint；当前 reducer 在 TurnEnd/SessionEnd 提交，ToolUse 只是观察。
- **Decision:** 不恢复 result content 拼接；checkpoint 实测使用显式 ignored 的真实 Libra ingress 门，不把 reducer 静态分支写成已持久化。
- **Alternatives considered:** 照搬 shim：扩大敏感数据面。完全不采 ToolUse：非本 issue 所需。
- **Consequences:** 当前工具 hook 不转 result 不构成未修项；真实 OpenCode 内容仍不在 synthetic 门范围内。
- **Revisit when:** 当前 reducer 或 checkpoint 合同正式改变。

## 文檔職責

本文解決首次以 SSH clone 未知主機時，Libra 無法像 Git 在終端顯示主機金鑰指紋並要求明確確認的體驗差距；目標是在不洩漏遠端輸出、不降低變更主機金鑰防護，且不干擾非互動自動化的前提下，提供 Git 相容的未知主機確認流程。

本文已依 [`docs/development/internal/ssh-host-key-interaction.md`](../../internal/ssh-host-key-interaction.md) 之實作 seam（HKT-01 host-key policy cascade + HKT-02 受限 human-terminal unknown-host confirmation）完成閉包：HKT-00 `done`/`complete`，HKT-01 `done`/`complete`，HKT-02 `done`/`complete`，並經 ER-05 final code review `PASS` 後以 Closed 狀態收口；GitHub Issue #582 已關閉。每張任務卡開工時都必須依 ER-01..ER-03 重新整理來源、測試與文件錨點；任一任務狀態推進時，同一變更必須更新 [`plan-status.md`](../plan-status.md)。

### 適用範圍

- 以共享 `SshClient` 連線的 `clone`、`fetch`、`pull`、`push` 與 `ls-remote`，以及 `ssh.strictHostKeyChecking` 的有效設定解析。
- 人類終端中、有效政策為 `ask`、主機尚未知時的明確主機金鑰確認；成功確認後由使用者 OpenSSH 設定指定的 known-hosts 位置保存信任。
- 未知、已知與變更主機金鑰，TTY／無 TTY、human／JSON／machine 輸出，以及 `ask`／`yes`／`accept-new`／`no` 政策的回歸測試。
- 六個命令的 EN、zh-CN、開發與網站文件，`COMPATIBILITY.md` 與 `docs/error-codes.md` 的一致性。

### 非目標

- 不以 `ssh-keyscan` 取得的未驗證金鑰直接寫入 `known_hosts`，也不新增跳過 host-key 驗證的預設或隱藏開關。
- 不將私鑰 passphrase 互動一併改為 Git 模式；加密私鑰仍須先由 `ssh-agent` 解鎖，另立 issue 才可擴張此範圍。
- 不改變 HTTPS、`git://`、SSH 使用者認證、代理、ControlMaster 或 Git packet-line 協議的其他語義。
- 不將遠端 SSH stderr、SSH banner、控制序列或封包資料重播到終端；不接受僅刪除 `BatchMode=yes` 的做法。

### 成功定義

- 人類終端以有效 `ask` 政策連到未知 SSH 主機時，Libra 顯示本地構造的演算法與指紋確認提示；接受後儲存信任並完成原命令，拒絕、EOF 或中斷均不寫入信任。
- JSON、machine、無 TTY、明確 `yes` 與變更主機金鑰保持非互動、fail-closed；`accept-new` 與 `no` 保留既有 OpenSSH 顯式政策語義。
- `LIBRA_SSH_STRICT_HOST_KEY_CHECKING` 優先於 local、global、system 設定；首次 clone 在倉庫外能讀取 global 與 system 設定。
- 所有卡取得各自 C/D 發布證據、文件與測試同步，計劃收口門全綠後才可標記完成。

## 已決議設計決策

### ADR-HKT-01：互動信任只接受本地受限提示，不重播遠端輸出

- **Status:** Accepted
- **Context:** 現行 BatchMode 保護了使用者終端與 log 免受遠端 stderr、banner 和控制序列污染，但同時阻止 OpenSSH host-key prompt。單純移除 BatchMode 或把 child stream `inherit()` 都會破壞這條安全契約。
- **Decision:** 僅在人類輸出、stdin 與 stderr 均為 TTY、有效政策為 `ask`，且分類為未知 host key 時，進入一個在 Git packet-line transport 之前的受限信任階段。HKT-00 必須選定並記錄一種能取得演算法與指紋、由 Libra 本地構造 prompt 的實作；它只能將明確接受後的信任寫入使用者 OpenSSH 已配置的目的地。完成後才以既有 batch-mode transport 重新連線。遠端 stdout、stderr、banner 及 protocol bytes 不得進入 prompt、終端或 log。
- **Alternatives considered:** 無條件維持 fail-closed（保留 UX 差距）；移除 `BatchMode=yes`（child streams 仍是 pipe 且會暴露輸出）；以 `ssh-keyscan` 直接追加（可被 MITM 污染）；通用 PTY 逐行轉發（輸出過濾與 locale 安全性不足）。
- **Consequences:** HKT-00 是 HKT-02 的 go/no-go gate；若無法在不回放遠端資料下實作，HKT-02 不得開工，必須以新的 DEFER-HKT-* 及 issue 更新回報。這不影響既有已知主機的 BatchMode 流程。
- **Revisit when:** OpenSSH 提供可消費的結構化 host-key 確認 API，或 HKT-00 的固定版本實驗證明既有限制不足以安全實作。

### ADR-HKT-02：SSH host-key 政策使用固定 cascade 與明確互動資格

- **Status:** Accepted
- **Context:** `LIBRA_SSH_STRICT_HOST_KEY_CHECKING` 已是最高優先序，但現行程式把後續讀取限制在 cwd 的 repository config，首次 clone 看不到 global/system policy。
- **Decision:** 有效政策依序為非空環境變數、local（若存在目前 repository）、global、system、預設 `ask`。設定 key 的名稱大小寫與值正規化行為遵循現有 strict config helper 與 `SshClient` validator。只在有效政策為 `ask` 時可取得互動資格；`yes`、`accept-new`、`no` 仍完整轉交 OpenSSH 且不顯示 Libra prompt。
- **Alternatives considered:** 維持 repo-only 讀取（首次 clone 無法使用 global 設定）；把 `accept-new` 設為預設（未經明確使用者選擇即改變 TOFU）；新增只供 clone 的 CLI 旗標（重複既有 config interface）。
- **Consequences:** HKT-01 必須用隔離的 local/global/system fixture 驗證 precedence，並在 human／machine 場景測試 explicit policy 不被互動路徑覆寫。
- **Revisit when:** Libra 增加與 OpenSSH config 等價的 per-host policy schema；屆時需要新的 precedence ADR。

### ADR-HKT-03：變更主機金鑰永不進入確認 prompt

- **Status:** Accepted
- **Context:** 未知鍵是使用者可以在 TOFU 互動中判斷的狀況；已信任 host 的鍵變更可能代表攔截或合法 rotation。
- **Decision:** 只對 typed `Untrusted` 進入互動流程。`Changed` 一律維持目前的固定 `LBR-NET-001` 錯誤與帶外驗證／手動修復指引；沒有 accept、fingerprint 或 retry prompt。
- **Alternatives considered:** 把兩種錯誤都提示確認（會降低既有 host identity 防護）；以 `accept-new` 覆蓋 changed key（不符合 OpenSSH 語義）。
- **Consequences:** HKT-02 的測試矩陣必須分開驗證 unknown 與 changed，文件也必須保留兩者的不同復原步驟。
- **Revisit when:** 使用者提供已驗證的 key-rotation trust channel；該能力需獨立設計。

## 全局工程約束

本計劃完整繼承模板 GC-01..GC-13。另加下列本計劃約束：

- **GC-HKT-01 互動資格：** `--json`、`--machine`、無 TTY、非 `ask` 政策、非 SSH URL、已知鍵與變更鍵都不得開啟互動 child 或寫入信任。
- **GC-HKT-02 來源隔離：** prompt 的每一個可見字元必須來自 Libra 固定字串或已解析並驗證的 host-key metadata；不接受任何未清理的 SSH subprocess 輸出。
- **GC-HKT-03 信任寫入：** 只使用使用者 OpenSSH 設定解析出的 known-hosts 目標與其語義；拒絕、EOF、訊號、timeout、失敗、機器模式與 changed key 均不得寫入條目。
- **GC-HKT-04 測試隔離：** 所有 local/global/system config 與 known-hosts 測試必須用 fixture path、`HOME`／`XDG_CONFIG_HOME`／`LIBRA_CONFIG_*_DB` 的 scoped 環境，禁止讀寫真實使用者設定與 `~/.ssh`。

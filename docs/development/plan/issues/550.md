## 已决议设计决策

### ADR-IN-01：只修静态末级链接环的扫描

- **Context：** 已列路径中的 `fs::metadata` 会跟随末级链接；worker 对静态链接读取链接文本。当前问题是跟随触发的 ELOOP，不是由显式循环检测器制造。
- **Decision：** 在 `hash_file` 保持 worker 散列与现有预算，令前后元数据取得末级链接自身信息，不为了避免 ELOOP 静默跳过其它 I/O 错误。静态 ASCII 链接夹具的目标文本与 OID 可验；已有常规文件、gitlink、index 短路和布局守卫的回归由现有表面门覆盖。以本卡列出的测试而不是类比宣称结果。
- **Alternatives：** 对 ELOOP 一律吞错会丢掉扫描条目；在 init 独自跳过快照不能修共享根因。
- **Limit：** `symlink_metadata` 只约束末级，且 worker/持久化/建树是不同观察；不保证任意并发或不读取工作区外目标，不保证捕获所有替换/ABA。IN-01 不宣称改变 `read_stable_file` 或 `tree_from_working_copy`。

### ADR-IN-02：将并发和内容/类型绑定保留为明确未完成项

- **Context：** 扫描得到 OID 后重读，OID 不匹配会 partial（`snapshot.rs:648`）；但中途 `fs::read` 可跟随被替换的路径，且后续 mode 单独读取。元数据大小与时间相同不意味着同一对象。
- **Decision：** 本卡只验证一个确定性窗口：扫描后、持久化前把链接文本从 `old` 改为 `new`，从而 OID 不同；该条目不进入持久化结果并标 partial。此测试不代表能检测 ABA，也不证明路径约束。将父目录固定、最终分量 no-follow、实际读取的类型/内容/OID/mode 绑定为一次可验证观察，连同 tracked index mode、untracked 建树模式与同长度/ABA 窗口，登记为 DEFER-IN-01；只有后续具名实现卡、平台策略和确定性测试落地后才可宣称更强安全合同。
- **Alternatives：** 仅比较两次 lstat 长度与时间无法实现上述完整合同；暂不承诺这一不成立的保障。

### ADR-IN-03：原始结果和范围不外推

#550 的 ref-format 场景必须保留 #473 的有意差异；#1014 的全量验收和其评论不是本卡交付清单。原始 36 项无法重建时 IN-03 保持 blocked；原始命名场景与后续关联用例分开记录。是否关闭公开 issue 由用户决定。

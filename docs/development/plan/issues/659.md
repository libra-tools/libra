# Issue #659：成功路径 stdout 必须与 Git 一致（`reset --mixed` 噪声收敛）

> 模板 v2.16。[Issue #659](https://github.com/libra-tools/libra/issues/659) OPEN，1 条评论（补充 TC-2536）。仅规划，未授权执行；`I659-01` 与 `I659-02` 均为 `pending` / Acceptance 空。Git 对照 pin `6de20f6092dcf9bdb1c8efe03db4b70c82b423dd`。测试用例仓 `/mnt/gitmono/libra-testcases` 本计划不修改。

## 文档职责

### 适用范围

成功路径的 stdout 契约：`reset --mixed` / `reset --soft` 成功时不得打印 hard-reset 专有的 `HEAD is now at <short> <subject>`；`reset --hard` 保留该行；`reset --mixed` 在无差异时静默（有差异时的 `Unstaged changes after reset:` 与路径清单属独立输出轴，见 `DEFER-I659-07`）。同时登记 `add --refresh` 的非 TTY 静默（当前 main 已交付）与 TTY 汇总行为作为回归面。

### 非目标

`reset` 的其它模式语义（`--merge`/`--keep` 的冲突处理、pathspec 形式的输出）、`--quiet`/`--json` 的既有行为、`add` 的其它选项面、`checkout`/`restore` 的同名文案、`docs/error-codes.md` 的错误码改动（本卡不改错误码）。不修改测试用例仓。

### 成功定义

- （`I659-01`）`libra reset --mixed HEAD`（无差异）stdout 为空且退出 0。
- （`I659-01`）`libra reset --soft HEAD`（无差异）stdout 为空且退出 0。
- （`I659-01`）`libra reset --hard HEAD` 输出 `HEAD is now at <short> <subject>` 且退出 0。
- （`I659-01`）在 `HEAD` 作为 target 时：`libra reset --mixed HEAD`（无差异）stdout/stderr 为空；`--hard` 保留 `HEAD is now at`；`--soft` 静默；`--json` 与 `pathspecs` 语义保持不变。mixed 的「`Unstaged changes after reset:` + 路径清单」属独立输出轴，由 `DEFER-I659-07` 承接。
- （`I659-02`）`libra add --refresh <pathspec>` 在非 TTY 下 stdout/stderr 为空（回归）；纯 refresh 在 TTY 下同样静默（含 `--dry-run`）；仅显式 `--verbose` 输出汇总；普通 `add` 的 TTY 汇总不受影响。
- 六份命令/开发文档（`reset` EN/zh-CN/开发、`add` EN/zh-CN/开发）、`COMPATIBILITY.md` 与网站 2 页随两卡交付。

## 已决议设计决策

### ADR-I659-01：按 `ResetMode` 分流成功输出

- **Status:** Accepted
- **Context:** `render_reset_output`（`src/command/reset.rs:2874`）只按 `quiet`/JSON/pathspec 分支，`--mixed`、`--soft`、`--hard` 共用同一 `HEAD is now at ...` 行；Git 仅在 hard 路径输出该行。
- **Decision:** 在 `render_reset_output` 内按 `ResetMode` 分流：`Hard` 打印 `HEAD is now at <short> [<subject>]`；`Mixed` 在无差异时静默（有差异时的 `Unstaged changes after reset:` + 路径清单由 `DEFER-I659-07` 承接，本卡不改该路径输出）；`Soft` 静默；`Merge`/`Keep` **保持现状**（沿用当前成功输出，不在本卡改动），并新增回归门固定该现状。`quiet` 与 `--json` 行为完全不变（含 `pathspecs` 语义）。
- **Alternatives considered:** 在调用点分别打印（分散且重复）；用 `quiet` 变通（改变用户可见选项语义）。
- **Consequences:** 无差异路径的 stdout 与 Git 一致（有差异的路径清单由 `DEFER-I659-07` 承接）；`--hard` 与既有脚本不变；`--json` 与 `pathspecs` 语义完全不变（本卡不改任何 JSON 字段）。
- **Revisit when:** 上游改变 reset 成功文案。

### ADR-I659-02：`add --refresh` 的汇总只由 `--verbose` 启用（含 `--dry-run` 的纯 refresh 一律静默）

- **Status:** Accepted
- **Context:** `emit_body` 现为 `dry_run || verbose || stdout_is_tty_for_add()`（`src/command/add.rs:2448`），未区分 refresh，管道下静默已交付。
- **Decision:** 在 `I659-02` 中把 `emit_body` 改为 `verbose || (!refresh && (dry_run || stdout_is_tty_for_add()))`；`render_add_output`（`add.rs:2425`）签名同步新增 `refresh: bool`，调用点传入 `AddArgs.refresh`。纯 refresh（含 `--dry-run`）一律静默，唯一例外是显式 `--verbose`；普通 `add -n`/TTY 汇总不变。
- **Alternatives considered:** 重写 add 渲染（无必要，且扩大写集）。
- **Consequences:** 写集含 `src/command/add.rs`（一处条件式 + `render_add_output` 签名与调用点同步）、`tests/command/add_test.rs` 与文档。
- **Revisit when:** add 输出策略调整。

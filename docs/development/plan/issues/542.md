### ADR-LF-02：目录折叠与 nested repository 边界分卡

- **Status:** Accepted
- **Context:** `--directory` 是输出折叠；nested repository 是遍历边界。普通 `-o` 也会经过 nested repo，二者可独立恢复。
- **Decision:** LF-02 先建立边界，LF-03 再实现 directory/no-empty-directory；不得用「折叠后看不见内部文件」替代普通 `-o` 的边界修复。边界只在 ls-files 内部实现：新增 `pub fn list_workdir_files_for_ls_files_others(root: &Path, respect_ignore: bool) -> Result<Vec<PathBuf>>`（`src/utils/util.rs`，additive-only 新 pub fn，不改 `list_files` / `list_workdir_files*` 的任何既有函数体），`ls_files.rs` 的 others 枚举两分支（`{ !needs_per_file && exclude_standard }` 走 `respect_ignore=true`、unfiltered 分支走 `respect_ignore=false`）均改走它；plain `-o`（无 `--exclude-standard`）属于 unfiltered 分支，同样受 nested 边界。`clean`/`grep` 共用的 `list_workdir_files*` 与 `status`/`mv` 自有 walker 保持不变。
- **Alternatives considered:** 改写共享的 `list_files` / `list_files_respecting_libraignore` —— 这两处同时被 `clean`/`grep`（及 `list_workdir_files`/`integrate_pathspec`）调用，改动面超出本卡已确定的行为轴，拒绝。合并为一个「目录处理」卡：同时改变 walker 与输出合同，违反 G-01。
- **Consequences:** 两卡共享 walker 和文档，必须串行；clean/grep/status/mv 的 nested-repo 边界未在本计划内修正，列为 Out of scope，由未排期 issue 承接；LF-02 用具名新测试证明 clean 与 grep 在解析前后语义不变。
- **Revisit when:** 系统 git 复核证明普通 `-o` 的 nested repo 表现与评论映射不同。

### ADR-LF-03：`--format` 只承诺 issue 证据涉及的字段集

- **Status:** Accepted
- **Context:** 评论概述字段不完整；TC-3393 实际还使用 `%(stage)` 与 `%x09`，TC-3395 实际使用 `%(eolattr)`。这些已由公开 TC 文件核实，不能只按评论概述划定支持集。
- **Decision:** LF-06 先独立交付 objectmode/objectname/stage/path 与 `%x09` 的有界格式化；LF-10 独立修复已有 `--eol` 的属性列；LF-06A 在两者发布后独立增加 eolinfo:index/worktree 和 eolattr 字段。LF-06 的发布文档须列出当时仅支持的字段，未支持的字段明确拒绝；LF-10 只改变已有 `--eol`，不引入新 format atom；LF-06A 完成后补齐 TC-3395。三个切片分别自洽并可由新版本前滚；不存在只有家族发布点前才能启用的半实现。其它 atom 登记 DEFER-LF-05。
- **Alternatives considered:** 将新增 format 与既有 `--eol` 的属性行为混入一张卡：存在不同公开入口和可独立恢复的发布边界，拒绝。所有字段、格式错误与组合判据压入单卡：独立 AC 超过 8，拒绝。完整移植 Git 全部 ls-files format：超出 issue 证据且规模不可控。
- **Consequences:** 开工用系统 git 复核句法、`-z` 与组合；文档必须按每一已发布切片列出实际支持字段，不能写成全量 Git format。
- **Revisit when:** 新 issue 要求其它字段。

### ADR-LF-04：`--with-tree` 是内存路径补充视图，不落盘

- **Status:** Accepted
- **Context:** TC-3394 同时证明选项缺失和 `-u` 组合错误未进入。
- **Decision:** 在 index 加载后构造只读路径补充视图，为 tree 中有而 index 中已删除的路径参与列表/pathspec；同名路径保留当前 index 对象，不用 tree 对象覆盖。不得写 index、对象库或 worktree。与 `-s/-u` 组合按本机 Git 2.56.0 探针以 128 拒绝；其它组合须开工复核后决定。
- **Alternatives considered:** 暂存 tree 后再恢复 index：引入崩溃窗口且违反只读边界，拒绝。只接受选项但忽略 tree：静默错误，拒绝。
- **Consequences:** 需要对象读取失败与 hash-kind 覆盖测试。
- **Revisit when:** 新需求要求 `--with-tree` 与其它筛选选项的完整组合矩阵。

### ADR-LF-05：icase 修复位于共享引擎，不做 ls-files 特判

- **Status:** Accepted
- **Context:** cwd 前缀和本体在 parse 阶段被合成，ls-files 外层无法可靠还原各段大小写规则。
- **Decision:** 在 `src/utils/pathspec/` 保留「cwd 字面前缀」与「pathspec 本体」的匹配边界；`:(top)` 与仓库根调用不受影响。`PathspecDepthRoot` 扩展携带可判定的 literal 前缀组件边界；grep 的 max-depth 先按该边界匹配再算深度，不能简单以仓库根替代深度根。status rename probe 对无法安全缩窄的 icase 根保守回退仓库根，最终由完整 `matches_path` 过滤。`positive_prefixes: Vec<PathBuf>` 无法独自表达混合大小写，rm 不得将它当成精确目录集；改为从相关 tracked 候选/目录导出再用完整 matcher 判定递归边界。不得只在 ls-files 后置过滤，否则其它共享引擎命令仍错误。已读调用面还包括 add 的 ignore 分类 `positive_spec_match_path`（其当前注释记录只能保守交给大小写敏感 ignore 引擎）、diff 的 `plain_positive_prefixes`（icase 返回 `None` 而最终仍由完整 matcher 过滤）、restore/reset/add 的最终 matcher 或 unmatched 检查。不能宣称这些调用均不受影响：LF-08 将逐个核对其大小写分类或投影，保守缩窄/分类须保持保守，最终选择继续使用完整 matcher；需要扩展的生产写集在开工前登记为 ER-10 修订，不得静默越界。
- **Alternatives considered:** ls-files 专用 patch：违反 GC-02 且无法修复根因。
- **Consequences:** LF-08 命中 T-1，必须全量 nextest；跨命令行为变化要在该卡记录。
- **Revisit when:** 共享 pathspec 表示层另有重构计划。

- **GC-LF-09 nextest 不生成 JUnit：** 默认 profile 的 `.config/nextest.toml:10-11` 会写 `junit.xml`，而 v2.12 禁止新建 JUnit XML。本计划每条 `cargo nextest run`（含 focused、C 组与 CLOSE-542）都必须带 `--config-file "$NEXTEST_NOJUNIT_CFG"`。**每条命令运行前都重新执行以下块**，在仓库根目录的 `bash -euo pipefail` 中用 `mktemp -d` 新建私有仓外目录，生成本次独立配置文件；不得复用配置文件、覆盖已有文件或接受调用者提供的输出路径。Rust 编译缓存可按常规复用：

  ```bash
  set -euo pipefail
  REPO_ROOT="$(pwd -P)"
  NEXTEST_TMP_PARENT="$(cd "${TMPDIR:-/tmp}" && pwd -P)"
  case "$NEXTEST_TMP_PARENT/" in "$REPO_ROOT"/*) printf '%s\n' 'temporary parent resolves inside the repository' >&2; exit 1 ;; esac
  NEXTEST_NOJUNIT_DIR="$(mktemp -d "$NEXTEST_TMP_PARENT/libra542-nojunit.XXXXXXXX")"
  cleanup_nojunit() {
    original_status=$?
    trap - EXIT
    if ! rm -rf -- "$NEXTEST_NOJUNIT_DIR"; then
      printf '%s\n' 'failed to clean this run temporary directory' >&2
      if [ "$original_status" -eq 0 ]; then original_status=1; fi
    fi
    exit "$original_status"
  }
  trap cleanup_nojunit EXIT
  chmod 700 "$NEXTEST_NOJUNIT_DIR"
  NEXTEST_NOJUNIT_DIR="$(cd "$NEXTEST_NOJUNIT_DIR" && pwd -P)"
  case "$NEXTEST_NOJUNIT_DIR/" in "$REPO_ROOT"/*) printf '%s\n' 'temporary directory resolves inside the repository' >&2; exit 1 ;; esac
  NEXTEST_NOJUNIT_CFG="$NEXTEST_NOJUNIT_DIR/nextest.toml"
  test ! -e "$NEXTEST_NOJUNIT_CFG"
  test ! -L "$NEXTEST_NOJUNIT_CFG"
  (set -o noclobber; grep -v -x -F -e '[profile.default.junit]' -e 'path = "junit.xml"' .config/nextest.toml > "$NEXTEST_NOJUNIT_CFG")
  test "$(grep -c -x -F '[profile.default.junit]' "$NEXTEST_NOJUNIT_CFG" || true)" = 0
  test "$(( $(wc -l < .config/nextest.toml) - $(wc -l < "$NEXTEST_NOJUNIT_CFG") ))" = 2
  ```

  规范化后的物理路径若在仓库内（包括经 symlink 或 `..` 迂回）立即失败；`noclobber` 和新私有目录共同避免覆盖既有内容。每条 nextest 命令与准备块放在单独 shell 运行；EXIT trap 只清理本轮专属目录，原命令失败时保留其原退出码，清理失败且命令成功时返回非零。该配置只供本次 nextest 进程使用，不是证据文件，不入库。`cargo-nextest 0.9.143` 的 `run` 支持 `--config-file <PATH>`；若配置行写法改变导致行数断言失败，先修订本节，不得绕过。

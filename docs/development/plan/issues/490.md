# Issue #490：skip-worktree 索引位与 `add` 稀疏路径诊断计划（2026-09-14）

## 文档职责

本文解决 issue #490：Libra 无法构造 Git 的 skip-worktree 索引状态，TC-0010 的准备步骤在 `update-index --force-remove` 处即失败，目标命令 `add --dry-run --ignore-missing sparse_entry` 从未执行。

核对发现，缺口不在命令行参数层，而在索引格式层：
- skip-worktree 位存放在 **index v3 的扩展标志字**中，而 Libra 依赖的 `git-internal`（本机 pin `0.8.6`，最新发布 `0.9.0`，同属 `libra-tools` 组织）读取时拒绝 version ≠ 2、写出固定 v2。
- 兼容登记 D10（`_compatibility.md:173`）已把「skip-worktree 索引位」列为稀疏检出的前置能力。
- 即使只加参数，Libra 的其它命令在重写索引时也会丢失该位，`status` 会把 skip-worktree 条目报告为删除（实测 ` D sparse_entry`）。

本计划按依赖链交付：
1. 采用支持 index v3 扩展标志的 `git-internal`；
2. `update-index --force-remove`；
3. 各类索引重写命令保留该位；
4. `status`/`diff` 尊重该位；
5. `add` 稀疏诊断与 `--sparse` 已移交 [`plan-20260918.md`](../plan-20260918.md) SW-06；
6. 本计划最后开放 `update-index --skip-worktree/--no-skip-worktree` 与 `ls-files` 的 `S` 标记，并移植 TC-0010。

`sparse-checkout` 命令、稀疏模式文件与工作树物化仍按 D10 延后。

本文只规划任务，不宣称实现完成。落地时每个任务都必须先刷新源码锚点，再按任务卡验收。

### 适用范围

- `update-index`：`--force-remove`、`--skip-worktree`、`--no-skip-worktree`，以及 `--remove` 对 skip-worktree 条目的处理。

### Git skip-worktree 行为真值（2026-09-14 实测）

| 情形 | git 2.54 |
|---|---|
| 设置位后删除或修改工作树文件 | `status --porcelain`、`diff --name-only` 均为空 |
| `add sparse_entry`、`add --dry-run sparse_entry`（文件缺失或已修改） | exit 1，稀疏诊断，条目不变 |
| `add --sparse sparse_entry`（文件存在且修改） | exit 0，暂存新内容，位保留（`S`） |
| `add --sparse --dry-run sparse_entry`（文件缺失） | exit 128，`pathspec 'sparse_entry' did not match any files` |
| `add -A --dry-run`（无 pathspec） | exit 0，不暂存删除 |
| `update-index --no-skip-worktree` | 位清除（`H`），索引头版本回到 2 |
| `update-index --force-remove sparse_entry` | 条目删除，exit 0 |
| `update-index --remove <存在的普通文件>` | 条目**保留**（Git 仅在文件缺失时删除） |
| `core.sparseCheckout true` 且无稀疏模式文件 | 对该条目 `add --dry-run --ignore-missing` 同样给出稀疏诊断 |
| 位保留：`reset --hard`、`reset -q HEAD`、`checkout -- s`（exit 1）、`restore --staged s`（exit 1）、`commit -a`（文件删除或他文件修改）、`switch` 往返、`stash` push/pop、`update-index` 他文件、`merge`（ff）、`cherry-pick`、`read-tree -m HEAD` | 位均保留（`S`） |
| 位清除：`read-tree HEAD`（无 `-m`） | 变为 `H` |
| `rm --cached s` | exit 128，pathspec 不匹配；条目保留 `S` |
| `mv s s2` | exit 0；`s` 条目移走 |

## 评审结论与修订记录

| 维度 | 结论 | 修订动作 |
|---|---|---|
| 合理性 | 只加参数会产生「能设置、但被其它命令静默清除、`status` 仍报告删除」的不一致状态 | 按依赖链先保留、再尊重、最后开放设置入口 |
| 可行性 | 索引格式在同组织的外部 crate 中；Libra 自身已有 `raw_index_blob` 快照与 v2-only 解析器需要适配 | 外部工作登记为 DEP-SW-01，契约写入 ADR-SW-02 |
| 任务卡粒度 | 格式采用、删除入口、两类重写命令保留、status 尊重、add 诊断、设置入口是 7 个可独立恢复的轴 | 7 张卡；重写命令按「暂存类/历史改写类」拆分以控制在 M |
| 依赖与顺序 | 开放设置入口（SW-07）必须晚于保留与尊重（SW-03..06），测试在此之前通过直接构造索引获得该位 | 实施顺序固定 SW-01 → SW-03 → SW-04 → SW-05 → SW-07；SW-02 独立 |
| 完整性 | Git 生成的 v3 索引、未知扩展位、v4、降级到旧 Libra 读取 v3 索引都需处理 | ADR-SW-02、SW-07 恢复模式 |
| 安全性 | 未知扩展位若被忽略可能丢失语义 | fail-closed（`LBR-REPO-002`） |
| 功能正确性 | 保留规则因命令而异（`read-tree` 无 `-m` 清除） | 判据矩阵以 git 2.54 实测为准 |
| 接口兼容 | 设置位后索引变为 v3，旧版 Libra 无法读取 | SW-07 `Rollback mode = compensating`：降级前清除位；文档写明 |
| 数据流与控制流 | 保留逻辑必须单点实现 | ADR-SW-03：共享 helper，禁止各命令各自复制标志 |
| 性能与容量 | 读取扩展标志字为每条目 2 字节 | 无显著影响 |
| 可靠性与容错 | 损坏索引不得被静默修复为 v2 | 读取失败沿用 fail-closed |
| 可维护性 | D10、sparse-view 文档需区分「索引位已支持」与「稀疏检出命令仍延后」 | SW-07 统一修订 |

## 已决议设计决策

实现时若需偏离本节，必须先修改计划并说明原因，不得在代码中静默改语义。

### ADR-SW-01: 部分重开 D10

- **Status:** Accepted
- **Context:** D10 延后原因是「依赖 skip-worktree 语义」；TC-0010 与 `t3705` 系列只需要索引位及其尊重语义，不需要稀疏模式或物化。
- **Decision:**
  1. 交付 skip-worktree 索引位的读写、保留、`status`/`diff` 尊重、`add` 稀疏诊断、`update-index` 设置入口与 `ls-files` 观察入口。
  2. `sparse-checkout` 命令、`info/sparse-checkout`、cone 模式、工作树物化与 `clone --sparse` 继续按 D10 延后。
  3. `core.sparseCheckout` 可被设置与读取，但 Libra 不评估稀疏模式：值为 `true` 时，尊重 skip-worktree 位的命令发出一次性 warning，说明模式匹配不受支持，行为与 `false` 相同（与 Git 的差异登记）。
  4. `sparse-view` 保持只读视图，不写入该位。
- **Alternatives considered:** 实现完整 `sparse-checkout`——超出 issue 且 D10 的重启条件（RFC）未满足，拒绝。只加参数不做保留与尊重——产生不一致状态，拒绝。
- **Consequences:** D10 条目拆为「索引位（已交付）」与「命令与物化（延后）」两部分。
- **Revisit when:** 出现大型 monorepo 子树检出需求并完成 D10 RFC。

### ADR-SW-02: 索引格式契约（`git-internal` 上游）

- **Status:** Accepted
- **Context:** GAP-01；git `read-cache-ll.h:19-20`、`:35`、`:70-75`，`read-cache.c:1821-1827`、`:2647-2648`、`:2852-2855`。
- **Decision:**
  1. `git-internal` 读取 version 2 与 3；version 4 或其它值 fail-closed。
  2. 条目 `flags & 0x4000` 时读取随后的 16 位扩展标志字，识别 `CE_INTENT_TO_ADD`（扩展位 `0x2000`）与 `CE_SKIP_WORKTREE`（扩展位 `0x4000`）；出现其它扩展位 → 错误（Libra 映射为 `LBR-REPO-002`）。
  3. `Flags` 新增 `skip_worktree: bool`、`intent_to_add: bool`，`extended` 由写出时自动计算。
  4. 写出时，任一条目含扩展位 → 整个索引写为 v3，否则写为 v2；v2 输出与现有实现逐字节相同。
  5. 该变更在 `git-internal` 以 minor 版本发布（`Flags` 新增公开字段属破坏性变更）。
- **Alternatives considered:** Libra 在 crate 外自行解析扩展字——形成第二个索引解析器，违反 GC-02，拒绝。总是写 v3——改变未使用扩展位仓库的字节并影响旧客户端，拒绝。
- **Consequences:** 设置位后旧版 Libra（v2-only）无法读取索引，需要 SW-07 的补偿说明。
- **Revisit when:** 需要 index v4 或 split index。

### ADR-SW-03: 标志保留单一实现

- **Status:** Accepted
- **Context:** GAP-04。约 25 处索引写入点在重写已存在条目时丢弃旧标志。
- **Decision:**
  - 新增共享 helper（如 `utils::index_ext::update_preserving_flags(index, new_entry)`）：替换同路径同 stage 的条目时，继承旧条目的 `skip_worktree` 与 `intent_to_add`，除非调用方显式声明清除。
  - 所有「以新条目替换旧条目」的写入点改用该 helper；「从树整体重建索引」的写入点（`read-tree` 无 `-m`）按 Git 语义不继承。
  - 每个写入点的归类（替换 / 重建 / 临时索引）在执行记录中逐条登记，并以判据矩阵验证。
  - 新增 compat 守卫：在 `src/` 中检测绕过 helper 直接 `index.update(` 的新调用（allowlist 记录已归类的例外）。
- **Alternatives considered:** 在 `git-internal` 的 `Index::update` 内自动继承——会让「重建」语义无法表达，且改变所有下游，拒绝。
- **Consequences:** SW-03、SW-04 按命令族分两卡落地；守卫在 SW-03 引入、SW-04 收紧 allowlist。
- **Revisit when:** `git-internal` 提供带语义参数的替换 API。

### ADR-SW-04: 尊重语义（`core.sparseCheckout=false`）

- **Status:** Accepted
- **Context:** GAP-05/06；git `builtin/add.c:55-57`、`:599-658`，`dir.c:1612`（稀疏检出关闭时 `path_in_sparse_checkout` 视全部路径在内，只看索引位）。
- **Decision:**
  1. **status/diff：** `changes_to_be_staged_split_with_index` 对 skip-worktree 条目不产生工作树删除或修改（`status`、`diff`/`diff-files`、`add -u`/`-A`、`commit -a` 随之一致）。
  2. **add：** pathspec 只命中 skip-worktree 条目时（且未给 `--sparse`），把该 pathspec 记入稀疏列表，不暂存、不删除，继续处理其它 pathspec；结束时输出稀疏诊断并以非零退出。适用于 `--dry-run`、`--ignore-missing`、`--renormalize`、`--chmod`。
  3. **pathspec 同时命中稀疏与非稀疏条目**（`t3705` 的 `*_entry`）时不给诊断。
  4. **`--sparse`：** 允许更新 skip-worktree 条目并保留该位；文件缺失时行为与 Git 一致（exit 128/Libra 对应的 pathspec 不匹配错误）。
- **Alternatives considered:** 仅在 `add` 内特判——`status` 仍报告删除，`commit -a` 会删除条目，拒绝。
- **Consequences:** 变更计算为共享函数，SW-05 命中 T-1。
- **Revisit when:** D10 物化稀疏落地后需要结合模式匹配。

### ADR-SW-05: `add` 稀疏诊断与退出

- **Status:** Accepted
- **Context:** issue 允许产品化措辞；issues/484 ADR-IA-02、issues/489 ADR-CH-02 已为 `add` 选定「完整渲染后 `silent_exit(1)`」。
- **Decision:**
  - stderr 输出头部「The following paths and/or pathspecs matched paths that exist outside of your sparse-checkout definition, so will not be updated in the index:」，随后逐行输出 pathspec 原文，再输出 Libra 格式的 hint（使用 `--sparse`；或清除 skip-worktree 位 `libra update-index --no-skip-worktree <path>`）。
  - 退出码 1，复用共享的渲染后非零决策 helper。
  - JSON 新增可选字段 `sparse_paths: [string]`（为空不序列化），结构化模式下不输出人读诊断。
  - `advice.updateSparsePath` 不支持（DEFER-02）。
- **Alternatives considered:** 新增稳定错误码并返回 `CliError`——丢失已渲染结果，与 484/489 模型不一致，拒绝。
- **Consequences:** 与 Git 的 hint 行差异登记为有意差异。
- **Revisit when:** 引入 advice 配置体系。

### ADR-SW-06: `update-index` 删除与位设置

- **Status:** Accepted
- **Context:** GAP-03/07；git `builtin/update-index.c:392-398`、`:485-496`。
- **Decision:**
  - `--force-remove`：删除给定路径的全部 stage 条目，不论文件是否存在，未跟踪路径为无操作（exit 0）。
  - `--skip-worktree` / `--no-skip-worktree`：对已跟踪路径设置或清除该位，不读取工作树；未跟踪路径的错误与退出码以 git 实跑为准。
  - `--remove` 遇到 skip-worktree 条目时不删除（与 Git 默认一致）；`--remove` 对普通存在文件的既有 Libra 语义不变（DEFER-01）。
- **Alternatives considered:** 把 `--remove` 整体改为 Git 语义——破坏既有文档化示例，超出本 issue，拒绝。
- **Consequences:** `--force-remove` 不依赖索引格式，可先行发布（SW-02）。
- **Revisit when:** DEFER-01 排期。

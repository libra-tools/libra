## 文档职责

issue #481 写于 libra 0.22.5。本计划在本机安装的 libra 0.22.28（`v0.22.25..HEAD` 在相关 `src/` 文件中无变更，安装版代表当前源码）与 git 2.54.0 上并排实跑两轮，逐条复核。结论分四类：

- **已修复或断言不成立：**
  - `repack -d`、`worktree move/lock/unlock`、`bisect visualize/run` 已存在；
  - `fsck --strict` 不是空操作，确实增加提交时区/邮箱与树条目检查；
  - `bisect log` 无会话时不再 exit 0（现为 128）；
  - `check-mailmap --stdin`、`check-ignore` 与 Git 一致。
- **确认的缺口：**
  - **P1：** `repack` 后同一对象同时存在于松散对象与 pack（或多个 pack）中，短 SHA 被判为「ambiguous」。
  - **bisect 卡死：** 仓库处于上述状态时，`bisect good` 报 `failed to resolve checkout source`，之后连 `bisect reset` 也失败。
  - **缺失的命令与参数：**
    - `gc` 不存在；
    - `repack` 缺 `--window/--depth/-l`，且不删除冗余 pack；
    - `merge-base` 缺 `--octopus/--independent/--fork-point`；
    - `merge-file` 缺 `-L/--ours/--theirs/--union/--marker-size`，默认标签与 Git 不同；
    - `replace` 缺 `--format/--graft/--edit/--convert-graft-file`；
    - `worktree remove` 缺 `-f`；
    - `bisect terms` 缺失；
    - `archive` 不按 `-o` 扩展名推断格式；
    - `check-attr` 缺 `--cached/--source`。
- **新发现：**
  - 真正有歧义的短 SHA 诊断与 Git 不同；
  - `log <有歧义前缀>` 静默 exit 0 无输出；
  - bisect 收敛后再标记报内部错误；
  - 签名提交的 culprit 主题显示为 `gpgsig` 头；
  - 新仓库因未跟踪的 `.libraignore` 无法 `bisect start`；
  - `fsck` 把 Git 视为警告的零填充文件模式当作错误；
  - `archive` 不写目录条目。

本计划按风险交付 16 张卡：
1. **Phase 1（短 SHA 与 bisect 可用性）：** MX-01..MX-03。
2. **Phase 2（bisect 对齐）：** MX-04、MX-05。
3. **Phase 3（对象维护）：** MX-06..MX-09。
4. **Phase 4（命令面补齐）：** MX-10..MX-16。

目标是完全解决 issue 描述的全部问题。仅在有明确理由时延后（`repack --write-bitmap-index`、`archive --remote/--exec`、`bisect replay`），理由见「非目标与延后项」。

本文只规划任务，不宣称实现完成。落地时每个任务都必须先刷新源码锚点，再按任务卡验收。

### 适用范围

- 短对象名解析：候选去重、真实歧义的诊断，以及 `rev-parse`、`cat-file`、`log`、`show`、`checkout`、`merge-base`、`branch`、`bisect`、`restore --source` 等消费方的一致性。
- `bisect`：失败步骤不卡死、`reset` 总能恢复、收敛后再标记、culprit 展示、未处于 bisect 时的统一错误、`start <bad> [<good>...]` 位置参数、未跟踪文件不阻止开始、`terms` 与自定义术语（重开 D7）。

- `check-attr --cached/--source`；`merge-base --octopus/--independent/--fork-point`；`merge-file -L/--ours/--theirs/--union/--marker-size` 与默认标签；`replace --format/--graft/--edit/--convert-graft-file` 与 `-d` 输出；`worktree remove -f/-f -f`、`worktree add -f`。

### ADR-MX-03: bisect 会话安全与统一错误

- **Status:** Accepted
- **Context:** 条目 3、20；N3、N4；git `builtin/bisect.c:250`、`:1142`，`bisect.c:975`。
- **Decision:**
  1. **原子步骤：** 每个 `good/bad/skip` 步骤先完成候选计算与 restore 预检，再写入状态；restore 失败时不修改 `bisect_state`。
  2. **reset 兜底：** `reset` 恢复原 HEAD 的失败不得阻止清除会话；恢复失败时输出恢复提示，并在清除状态前保留原分支记录以便重试。
  3. **收敛后再标记：** 已收敛会话再次 `good/bad` 时 exit 0，重新输出 culprit。
  4. **culprit 展示：** 主题取提交消息正文（跳过 `gpgsig` 等头部），输出格式对齐 `bisect.c:975` 的 `show_commit`（M-BSAFE S3 实跑写回）。
  5. **统一错误：** 无会话时所有需要会话的子命令映射为 `LBR-BISECT-001`；`reset` 无会话输出 `We are not bisecting.` 并 exit 0。
- **Alternatives considered:** 只修复短 SHA 去重——restore 的其它失败（如文件冲突）仍会卡死会话，拒绝。
- **Consequences:** `bisect_state` 写入顺序调整；`bisect_test` 增加故障注入用例。
- **Revisit when:** 无。

### ADR-MX-04: 短对象名候选去重与歧义诊断

- **Status:** Accepted
- **Context:** GAP-01、GAP-02；git `object-name.c:55-102`、`:292`、`:515`、`:537`。
- **Decision:**
  1. **去重位置：** 在存储层去重，使所有调用方自动受益：`LocalStorage::search` 返回前排序去重，`ClientStorage::search_result`（`src/utils/client_storage.rs:1844`）返回前再按 OID 去重；`resolve_hash_atom_typed` 保留防御性去重。直接调用 `search`/`search_result` 的 `rev_parse.rs:878`、`ls_tree.rs:247`、`am.rs:767`、`restore.rs:824`、`:943`、`:974` 由此一并修复（`restore` 的 `ResolveSource` 失败即 bisect 卡死的直接原因）。
  2. **歧义诊断：** 真实歧义时错误消息为 `short object ID <p> is ambiguous`，hint 以 `The candidates are:` 起头列出 `<abbrev> <type>`（排序与格式以 git 实跑为准），`--json` 在 `details.candidates` 中给出完整 OID 与类型。
  3. **消费方一致：** `rev-parse`、`cat-file`、`show`、`log`、`checkout`、`merge-base`、`branch`、`bisect`、`restore --source` 均经共享解析得到同一结果。`log` 解析失败必须非零退出；`checkout` 仅在修订确实无法解析时才回落为 pathspec。
- **Alternatives considered:** 只在 `LocalStorage::search` 去重——其它存储实现或未来的多来源搜索仍可能重复，拒绝。
- **Consequences:** MX-01 命中 T-1（共享修订解析）；MX-02 修改共享错误文案。
- **Revisit when:** 支持 `core.disambiguate`。

### ADR-MX-08: repack 的 pack 生命周期与 `-l`

- **Status:** Accepted
- **Context:** 条目 9；N6；git `builtin/repack.c:207`、`:220`、`:719`；`t7700:86`、`:94`。
- **Decision:**
  1. **冗余 pack：** `-a -d` 在新 pack 与 idx 写入并同步后，删除内容已被新 pack 完全覆盖的旧 pack 及其 idx；`-d` 不带 `-a` 的行为以 M-REPACK R3 实跑为准。

### ADR-MX-13: check-attr、merge-base、merge-file 参数语义

- **Status:** Accepted
- **Context:** 条目 11、12、13；N8；git `builtin/check-attr.c:27`、`:31`，`builtin/merge-base.c:128-168`，`builtin/merge-file.c:77-121`。
- **Decision:**
  1. **check-attr：** `--cached` 从索引中的 `.gitattributes` blob 读取；`--source=<tree-ish>` 从该树读取；二者组合以 M-ATTR T3 实跑为准。复用 archive 已有的「从树读取属性源」逻辑。

- **Consequences:** merge-file 默认标签是可观察输出变化，文档登记。
- **Revisit when:** 支持 `merge-file --object-id`。

- **Context:** 条目 14；git `builtin/replace.c:150`、`:565-571`；`t6050`。
- **Decision:**
  1. **输出：** `-l --format=short|medium|long` 与 Git 一致；`-d` 每删除一项输出 `Deleted replace ref '<oid>'`。
  2. **`--graft <commit> [<parent>...]`：** 基于原提交生成替换提交，父提交可为 tag（剥离到提交），签名头按 Git 规则移除。
  3. **`--edit <object>`：** 以 `cat-file -p` 形式写入临时文件，经编辑器修改后按类型重新写入；内容不变时报错。
  4. **`--convert-graft-file`：** 读取 `.libra/info/grafts`（双布局下也读 `.git/info/grafts`），逐行生成 graft 替换，全部成功后删除该文件，任一失败不删除。
- **Alternatives considered:** 不支持 grafts 文件——`t6050:518` 与迁移场景需要，拒绝。
- **Consequences:** 替换引用仍存于 `.libra/refs/replace/`。
- **Revisit when:** 无。

### 故障恢复矩阵

| 故障点 | 可接受残留 | 恢复动作 | 禁止结果 |
|---|---|---|---|
| bisect 某一步 restore 失败 | 会话停在失败前状态 | 报错并提示 `bisect reset` 或处理冲突后重试 | 状态前进而工作树未更新；`reset` 失败导致会话无法结束 |
| `repack -a -d` 在写新 pack 时中断 | 旧 pack 与松散对象完好，可能残留临时文件 | 下次 `repack`/`gc` 清理临时文件 | 删除旧 pack 而新 pack 不完整 |
| `gc` 在删除阶段中断 | 部分不可达松散对象已删除 | 重跑 `gc` | 删除可达对象或被借用对象 |
| `worktree remove -f` 删除目录中途失败 | 注册表保留 `tombstone` | `worktree repair --confirm` 重试 | 注册表已清除而目录部分残留且无记录 |
| `replace --convert-graft-file` 某行失败 | 已生成的替换引用保留，grafts 文件保留 | 修正该行后重跑 | 删除 grafts 文件而引用不完整 |
| 发布步 `gh release create` 失败 | 已推送的 `main` 提交 | 按 ER-09 记录，下一窗口补 tag/release | blind retry；只推 `main` 就宣称已发布 |
| D 组 `release.yml` 失败 | 已存在的 tag | 前滚修复，发新 patch | 回退已推送提交或删除已发布 artifact |

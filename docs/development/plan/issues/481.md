## 文档职责

issue #481 写于 libra 0.22.5。本计划初版基线（2026-09-15）曾在本机当时的 libra 0.22.28 与 git 2.54.0 上并排实跑两轮；当前仓库 `Cargo.toml:3` 为 `0.30.205`（PATH `libra` 为 `0.30.157`），本轮修订（2026-11-15）均以当前源码树及实测为准，历史基线仅作问题起源对照。结论分四类：

- **已修复或断言不成立：**
  - `repack -d`、`worktree move/lock/unlock`、`bisect visualize/run` 已存在；
  - `fsck --strict` 不是空操作，确实增加提交时区/邮箱与树条目检查；
  - `bisect log` 无会话时不再 exit 0（现为 128）；
  - `check-mailmap --stdin`、`check-ignore` 与 Git 一致。
- **确认的缺口：**
  - **P1：** `repack` 后同一对象同时存在于松散对象与 pack（或多个 pack）中，短 SHA 被判为「ambiguous」。
  - **bisect 卡死：** 仓库处于上述状态时，`bisect good` 报 `failed to resolve checkout source`，之后连 `bisect reset` 也失败。
  - **缺失的命令与参数：**
    - `gc` 不存在；
    - `repack` 缺 `--window/--depth/-l`，且不删除冗余 pack；
    - `merge-base` 缺 `--octopus/--independent/--fork-point`；
    - `merge-file` 缺 `-L/--ours/--theirs/--union/--marker-size`，默认标签与 Git 不同；
    - `replace` 缺 `--format/--graft/--edit/--convert-graft-file`；
    - `worktree remove` 缺 `-f`；
    - `bisect terms` 缺失；
    - `archive` 不按 `-o` 扩展名推断格式；
    - `check-attr` 缺 `--cached/--source`。
- **新发现：**
  - 真正有歧义的短 SHA 诊断与 Git 不同；
  - `log <有歧义前缀>` 静默 exit 0 无输出；
  - bisect 收敛后再标记报内部错误；
  - 签名提交的 culprit 主题显示为 `gpgsig` 头；
  - 新仓库因未跟踪的 `.libraignore` 无法 `bisect start`；
  - `fsck` 把 Git 视为警告的零填充文件模式当作错误；
  - `archive` 不写目录条目。

本计划按风险交付 16 张卡：
1. **Phase 1（短 SHA 与 bisect 可用性）：** MX-01..MX-03。
2. **Phase 2（bisect 对齐）：** MX-04、MX-05。
3. **Phase 3（对象维护）：** MX-06..MX-09。
4. **Phase 4（命令面补齐）：** MX-10..MX-16。

目标是完全解决 issue 描述的全部问题。仅在有明确理由时延后（`repack --write-bitmap-index`、`archive --remote/--exec`、`bisect replay`），理由见「非目标与延后项」。

本文只规划任务，不宣称实现完成。落地时每个任务都必须先刷新源码锚点，再按任务卡验收。

### 适用范围

- 短对象名解析：候选去重、真实歧义的诊断，以及 `rev-parse`、`cat-file`、`log`、`show`、`checkout`、`merge-base`、`branch`、`bisect`、`restore --source` 等消费方的一致性。

- `check-attr --cached/--source`；`merge-base --octopus/--independent/--fork-point`；`merge-file -L/--ours/--theirs/--union/--marker-size` 与默认标签；`replace --format/--graft/--edit/--convert-graft-file` 与 `-d` 输出；`worktree remove -f/-f -f`、`worktree add -f`。

### ADR-MX-02: 退出码模型

- **Status:** Accepted
- **Context:** Git 对拒绝与无会话多用 exit 1；Libra 稳定错误码表只有 0/9/128/129；[`issues/479.md`](479.md) ADR-PL-02 已决定保留文档化退出码。
- **Decision:**
  1. 本计划的新错误沿用 128（运行期，含 `bisect` 无会话 `LBR-BISECT-001` 对 Git exit 1 的有意偏离）与 129（用法、无效目标，含短对象名真实歧义 `LBR-CLI-003` 对 Git exit 128 的有意偏离）。
  2. Git 语义规定的非错误非零保持 Git 值：`merge-file` 冲突、`merge-base --is-ancestor` 为假、`--fork-point` 无结果。
  3. 脚本通过 stderr 的 `Error-Code:` 行、`--json` 的 `error_code` 与 `LIBRA_FINE_EXIT_CODES=1` 区分类别。
- **Alternatives considered:** 逐命令改为 exit 1——与 479/477 的决策冲突，拒绝。
- **Consequences:** 与 Git 的退出码差异在各命令 `COMPATIBILITY.md` 行登记。
- **Revisit when:** 稳定错误码表进行 major 调整。

### ADR-MX-03: bisect 会话安全与统一错误

- **Status:** Accepted
- **Context:** 条目 3、20；N3、N4；git `builtin/bisect.c:250`、`:1142`，`bisect.c:975`。
- **Decision:**
  1. **原子步骤：** 每个 `good/bad/skip` 步骤先完成候选计算与 restore 预检，再写入状态；restore 失败时不修改 `bisect_state`。
  2. **reset 兜底：** `reset` 恢复原 HEAD 的失败不得阻止清除会话；恢复失败时输出恢复提示，并在清除状态前保留原分支记录以便重试。
  3. **收敛后再标记：** 已收敛会话再次 `good/bad` 时 exit 0，重新输出 culprit。
  4. **culprit 展示：** 主题取提交消息正文（跳过 `gpgsig` 等头部），输出格式对齐 `bisect.c:975` 的 `show_commit`（M-BSAFE S3 实跑写回）。
  5. **统一错误：** 无会话时所有需要会话的子命令映射为 `LBR-BISECT-001`；`reset` 无会话输出 `We are not bisecting.` 并 exit 0。
- **Alternatives considered:** 只修复短 SHA 去重——restore 的其它失败（如文件冲突）仍会卡死会话，拒绝。
- **Consequences:** `bisect_state` 写入顺序调整；`bisect_test` 增加故障注入用例。
- **Revisit when:** 无。

### ADR-MX-04: 短对象名候选去重与歧义诊断

- **Status:** Accepted
- **Context:** GAP-01、GAP-02；git `object-name.c:55-102`、`:292`、`:515`、`:537`。
- **Decision:**
  1. **去重位置：** 在存储层去重，使所有调用方自动受益：`LocalStorage::search` 返回前排序去重，`ClientStorage::search_result`（`src/utils/client_storage.rs:2818`）返回前再按 OID 去重；`resolve_hash_atom_typed` 保留防御性去重。直接调用 `search`/`search_result`/`search_checked` 的 `rev_parse.rs:885`、`ls_tree.rs:258`、`am.rs:772`、`restore.rs:1074`、`:1313`、`:1346` 由此一并修复（`restore` 的 `ResolveSource` 失败即 bisect 卡死的直接原因）。
  2. **歧义诊断：** 真实歧义时错误消息为 `short object ID <p> is ambiguous`，hint 以 `The candidates are:` 起头列出 `<abbrev> <type>`（排序与格式以 git 实跑为准），`--json` 在 `details.candidates` 中给出完整 OID 与类型。

- **Alternatives considered:** 只在 `LocalStorage::search` 去重——其它存储实现或未来的多来源搜索仍可能重复，拒绝。
- **Consequences:** MX-01 命中 T-1（共享修订解析）；MX-02 修改共享错误文案。
- **Revisit when:** 支持 `core.disambiguate`。

### ADR-MX-05: bisect start 参数与工作树策略

### ADR-MX-06: fsck 消息严重级别

- **Status:** Accepted
- **Context:** 条目 6；git `fsck.h:89`、`fsck.c:110`、`:627-661`、`:789-791`、`:877`、`:945`。
- **Decision:**
  1. **级别表：** 引入 `FsckSeverity` 与 `FsckMessage`，`FsckMsgId::severity()` 按 Git msg-id 表映射严重级别（`zeroPaddedFilemode` 为 `Warning`；`badTimezone` 为 `Error` 且只校验格式，不校验取值范围）。
  2. **提升规则：** 默认只有错误决定非零退出，警告输出 `warning in <type> <oid>: <msgId>: <text>`；`--strict` 把警告提升为错误并输出 `error in ...`。
  3. **既有 strict 检查：** 按 M-FSCK F4 实跑重新归类；其中 `badEmail` 与 `treeNotSorted` 保留 Libra 既有的 `strict-only` 行为（`badEmail` 为有意更严，见 M-FSCK F4 写回）。
  4. **`--json`：** 输出每条消息的 `severity`。
- **Alternatives considered:** 维持「一律错误」——与 Git `t1450` 的 strict 语义不符，且让含零填充模式的历史仓库无法通过默认 fsck，拒绝。
- **Consequences:** 默认 fsck 对部分历史对象从失败变为警告，文档登记。
- **Revisit when:** 支持 `fsck.<msg-id>` 配置（DEFER-06）。

### ADR-MX-08: repack 的 pack 生命周期与 `-l`

- **Status:** Accepted
- **Context:** 条目 9；N6；git `builtin/repack.c:207`、`:220`、`:719`；`t7700:86`、`:94`。
- **Decision:**
  1. **冗余 pack：** `-a -d` 在新 pack 与 idx 写入并同步后，删除内容已被新 pack 完全覆盖的旧 pack 及其 idx；`-d` 不带 `-a` 的行为以 M-REPACK R3 实跑为准。
  2. **`-l/--local`：** 跳过仅存在于 alternates 对象目录中的对象。
  3. **安全：** 删除前再次确认旧 pack 中每个对象都在新 pack 中；任一检查失败则保留全部旧 pack。
- **Alternatives considered:** 保留旧 pack 由 gc 清理——`repack -a -d` 的 Git 语义即删除冗余 pack，且 pack 累积加剧短 SHA 重复，拒绝。
- **Consequences:** `pack_writer` 调用方新增删除步骤；与 issues/487 串行。
- **Revisit when:** 支持 `.keep` pack 或 geometric repack。

### ADR-MX-09: delta 压缩参数

- **Status:** Accepted
- **Context:** 条目 9；历史基线 `src/internal/pack_writer.rs:91` 曾以窗口 0 构造编码器；当前 `Cargo.toml:29` 锁定 `git-internal = "=0.10.4"`，支持外部窗口参数但链深上限固定为 `MAX_CHAIN_LEN=50`；git `builtin/repack.c:231`、`:235`。
- **Decision:**
  1. **参数：** `repack` 新增 `--window=<n>` 与 `--depth=<n>`，缺省取 `pack.window`/`pack.depth`，默认 10/50（与 Git 一致）。
  2. **aggressive：** `gc --aggressive` 使用窗口 250、深度 50（与 Git `gc.aggressiveWindow`/`gc.aggressiveDepth` 默认一致）。
  3. **边界：** 维护任务的内部 pack 写入沿用同一默认值；窗口 0 保持无 delta。
  4. **依赖：** 若 `git-internal`（当前 `0.10.4`）编码器不支持外部链深上限，按 ER-MX-03 登记上游依赖（`DEP-MX-08`）并按 `DEFER-07` 延后强制链深限制。
- **Alternatives considered:** 默认保持窗口 0——与 Git 默认不一致，打包体积显著更大，拒绝。
- **Consequences:** 默认打包耗时增加，受性能预算约束；`pack_writer` 为共享实现，MX-09 命中 T-1。
- **Revisit when:** 需要多线程 delta 搜索调优。

### ADR-MX-10: archive 格式推断与条目

- **Status:** Accepted
- **Context:** 条目 4、5；N7；git `archive.c:171-213`、`:245`、`:590`、`:664`、`:673`、`:805-830`。
- **Decision:**
  1. **格式推断：** 未显式给 `--format` 时，按 `-o` 文件名后缀推断：`.zip` → zip，`.tgz`/`.tar.gz` → tar.gz，其它 → tar。显式 `--format` 优先。为此 `--format` 的缺省值改为「未指定」。
  2. **目录条目：** tar 与 zip 为每个目录写入目录条目（含前缀目录）。
  3. **列表：** `-l` 先输出 `tar`、`tgz`、`tar.gz`、`zip`，再输出 Libra 扩展 `tar.bz2`；`tgz` 为 `tar.gz` 别名。
  4. **新参数：** `--worktree-attributes` 从工作树读取属性；`--add-virtual-file=<path>:<content>` 写入内联内容。
  5. **远程：** `--remote/--exec` 返回 `LBR-UNSUPPORTED-001` 与说明（DEFER-02）。
- **Alternatives considered:** 只加 hint 提示使用 `--format`——Git 用户的 `-o x.zip` 仍得到 tar，拒绝。
- **Consequences:** 输出成员列表变化，文档登记。
- **Revisit when:** Libra 传输层提供 upload-archive 服务。

- **Context:** 条目 19；D7 的重启条件为「用户明确请求且 bisect run 已稳定」（`_compatibility.md:158-162`），issue 已明确请求，`bisect run` 在 M-BSAFE S6 中验证；git `builtin/bisect.c:601`、`:612-614`。

  4. 术语校验规则与 Git 一致（M-BTERMS T5）。
- **Alternatives considered:** 维持 D7——issue 明确要求，拒绝。

### ADR-MX-12: worktree 强制删除与 repair 确认

- **Status:** Accepted
- **Context:** 条目 15；`COMPATIBILITY.md:250`（worktree 为 `intentionally-different`）；git `builtin/worktree.c:806`、`:1362`、`:1385-1390`、`:1451`（均按固定提交 `1630431f32` 读取）。
- **Decision:**
  1. **`remove -f/--force`：** 等价于 `--delete-dir` 且跳过脏工作树检查；`-f -f` 额外允许删除锁定的 worktree。删除顺序沿用 `--delete-dir` 的「删除并同步父目录后再清理作用域行」。
  2. **`add -f/--force`：** 允许检出已被其它 worktree 使用的分支，以及覆盖缺失但仍登记的路径；`--force --force` 覆盖锁定路径（与 `t2400:1150-1160` 一致）。
  3. **`repair`：** 保持需要 `--confirm`（修改注册表的维护动作），在 worktree 文档与 `COMPATIBILITY.md:250` 写明与 Git 的差异。
- **Alternatives considered:** `remove -f` 仅跳过脏检查但保留目录——与 Git 用户预期（删除目录）不符，拒绝。
- **Consequences:** `remove` 默认的 detach 语义不变。
- **Revisit when:** worktree 注册表模型变化。

### ADR-MX-13: check-attr、merge-base、merge-file 参数语义

- **Status:** Accepted
- **Context:** 条目 11、12、13；N8；git `builtin/check-attr.c:27`、`:31`，`builtin/merge-base.c:128-168`，`builtin/merge-file.c:77-121`。
- **Decision:**
  1. **check-attr：** `--cached` 从索引中的 `.gitattributes` blob 读取；`--source=<tree-ish>` 从该树读取；二者组合以 M-ATTR AT3 实跑为准。复用 archive 已有的「从树读取属性源」逻辑。
  2. **merge-base：** `--octopus`、`--independent`、`--fork-point` 为互斥模式。`--octopus` 与 `--independent` 复用共享 `internal/merge_base.rs`；`--fork-point` 读取 `<ref>` 的 reflog，按 `handle_fork_point` 语义计算。
  3. **merge-file：**
     - 默认标签为三个文件名；`-L` 最多三次，依次覆盖；
     - `--ours/--theirs/--union` 映射到既有 merge driver 的 favor 选项，`--marker-size` 传入 driver；
     - 冲突时 stderr 与 Git 一致（去掉额外警告行，除非 git 实跑证明存在）。
- **Alternatives considered:** 为 merge-file 保留 `ours/theirs` 标签——脚本按文件名解析会失败，拒绝。
- **Consequences:** merge-file 默认标签是可观察输出变化，文档登记。
- **Revisit when:** 支持 `merge-file --object-id`。

### ADR-MX-14: replace 扩展

- **Status:** Accepted
- **Context:** 条目 14；git `builtin/replace.c:150`、`:565-571`；`t6050`。
- **Decision:**
  1. **输出：** `-l --format=short|medium|long` 与 Git 一致；`-d` 每删除一项输出 `Deleted replace ref '<oid>'`。
  2. **`--graft <commit> [<parent>...]`：** 基于原提交生成替换提交，父提交可为 tag（剥离到提交），签名头按 Git 规则移除。
  3. **`--edit <object>`：** 以 `cat-file -p` 形式写入临时文件，经编辑器修改后按类型重新写入；内容不变时报错。
  4. **`--convert-graft-file`：** 仅允许 `.libra/info/grafts` 或（双布局下的）`.git/info/grafts` 二者之一存在；若两者同时存在则 fail-closed 拒绝并返回非零错误（两个文件均保留不删）。对唯一存在的 grafts 文件先完成全量语法/OID 解析校验再提交替换引用，全部成功后仅删除该源文件；任一行失败则不删除任何 grafts 文件。
- **Alternatives considered:** 不支持 grafts 文件——`t6050:518` 与迁移场景需要，拒绝。
- **Consequences:** 替换引用仍存于 `.libra/refs/replace/`。
- **Revisit when:** 无。

### 故障恢复矩阵

| 故障点 | 可接受残留 | 恢复动作 | 禁止结果 |
|---|---|---|---|
| bisect 某一步 restore 失败 | 会话停在失败前状态 | 报错并提示 `bisect reset` 或处理冲突后重试 | 状态前进而工作树未更新；`reset` 失败导致会话无法结束 |
| `repack -a -d` 在写新 pack 时中断 | 旧 pack 与松散对象完好，可能残留临时文件 | 下次 `repack`/`gc` 清理临时文件 | 删除旧 pack 而新 pack 不完整 |
| `gc` 在删除阶段中断 | 部分不可达松散对象已删除 | 重跑 `gc` | 删除可达对象或被借用对象 |
| `worktree remove -f` 删除目录中途失败 | 注册表保留 `tombstone` | `worktree repair --confirm` 重试 | 注册表已清除而目录部分残留且无记录 |
| `replace --convert-graft-file` 某行失败 | 已生成的替换引用保留，grafts 文件保留 | 修正该行后重跑 | 删除 grafts 文件而引用不完整 |
| 发布步 `gh release create` 失败 | 已推送的 `main` 提交 | 按 ER-09 记录，下一窗口补 tag/release | blind retry；只推 `main` 就宣称已发布 |
| D 组 `release.yml` 失败 | 已存在的 tag | 前滚修复，发新 patch | 回退已推送提交或删除已发布 artifact |

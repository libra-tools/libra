## 已决议设计决策

1. **状态与布局：** 沿用 Libra sequencer，不伪造 `.git/rebase-apply`；detached 显式身份与 expected_head 保护，旧 branch payload 向后兼容。
2. **retry 安全（ADR-AM-RETRY）：** `--retry` 是与 patches/--continue/--skip/--abort 互斥的当前邮件 resume；state 必须存在、branch 身份一致、HEAD 等于 expected_head、未处于 paused_in_conflict，且 R1 无 unmerged index、R2 无任何 staged 变更、R3 无 tracked 工作树 modified/deleted/renamed、R4 当前邮件目标路径无未跟踪文件。任一拒绝或检查错误发生在任何写入前；不改工作树、index、HEAD、refs 或 state，不运行可能写入的 hook；绝不 reset --hard 或 cleanup_untracked_patch_targets。AM-02 原子实现入口、所有安全门和一次性 --3way 覆盖；利用现有 `recovery_state_is_pristine` 单一检查边界并保持其原有调用语义。任一安全保护不可单独撤除而保留入口；未发布一次完整 revert，发布后新 patch 前滚。旧 REL-AM-RETRY 不再有效，不存在其 child 或 G-08 发布例外。
3. **单一共享管线：** traditional header 识别/安全引用处理 → SVN 已验证删除元数据投影（不把异常行伪造为标准 hunk）→ recount 实际 hunk 行数 → whitespace fix → target 解析/strip/directory/安全校验 → prepare/check/write；只在相关选项启用时执行。AM-10 等待 #546 AP-03/04/06；各写者严格串行。
4. **quoted CR：** transfer 解码后仅 strip 行尾 CRLF 的 CR，不能删行内独立 CR；现有原始 CR/LF 规范化和 MIME/非 UTF-8/NUL/cap 防线不放宽。具体 outside-repo 配置由独立隔离 DB 验证。

- **分别精确提交与验签：** 只 stage 本卡网站文件；Git 用 `git -C <后端根> add <确切文件>`、`git -C <后端根> diff --cached --name-only`、`git -C <后端根> commit -S -s -m '<scope>: <summary>'`，然后对同一 `git -C <后端根> rev-parse HEAD` 用 `git -C <后端根> verify-commit HEAD` 和 `git -C <后端根> log -1 --format=%B | rg '^Signed-off-by: '` 验证。Libra 在后端根用 `libra add <确切文件>`、检查 staged diff、`libra commit -S -s -m '<scope>: <summary>'`，固定 `libra rev-parse HEAD`，再对该 SHA 用 `libra log -1 --pretty=raw <SHA> | rg '^gpgsig '` 与 `libra log -1 --only-trailers --trailer Signed-off-by <SHA> | rg '^    Signed-off-by: '` 检查；签名未验证或 DCO 不符即停。
- **分别推送及核远端：** 推前再用对应 VCS 的 `ls-remote --exit-code origin refs/heads/cf`，必须等于上述基线，且 `git -C <后端根> merge-base --is-ancestor <基线SHA> HEAD` 或 `(cd <后端根> && libra merge-base --is-ancestor <基线SHA> HEAD)` 成功。Git 用 `git -C <后端根> push origin HEAD:refs/heads/cf`，Libra 用 `(cd <后端根> && libra push origin cf)`；禁止强推。推后用同一种 VCS 的 `ls-remote` 重新读取，必须等于本次提交 SHA，记录推前/推后 SHA、VCS、部署与线上结果。任何失败 STOP；不把本地成功当成线上交付。

### 成功定义

- `clone -b <tag>` 与 Git 一致地以分离 HEAD 检出 tag 指向的提交；`--single-branch -b <tag>` 写入 `+refs/tags/<tag>:refs/tags/<tag>`，之后的 `libra fetch` 能更新该 tag。
- `--single-branch` 经传输层（`file://`、`--no-local`、网络）克隆时只保留指向已取回历史的 tag。
- `--bundle-uri` 接受本地路径与 `file://` 的 bundle 或 bundle list，失败按 Git 以警告继续；与 `--depth`/`--shallow-*` 互斥；bundle tip 作为 have，全部 want 已在 bundle 闭包中时不再请求对象。
- `--recurse-submodules`/`--recursive` 得到指向 D4 的显式拒绝。
- 每项行为都有 `command_test` 中的具名用例；EN、zh-CN、网站、开发文档与 `COMPATIBILITY.md` 两行与实现一致。
- 九张实现卡各自完成独立发布切片（ER-08），全部卡 `done`/`complete`，计划收口点 CLOSE-530 全绿；CLN-09 已把维护者公开发布的复跑结果逐行写入本计划。

### ADR-CLN-01：范围以 #530 自留项为准

- **Status:** Accepted
- **Context:** #530 正文按 0.23.49 列出 8 类失败。2026-11-01 起维护者把其中多类拆成专门 issue（#740、#741、#752、#756 等），并在 0.30.91 的 `notes.md` 中只把 TC-0641..0645、0678、0679、0690 归给 #530。
- **Decision:**
  - 本计划承接：`--branch` 指向 tag（场景 1）、单分支 tag 跟随（TC-0690 的产品部分）、`--bundle-uri`（场景 3）、子模块选项的显式分类（场景 2/6）。
  - 为避免 tag 单分支克隆写出 `libra fetch` 自己拒绝的配置，同轴吸收「fetch 接受 `refs/tags/*` 目标」（CLN-01）；其它非常规目标仍归 #722。
  - 场景 4/5/7/8 与单例拒绝只登记 DEP-CLN-01，不实现。
- **Alternatives considered:** 一份计划吞下全部 clone 缺口：与 9 个专门 issue 重复，范围失控。只做 `--bundle-uri`：tag 起点是评论里三个 TC 的直接阻塞。
- **Consequences:** #530 在本计划完成后仍可能保持 OPEN（DEP-CLN-10）。
- **Revisit when:** 开工时发现某专门 issue 已被其它计划认领并改写 `clone.rs`。

### ADR-CLN-02：`-b <name>` 先找分支再找 tag，tag 起点分离 HEAD

- **Status:** Accepted
- **Context:** Git 先查 `refs/heads/<name>`，再查 `refs/tags/<name>`（探针 #1、#4）；完整 ref 名不被接受（探针 #6）；tag 起点时 HEAD 分离于剥离后的提交，不建本地分支、不写 `branch.*`（探针 #1–#3、#9）。
- **Decision:**
  - 在 clone 内把 `--branch` 解析为「分支起点」或「tag 起点」：远端通告 `refs/heads/<name>` 时为分支；否则通告 `refs/tags/<name>` 时为 tag；都没有时沿用现有 `RemoteBranchNotFound`（文案、`LBR-REPO-003`、128、提示均不变，Git 的 `Remote branch <x> …` 写法差异写入文档）。
  - tag 起点：fetch 后把 HEAD 写为分离状态，值为 tag 剥离后的提交；`--bare`/`--no-checkout` 同样分离；非 bare 且未给 `--no-checkout` 时检出该提交的树；不建本地分支，不写 `branch.*`；`CloneOutput.branch` 为 `null`；不追加「empty repository」警告。
  - 非单分支的 tag 起点：分支与 tag 的取回范围与当前非单分支克隆相同。
  - 不打印 Git 的 detached-HEAD 提示段落，作为文档化差异。
  - `setup_repository` 的签名变化须同步 `src/utils/convert.rs:176` 的调用方（T-1）。
- **Alternatives considered:** 把 tag 起点建成同名本地分支：与 Git 不同，且污染分支命名空间。打印 Git 提示全文：多为操作建议，人读输出差异不影响脚本。
- **Consequences:** `--mirror -b <tag>` 不在本 ADR 内：mirror 路径不检出，行为维持现状（Git 2.54 在附注 tag 时自身报错）。「不建本地分支」只指不为 tag 造出分支：`--bare -b <tag>` 的分支映射沿用 Libra 现有 bare 克隆（源分支保存在 `refs/remotes/origin/*`，不像 Git 那样映射到 `refs/heads/*`，探针 #37），该既有差异不在本计划修正（DEFER-CLN-08）。
- **Revisit when:** 需要与 Git 逐字节一致的 detached 提示时。

### ADR-CLN-03：单分支克隆的 tag 选择

- **Status:** Accepted
- **Context:** Git 单分支经传输层克隆时只保留指向已取回历史的 tag（探针 #7、#11、#12、#33）；普通路径的本地克隆复制全部对象，故 tag 全取（探针 #10、#12）；非单分支取全部 tag（探针 #13）。
- **Decision:** clone 调用 fetch 时的 tag 模式：`--no-tags` → `NoTags`；否则单分支且未走本地克隆语义（`uses_local_clone_semantics` 为假）→ `AutoFollow`；其余 → `All`。tag 起点的单分支克隆另把起点 tag 自身写入 `refs/tags/<t>`，`--no-tags` 时也写；refspec 为 `+refs/tags/<t>:refs/tags/<t>`（CLN-04）。
- **Alternatives considered:** 一律 `AutoFollow`：普通路径与 Git 本地克隆不一致。
- **Consequences:** 单分支传输克隆少取对象。
- **Revisit when:** Libra 实现本地克隆硬链接时（#743）。

### ADR-CLN-04：`fetch` 的 tag 目标 refspec

- **Status:** Accepted
- **Context:** Git 接受 `refs/tags/*` 目标；无 `+` 时，改变已有 tag 被拒绝为「would clobber existing tag」并以 1 退出，其它 ref 照常更新（探针 #15、#16）。Libra 的 fetch 是原子的：任何非快进的拒绝使整次 fetch 失败（探针 #17）。
- **Decision:**
  - 源与目标都在 `refs/tags/` 下的 refspec 被接受，形态为精确（`refs/tags/<n>:refs/tags/<n>`）或单通配（`refs/tags/*:refs/tags/*`），可带 `+`。
  - 目标在 `refs/tags/` 下而源不在的 refspec，仍以现有 `InvalidRefspec` 拒绝，原因改为 `a refs/tags/* destination requires a refs/tags/* source`。
  - 写入规则：新建 tag 总是允许；已有 tag 改指向时，需要 `+` 或 `--force`，否则沿用 Libra 的原子拒绝 `RefUpdateRejected`，消息为 `would clobber existing tag '<目标>' (requires '+' in the refspec or --force)`，提示沿用现有文字。拒绝在 ref 事务内发生：本次 fetch 不写入任何 ref（包括同一次 fetch 中本可更新的其它分支与 tag）、不写 FETCH_HEAD、不写 reflog；但对象包已在 ref 事务之前安装（`fetch.rs:2620-2623`），保留为不可达对象，与现有非快进拒绝相同。这一点与 Git（逐 ref 拒绝、其它 ref 照常更新、退出 1）不同，作为与现有非快进规则一致的有意差异写入文档。
  - tag 目标的更新与 `tagOpt`/自动跟随相互独立：`--no-tags` 只关闭自动跟随，显式映射的 tag 照常更新（TC-0679）。
- **Alternatives considered:** 逐 ref 拒绝并以 1 退出：要改 fetch 的原子更新模型，超出范围。
- **Consequences:** #722 的后续计划须在 CLN-01 之后再改 `validate_fetch_destination`（DEP-CLN-04）。
- **Revisit when:** fetch 改为逐 ref 报告时。

### ADR-CLN-05：`--bundle-uri` 的范围

- **Status:** Accepted
- **Context:** Git 的 `--bundle-uri` 在克隆前从 URI 取 bundle 或 bundle list，解包对象并写 `refs/bundles/*`，任何失败都是警告（探针 #18–#30）。Libra 可以存完整名的 ref，但 `for-each-ref`/`branch` 的读取面会把它们显示成本地分支（探针 #35）。
- **Decision:**
  - 参数：`--bundle-uri=<uri>` 可重复，最后一个生效；`--no-bundle-uri` 取消；空值视为「已给出但不处理」。给出（含空值）且同时给出 `--depth`/`--shallow-since`/`--shallow-exclude` 时，在发现远端前按 GC-CLN-05 U 型拒绝：`options '--bundle-uri' and '--depth/--shallow-since/--shallow-exclude' cannot be used together`。
  - URI：本地路径（相对路径以调用者 cwd 解析）与 `file://<绝对路径>`（前缀后的部分原样作为路径）。其它 scheme 先加警告 `bundle URI scheme '<scheme>' is not supported; only local paths and file:// URIs are read`，再走下载失败路径（DEFER-CLN-03）。
  - 显示值：凡写入警告、人读输出或 `--json`/`--machine` 的 URI，一律先经 `redact_url_credentials`（`src/utils/redact.rs:26`）脱敏；下文的「显示值」即脱敏后的字符串。读取用原值，显示用显示值，两者分开保存。
  - 打开文件：`src/internal/bundle_uri.rs` 先以 `std::fs::metadata` 确认目标是普通文件；Unix 上再以 `O_NONBLOCK` 打开并对已打开的句柄做 `fstat`，仍须是普通文件（防止检查与打开之间被替换）；读取上限沿用 `MAX_BUNDLE_BYTES`（改为 `pub(crate)`）。任何一步不满足都按「下载失败」处理，不阻塞、不报错退出。
  - 判定：内容以 `# v2 git bundle` 或 `# v3 git bundle` 开头即为 bundle（v3 在 `parse_header` 中失败，按「应用失败」处理），否则按 bundle list 解析（CLN-06）；两者都不是时警告 `file at URI '<显示值>' is not a bundle or bundle list`。读取失败警告 `failed to download bundle from URI '<显示值>'`。最后若没有任何 bundle 被应用、且出现过上述失败或应用失败，再加 `failed to fetch objects from bundle URI '<显示值>'`。前置条件缺失的 bundle 静默跳过（探针 #25）。
  - 应用：在 init 之后、fetch 之前进行，经 CLN-10 抽取的 `pub(crate) async fn install_bundle_pack`（clone 在异步流程中 `await` 它；前置条件校验 → pack 校验 → 写临时 pack 与临时 idx → 用临时 idx 校验每个 head → 原子重命名 pack、idx；整个过程持有与 fetch 相同的 `pack-<校验和>.install.lock`；任何一步失败都删除本次写出或已发布的新文件，已有的其它 pack 不动）。安装失败按「应用失败」处理：警告后继续克隆。
  - **安装后的逐对象校验与不完整 bundle 的移除（与预置同卡交付，CLN-05）：** `install_bundle_pack` 只证明 head 对象存在（`bundle.rs:665-680`），前置条件校验只证明前置对象可读（`:779-797`）。本计划维持一条不变量：克隆中保留下来的每个对象，其全部直接引用（提交的树与父提交、树的子树与 blob、附注 tag 的目标）都在对象库中。新克隆在应用 bundle 之前对象库为空，因此只需在每安装一个 bundle 后，对**该 pack 索引列出的每一个对象**（不只是 head，含未被任何 head 引用的对象）做带类型的检查：对象必须能解析；提交的 `tree` 必须是树、每个 `parent` 必须是提交；树条目按模式检查（`040000` 为树，`100644`/`100755`/`120000` 为 blob，`160000` gitlink 不要求对象）；附注 tag 声明的 `type` 必须等于其目标对象的实际类型；被引用的对象都必须存在。全部满足即保留，任一不满足（含解析或读取失败）即在同一把 `pack-<校验和>.install.lock` 内删除本次为它安装的 pack 与 idx（若同名 pack 在安装前已存在则不删），加警告 `bundle from URI '<显示值>' is incomplete and was not applied`，不计入 `applied`。由不变量可推出保留对象的闭包都完整；被删除 pack 中的对象不再存在，之后引用它们的 bundle 会在自己的检查中失败，因此不需要也不保存跨 bundle 的「完整/不完整」缓存，不会出现过期的正/负结果。检查的对象数上限为该 pack 的对象数（debug 构建且 `LIBRA_TEST=1` 时可由 `LIBRA_TEST_BUNDLE_VERIFY_BUDGET=<n>` 改为 `n`，先例 `src/command/tag.rs:889-902`）；超过上限即按不完整处理。由此不会留下悬空对象（`fsck` 检查全部对象，`fsck.rs:1224`、`:2761`），也不需要改变 fetch 的 tag 选择规则。校验结果（已保留 bundle 的 head、已保留 pack 中全部对象的集合）以 `BundleVerification` 交给 CLN-07。
  - 记录：不写 `refs/bundles/*`（DEFER-CLN-01）；改为在 `CloneOutput` 新增可选字段 `bundle_uri`（未给或空值时省略），形如 `{"uri":"<显示值>","applied":[{"name":"refs/heads/topic","oid":"<oid>"}]}`，`applied` 为全部已应用 bundle 的 head（同名取最后应用者），按 `name` 排序。
  - Git 打印的 `error: bad config line …`（含克隆内临时文件路径）不复现；全部警告经现有 `warnings` 输出（人读模式在结束时写 stderr），时机与 Git 不同。
- **Alternatives considered:** 保留不完整 bundle 的对象、只在 fetch 收尾时不发布其 tag：对象库仍含悬空 tag 对象，且会误伤完整的 tag（R8）。等 DEFER-CLN-01 解除后一次交付：用户今天就因参数被拒而失败。现在就写完整名 ref：每个 bundle 克隆的 `branch` 输出多出伪分支（探针 #35）。复用 `read_bundle_bounded`：它不检查文件类型，FIFO 会阻塞。
- **Consequences:** TC-0641..0645 的 `refs/bundles` 断言保持 FAIL，直至 DEFER-CLN-01；`bundle unbundle` 的失败残留语义收紧（写入文档）。
- **Revisit when:** DEP-CLN-14 的读取面修正落地，或出现 HTTP bundle 的需求。

### ADR-CLN-06：bundle list 的读取规则

- **Status:** Accepted
- **Context:** Git 以 git-config 格式读取列表：`bundle.version` 必须为 1，`bundle.mode` 为 `all` 或 `any`，`bundle.<id>.uri` 相对 URI 以列表位置解析，`bundle.heuristic=creationToken` 时按 token 由新到旧下载、够用即停（Git `bundle-uri.c` 的 `fetch_bundles_by_token`），语法错误的列表视为「not a bundle or bundle list」（探针 #19、#26–#30）。单个 bundle 可达 1 GiB，列表可让总量远超单个上限。
- **Decision:**
  - 解析：`src/internal/bundle_uri.rs` 内的严格读取器，只接受 `[bundle]` 与 `[bundle "<id>"]` 两种节、`key = value` 行与 `#`/`;` 注释；任何无法解析的行使整个列表无效。不复用 `config.rs` 的 `read_git_config_file`（它跳过坏行，语义与 Git 不同）。与 Git 一样，`version` 缺省为 `1`、`mode` 缺省为 `all`；给出时 `version` 须为 `1`、`mode` 须为 `all`/`any`；每个条目须有 `uri`；否则列表无效（警告同 ADR-CLN-05）。
  - 去重与上限：条目按「解析后的绝对路径」去重，保留第一次出现者；列表文件 ≤ 1 MiB、去重后条目 ≤ 1024，超出即列表无效。
  - 读取：每个条目先只读**头部**（到第一个空行，≤ 1 MiB）；完整 bundle 只在决定安装时读取，同一时刻只持有一个 bundle 的字节，安装后立即释放。一次 `--bundle-uri` 处理中读取的字节总量（头部与完整读取合计）≤ 4 GiB；达到上限时停止处理剩余条目，并加警告 `bundle URI processing stopped: read budget exhausted`。
  - `all`：头部读取失败者警告 `failed to download bundle from URI '<条目显示值>'`。然后按轮进行：每一轮按列表顺序遍历尚未处理的条目，**以对象库的实况**检查其前置条件；满足者立即读取并安装（因此前一个 bundle 带来的内部提交也能满足后一个 bundle 的前置条件）；某一轮没有任何新安装时结束。安装失败者（含 thin bundle，DEFER-CLN-07）警告 `failed to unbundle bundle from URI '<条目显示值>'` 并不再重试；按 ADR-CLN-05 判为不完整而被移除的条目同样不再重试；结束时仍未满足前置条件者静默跳过。
  - `any`：按列表顺序尝试，第一个**成功安装并通过校验**者为止。与 Git 有两处差异：Git 的尝试顺序未定义，Libra 取列表顺序；Git 在第一个**下载成功**的条目处停止（即使它的前置条件不满足、随后无法解包），Libra 会跳过无法应用的条目继续尝试下一个。两处都写入文档。
  - `heuristic = creationToken`：按 Git `fetch_bundles_by_token` 的调度：按 `creationToken` 从大到小尝试；某个 bundle 前置条件不满足时，继续尝试更旧的一个；每成功安装一个 bundle，就回到比它新、尚未安装的 bundle 重试；最新的 bundle 已安装，或已尝试到最旧一个仍无法再前进时停止。不写 `fetch.bundleURI`/`fetch.bundleCreationToken`（DEFER-CLN-04）。
  - 条目内容又是列表时，视为「not a bundle or bundle list」（DEFER-CLN-05）。
- **Alternatives considered:** 先把全部 bundle 读入内存再排序：内存可达 1024 GiB。复用宽松读取器：会把 Git 拒绝的列表当作有效。
- **Consequences:** 与 Git 的差异（`any` 的顺序、不写 `fetch.bundle*`、不支持嵌套、上限）写入文档。
- **Revisit when:** DEFER-CLN-04/05 重启。

### ADR-CLN-07：bundle tip 参与协商

- **Status:** Accepted
- **Context:** Git 把 bundle ref 当作本地 ref，协商时作为 have 发送；全部 want 已在本地时不发 want（TC-0642/0645）。Libra fetch 的 have 取本地与远程跟踪分支 tip 及本地 tag tip（`fetch.rs:5281-5390`），want 不按本地是否已有过滤。`install_bundle_pack` 只证明 head 对象存在（`bundle.rs:665-680`），不证明其闭包完整（Codex R1-P1-1）；附注 tag 对象可能不在 bundle 中（R1-P1-3）。
- **Decision:**
  - **校验来源：** 连通性校验与不完整 bundle 的移除由 ADR-CLN-05 / CLN-05 在安装时完成；本 ADR 只消费其结果 `BundleVerification`，其中的 head 都已校验完整。
  - `fetch_repository_with_result` 新增参数 `bundle_verification: Option<&BundleVerification>`（fetch、pull 传 `None`）。`BundleVerification` 由 CLN-05 的校验产出，持有：已保留 bundle 的 head 列表、已保留 pack 中全部对象的集合（按不变量都完整）。fetch 只读它，不再自行遍历：
    - 已校验 head 的 oid 追加到 have 列表（去重）；
    - 提交类 want 若在该对象集合中，从 want 中去掉——这是集合查询，不重新遍历；
    - 附注 tag 不受影响：`AutoFollow`/`All` 选中的 tag，若其 tag 对象不在对象库中，tag 对象 oid 照常留在 want 中；
    - want 为空时不调用 `fetch_objects`，`objects_fetched` 为 0；ref 更新、tag 持久化与返回的 `fetch_head_records` 都走与有对象传输时相同的收尾路径（不复用 `fetch.rs:2529-2562` 那个返回空记录的早退分支）。clone 自身不写 FETCH_HEAD 文件（文件由 `libra fetch` 的命令封装层写，`fetch.rs:1267-1270`），因此本 ADR 约束的是返回的记录。
  - **测试观测点：** debug 构建且 `LIBRA_TEST=1` 时，`LIBRA_TEST_FETCH_NEGOTIATION_LOG=<路径>` 让 `fetch_repository_with_result` 把最终的协商列表追加到该文件：每个 have 一行 `have <oid>`、每个 want 一行 `want <oid>`，实际调用 `fetch_objects` 时再写一行 `fetch_objects`（先例 `src/command/tag.rs:889-902`）。
  - `GIT_TRACE_PACKET` 的输出不在本 ADR（DEFER-CLN-02）。
- **Alternatives considered:** 对所有 fetch 跳过本地已有对象：会改变 fetch 与 pull 的既有行为（issues/496 的路径）。只在协商时排除不完整 head、但保留其对象：会留下悬空对象，`fsck` 报错（R8）。
- **Consequences:** 改动共享函数签名，属 T-1。
- **Revisit when:** fetch 获得通用的「本地已完整」判定。

### ADR-CLN-08：期望值来源

- **Status:** Accepted
- **Context:** CI 有 `git`；现有 `clone_test` 已用真实 Git 构建夹具。
- **Decision:** 夹具用 GC-CLN-08 给出的 Git 命令构建；期望值写成测试内字面量或由夹具中 `git rev-parse` 取得的 oid，来源是本计划探针表；被测命令只运行 Libra。
- **Alternatives considered:** 运行时用 Git 跑同样的 clone 作为期望：随 Git 版本漂移。
- **Consequences:** Git 行为变化时人工更新。
- **Revisit when:** Git 改变上述任一行为。

### ADR-CLN-09：拒绝的构造

- **Status:** Accepted
- **Context:** Git 对选项冲突用 `die()`（`fatal:`、128）。Libra 的 `command_usage` 输出 `error:`；`fatal` 加 `LBR-CLI-002` 输出 `fatal:` 并以 129 退出（`src/utils/error.rs:826-835`）。
- **Decision:** `--bundle-uri` 冲突用 U 型（`CliError::fatal(msg).with_stable_code(CliInvalidArguments)`）；子模块选项用 X 型（`CliError::failure(msg).with_stable_code(Unsupported).with_hint(hint)`）；tag clobber 用现有 C 型；tag 源规则用现有 E 型（`command_usage` 加提示）。Git 的 128 与 Libra 的 129 之差写入文档错误表。
- **Alternatives considered:** 为 clone 另设 128 例外：扩大错误码合同的例外面。
- **Consequences:** 上游 `test_must_fail` 成立；比较完整 stderr 的用例仍受 `Error-Code:` 行影响（全局合同）。
- **Revisit when:** 全局错误输出合同变化。

## 全局工程约束

本计划完整继承模板 GC-01..GC-13，另加以下约束：

- **GC-CLN-01 单一事实源：** tag 目标 refspec 的判定只在 `fetch.rs` 的 refspec 校验与解析处；bundle 的头部解析、pack 校验与安装只经 `bundle.rs` 的 `parse_header`/`verify_prerequisites`/`validate_bundle_pack` 与 CLN-10 抽取的 `install_bundle_pack`；pack 安装锁只经 CLN-10 的 `src/utils/pack_install_lock.rs`；bundle URI 的文件读取只经 `bundle_uri.rs` 的普通文件读取函数（ADR-CLN-05），读取上限共用 `MAX_BUNDLE_BYTES`；tag 自动跟随只用 fetch 的 `TagFetchMode::AutoFollow`；URI 脱敏只用 `redact_url_credentials`。不复制函数体。
- **GC-CLN-02 零写入：** 本计划新增的 clone 拒绝都在发现远端与创建目标目录之前完成。fetch 的拒绝在 ref 事务内完成：不写任何 ref、FETCH_HEAD 与 reflog；拒绝前已安装的对象包按 ADR-CLN-04 保留。
- **GC-CLN-03 零命中守卫：** Verification 中凡标「零命中」的命令，都在 `bash -euo pipefail` 中先定义下列函数再调用（模板三分支写法，2026-11-04 在 `bash -e` 与 `zsh -e` 下验证）：

  ```bash
  zero_hits() {
    pattern="$1"; shift
    if rg -n -- "$pattern" "$@"; then
      echo "FAIL: forbidden pattern found"; return 1
    else
      rc=$?
      if [ "$rc" -ne 1 ]; then echo "ERROR: rg failed with exit $rc"; return "$rc"; fi
      echo "OK: zero hits"
    fi
  }
  ```

- **GC-CLN-04 测试隔离：**
  - 新用例全部用 `tempdir()` 与显式 cwd；环境变量只给子进程设置，不改测试进程环境，不需要 `#[serial(env)]`。
  - 子进程把 `HOME`、`XDG_CONFIG_HOME`、`LIBRA_CONFIG_GLOBAL_DB`、`LIBRA_CONFIG_SYSTEM_DB` 指向用例临时目录；Git 夹具命令另设 GC-CLN-08 的固定身份、日期与 `GIT_CONFIG_NOSYSTEM=1`（GC-13 的测试隔离）。
- **GC-CLN-05 门族：** 本计划含门族的卡，每个门是一个独立命名的 Rust 测试函数，只断言一个谓词，计入所在卡的 G-03 分子（由 EX-CLN-01 承载超限）。完整测试名为 `command::<模块>::<门名>`（`tests/command_test.rs:8` 以 `command` 模块挂载 `tests/command/mod.rs`；`<模块>` 为 `clone_test`、`fetch_test` 或 `bundle_test`）；库内单元测试的完整名为 `command::fetch::tests::<名>`、`command::bundle::tests::<名>`、`internal::bundle_uri::tests::<名>`。
  - **单门命令：** `source .env.test && cargo nextest run --test command_test --no-tests=fail -E 'test(=command::<模块>::<门名>)'`；库内单元测试为 `source .env.test && cargo nextest run --lib --no-tests=fail -E 'test(=<完整名>)'`。`=` 是完整名精确匹配，零匹配即失败。
  - **整卡命令：** `source .env.test && cargo nextest run --test command_test --no-tests=fail -E 'test(/^command::<模块>::<卡前缀>/)'`（前缀正则）。
  - **拒绝门：** 由 CLN-01 在 `tests/command/mod.rs` 新增的宏 `refusal_gates!` 生成。宏输入：夹具构造函数、argv（原样执行，不为夹具追加参数）、cwd、类型、消息、提示、目标路径的初始状态。初始状态取值：`absent`（clone 的目标目录执行前不存在，执行后仍不存在）；`sentinel`（目标目录执行前已存在，只含内容为 `sentinel` 的文件 `keep`；执行后目录、`keep` 及其内容不变，且没有新增条目）；`refs`（fetch：比较 ref 快照）。2026-11-04 探针确认 Libra 错误输出的通道：stdout 为空；人读 stderr 依次为 `fatal:`/`error:` 行、`Error-Code:` 行、可选空行与 `Hint:` 行、一行紧凑 JSON；`--json` 在 stderr 输出美化 JSON；`--machine` 输出单行 JSON；fetch 在 `--json`/`--machine` 下先输出 NDJSON 进度事件（探针 #14、#17）。

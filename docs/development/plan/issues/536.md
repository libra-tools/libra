## 文档职责

本文处理 Issue #536 在当前 `main` 上仍成立的 `libra reset` 与 Git 契约差异。目标：#536 正文与评论中列出、且仍能复现的每一项，要么对齐 Git，要么显式归类并写进文档；不属于 `reset` 的根因登记为依赖；并给出 #536 引用的上游用例如何复核。

### 适用范围

- `libra reset` 的以下表面：
  - 目标为 `main` 等普通分支（含 `~`/`^`/`@{…}` 后缀与 pathspec 形式）时的锁定分支拒绝；
  - 裸仓库中需要工作树的模式（`--hard`/`--merge`/`--keep`）与 `--mixed`（含 pathspec）的拒绝；
  - 合并进行中或索引含未合并条目时 `--soft`/`--keep` 的拒绝；
  - `--merge` 对未合并路径的处理；
  - pathspec 形式接受 tree-ish 目标；
  - `--refresh`（与既有 `--no-refresh` 最后者生效）；
  - `--end-of-options`；
  - `--pathspec-from-file` 行模式的 C 风格引号解码，以及 pathspec 相关用法冲突的 Git 诊断。
- 对应文档：`docs/commands/reset.md`、`docs/commands/zh-CN/reset.md`、由同步脚本生成的网站页 `../libra-backend/apps/tanstack-app/content/docs/commands/reset.en.md`、开发文档 `docs/development/commands/reset.md`，以及 `COMPATIBILITY.md` 第 216 行 `reset` 行（原地改写，不增删行）。
- 测试：`tests/command/reset_test.rs`（`command_test` 目标）、`src/command/reset.rs` 与 `src/internal/branch.rs`、`src/cli.rs` 内的单元测试；既有守卫 `compat_noninteractive_history_controls`、`compat_help_flag_descriptions`。

### 非目标

- 不改 `restore --source main` 的同类拒绝（`src/command/restore.rs:484-488`，DEFER-RS-01）。
- 不实现 reset 后的索引 stat 刷新：由 [#660](https://github.com/libra-tools/libra/issues/660) 承接（DEP-RS-04）。本计划只让 `--refresh` 被接受，并与 `--no-refresh` 按最后者生效（ADR-RS-07）。
- 不改未出生 HEAD 上的 reset（[#670](https://github.com/libra-tools/libra/issues/670)）、`reset --hard` 留下未合并文件（[#1012](https://github.com/libra-tools/libra/issues/1012)）、操作快照（[#1039](https://github.com/libra-tools/libra/issues/1039)）、`checkout -B`（[#723](https://github.com/libra-tools/libra/issues/723)）；它们与本计划改同一文件，只登记顺序约束（DEP-RS-07）。

- 不实现全局 `--end-of-options`（DEFER-RS-03），不合并各命令重复的 `core.bare` 读取函数（DEFER-RS-02）。
- 不改 Libra 无效目标的退出码约定（`LBR-CLI-003` 退出 129，Git 为 128；DEFER-RS-06）；未匹配的 pathspec 继续报错（ADR-RS-12，Git 退出 0）。

- 计划完成不以关闭 #536 为条件；关闭条件见 DEP-RS-06。

### 成功定义

- #536 中仍能复现的各项全部按 Git 处理：
  - `reset <main 或其它普通分支>` 不再被拒绝，只有 Libra 托管的 AI 分支（`intent`、`traces`、`agent-traces`）仍被拒绝；
  - 裸仓库中 `--hard`/`--merge`/`--keep` 与 `--mixed`（含 pathspec）被拒绝，GC-RS-02 的八个状态域不变（中央操作边界的既有快照写入除外），`--soft` 可用；
  - 合并进行中或索引含未合并条目时，`--soft`/`--keep` 以 Git 的原文拒绝；
  - `--merge` 把未合并路径重置为目标；
  - pathspec 形式接受 tree-ish 目标；
  - `--refresh` 被接受；`--end-of-options` 后的参数一律按非选项处理；
  - `--pathspec-from-file` 行模式解码引号；pathspec 相关用法冲突用 Git 原文与退出 128；未匹配 pathspec 的报错写明为有意差异。
- 每项行为有 `command_test` 或单元测试中的具名门；期望值取自本计划「行为探针」表。
- EN、zh-CN、网站页、开发文档与 `COMPATIBILITY.md` 第 216 行与实现一致，`--help` 同步。
- 十张实现卡各自完成独立发布切片（ER-08），全部卡 `done` / `complete`，计划收口点 CLOSE-536 全绿。
- RS-08 已把 libra-testcases 维护者公开发布的复跑结果逐行写入本计划。

### ADR-RS-02：只拒绝 AI 托管分支作为 reset 目标

- **Status:** Accepted
- **Context:** `is_locked_branch` 包含 `main`，是为了阻止删除或重命名默认分支；`is_ai_managed_branch` 的注释明确说 `main` 仍是普通用户工作树分支（`branch.rs:66-72`）。reset 用前者，把 `main` 当成了 AI 托管分支。用户无法创建 `intent`/`traces` 同名分支（探针 #4）。
- **Decision:**
  - 在 `src/internal/branch.rs` 新增 `pub fn is_ai_managed_revision(rev: &str) -> bool`：与 `is_locked_revision` 同样去掉第一个 `~`/`^`/`@` 之后的部分，再调用 `is_ai_managed_branch`。
  - `run_reset` 的目标检查改用它；拒绝的消息、稳定码、提示与检查位置都不变（AI 托管分支仍在模式选择与 pathspec 分支之前被拒绝）。
  - `restore` 继续用 `is_locked_revision`（DEFER-RS-01）。
- **Alternatives considered:** 直接改 `is_locked_revision` 的语义：会同时改变 `restore` 的行为，超出 #536。删除目标检查：会允许把工作树重置到 AI 托管的提交，违反该检查的安全目标。
- **Consequences:** `main`、`main~1`、`main@{0}` 等形式与其它分支一样可用；`refs/heads/main` 的行为不变。
- **Revisit when:** `restore` 的同类问题另立计划时，两处统一改用 `is_ai_managed_revision`。

### ADR-RS-03：裸仓库中需要工作树的模式与 `--mixed` 被拒绝

- **Status:** Accepted
- **Context:** Git 对 `--hard`/`--merge`/`--keep` 调 `setup_work_tree`，在裸仓库报 `this operation must be run in a work tree`；`--mixed`（含 pathspec 与 `--pathspec-from-file`，因无模式时按 `--mixed` 处理）报 `mixed reset is not allowed in a bare repository`；`--soft` 允许（探针 #17–#19）。Libra 的裸仓库由 `core.bare` 标记，`status` 已有同样的拒绝写法；Libra 裸仓库不能有关联工作树（探针 #22）。
- **Decision:**
  - 在 `reset.rs` 内新增私有函数读取 `core.bare`，写法与 `status.rs:904-919` 相同：未设置为否；Git 布尔拼写之外的值以 `invalid core.bare value '<v>': expected true/false/yes/no/on/off/1/0` 加 `LBR-CLI-002` 拒绝（`fatal`，退出 129；Git 为 `bad boolean config value`，退出 128，属有意差异，与 `status` 一致）；读取失败以 `cannot read core.bare to classify this repository: <detail>` 加 `LBR-IO-001`（128）拒绝。
  - 读取失败路径用 debug 构建故障注入点验证：`LIBRA_TEST=1` 且 `LIBRA_TEST_RESET_FAIL_CORE_BARE_READ=1` 时，该函数不读配置，直接以 detail `test-injected core.bare read failure` 返回读取失败；release 构建无此路径（`tag.rs:889-902` 的写法）。
  - 判定顺序与 Git 相同：目标解析错误、pathspec 与模式冲突先报；之后、任何索引/工作树/引用读写之前做裸仓库检查。整树分支放在 `resolve_commit`（`reset.rs:969`）之后、停止状态快照之前；pathspec 分支放在目标解析（`:942`）之后、`reset_pathspecs` 之前。
  - `--hard`/`--merge`/`--keep`：`CliError::fatal("this operation must be run in a work tree")`，`LBR-REPO-003`，退出 128，无提示。`--mixed`、无模式（含 pathspec）：`CliError::fatal("mixed reset is not allowed in a bare repository")`，同码同退出。`--soft` 不变。
  - `reset -p` 不在本轴（探针 #31）。
- **Alternatives considered:** 把 `status` 的私有函数改为 `pub(crate)` 供 reset 复用：把 `status.rs`（与 plan-20260927 CM-06/07 等计划共享）拉进写集，且 `rev-parse`、`bisect` 两份副本仍在，单一来源仍未达成；合并四份副本另立延后项（DEFER-RS-02）。只看「工作目录等于存储目录」：Libra 的裸仓库判定以配置为准（`worktree.rs:612-621`）。
- **Consequences:** reset 新增两种拒绝与两种配置错误；`core.bare` 有四份读取副本，由 DEFER-RS-02 跟踪。
- **Revisit when:** DEFER-RS-02 立项。

### ADR-RS-04：合并进行中或索引含未合并条目时拒绝 `--soft`/`--keep`

- **Status:** Accepted
- **Context:** Git 的 `die_if_unmerged_cache` 在 `MERGE_HEAD` 存在或索引含未合并条目时，对 `--soft`/`--keep` 报 `Cannot do a %s reset in the middle of a merge.`（探针 #23–#24）。Libra 的文档把「允许在未合并索引上 soft reset」写成有意差异（`docs/commands/reset.md:40`），`issues/477.md` 把对齐 Git 列为 DEFER-05。
- **Decision:**
  - 条件：`command::merge::merge_in_progress()` 为真，或 `Index::load(path::index())` 的结果中 `unmerged_paths` 非空。与 Git 相同，只看这两项：没有停止序列状态的未合并索引（例如 `cherry-pick --quit` 之后）同样拒绝。索引文件不存在按空索引处理（`Index::load` 的既有行为，裸仓库与新仓库不受影响）。
  - 只用于整树的 `--soft`/`--keep`（带路径的这两种模式已在更早处被拒绝）；位置在目标解析与裸仓库检查之后、停止状态快照之前。
  - 构造 `CliError::fatal("Cannot do a soft reset in the middle of a merge.")`（`--keep` 为 `keep`），`LBR-REPO-003`，退出 128，无提示。
  - 读索引失败沿用既有 `ResetError::IndexLoad`（`LBR-REPO-002`，退出 128；Git 此时 `index file corrupt`，退出 128）。`merge_in_progress` 失败映射为既有 `ResetError::WorktreeRead`（`failed to read working tree: <detail>`，`LBR-IO-001`，128）；该路径用 debug 构建故障注入点验证：`LIBRA_TEST=1` 且 `LIBRA_TEST_RESET_FAIL_MERGE_STATE_PROBE=1` 时不调用 `merge_in_progress`，直接以 detail `test-injected merge-state probe failure` 失败。
  - revert 当前把文本冲突存为 stage 0（`docs/commands/reset.md:50`），不构成未合并条目；这种状态下 `--soft` 仍可执行，其告警路径不变。
- **Alternatives considered:** 只看合并状态、不看未合并索引：cherry-pick/rebase 冲突下 `--soft`/`--keep` 仍会通过，与 Git 不同。只改 `--soft`：`--keep` 目前会静默丢掉冲突阶段（探针 #23），t7110#17/#19/#21 要求拒绝。
- **Consequences:**
  - HF-01 状态矩阵 `test_reset_clears_single_pick_and_revert_state_matrix` 删去依赖「`--soft` 在冲突阶段下成功」的迭代与段落，由 RS-03 的拒绝门族承接同一批状态（单提交与多提交 pick、单提交与多提交 revert 手工未合并索引、无停止状态的未合并索引、读不出索引），并加多提交场景下 `--abort` 仍可用的门；结构化输出告警的覆盖由矩阵中既有、未改动的 revert 暂存标记场景承担。
  - 推翻文档中的有意差异；`issues/477.md` 的 DEFER-05 由本卡交付。
- **Revisit when:** revert 改为写真正的未合并条目时，复核暂存标记场景。

### ADR-RS-05：`--merge` 把未合并路径重置为目标

- **Status:** Accepted
- **Context:** Git 的 `--merge` 先 `repo_read_index_unmerged`，再对目标做 `oneway_merge`；对带 `CE_CONFLICTED` 的条目，`merged_entry`/`deleted_entry` 不做「工作树须与索引一致」检查，直接以目标内容覆盖工作树，目标没有该路径时删除（`unpack-trees.c:2600`、`:2691`）。这正是 Git 中止合并的惯用法（探针 #26–#29）。Libra 跳过这些路径并把冲突阶段搬进新索引（`reset.rs:1617-1620`、`:1687-1689`）。
- **Decision:**
  - `build_guarded_reset_plan` 在 `--merge` 下：遍历集合显式并入 `unmerged_paths`（现有遍历只取 stage-0、HEAD 与目标三者的路径，`reset.rs:1609-1612`；`F-DU` 这类只存在于冲突阶段的路径否则会漏掉）；未合并路径一律加入工作树更新（目标有则写目标内容与模式，无则删除），不做工作树与索引一致性检查；目标索引不再搬入 stage 1–3（删除 `carry_unmerged_entries` 的调用与函数）。
  - 写入路径不跟随符号链接：`write_guarded_worktree_value` 清理现有条目时改用 `symlink_metadata`（现为跟随链接的 `is_dir()` 加 `remove_dir`，`reset.rs:1798-1805`），真实目录才 `remove_dir`，符号链接（含指向目录的）以 `remove_file` 删除链接本身，链接目标不受影响。
  - 非冲突路径的 `--merge` 规则不变（含未跟踪路径冲突检查与文件/目录转换检查）。
  - 未合并路径没有 stage-0 值，现有快照（`reset.rs:1711-1757`）无法覆盖它。新的捕获按实际条目类型、不跟随符号链接（`symlink_metadata`）进行：普通文件以其字节写一个 blob 对象，模式取实际可执行位（`100755`/`100644`）；符号链接以链接目标字节写 blob，模式 `120000`；不存在记为 `Missing`；目录记为 `Directory`。前两种以 `WorktreeSnapshotKind::Tracked(ResetIndexValue { hash, mode })` 表示，复用既有恢复（`reset.rs:1894-1972`：先清掉现有条目，再按模式写回）。这些 blob 未被引用，可由 gc 回收。
  - 内存特征与既有被跟踪路径的快照相同：捕获时读入单个文件写成对象，恢复时整块读回（`reset.rs:1964-1969`）；本卡不宣称流式处理，也不新增其它缓冲。
  - 新增 debug 构建故障注入点：`LIBRA_TEST=1` 且 `LIBRA_TEST_RESET_FAIL_AFTER_GUARDED_WORKTREE=1` 时，在 `apply_guarded_worktree_updates` 成功返回之后、写入闭包结束之前（`reset.rs:1996-2001`）返回 `ResetError::WorktreeRestore("test-injected failure after <n> guarded worktree update(s)")`，使 `:2002-2009` 的既有回滚执行；消息中的 `<n>` 证明注入点已到达；release 构建无此路径（`tag.rs:889-902` 的写法）。
  - 因结果索引不再有冲突阶段，HF-01/HF-26 的既有收尾随之生效（结束停止的 pick/revert、清除合并状态），与 Git `remove_branch_state` 一致。
- **Alternatives considered:** 保留「携带冲突阶段」并文档化为有意差异：#536 正文点名的场景与 t7110 的四个用例持续失败，且用户无法用 `--merge` 中止合并。只快照字节、按普通文件恢复：会丢失可执行位或把符号链接恢复成普通文件。
- **Consequences:**
  - 对外行为变化：`--merge` 后冲突标记被目标内容替换；依赖旧行为的调用者需先自行保存冲突文件。
  - HF-01 状态矩阵删去 `--merge` 迭代，其单提交与多提交 pick/revert 的结束结果由 RS-04 的具名门承接。
  - `reset.rs:1018-1041` 中「索引仍有冲突阶段」的告警分支在 `--soft`/`--keep` 被拒、`--merge` 清除冲突之后不再可达；保留为防御分支，不删除。
- **Revisit when:** 无。

### ADR-RS-06：pathspec 形式接受 tree-ish 目标，JSON 增加 `target_kind`

- **Status:** Accepted
- **Context:** Git 在有 pathspec 时把目标按 tree-ish 解析（`builtin/reset.c:418-425`），无 pathspec 时按 commit-ish（探针 #14–#16）；消歧时（`builtin/reset.c:266-289`），单个参数按 commit-ish、其后还有参数时按 tree-ish 判断「像修订」，像修订又同时是文件名即报歧义。Libra 的 `target_resolves_as_revision`（`reset.rs:1099-1105`）只按 commit-ish 判断，所以 `reset <tree-ish> <path>` 中若 `<tree-ish>` 恰好也是工作树文件名，会被静默当作路径。
- **Decision:**
  - 消歧：`normalize_reset_request` 在未写 `--`、且目标之后还有 pathspec 时，以 tree-ish 解析判断「像修订」；只有一个参数时仍按 commit-ish。像修订且同时是工作树路径时，沿用既有 `AmbiguousRevisionPath`（`error: ambiguous argument '<arg>': both revision and filename`，`LBR-CLI-002`，129；Git 128）。
  - 执行：pathspec 分支（含 `--pathspec-from-file`）先按 commit-ish 解析（`-- .` 等目录形式的展开由 RS-11/ADR-RS-13 提供，本卡依赖它）；失败原因为「目标是 tree」时，改用 `util::resolve_tree_ish_typed` 并以 `index_for_tree` 构造目标索引。其余失败（含 blob、未知名字）沿用既有错误。
  - 整树形式仍只接受 commit-ish，tree 目标沿用既有 `LBR-CLI-003`/129（Git 为 128，与 `reset -p` 的既有差异一致）。
  - 成功 JSON 新增 `target_kind` 字段，取值 `"commit"` 或 `"tree"`，所有 reset 输出都有；目标为 tree 时 `commit` 与 `short_commit` 为 tree OID 及其缩写，`subject` 为空串，`previous_commit` 仍为 `null`。
- **Alternatives considered:** 不加字段、只让 `commit` 承载 tree OID：机器消费者无法区分。把 `commit` 改为可空：属破坏性 schema 变化。消歧保持 commit-ish：tree-ish 与文件名重名时静默误判。
- **Consequences:** JSON schema 只增字段；三份文档的 JSON 示例与字段说明同步。
- **Revisit when:** 无。

### ADR-RS-07：`--refresh` 与 `--no-refresh` 最后者生效

- **Status:** Accepted
- **Context:** Git 的 `--no-refresh` 是 `OPT_BOOL`，其否定形式 `--refresh` 自然可用（探针 #8）。Libra 的 reset 不刷新索引 stat（探针 #10），这是 #660 的范围。
- **Decision:** 新增 `--refresh`，与 `--no-refresh` 以 `overrides_with` 互相覆盖（`--auto-advance` 的写法）；`ResetArgs` 提供解析后的 `refresh()`（默认 `true`），供 #660 接入。新字段使 `am.rs:1284`、`cherry_pick.rs:994` 两处 `ResetArgs` 结构字面量必须补字段（取 `refresh: false`，与其 `--hard` 回滚语义无关），二者进入写集。两旗标在本计划中都不改变索引写入；文档写明「stat 刷新尚未实现，见 #660」。`--refresh=<值>` 与改动前一样是 clap 用法错误类（探针 #9：改动前为未知参数，`LBR-CLI-002`，129），不是本卡新增的失败路径。
- **Alternatives considered:** 在本卡实现 stat 刷新：与 #660（含 `add -u`、`reset --hard`）同轴，且工作区已有其它 Agent 在改共享刷新函数（`src/command/refresh.rs`）。不接受 `--refresh`：TC-2535 的首步持续失败。为 `ResetArgs` 实现 `Default` 以避免改两处字面量：同样要改这两个文件。
- **Consequences:** TC-2535 在 #660 交付前仍为 FAIL（其后半要求默认刷新且 `--no-refresh` 不刷新）。
- **Revisit when:** #660 开工时，它须使用 `refresh()` 的结果。

### ADR-RS-08：`--end-of-options` 在 reset 的 argv 预处理与错误输出解析中实现

- **Status:** Accepted
- **Context:** Git 的 `--end-of-options` 结束选项解析，其后的参数即使以 `-` 开头也按非选项处理；之后的 `--` 仍分隔路径（探针 #11–#13）。Libra 的 reset 已在 clap 之前做 argv 预处理（`cli.rs:1151-1197`）。另外，命令失败时 `main.rs:700-704` 用 `OutputConfig::resolve_from_argv`（`output.rs:250`）重新扫描原始 argv 决定错误输出模式，该扫描不在任何分隔符处停止。
- **Decision:**
  - 在 `rewrite_reset_pathspec_separator_args` 中处理 reset 子命令后、用户 `--` 之前的第一个 `--end-of-options`：删除它；其后直到用户 `--`（或末尾）的参数（「字面区」）放到 clap 的 `--` 之后，使 clap 按位置参数接收；用户的 `--` 仍改写为隐藏旗标。
  - 「用户 `--` 前是否已有目标」的判定：既有 `reset_has_positional_target_before_separator`（`cli.rs:1278-1300`）跳过一切以 `-` 开头的标记，不能用于字面区；改为「`--end-of-options` 之前的位置参数，加上字面区内的全部标记（不论是否以 `-` 开头）」中至少有一个即为有目标，否则才补 `HEAD`。与 Git 的 `<rev> -- <paths>` 形式相同（`builtin/reset.c:266-279`：`argv[1]` 为 `--` 时取 `argv[0]` 为修订，即第一个操作数是修订）：`reset --end-of-options --foo -- file1` 改写为 `reset --__libra-reset-pathspec-separator -- --foo file1`，目标为 `--foo`、路径为 `file1`。
  - 用户 `--` 之后的 `--end-of-options` 是普通路径。
  - `OutputConfig::resolve_from_argv` 遇到 `--end-of-options` 即停止扫描（之后的 `--json`、`--machine` 等是字面参数），使错误输出模式与成功路径一致。对不支持该分隔符的命令，这只影响其后的标记，而这些命令本就以「未知参数」失败。
  - `--end-of-options --hard`：`--hard` 成为目标，解析失败沿用既有 `invalid reference: --hard`（`LBR-CLI-003`，129；Git 为 128 加 `option '--hard' must come before non-option arguments`，属 DEFER-RS-06 的既有差异）。
  - 只对 `reset` 的参数生效；全局支持登记为 DEFER-RS-03；`--` 之后的 `--json` 在错误路径仍被当作输出旗标的既有问题登记为 DEFER-RS-07。
- **Alternatives considered:** 在 `ResetArgs` 用 clap `allow_hyphen_values`：会让 `--hard` 等真选项被当作值。全局实现：影响所有命令，超出 #536。只改 argv、不改错误输出解析：`reset --end-of-options --json` 的错误会被渲染成 JSON，与成功路径不一致。
- **Consequences:** `src/cli.rs` 与共享的 `src/utils/output.rs` 进入 RS-07 的写集，须与其它写这两个文件的卡串行（DEP-RS-03）。
- **Revisit when:** DEFER-RS-03 立项时，改为复用全局实现。

### ADR-RS-09：新增拒绝的构造方式

- **Status:** Accepted
- **Context:** Git 对上述拒绝都以 `die()` 输出 `fatal: …` 并退出 128；Libra 的 `ResetError` 经 `From<ResetError> for CliError` 映射，`is_command_usage` 为假时用 `CliError::fatal`。
- **Decision:** 新增 `ResetError` 变体：`WorkTreeRequired`、`MixedInBare`、`InvalidCoreBare(String)`、`CoreBareRead(String)`、`MiddleOfMerge(&'static str)`；`WorkTreeRequired`、`MixedInBare`、`MiddleOfMerge` 用 `LBR-REPO-003`（128），`InvalidCoreBare` 用 `LBR-CLI-002`（129），`CoreBareRead` 用 `LBR-IO-001`（128）；`is_command_usage` 都为假，`hint` 都为 `None`。消息为 Git 原文去掉 `fatal: ` 前缀（Git 无对应者按 ADR-RS-03）。既有单测 `reset_error_display_pins_static_message_variants` 与 `reset_error_stable_code_pins_each_variant` 同卡补齐新变体。
- **Alternatives considered:** 加提示：Git 无提示；无提示时 JSON 没有 `hints` 字段，门的期望对象更简单。
- **Consequences:** 不新增稳定码，`docs/error-codes.md` 不变。
- **Revisit when:** 全局错误输出合同变化。

### ADR-RS-10：`--pathspec-from-file` 行模式解码 C 风格引号

- **Status:** Accepted
- **Context:** Git 在 `--pathspec-from-file` 的行模式下对以 `"` 开头的行做 `unquote_c_style`，NUL 模式不解码；引号格式错误时报 `fatal: line is badly quoted: <line>` 并退出 128（t7107#8、#9；2026-11-04 实测）。Libra reset 把每行原样当作路径（`reset.rs:1319-1333`），文档与 `COMPATIBILITY.md:216` 把它写成有意差异；而 `libra add` 已用共享的 `utils::text::decode_c_quoted`（`src/utils/text.rs:99-111`）实现同样的解码，格式错误报 `line is badly quoted in --pathspec-from-file: <reason>: <line>` 加 `LBR-IO-001`（`src/command/add.rs:742-766`）。
- **Decision:** reset 的行模式对每一项调用 `decode_c_quoted`：不是引号串则原样使用，解码成功用解码结果，格式错误以与 `add` 相同的消息与 `LBR-IO-001`（`fatal`，128）拒绝；NUL 模式不解码。读取上限、CRLF 处理与原始空行丢弃不变。解码结果为空串（列表项为 `""`）时不得像 `add` 那样丢弃：否则列表可能变空，reset 会改走整树分支（`reset.rs:931`）并移动 HEAD。与 Git 相同（`pathspec.c:637-641`；2026-11-04 实测 `""` 单独或与有效项同在都报错、退出 128），以 `CliError::fatal("empty string is not a valid pathspec. please use . instead if you meant to match all paths").with_stable_code(StableErrorCode::CliInvalidTarget)`（`LBR-CLI-003`，129；Git 128，沿用 Libra 无效 pathspec 的退出码约定）在任何写入之前拒绝。
- **Alternatives considered:** 保留有意差异：与 `add` 不一致，TC-2604 持续失败，且没有安全收益（解码后的路径仍经同一包含性检查）。在 reset 内另写解码：违反 GC-02。
- **Consequences:** 推翻文档中的有意差异；`add` 记录的两处解码差异（1–3 位八进制、拒绝闭引号后的多余字节）同样适用于 reset，文档写明。
- **Revisit when:** `decode_c_quoted` 的语义调整时，两条命令一起变化。

### ADR-RS-11：pathspec 相关的用法冲突用 Git 原文、`fatal`、退出 128

- **Status:** Accepted
- **Context:** Git 对 `--pathspec-from-file` 与 `--patch`、与命令行路径同用，`--pathspec-file-nul` 缺少 `--pathspec-from-file`，以及 `--soft`/`--hard`/`--merge`/`--keep` 带路径，都以 `die()` 输出 `fatal: …` 并退出 128（`builtin/reset.c:391-403`、`:455-461`；t7107#11 逐条 grep 这些原文）。Libra 当前：`--pathspec-from-file` 与 `--patch` 同用时静默忽略列表并进入交互模式；`--pathspec-file-nul` 单独使用被当作空操作（`reset.rs:1300-1306`）；其余冲突以 `error:` 前缀、Libra 自拟报文、`LBR-CLI-002`、129 拒绝（`reset.rs:683-698`、`:820-832`）。reset 内已有「Git `die` 的用法错误用 `fatal` 加 `LBR-CLI-002` 并以 `with_exit_code(128)` 退出 128」的先例（`--no-auto-advance` 需要 `--patch`，`reset.rs:220-233`）。
- **Decision:**
  - 新增两条拒绝：`options '--pathspec-from-file' and '--patch' cannot be used together`（在 `-p` 分派之前检查）、`the option '--pathspec-file-nul' requires '--pathspec-from-file'`（在读取任何列表之前检查）。
  - 既有四类冲突改为 Git 原文：`'--pathspec-from-file' and pathspec arguments cannot be used together`、`Cannot do soft reset with paths.`、`Cannot do hard reset with paths.`、`Cannot do <merge|keep> reset with paths.`；保留各自既有提示。
  - 六类全部构造为 `CliError::fatal(msg).with_exit_code(128).with_stable_code(StableErrorCode::CliInvalidArguments)`（沿用 `--no-auto-advance` 先例），检查顺序与 Git 相同：`--pathspec-from-file` 与 `--patch` → 与命令行路径 → `--pathspec-file-nul` → 模式带路径。
- **Alternatives considered:** 保留 129：t7107#11 用 `test_must_fail` 通过，但 `fatal:` 前缀与原文的 grep 仍失败，且与 reset 内既有的 128 先例不一致。
- **Consequences:** 四类既有拒绝的前缀、报文与退出码对外变化（129 → 128，稳定码不变）；`reset_test.rs:186-203` 与 `reset.rs` 的报文单测（`:3028` 起）同卡改写；文档错误表同步。
- **Revisit when:** 全局错误输出合同变化。

### ADR-RS-12：未匹配的 pathspec 继续报错（有意差异）

- **Status:** Accepted
- **Context:** Git 的 reset 不检查 pathspec 是否匹配：`git reset -- nosuch` 与 t7107#9 的 `--pathspec-from-file=list --pathspec-file-nul`（列表项不匹配）都退出 0；上游测试注释写明「`git reset` has not yet learned to fail on wrong pathspecs」。Libra 以 `pathspec '<p>' did not match any file(s) known to libra`（`LBR-CLI-003`，129）拒绝（`reset.rs:695-696`）。
- **Decision:** 保留 Libra 的拒绝，作为有意差异写入三份文档与 `COMPATIBILITY.md:216`（RS-10 同卡）；TC-2605 在 RS-08 中归属为本 ADR。
- **Alternatives considered:** 改为静默接受：拼写错误的路径会被无声忽略，Agent 与脚本无法发现；Git 自己的注释也把现状描述为尚未实现的检查。
- **Consequences:** TC-2605 保持 FAIL。
- **Revisit when:** Git 上游开始对 reset 的未匹配 pathspec 报错，或用户要求对齐。

### ADR-RS-13：pathspec 的选中集合按名字与后代匹配，条目整体替换

- **Status:** Accepted
- **Context:** Git 的普通 pathspec 同时匹配同名条目与其后代（`dir.c:444-449`），`.` 指当前目录（在子目录内只覆盖该子目录）；reset 以目标树对选中路径整体重建索引：目标有的写入 stage 0，没有的删除，并替换该路径的全部冲突阶段（`read-cache.c:1286-1296`）。2026-11-04 实测 Git：`DU` 冲突中只在冲突阶段存在的 `f`，`reset HEAD -- .` 后从索引消失；索引里是文件 `d`、`HEAD` 里是 `d/y` 时，`reset HEAD -- d` 后索引恰为 `d/y`。Libra reset 只把通配与 `:(magic)` 形式交给共享引擎（`reset.rs:1285-1290`），普通名字只做精确条目查找（`:1238-1250`），因此 `.` 与目录都报 `did not match`；引擎分支只枚举 stage-0 条目（`tracked_files()`）并只删 stage 0（`reset.rs:1183-1220`），精确分支用 `Index::add` 只插入 `(名字, 0)`（git-internal 0.10.4 `index.rs:630`、`:687`），两者都会留下 stage 1–3。
- **Decision:**
  - 选中集合：对每个 pathspec，在目标索引与当前索引（含全部 stage）的所有路径中，取等于该名字或以「该名字 + `/`」为前缀者（`.`、`./` 与以 `/` 结尾的形式按目录处理，相对路径按当前目录解析）；通配与 `:(magic)` 形式仍经共享引擎判定，但同样作用于两侧全部 stage 的路径。
  - 替换：对选中集合中的每个路径，先删除当前索引中该路径的 stage 0–3，再在目标有该路径时写入目标的 stage-0 条目（保留目标模式）。写入时按 Git 的文件/目录冲突规则（`builtin/reset.c:192-193` 打开替换；`read-cache.c:1177-1182`、`:1301-1307`）一并删除与之冲突的 stage-0 条目，即使它们不在选中集合内：该路径的每个祖先若在索引中是 stage-0 文件条目则删除，该路径之下的 stage-0 条目（`<路径>/…`）也删除；选中集合之外的冲突阶段（stage 1–3）一律保留，与 Git 一致（`read-cache.c:1071-1082`、`:1126`、`:1167` 只在写入的同一 stage 上处理冲突，reset 写 stage 0，`builtin/reset.c:169-170`；路径过滤不会把祖先 `d` 选入 `d/y` 的集合，`dir.c:444-449`）。精确命中文件、目录前缀、文件与目录互换、冲突路径都走同一过程，不再保留只按名字插入的精确分支。
  - 选中集合为空时沿用 `PathspecNotMatched`（ADR-RS-12）。包含性检查（`:1163-1172`）仍在选择之前，`..` 等逃逸照旧以 `LBR-CLI-002` 拒绝。工作树不写。
- **Alternatives considered:** 精确命中时保留旧分支：文件与目录互换时只处理名字本身，留下不完整或冲突的索引。只特判 `.`：目录名、子目录相对路径与冲突阶段仍错。
- **Consequences:** 文档中「普通名字只精确匹配索引路径」一句改写；RS-05 的 `-- .` 门依赖本卡；带路径的 reset 现在会清除选中路径的冲突阶段（与 Git 相同）。
- **Revisit when:** 无。

  ```bash
  zero_hits() {
    pattern="$1"; shift
    if rg -n -- "$pattern" "$@"; then
      echo "FAIL: forbidden pattern found"; return 1
    else
      rc=$?
      if [ "$rc" -ne 1 ]; then echo "ERROR: rg failed with exit $rc"; return "$rc"; fi
      echo "OK: zero hits"
    fi
  }
  ```

      actual="$(printf '%s\n' "$listing" | sed -n 's/: test$//p' | sort)"

      test "$actual" = "$expected"
    }
    gate_set_lib() {
      local module="$1" prefix="$2"; shift 2
      test "$#" -gt 0
      local listing actual expected
      listing="$(cargo test --lib -- --list "${module}${prefix}")"
      actual="$(printf '%s\n' "$listing" | sed -n 's/: test$//p' | sort)"

      test "$actual" = "$expected"

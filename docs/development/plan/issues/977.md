# Issue #977：`merge --log=<n>` 截断时必须输出 `(N commits)` 标头与 `...` 标记（2026-11-12）

> 模板 v2.16。[Issue #977](https://github.com/libra-tools/libra/issues/977) OPEN。仅规划，未授权执行；`I977-01` 为 `pending` / Acceptance 空。Git 对照 pin `6de20f6092dcf9bdb1c8efe03db4b70c82b423dd`。基线 `Cargo.toml` `0.30.173`（`Cargo.toml:3`）；实测 system `libra 0.30.173`。测试用例仓 `/mnt/gitmono/libra-testcases` 本计划不修改。

## 文档职责

### 适用范围

`merge`（及 `pull` 的自动合并、octopus 合并）生成的合并消息里，目标侧 shortlog 段落被 `--log=<n>` / `merge.log=<n>` 截断时的 Git 兼容形态：标头由 `* <upstream>:` 改为 `* <upstream>: (<N> commits)`，且被截断时在已列出 subject 之后追加一行 `  ...`；`n >= 总提交数` 时不截断、不出现 `(N commits)` 与 `...`。覆盖 `append_shortlog`/`unique_side_subjects` 的计数与渲染，以及 `merge`/`pull` 的既有调用点。

### 非目标

不实现 `issues/975.md` 的 `fmt-merge-msg` 子命令（本卡只让共享合成器在截断时输出 Git 形态，`fmt-merge-msg` 交付后自动受益）。不改变 `--log`/`--no-log`/`merge.log` 的取值与优先级（`src/command/merge.rs:340-345` 既有语义保持不变）。不改变 `unique_side_subjects` 的遍历顺序（仍为从 tip 起的 BFS 顺序）。不实现 `--into-name`/`-F` 行为变更、不实现 octopus 的 `Merge branches 'a', 'b'` 之外的新标题规则、不修改测试用例仓。

### 成功定义

- 侧分支提交数 `C > n` 时，标头行为 `* <upstream>: (C commits)`，subject 行数为 `n`，且其后恰好一行 `  ...`。
- `C <= n` 时标头为 `* <upstream>:`，无 `(... commits)`、无 `  ...`。
- `n == 0`（`--no-log`/`--log=0`）时不出现 shortlog 段落任何部分（既有短路保持）。
- 同时提供 `unique_side_subjects` 的总数信息（不截断遍历计数）以支撑 `C` 的判定，且不改变既有 `(new)`/既有断言。
- `merge`/`pull` 在未截断场景下输出与改动前逐字节相同。
- 扫描超过 100,000 个提交仍未完成时，使用 `LBR-MERGE-001`、退出码 128 与固定提示 `reduce the merge range and retry` 拒绝合成，stdout 不含部分消息。

## 已决议设计决策

### ADR-I977-01：`append_shortlog` 依赖一个携带总数的遍历结果

- **Status:** Accepted
- **Context:** `unique_side_subjects`（`src/command/merge_message.rs:65-90`）在 `subjects.len() == limit` 时 `break`，调用方无从得知是否被截断、更无从得知总数 `C`（`src/command/merge_message.rs:83-85`）。
- **Decision:** 让侧分支遍历返回 `SideSubjects { subjects: Vec<String>, total: usize }`：`subjects` 长度为 `min(C, limit)`，`total` 为不重复的目标侧提交总数（BFS 走完且不重复计数）。`append_shortlog` 据 `total > subjects.len()` 判定截断并渲染 `* <upstream>: (<total> commits)` + 尾部 `  ...`。
- **Alternatives considered:** 只在函数内比较 `subjects.len() == limit`（`C == n` 时会误判为截断，属真实边界错误）。
- **Consequences:** 截断判定精确；需要为计数多走剩余提交（见 ADR-I977-02）。
- **Revisit when:** 出现超大侧分支需要把计数改为流式提前终止策略。

### ADR-I977-02：计数遍历必须有明确上界，避免无界扫描

- **Status:** Accepted
- **Context:** 为得到 `C` 需要遍历侧分支全部提交，最坏为 `O(侧分支提交数)`，可能远大于 `limit`。
- **Decision:** 计数遍历与渲染遍历合并在同一次 BFS 内完成：最多加载 `MAX_SIDE_COMMITS_SCAN = 100_000` 个提交且不重复入队；若到达上界时仍有待遍历提交，返回可操作错误并停止合成，不调用渲染器，也不把已扫描数量冒充总提交数。成功时 `total` 始终是精确总数。性能预算记录为 `O(min(C, MAX_SIDE_COMMITS_SCAN))` 次对象加载。
- **Alternatives considered:** 二次独立遍历（对象加载翻倍）；只比较 `len == limit`（边界错误）。
- **Consequences:** 行为有界、可测；上界命中时整个消息合成失败，不会输出错误的 `(... commits)` 数量或部分消息。
- **Revisit when:** 出现真实仓库超过该上界并影响可用性。

### ADR-I977-03：未截断场景必须字节不变

- **Status:** Accepted
- **Context:** `merge_message_options_*`（`tests/command/merge_test/message_options.rs:99/131/144`）等既有断言依赖当前输出。
- **Decision:** `total == subjects.len()` 时输出与改动前逐字节相同（`* <upstream>:` + 逐行 `  <subject>`，无计数、无 `...`）。新增断言只覆盖截断分支。
- **Alternatives considered:** 统一加计数（会破坏既有断言与非截断 Git 形态）。
- **Consequences:** 零回归可机械验证。
- **Revisit when:** N/A。

  sleep 30
done

test "$(gh run view "$REL_ID" --repo libra-tools/libra --json jobs --jq '[.jobs[]|select(.name|startswith("build-and-upload ("))|select(.conclusion=="success")]|length')" = 4
for j in upload-install-scripts update-homebrew-tap verify-homebrew-formula request-stable-manifest; do
  gh run view "$REL_ID" --repo libra-tools/libra --json jobs --jq "[.jobs[]|select(.name|startswith(\"$j\"))|select(.conclusion==\"success\")]|length" | awk '{exit ($1>=1)?0:1}' || { echo "release job missing/failed: $j" >&2; exit 1; }

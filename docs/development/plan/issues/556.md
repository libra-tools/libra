# Issue #556：非 HEAD 符号引用存储与 `symbolic-ref` / `branch` 对齐计划（2026-11-08，R1 修订）

> 模板版本：v2.16。本计划不在 `code-only` 具名范围内，migration/implementation 卡按默认版本化发布合同执行（`independent`、`patch + 1`、`gh release`）。来源：[libra-tools/libra#556](https://github.com/libra-tools/libra/issues/556)（OPEN）。事实基线为 `main` @ `07bffa6885604553babc45d2148c3fe53341e868`（`Cargo.toml:3`、`Cargo.lock:6480`、`install.sh:21` 和 `install.ps1:25` 均为 `0.30.160`），2026-11-08。本文只规划，不宣称实现完成；行号开工时按 ER-02 刷新。`plan-status.md` 由协调者在同一提交登记，本文件不代替登记。本轮只修订本文，不修改源码、测试或其它计划。

## 文档职责

本文处理 #556 正文和全部 7 条评论在 baseline 上仍成立的非 HEAD 符号引用缺口，并承接 #541 评论 10 的 remote HEAD 符号形式。设计使用 Repository-only `symbolic_reference` 表保存通用符号引用，以 canonical view 和数据库触发器保证它与既有 `reference` 直接行在两个写入方向、层级冲突和并发下都不能形成双表示；统一解析器跨通用行、本地 HEAD、remote HEAD、直接 ref 和不存在目标逐跳工作。不重做 #479 SR-01 的 HEAD 删除语义。

### 适用范围

- `symbolic_reference(id, name, target, worktree_id)`、canonical direct-ref view、跨表/层级触发器、唯一索引、guarded down 和角色隔离。
- 固定 WorktreeScope 的统一逐跳解析器，覆盖通用 symref、本地 HEAD、remote HEAD、直接 ref、missing target、跨形态环、损坏和 DB 错误。
- 非 HEAD `symbolic-ref` 创建、默认递归读取、`--no-recurse`、`--short`、JSON、quiet 和真实 `-d/--delete`：
  - `refs/heads/dangling-symref -> nowhere`（TC-0228）；
  - `refs/heads/self-reference -> refs/heads/self-reference`（TC-0229）；
  - `refs/heads/broken_symref -> refs/heads/i_am_broken`（TC-0239）；
  - `refs/heads/topic -> refs/heads/main`（TC-0251）；
  - 根级 `DANGLING_HEAD -> refs/heads/missing`（TC-3298 前置）。
- `refs/remotes/<remote>/HEAD` 继续只存于既有 remote Head 行；#541 URM-01 的 fallible 读写是强制前置。
- `branch -d/-D` 删除 heads 符号引用并输出 `(was <target>)`；`branch -m` 的 source symref 拒绝和 destination symref 原子替换/reflog 移动。
- EN、zh-CN、开发文档、网站页、`COMPATIBILITY.md:204/:206`、必要的错误码文档和真实上游复核。

### 非目标

- 不重做 #479 SR-01：`-d HEAD` 继续 128 `deleting 'HEAD' is not allowed`；HEAD read/set/detached/quiet 和跨 worktree checkout 守卫不重写。
- 不实现 `for-each-ref --include-root-refs` 或根级符号引用枚举；TC-3298 的 DANGLING_HEAD setup 解除不等于整条通过（DEFER-SY-01）。
- 不实现 update-ref stdin `symref-*`（DEFER-SY-02），也不让 `DANGLING_HEAD` 自动成为 rev-parse 伪引用。
- 不支持用 symbolic-ref 覆盖同名现存直接 Branch/Tag/Head；remote Detached HEAD 的 set/read/delete 同样拒绝并保留（DEFER-SY-03）。
- 不修 #688 的普通 direct-to-direct rename/reflog 全部缺口；SY-05 只覆盖 issue 指定的 symref source/destination（DEFER-SY-04）。
- 不改变六个历史 pseudo-ref 的 sequencer/sidecar 投影，不为它们建第二存储。
- 不实现 checkout、for-each-ref 或其它下游命令的独立缺口；TC-0347 的不带前缀 branch checkout 单列，不宣称已支持。
- 不创建或修改 `issues/711.md`；未来重叠由协调者去重。
- 不新增稳定错误码，不默认关闭 #556；回复、关闭和后续 issue 均需用户确认。

### 成功定义

- 通用符号引用有单一 Repository 存储，canonical view + 触发器在两个创建方向原子阻止同名/层级双表示；并发测试不依赖 CLI 自查。
- 默认读取在同一固定 scope 和读取快照中跨所有 Head/ref 形态逐跳解析；dangling 可读出，环/超深/DB 错误 fail-closed，`--no-recurse` 只返回直接 target。
- #541 URM-01 先交付 Result 型 remote HEAD 读写；本计划 SY-07 复用它，SY-03 强制通过 direct/symbolic 双向联合测试。
- 旧二进制对迁移后空表和非空表仓库都因 future schema 拒绝且零写；文档不提供直接降级旧二进制的错误建议。
- 十张 migration/implementation 卡独立版本化发布，SY-06 由 CLOSE-556 承载；CLI、网站和最终全量证据完整。
- TC-0228/0229/0239/0240/0251/3298 与 TC-0199 的结果如实记录，DEFER 和下游失败不写成 PASS。

### ADR-SY-01：通用表保留，但名称占用由数据库跨表强制

- **Status:** Accepted（替代 R0 的“仅靠 helper 查重”）
- **Decision:** 新建 `symbolic_reference` 与 `canonical_reference` view。view 将 local Branch 短名映射为 `refs/heads/<name>`、remote Branch 短名映射为 `refs/remotes/<remote>/<name>`；已保存完整 `refs/heads/…` 或 `refs/remotes/…` 的 Branch 行不重复追加前缀（`src/command/show_ref.rs:265-293`、`src/command/for_each_ref.rs:343-351`）。注意 for-each-ref 的本地分支路径当前仍无 full-name 检测（`:324-333`）：SY-09 必须用真实旧行 fixture 检查规范化与双向占用，不得声称所有读者已有一致语义；若兼容旧行和安全占用无法同时证明，先修订设计并阻断迁移，不能静默改写旧行。Tag 使用完整 name，local Head 为 scoped `HEAD`，remote Head 为 `refs/remotes/<remote>/HEAD`。不合规范或无法判定 canonical 名的已有行 fail-closed，不能静默漏掉。共享 scope key 为空串；根级 symref/local HEAD 使用 `COALESCE(worktree_id,'')`。
- **Decision（触发器）：** SY-01 只落内部表，不暴露可创建符号行的公开入口；SY-09 在 SY-02 前安装两表 AFTER INSERT/UPDATE 触发器，检查另一表的 canonical 等值与 `/` 层级冲突，并检查通用表自身层级冲突。比较采用大小写敏感的字节前缀和分隔符，不能把 refname 中合法的 `_` 等字符当 SQL LIKE 通配符。共享 `refs/` 与所有 worktree 同名占用冲突，根级名只与同 scope 冲突。触发器 `RAISE(ABORT)` 撤销当前 SQL 语句；调用方必须传播错误、回滚其整个写事务，不能假称 SQLite 的 ABORT 自动回滚外层事务。直接 SQL 也无法留下跨表双表示。
- **Alternatives considered:** 只做 CLI 检查无法覆盖现有写者；第三张 occupancy 表需要额外 backfill/删除维护；重建 reference 单表会扩大所有既有行和读者迁移。
- **Consequences:** 现有 direct 写者无需知道新表也无法绕过；通用表从空开始，无历史双表示。SQLite 写事务串行决定并发赢家，另一方失败且无双行。`reference` 旧索引以 `(name,kind,remote)` 为键，SQLite 对 NULL 不判相等，不能保证同一 remote 的 Detached / Branch Head 唯一；SY-09 必须在基表新增针对 remote Head 的部分唯一索引和既有重复 fail-closed 预检。本地 HEAD 复用 `2026072901_head_scope_unique.sql:54-60` 的已交付唯一约束，不声称可以在 view 建索引。
- **Revisit when:** 采用真正统一的 Git ref backend。

### ADR-SY-02：name、target、scope 与保留名称分别校验

- **Status:** Accepted
- **Decision:** `refs/**` name 必须经完整 refname 校验且 worktree_id NULL；根级 name 只允许合法非空 Git pseudoref 形态并绑定当前 WorktreeScope。`HEAD` 走本地 Head，`refs/remotes/<remote>/HEAD` 走 remote Head，六个 scoped pseudo-ref 名称拒绝进入通用表。
- **Decision（target）：** target 原样保存，可为难存在的完整 ref 或 `nowhere`；空串、NUL、换行、路径穿越式非法 ref 形态拒绝，但不要求 target 存在。name/target 规则不同，不能把 nowhere 强制套入严格 target refname。
- **Consequences:** 等值和父子前缀冲突均 fail-closed；linked worktree 根级同名互不覆盖，普通 refs 共享。
- **Revisit when:** Git root-ref 规则或 pseudo-ref 架构改变。

### ADR-SY-03：统一解析器跨所有存储形态

- **Status:** Accepted
- **Context:** 通用表不含 HEAD/remote HEAD，但 target 可以指向它们。
- **Decision:** SY-07 在一个 SQLite 读取快照和固定 WorktreeScope 中执行逐跳 `RefHop` 查询：通用符号行、本地 Head、remote Head、直接 Branch/Tag/remote Branch、missing。起始名称必须是符号引用；默认读取遇到符号 target 继续前进，遇到直接 ref 或 missing target 返回其 canonical 名称。detached HEAD/remote HEAD 不是可输出的符号 target，终止为 128 非符号错误。
- **Decision（安全）：** visited key 包含 canonical name + scope，固定深度上限 32 跨所有形态生效；重复/超深、损坏和 DB 错误均为 Err。`--no-recurse` 只调用 immediate read，不检查 target 存在。
- **Alternatives considered:** 只遍历通用表会漏跨存储环；每次跳重新获取连接会读到混合快照；限制 target 不指向 HEAD 会无依据缩小 issue 的通用语义。
- **Consequences:** #541 URM-01 Result 型 remote 查询是硬前置；symbolic-ref 与未来消费者共用同一 helper。
- **Revisit when:** ref backend 或 worktree scope 规则改变。

### ADR-SY-04：非 HEAD 删除真实生效，HEAD 不变

- **Status:** Accepted
- **Decision:** SY-08 对实际通用符号行事务删除；不存在/direct 名称 128 `Cannot delete <name>, not a symbolic ref`；HEAD 原拒绝不变。普通 missing read 改 128 `ref <name> is not a symbolic ref` / LBR-CLI-003；quiet exit 1 无 human 输出；JSON quiet exit 1 只有结构化 envelope。
- **Consequences:** 更新 plumbing_exit_contract 的 non-HEAD read 行为，保留三个 SR-01 删除断言。错误码表补充 quiet 例外而非新增码。
- **Revisit when:** HEAD 存储或稳定错误码合同改变。

### ADR-SY-05：remote HEAD 只复用 remote Head 行，直接值不被覆盖

- **Status:** Accepted
- **Decision:** SY-03 target 必须是 `refs/remotes/<同一 remote>/<非空 branch>`，可 dangling；Head::Branch 可创建/更新/读取/删除。已有 Detached 行的 symbolic-ref set/read/delete 均 128 拒绝并保留；#541 update-ref 对 Head::Branch 的 update/create/delete/verify 在默认、argv `--no-deref` 与 stdin `option no-deref` 下均拒绝且零写。跨 remote target 不在 issue 验收，拒绝。
- **Consequences:** URM-01 → SY-07 → SY-03 为不可逆执行顺序；两个方向真实 CLI 联合测试是 SY-03 必门，不得条件跳过。
- **Revisit when:** 另立直接/符号 ref 覆盖或跨 remote target ADR。

### ADR-SY-06：branch rename 的 source/destination 规则不同

- **Status:** Accepted
- **Decision:** source symref 以 128 拒绝；direct source 改名到 symref destination 时，在一个写事务删除 destination symref、移动 direct source、移动 source reflog，并保留 config/policy/worktree/operation 守卫。普通 direct-to-direct 的 #688 不扩大进来。
- **Revisit when:** #688 统一重整 rename/reflog。

## 全局工程约束

- **GC-SY-01 单一事实源：** 本地/remote HEAD 只在 Head 行；其它通用 symref 只在 symbolic_reference。canonical view 和触发器是唯一跨表占用机制，禁止第二套 CLI-only 判定。
- **GC-SY-02 共享解析：** SY-07 的 RefHop/visited/scope/snapshot 被 symbolic-ref、remote HEAD 和后续消费者复用；branch delete/rename 不复制递归逻辑。
- **GC-SY-03 原子性：** 创建、删除、rename 替换、reflog/config/operation 写在同一写事务；任何失败全部不变。数据库触发器错误不得被改写成 missing。
- **GC-SY-04 有界 fail-closed：** 固定 scope、单读取快照、visited 和 32 跳上限；busy 有界重试后 Err，非 busy/损坏/重复均 Err。
- **GC-SY-05 名称与 scope：** ADR-SY-02 的 name/target/保留名/层级规则在存储与 CLI 一致；双 worktree 证明根级隔离和 refs 共享。
- **GC-SY-06 既有功能：** HEAD SR-01、detached/quiet、cross-worktree、普通 branch delete/rename、protect/archive、operation log 不削弱。
- **GC-SY-07 数据库角色：** 仅 Repository 注册/应用 migration；GlobalConfig/SystemConfig 的 configuration ledger 与 config_kv 语义不变；Derived 拒绝迁移且字节不变。bootstrap 不伪装已含新表，fresh 经 runner 与 upgrade 收敛。
- **GC-SY-08 文档：** COMPATIBILITY :204/:206 原地更新且行数不变；区分通用、HEAD、remote HEAD 与 DEFER，不写完整 symbolic-ref。
- **GC-SY-09 退出合同：** SY-08 起 missing 非 HEAD 普通/short 为 128 LBR-CLI-003，human quiet 为 1 无输出，JSON quiet 为 1 结构化错误；HEAD 既有行为不变。
- **GC-SY-10 证据卫生：** 只记录 sanitized 摘要；oracle 路径用环境变量，不把本机私有路径写进计划。
- **GC-SY-11 no-JUnit 与重跑安全：** 本计划每条 nextest 命令都使用下面的 `run_nextest` / `check_exact_set`（`run_exact`、`run_exact_names` 分别封装它们）执行。配置只能在规范化验证的仓外新建 0700 私有目录内由 `mkstemp` 独占创建；禁止用 `>` 写到调用者路径、复用已有配置、跟随 symlink 或经 `..` 指回仓库。每次运行生成不同配置，普通 Cargo 编译缓存可以复用；不设置“必须不存在”的共享测试输出目录，也不清理其它轮次内容。
- **GC-SY-12 不可信工件：** 下载文件和解压内容均视为不可信；每份下载及每个解压目录分别使用新建空目录，脚本与这些目录分开，通过参数传路径；不得在下载目录内运行解释器或构建工具，Python 读取下载数据一律 `python3 -I`。oracle 先用独立可信的官方发行信息固定并校验准确版本和 SHA-256，失败或未确定时不得执行该 binary；结果只记录 sanitized 摘要。

```bash
TASK_NEXTEST_DIR="$(python3 -I -c 'import pathlib,tempfile; root=pathlib.Path.cwd().resolve(); base=pathlib.Path("/tmp").resolve(strict=True); assert base != root and root not in base.parents; print(tempfile.mkdtemp(prefix="libra-556-nextest-",dir=base))')" || exit
export TASK_NEXTEST_DIR
prepare_nextest_cfg() {
  NEXTEST_NOJUNIT_CFG="$(python3 -I -c 'import os,pathlib,stat,sys,tempfile; root=pathlib.Path.cwd().resolve(); d=pathlib.Path(sys.argv[1]); real=d.resolve(strict=True); st=d.lstat(); assert d.is_absolute() and not stat.S_ISLNK(st.st_mode) and real==d and root != real and root not in real.parents and st.st_uid==os.getuid() and stat.S_IMODE(st.st_mode)==0o700; s=pathlib.Path(".config/nextest.toml").read_text(); a="[profile.default.junit]\npath = \"junit.xml\"\n"; assert s.count(a)==1 and s.count(".junit]")==1; fd,p=tempfile.mkstemp(prefix="nextest-",suffix=".toml",dir=real); f=os.fdopen(fd,"w"); f.write(s.replace(a,"",1)); f.close(); print(p)' "$TASK_NEXTEST_DIR")" || return
  export NEXTEST_NOJUNIT_CFG
}
run_nextest() {
  prepare_nextest_cfg || return
  cargo nextest run --config-file "$NEXTEST_NOJUNIT_CFG" "$@"
}
run_exact() {
  local target="$1" name="$2"
  shift 2
  if [ "$target" = --lib ]; then
    run_nextest --lib --no-tests=fail -E "test(=$name)" "$@"
  else
    run_nextest --test "$target" --no-tests=fail -E "test(=$name)" "$@"
  fi
}
check_exact_set() {
  local target="$1" ignored="$2" expected="$3" expr="$4"
  shift 4
  local -a selector=() capture=()
  [ "$target" = --lib ] && selector=(--lib) || selector=(--test "$target")
  [ "$ignored" = only ] && capture=(--no-capture)
  case "$ignored" in default|only) ;; *) return 2 ;; esac
  prepare_nextest_cfg || return
  (set -o pipefail
   cargo nextest list --config-file "$NEXTEST_NOJUNIT_CFG" --user-config-file none --show-progress none --ignore-default-filter "${selector[@]}" --run-ignored "$ignored" -E "$expr" -T oneline "$@" |
     python3 -I -c 'import sys; expected=sys.argv[1].splitlines(); found=sys.stdin.read().splitlines(); names=[line.split(None,1)[1] for line in found]; assert expected and len(set(expected))==len(expected) and sorted(names)==sorted(expected), {"expected":expected,"found":names}' "$expected") || return
  cargo nextest run --config-file "$NEXTEST_NOJUNIT_CFG" --user-config-file none --ignore-default-filter --no-tests=fail --no-fail-fast --status-level pass --final-status-level all "${capture[@]}" "${selector[@]}" --run-ignored "$ignored" -E "$expr" "$@"
}
run_exact_names() {
  local target="$1" ignored="$2" expected expr="" name
  shift 2
  [ "$#" -gt 0 ] || return 2
  printf -v expected '%s\n' "$@"
  for name in "$@"; do
    [[ "$name" =~ ^[a-zA-Z0-9_]+(::[a-zA-Z0-9_]+)*$ ]] || return 2
    [ -z "$expr" ] || expr+=" or "
    expr+="test(=$name)"
  done
  check_exact_set "$target" "$ignored" "$expected" "$expr"
}
```

模板 G-05 只要求确切命令，不要求每个测试各跑一次。单一测试用 `run_exact target '完整函数名'`；多个同类必需测试用 `check_exact_set target ignored 期望的完整函数名清单 'test(=name1) or test(=name2)'`，`ignored` 为 `default` 或 `only`。该门先以 `nextest list` 验证实际选中且可运行的完整名称与预期集合**完全一致**，零命中、漏名、额外名、错误 ignored 分类及默认 filter 排除均失败；再以完全相同的 selector、filterset、ignored mode 和 `--ignore-default-filter` 执行，并显示并记录逐测试 terminal status。不能用宽泛前缀的非零命中替代此集合校验。每次 `check_exact_set` 的 list 判定和 run 判定按 G-03 分别计两门，里面测试覆盖的行为谓词仍分别计入 AC。

```bash
TASK_SY01_TESTS="$(printf '%s\n' 'symbolic_reference_example_a' 'symbolic_reference_example_b')"
check_exact_set db_migration_test default "$TASK_SY01_TESTS" 'test(=symbolic_reference_example_a) or test(=symbolic_reference_example_b)'
```

`run_exact_names target ignored 完整测试名...` 依上述清单生成精确表达式，仍按 list 和 run 各计一门；不接受空清单、重复名或非法名称。该集合 helper 已在独立临时 Rust 测试夹具验证：完全匹配及 only-ignored 成功，漏项、多项和默认模式选 ignored 均失败；这不是本计划新增测试已实现的证据。

环境 gate 或平台 guard 不能造成静默跳过：这类测试在隔离前置条件满足后执行，加 `--no-capture` 并在结果中记录实际 terminal status 和实际 setup；缺前置保持 blocked，而不是把 skip 算作通过。`check_exact_set` 对 `only` 自动为 run 加 `--no-capture`（不传给 list）；已在独立临时 Rust 夹具中以测试体 sentinel 验证实际运行。oracle 测试本身必须断言 opt-in、摘要及所有前置，不得条件 return。`nextest list` 的 oneline 解析规则已对照本机 nextest-runner 0.122.1 `src/list/test_list.rs:2316-2327`，固定 cargo-nextest 0.9.143。

根配置的 JUnit 段若与断言不符即停止，不得静默删除其它配置。每轮配置路径均唯一且不会覆盖已有内容；只需清理本轮经上述检查的专属目录，不要求重建 Cargo target 缓存。

## 文档职责

issue #478 是一次批量对照，写于 libra 0.22.5。本计划在 libra 0.22.28 与 git 2.54.0 上分四轮并排实跑，逐条复核正文全部断言，结论分四类：

- **已修复（只需回归守卫）：**
  - `rev-list --objects`；
  - `notes merge/prune/get-ref`；
  - `reflog delete/exists`；
  - `mailinfo <msg> <patch>` 两参数形式；
  - `diff-index`/`diff-files` 非 TTY 下的进度噪声（#466）。
- **断言不成立：**
  - **`log --grep`：** issue 称「Libra 为正则、Git 为固定字符串」，实测相反：Git 默认 POSIX BRE，Libra 为子串匹配，且会匹配到提交签名文本。
  - **`fast-import`：** Git 本身也不接受位置参数 `<file>` 与 `--dry-run`。
  - **`am` 失败时 exit 0：** 连续三次未复现，Git 与 Libra 均为 128。
  - **跨工具互通：** bundle 双向 verify 与 fetch 均通过。
- **确认的缺口：**
  - log：`--grep` 模式选择；notes 显示与 `%N`；`--graph` 拓扑。
  - show：`^{tree}` 与 `<rev>:<dir>`。
  - diff 与 apply：`--dirstat`；plumbing diff 默认 raw 输出；`apply` 实际应用及其参数。
  - grep：`--fixed-strings` 长选项、`-P`、布尔表达式、函数与数字上下文。
  - blame：`-L` 夹取、`--date`、`--incremental`、`-M/-C`。
  - 其它：shortlog 修订范围；notes `-C/-c`；reflog 裸命令参数与 `--date`；rev-list `--no-walk`/`--disk-usage`；fast-import `--force/--stats/--big-file-threshold`。
- **issue 未列出、影响脚本与互操作的新发现：**
  - unified diff hunk 头不是 Git 规范形式，清空文件被写成 `+++ /dev/null`；
  - `show --stat` 输出为名称状态列表且统计错误；
  - log/show 默认布局（日期补零、空行）与 Git 不同；
  - `show` 的树输出格式不同；
  - `diff-index --cached` 不支持；
  - `notes list` 输出缩写 OID；
  - blame 缺边界 `^` 前缀；
  - fast-import 的 progress 与统计写错输出流。

### ADR-LG-02: `--grep` 模式类型与匹配范围

- **Status:** Accepted
- **Context:** GAP-01；git `grep.c:43`、`revision.c:2704-2717`；`t4202:267-290`。
- **Decision:**
  1. **模式类型：** `log` 与 `rev-list` 共用一个提交消息过滤器：
     - 默认 POSIX BRE（含 GNU `\+`、`\?`、`\|` 扩展）；
     - `-E/--extended-regexp` 为 ERE；
     - `-F/--fixed-strings` 为固定字符串；
     - `-P/--perl-regexp` 使用 ADR-LG-09 的引擎；
     - `--basic-regexp` 显式选择 BRE；
     - 同一命令行中后出现的模式类型选项生效；
     - 配置 `grep.patternType` 与 `grep.extendedRegexp` 在无命令行选项时生效。
  2. **BRE/ERE 实现：** 由单一转换函数把 BRE/ERE 翻译为 Rust `regex` 语法（转义字面 `+?|(){}`、处理 `\<`/`\>` 词边界），与 grep 命令共用（LG-14 复用）。
  3. **多模式：** 多个 `--grep` 默认为「任一匹配」；`--all-match` 为「全部匹配」；`--invert-grep` 与 `-i/--regexp-ignore-case` 组合语义与 Git 一致。
  4. **匹配范围：** 只匹配提交消息（`encoding` 与签名头之外的消息正文，含主题），不匹配 `gpgsig`/签名块、树与作者行（N1）。
  5. **错误：** 非法模式为用法错误（129，`LBR-CLI-002`），错误中给出模式与原因。
- **Alternatives considered:** 保留子串匹配并只新增 `-E`——默认语义仍与 Git 不同，拒绝。直接把默认改为 Rust `regex`——`c++ (fix)` 等 BRE 字面在 Rust 语法下报错或语义不同，拒绝。
- **Consequences:** 默认匹配语义变化是公开行为变化，log/rev-list 文档与 `COMPATIBILITY.md:196`、`:218` 登记。
- **Revisit when:** 无。

### ADR-LG-04: unified diff 规范 hunk 头与 diffstat

- **Status:** Accepted
- **Context:** GAP-03、GAP-04；Libra hunk 头在 `src/command/diff.rs:6321`、`:6537` 两处格式化；Git 规则为「长度为 1 时省略 `,1`，长度为 0 时起始行取前一行（新文件为 0）」。
- **Decision:**
  1. **单一格式化函数：** hunk 头集中为一个函数，所有 patch 输出面共用（`diff`、`diff --cached`、`show`、`log -p`、`format-patch`、plumbing `-p`、`stash show -p`）。
     - 长度为 1 时写 `-<start>`；
     - 长度为 0 时写 `-<start-1>,0`，新文件为 `-0,0`；
     - 其余写 `-<start>,<len>`；新侧同理。
  2. **文件头：** 只有真正删除的文件写 `deleted file mode` 与 `+++ /dev/null`；内容被清空但仍存在的文件保持 `+++ b/<path>`。
  3. **解析兼容：** Libra 的补丁解析（`apply`、`am`、patch mode）同时接受旧的非规范头与规范头，已保存的旧补丁仍可应用。
  4. **diffstat：** `show --stat` 与 `log --stat`、`diff --stat` 共用同一 diffstat 渲染与计数（名称列、`|`、计数、`+/-` 条形、`N files changed, X insertions(+), Y deletions(-)`）；二进制文件为 `Bin a -> b bytes`。
- **Alternatives considered:** 只修 porcelain `diff`——`format-patch` 与 plumbing 仍输出旧格式，与 477 HF-15 的逐字节比对冲突，拒绝。
- **Consequences:** 所有 patch 输出面的字节变化；同批更新依赖旧头的测试；LG-03 命中 T-1。
- **Revisit when:** 支持 `diff.suppressBlankEmpty` 等细节配置。

  **M-HUNK（LG-03）与 M-STAT（LG-04）**

  | 行 | 场景 | 期望（与 git 2.54 逐字节一致） |
  |---|---|---|
  | H1 | 新增 1 行文件；新增 3 行文件 | `@@ -0,0 +1 @@`；`@@ -0,0 +1,3 @@` |
  | H2 | 删除文件 | `deleted file mode 100644`、`+++ /dev/null`、`@@ -1 +0,0 @@` |
  | H3 | 内容清空但保留的文件 | `+++ b/gone.txt`、`@@ -1 +0,0 @@` |
  | H4 | 单行修改；2 行变 1 行 | `@@ -1 +1 @@`；`@@ -1,2 +1 @@` |
  | H5 | H1–H4 在 `diff`、`diff --cached`（含未诞生 HEAD）、`show`、`log -p`、`format-patch --stdout`、`diff-files -p`、`diff-tree -p` 上 | 输出一致 |
  | H6 | `git apply --check`、`git am` 应用 Libra 补丁；`libra apply --check`、`libra am` 应用 Git 补丁 | 均成功（互操作守卫） |
  | H7 | Libra 旧格式补丁（`@@ -1,0 +1,1 @@`）经 `libra apply --check` / `libra am` | 仍被接受 |

  | S2 | 同一提交的 `log --stat -1`、`diff --stat HEAD~1 HEAD` | 与 S1 计数一致 |
  | S3 | 二进制文件 | `Bin <a> -> <b> bytes` 行，以 git 实跑为准 |

### ADR-LG-06: `--dirstat` 与 plumbing diff 输出格式

- **Status:** Accepted
- **Context:** GAP-08..GAP-10；git `diff.c:141`、`:3366`、`:5436`，`builtin/diff-tree.c:108`，`builtin/diff-index.c:50`、`:60`，`builtin/diff-files.c:65`，`revision.c:2563-2566`、`:2651-2653`；`t4047:330-355`。名称输出与退出码由 479 DF-01 承接。
- **Decision:**
  1. **`--dirstat`：**
     - 参数形式为 `--dirstat[=<param>,...]`，参数取 `changes`/`lines`/`files`、`cumulative`/`noncumulative` 与百分比阈值（默认 3）；
     - 另支持 `--cumulative` 与 `-X[<param>]`；
     - 输出每行为 `%5.1f% <dir>/`，排序、阈值与父目录归并规则与 Git 一致；
     - 在 `diff`、`show`、`log` 的共享 diff 选项上可用；
     - 非法参数为用法错误。
  2. **`diff-tree`：**
     - 默认 raw 格式 `:<old-mode> <new-mode> <old-oid> <new-oid> <status>\t<path>`，OID 为完整长度（随对象格式 40/64 位），非递归时子树作为 `040000` 条目出现；

     - `--root` 使根提交与空树比较。
  3. **`diff-index` / `diff-files`：**
     - 默认 raw，工作树侧 OID 为全零；
     - `-p` 输出补丁，`--raw` 显式选择 raw；
     - `diff-index --cached <tree>` 比较树与索引。

- **Alternatives considered:** 保留 patch 默认并新增 `--raw`——plumbing 默认格式仍与 Git 不同，脚本继续误解析，拒绝。
- **Consequences:** LG-09/LG-10 与 479 DF-01 同文件串行（DEP-LG-01）。
- **Revisit when:** 支持 `--stdin`、`-c/--cc` 合并提交格式（DEFER-06）。

### ADR-LG-07: `apply` 应用语义

- **Status:** Accepted
- **Context:** GAP-11..GAP-13；git `apply.c:5217-5280`；`t4106:15`、`t4102:38`、`t4108:40`、`:75`。Libra 已有补丁准备与 section 应用（`src/command/apply.rs:309`、`:630`），`--check` 已落地。
- **Decision:**
  1. **默认应用：** `apply <patch>...`（或 stdin `-`）只作用于工作树，全部检查通过后才写入任何文件，任一 hunk 失败则零写入。
  2. **报告模式：**
     - `--stat`、`--numstat`、`--summary` 只输出报告不应用（与 `--apply` 同用时先报告后应用），格式与 Git 相同；
     - `--check` 保持现状。
  3. **方向与过滤：**
     - `-R/--reverse` 反向应用；
     - `--exclude=<glob>`、`--include=<glob>` 按命令行顺序首个匹配决定是否使用该路径，使用 Git wildmatch 语义。
  4. **索引模式：**
     - `--index` 要求受影响路径的工作树与索引一致，否则报 `<path>: does not match index` 并零写入；成功时同时更新索引与工作树。
     - `--cached` 只更新索引。
  5. **三路模式（`--3way`）：**
     - hunk 不能直接应用时，用补丁 `index` 行的前像 blob 在对象库中做三路合并（复用 merge 内容合并引擎）；
     - 干净合并时 stderr 输出 `Applied patch to '<path>' cleanly.` 并更新索引；
     - 冲突时写冲突标记与未合并 stage，失败退出；
     - 前像 blob 缺失时与 Git 一样失败；
     - `--3way` 隐含 `--index`，与 `--cached` 的组合以 git 实跑为准。
  6. **退出与安全：**
     - 补丁不适用为 `LBR-CONFLICT-001`（128）；
     - 路径逃逸、`.libra` 元数据与符号链接祖先沿用既有 section 校验；
     - 二进制补丁沿用既有解析。
- **Alternatives considered:** 逐文件写入并在失败时回滚——中途崩溃会留下部分应用，拒绝。
- **Consequences:** `COMPATIBILITY.md:183` 从 `--check` only 更新为完整面；`am` 继续使用同一应用路径。
- **Revisit when:** 支持 `--reject`、`--whitespace`、`--recount` 等（DEFER-07）。

  **M-APPLY（LG-11）、M-AIDX（LG-12）、M-A3W（LG-13）**

  | 行 | 调用（补丁为 `a.txt` 末尾追加一行） | 期望（与 git 2.54 一致） |
  |---|---|---|
  | A1 | `apply --stat p.patch` | ` a.txt \|    1 +` 与 `1 file changed, 1 insertion(+)`；不修改文件 |
  | A2 | `apply --numstat p.patch`；`--summary`（新增/删除/mode 变更补丁） | `1\t0\ta.txt`；summary 以 git 实跑为准 |
  | A3 | `apply p.patch` | 工作树改动，索引不变（`status --short` 为 ` M a.txt`） |
  | A4 | `apply -R p.patch` | 恢复原内容 |
  | A5 | 两文件补丁中第二个 hunk 不适用 | 失败，两个文件都未改动 |
  | A6 | `t4106:15`（`--numstat -` 自 stdin）、`t4102:38`（reverse rename） | 通过 |
  | B1 | 工作树与索引一致时 `apply --index p.patch` | 索引与工作树同时更新（`M  a.txt`） |
  | B2 | 工作树与索引不一致时 `apply --index` | `a.txt: does not match index`，零写入 |
  | B3 | `apply --cached p.patch` | 只更新索引，工作树不变 |
  | B4 | `--exclude=a.txt`；`--include=a.txt --exclude=*`；`--exclude=* --include=a.txt` | 第一个跳过且 exit 0；第二个应用；第三个跳过 |
  | B5 | 新增文件、删除文件、mode 变更补丁配合 `--index` | 索引与工作树结果与 Git 一致 |
  | C1 | 基底行被改动但可三路合并时 `apply --3way p.patch` | `Applied patch to 'a.txt' cleanly.`，索引已暂存 |
  | C2 | 真冲突时 `--3way`（`t4108:75`） | 冲突标记与未合并 stage，失败退出 |
  | C3 | 前像 blob 不在对象库时 `--3way`；`t4108:40`（不带 `--3way`） | 失败，零写入 |
  | C4 | `--3way --cached`；`--3way --index` | 以 git 实跑为准登记 |

### ADR-LG-08: grep 布尔表达式与函数上下文

- **Status:** Accepted
- **Context:** GAP-15、GAP-16；git `builtin/grep.c:1133-1158`；`t7810:715`、`:736`、`:848`、`:1040`。
- **Decision:**
  1. **表达式：**
     - 由 `-e` 模式、`--and`、`--or`、`--not` 与独立参数 `(`、`)` 组成；
     - 优先级 `--not` > `--and` > 隐式或显式 `--or`；
     - `--all-match` 保持「文件内每个顶层 OR 分支至少命中一次」的 Git 语义；
     - 语法错误为用法错误。
  2. **`-p/--show-function`：**
     - 在匹配行之前输出最近的函数头，前缀为 `<path>=`；
     - 函数头规则先取 `.gitattributes` 的 `diff=<driver>` 与 `diff.<driver>.xfuncname`/`funcname` 配置，否则取 Git 默认规则（以字母、`_` 或 `$` 开头的行）。
     - 该规则与 unified diff hunk 头的函数上下文共用同一实现。
  3. **`-W/--function-context`：** 输出匹配所在函数的完整范围，非匹配行前缀 `-`，函数头前缀 `=`。
  4. **`-<n>`：** 等价于 `-C <n>`；与 `-A/-B/-C` 按后出现者生效。

### ADR-LG-09: grep 模式类型：`--fixed-strings` 长名与 `-P`

- **Status:** Accepted
- **Context:** GAP-14；git `builtin/grep.c:1085-1094`。Libra `grep` 已有 `-E`、`-G`、`-F`（长名为单数 `--fixed-string`）与 `-P` 参数，但 `-P` 在执行时拒绝（`src/command/grep.rs:88-96`、`:359`）；依赖中只有 `regex = "1.12.3"`，不支持环视与反向引用。
- **Decision:**
  1. **`--fixed-strings`：** 作为 `-F` 的正式长名；单数 `--fixed-string` 保留为隐藏别名，不破坏既有调用。
  2. **`-P` 引擎：**
     - `-P/--perl-regexp` 新增 `fancy-regex`（纯 Rust、支持环视与反向引用）依赖实现；
     - 编译时设置回溯上限与模式长度上限，超限为运行期失败并给出模式与原因；
     - 引擎不支持的 PCRE 语法（`\K`、递归、`(*VERB)` 等）为用法错误，并登记为有意差异。
  3. **共享：** grep 与 `log/rev-list --grep`（ADR-LG-02）共用同一「模式类型 → 匹配器」工厂，BRE/ERE 转换与 `-P` 引擎只实现一次。
- **Alternatives considered:**
  - `pcre2` crate——引入 C 库构建依赖，跨平台发布成本高，拒绝；
  - 继续拒绝 `-P`——issue 明确列出，且 `t7810` 相关用例不可移植，拒绝。
- **Consequences:** 新增 `Cargo.toml` 依赖，LG-14 命中 T-1；`deny`/许可证核对纳入该卡。
- **Revisit when:** 需要完整 PCRE 语义。

  **M-GTYPE（LG-14）**

  | 行 | 调用 | 期望（与 git 2.54 一致） |

  | P1 | `grep --fixed-strings foo.bar`；`grep -F foo.bar` | 均只输出 `code.c:  return foo.bar;` |
  | P2 | `grep --fixed-string foo.bar`（旧别名） | 同 P1，且不出现在 `--help` |

  | P4 | `grep -P '(a)\1'`；`grep -P '\Kfoo'` | 前者按反向引用匹配；后者用法错误并说明不支持 |
  | P5 | 灾难性回溯模式 `grep -P '(a+)+$'` 于长输入 | 在回溯上限内失败并给出原因，不挂起 |
  | P6 | `-E`、`-G`、`-w`、`--untracked`、`--no-index`、`--heading --break` 回归 | 与 `report-a.txt` A8 的 git 输出一致 |

### ADR-LG-10: blame 行范围、边界前缀、列宽、日期与增量输出

- **Status:** Accepted
- **Context:** GAP-17、GAP-18；git `builtin/blame.c:466-467`、`:977`、`:991`、`:1236-1237`；`t/annotate-tests.sh:243-271`、`:331`；`t8002:29`、`:120`。
- **Decision:**
  1. **`-L` 范围：**
     - 结束行超出文件时夹取到最后一行；
     - 起始行超出文件为运行期失败（128），文案 `fatal: file <path> has only <n> line(s)`（单复数随 n）；
     - 语法错误仍为用法错误（129）；
     - 多个 `-L` 按 Git 合并输出，以 git 实跑为准。
  2. **边界前缀：**
     - 边界提交（根提交或范围边界）默认输出 `^` 加缩短一位的 hash；
     - `--root` 不把根提交视为边界；`-b` 以空白代替边界 hash；
     - `blame.showRoot`、`blame.blankBoundary` 配置生效；
     - 删除 `src/command/blame.rs:95` 的 no-op 注释与实现。
  3. **列宽：** 作者列（含 `-e` 的邮箱列）按本次输出最长值对齐，与 Git 一致。
  4. **`--date=<format>`：** 复用 log 的日期格式化（`iso`、`iso-strict`、`rfc`、`short`、`relative`、`local`、`raw`、`unix`、`default`、`format:<strftime>`）；未指定时保持 blame 默认的 ISO 风格。
  5. **`--incremental`：** 按 Git 增量格式输出 `<oid> <orig-line> <final-line> <count>`，每个提交首次出现时输出元数据头，随后 `filename`，`previous` 行规则与 porcelain 一致。
- **Alternatives considered:** 保留「范围超出即用法错误」——`t/annotate-tests.sh` 的夹取用例不可移植，拒绝。
- **Consequences:** blame 默认输出因 `^` 前缀变化，既有测试同批更新。
- **Revisit when:** 支持 `--reverse`（DEFER-09）。

  **M-BRANGE（LG-17）、M-BDATE（LG-18）**

  | 行 | 调用 | 期望（与 git 2.54 一致） |
  |---|---|---|
  | L1 | 1 行文件上 `blame -L 1,2 single.txt` | exit 0，输出第 1 行 |
  | L2 | `blame -L 5,9 single.txt` | 128，`fatal: file single.txt has only 1 line` |
  | L3 | `blame -L abc single.txt`（语法错误） | 129，`LBR-CLI-002` |
  | L4 | `t/annotate-tests.sh:243-271`、`:331` | 通过 |
  | L5 | `blame -s m.txt` 中根提交行 | `^` 前缀加 7 位 hash |
  | L6 | `blame --root -s m.txt`；`blame -b -s m.txt`；`-c blame.showRoot=true`、`-c blame.blankBoundary=true` | 以 git 实跑为准登记 |
  | L7 | `blame -e -L 1,1 m.txt`；`t8002:29`、`:120` | `(<t@example.com> 2026-01-03 00:00:00 +0000 1)`，列宽一致 |
  | L8 | 多个 `-L` | 以 git 实跑为准登记 |
  | T1 | `blame --date=iso m.txt`；`--date=short` | `(T 2026-01-03 00:00:00 +0000 1)`；`(T 2026-01-03 1)` |
  | T2 | `--date=relative`、`--date=format:%Y` | 以 git 实跑为准登记（relative 使用固定当前时间注入） |

  | T4 | `--incremental` 与 `--porcelain` 同用 | 以 git 实跑为准登记 |

### ADR-LG-11: blame 移动与复制检测

- **Status:** Accepted
- **Context:** GAP-19；git `builtin/blame.c:1005-1006` 与 `blame.c` 的 move/copy 查找；`t/t8003-blame-corner-cases.sh:51-76`（straight copy/move，无 `-C`、`-C`、`-C -C`）。
- **Decision:**
  1. **`-M[<score>]`：** 在同一文件内检测从父提交移动或复制过来的行块，默认分数为 20 个字母数字字符。
  2. **`-C[<score>]` 的叠加规则：**
     - 一个 `-C`：额外在同一提交修改的其它文件中查找来源；
     - 两个 `-C`：扩展到创建该文件的提交中的任意文件；
     - 三个 `-C`：扩展到任意提交的任意文件；
     - 分数语义与 `-M` 相同。
  3. **实现：** 以行内容指纹索引父提交相关文件，只在无法直接归因的行块上查找，复用 blame 既有的父提交遍历与 `-w` 规范化。
  4. **porcelain：** 输出的 `filename` 为来源文件。
- **Alternatives considered:** 只接受参数而不检测——静默错误，拒绝。
- **Consequences:** `-C -C -C` 成本随历史增长，性能预算见 LG-19。
- **Revisit when:** 需要 `--ignore-rev`/`--ignore-revs-file`（DEFER-09）。

  **M-BMOVE（LG-19）**

  | 行 | 场景（行长 ≥ 20 个字母数字字符的夹具） | 期望（与 git 2.54 一致） |
  |---|---|---|
  | M1 | 同文件内移动行块后 `blame -M -s` | 被移动行归因到原始提交 |
  | M2 | 从同提交修改的另一文件复制行块后 `blame -C -s` | 归因到来源提交，porcelain `filename` 为来源文件 |
  | M3 | 从未在同提交修改的文件复制后 `blame -C -C -s`；`-C -C -C` | 以 git 实跑为准登记 |
  | M4 | `-M` 与 `-w` 组合；自定义分数 `-M40` | 以 git 实跑为准登记 |
  | M5 | 短行（不足分数）的移动 | 不重新归因（与 `report-b.txt` B1 一致） |
  | M6 | `t/t8003-blame-corner-cases.sh:51-76` | 通过 |

### ADR-LG-13: fast-import 选项与输出流

- **Status:** Accepted
- **Context:** GAP-24；git `builtin/fast-import.c:3872`、`:3921-3923`、`:4135-4149`、`:4263`；`t9300:833`、`:2763-2793`。Git 不支持位置参数 `<file>` 与 `--dry-run`（`report-c.txt` C5）。
- **Decision:**
  1. **维持拒绝：** 位置参数与 `--dry-run` 维持用法错误，文档说明 Git 同样不支持。
  2. **`--force`：** 允许非快进的 ref 更新；未给时对非快进更新输出 Git 同样的 warning，其余 ref 正常更新，最终退出码按 Git。
  3. **统计：**
     - `--stats`/`--no-stats` 控制结束时统计，默认开启；`--quiet` 关闭统计；
     - 统计写 stderr，保留 `Total objects`、`blobs`、`trees`、`commits`、`tags` 与 `branches`/`marks` 计数行；
     - Git 的内存分配类行（`Alloc'd objects`、`pools` 等）不输出，登记为有意差异；
     - 现有 stdout 汇总行移入统计块。
  4. **`--big-file-threshold=<n>[k|m|g]`：** 校验并接受；Libra 以松散对象写入，大文件不做 delta，与 Git 语义等价；非法值为用法错误。
  5. **`--done`：** 要求流以 `done` 结束，缺失时报错且不更新 ref；`feature done` 等价。`feature force` 等价 `--force`。
  6. **`progress <text>`：** 输出到 stdout，内容为 `progress <text>`。
- **Alternatives considered:** 实现 `--dry-run`——Git 没有该选项，属于 Libra 扩展且 issue 基于错误前提，拒绝。
- **Consequences:** fast-import stdout 内容变化（汇总行移出），文档与 `COMPATIBILITY.md:232` 登记。
- **Revisit when:** 支持 `--export-marks/--import-marks/--date-format`（DEFER-01）。

  **M-FIMP（LG-24）**

  | 行 | 调用（`directives.fi`：`feature date-format=raw`、`feature done`、blob、commit、`checkpoint`、`progress halfway there`、`done`） | 期望（与 git 2.54 一致） |
  |---|---|---|
  | F1 | `fast-import < directives.fi` | stdout 仅 `progress halfway there`；stderr 为统计块；ref 更新 |
  | F2 | `fast-import --quiet --force < directives.fi` | stdout `progress halfway there`；无统计 |
  | F3 | `--stats --quiet`；`--quiet --stats` | 以 git 实跑为准登记（后者生效） |
  | F4 | 非快进更新无 `--force`；有 `--force`；`t9300:833` | warning 与退出码按 Git；强制更新成功 |
  | F5 | `--done` 且流缺少 `done`；`t9300:2776-2793` | 失败且不更新 ref；上游用例通过 |

| 发布步 `gh release create` 失败 | 已推送的 `main` 提交 | 按 ER-09 记录，下一窗口补 tag/release | blind retry；只推 `main` 就宣称已发布 |
| D 组 `release.yml` 失败 | 已存在的 tag | 前滚修复，发新 patch | 回退已推送提交或删除已发布 artifact |

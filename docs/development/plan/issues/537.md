## 文档职责

本文处理 Issue #537 在当前 `main` 上仍成立的 `cat-file` 与 Git 契约差异。目标：#537 正文与评论中列出、且仍能复现的每一项，要么对齐 Git，要么显式归类为不支持并写进文档；同时给出 #537 引用的上游用例如何复核、哪些用例被其它 issue 阻塞。

### 适用范围

- `libra cat-file` 的以下表面：
  - `<type> <object>` 两位置参数形式（正文场景 1/4/5/8，评论 11–54；同轴吸收 [#1029](https://github.com/libra-tools/libra/issues/1029)）及位置参数个数合同；
  - 共享对象解析器中 `<rev>:./<path>`、`<rev>:../<path>` 的相对 tree path（正文场景 5）；
  - batch 输入成帧：空行、首尾空白、`%(rest)` 切分；
  - `--batch-command` 的输入校验与参数原样传递；
  - `--no-buffer`，以及 `--buffer`/`--batch-all-objects` 的「需要 batch 模式」校验；
  - `-z`/`-Z` NUL 分隔；
  - batch 格式串：`%(objectmode)`、`%%`、未知/未闭合原子的拒绝、`%(deltabase)`/`%(objectsize:disk)` 的显式不支持；
  - `--follow-symlinks`；
  - Git `cat-file` 其余选项（`--textconv`、`--filters`、`--path`、`--use-mailmap`/`--mailmap`、`--filter`、`--allow-unknown-type`、`--unordered` 及其 `--no-*` 形式）的显式分类。
- 对应文档：`docs/commands/cat-file.md`、`docs/commands/zh-CN/cat-file.md`、由同步脚本生成的网站页 `../libra-backend/apps/tanstack-app/content/docs/commands/cat-file.en.md`、开发文档 `docs/development/commands/cat-file.md`、`COMPATIBILITY.md` 第 265 行 `cat-file` 行（原地改写，不增删行）、`docs/error-codes.md` 第 167–173 行的 128 例外说明；CF-03 另改 `docs/commands/rev-parse.md`、`docs/commands/zh-CN/rev-parse.md` 与网站 `rev-parse.en.md`。
- 测试：`tests/command/cat_file_test.rs`（`command_test` 目标），CF-03 另加 `tests/command/rev_parse_test.rs` 一个用例与 `src/utils/util.rs` 内单元测试。

### 非目标

- 不修 `libra commit` 写出的提交对象尾部多一个换行（[#1032](https://github.com/libra-tools/libra/issues/1032)）。它让 t1006 的 commit 大小与 `-p` 输出差 1 字节（TC-3178/3179/3180/3182/3194/3202/3238/3239/3282/3289）；本计划只登记依赖（DEP-CF-02）。
- 不修工作区扫描跟随符号链接导致的 ELOOP（[#1014](https://github.com/libra-tools/libra/issues/1014)）。它让 t1006 的符号链接 setup（`git add` 互指链接）失败，挡住 `--follow-symlinks` 的 20 个上游用例（DEP-CF-01）；CF-09 的测试用 `update-index --cacheinfo` 构造环形链接，不依赖它。
- 不实现 `<rev>^{/<text>}` 中含冒号的切分（[#1055](https://github.com/libra-tools/libra/issues/1055)，TC-3285）、全局 `-C`/`-c`（[#686](https://github.com/libra-tools/libra/issues/686)、[#557](https://github.com/libra-tools/libra/issues/557)）、`rev-parse --git-path`（[#1053](https://github.com/libra-tools/libra/issues/1053)）、`mktag`（[#1052](https://github.com/libra-tools/libra/issues/1052)）、`commit --date` 的 approxidate（[#769](https://github.com/libra-tools/libra/issues/769)，TC-3286 的真实阻塞点）、scissors 清理（[#982](https://github.com/libra-tools/libra/issues/982)）、`replace` 对象（[#758](https://github.com/libra-tools/libra/issues/758)）。这些缺口挡住部分 #537 引用的上游用例；本计划只登记依赖（DEP-CF-04），不把这些用例记为通过。
- 不实现 `%(deltabase)`、`%(objectsize:disk)`、`--textconv`、`--filters`、`--path`、`--use-mailmap`、`--filter`、`--unordered`、`--allow-unknown-type`；CF-08/CF-10 把它们显式归为不支持（DEFER-CF-01..03）。
- 不实现 Git 的双哈希 `compatObjectFormat` 与 `version --build-options`（t1006 的 `RUST` 前置条件，DEFER-CF-05），也不支持 Git 测试专用环境变量 `GIT_TEST_CAT_FILE_NO_FLUSH_ON_EXIT`（DEFER-CF-06）。
- 不让 Libra 读取 `.git/objects`（TC-3281/TC-3185 的根因，ADR-CF-11，DEP-CF-05）。
- 不改 Libra 全局错误输出合同（`Error-Code:` 行与 JSON 行）。上游用例中以 `test_cmp` 比较完整 stderr 的，会继续因这两行失败。
- 计划完成不以关闭 #537 为条件；#537 与 #1029 的关闭条件见 DEP-CF-08。

### 成功定义

- #537 中仍能复现的各项按 Git 处理：
  - `cat-file <type> <object>` 输出原始对象字节，按 Git 规则 peel，并有 Git 的类型与个数诊断；
  - 选项模式缺对象、多对象，batch 模式带位置参数，均以 Git 的诊断失败；
  - `<rev>:./<path>`、`<rev>:../<path>` 按当前目录解析（共享解析器的显式启用选项，`cat-file` 与 `rev-parse` 启用；其它命令 DEFER-CF-10）；
  - batch 不再修剪输入行，空行输出 ` missing`，`%(rest)` 可用；
  - `--batch-command` 的六类输入错误以 `fatal:`、退出 128 结束；
  - `--no-buffer`、`-z`、`-Z`、`--follow-symlinks`、`%(objectmode)` 可用；
  - 未知或未闭合的格式原子被拒绝；其余未实现的 Git 选项与原子以 `LBR-UNSUPPORTED-001` 显式拒绝。
- 每项行为有 `command_test` 中的具名用例；期望字节取自本计划「行为探针」表或与 Libra 既有输出（`-p`、`rev-parse`）同源比较。
- EN、zh-CN、网站页、开发文档、`COMPATIBILITY.md` 第 265 行与实现一致，`--help` 同步。
- 十张实现卡各自完成独立发布切片（ER-08），全部卡 `done` / `complete`，计划收口点 CLOSE-537 全绿。
- CF-11 已把 libra-testcases 维护者公开发布的复跑结果逐行写入本计划，并把 TC-3281 的处置记录在案。

### ADR-CF-02：`<type> <object>` 按 Git `cat_one_file` 的语义

- **Status:** Accepted
- **Context:** Git 在未给 `-e/-p/-t/-s`、batch 等模式时，把两个位置参数解释为 `<type> <object>`（`builtin/cat-file.c` @ 6de20f6092：`:1342-1370` 的参数分派，`:236-283` 的 `case 0`）。探针 #1–#12。
- **Decision:**
  - 位置参数改为列表。无模式选项时：0 个位置参数保持现有 `error: <object> is required for Git object modes`（C 型，GC-CF-05）；1 个或 3 个以上时，U 型拒绝 `only two arguments allowed in <type> <object> mode, not <n>`；2 个时进入类型模式。有 `-e/-p/-t/-s` 时，2 个以上位置参数 U 型拒绝 `too many arguments`。
  - 类型模式先按现有规则解析 `<object>`（失败为既有的 T 型 `Not a valid object name <object>`），再校验 `<type>` 是否为 `blob`、`tree`、`commit`、`tag` 之一（区分大小写；否则 D 型 `invalid object type "<type>"`）。
  - 取对象：`<type>` 为 `blob` 且对象是 tag 时，先按 tag 的 `object` 行取一次目标，若目标是 blob 则输出该 blob；其余情况按 Git `read_object_peeled`：类型相同即输出；是 tag 则取其目标再判；是 commit 而请求 `tree` 则取其树；否则 T 型拒绝 `libra cat-file <object>: bad file`。
  - 成功时 stdout 只有对象的原始字节（与 `--batch` 内容部分相同，树为二进制格式），不加换行。
  - `--json`/`--machine` 下输出 `{"mode":"raw","object":<参数>,"object_type":<type>,"hash":<输出对象的 ID>,"size":<字节数>,"content_base64":<标准 base64>}`（`base64` 0.22 已是依赖，`Cargo.toml:134`）。
- **Alternatives considered:** 把类型模式实现为 `-p` 的别名：树会输出为文本，`commit_body` 之外的脚本（`cat-file tree`）拿到错误字节。JSON 只在 UTF-8 时给 `content`：树与二进制 blob 无法表达。
- **Consequences:** 位置参数结构变化后，选项模式的多对象拒绝必须同卡给出（G-02）。
- **Revisit when:** 无。

### ADR-CF-03：错误分四型，退出码按 Git 的失败来源

- **Status:** Accepted
- **Context:** Git 的 `usage_msg_opt` 系错误退出 129，`die()` 系错误退出 128。Libra 的不可解析名一律 LBR-CLI-003/129（`COMPATIBILITY.md:265` 已登记为与 Git 128 的有意差异）。t1006 的 batch-command 错误用 `test_expect_code 128` 断言（探针 #25）。`ls-files` 已有 `fatal` + LBR-CLI-002 + `with_exit_code(128)` 的先例（探针 #42）。
- **Decision:** 本计划新增或改写的错误按下表构造（GC-CF-05 据此定义门族）：
  - **U 型**（Git `usage_msg_opt`，129）：`CliError::fatal(msg).with_stable_code(StableErrorCode::CliInvalidArguments)`。
  - **D 型**（Git `die()` 针对参数或输入内容，128）：`CliError::fatal(msg).with_stable_code(StableErrorCode::CliInvalidArguments).with_exit_code(128)`。用于类型名非法、batch-command 输入错误、格式串错误。
  - **T 型**（名字解析或 peel 失败）：`CliError::fatal(msg).with_stable_code(StableErrorCode::CliInvalidTarget)`，129，沿用 `Not a valid object name` 的既有合同。
  - **X 型**（显式不支持）：`CliError::failure(msg).with_stable_code(StableErrorCode::Unsupported).with_hint(hint)`，128。
  - **C 型**（既有 `command_usage`，只在 CF-01 作回归）：`error:`、LBR-CLI-002、129。
- **Alternatives considered:** D 型也用 129：t1006 的六个 batch-command 用例无法通过。T 型改 128：改变已发布的 `Not a valid object name` 合同。
- **Consequences:** CF-01 在 `docs/error-codes.md` 第 167–173 行的注后增加一段，说明 `cat-file` 的 D 型错误以 LBR-CLI-002 退出 128；后续 D 型卡只在该段追加消息。
- **Revisit when:** 全局错误输出合同变化。

### ADR-CF-04：相对 tree path 只解析前导 `./` 与 `../`，以共享解析器的选项显式启用

- **Status:** Accepted
- **Context:** Git `object-name.c` 的 `resolve_relative_path` 只处理以 `./` 或 `../` 开头的路径，相对当前目录换算成仓库相对路径，越出工作树时报 `'<p>' is outside repository at '<root>'`；其它位置的 `.`/`..` 分量不被解析（探针 #17–#19）。Libra 的 index path 已按此实现（`util.rs:2808-2830`）。共享解析器的使用者很多（`origin/main` 中调用 `resolve_object_spec_typed`、`resolve_object_spec_with_auto_merge_typed`、`resolve_tree_ish_typed`、`resolve_tree_ish_with_auto_merge_typed` 或 `get_commit_base_typed` 的文件，2026-11-04 `rg -l` 列举：`cat_file.rs`、`rev_parse.rs`、`show.rs`、`ls_tree.rs`、`read_tree.rs`、`check_attr.rs`、`checkout.rs`、`restore.rs`、`reset.rs`、`diff.rs`、`diff/compare.rs`、`log.rs`、`shortlog.rs`、`format_patch.rs`、`rev_list_spec.rs`、`update_ref.rs`、`tag.rs`、`commit.rs`、`describe.rs`），其中接受非提交对象的有 `rev-parse`、`read-tree`（`read_tree.rs:116`）、`diff` 的 tree-ish 参数（`diff.rs:2017`、`diff/compare.rs:1050`）、`check-attr --source`（`check_attr.rs:161`）、`reset` 的树目标（`reset.rs:269`）、`update-ref`（`update_ref.rs:1329`、`:1389`）、`tag`（`tag.rs:878`）、`checkout`（`checkout.rs:681`）；`show` 与 `ls-tree` 另有自己的 `REV:path` 切分与查找（`show.rs:410-415`、`:471-476`；`ls_tree.rs:209-226`；探针中二者对 `HEAD:./x` 报 path 不存在）。共享解析器已有「显式启用」的先例：`AUTO_MERGE` 只经 `resolve_object_spec_with_auto_merge_typed` 投影，以保持其它使用者的拒绝合同（`util.rs:3085-3112`）。
- **Decision:**
  - 把 `resolve_index_path_typed` 中把 `./`/`../` 换算为仓库相对路径的代码（`util.rs:2812-2824`）提取为 `pub(crate) fn repo_relative_spec_path(path_spec: &str) -> Result<String, CommitBaseError>`，index path 与 tree path 共用（index path 行为不变）。
  - 把 `resolve_object_spec_typed` 的 `<rev>:<path>` 切分（`util.rs:3075`）提取为 `pub(crate) fn split_tree_path_spec(name: &str) -> Option<(&str, &str)>`，规则不变（第一个 `:`），供 CF-09 复用。
  - 新增 `pub(crate) struct ObjectSpecOptions { auto_merge: bool, relative_tree_path: bool }` 与 `pub(crate) async fn resolve_object_spec_with_options_typed(name, ObjectSpecOptions)`，作为唯一实现；`resolve_object_spec_typed` 与 `resolve_object_spec_with_auto_merge_typed` 改为以固定选项（`relative_tree_path: false`）调用它，现有使用者行为不变。
  - `relative_tree_path: true` 时，`resolve_tree_path_typed` 在拒绝空、`.`、`..` 分量之前，先对以 `./`/`../` 开头的路径调用 `repo_relative_spec_path`；换算结果为空串时返回树本身。其它 `.`/`..` 分量继续拒绝。`false` 时与今天完全相同。
  - 启用者只有 `cat-file`（`resolve_object_safe`，`cat_file.rs:991`，含 batch 与类型模式）与 `rev-parse`（`rev_parse.rs:431`、`:643`、`:806` 三处全部改用启用入口，使参数分类与解析一致）。
  - 越出工作树或无法换算时，`cat-file` 仍映射为 T 型 `Not a valid object name <spec>`；`rev-parse` 沿用其既有的不可解析诊断。
- **Alternatives considered:** 对全部使用者默认启用（与 Git 一致）：会同时改变 `read-tree`、`diff`、`check-attr`、`reset`、`update-ref`、`tag`、`checkout` 的公开行为，每个都需同卡回归与文档，超出 #537 的范围；`show`/`ls-tree` 还要先改为经共享解析器。只在 `cat-file` 内换算：复制解析逻辑，违反 GC-02。
- **Consequences:** 只有 `cat-file`、`rev-parse` 获得该语法，二者文档同卡更新并写明其它命令暂不支持；其余使用者的启用与 `show`/`ls-tree` 的重复解析登记为 DEFER-CF-10。
- **Revisit when:** DEFER-CF-10 重启；#1055 改切分规则时，只改 `split_tree_path_spec`。

### ADR-CF-05：batch 输入成帧按 Git

- **Status:** Accepted
- **Context:** Git 只去掉行分隔符与紧邻的 `\r`（换行模式），不修剪其它空白；格式串含 `%(rest)` 时，名字取到第一个 ASCII 空格（0x20）或制表符（0x09）为止，随后连续的空格与制表符被跳过（只有这两个字节，`\v` 等其它空白保留），余下字节原样为 rest（`builtin/cat-file.c` @ 6de20f6092 `:1126-1129`；探针 #22–#24、#40d）。
- **Decision:**
  - `--batch`/`--batch-check` 的每行只去掉 `\n` 与紧邻的 `\r`；空行的名字为空串，输出 ` missing`（CF-04）。
  - `%(rest)` 的切分不在 CF-04 做：是否切分由 CF-08 的格式串解析结果决定——只有解析出活动的 `rest` 原子时才切分，`%%(rest)` 这类转义文本不触发（探针 #40b）。CF-04 交付后、CF-08 交付前，整行总是名字（与今天相同，`%(rest)` 仍原样输出）。
  - 名字只在按字节切分（CF-08 的 `%(rest)` 规则；无 `%(rest)` 时为整行）**之后**做 UTF-8 校验：名字部分不是合法 UTF-8 时输出 `<名字原字节> missing`（既有行为）；`rest` 部分的字节不做 UTF-8 校验，原样进入输出（探针 #40e）。
- **Alternatives considered:** 保留修剪：与 Git 和 t1006 的 #185 不符，名字带空白的路径（如 `:white space`）无法查询。
- **Consequences:** 对外行为变化：依赖修剪的调用者需要自行修剪；文档写明。
- **Revisit when:** 无。

### ADR-CF-06：batch-command 的解析按 Git 的命令表

- **Status:** Accepted
- **Context:** Git `batch_objects_command`（`builtin/cat-file.c` @ 6de20f6092 `:928-971`）：空行 `empty command in input`；以空白开头 `whitespace before command: '<行>'`；按前缀匹配命令名，带参数的命令要求紧跟一个空格，否则 `<cmd> requires arguments`；不带参数的命令后有内容则 `<cmd> takes no arguments`；无匹配 `unknown command: '<行>'`；`flush` 只在 `--buffer` 下有效。均为 `die()`，退出 128。参数为单个空格之后的全部内容。
- **Decision:** 按上述规则实现，错误为 D 型（ADR-CF-03），消息与 Git 逐字相同；`contents`、`info`、`flush` 之外的 Git 命令（`mailmap`、`remote-object-info`）按未知命令处理并写入文档（DEFER-CF-03）。错误发生前已处理的行，其响应已按缓冲规则输出。
- **Alternatives considered:** 保留 129：TC-3241–3246 无法通过。
- **Consequences:** 对外行为变化：退出码由 129 改为 128，前缀由 `error:` 改为 `fatal:`。
- **Revisit when:** 支持 `mailmap`/`remote-object-info` 时。

### ADR-CF-07：格式串只有一个解析函数，未支持的原子显式拒绝

- **Status:** Accepted
- **Context:** Git 在开始读输入前解析格式串：`%%` 输出 `%`；`%(` 未闭合 `die("bad cat-file format: element '%s' does not end in ')'")`；未知原子 `die("bad cat-file format: %(%s)")`；`%` 后不是 `(` 或 `%` 则原样输出（探针 #33–#35）。
- **Decision:**
  - CF-08 用一个解析函数替换 `format_batch_line` 的字符串替换，在读取 stdin 之前完成解析（stdin 为空或保持打开而不写入时都立即失败，探针 #40a）。
  - 支持 `objectname`、`objecttype`、`objectsize`、`objectmode`、`rest`。解析结果中含活动的 `rest` 原子时，`--batch`/`--batch-check` 在第一个空格或制表符处切分输入行，只跳过随后连续的空格与制表符，其余字节原样保留（ADR-CF-05）；切分按字节进行，在对名字部分做 UTF-8 校验之前，rest 字节不做 UTF-8 校验；`--batch-command` 不切分，`%(rest)` 展开为空串（探针 #26）。
  - `deltabase` 与 `objectsize:disk` X 型拒绝（DEFER-CF-01）；未知原子与未闭合元素 D 型拒绝，消息与 Git 相同。
  - `%(objectmode)` 取自名字解析的上下文：`<rev>:<path>` 为树项模式，`:<path>` 为 index 项模式，均为 6 位八进制；其它名字为空串。
  - 共享解析器新增 `pub(crate)` 的带上下文变体 `resolve_object_spec_context_typed` 与 `resolve_object_spec_with_auto_merge_context_typed`，返回 `ObjectSpecResolution { id, mode: Option<u32> }`；既有两个函数改为调用它并丢弃 `mode`。
- **Alternatives considered:** 在 `cat-file` 内重新遍历树以取模式：复制解析逻辑，违反 GC-02。实现 `%(deltabase)`/`%(objectsize:disk)`：需要读取 pack 条目头与分层存储的落盘大小，且 TC-3279 依赖 `.git/objects/pack` 布局、TC-3230 依赖 `repack` 的增量选择，收益与成本不成比例。
- **Consequences:** 原样输出未知原子的旧行为消失；文档写明。
- **Revisit when:** DEFER-CF-01 重启。

### ADR-CF-08：`--follow-symlinks` 按 Git 文档

- **Status:** Accepted
- **Context:** Git 文档与 `get_tree_entry_follow_symlinks`：只对 `<tree-ish>:<path>` 名字生效；index 形式（`:<path>`）不跟随；链接相对其所在目录解析；最多跟随 40 次；结果为树内对象时照常输出；目标在树外时输出 `symlink <len>` 与树外路径；目标缺失 `dangling <len>` 与输入名；成环或超限 `loop <len>` 与输入名；路径中途遇到非目录 `notdir <len>` 与输入名；这些形式不受格式串影响，`-Z` 时用 NUL 结尾（探针 #36–#38、#38a）。
- **Decision:**
  - 解析算法（按字节，不做路径规范化；对应 Git `tree-walk.c` @ 6de20f6092 的 `get_tree_entry_follow_symlinks`）：维护「已进入的目录栈」与「待解析字节串」（初值为 `<path>` 的原始字节）。每步从待解析串取出第一个 `/` 之前的分量，并记下其后**是否有** `/`（`has_sep`）与该 `/` 之后的剩余字节（可以为空）：
    - 空分量（`//` 中间）跳过；
    - `..` 弹出一层目录；栈已空时即越出树，输出 `symlink <len>` 与此刻待解析串的原始字节（从这个 `..` 开始，原样保留其中的 `//` 与结尾 `/`）；
    - 其它分量（包括 `.`，**不**做特殊处理）按名字在当前目录查找：找不到时，若此前尚未跟随过任何链接则输出普通的 `<输入名> missing`，否则输出 `dangling <len>` 与输入名；找到目录则进入并继续；找到普通文件时，`has_sep` 为真（如 `HEAD:samelink/` 跟随后的 `hello/`）输出 `notdir <len>` 与输入名，否则它就是结果；
    - 找到链接时计数加一，第 41 次（超过 40 次）输出 `loop <len>` 与输入名；相对链接把待解析串替换为「链接文本 + （`has_sep` 为真时）`/` + 剩余字节」，并从链接所在目录继续；绝对链接文本（以 `/` 开头）直接输出 `symlink <len>` 与链接文本本身，丢弃剩余部分。
    - `<len>` 为随后输出那一行的字节数。探针 #36–#38、#38a–#38c 的各例均按此推导。
  - 按上述规则在 `cat_file.rs` 实现，复用 `util::split_tree_path_spec`、`util::repo_relative_spec_path`（CF-03）与既有的 tree-ish 解析和对象读取。
  - 不访问工作区文件系统。
  - 适用于 `--batch`、`--batch-check`、`--batch-command`。
  - `--no-follow-symlinks` 取消之前的 `--follow-symlinks`；单独的 `--no-follow-symlinks` 不触发 batch 前置条件（探针 #38）。
  - 无 batch 模式时给出 `--follow-symlinks`，U 型拒绝 `'--follow-symlinks' requires a batch mode`。
- **Alternatives considered:** 依赖工作区中的真实符号链接：受 #1014 影响，且与 Git 只看对象树的语义不同。
- **Consequences:** t1006 的符号链接用例仍要等 #1014（DEP-CF-01）。
- **Revisit when:** 无。

### ADR-CF-09：其余 Git 选项显式分类

- **Status:** Accepted
- **Context:** Git `cat-file` 选项表（`builtin/cat-file.c` @ 6de20f6092 `:1211-1258`）中 Libra 未实现的有 `--textconv`、`--filters`、`--path`、`--use-mailmap`/`--mailmap`、`--filter`、`--allow-unknown-type`、`--unordered`。它们今天只得到 clap 的 `unexpected argument`（探针 #39–#40）。
- **Decision:** 这些选项（含 `--path=<p>`、`--filter=<spec>` 的值形式）以 X 型拒绝，在任何其它校验与读取 stdin 之前报出；消息 `option '<选项>' is not supported by libra cat-file`，提示固定为 `see the cat-file row of COMPATIBILITY.md for the supported option set`。只选择 Git 默认行为的否定形式（`--no-use-mailmap`、`--no-mailmap`、`--no-unordered`、`--no-filter`、`--no-path`、`--no-allow-unknown-type`，探针 #40）作为无操作接受；`--textconv`/`--filters` 在 Git 中没有否定形式，不接受。这些选项在 `--help` 中隐藏。
- **Alternatives considered:** 继续让 clap 报错：用户分不清「拼错」与「不支持」。把 `--unordered` 当无操作接受：会让依赖其性能语义的脚本误以为生效；在 DEFER-CF-03 重启时再接受。
- **Consequences:** 选项面完整：Git 的每个 `cat-file` 选项要么支持，要么显式拒绝。
- **Revisit when:** DEFER-CF-02/03 重启。

## 全局工程约束

本计划完整继承模板 GC-01..GC-13，另加以下约束：

- **GC-CF-01 单一事实源：** 名字解析只经 `util::resolve_object_spec_*`；`<rev>:<path>` 切分只经 `util::split_tree_path_spec`，相对路径换算只经 `util::repo_relative_spec_path`（CF-03 提取）；模式上下文只经 `util::resolve_object_spec_*_context_typed`（CF-08 新增）；格式串只经 CF-08 的单一解析函数；batch 的「名字 → 输出字节」只经 `build_batch_object`（各卡扩展其参数，不另写一份）。
- **GC-CF-02 输出前校验：** 参数、格式串、选项组合的校验都在读取 stdin、写 stdout 之前完成。batch-command 的输入错误发生在读到该行时：之前各行的响应已按缓冲规则输出，出错行不产生任何输出。`cat-file` 没有产品写路径（探针 #42：只有对象库打开时的代际锁文件变化），因此拒绝门族不设文件快照门。
- **GC-CF-03 零命中守卫：** Verification 中凡标「零命中」的命令，都在 `bash` 中先定义下列函数再调用。该函数按模板对 `rg` 退出码三分支判定（2026-11-04 在 `bash -e` 与 `zsh -e` 下验证三条分支）：

  ```bash
  zero_hits() {
    pattern="$1"; shift
    if rg -n -- "$pattern" "$@"; then
      echo "FAIL: forbidden pattern found"; return 1
    else
      rc=$?
      if [ "$rc" -ne 1 ]; then echo "ERROR: rg failed with exit $rc"; return "$rc"; fi
      echo "OK: zero hits"
    fi
  }
  ```

- **GC-CF-04 测试隔离与夹具：**
  - 新用例全部用 `tempdir()` 仓库与显式 cwd，经子进程运行构建产物 `libra`；环境变量只给子进程设置，不改测试进程环境，因此不需要 `#[serial(env)]`。子进程的 `HOME`、`XDG_CONFIG_HOME`、`LIBRA_CONFIG_GLOBAL_DB`、`LIBRA_CONFIG_SYSTEM_DB` 指向该用例的临时目录（GC-13）。
  - **F1**（CF-01 在 `tests/command/cat_file_test.rs` 新增构造函数 `cf_f1_repo()`，后续卡复用）：`libra init`；`config user.name T`、`config user.email t@e`；写 `hello`（`Hello World`，无换行）、`first.t`（`first\n`）、`sub/x`（`x\n`）、`commit is`（`is\n`）并 `add`；写 `path with spaces`（`Hello World`，无换行）后 `update-index --add --chmod=+x "path with spaces"`；`commit -m Initial`；`tag Initial`、`tag first`、`tag -a -m 'annotated msg' ann`；给 `first.t` 追加 `two\n`，`add first.t`，`commit -m second`；用 `hash-object -t tag -w --stdin` 写入指向 `HEAD:hello` 的 tag 对象（内容 `object <oid>\ntype blob\ntag bt\ntagger T <t@e> 1700000000 +0000\n\nblob tag\n`），其 ID 记为 `TAGBLOB`。
  - **F2**（CF-09 新增 `cf_f2_repo()`）：在 F1 上以 `ln -s` 加 `add` 建 `samelink -> hello`、`link2 -> samelink`、`dirlink -> sub`、`broken -> missing`、`outlink -> ../outside`、`abslink -> /etc/passwd`、`sub/uplink -> ../hello`、`sub/escape -> ../../escape`、`sub/escdir -> ../../`、`updown -> sub/../../hello` 并提交 `links`（这些链接都不成环、链长不超过 2，工作区扫描可正常处理；2026-11-04 在 Libra 0.30.129 上 `add`/`commit` 成功）。随后**只在 index 中**加入：互指链接 `loop1 -> loop2`、`loop2 -> loop1`，以及链 `c1 -> c2`、…、`c44 -> c45`、`c45 -> hello`（共 45 个链接；在工作区创建会让操作系统的 `stat` 报 ELOOP，即 #1014 的失败面）——每个链接文本经 `hash-object -w --stdin` 写成 blob，再以 `update-index --add --cacheinfo 120000,<oid>,<path>` 加入 index（探针 #41），最后 `write-tree`，其树 ID 记为 `LINKTREE`；不提交、不在工作区创建这些链接。
  - **F3**（CF-07 新增 `cf_f3_tree()`）：在 F1 中以 `hash-object -w --stdin`（空输入）写空 blob，再 `update-index --add --cacheinfo "100644,<空 blob>,newline<LF>embedded"`（路径含一个换行，探针 #40c）并 `write-tree`，其树 ID 记为 `NLTREE`（不提交；每个用例各自新建仓库）。
  - 「stdout 等于 `-p <x>` 的字节」类判据，先在同一夹具中运行 `libra cat-file -p <x>` 取期望字节（ADR-CF-10）。
- **GC-CF-05 拒绝门族：** 本计划每条新增或新可达的失败路径都按下表展开成一组门。每个门是一个独立命名的测试函数，只断言一个谓词，计入所在卡的 G-03 分子（由 EX-CF-01 承载超限）。测试函数由 CF-01 在 `tests/command/cat_file_test.rs` 新增的模块内宏 `cat_file_refusal_gates!` 生成（不导出），命名为 `<卡前缀>_<拒绝名>__<后缀>`，完整路径 `command::cat_file_test::<名>`（`tests/command_test.rs` 以 `mod command` 挂载 `tests/command/mod.rs`）。单门执行命令一律为 `source .env.test && cargo nextest run --test command_test --no-tests=fail -E 'test(=command::cat_file_test::<名>)'`（零匹配即失败）。每条拒绝在卡内表格给出 argv 与 stdin 字节；`--json`、`--machine` 门在 argv 前插入对应全局参数，stdin 相同。
  - **U 型 / D 型 / T 型 / C 型**（ADR-CF-03）：7 个门：
    - `__msg`：stderr 第 1 行等于 `fatal: <msg>`（C 型为 `error: <msg>`）；
    - `__code`：stderr 第 2 行等于 `Error-Code: LBR-CLI-002`（T 型为 `LBR-CLI-003`）；
    - `__exit`：退出码为 129（D 型为 128）；
    - `__stdout`：stdout 为 0 字节；
    - `__json`：以 `--json` 重跑，stderr 解析出的对象等于 `{"ok":false,"error_code":<码>,"category":"cli","exit_code":<退出码>,"severity":<"fatal"，C 型为 "error">,"message":<msg>}`（无 `hints` 键）；
    - `__machine_lines`：以 `--machine` 重跑，stderr 恰为一行；
    - `__machine_json`：同一次 `--machine` 运行，该行解析出的对象与 `__json` 的期望对象相等。
  - **batch 修饰（`b`）：** argv 含 batch 模式（`--batch`、`--batch-check`、`--batch-command`）、且拒绝依据是参数或格式串而非输入内容的拒绝，在卡内拒绝表的「型」列标 `Ub`/`Db`/`Xb`，基础门的 stdin 为卡内表格给出的非空内容（未写明时为 `HEAD\n`），另加 2 个门：`__open_stdin`——以相同 argv 启动子进程，stdin 为保持打开、不写入任何字节的管道，进程在 10 秒内退出且退出码等于该型的退出码（超时即杀进程并判失败）；`__eof_stdin`——stdin 为立即关闭的空输入，退出码等于该型的退出码。二者证明校验发生在读取输入之前（GC-CF-02），既不等待输入，也不因空输入而走成功路径。
  - **X 型**（ADR-CF-03）：8 个门：后缀同上，另加 `__hint`；`__msg` 期望 `error: <msg>`，`__code` 期望 `Error-Code: LBR-UNSUPPORTED-001`，`__exit` 期望 128，JSON 期望 `{"ok":false,"error_code":"LBR-UNSUPPORTED-001","category":"internal","exit_code":128,"severity":"error","message":<msg>,"hints":[<hint>]}`；`__hint`：人读 stderr 中恰有一行等于 `Hint: <hint>`。
  - **门集合核对（shell 门）：** 每张含门族的卡另有一个「门集合相等」门。它是 shell 门，不是 Rust 测试：在仓库根目录新开 `bash -euo pipefail` 进程，先定义下列函数，再执行卡内给出的 `gate_set …` 调用，退出 0 即通过。期望集合只含测试门，不含门集合门本身；集合为空、列举失败或集合不等都非 0 退出。本门只断言「集合相等」一个谓词，计 1 项。

    ```bash
    source .env.test
    gates_r() { for id in "$@"; do for x in msg code exit stdout json machine_lines machine_json; do echo "${id}__${x}"; done; done; }
    gates_x() { for id in "$@"; do for x in msg code exit stdout json machine_lines machine_json hint; do echo "${id}__${x}"; done; done; }
    gates_rb() { for id in "$@"; do for x in msg code exit stdout json machine_lines machine_json open_stdin eof_stdin; do echo "${id}__${x}"; done; done; }
    gates_xb() { for id in "$@"; do for x in msg code exit stdout json machine_lines machine_json hint open_stdin eof_stdin; do echo "${id}__${x}"; done; done; }
    gate_set() {
      local prefix="$1"; shift
      test "$#" -gt 0
      local listing actual expected
      listing="$(cargo test --test command_test -- --list "command::cat_file_test::${prefix}")"
      actual="$(printf '%s\n' "$listing" | sed -n 's/: test$//p' | sort)"
      expected="$(printf 'command::cat_file_test::%s\n' "$@" | sort)"
      test -n "$actual"
      test "$actual" = "$expected"
    }
    gate_set_lib() {
      local module="$1" prefix="$2"; shift 2
      test "$#" -gt 0
      local listing actual expected
      listing="$(cargo test --lib -- --list "${module}${prefix}")"
      actual="$(printf '%s\n' "$listing" | sed -n 's/: test$//p' | sort)"
      expected="$(printf "${module}%s\n" "$@" | sort)"
      test -n "$actual"
      test "$actual" = "$expected"
    }
    ```

  - **单元门：** 新增选项的解析与新增的纯函数（NUL 记录读取、格式串解析、符号链接分量切分）各有 `#[cfg(test)]` 单元测试门，位于 `src/command/cat_file.rs` 的 `tests` 模块（完整名 `command::cat_file::tests::<名>`）或 `src/utils/util.rs` 的 `test` 模块（`utils::util::test::<名>`），单门命令为 `source .env.test && cargo nextest run --lib --no-tests=fail -E 'test(=<完整名>)'`；每个单元门只断言一个输入的一个谓词；其清单由卡内的 `gate_set_lib` 调用确认，不进 `gate_set`（该函数只列举 `command_test`）。
  - **拒绝回归门：** 断言一条既有拒绝保持不变（例如未启用相对 tree path 的命令）：测试先断言退出码不为 0（前置条件），再断言 stderr 第 1 行等于给定的既有消息，计 1 项。
  - **成功门：** 只断言一个谓词（「stdout 逐字节等于给定字面量或同源输出」「退出码为 0」之类）；命令须退出 0 是测试前置条件，若 AC 单独要求退出码，则另计一门。

## 文档职责

本文解决 issue #486：`libra status` 与 `libra branch -vv` 报告的 upstream ahead/behind 计数错误。只要本地分支与 upstream 共享历史且两者不相等，计数就会失真：upstream 是本地的直接祖先时仍报告 `behind N`，本地落后时报告大量虚假的 `ahead`，真正分叉时两侧都偏大。目标是用单一、可证明正确的 commit 图算法替换 `src/command/status.rs::compute_ahead_behind`，让所有渲染器输出与 `rev-list --left-right --count` 及 Git 一致的计数。

本文只规划任务，不宣称实现完成。落地时必须先刷新源码锚点，再按任务卡验收。

### 适用范围

- ahead/behind 计数算法：新增 `src/internal/merge_base.rs::ahead_behind`，与 merge-base 共用 commit 图遍历核心。
- 消费者：`status` 的 `--short --branch` / porcelain v1、porcelain v2 的 `# branch.ab`、长格式 tracking 句子、`--json` 的 `upstream` 对象，以及 `branch -vv` 的 tracking 段。
- 计数不可得的形态（shallow 边界、缺失 commit 对象、unborn 分支）的输出契约。
- status 冻结 warning schema 新增 `upstream_counts_unavailable`（source `metadata`）：计数不可得的原因只经本次调用的结构化 warning 列表交付（ADR-AB-03）。
- 同步：`docs/commands/status.md`、`docs/commands/branch.md` EN + zh-CN，`docs/development/commands/{status,branch}.md`，`COMPATIBILITY.md` 的 `status`/`branch` 行，以及 `../libra-backend` 网站文档。

### 非目标

- commit-graph generation 读取器与基于 generation 的提前终止（DEFER-01）。
- `--no-ahead-behind` 跳过遍历（Git `AHEAD_BEHIND_QUICK` 的 `[different]`）以及 JSON 契约调整（DEFER-02）。
- 把 `rev-list --left-right --count` 与 `log A...B` 迁移到新 helper（DEFER-03）。
- 长格式 tracking 句子的措辞对齐（如 Git 的 “and can be fast-forwarded” 与 pull hint，DEFER-04）。
- 让 `merge_bases` / `is_ancestor` 感知 shallow 边界（DEFER-05）。

### 成功定义

- issue 复现形态：upstream 是本地的直接父提交时，`status --short --branch` 输出 `## main...origin/main [ahead 1]`，porcelain v2 为 `# branch.ab +1 -0`，JSON 为 `ahead: 1, behind: 0`，`branch -vv` 为 `[origin/main: ahead 1]`。
- 落后、分叉、相等、含 merge 的历史，其计数与 `libra rev-list --left-right --count <upstream>...HEAD` 及 git 2.54 一致。
- 计数不可得时不再输出虚假数字：porcelain v2 省略 `# branch.ab`，JSON 为 `null`，并以调用级结构化 warning `upstream_counts_unavailable` 说明原因（文本 stderr、JSON `data.warnings[]`、退出码 9 仲裁）。
- 仓库中只剩一个 ahead/behind 实现；merge-base 既有行为与性能上界不变。
- 本卡完成 C 组发布（`patch + 1`；在已验证 `HEAD` 上推送 tag `v0.22.31`，由该 tag 推送触发 `release.yml`；`gh release create v0.22.31 -R libra-tools/libra --verify-tag` 只创建 Release 元数据）并取得 D 组证据，然后全量收口门全绿，本计划才可标记完成。

## 已决议设计决策

实现时若需偏离本节，必须先修改计划并说明原因，不得在代码中静默改语义。

### ADR-AB-01: 复用 merge-base 的标记遍历实现 ahead/behind

- **Status:** Accepted
- **Context:** GAP-01/02。`paint_down_to_common_many` 已按「每个 commit 在获得新标记时才重新入队」遍历到不动点，排空后每个被访问 commit 的 `lhs`/`rhs` 标记恰为其对两个 tip 的可达性。它只返回候选集，没有暴露最终标记。
- **Decision:**
  1. 把遍历循环提取为模块私有的共享核心，返回最终 `painted` 表与 `WalkStats`；`paint_down_to_common_many` 改为该核心的薄包装，行为不变。
  2. 新增 `pub fn ahead_behind(local: &ObjectHash, upstream: &ObjectHash, boundaries: &HashSet<ObjectHash>) -> Result<AheadBehind, MergeBaseError>`：`local == upstream` 返回 `(0, 0)`；否则排空遍历，`ahead` = 只带 `lhs` 的 commit 数，`behind` = 只带 `rhs` 的 commit 数。
  3. 终止方式保持保守（排空队列），读取上界沿用 `3 × (commits + edges)`。
  4. 提供 `ahead_behind_with<S: CommitSource>` 供 `TestGraph` 测试。
- **Alternatives considered:**
  - 修补交替 BFS——commonness 传播需要重新入队语义，最终就是本方案，且会留下第二份实现。
  - 两个完整可达集合求差——内存 O(history) × 2，且与 merge-base 重复。
  - 按提交日期提前终止（Git 旧式 `everybody_uninteresting` 启发式）——无 generation 读取器时日期偏斜会导致错计，与 `merge_base.rs:25-29` 的既定结论冲突。
- **Consequences:** status 在不相等时遍历两侧可达历史的并集；该成本与缺陷实现在「ahead」形态下相当。提前终止记为 DEFER-01。
- **Revisit when:** commit-graph generation 读取器落地。

### ADR-AB-02: shallow 边界与缺失对象

- **Status:** Accepted
- **Context:** GAP-03。shallow clone 的边界 commit 父对象本就不存在；tiered 离线读取策略或损坏也会导致 commit 不可读。
- **Decision:**
  1. 调用方经 `fetch::read_shallow_boundaries()` 读取边界，并传给 `ahead_behind`；边界 commit 在遍历中视为无父提交（与 Git shallow graft 一致）。
  2. shallow 文件读取失败（例如该路径不是可读文件）、含非法对象 id 的行，或遍历中非边界 commit 读取失败（`MergeBaseError::Load`）时，计数为「不可得」（ADR-AB-03），不猜测数字。Git 对非法 shallow 行直接 `fatal: bad shallow line`；Libra 保持 status 成功、只省略计数，这是有意差异（理由见 Alternatives）。
  3. 边界感知只存在于 `ahead_behind` 使用的 `CommitSource` 包装中，不改变 `merge_bases` 等既有 API（DEFER-05）。
  4. 边界 commit 的父提交即使仍在本地可读，也按根处理（与 Git shallow graft 一致；git 2.54 实测见事实基线「外部参照（shallow / unborn）」）。
  5. commit 读取沿用对象存储既有读取策略：`offline`/`local` 下远端层 commit 不可得即计数不可得；默认 `auto` 下 `Commit::try_load` 可按既有策略回退远端层。本卡不新增远端读取路径，也不改变读取策略。
- **Alternatives considered:** status 在缺失对象时整体失败——会让 tiered 离线仓库和部分损坏仓库连 status 都无法运行，而计数只是附加信息，拒绝。继续静默截断——输出看似可信的错误数字，拒绝。
- **Consequences:** status 需要一次 shallow 文件读取（不存在时为空集）。
- **Revisit when:** DEFER-05 被排期。

### ADR-AB-03: 计数不可得时的输出契约

- **Status:** Accepted
- **Context:** GAP-04。`UpstreamInfo.ahead/behind` 为 `Option`，但短格式与 porcelain v2 把 `None` 当 0。Git porcelain v2 只在「upstream 已设置且 commit 存在」时输出 `# branch.ab`。
- **Decision:** 当 `gone == false` 且计数为 `None`（unborn 分支，或 ADR-AB-02 的不可得）时：
  - 短格式 / porcelain v1：`## <branch>...<upstream>`，不带括号；
  - porcelain v2：输出 `# branch.upstream`，省略 `# branch.ab`；
  - 长格式：不输出 tracking 句子（沿用 `status.rs:4393-4400`）；
  - JSON：`ahead`/`behind` 为 `null`，`gone: false`；
  - `branch -vv`：输出 `[<upstream>]`。
  - 仅「不可得」情形（非 unborn）发出 warning，消息为 `cannot count commits ahead/behind '<upstream>': <原因>`：
    - `status`：新增冻结 code `upstream_counts_unavailable`（discriminant 15，`source()` 为 `metadata`）。`resolve_upstream_info` 把它追加到**本次调用**的 warning 列表；全量收集 `collect_status_data` 与 dirty-cache 收集 `run_status_cache_mode` 两条路径都经此入口。因此它与其它 status warning 同路交付：文本模式打印到 stderr；`--json` 进入 `data.warnings[]` 且 stderr 保持干净；参与 `--exit-code-on-warning` 的退出码 9 仲裁。嵌入式 API `collect_status_json_envelope_for_api` 只把它放进返回的 envelope，不触碰进程级 warning tracker（`InvocationWarningCtx` 契约）。该 code 与 rename 检测无关：不置位 `rename_scan_blocked`，不影响 `rename_detection_complete`。
    - `branch -vv`：纯文本 CLI 面，没有结构化 warning 列表，经 `utils::error::emit_warning` 发出同一消息（stderr 与进程级退出码仲裁；M-UNKNOWN U2 判定 stderr 与 `--exit-code-on-warning` exit 9）。
  - unborn 分支的短格式为 `## <branch>...<upstream>`。Git 此时输出 `## No commits yet on <branch>...<upstream> [gone]`（git@1630431f32 `wt-status.c:2211-2245`：unborn 本地 ref 让 tracking 统计失败，被当作 gone）。Libra 不把已存在的 upstream ref 报告为 gone，本卡也不改动既有 unborn 标题前缀，记为有意差异（DEFER-06），由 M-UNKNOWN U3 固定。
- **Alternatives considered:**
  - 新增 `[unknown]` 文本标记——偏离 Git porcelain，脚本难以兼容，拒绝。
  - status 经进程级 `emit_warning` 发 warning——违反调用级 warning 契约：JSON/API 收集会丢失或串扰 warning，并破坏退出码仲裁，拒绝（R1 P1）。
  - 复用 `metadata_unavailable`——其文档语义是「rename inexact 候选被跳过」，且计入 `rename_detection_complete`，会误报 rename 不完整，拒绝。
  - shallow 文件非法时像 Git 一样让 status 失败——计数只是附加信息，与 ADR-AB-02 的「不因计数失败而整体失败」一致地降级为不可得，拒绝。
- **Consequences:** porcelain v2 在 unborn 分支上不再输出虚假的 `+0 -0`。这是契约修正，必须写入 EN/zh 文档、`COMPATIBILITY.md` 与 dev 文档。冻结 warning schema 追加一个 code，须同批更新 `status_wave0_test` 的 schema 快照（名称与 discriminant）以及 EN/zh warning 表（`compat_r0_9_doc_closeout` 守卫）。
- **Revisit when:** 需要在文本输出中区分「不可得」与「相等」。

#!/bin/bash
# GATE-AB-PERF (#486, ER-AB-02): on a >= 3000-commit R1 fixture (local one
# commit ahead of origin/main), the median of 3 `status --short --branch` runs
# of NEW_LIBRA must be <= 1.5x OLD_LIBRA's, and NEW_LIBRA must report [ahead 1].

: "${OLD_LIBRA:?set OLD_LIBRA to the pre-change release binary}"
: "${NEW_LIBRA:?set NEW_LIBRA to the release binary built from this card}"
# Resolve both binaries before leaving the caller's directory.
abs_exe() {
  case "$1" in
    /*) printf '%s\n' "$1" ;;
    */*) printf '%s/%s\n' "$(cd "$(dirname "$1")" && pwd)" "$(basename "$1")" ;;
    *) command -v "$1" ;;
  esac
}
OLD_LIBRA=$(abs_exe "$OLD_LIBRA") && NEW_LIBRA=$(abs_exe "$NEW_LIBRA") || { echo "FAIL: cannot resolve binaries"; exit 2; }
[ -x "$OLD_LIBRA" ] && [ -x "$NEW_LIBRA" ] || { echo "FAIL: OLD_LIBRA/NEW_LIBRA must be executable"; exit 2; }
N=${N:-3200}
case "$N" in ''|*[!0-9]*) echo "FAIL: N must be a non-negative integer"; exit 2 ;; esac
[ "$N" -ge 3000 ] || { echo "FAIL: N must be >= 3000 (got $N)"; exit 2; }
W=$(mktemp -d "${LIBRA_TEST_SCRATCH_DIR:-${TMPDIR:-/tmp}}/ab-perf.XXXXXX") || exit 2
[ -n "$W" ] && [ -d "$W" ] || exit 2
trap 'rm -rf -- "$W"' EXIT

{
  for i in $(seq 1 "$((N + 1))"); do
    ts=$((1700000000 + i * 60)); msg="c$i"
    printf 'blob\nmark :%d\ndata %d\n%s\n\n' $((i * 2 - 1)) $((${#i} + 1)) "$i"
    printf 'commit refs/heads/main\nmark :%d\n' $((i * 2))
    printf 'author T <t@example.com> %d +0000\ncommitter T <t@example.com> %d +0000\n' "$ts" "$ts"
    printf 'data %d\n%s\n' $((${#msg} + 1)) "$msg"
    [ "$i" -gt 1 ] && printf 'from :%d\n' $(((i - 1) * 2))
    printf 'M 100644 :%d f.txt\n\n' $((i * 2 - 1))
  done
} > "$W/stream.fi"
mkdir "$W/B" && cd "$W/B"
"$NEW_LIBRA" init --quiet </dev/null
"$NEW_LIBRA" fast-import --quiet --input "$W/stream.fi" </dev/null
"$NEW_LIBRA" reset --hard HEAD </dev/null >/dev/null

echo "ok   NEW_LIBRA reports [$line]"
echo "info OLD_LIBRA reports [$("$OLD_LIBRA" status --short --branch </dev/null | head -1)]"

  for _ in 1 2 3; do
    perl -MTime::HiRes=time -e 'my $t = time; open(STDOUT, ">", "/dev/null"); open(STDIN, "<", "/dev/null"); system(@ARGV) == 0 or die "run failed"; printf STDERR "%.4f\n", time - $t' "$1" status --short --branch
  done 2>&1 | sort -n | sed -n 2p
}
old=$(median "$OLD_LIBRA"); new=$(median "$NEW_LIBRA")
echo "info commits=$((N + 1)) old_median=${old}s new_median=${new}s"
if perl -e 'exit(($ARGV[1] <= 1.5 * $ARGV[0]) ? 0 : 1)' "$old" "$new"; then
  echo "GATE-AB-PERF: PASS"
else
  echo "GATE-AB-PERF: FAIL (new > 1.5x old)"; exit 1
fi

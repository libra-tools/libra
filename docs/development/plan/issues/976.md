# Issue #976：`fetch` 必须把命令行 refspec 记为可合并候选（2026-11-12）

> 模板 v2.16。[Issue #976](https://github.com/libra-tools/libra/issues/976) OPEN。仅规划，未授权执行；`I976-01` 为 `pending` / Acceptance 空。Git 对照 pin `6de20f6092dcf9bdb1c8efe03db4b70c82b423dd`。基线 `Cargo.toml` `0.30.173`（`Cargo.toml:3`）；实测 system `libra 0.30.173`。测试用例仓 `/mnt/gitmono/libra-testcases` 本计划不修改。

## 文档职责

### 适用范围

`libra fetch <remote> <refspec>` 写出的 `FETCH_HEAD` 行语义：命令行显式给出的 refspec（`git fetch . left`、`git fetch origin main`）必须写成 Git 的**可合并候选**行（第二个字段为空），而 `--all`、配置 `remote.<name>.fetch` 展开、tag 自动跟随产生的行继续保持 `not-for-merge`。覆盖 `format_fetch_head` 的行渲染、`FetchHeadRecord` 的候选标记、`FETCH_HEAD` 伪引用的解析投影（`src/internal/pseudo_ref.rs`），以及 `merge FETCH_HEAD` 与 `fmt-merge-msg`（`issues/975.md`）读该文件的前置可用性。

### 非目标

不实现 `merge` 的 `FETCH_HEAD` 多候选选择策略变更（`merge FETCH_HEAD` 仍取首个可合并行）。不改变 remote-tracking ref 的更新/裁剪语义、`--refmap` 映射、`--depth`、tag 策略（`--tags`/`--no-tags`/自动跟随）与 `--append` 语义。不修改 `.git` 兼容 shim，不修改测试用例仓。不实现 `issues/975.md` 的 `fmt-merge-msg` 命令本身。

### 成功定义

- `libra fetch . left` 写出的 `FETCH_HEAD` 中，`left` 对应行第二个字段为空（可合并候选）。
- 同一文件里由配置 refspec 或 `--all` 展开产生的行仍为 `not-for-merge`。
- `with_explicit_refspec(...)` 校验结果（`format_fetch_head`）在显式/非显式两类输入上分别逐字断言。
- `FETCH_HEAD` 伪引用解析在存在可合并行时返回该行；无该行时保持既有回退语义。
- `merge FETCH_HEAD` 在有可合并候选时不再因「无可合并行」失败；`fmt-merge-msg` 的输入前置（`issues/975.md` 的 `DEFER-I975-03`，该 DEFER 定义在 975 侧）解除。
- 既有 `--all`/配置 refspec 行渲染与 `FETCH_HEAD` 回退行为零回归。

## 已决议设计决策

### ADR-I976-01：只有命令行显式 refspec 成为可合并候选

- **Status:** Accepted
- **Context:** `src/command/fetch.rs:679-681` 的 `FetchArgs::refspec` 是唯一「用户显式点名」入口；`--all` 与配置 refspec 展开是批量面。Git 对前者写可合并行、对后者写 `not-for-merge`。
- **Decision:** 新增 `FetchHeadRecord::merge_candidate: bool`，在 `src/command/fetch.rs:2799-2811` 的记录构造处按「该记录来源是否为命令行 refspec」赋值；`format_fetch_head` 对 `merge_candidate == true` 的行输出空第二字段（`"{oid}\t\t{desc}"`），否则维持 `not-for-merge`。
- **Alternatives considered:** 在 `format_fetch_head` 里比较 ref 名（易与真实分支名撞车）；让所有行都可合并（破坏 `--all` 语义与既有回退）。
- **Consequences:** tag 跟随与 `--all` 行形态不变；`FETCH_HEAD` 伪引用对新文件优先返回可合并行（已是既有解析逻辑）。
- **Revisit when:** Git 改变 `FETCH_HEAD` 候选规则（例如 `--no-write-fetch-head` 交互）。

### ADR-I976-02：标记随记录传递，渲染层不做来源推断

- **Status:** Accepted
- **Context:** `FetchHeadRecord`（`src/command/fetch.rs:890-893`）是渲染的唯一输入。
- **Decision:** 候选性是记录属性，不在 `format_fetch_head` 内二次推断；单元测试直接构造记录断言渲染结果，覆盖两种取值。
- **Alternatives considered:** 渲染层读取 `FetchArgs`（会把 CLI 与 I/O 层耦合）。
- **Consequences:** 渲染可纯函数测试。
- **Revisit when:** 出现第二个 `FETCH_HEAD` 写入方。

### ADR-I976-03：既有「全部 not-for-merge」测试同批改写，不留矛盾断言

- **Status:** Accepted
- **Context:** `src/command/fetch.rs:6312` 的 `format_fetch_head_marks_every_ref_not_for_merge` 与目标语义直接冲突。
- **Decision:** 同批把该测试改名为 `format_fetch_head_marks_config_refs_not_for_merge` 并保留 `not-for-merge` 断言（构造 `merge_candidate=false` 记录），另加可合并行测试；不删除覆盖，只校正前提。
- **Alternatives considered:** 保留旧测试并放宽断言（会失去对 `--all` 面的保护）。
- **Consequences:** `--all`/配置面仍有逐字断言。
- **Revisit when:** N/A。

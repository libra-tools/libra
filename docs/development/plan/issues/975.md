> 模板 v2.16。[Issue #975](https://github.com/libra-tools/libra/issues/975) OPEN，1 条评论（TC-1800 统计块扩展）。仅规划，未授权执行；`I975-01` 为 `pending` / Acceptance 空。Git 对照 pin `6de20f6092dcf9bdb1c8efe03db4b70c82b423dd`；Libra 源码基线 `c06c5e5`。基线 `Cargo.toml` `0.30.190`（`Cargo.toml:3`）；实测 system `libra 0.30.171`。测试用例仓 `/mnt/gitmono/libra-testcases` 本计划不修改。

## 文档职责

### 适用范围

新增 `libra fmt-merge-msg` 子命令：从 stdin（或 `-F <file>`）读取 `FETCH_HEAD` 格式行输入（`<oid>\t<not-for-merge>\t<label>`），复用既有 `src/command/merge_message.rs` 的消息合成逻辑，把组合后的提交消息写到 stdout 并以 0 退出；同时支持 `--log=<n>`、`--no-log`、`--log=0`、`--into-name=<name>`、`-F <file>`、`--file=<file>` 以及 `core.commentChar` 对 `# By …`/`# Via …` 统计行的注释字符替换（shortlog 标头保持 `* <label>:`）；并保证 `merge`/`pull` 继续使用同一合成函数、输出不变。

### 非目标

不修复 `fetch . <ref>` 把命令行 refspec 标记为 `not-for-merge` 的缺陷（独立行为轴，由 `issues/976.md` 承接，见 `DEFER-I975-03`）。不实现 annotated tag 的 `Merge tag '<name>'` 标题与 tag 消息合成（`DEFER-I975-02`）。不改变 `merge` 的既有 subject 规则（`Merge <upstream> into <branch>` 与 Git 的 `Merge branch '<x>'` 差异单独跟踪）；不实现多有效条目的章鱼合并消息聚合（`Merge branches 'a' and 'b'` 与多 shortlog 聚合段落；由专有章鱼合并计划承接，见 `DEFER-I975-01`）。不新增 `.git` shim（见 `DEFER-I975-06`）、不修改测试用例仓、不实现 `--log` 之外的 Git 消息选项（`--message`、`--into-name` 之外的 `--suppress-destination` 等）；不处理纯 OID 列表输入（如 raw `MERGE_HEAD` 文件，逐行裸 OID 无制表符与 label；见 `DEFER-I975-07`）。

### 成功定义

- `libra fmt-merge-msg < FETCH_HEAD` 退出 0 且 stdout 等于 Git 同输入输出（fixtures 见判据规范）。
- `--log=3/--log=5`、`--no-log`、`--log=0`、`--into-name=<name>`、`-F <file>`、`core.commentChar` 配置选项面各自与 Git 对齐（含 TC-1799 截断标记 `(5 commits)` 与 `...` 完整形态由本卡闭环断言；根命令 `-c` 参数重载见 `DEFER-I975-04`）。
- 非法输入（缺失 ref 行、不可解析 OID、不存在的 `-F` 文件）fail-closed：非零退出且给出可操作提示，不输出半成品消息。
- `merge`/`pull` 的既有消息输出零回归。
- TC-1798…TC-1802、TC-1862 在固定 testcase pin 下由 V25–V31 进行 pin 校验与 TC 映射核对；TC-1828 由 `DEFER-I975-02` 承接；TC-1862（`merge --into-name` 行为）由 `DEFER-I975-08` 承接；testcase 完整运行依赖 #976、#557（根 `-c`，`DEFER-I975-04`）及 testcases 仓 D-layout 适配（`DEFER-I975-06`）。

## 已决议设计决策

### ADR-I975-01：`fmt-merge-msg` 复用既有合成器，不写第二套实现

- **Status:** Accepted
- **Context:** `src/command/merge_message.rs:9` 的 `default_message` 与 `:28` 的 `append_shortlog` 已实现 Git 风格 shortlog，`merge` 在 `src/command/merge.rs:2080` 复用。
- **Decision:** 新增的 `fmt-merge-msg` 只负责（a）解析 CLI 选项、（b）解析 stdin/`-F` 的 `FETCH_HEAD` 行以得到 `(oid, upstream_label, not_for_merge)`、（c）调用 `default_message`/`append_shortlog`、（d）生成多作者 `# By …` 与不同提交者 `# Via …` 统计行（应用 `core.commentChar` 前缀）、（e）写 stdout。合成逻辑零复制。
- **Alternatives considered:** 在 `fmt-merge-msg` 内重写短日志生成（会与 `merge` 漂移，违反 GC-02/ADR-I975-02）。
- **Consequences:** `merge` 输出保持字节不变；任一合成变更同时影响两个入口，需同批复核。
- **Revisit when:** Git 变更 `fmt-merge-msg` 的默认消息格式。

### ADR-I975-02：单一合成器 + 管线适配层的分层

- **Status:** Accepted
- **Context:** `merge_message.rs` 当前只导出 `pub(crate)` 函数，供 `merge` 调用。
- **Decision:** 保持 `merge_message.rs` 为唯一合成点；新增的 `src/command/fmt_merge_msg.rs` 仅做输入解析与选项映射，不新增消息拼装分支。`--no-log`/`--log=0` 通过 `log_limit = 0` 表达（`src/command/merge_message.rs:35-36` 已实现该短路）。
- **Alternatives considered:** 让 `fmt-merge-msg` 直接调用 `merge` 内部私有路径（会耦合 merge 的仓库状态）。
- **Consequences:** 单元测试可直接断言合成结果，无需构造完整 merge 流程。
- **Revisit when:** 合成器需要仓库外输入（如 remote 配置）。

### ADR-I975-03：非法输入 fail-closed，不输出部分消息

- **Status:** Accepted
- **Context:** Git 在不合法 `FETCH_HEAD` 行上以非零退出并给出 stderr 诊断；写出半成品会被 `test_cmp` 误判。
- **Decision:** 输入解析先完整构建 `Vec<MergeHeadEntry>` 并校验（OID 可解析、标签非空），任一失败立即返回错误、stdout 保持空、退出码非 0（复用 `StableErrorCode::CliInvalidArguments`）。
- **Alternatives considered:** 流式边解析边输出（失败时已污染 stdout）。
- **Consequences:** 峰值内存 O(输入行数)。
- **Revisit when:** 输入规模需要流式处理。

### ADR-I975-04：fmt-merge-msg 独有统计行与注释字符前缀

- **Status:** Accepted
- **Context:** Issue #975 唯一评论指出，`fmt-merge-msg` 是管线命令，当合并历史包含多作者时输出 `# By <author> (<n>) [and <author> (<n>) …]` 统计行；当提交者与当前用户不同时输出 `# Via <committer>`；这些统计行使用 `core.commentChar` 作为前缀；`--no-log`/`--log=0` 会同时抑制 shortlog 段落和统计块。普通 `merge --log` 前端不输出该统计块。
- **Decision:**
  1. 在 `fmt_merge_msg` 管线中，当 `log_limit > 0` 且多作者或提交者与当前用户不同时，在 shortlog 前输出统计块。
  2. 统计行前缀为配置的 `core.commentChar`（默认 `#`；例如 `core.commentChar=';'` 时前缀为 `; `）。
  3. shortlog 标头 `* <label>:` 保持不受 `core.commentChar` 影响。
  4. 当 `log_limit == 0`（`--no-log`/`--log=0`）时，统计块与 shortlog 段落一同被抑制，仅输出合并标题。
- **Alternatives considered:** 将统计块下沉到 `merge_message.rs::append_shortlog`（会导致普通 `merge --log` 也输出统计行，与 Git 行为相悖）。
- **Consequences:** `fmt-merge-msg` 独有统计块在管线适配层生成，普通 `merge` 保持零回归。
- **Revisit when:** Git 统一 merge 与 fmt-merge-msg 的统计块输出策略。

# libra fmt-merge-msg

Format a merge commit message from formatted input.

## Synopsis

    libra fmt-merge-msg [--log[=<n>] | --no-log] [--into-name <name>] [-F <file> | --file <file>]

## Description

`libra fmt-merge-msg` reads `FETCH_HEAD` formatted lines from stdin (or from a file with `-F`) and prints a composed merge commit message to stdout.

The input consists of lines formatted as `<oid>	<not-for-merge>	<label>`.

When `--log` (or `--log=<n>`) is given, shortlog summaries of the commits being merged are appended. When multiple authors or a differing committer are present, `# By <author>` and `# Via <committer>` statistics lines are emitted before the shortlog, prefixed by `core.commentChar` (default `#`).

## Options

- `--log[=<n>]`: Include at most `<n>` commit titles in the shortlog (default 20).
- `--no-log`, `--log=0`: Suppress shortlog and author/committer statistics.
- `--into-name <name>`: Prepare the merge message as if merging into `<name>` rather than the current branch.
- `-F <file>`, `--file <file>`: Read input from `<file>` instead of stdin.

## Examples

    libra fmt-merge-msg < .libra/FETCH_HEAD
    libra fmt-merge-msg --log=5 -F .libra/FETCH_HEAD

## Compatibility

Matches `git fmt-merge-msg` on valid `FETCH_HEAD` lines within the supported option set. Malformed inputs fail closed with exit code 129 (`LBR-CLI-002`).

Known differences tracked in follow-up issues:
- Multi-target merge message aggregation (octopus merges such as `Merge branches 'a' and 'b'`) is deferred to a future plan (`DEFER-I975-01`); single-target merge formatting is fully supported.
- Annotated tag message folding for fmt-merge-msg (TC-1828) is deferred to a future plan (`DEFER-I975-02`).
- TC-1862 tests `merge --into-name` and is tracked under issues #974/#999 (`DEFER-I975-08`).
- Root command `-c <key>=<val>` runtime overrides are tracked in issue #557 (`DEFER-I975-04`).

set -euo pipefail
HEAD_SHA="$(libra rev-parse HEAD)"
VERSION="$(sed -n 's/^version = "\(.*\)"/\1/p' Cargo.toml | head -n1)"
wait_run() {
  local wf="$1" i id st
  for i in $(seq 1 40); do
    id=$(gh run list --repo libra-tools/libra --workflow "$wf" --branch main --event push --limit 10 --json databaseId,headSha --jq '.[]|select(.headSha=="'"$HEAD_SHA"'")|.databaseId' | head -n1)

    for _ in $(seq 1 480); do
      st=$(gh run view "$id" --repo libra-tools/libra --json status,conclusion --jq '.status+" "+.conclusion')
      case "$st" in "completed success") echo "$id"; return 0;; "completed "*) echo "$wf $id failed: $st" >&2; return 1;; esac
      sleep 30
    done
    return 1
  done
  return 1
}
BASE_ID="$(wait_run base.yml)"

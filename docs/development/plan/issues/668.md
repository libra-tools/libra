## 文档职责

### 适用范围

`libra ls-files` 在**子目录**中调用时的选择作用域与路径投影：无显式 pathspec 时只列调用目录树；文本默认输出按 cwd 相对、`--full-name` 按仓库根相对；`-s/--stage`、`-t`、`-o`、`-i`、`-c`、`--debug` 等既有文本模式共享同一投影。显式普通 pathspec 由 `PathspecSet::from_workdir` 相对 cwd 解析，`../` 与 `:(top)` 可在仓库内扩展选择作用域；JSON/machine 保持 `data[].path` 仓库根相对的稳定机器合同，但与文本共享筛选集合。

### 非目标

`ls-files --directory`/`--deduplicate` 等未实现对上游的补齐（`DEFER-I668-02`）。`ls-tree` 的路径基（不同命令，另行立项）。`add` 的路径输出（`issues/667.md`/`issues/669.md` 各自轴）。测试用例仓新增 TC-0054 case（`DEFER-I668-01`，需单独提交测试仓）。

### 成功定义

- 子目录中 `libra ls-files` 默认输出 cwd 相对路径（`foo1`），与 Git 一致；仓库根调用输出不变（`sub/foo1`）。
- `--full-name` 在子目录中输出仓库根相对路径（该 flag 由此变为真实语义，不再是 no-op）。
- 无显式 pathspec 时，子目录调用不泄漏仓库根兄弟条目；显式 `../`/`:(top)` 仍可选择仓库内 cwd 外条目并以 cwd 相对 `../...` 文本渲染。
- 其余文本输出模式（`-s`、`--stage`、`-t`、`-o`、`-i`、`-c`、`--debug`）沿用同一投影；普通 pathspec 相对 cwd 解析，`--error-unmatch foo1` 命中 `sub/foo1`，冗余写成 `sub/foo1` 则不命中。
- JSON/machine 的条目集合遵守调用目录/显式 pathspec 选择规则，`data[].path` 继续使用仓库根相对路径，不随文本默认值或 `--full-name` 改变。
- 文档与兼容矩阵同卡，回归用例覆盖子目录与仓库根两种调用。

## 已决议设计决策

### ADR-LSF-01: 默认 cwd 基，`--full-name` 恢复真实语义

- **Status:** Accepted
- **Context:** Git 默认按 cwd 输出相对路径；`--full-name` 才输出仓库根相对。Libra 现在两者都输出根相对（`src/command/ls_files.rs:115-117`）。
- **Decision:** 先把 `current_dir` 可靠地相对到 workdir。无显式 pathspec 时，用该前缀形成隐式 cwd 选择作用域；有显式 pathspec 时只由 `PathspecSet::from_workdir` 决定选择集合，允许仓库内 `../` 与 `:(top)` 扩展到 cwd 外。文本默认路径用 `pathdiff::diff_paths(workdir.join(entry.path), current_dir)` 计算，因而显式选中的 cwd 外条目显示为 `../...`，不得在相对化失败时回退根相对路径；`--full-name` 使用 `entry.path`。cwd 为仓库根时两者等价。`-s`/`--stage`/`-t`/`-o`/`-i`/`-c`/`--debug` 共享投影，只改路径片段，不改其它列。
- **Alternatives considered:** 只让 `--full-name` 失效（继续偏离 Git）；用 `--full-name` 反转语义（与 Git 相反，破坏脚本）。
- **Consequences:** 依赖 root-relative 默认输出的脚本需加 `--full-name`；文档与 COMPATIBILITY 必须登记。
- **Revisit when:** Git 改变 `ls-files` 的路径基规则。

### ADR-LSF-02: 单一文本投影 helper，机器路径合同保持稳定

- **Status:** Accepted
- **Context:** `FileEntry.path` 同时承担筛选候选、工作树文件定位与 JSON/machine 序列化；若在收集阶段原地改成 cwd 相对，会破坏 pathspec/文件访问，并无意改变稳定机器字段。真正的人读文本拼接在 `render_output:567-618`，不是 `CachedStat::render:201`。
- **Decision:** 保持内部 `FileEntry.path` 为仓库根相对；在 `render_output` 抽出返回 `CliResult` 的 `render_path(entry, current_dir, workdir, full_name)`，供所有 human text 模式使用，失败返回带资源与修复提示的上下文错误，禁止 fallback。JSON/machine 在该 helper 前序列化，`data[].path` 保持仓库根相对；其条目集合仍消费 `run_ls_files` 的同一作用域/pathspec 筛选。`PathspecSet::from_workdir` 继续以仓库根候选执行匹配，但普通 raw spec 先相对 cwd 解析；`--error-unmatch` 检查同一筛选集合。
- **Alternatives considered:** 在每种输出模式内各自 `strip_prefix`（易漂移）。
- **Consequences:** 必须分别验收 human text 与 JSON/machine；`--full-name` 只改变 human text 路径表示，不改变机器字段。
- **Revisit when:** 引入 pathspec 的 cwd 前缀语义变更。

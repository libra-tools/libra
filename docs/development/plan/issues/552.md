## 已决议设计决策

### ADR-SM-01：enum 外识别

**Status:** Accepted。`src/cli.rs:3080-3115` 的未知顶层命令分支内集中精确匹配有意拒绝的名称，命中时按既有 `CliError::failure(...).with_stable_code(StableErrorCode::Unsupported)` 构造；不得误识参数值、非顶层 token 或其它命令。`Commands`、根 Command Groups 与主兼容表不增加 variant。未来需要实际支持时重新评估 variant、主表迁移和 `compat_help_examples_banner`、`cli::tests::root_after_help_lists_every_visible_command`、`compat_command_docs_examples_section` 三守卫（DEFER-SM-04，T-1）。

### ADR-SM-02：稳定诊断与可行替代

**Status:** Accepted。主消息说明 D1 产品边界；最多两条普通 hint：① `libra clone <submodule-url> <independent-dir>` 建独立 Libra 仓库并指向文档；② package manager/vendoring 与 gitlink 保留但不检出。两条 hint 不得丢失，参见 `with_hint` 限制。不得使用显式退出码 override 绕过 fine 模式；文档按实际发布版本记载旧默认 129/fine 2 到新默认 128/fine 8 的变化。

独立工作流示例（将 URL 替换成有权限访问的上游地址，目录必须不存在）：

```sh
libra clone https://example.org/project/dependency.git dependency-copy
cd dependency-copy
libra status
# 仅在需要搜索时
libra grep 'needle'
```

这会在新目录创建 `.libra` 并单独管理仓库；不会替父仓库执行 submodule init/update/status 或固定其 gitlink，也不假定已有 stock Git `.git` 子模块可直接被 Libra 打开。需组合依赖可选 package manager 或 vendoring。grep 只是独立仓库内的搜索工作流，不是 submodule 命令族的通用替代。`send-email` 诊断统一不在本卡。

### ADR-SM-03：上游结果的事实优先

**Status:** Accepted。`../libra-testcases/review/command-support-policy.md:15-27` 规定：D 类符合条件的**已执行 FAIL** 记录为 `SKIP`，同一详情保留 `original_verdict=FAIL`、原 Git/Libra 双轨与 excerpt；T 类失败保持 `FAIL`。真实 `PASS` / `PASS-XFAIL` 一律原样保留，不转 SKIP 或拒绝登记，并调查由其它修复、测试环境或归因变化引起的事实。若一个已确认 D 案例更早被 T 缺口阻断，政策第 5 条仍按 D 记 `SKIP`，同时记具体 T blocker；是否属 D 必须以固定上游政策与真实案例映射确定，不凭字符串推断。

归因不能只保存三个相互替代的 verdict。SM-10 须分列：`source_verdict`（SM-08 固定 summary 的 verdict）、`execution_verdict`（固定详情或固定运行记录证明的真正执行结果）、`recorded_verdict`（政策产物）。公开汇总中 TC-0660/1584/1585 的 `source_verdict` 已是 `SKIP`，而详情中的 `original_verdict=FAIL` 必须通过 `execution_verdict` 的执行证据核验；只有同时证明该 TC 实际执行、执行结果为 FAIL、属已确认 D scope，才产生 `recorded_verdict=SKIP`。T 类证明为 FAIL 时为 `FAIL`；PASS/PASS-XFAIL 原样记录。源端仅有 `SKIP` 而无可核验的原始执行结果、执行记录或目标 testcase 实际运行证据时保持 `blocked`，不得把 `source_verdict` 当作 `execution_verdict`。#552 的 14 ID 未获权威清单前不猜其余 11 项。

## 全局工程约束

继承 GC-01..GC-13；数据库角色 N/A，不改 schema、连接或迁移。拒绝发生于顶层解析失败路径，不得新建持久状态。测试把 `HOME`、`XDG_CONFIG_HOME`、`LIBRA_HOME`、global/system config DB 均指向隔离目录，清除日志输出与 fine 环境变量后分别设置模式；仓库 fixture 前后递归快照路径、文件类型/权限、symlink 目标、文件内容 hash，包括 index、objects、SQLite 主库及 WAL/SHM、配置和工作树。非仓库 fixture 同样比较；输出与快照放内存，不得混入被比较目录。为排除测试自身噪声，构造完成并关闭 SQLite 后基线快照，调用完成后再快照；失败即整门失败。

**no-JUnit 与重跑安全：** 每轮验收开始前，在已有的、操作者拥有的仓外 scratch 根创建新的私有临时目录；不得接受输出文件路径作为输入，不覆盖已有文件。下列块在 Libra 仓库根执行；`SCRATCH_ROOT` 必须预先指向已有绝对目录。解析物理路径后同时排除 Libra、backend 和 testcase checkout 的根及其后代。目录只供本轮临时配置，不是证据目录；不设置 `CARGO_TARGET_DIR`，正常 Rust 编译缓存可复用；若某测试需不存在的目标目录，使用该轮私有目录下的新子路径，重跑重新申请目录，不删除他人内容。

```bash
set -euo pipefail
: "${SCRATCH_ROOT:?set an existing external scratch root}"
case "$SCRATCH_ROOT" in /*) ;; *) exit 1;; esac
SROOT="$(cd -P -- "$SCRATCH_ROOT" && pwd -P)"
test -d "$SROOT" && test -O "$SROOT"
for repo in /mnt/data/gitmono/libra /mnt/data/gitmono/libra-backend /mnt/data/gitmono/libra-testcases; do
  ROOT="$(cd -P -- "$repo" && pwd -P)"
  case "$SROOT/" in "$ROOT/"*) exit 1;; esac
done
RUN_DIR="$(umask 077; mktemp -d "$SROOT/libra-sm-nextest.XXXXXXXX")"
test -O "$RUN_DIR" && test ! -L "$RUN_DIR"
NEXTEST_NOJUNIT_CFG="$RUN_DIR/nextest.toml"
(set -C; python3 -I -c 'import sys; p=sys.argv[1]; s=open(p,encoding="utf-8").read().splitlines(keepends=True); a="[profile.default.junit]\n"; b="path = \"junit.xml\"\n"; assert s.count(a)==s.count(b)==1; sys.stdout.writelines(x for x in s if x not in (a,b))' .config/nextest.toml > "$NEXTEST_NOJUNIT_CFG")
test -f "$NEXTEST_NOJUNIT_CFG" && test ! -L "$NEXTEST_NOJUNIT_CFG"
```

同一轮的 nextest 命令可复用该配置；重跑另建私有目录并在同一 shell 使用新路径。内容形态变化即停止修计划，不能用不带配置的 nextest。v2.12 禁止新建证据文件/目录，不禁止执行上游测试；本计划选择只读公开结果是范围决定。临时 fixture/配置不是证据归档，摘要、结果、SHA 和 run ID 写入本计划。不得保存私有路径、密钥或原始隐私数据。

## 文档职责

在 [#1062 计划](1062.md) 的转换模块及完整调用路径上，补足 text=auto 自动文本识别、已有 CRLF 索引保护与原始 TC-1324。此计划对“自动转换策略”负责，不重做显式 text/eol 的基础设施。

### 适用范围

- .gitattributes 的 text=auto（含与 eol=lf/crlf 搭配的自动策略）；新文件转换、普通 add 的历史 CRLF 索引保护与显式 --renormalize。
- 上游 t/t4035-diff-quiet.sh#23：Libra 自己 add CRLF 文件，再把工作区改成 CRLF/LF 混合后 diff --quiet 返回 0。
- 使用同一策略的 status/add/diff 与同步预检不得分叉；共享状态的 am/checkout/commit/describe/rebase/stash/switch 也须回归及同步文档；新增策略同卡独立 patch 发布。

### 非目标

- 显式 text/eol 的 clean 模块、worker 接线、stat/cache、diff 视图：前驱 I1062-02/03/06 交付，不复制实现。
- 无属性时 core.autocrlf=true/input 的完整配置兼容、core.safecrlf、encoding、ident、自定义过滤器或 checkout smudge：DEFER-861-01，未排期。
- t4035 其它独立失败的修复和全部 diff 兼容不是本卡范围；必须真实执行原文件和前置，若它们阻止 TC-1324 到达，按 DEP-861-TC 阻塞，不改写步骤或用小探测替代关闭条件。

### 成功定义

完整原始 TC-1324 在固定 Git 对照与最终 Libra 二进制两轨均 PASS；binary/历史 CRLF 索引等负例不被过度归一化；全部消费者同策略，真实变化仍报告；A/B/C/D、网站部署及计划最后全量完成后仅本计划可收口。#1062 完成不会自动使 #861 完成。

## 已决议设计决策

### ADR-861-01：auto 是 clean 策略，禁止 diff 特判

- Status：Accepted；用户已授权实施。
- Decision：扩展 #1062 的同一策略解析/转换模块。以固定 Git 的 convert_is_binary、has_crlf_in_index 与 CONV_EOL_RENORMALIZE 语义为对照，区分 normal 与 renormalize。新文件的 Libra add 必须产生正确的规范化 blob，不能仅在比较时清洗两侧。
- Alternatives：拒绝不看 index 的 replace CRLF；拒绝仅按 NUL 单点探测就宣称与 Git binary 检测等价；拒绝把本题替换成 --ignore-cr-at-eol。
- Consequences：同卡覆盖所有消费者与文档；是否转换必须在 stat/hash 缓存之前形成一致上下文。Revisit：固定 Git 对照显示模式表错误时先修计划。

### ADR-861-02：独立关闭条件

- Status：Accepted。
- Decision：#1062 的完成证据仅解锁本卡；本卡自行取得 TC-1324 和独立发布/全量门。#1062 不等待本卡，也不提前声明它已修复。
- Alternatives：拒绝两个 Issue 共用一条模糊“CRLF 已修复”结论。
- Consequences：若前驱意外已经通过本场景，先复核是否已交付本卡全部语义；按 ER-03/G-09 改成真实承接审计，不制造无行为的重复实现/版本发布。

## 全局工程约束

继承模板 GC-01～GC-13、G-01～G-11、ER-01～ER-14。数据库/schema 为 N/A：不改迁移、全局或系统配置库。另有共同约束：

1. 唯一转换实现位于拟新增 src/utils/worktree_conversion.rs；使用现有属性解析语法及优先级，不新增另一套 parser。转换策略必须带仓库根、相对路径、文件类型及必要的索引上下文，禁止依赖 worker 的偶然 cwd。
2. 工作区原始字节、clean 后字节、索引 blob 三者分开。仅转换工作区输入，禁止把索引/HEAD 历史对象也归一化后掩盖真实差异；禁止以空白忽略选项替代 clean。
3. 现有原始读字节 API 不得被无差别改成 clean API，避免改变 checkout、外部驱动、快照及其它未知调用方。调用方显式选择转换模式；LFS pointer 与 symlink target 仍走原有专用分支。
4. 模式位、类型变化、冲突 stage、intent-to-add、skip-worktree、删除等独立状态不得被“内容相等”覆盖。新生产路径不得加入无说明的 unwrap/expect/panic；失败须提供路径与可操作上下文。
5. 保持 status 的 no-follow/beneath 根能力、每次 I/O deadline、子进程回收、io_blocked 分类和 hash-kind 传递。不得把原受限读取挪回主进程同步 I/O，或把属性/索引读取失败当作未设置属性/干净。
6. 所有测试在隔离 fixture 中运行，真实 install.ps1、template/pre-commit.ps1 不作为可写 fixture。Implementation write set 排除两文件；install.ps1 仅在 ER-08 发布写集内允许版本字段同步，保持换行及其它内容。旧稿“任何写集都禁止该文件”与版本面强制门相冲突，本次明确区分修复写集与发布写集；若实施时另有仍有效的逐字节冻结指令，先登记发布阻塞，不偷偷豁免版本 parity。
7. stat 快路只能在其输入和转换策略仍有效时复用；变更属性文件即使目标文件 stat 未变，也须得到正确结果。转换摘要缓存不得跨仓串用或无限增长；读取失败不得缓存为 clean。
8. tests/command/*.rs 属于现有 command_test。不新增同名独立 target，不杜撰 --test status_test/diff_test/merge_test。新增函数明确标 new；listing 必须非零命中，运行不得 ignored/SKIP。进程全局状态用 keyed serial 并更新 tests/SERIAL_REGISTRY.tsv、执行 sh tests/NEXTEST_GROUPS.sh；优先使用 subprocess fixture 避免全局改 cwd/env。
9. 原始 calc_file_blob_hash/read_worktree_blob_bytes 的未改调用方（如 refresh、restore、hydrate、mv、update-index、worktree doctor）不因名称相似被批量改语义；若实施发现这些路径也必须转换，先 ER-03 明确新卡或写集，不顺手扩展。

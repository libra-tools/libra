## 已决议设计决策

### ADR-AP-01：单一最终路径投影

先解析 header，再按 `-p` strip，再规范化 directory，最后拼接并做既有安全校验。`some/sub/`、`./some/sub`、`some//sub`、`some/./sub`、`some/../some/sub` 均归一为 `some/sub`；leading `../` 以含 `unable to normalize directory` 的错误拒绝。`--check`、write、index、stat 和 `patch_targets` 消费同一投影，不在 am 复制逻辑。

### ADR-AP-02：traditional 路径不以文件存在性猜测

Git `apply.c:666-714,732-753,868-912` 的语法优先：剥离后 new 名以较短 old 名为前缀时用 old，否则用解析后的 new；new 侧 strip 不足且 old 可解析时回退 old；`/dev/null` 分别表示创建/删除。选择与文件是否存在无关，report-only 不读取工作树决定名称。仅承接 `"a/"sub/file1`、`"b/"sub/file1` 等上游 fixture，完整 `diff --git` C 风格 quoted-path 进入 DEFER-AP-01；不声称已验证其它 quoted forms。

### ADR-AP-03：共享预处理顺序

共同 pipeline 固定为：traditional header 识别/安全引用处理 → SVN 已验证删除元数据投影（不把 `@@ +1 0,0 @@` 伪造为标准 hunk）→ recount 实际 hunk 行数 → #547 AM-10 的 whitespace fix → target 解析/strip/directory/安全校验 → prepare/check/write。只在该选项开启时执行对应步骤；不得复制 patch 内容后绕过 64 MiB cap。#547 的 whitespace 卡须追加 quoted+SVN+recount 组合回归；在两计划间串行发布。

### ADR-AP-04：报告、no-op 与 recount

`--stat` 和 `--numstat` 默认报告不写；`--apply` 与报告/check 组合时在检查成功后写。纯 context、无增删的 fragment 无 recount 时在 `--stat` 和 `--check` 均应非零，不能打印成功统计；`--recount --check` 可接受有匹配 context 的 no-op（pinned `t4136:20-42`）。binary stat 按 pinned `apply.c:2388-2391` 输出 `Bin`，不是自造字节大小；binary numstat 为 tab 分隔 `- - path`。`--recount --stat` 与 `--recount --stat --apply` 的 no-op 结果按上述 Git 源码调用链规划；尚未运行 pinned 二进制探针，实施前须对照上游。具体失败退出码尚未核实，暂以非零记载，不能写成特定数值。

### ADR-AP-05：binary 开关只作兼容语法

Git `apply.c:5228-5233` 把 `--allow-binary-replacement` 定义为无动作兼容选项；Libra 接受后继续使用既有 literal/delta 和 preimage 验证，不放宽大小、OID、路径或 malformed 安全边界。

## 已决议设计决策

### ADR-AP-01：单一最终路径投影

先解析 header，再按 `-p` strip，再使用经 `normalize_directory` 规范化的 `--directory`，最后拼接并做既有安全校验。`some/sub/`、`./some/sub`、`some//sub`、`some/./sub`、`some/../some/sub` 均归一为 `some/sub`；leading `../` 以含 `unable to normalize directory` 的错误拒绝。`--check`、write、index、stat 和 `patch_targets` 消费同一投影。

### ADR-AP-02：traditional 路径不以文件存在性猜测

按 Git `apply.c:666-714,732-753,868-912` 语法优先：剥离后 new 名以较短 old 名为前缀时用 old，否则用解析后的 new；new 侧 strip 不足且 old 可解析时回退 old；`/dev/null` 分别表示创建/删除。不读取工作树决定名称。仅承接 `"a/"sub/file1`、`"b/"sub/file1` 等上游 quoted-prefix fixture，完整 C-style quoted-path 进入 `DEFER-AP-01`。

### ADR-AP-03：共享预处理顺序

共同 pipeline 固定为：traditional header 识别/quoted-prefix 处理 → SVN 已验证删除元数据投影（不把 `@@ +1 0,0 @@` 伪造为标准 hunk）→ recount 实际 hunk 行数 → #547 AM-10 的 whitespace fix → target 解析/strip/directory/安全校验 → prepare/check/write。只在该选项开启时执行对应步骤；不得复制 patch 后绕过 64 MiB cap。

### ADR-AP-04：报告、no-op、`--apply` 与 recount

`--stat` 和 `--numstat` 默认报告不写；`--apply` 与报告或 `--check` 组合时在检查成功后写入。纯 context、无增删的 fragment 无 `--recount` 时在 `--stat`/`--check`/apply 均应非零退出，不能打印成功统计；`--recount --check` 可接受有匹配 context 的 no-op（pinned `t4136:20-42`）。具体失败退出码以非零记载，实施前对照 pinned Git 二进制核实。

### ADR-AP-05：binary 开关只作兼容语法

Git `apply.c:5228-5233` 将 `--allow-binary-replacement` 定义为无动作兼容选项；Libra 接受后继续使用既有 literal/delta 和 preimage 验证，不放宽大小、OID、路径或 malformed 安全边界。

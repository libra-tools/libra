# Issue #488：`grep` 的 `--exclude-standard` 与子目录作用域对齐计划（2026-09-14）

> 来源：[libra-tools/libra#488](https://github.com/libra-tools/libra/issues/488)（libra-testcases TC-1596，对应 `t/t7810-grep.sh:1288-1328`）。
> 状态：设计计划；全部任务卡 `pending`，尚未进行 Codex review（见「Codex review log」）。

## 文档职责

本文解决 issue #488 报告的两处 `libra grep` 与 Git 的行为差异：

1. `grep --no-index --exclude-standard` 被当作未知参数拒绝（exit 129）。
2. 在子目录中执行 `grep --untracked` 时，搜索范围仍是整个仓库，输出路径也是仓库根相对路径。

核对时发现第二处差异远比 issue 描述的宽：从子目录执行的**所有仓库模式搜索**（默认已跟踪文件、`--cached`、`--untracked`、`--tree`，以及 `-l`/`-c`/`--heading`/`-z` 各种输出形态、显式 `../` pathspec）都不限定到当前目录，路径也不相对当前目录显示；`--full-name` 与 `--no-exclude-standard` 同样缺失。本计划按两个行为轴修复：忽略规则的选择（GR-01）、仓库模式搜索的当前目录作用域与路径显示（GR-02）。

本文只规划任务，不宣称实现完成。落地时每个任务都必须先刷新源码锚点，再按任务卡验收。

### 适用范围

- `libra grep` 的 `--exclude-standard` / `--no-exclude-standard`，作用于 `--no-index` 与 `--untracked`。
- 仓库模式（默认、`--cached`、`--untracked`、`--tree`）从子目录执行时：空 pathspec 默认限定到当前目录；人读输出路径相对当前目录；新增 `--full-name`；`--max-depth` 的深度起点随之调整。
- 同步：`docs/commands/grep.md` EN + zh-CN、`docs/development/commands/grep.md`、`COMPATIBILITY.md` 的 `grep` 行、`../libra-backend` 网站文档。

### 非目标

- `--recurse-submodules`（DEFER-01）。
- JSON 输出的 `path` 字段改为相对当前目录显示（DEFER-02；本计划保持现有语义，见 ADR-GR-03）。
- `libra init` 自动生成的 `.libraignore` 在 `--no-index` 下被搜到：这是 Libra 有意差异，issue 已说明它不影响行为结论。
- Git 的位置参数 `<tree>...` 形式（Libra 使用 `--tree`，保持现状）。

### 成功定义

- 移植 TC-1596（`t7810-grep.sh:1288-1328` 等价，忽略文件使用 Libra 原生读取的 `.gitignore` 或 `.libraignore`）完整通过：
  - 根目录执行 `grep --no-index --exclude-standard o` 输出 `file1:hello`、`sub/file2:world`，exit 0；
  - 在 `sub` 中执行 `grep --untracked o` 只输出 `file2:world`，exit 0。
- 本计划判据矩阵的每一行都与 git 2.54 实跑一致（人读输出、退出码）。
- 从仓库根目录执行的全部既有 grep 行为不变。
- 两张卡各自完成 C 组发布并取得 D 组证据，然后全量收口门全绿。满足这些之后，本计划才可标记完成。

### ADR-GR-01: 忽略规则的选择

- **Status:** Accepted
- **Context:** GAP-01/02；git `builtin/grep.c:1399-1409`、`dir.c:3482-3500`。
- **Decision:**
  1. 新增 `--exclude-standard` 与 `--no-exclude-standard`，二者互相覆盖（后出现者生效，与 Git 的 `OPT_SET_INT` 一致，开工时实跑确认）。
  2. 默认值与 Git 一致：`--untracked` 默认套用忽略规则，`--no-index` 默认不套用。
  3. 在默认、`--cached`、`--tree` 模式下使用任一 flag → 用法错误，沿用 grep 既有冲突处理（`grep.rs:635-640` 的 `command_usage` + `CliInvalidArguments`）；消息为 `--[no-]exclude-standard cannot be used for tracked contents`。Git 的 128 与 Libra 的用法错误退出码之差登记为有意差异。
  4. **仓库内**（含从子目录执行）：以工作树根为判定根调用 `check_gitignore_with_layers`，因此当前目录之上的 `.libraignore`/`.gitignore`、`info/exclude` 与 `core.excludesFile` 均生效。
  5. **仓库外**：以每个遍历根为判定根，只读取遍历根及其子目录中的 `.gitignore`/`.libraignore`，外加全局 `core.excludesFile`；不读取遍历根之上的文件，没有 `info/exclude`。
  6. `--untracked --no-exclude-standard` 使用 `list_workdir_files_unfiltered` 取得未跟踪文件。
- **Alternatives considered:** `--no-index` 默认套用忽略规则——与 Git 相反，且改变既有文档化行为，拒绝。仓库外向上查找忽略文件——可能读取用户主目录等无关位置，拒绝。
- **Consequences:** 仓库外判定根不是仓库，若 `check_gitignore_with_layers` 的 `info/exclude` 查找假定存在仓库，需在 grep 内包装为不含该源的调用（落点仍在 grep 或 ignore 模块，见 GR-01 写集）。
- **Revisit when:** Libra 引入独立的 `grep.fallbackToNoIndex` 等配置。

### ADR-GR-02: 仓库模式的当前目录作用域与路径显示

- **Status:** Accepted
- **Context:** GAP-03/04/05；git `builtin/grep.c:1310-1314`（`PATHSPEC_PREFER_CWD`）、`:334-352`、`:1102`。
- **Decision:**
  1. **作用域：** 仓库模式（默认、`--cached`、`--untracked`、`--tree`）下，若没有任何正向 pathspec，按当前目录合成一个目录前缀 pathspec；在仓库根执行时合成结果等于匹配全部，行为不变。
  2. **显示路径：** 人读输出（普通行、`-l`、`-L`、`-c`、`--heading`、`-z`）默认相对当前目录（`util::workdir_to_current`），当前目录之外的文件显示为 `../` 形式。
  3. **`--full-name`：** 恢复为工作树根相对路径。
  4. **`--max-depth`：** 无 pathspec 时从当前目录度量深度（因为合成的 pathspec 就是当前目录）。
  5. **匹配语义不变：** 显式 pathspec（含 `:/`、`:(top)`、`../`）的匹配语义沿用共享 pathspec engine，只改变显示方式。
  6. **`--no-index`：** 保持现有（已与 Git 一致）的 cwd 相对行为。
- **Alternatives considered:** 只修 `--untracked`——同一命令不同模式作用域不一致，拒绝。修改 `PathspecSet::from_workdir` 的空 pathspec 语义——会影响 `add`、`ls-files` 等所有消费者，拒绝。
- **Consequences:** 从子目录执行的默认搜索结果变少，属于公开行为变化，需要在 EN/zh 文档、`COMPATIBILITY.md:233` 与 dev 文档登记。
- **Revisit when:** 无。

### ADR-GR-03: JSON 输出的 `path` 语义

- **Status:** Accepted
- **Context:** 现有 JSON `path`：仓库模式为工作树根相对，`--no-index` 为 cwd 相对（`grep.rs:236-246`）。Agent 调用方依赖稳定路径。
- **Decision:** JSON 输出同样适用 ADR-GR-02 第 1 条的作用域限定（结果集与人读输出一致）；仓库模式的 `path` 保持工作树根相对，不受当前目录与 `--full-name` 影响；`--no-index` 保持 cwd 相对。
- **Alternatives considered:** JSON 跟随人读显示——会破坏从子目录调用的 Agent 的路径解析，拒绝。
- **Consequences:** 人读与 JSON 的路径表示在子目录中不同，需在文档「结构化输出」节写明。
- **Revisit when:** DEFER-02 引入显式的显示路径字段。

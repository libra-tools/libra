## 文档职责

issue #479 是一份 plumbing 命令逐项对照清单（libra 0.22.5 vs git 2.55），后续评论补充了 TC-0021（`t3700-add.sh#25`）所需的 `rev-parse :<path>`。本计划先以当前 checkout（0.22.25 / 源码 0.22.26）逐条复核：

- 已修复或不复现的条目只做证据登记与回归守卫；
- 仍然存在的缺口拆成可独立发布的任务卡；
- 需要的前置能力（`diff-files --name-only` 与退出码）一并纳入，使 TC-0021 完整序列可以移植。

本文只规划任务，不宣称实现完成。落地时每个任务都必须先刷新源码锚点，再按任务卡验收。

### 适用范围

- `cat-file`、`hash-object`、`ls-tree`、`rev-parse`、`update-ref`、`symbolic-ref`、`verify-pack` 的退出码契约守卫。
- 修订语法：`:<path>`、`:<n>:<path>`、`:/<regex>`、`:/!-<regex>`、`:/!!<regex>`、`<rev>^{/<regex>}`（共享解析器，所有对象规格消费者受益）。
- `update-index`：`--index-info`、`--stdin`、`-z`、`--refresh`、`--really-refresh`、`-q`、`--ignore-missing`、`--unmerged`、`--chmod=(+|-)x`、`--info-only`、`--verbose`。
- `diff-files` / `diff-index` / `diff-tree`：`--name-only`、`--name-status`、`--exit-code`，以及默认退出码与 Git 对齐。
- `symbolic-ref -d/--delete`；`update-ref --stdin [-z]` 批量事务与 `--no-deref`。
- 同步：各命令 `docs/commands/<cmd>.md` EN + zh-CN、`docs/development/commands/<cmd>.md`、`COMPATIBILITY.md` 对应行、`../libra-backend` 网站文档、测试索引。

### 非目标

- `update-index --unresolve` / `--again`（DEFER-01）。
- `update-index --assume-unchanged` 及其在 status/diff/add 中的生效（DEFER-02）。
- `update-index --skip-worktree`：依赖的 `git-internal 0.8.6` 只读写 index v2，不支持扩展标志位（DEFER-03）。
- `update-ref` 对 `HEAD` 与 `symref-*` 命令的支持，以及 `symbolic-ref` 对非 `HEAD` 符号引用的支持：refs 存于 SQLite，范围沿用既有 `refs/heads/*` / `HEAD` 限定（DEFER-04）。
- 把 Libra 的 `LBR-CLI-002`/`LBR-CLI-003`（129）改为 Git 的 128（ADR-PL-02 决议保留）。
- `hash-object --literally` 的任意类型字符串（既有文档化差异）。

### 成功定义

- TC-0021 完整序列可移植并通过：
  1. `add foo bar baz`；
  2. `rev-parse :foo` 返回 index 中的 blob OID；
  3. `rm -f foo`；
  4. `update-index --index-info` 写入 stage 3；
  5. `add --refresh bar` 以 exit 0 结束且 stdout 为空；
  6. `diff-files --name-only` 以 exit 0 结束，输出含 `baz` 而不含 `bar`。
- issue 中仍存在的每个缺口都有交付卡或登记延后项。
- plumbing 退出码有表驱动守卫，同一输入重复运行结果一致。
- 九张卡各自完成 C 组发布并取得 D 组证据，然后全量收口门全绿。满足这些之后，本计划才可标记完成。

## 已决议设计决策

实现时若需偏离本节，必须先修改计划并说明原因，不得在代码中静默改语义。

### ADR-PL-01: Git 参照与判据

- **Status:** Accepted
- **Context:** 本计划横跨多条命令，需要统一的真值来源。
- **Decision:**
  - 语义以 git@`1630431f32` 源码为准（事实基线逐项锚定）；每张卡开工时，在同形 fixture 上用 `/usr/bin/git` 实跑本卡矩阵的全部行，并把 sanitized 对照写入 `LIBRA_TEST_SCRATCH_DIR`。
  - 自动化测试不调用系统 git（沿用仓库约定），期望值写在测试内。
  - 输出措辞允许与 Git 不同（issue 评论同意）；退出码按 ADR-PL-02。
  - stdout/stderr 的字节级格式凡为机器消费（`--index-info` 输入、`--stdin` 输出行、`--name-only`、`--refresh` 的 `needs update` 行）必须与 Git 一致。
- **Alternatives considered:** 录制 git 输出逐字节比对——人读措辞允许不同，拒绝。
- **Consequences:** 每张卡的 AC 引用本卡矩阵；矩阵行变化时同批修改 ADR、测试与修订历史。
- **Revisit when:** 外部用例仓库升级参照版本。

### ADR-PL-02: plumbing 退出码契约

- **Status:** Accepted
- **Context:** issue 条目 1、3、4。Libra 的错误模型为：运行期 fatal → 128，用法与无效目标（`LBR-CLI-002`/`LBR-CLI-003`）→ 129；`cat-file -e` 已有明确的「保留 129」决策（`cat_file.rs:486-494`）。上游用例多用 `test_must_fail`（非零且非信号）。
- **Decision:**
  1. 保留 Libra 文档化退出码，不为对齐 Git 的 128 改码。
  2. `cat-file -e` 保持 0（存在）/ 1（格式正确但缺失）/ 129（无法解析）。
  3. 新增 flag 的错误遵循同一规则：用法错误 129，运行期失败 128，Git 语义规定的非错误非零（`--refresh` 需要更新、`--exit-code` 有差异、`-e` 缺失）为 1。
  4. EC-01 以表驱动测试钉住上述契约，并对每个用例重复执行 3 次，断言退出码一致。
- **Alternatives considered:** 全局把 `LBR-CLI-003` 改为 128——影响所有命令的稳定错误码契约，拒绝。按命令逐个改为 128——与 `docs/error-codes.md` 冲突，且不影响上游 `test_must_fail`，拒绝。
- **Consequences:** 与 Git 的 128/129 差异在 `COMPATIBILITY.md` 相关行登记。
- **Revisit when:** 稳定错误码表进行 major 调整。

### ADR-PL-03: `:<path>` 与 `:<n>:<path>`

- **Status:** Accepted
- **Context:** GAP-02；git `object-name.c:1755-1800`。
- **Decision:** 在 `resolve_object_spec_typed` 中，输入以 `:` 开头且第二个字符不是 `/` 时：
  - 若匹配 `:[0-3]:<path>`，取对应 stage；否则取 stage 0，`<path>` 为冒号后的全部内容。
  - `<path>` 以 `./` 或 `../` 开头时相对当前目录解析为仓库相对路径，否则视为仓库相对路径（与 Git `resolve_relative_path` 一致）。
  - 读取当前请求作用域 worktree 的 index，返回匹配条目的对象 id。
  - 路径不在 index → `LBR-CLI-003`，消息说明路径不在 index 中；stage 0 缺失但存在其它 stage → `LBR-CLI-003`，消息说明「is in the index, but not at stage 0」。
  - 所有经 `resolve_object_spec_typed` 的消费者（`rev-parse`、`cat-file`、`show` 等）同时获得该语法；`<rev>:<path>` 行为不变。
- **Alternatives considered:** 只在 `rev-parse` 中实现——`cat-file -p :foo` 等常见用法仍失败，且违反 GC-02，拒绝。
- **Consequences:** 对象规格解析需要读取 index；只在 `:` 开头时读取，其它规格不产生额外 I/O。
- **Revisit when:** 需要支持 `--index-file` 覆盖。

### ADR-PL-04: `:/<regex>` 与 `<rev>^{/<regex>}`

- **Status:** Accepted
- **Context:** GAP-03；git `object-name.c:1183-1233`。
- **Decision:**
  - **起点：** `:/` 以全部本地 refs 加 `HEAD` 为起点，`<rev>^{/}` 以 `<rev>` 为起点。
  - **遍历顺序：** 按提交时间最新优先遍历祖先。
  - **匹配范围：** 对提交消息（头部之后空行以后的全部内容）做正则匹配，返回第一个匹配的提交。
  - **前缀：** `!-` 取反；`!!` 表示字面 `!`；其它 `!` 开头为错误。
  - **正则引擎：** 使用 `regex` crate，设置编译大小上限；无效正则或无匹配 → `LBR-CLI-003`。与 POSIX ERE 的语法差异（反向引用等）在文档中登记。
  - **结果：** 为提交，可用于所有 commit-ish 消费者。
- **Alternatives considered:** 调用系统 `grep` 或 PCRE——引入外部依赖或回溯风险，拒绝。
- **Consequences:** 最坏情况遍历全部历史（只读提交对象，不加载 tree）；性能预算见 RV-02。
- **Revisit when:** 需要 `grep.patternType` 等配置。

### ADR-PL-05: `update-index` 批量输入

- **Status:** Accepted
- **Context:** GAP-04；git `builtin/update-index.c:1020-1035`。
- **Decision:**
  - `--stdin` 读取路径列表，行分隔（配 `-z` 为 NUL 分隔），按与位置参数相同的规则处理（受 `--add`/`--remove` 约束）。
  - `--index-info` 接受三种行格式：
    - `<mode> SP <oid> TAB <path>`；
    - `<mode> SP <type> SP <oid> TAB <path>`；
    - `<mode> SP <oid> SP <stage> TAB <path>`。
  - `mode` 为 `0` 时删除该路径的全部 stage；插入非零 stage 条目时的 stage-0 处理按 git 实跑结果登记并测试。
  - 全部输入解析并应用于内存 index，最后保存一次；任一行格式错误 → 128，不保存。
  - 输入逐行流式读取，不整块读入内存。
- **Alternatives considered:** 逐行立即保存——失败时留下部分写入，拒绝。
- **Consequences:** 与 Git 一致：失败时 index 保持原样。
- **Revisit when:** 需要支持 `--index-version`。

### ADR-PL-06: `update-index` refresh

- **Status:** Accepted
- **Context:** GAP-05；`add --refresh` 已有 refresh 实现（`add.rs:1269`、`:1310`）。
- **Decision:**
  - 把 refresh 候选筛选与 stat 刷新抽成 `src/command/add.rs` 与 `update_index.rs` 共用的 helper（GC-02）。
  - `--refresh` 对内容已修改的条目在 stdout 输出 `<path>: needs update`；存在需要更新的条目时 exit 1。
  - `-q` 不输出并 exit 0；`--ignore-missing` 跳过工作树缺失的条目；`--unmerged` 对未合并条目不报 `needs merge`。
  - `--really-refresh` 在 DEFER-02 落地前等同 `--refresh`（文档登记）。
- **Alternatives considered:** 在 update-index 内重写 refresh——违反 GC-02，拒绝。
- **Consequences:** `add.rs` 被修改，UI-02 命中 T-1。
- **Revisit when:** DEFER-02 落地。

### ADR-PL-07: `update-ref --stdin`

- **Status:** Accepted
- **Context:** GAP-09；git `builtin/update-ref.c:318-689`。
- **Decision:**
  - 支持 `update`、`create`、`delete`、`verify`、`option no-deref`，以及 `start`/`prepare`/`commit`/`abort` 事务命令；`start`/`prepare`/`commit`/`abort` 按 Git 在 stdout 输出 `<cmd>: ok`。
  - 无显式事务命令时，整个输入为一个事务。
  - 全部更新在一个 SQLite 写事务内执行（复用 `update_ref.rs:190` 的事务模式），逐 ref 写 reflog（`-m` 作为消息）。
  - 同一 ref 出现多次更新 → fatal 128。
  - `-z` 按 Git 的 NUL 格式解析。
  - ref 范围沿用 `refs/heads/*`：其它 ref 与 `symref-*` 命令 → `LBR-CLI-003`/129 并说明范围（DEFER-04）。
  - `--no-deref` 与 `option no-deref` 被接受；由于范围内的 ref 均非符号引用，二者不改变结果（文档登记）。
- **Alternatives considered:** 只支持隐式单事务——`t1400` 大量用例依赖 `start`/`prepare`，拒绝。
- **Consequences:** 任何一行失败都回滚整个事务。
- **Revisit when:** DEFER-04 扩展 ref 范围。

### ADR-PL-08: `symbolic-ref -d`

- **Status:** Accepted
- **Context:** GAP-08；Libra 只存在 `HEAD` 一个符号引用。
- **Decision:**
  - `symbolic-ref -d HEAD` → fatal 128：`deleting 'HEAD' is not allowed`（与 Git 一致）。
  - `-d <其它名称>` → fatal 128：`Cannot delete <name>, not a symbolic ref`。在 Libra 中该陈述恒为真；Git 用例中创建并删除 `NOTHEAD` 的形态不可移植，登记为有意差异。
  - `-q` 与 `-d` 组合时的输出按 git 实跑登记。
- **Alternatives considered:** 继续拒绝 `-d`——脚本与 `t1401` 的 `HEAD cannot be removed` 需要该 flag 存在，拒绝。
- **Consequences:** `-d` 在 Libra 中永远不会删除任何东西。
- **Revisit when:** DEFER-04 支持非 `HEAD` 符号引用。

### ADR-PL-09: plumbing diff 输出与退出码

- **Status:** Accepted
- **Context:** GAP-07。Git plumbing diff 默认 exit 0，`--exit-code`/`--quiet` 有差异时 exit 1；Libra `diff-files` 默认 exit 1，且没有 `--exit-code`。
- **Decision:**
  - `diff-files`、`diff-index`、`diff-tree` 增加 `--name-only`、`--name-status`、`--exit-code`，复用 `diff.rs` 已有的渲染（`:5180-5185`），不复制格式化逻辑。
  - 默认退出码改为 0；有差异且带 `--exit-code` 或 `--quiet` 时为 1；错误仍为 128。
  - 这是公开行为变化，四处文档与 `COMPATIBILITY.md:230` 登记。
  - TC-0021 中 `add --refresh bar` 的 stdout 断言：Libra 输出 `refreshed 1 file`，与上游「stdout 为空」不同。本卡不改 `add` 输出，TC-0021 移植测试以 `add --refresh -q bar` 或只断言退出码与 index 效果登记该差异（DEFER-05）。
- **Alternatives considered:** 保持默认 exit 1——TC-0021 与所有 `diff-files ... &&` 的 Git 脚本都会中断，拒绝。
- **Consequences:** 依赖旧 exit 1 的调用方需改用 `--exit-code`。
- **Revisit when:** 无。

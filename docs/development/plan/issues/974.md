## 文档职责

### 适用范围

`merge` 生成的合并提交标题与 shortlog 标头对「目标引用的类型」的装饰：本地分支 → `Merge branch '<name>'`；tag → `Merge tag '<name>'`；裸 commit（OID/`FETCH_HEAD` 等非命名引用）→ `Merge commit '<sha>'`；远程跟踪分支 → `Merge remote-tracking branch '<remote>/<branch>'`；shortlog 标头同步使用同一装饰标签（`* tag 'c3':` 而非 `* c3:`）。覆盖 `merge_message::default_message`、`merge` 的标题构造与 `--continue` 回落路径，以及 octopus 的多目标标题。

### 成功定义

- 合并本地分支 `left` 时标题逐字为 `Merge branch 'left'`（无 ` into <head>` 后缀）。
- 合并 annotated/lightweight tag `c2` 时标题逐字为 `Merge tag 'c2'`。
- 合并裸 OID `<sha>` 时标题逐字为 `Merge commit '<sha>'`。
- 合并远程跟踪分支 `origin/x` 时标题逐字为 `Merge remote-tracking branch 'origin/x'`。
- shortlog 段头与标题**共享分类结果、但各自渲染**：标题走 `decorated_label`；段头走 `section_label(kind, literal_argument)`（branch 无前缀、commit 保留字面参数、annotated tag 折入消息）。
- `--continue` 在状态中无消息时回落到同一装饰规则（不再产生 `Merge <ref> into <head>`）。
- 显式 `-m`/`-F` 仍完全覆盖自动标题；`--no-ff`/fast-forward 判定与既有输出不变。

## 已决议设计决策

### ADR-I974-01：目标类型分类在解析引用时确定，随目标传递

- **Status:** Accepted
- **Context:** `resolve_merge_target`（`src/command/merge.rs:4637-4648`）已区分 `refs/remotes/*` 与其它引用，但未返回类型；标题构造处（`src/command/merge_message.rs:17`、`src/command/merge.rs:4330`、`src/command/merge.rs:2075`）各自拼字符串。
- **Decision:** 引入 `MergeTargetKind { Branch, Tag, RemoteTracking { remote }, Commit }`（由 `MergeTarget` 携带原始 tag OID 与可选 `tag_message`） 与 `decorated_label(name) -> String`（标题：`branch 'x'` / `tag 'x'` / `remote-tracking branch 'o/x'` / `commit '<sha>'`）与 `section_label(kind, literal) -> String`（段头：branch 无前缀 / `tag 'x'` / `remote-tracking branch 'o/x'` / `commit '<literal>'`）；`resolve_merge_target` 返回 `MergeTarget { kind, oid, tag_message }`：标题用 `decorated_label`，shortlog 段头用 `section_label`。
- **Alternatives considered:** 在渲染处按前缀猜类型（会把名为 `v1` 的分支误判为 tag）。
- **Consequences:** 分类唯一（旧 `MergeState` 无 kind 时按 OID 确定性归为 `Commit`）；标题与段头各自渲染（`decorated_label` / `section_label`）；`--continue` 回落复用同一分类结果。
- **Revisit when:** Git 增加新的引用类别装饰（例如 `Merge notes 'x'`）。

### ADR-I974-02：默认目的地抑制后缀，detached HEAD 例外

- **Status:** Accepted
- **Context:** TC-1809 记录 Git 期望 `Merge tag 'c2'`，而 libra 现为 `Merge c2 into main`（`tc1809-merge-squash.sh:21`）。
- **Decision:** 三种条件（与 Git 2.56 `fmt-merge-msg` 一致）：① 目的地=当前分支（默认）⇒ `Merge {decorated_label}`，无后缀；② 目的地≠当前分支或 `--into-name=<other>` ⇒ `Merge {decorated_label} into <name>`；③ detached HEAD ⇒ `Merge {decorated_label} into HEAD`。
- **Alternatives considered:** 恒保留后缀（与 Git 不符）；恒删除（会破坏 `--into-name` 既有用例）。
- **Consequences:** `--into-name` 行为不变，默认面与 Git 对齐。
- **Revisit when:** Git 改回默认带后缀。

### ADR-I974-03：无法分类的引用 fail-closed 为 `Merge commit '<sha>'`

- **Status:** Accepted
- **Context:** `merge FETCH_HEAD`、裸完整 OID、`refs/notes/*` 等既不是分支也不是 tag 的引用；`FETCH_HEAD` 的内容是 OID，因此按 commit 目标渲染完整 SHA。
- **Decision:** 不是 `refs/heads/*`、不是 tag、不是 `refs/remotes/*` 的目标一律归为 `Commit` 并用**完整 OID（按 object format）** 渲染 `Merge commit '<full-sha>'`（与 Git `fmt-merge-msg` 一致；短 SHA 只用于人类可读摘要，不得进入标题）。
- **Alternatives considered:** 保留原始输入串（会产生 `Merge FETCH_HEAD` 这类非 Git 形态）。
- **Consequences:** 非命名目标有确定形态。
- **Revisit when:** N/A。

### ADR-I974-04：shortlog 段头复用同一分类，并折入 annotated tag 消息

- **Status:** Accepted
- **Context:** Issue #974 评论 TC-1803（对齐上游 `t/t7604-merge-custom-message.sh#3`）要求 `--log` 追加段的段头同样带引用种类前缀，且 annotated tag 的 tag 消息要折入段头之上。
- **Decision:** `--log` 段头规则：branch → `* <branch>:`（无前缀）；tag → `* tag '<tag>':`；remote-tracking → `* remote-tracking branch '<o/x>':`；commit → `* commit '<literal-argument>':`（保留用户字面参数，如 `c2^{commit}`）；annotated tag 额外把 tag 消息正文折入段头之前的段落。
- **Alternatives considered:** 段头恒用原始参数（现状，与 Git 不符）。
- **Consequences:** 与 Git 2.56 的 `t7604#3` 逐字节对齐；plain tag 不折入消息。
- **Tag object 读取方案:** `resolve_merge_target` 在 peeling 前保留 ref 目标的原始 OID（`refs/tags/<name>` 指向的 tag object），对 annotated tag 额外执行一次 `load_object_raw(&tag_oid)`（`src/command/merge.rs:28` 已导入，O(1)、单对象、无遍历）取 `tag` 消息正文；读取失败按 fail-closed 返回带上下文的 既有 `PullMergeError::ObjectLoad`（Display 携带 tag 名与底层错误文本），不静默省略消息。lightweight tag 不触发该读取。
- **Revisit when:** Git 改动 `fmt-merge-msg` 的段头格式。

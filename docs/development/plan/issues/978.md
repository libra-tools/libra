> 模板 v2.16。[Issue #978](https://github.com/libra-tools/libra/issues/978) OPEN。仅规划，未授权执行；`I978-01` 为 `pending` / Acceptance 空。Git 对照 pin `6de20f6092dcf9bdb1c8efe03db4b70c82b423dd`。基线 `Cargo.toml` `0.30.173`（`Cargo.toml:3`）；实测 system `libra 0.30.173`。测试用例仓 `/mnt/gitmono/libra-testcases` 本计划不修改。

## 文档职责

### 适用范围

`branch.<name>.mergeOptions` 在 `libra merge` 上的读取与套用：当当前分支为 `<name>` 时，把该配置值按 Git 规则切分为命令行选项令牌，并以「低于显式 CLI flag」的优先级套用到 `merge` 的解析结果上（例：`branch.main.mergeOptions = --no-ff` 使裸 `libra merge left` 产生合并提交；`= --squash` 使其产生 staged-only 结果）。覆盖新增的 typed reader（沿用 `src/command/history_config.rs` 既有范式）、`MergeArgs` 的 CLI-优先覆盖链，以及非法值与未知选项的 fail-closed 诊断。

### 非目标

不实现以 `-` 开头的配置值的底层解析缺陷（`issues/817.md`，属配置值解析轴；本卡在其修复后自然可用，并在其未修复时按 `DEFER-I978-01` 记录 `blocked` 语义）。不实现 `--no-squash` 参数面（`issues/984.md`），但套用时允许该令牌（其可用性由 #984 决定，见 `DEFER-I978-02`）。不改 `merge.ff`/`merge.log`/`merge.verifySignatures` 的既有 reader 语义。不改合并算法、消息渲染（`issues/974.md`/`issues/977.md`）、`--continue`/`--abort` 状态机；不修改测试用例仓。

### 成功定义

- `branch.<current>.mergeOptions = "--no-ff"` 时，裸 `libra merge <branch>` 产生合并提交（`HEAD` 有两个父提交），与显式 `--no-ff` 一致。
- `branch.<current>.mergeOptions = "--squash"` 时，裸 `libra merge <branch>` 产生 staged-only 结果（`HEAD` 不前移），与显式 `--squash` 一致。
- 显式 CLI flag 始终优先于配置（`mergeOptions=--no-ff` + 显式 `--ff` → fast-forward；`mergeOptions=--squash` + 显式 `--no-squash` → 合并提交，依赖 #984）。
- 非当前分支的 `mergeOptions` 不影响本次合并。
- 含未知选项令牌或非法引号的值 fail-closed：非零退出且提示指向 `branch.<name>.mergeOptions`。
- 无该配置时行为与改动前逐字节/逐状态一致。

## 已决议设计决策

### ADR-I978-01：`mergeOptions` 走与 `merge.ff`/`merge.log` 相同的 typed reader 范式

- **Status:** Accepted
- **Context:** `src/command/history_config.rs:36-71` 的 reader 均以 `read_value(key)`（`:94-101`）为基础并返回 typed 结果或 `HistoryConfigError`；分支作用域键在他处已用 `format!("branch.{}.merge", name)` 拼装（`src/command/clone.rs:2017`）。
- **Decision:** 新增 `pub(crate) async fn branch_merge_options(branch: &str) -> Result<Vec<String>, HistoryConfigError>`，键为 `branch.<branch>.mergeOptions`；无值返回空 `Vec`；读取错误映射 `Read`，令牌切分失败映射 `Invalid`（`expected = "a space-separated option list"`）。
- **Alternatives considered:** 在 `merge.rs` 内直接 `ConfigKv::get`（绕过 strict reader，错误形态不一致）。
- **Consequences:** 错误形态与既有 reader 一致；可单测。
- **Revisit when:** Git 引入 `mergeOptions` 之外的等价键（如 `merge.autoSquash`）。

### ADR-I978-02：令牌切分按 Git 的引号规则，未知选项 fail-closed

- **Status:** Accepted
- **Context:** Git 的 `mergeOptions` 是按 shell 风格引号切分的选项列表；无法识别的选项在 Git 里同样报错。
- **Decision:** 用与 `src/command/history_config.rs` 现有解析等价的轻量切分（支持双引号包裹的含空格令牌），把结果作为 clap 参数向量解析进一份**新的** `MergeArgs` 基线；任一令牌不被 `MergeArgs` 接受则返回 `Invalid`，诊断文本包含 `branch.<name>.mergeOptions` 与 offending token。
- **Alternatives considered:** 忽略未知令牌（会静默改变用户预期）；只支持布尔开关（覆盖面不足）。
- **Consequences:** 配置错误可定位；不会静默降级。
- **Revisit when:** 需要支持 `--strategy-option` 之类带 `=` 的复合令牌（当前 clap 已可解析，不需特例）。

### ADR-I978-03：优先级为「默认 < 配置 < 显式 CLI」

- **Status:** Accepted
- **Context:** `src/command/merge.rs:1288-1313` 已确立「`args.X` 优先，否则读配置」的范式（`log`、`ff`）。
- **Decision:** 先解析 CLI 为 `cli_args`；若某开关**未**在命令行显式出现（借助 `ArgMatches::contains_id` 或等价的「是否显式设置」布尔），才用配置值填充；显式 CLI 永远获胜。为此 `MergeArgs` 的布尔字段需按需追加「explicit」陪伴位，或在 `run_merge` 入口用 `clap::ArgMatches` 判定后回写，禁止用「字段为 false」推断「未设置」。
- **Alternatives considered:** 只比较字段默认值（无法区分 `--ff` 显式与默认 false）。
- **Consequences:** 覆盖链可机械验证；不误判显式 flag。
- **Revisit when:** clap 升级改变 `contains_id` 语义。

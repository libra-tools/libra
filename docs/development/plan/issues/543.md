## 文档职责

本文处理 #543 正文、全部 28 条评论与当前源码共同证明仍成立的 `read-tree` 缺口。后写评论主要是 cherry-pick/revert/rebase 测试在 setup 的 `git read-tree -u --reset HEAD` 处级联中止；本计划只交付 read-tree 本身，不把后续 sequencer 行为包装成 read-tree 卡。

新建或推进本计划时，协调者在同一变更中更新 [`plan-status.md`](../plan-status.md)（状态、版本/提交、`YYYY-MM-DD HH:MM:SS UTC`）。行号和外部结果锚点在每卡开工当天按 ER-02 刷新。

### 适用范围

- 单 tree-ish `read-tree` 的 `--reset`（index reset）、`-u`（工作树更新）、`-n`（dry-run）与 `--prefix=<prefix>`（前缀读取）。
- 评论直接点名的命令形态：`read-tree -u --reset HEAD`、`read-tree --reset -u HEAD`、`read-tree -n --reset -u HEAD`、`read-tree --quiet -m -u HEAD simple` 中的 `-u` 阻塞，以及正文 `--prefix` 拒绝。
- 工作树更新的覆盖政策、file/dir 切换、符号链接/mode、失败回滚、linked-worktree scope 与 `--index-file` 的明确组合合同；Git 已探针的 reset 覆盖场景按实测处理，其余以开工对照为前置。
- `src/command/read_tree.rs`、必要的 `src/internal/tree_plumbing.rs` 与复用/抽取的 guarded worktree helper；`tests/command/read_tree_test.rs`。
- EN、zh-CN、网站、开发文档、`COMPATIBILITY.md:241`、`docs/development/commands/README.md:82` 与 `--help` examples 同卡同步。
- 80 个评论引用且存在于 0.30.91 `summary.tsv` 的 TC 的公开复跑归因；不要求它们全部因本计划而 PASS。

### 非目标

- 不实现或修改 cherry-pick/revert 的 advice、`could not apply ...` 文案、`CHERRY_PICK_HEAD`/`REVERT_HEAD`、`--continue`/`--abort`/`--skip`/`--quit`、signoff/`-s`/`-x` footer、empty persistence、sequencer opts 或 auto-maintenance。正文场景 2 和评论 5–28 的后续断言均属这些命令，登记 DEFER-RT-01。
- 不实现完整多树 `read-tree -m` merge。TC-3157 的 `read-tree --quiet -m -u HEAD simple` 有两个 tree-ish；当前命令只接受一个，且 `COMPATIBILITY.md:241` 明确多树 deferred。本计划解除 `-u` 的首个阻塞，但不承诺 TC-3157 全绿，登记 DEFER-RT-02。
- 不修改 porcelain `reset --hard/--merge/--keep` 的公开行为；只允许为 `-u` 复用或抽取既有 guarded worktree 算法，且 reset 既有回归必须不变。
- 不处理 rebase detached-HEAD 拒绝、TC-2441 中止、t3510 #56/#57 auto-maintenance 或 `checkout -f conflicting^0` 的标签缺失本身；它们是级联或独立命令缺口（DEFER-RT-03）。
- 不扩展 `write-tree --prefix`、index `:/<text>`/`":<path>"` 或 #479 的其它 plumbing 范围。
- 不把全局 `--quiet` 当作新 read-tree 选项重复实现：根 CLI 已有 `quiet` 字段（`src/cli.rs:286`）；只需验证组合不分叉输出。
- 不新增稳定错误码、schema、配置、`--test` target 或共享测试基建，不改 `src/cli.rs` 命令注册。

### 成功定义

- `--reset`、`-u`、`-n`、`--prefix` 分别有独立实现卡；Git 精确句法、组合限制、输出与退出码均由开工时系统 git 复核固定。
- `read-tree -u --reset HEAD` 能完成评论中 setup 所需的 index+worktree 更新；对本机探针的 tracked 修改与 untracked 目标冲突按 Git 覆盖，失败路径按规定恢复并明确报告恢复失败。
- `-n --reset -u HEAD` 做完整验证但不写 index、worktree、对象库或操作记录；`--prefix` 只改变 index 视图，未显式 `-u` 时不触工作树。
- 文本静默、全局 `--quiet`、JSON/machine、`--index-file` 与 linked worktree 的行为有明确测试；无新稳定错误码。
- 四张实现卡各自完成 ER-04 C/D 和 patch 发布；RT-05 对 80 个 TC 逐行记录 verdict 与首个剩余阻塞方。任何仍由本计划四个选项导致的 FAIL 都是本计划缺陷。
- 文档不再把已交付选项写成 deferred，同时保留多树 merge 与 sequencer 的真实边界；不把 setup 通过等同于上游整例通过。

## 已决议设计决策

### ADR-RT-01：先 `--reset`，再 `-u`，再 `-n`

- **Status:** Accepted
- **Context:** 评论的核心 setup 是 `read-tree -u --reset HEAD`，TC-2558 又加 `-n`。三者共享同一目标状态计算，但分别是 index reset、工作树更新、无写验证三个行为轴。
- **Decision:** RT-01 定义单 tree reset 的 index 结果；RT-02 消费该结果并加入 guarded worktree 更新；RT-03 对同一计划 dry-run。不得先做一个忽略 `--reset` 的 `-u`，也不得让 dry-run 另算一套目标。
- **Alternatives considered:** 三选项一卡：参数、写工作树、无写恢复是三个独立恢复轴，违反 G-01。只做 `-u` 而把 reset 当 alias：会丢失 unmerged/组合语义，拒绝。
- **Consequences:** 三卡同文件串行；每卡独立发布。
- **Revisit when:** 系统 git 复核证明评论之外必须扩大组合矩阵。

### ADR-RT-02：`-u` 的覆盖政策与失败恢复分开设计

- **Status:** Accepted
- **Context:** 当前 read-tree 从不写工作树；本机 Git 2.56.0 探针表明 `--reset -u` 可覆盖目标路径上的 tracked 修改和同名 untracked 文件。reset.rs 的快照/恢复可借鉴，但它自己的冲突防护政策不能直接套给 read-tree；legacy `restore_worktree` 也不能直接当作完整更新/恢复实现。
- **Decision:** 以「旧 index + 目标 index + 当前 worktree」生成更新计划，按本机探针及开工补充的 Git 金样选择覆盖或拒绝。只复用经核实适用的 reset 规划/应用机制；扩展或抽取对**实际工作树**的快照，保存将被覆盖的 dirty tracked 与 untracked 字节、对象类型、symlink 目标、目录层次及 mode，不能用旧 index blob 代替，也不能沿用拒绝 untracked 快照的代码。首写前完成所有适用预检和快照，否则拒绝写入；写入期失败尽力恢复实际快照和旧 index 并返回非零。恢复失败明确报告未恢复路径、残留与可操作修复指引；不承诺断电/进程崩溃绝对原子。
- **Alternatives considered:** 直接套用 reset 的 untracked/local-change 拒绝策略：与已测 Git `--reset -u` 覆盖相冲突，拒绝。调用 porcelain `reset --hard`：会移动 HEAD、改变操作日志或 sequencer 语义，拒绝。无快照地逐条 `restore_worktree`：不能实现所需故障恢复，拒绝。
- **Consequences:** RT-02 写集较其它卡大但仍为 M；与 reset/tree_plumbing 写者串行；测试和用户文档须明确潜在数据覆盖，必须故障注入。
- **Revisit when:** 未来统一 checkout/reset/read-tree 的 worktree transaction API。

### ADR-RT-03：`-n` 验证同一计划但不产生副作用

- **Status:** Accepted
- **Context:** TC-2558 使用 `-n --reset -u HEAD`，仅接受 clap 选项而继续写状态会造成危险假象。
- **Decision:** dry-run 执行 tree-ish 解析、index 构造和 RT-02 的适用预检，但不保存 index、不写工作树、不写对象或操作记录；对已探针的 untracked 冲突，真实命令与 dry-run 均成功，dry-run 不覆盖。其它成功/拒绝例须逐项对照系统 git，不假设所有冲突均拒绝。输出内容以系统 git 复核为准；Libra JSON 只能在成功后返回预览计数并明确无写。
- **Alternatives considered:** 在接受参数后直接返回 0：会掩盖真实命令会拒绝的其它错误，拒绝。调用真实更新后回滚：有副作用与崩溃窗口，拒绝。
- **Consequences:** 需要前后状态哈希与操作记录零变化测试。
- **Revisit when:** dry-run 扩展到多树 merge。

### ADR-RT-04：`--prefix` 只实现单树前缀读取，不多树化

- **Status:** Accepted
- **Context:** 正文只证明 `--prefix` 被拒绝，没有给 TC 或完整组合矩阵；当前 `-m` 只是单树叠加。
- **Decision:** 开工用系统 git 复核单树 `--prefix=<prefix> <tree-ish>` 的路径规范化、保留前缀外 index、未合并条目、空/缺失前缀及错误退出码，再固定 AC 金样。实现只构造目标 index；未显式 `-u` 不写工作树。多树与复杂组合仍 DEFER-RT-02。
- **Alternatives considered:** 按 `write-tree --prefix` 的语义反推：两个命令方向相反，不能互抄，拒绝。接受参数后把 tree 错放到根目录：静默数据错误，拒绝。
- **Consequences:** #543 的原始 `--prefix` 场景以本地金样为证据，RT-05 不虚构 TC。
- **Revisit when:** 有上游 TC 或多树 prefix 需求。

### ADR-RT-05：级联用例按「首个剩余阻塞方」归因，不要求全 PASS

- **Status:** Accepted
- **Context:** 评论自己说明 cherry-pick 后续行为尚未运行；修 read-tree 后才会暴露真正结果。
- **Decision:** RT-05 读取新公开结果，凡 FAIL 仍由本计划四个选项引起则开 FIX；若进入 cherry-pick/rebase/maintenance/多树等已登记边界，则如实记 FAIL+阻塞方，不宣称本计划使其通过。
- **Alternatives considered:** 把评论中的全部 acceptance 复制成 RT-02 的 AC：会造成多轴巨型卡并伪造归属，拒绝。只挑会 PASS 的 TC：违反追溯完整性，拒绝。
- **Consequences:** 计划完成不等于 80 个 TC 全 PASS，也不等于 #543 可关闭；多树/未映射场景仍需维护者确认。
- **Revisit when:** 后续命令计划交付并产生新结果。

### 既有模块的 ER-04 A 组回归

不得把以下各模块放进同一 Bash 块，也不得把它们用单个组合 selector 误报为全通过。每条命令均须在独立 Bash 进程执行、生成 GC-RT-09 的新临时配置、单独记录自己的日志，配置不存在即 fail-closed。采用 `run_543_module` 封装每次调用；每个调用实际计为各自的一条独立命令，日志中核对该模块的测试数、PASS 和 skip，不能由后续模块覆盖计数。依赖的 shell 函数：

```bash
run_543_module() (
  set -euo pipefail
  local label="$1" root_tmp parent_tmp private_tmp log tmpdir cfg
  local -a spec=("${@:2}")
  root_tmp="$(pwd -P)"
  parent_tmp="$(cd "${TMPDIR:-/tmp}" && pwd -P)"
  case "$parent_tmp/" in "$root_tmp"/*) exit 1 ;; esac
  private_tmp="$(mktemp -d "$parent_tmp/libra543-module.XXXXXXXX")"
  chmod 700 "$private_tmp"
  private_tmp="$(cd "$private_tmp" && pwd -P)"
  case "$private_tmp/" in "$root_tmp"/*) exit 1 ;; esac
  log="$private_tmp/${label//[^A-Za-z0-9_]/_}.log"
  tmpdir="$(mktemp -d "$parent_tmp/libra543-nojunit.XXXXXXXX")"
  chmod 700 "$tmpdir"
  tmpdir="$(cd "$tmpdir" && pwd -P)"
  case "$tmpdir/" in "$root_tmp"/*) exit 1 ;; esac
  cfg="$tmpdir/nextest.toml"
  trap 'rm -f -- "$cfg"; rm -f -- "$log"; rmdir -- "$tmpdir"; rmdir -- "$private_tmp"' EXIT
  test ! -e "$cfg" && test ! -L "$cfg"
  (set -o noclobber; grep -v -x -F -e '[profile.default.junit]' -e 'path = "junit.xml"' .config/nextest.toml > "$cfg")
  test "$(grep -c -x -F '[profile.default.junit]' "$cfg" || true)" = 0
  test "$(( $(wc -l < .config/nextest.toml) - $(wc -l < "$cfg") ))" = 2
  source .env.test
  cargo nextest run --config-file "$cfg" --no-tests=fail "${spec[@]}" >"$log" 2>&1
  pass_count="$(grep -c -E '^[[:space:]]*PASS[[:space:]]+' "$log" || true)"
  skip_count="$(grep -c -E '^[[:space:]]*SKIP[[:space:]]+' "$log" || true)"
  summary="$(rg -E '^[[:space:]]*[0-9]+ (passed|failed|skipped)' "$log" | tail -n 1)"
  printf 'module=%s PASS=%s SKIP=%s summary=%s\n' "$label" "$pass_count" "$skip_count" "$summary"
  test "$pass_count" -ge 1
  test "$summary" != ""
  sed -e "s|$root_tmp|REPO|g" -e "s|$tmpdir|TMP|g" -e "s|$private_tmp|PRIVATE|g" "$log" | grep -E '^[[:space:]]*(PASS|FAIL|SKIP)[[:space:]]+|^[[:space:]]*[0-9]+ (passed|failed|skipped)'
)
```

### 故障恢复矩阵

| 故障点 | 可接受残留 | 恢复动作 | 禁止结果 |
|---|---|---|---|
| tree-ish/prefix 解析失败 | 无 | 写入前返回错误，原 index/worktree 不变 | 部分替换 index |
| `--reset -u` 的已探针 tracked 修改或目标同名 untracked 碰撞 | Git 语义允许以目标内容覆盖这些路径 | 按已探针合同更新；文档明确覆盖风险；不碰无关路径 | 套用 porcelain reset 的拒绝政策，或超出目标 scope 写入 |
| `-u` 写入期 IO/故障注入 | 恢复过程本身的明确错误可报告；不得隐瞒 | 按快照恢复旧 index/worktree，返回非 0；恢复失败给 doctor/修复指引 | 半写却输出成功 JSON |
| `-n` 路径 | 无任何持久残留 | 只预检并返回结果 | 写后回滚、遗留 scratch/op log |
| linked worktree | 其它 scope 完全不变 | 仅当前 scope；失败按同一恢复 | 写 main/shared index 或其它 worktree |
| helper 抽取导致 reset 回归 | 当前卡不得发布 | 修 helper 或撤回未提交抽取，重跑 reset/全量 | 为 read-tree 改 reset 公开语义 |
| 公开复跑仍由四选项失败 | RT-05 blocked，相关 FIX | 新建 FIX、前滚版本、重新复跑 | 把失败归为 cherry-pick 而不看 detail |
| 公开复跑进入下游缺陷 | 如实 FAIL+DEP | 交 cherry-pick/rebase/多树计划 | 在 RT 卡顺手修下游 |

## 文档职责

issue #473 写于 libra 0.22.5。本计划在 libra 0.22.28（本机安装版本即当前源码版本）与 git 2.54.0 上并排实跑三轮，逐条复核 6 个条目与 2 条「Test gaps」，结论如下：

- **已修复或断言不成立：**
  - 条目 2 部分变化：Libra 已在换格式 reinit 时输出 `warning: ignoring --object-format ...`，但仍 exit 0 并保留原格式；
  - 条目 4、5、6 的核对结论成立（`--shared=group` 目录为 `2775`、嵌套 init、模板 top-up），作为回归守卫保留；
  - 条目 1 的「无迁移说明」部分不成立：`docs/commands/init.md` 已说明移除原因与 Libra 旧分离布局迁移，但缺 Git `gitdir:` 布局的迁移路径，`COMPATIBILITY.md` 也未登记；
  - 「Test gaps」中「`--recurse-submodules` 未文档化」不完全成立：`COMPATIBILITY.md` init 行已写 recursive submodule init 不支持。
- **确认的缺口：** 换格式 reinit 不 fail-closed；参数错误退出码 129（Git 128）；`--separate-git-dir` 拒绝时提示误导；`t0001-init` 覆盖缺口。
- **issue 未列出、风险更高的新发现：**
  - 空模板 `--template=` 会把当前目录递归复制进 `.libra`（实测 80 层嵌套），最终以 `File name too long` 失败并留下大量垃圾；
  - `--shared=all` 把目录与 `libra.db` 设为全局可写（`2777`/`0777`），普通文件被赋予目录位（`info/exclude` 为 `2775`、`libra.db` 为 `0775`）；
  - init 之后新写入的对象、`COMMIT_EDITMSG`、操作指针为 `0600`，group 共享实际无效；
  - Git 文件式数字模式（`0660`/`0640`/`0600`）被拒，`--shared` 无值被拒，`0775` 不规范化；
  - `GIT_TEMPLATE_DIR`、`init.templateDir`、`GIT_DEFAULT_HASH`、`init.defaultObjectFormat` 全部被忽略；
  - `.libra` 为普通文件时先打印 `Reinitializing` 再以 I/O 错误失败；
  - `--from-git-repository` 不接受 `.git` 为 `gitdir:` 指针文件的 Git 工作树（恰是 `--separate-git-dir` 用户的迁移入口）；
  - `--ref-format` 的取值（`strict`/`filesystem`）与 Git（`files`/`reftable`）语义不同，issue 所称「参数面对齐」不成立。

本计划按风险排序交付 12 张卡：
1. **Phase 1（数据与状态安全）：** IN-01、IN-03、IN-02。
2. **Phase 2（共享权限）：** IN-04..IN-07。
3. **Phase 3（默认来源）：** IN-08、IN-09。
4. **Phase 4（Git 布局迁移与有意差异）：** IN-10、IN-11。
5. **Phase 5（覆盖收口）：** IN-12。

「Test gaps」第二条（`clone --depth` 测试）属于 [#474](https://github.com/libra-tools/libra/issues/474)，由其计划承接（DEP-IN-09）。

本文只规划任务，不宣称实现完成。落地时每个任务都必须先刷新源码锚点，再按任务卡验收。

### 适用范围

- 空模板与模板源安全；模板来源 `--template` > `GIT_TEMPLATE_DIR` > `init.templateDir`（含 `~` 展开）。
- reinit 时对象格式不一致的 fail-closed；存储路径存在但不是目录时的检测。
- `--shared` 取值解析与持久化（无值、`umask`/`group`/`all`、Git 文件式数字模式、owner 读写校验）、权限计算（文件与目录分别计算、setgid）、init 之后新写入文件对 `core.sharedRepository` 的遵循。

- `t0001-init`、`t1301-shared-repo` 的迁移账本与可移植用例。
- 同步：`docs/commands/init.md` EN + zh-CN、`docs/development/commands/init.md`、`docs/development/commands/_compatibility.md`、`COMPATIBILITY.md` init 行、`docs/error-codes.md`（仅示例列）、`../libra-backend` 网站文档。

### ADR-IN-03: 模板来源与空模板

- **Status:** Accepted
- **Context:** GAP-01、GAP-08；git `setup.c:2242`、`:2263`、`:2291`、`:2360`；`t0001:176-216`。
- **Decision:**
  1. **空模板：** `--template=`（空值）表示不使用任何模板，不复制内置 hooks 与 `info/exclude` 默认内容，只创建仓库必需结构。
  2. **自引用防护：** 模板目录与目标存储目录相同则拒绝（129，零写入）；模板目录是目标存储目录祖先时，复制跳过目标存储子树。
  3. **来源优先级：** `--template` > `GIT_TEMPLATE_DIR` > `init.templateDir`（local→global→system 严格读取，沿用 `init.defaultBranch` 的模式与错误映射）> 内置默认；`~` 展开到 `HOME`。
  4. **不存在的环境或配置路径：** 行为以 git 实跑为准写回 M-TPLSRC S5。
  5. **模板中的 Git 专有文件：** 如 `config`，按普通文件复制但不应用为配置（Libra 元数据在 SQLite），登记有意差异。
  6. **失败回滚：** 新建仓库时模板复制失败，删除本次创建的存储目录。
- **Alternatives considered:** 把空模板当作错误——与 Git 不一致，拒绝。
- **Consequences:** `resolve_template_path` 不再对空值返回基准目录。
- **Revisit when:** 无。

### ADR-IN-04: 共享模式解析与持久化

- **Status:** Accepted
- **Context:** GAP-04；git `builtin/init-db.c:53`、`setup.c:2115-2163`、`:2881-2899`；`t1301:18`、`:49`；`t0001:226`。
- **Decision:**
  1. **语法：** `--shared[=<perm>]`，值只能以 `=` 给出；无值为 group。
  2. **取值：**
     - `umask`/`false`/`0`：不 chmod，不持久化，reinit 时移除已存值；
     - `group`/`true`/`1`：group；`all`/`world`/`everybody`/`2`：everybody；其它布尔拼写按 Git 布尔规则解析；
     - 八进制：视为文件模式，要求 `mode & 0600 == 0600`，以 `mode & 0666` 保存与应用。
  3. **持久化：** group → `1`，everybody → `2`，八进制 → `0%o`（掩码后）。
  4. **读取兼容：** 旧版 Libra 写入的 `group`、`all`、`umask`、`false`、四位八进制继续按上述规则解析，reinit 时改写为 Git 表示。
  5. **级联：** 未显式给出 `--shared` 时，按 local→global→system 读取 `core.sharedRepository`。
  6. **退出码：** 按 ADR-IN-02。
- **Alternatives considered:** 保留 `group`/`all` 文字表示——与 Git 配置不互通，`t1301:49` 不可移植，拒绝。
- **Consequences:** `docs/commands/init.md:169-191` 中「拒绝 `0660`」的说明改写。
- **Revisit when:** 无。

### ADR-IN-05: 共享权限计算与覆盖面

- **Status:** Accepted
- **Context:** GAP-05..GAP-07；git `path.c:739-790`。
- **Decision:**
  1. **单一 helper：** 新增 `src/utils/shared_perm.rs`，提供 `calc_shared_perm(mode, shared)` 与 `adjust_shared_perm(path, shared)`，语义对齐 Git：
     - 普通文件：在原模式上叠加共享位；owner 不可写时去掉共享写位；owner 可执行时把读位复制到执行位；强制模式（八进制）替换低 9 位；
     - 目录：额外把读位复制到执行位，存在 group 访问时加 setgid；
     - everybody 的共享位为 `0664`，group 为 `0660`。
  2. **init 与 reinit：** 递归应用改为按文件类型调用 helper；vault 与 sidecar 保持 owner-only；不跟随符号链接。
  3. **init 之后：** 松散对象与 pack、数据库文件与 SQLite sidecar、索引，以及 IN-07 清单中的元数据文件与目录，都在创建后经 helper 调整；仓库共享模式每个进程读取一次并缓存。
  4. **非共享仓库：** 不调用 chmod，权限与现状一致。
  5. **Windows：** no-op。
- **Alternatives considered:** 在 init 时放宽 umask——无法覆盖后续进程写入，拒绝。继续用目录位 chmod 文件——产生可执行与 setgid 文件，拒绝。
- **Consequences:** IN-06 修改共享原子写入与存储层，命中 T-1；compat 守卫限制 `.libra` 内新增直接 chmod。
- **Revisit when:** 支持 ACL 或 Windows 共享语义。

### ADR-IN-06: 默认对象格式来源

- **Status:** Accepted
- **Context:** GAP-09；git `setup.c:2716`、`:2778`；`t0001:519-600`。
- **Decision:**
  1. **优先级：** `--object-format` > `GIT_DEFAULT_HASH` > `init.defaultObjectFormat`（local→global→system 严格读取）> `sha1`。
  2. **非法值：** `init.defaultObjectFormat` 非法时输出 warning `unknown hash algorithm '<value>'` 并回落 sha1；`GIT_DEFAULT_HASH` 非法时 129 `LBR-CLI-002`，零写入。

  4. **不适用场景：** reinit 与 `--from-git-repository` 不读取默认来源。
- **Alternatives considered:** 只支持配置不支持环境变量——`t0001:519`、`:578`、`:585` 不可移植，拒绝。
- **Consequences:** `resolve_object_format` 改为接受来源链。
- **Revisit when:** plan-20260907 调整对象格式接受集。

### 故障恢复矩阵

| 故障点 | 可接受残留 | 恢复动作 | 禁止结果 |
|---|---|---|---|
| 新建仓库时模板复制失败 | 无（本次创建的存储目录已删除） | 报告原始 I/O 错误 | 残留半成品 `.libra` 或当前目录副本 |
| reinit 格式比较时数据库不可读 | 仓库原样 | 以既有 I/O 或元数据错误报告 | 在比较前触发迁移或布局写入 |
| 共享权限应用中途失败 | 已调整的部分文件 | 报错并提示重新执行 `libra init --shared=<mode>`（幂等） | 放宽 vault 或产生全局可写路径 |
| 后建文件 `chmod` 失败 | 文件已写入但权限为 owner-only | 命令以 I/O 错误结束，提示检查目录归属 | 静默忽略导致共享失效 |
| 发布步 `gh release create` 失败 | 已推送的 `main` 提交 | 按 ER-09 记录，下一窗口补 tag/release | blind retry；只推 `main` 就宣称已发布 |
| D 组 `release.yml` 失败 | 已存在的 tag | 前滚修复，发新 patch | 回退已推送提交或删除已发布 artifact |

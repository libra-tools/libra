## 文档职责

本文将 CodeQL（CodeQL 2.26.4，`.github/workflows/codeql.yml`，baseline `0d32b766`，2026-09-05 抓取）的 112 个 open alert 按行为轴收敛为独立可恢复切片：

1. **SC-01**：`base.yml` 8 个 job 缺 `permissions:`（#67/#68/#69/#72/#97/#101/#207/#208，medium）——CI least-privilege 加固。
2. **SC-02**：session store 读取/删除/**迁移/归档**路径缺集中式 id 校验（path-injection 的真实缺口，high）——defense-in-depth 收敛为单一事实源守卫（含 `adopt_legacy_subdir_session_if_needed` / `archive_corrupt_session`）。
3. **SC-03**：`agent session promote --dry-run` 人读与 JSON 的 prompt 原文回显（cleartext-logging 生产位点之一，high）——默认只报长度；opt-in 脱敏全文。拆出 SC-07。
4. **SC-04**：`LocalStorage::new` / `new_with_alternates` / `ClientStorage::init` 构造 `panic!`（扫描未覆盖，GC-11）——`try_*` + 同型 `Result` 机械接线（EX-SC-01）。
5. **SC-05**：5 个 critical `hard-coded-cryptographic-value` FP（#92/#93/#95/#98/#99）——逐条复核后 `false positive` dismiss。
6. **SC-06**：残余 FP 逐条现场复核后 dismiss + D 组复扫卫生。
7. **SC-07**：自 SC-03 拆出——`auth status` / `login` / `whoami` 人读 host 字段走 `redact_url_credentials`。
8. **SC-CLOSE**：全量收口、D 组聚合、版本发布。

本文只规划任务，不宣称实现完成。落地时每张卡先刷新源码锚点与 alert 状态，再按本卡验收。

### ADR-SC-01: session id 守卫收敛为单一事实源，fail-closed

- **Status:** Accepted
- **Context:** `is_safe_session_path_id` 已存在（store.rs:899）但只有 `save` 强制；`load/delete/lock_session/file_history/session_modified_time` **以及** `adopt_legacy_subdir_session_if_needed`（store.rs:133）/`archive_corrupt_session`（store.rs:676）依赖"调用者传安全值"。后两者会 `rename`/`remove_file`，且 `adopt_*` 的 `parent` 已在 `sessions/` 之上。`file_history`/`session_modified_time` 当前不是 `Result`。
- **Decision:** 七个入口在拼路径前统一调用 `is_safe_session_path_id`。`load` 反序列化后还须断言 `session.id == 请求 id` 且 id 安全，失败 `InvalidInput`，不得把磁盘 traversal id 交给调用方（堵住 `graph.rs:206`）。`adopt_*`/`archive_*` 失败同样 `InvalidInput`，不得 `join`/`exists`/`rename`/`remove_file`。`file_history` → `io::Result<FileHistoryStore>`，`session_modified_time` → `io::Result<SystemTime>`。消息含形态、不含 id 原文。`save` 既有守卫不变。`provider__session` 这类单组件 id（`hooks/runtime.rs:120` 的 `__`）仍合法。`is_safe_session_path_id` 本体一并收紧：在**保留**现行黑名单（空串/`.`/`..`/含 `/`、`\`、`\0`、绝对路径）的前提下追加白名单判定——恰好一个 `Component::Normal`，拒绝 Windows `C:` Prefix 等一切非 `Normal` 单组件。黑名单不得随白名单引入而删除：`components()` 会把 `a/`、`a/.` 规范化为单 `Normal`，Unix 上 `\` 亦非分隔符，纯白名单会放宽现行行为（`a/`、`a/.`、含 `\`、含 `\0` 仍须拒绝，由 ⑧ 的 traversal 形态与新测 `session_store_rejects_windows_drive_prefix` 钉死）。且 `Component::Prefix` 解析只在 Windows 生效——Unix 上 `C:` 就是单 `Normal`，纯白名单**仍会接受**盘符形态，故白名单之外再补**平台无关**判定：id 匹配 `^[A-Za-z]:` 即拒绝（macOS/Linux/Windows 全平台可验）。不得用裸 `contains(':')`——`build_ai_session_id`（`hooks/runtime.rs:114-122`）要求 provider 原生 session id 无转义 round-trip，全面禁 `:` 可能误伤合法 id。`session_ids_for_thread` 对 `.thread_index` 每一行在 `exists` 前调用该守卫。`is_safe_session_path_id` 提升为 `pub(crate)` 单一事实源，`HeadlessSessionPersistence::acquire_session_lease`（`web/headless.rs:879`）删除其平行弱判定（仅「单 `Normal` + 非空」，会接受 `a/`、`a/.`、含 `\` / `\0`、盘符形态）改调共享守卫；`session_root` 保持非 `Result`（拼接本身不可失败），守卫一律在调用前执行。
- **Alternatives considered:** ① 只守卫 `delete`（拒绝：`load` 的 `session_root.exists()` 探测同样可越界）；② 在 `session_root/session_path` 内部守卫（拒绝：`session_ids_for_thread:258` 用假想 id 探测 `exists()` 属合法用法）；③ 引入 `SessionId` newtype（拒绝：跨 crate 触及面过大）。
- **Consequences:** 传入带分隔符 id 的新调用点会显式报错而非静默越界；现有合法调用（内部生成 UUID、`read_dir` 文件名派生 id）不受影响。`file_history` 由 `FileHistoryStore` 改为 `io::Result<FileHistoryStore>`：仓库内 **零调用点**，且 `internal` 非稳定嵌入面（`src/lib.rs:1-13`），`Version increment=patch`；兼容窗口证据 = 本 ADR + `CHANGELOG.md` 一条说明（旧签名 → `file_history(id)?`；本仓库是唯一消费者）。不走 deprecation 周期（未守卫入口是 path-injection 缺陷）。不改 `COMPATIBILITY.md`（非 Git CLI 矩阵）。§2.2（`migration.rs` `LegacySessionMigrator`，6 个 alert #149/#161/#165/#166/#176/#185——注意源文档中 #161 在 §2 per-file 表（`util.rs` 行）与 §2.2/§2.4 清单重复出现、自相矛盾，ER-SC-01 开工抓取时按 `location` 校正并回写源文档）的 id 全部经 `SessionStore` 入口流入（`migrate_legacy_session_if_needed`，store.rs:780-784 → `session_root(id)`），本决策的入口守卫 + `load` 反序列化断言在边界覆盖；CodeQL 复扫未自动转 fixed 的残余由 SC-06 逐条复核。
- **Revisit when:** 出现需要多组件 id 的合法场景。

### ADR-SC-02: 输出 redaction 复用既有 redactor；promote JSON 同步收敛

- **Status:** Accepted
- **Context:** GC-02。`SecretRedactor::default_runtime` 不识别裸 `sk-`/`ghp_`。`redact_url_credentials` 不处理无 scheme 的 userinfo。`LoginJsonView` 只证明 login JSON 省略 session token，**不能**证明 promote JSON 已脱敏——`agent/session.rs:999-1008` 把 prompt 原文写入 `"prompt"`。
- **Decision:**
  1. `agent session promote --dry-run` **默认**人读与 JSON 的 `prompt` **保持 string 类型**：值为 `"<len=N>"`，**不**输出原文任何前缀（避免把 string 改成 object，patch 即可，ER-08）。
  2. `--show-redacted-prompt`（additive opt-in）输出脱敏全文（仍为 string）：先 `SecretRedactor::default_runtime().redact()`，再在 **本卡调用点**对文档化前缀 `sk-` / `ghp_` / `github_pat_` 做最长匹配替换为 `[REDACTED]`。
  3. `auth`/`login`/`whoami` 人读 host 经共享 helper：仅当输入含 userinfo（`://` 且 userinfo 含 `:` 或 HTTP username）时调用 `redact_url_credentials`；否则 **原样返回**（避免 `Url::to_string()` 给干净 origin 加尾 `/`）。JSON 路径保持既有契约。
- **Alternatives considered:** 默认输出原文前 8 字符（拒绝：短密码完整泄漏）；把 `sk-` 写入 `SecretRedactor` 默认表（拒绝：超出本计划、污染其它投影面）；scheme-less userinfo 扩 `redact.rs`（拒绝：另开行为轴，见 RR-SC-01）。
- **Consequences:** dry-run 人读 **与 JSON** 契约收紧记入 `COMPATIBILITY.md`；CI `--json` 不再携带原文 prompt。`prompt` 值由原文变为 `<len=N>` 是**有意的值语义变更**，不是兼容性证明：依赖原文值的 dry-run JSON 消费方会拿到占位串——这正是本卡要消除的泄漏面本身；`--dry-run` 是预览路径（非持久化/协议面），变更经 COMPATIBILITY 登记，按 ER-08 取 `patch`（非稳定面删除或 schema/协议破坏才需 minor）。账本口径：eli 具名接受残留（Claude R22 P2-5），不声称「已证明兼容」。
- **Revisit when:** 出现第二个 prompt 类输出面时提升为共享 helper。

### ADR-SC-03: ClientStorage 构造改为同型 `Result`（不可拆机械接线）

- **Status:** Accepted
- **Context:** 只改 `LocalStorage::new` 的直接调用点不能关闭 panic 链：`new_with_alternates` 调用 `new`；`ClientStorage::init`/`create_storage_backend` 调用 `new_with_alternates` 且返回非 `Result`。生产调用点分布在 30+ 文件（含 `code.rs:4387`）。
- **Decision:** 引入 `LocalStorage::try_new` / `try_new_with_alternates` 与 `ClientStorage::try_init` / `try_init_local`。**删除**生产路径上的 panic `new`/`init`/`init_local`/`new_with_alternates`（不得以 `// INVARIANT:` + `expect` 保留可失败的 `create_dir_all`）。若测试仍需简写，仅 `#[cfg(test)]` 包装。`src/**` 与 `tests/**` 全部**构造器**调用点同型 `?` / `map_err`。`cached_objects_storage` 改为 `try_init`；公开 `objects_storage()` 改为返回 `io::Result<ClientStorage>` 或删除，写路径迁 `try_objects_storage`。读路径：`classify_presence` 改 `init_local_existing`（不 mkdir，签名不变）。`TreeExt`/`CommitExt`/`BlobExt::load` 改为 `io::Result<T>`（当前是 `Tree`/`Commit`/`Blob`，**没有** `GitError`）；`get_plain_items*` 改为 `io::Result<Vec<_>>`；内部 `try_objects_storage()?`，构造 IO **禁止**折进 panic。命令层机械 `?` 到既有错误类型。这是 G-04 白名单「跨文件同型 API 机械替换」，登记 EX-SC-01。

#### D-STD-REL：独立发布卡 release.yml 远端后置门

每张 `independent` 卡在 ER-04 C 组第 ⑨ 步之后执行。C⑨ 的 `gh release create "v${VERSION}" --verify-tag` 要求远端已有同名 tag——执行序列必须是 `libra tag "v${VERSION}"`（指向本卡提交）→ `libra push origin "v${VERSION}"` → `gh release create "v${VERSION}" --title "v${VERSION}" --generate-notes --verify-tag`（tag 解析到 `CARD_SHA` 的断言由本门脚本在 C⑨ 之后执行；C⑨ 内可用 `gh api "repos/${GH_REPO}/commits/v${VERSION}" --jq .sha` 立即预检）。缺 tag 时 `release.yml` 不会被触发，本门无 run 可验（卡停 `remote-pending`）。D 组**只读**核对，不创建 tag/Release。`LIBRA_DSTD_EVIDENCE_DIR` 必设。`gh run list --branch` **不**匹配 tag ref。网络预算（ER-10）：单次 curl `--connect-timeout 10 --max-time 60`；轮询由 `DEADLINE` 驱动、不设固定次数；整门预算由脚本内 `ckb`/`breach` 强制执行（每个外部调用前与成功出口前检查；残留窗口 = 单个进行中 gh/curl 调用的自身超时——curl ≤60 s、gh 内部默认——由下一检查点捕获）。超预算**不是** FAIL：`breach` 记录脱敏证据并以 exit 42 把卡置 `remote-pending`，按记录的 RUN_ID/CARD_SHA/VERSION 恢复重跑。预算值：D-STD-REL 45 min、D-STD-SC 与 SC-04 集合差 40 min、SC-01 dispatch 门 400 min（按 `base.yml:180` 的 `timeout-minutes: 350` + 排队余量推导；A 组本地 nextest 全量 + `cargo test --all` ≈ 2.4 h，CI 腿不可能更短）。40/45 min 的依据：CodeQL（buildless `build-mode: none`，`codeql.yml` 未声明 `timeout-minutes`）与 `release.yml` 五 job 的常规运行均在数十分钟量级；冷启动首轮超预算走 breach + resume（exit 42；run 已完成时恢复很快返回），属预期路径而非失败。

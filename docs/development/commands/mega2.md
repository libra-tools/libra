# `libra mega2 traces`

Read commands are GETs under `/api/v1/traces`. Token precedence is `--token-file`, then `LIBRA_MEGA2_TOKEN`, then `--token`. A redirect keeps `Authorization` only when the scheme, host, and port stay the same. Bodies over 1048576 bytes are rejected before JSON parsing.

`capabilities --require-search` reads the existing `search_ready` field. It does not add a server route. `targets --path` calls `/targets/resolve` and does not create a scope. Stream and session lists default to 50 and reject a limit above 200. `since`/`until` are RFC3339 values compared as Unix seconds on `[since, until)`; an inverted window is rejected before a socket opens. Search defaults are limit 20 and max_bytes 16384, with maxima 100 and 131072. Query admission is 1..=256 UTF-8 bytes and runs before target resolution. Transcript reads default to 16384 bytes.

`streams` passes `source`, `owner`, `epoch`, and `cursor` unchanged and defaults `limit` to 50 (maximum 200). `sessions` passes `agent`, `session`, `code_commit`, and `cursor` unchanged. `since` / `until` are normalized to UTC RFC3339 before the request. `since` later than `until` never opens a socket; equal bounds are sent as an empty `[since, until)` interval. `show` rejects both `--session` and `--checkpoint`. `search` admits `q` and any `--code-commit` or time window before target resolution, then sends the optional source, stream, session, agent, time, code OID, and cursor with the resolved `target_id`. The query text is not case-folded locally.

`capabilities --require-search` rejects a missing `search_ready`, a non-boolean value, and `false`. Without the flag, the command still prints the capability body.

`fetch --remote --stream` reads `remote.<name>.url` and opens `/.traces/by-scope/<uuid>.git` on the same origin through `command::mega2_traces::git`. HTTP needs a token (no token is an anonymous refusal before any socket) and sends it as the Basic password under login `traces`; SSH keeps the leading `/` of the locator (`SshClient::with_literal_repo_path`) and uses login `traces`. Upload discovery must advertise `libra-traces-v1`, `libra-traces-server=<id>`, and the requested `libra-traces-scope`. The fingerprint is `SHA-256(libra-traces/server/v1\0 + server_id + scheme://host:port/service-root)`; a different stored fingerprint stops before the upload request. The request is one `want <tip>` with only `object-format=sha256` (when needed) and `agent=`, a flush, and `done`, because the TraceRepo refuses unadvertised capabilities such as `side-band-64k`. The response must be one `NAK` packet followed by PACK bytes; an `ERR` packet is reported as the remote error. `fetch::install_fetched_pack` checks the pack trailer, writes and indexes it under a `.keep` pin, and the tip must load as a commit before `refs/remotes/<remote>/traces/<uuid>/<hash>` is written (a re-fetch replaces that row). Then `libra.traces.archive.<uuid>.ref`, `.tip`, `.hash_kind`, and `libra.traces.remote.<name>.fingerprint` / `.server_id` are recorded and the pin is released. A hash kind other than `core.objectformat` is rejected and not converted. `refs/heads/traces` and `refs/libra/traces` are refused as publish targets. `HEAD`, the index, the worktree, and the capture catalog are not updated. A failed check publishes nothing. A busy TraceRepo (`query_timeout` or HTTP 503; it admits one receive and one fetch at a time) is retried up to 8 times with exponential backoff from 200 ms. The former JSON `/api/v1/traces/streams/<uuid>/archive` request is gone; `explicit_fetch_scope_and_local_invariants` serves a real `git pack-objects` PACK from a loopback smart-HTTP stub.
